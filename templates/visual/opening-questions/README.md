# 同一科技对象，引出两个问题

## 表达任务

开场围绕同一主体，先提出能力问题，再用一次触及边界的动作提出限制或确认问题。对象、模块与边界参与解释；结束保留两个问题及完整主体，供正文承接。

中性示例使用任务核心、读取资料／整理内容／执行任务模块与权限边界，提出「它能做什么？」和「哪些操作需要确认？」。这是概念示意，不代表具体产品的能力或权限策略，不在开场给出答案。

## 使用入口

- `index.tsx`：`OpeningQuestionsMotion`。
- `example.tsx`：`OpeningQuestionsExample` 与 Composition 元数据；1920×1080、30fps、222帧／７．４秒。
- `artwork.ts`：逐帧状态、SVG与Canvas绘制。
- `scene.ts`：主体造型、能力模块、问题文字与权限边界。

组件无配置参数。按实际内容修改对象、问题、模块标签、边界含义和时间锚点；文字、几何坐标、裁切区域及模块移动终点要同步调整。

## 问题与对象的关系

- 两个问题围绕同一主体，模块、动作与边界含义符合当前内容；概念示意与实际产品事实可区分。
- 问题文字与所指对象对应清楚，限制有可辨认的行为或形态依据。

## 当前实现

- 中央主体具有顶面、明暗侧面与接触阴影；低亮环境承托主体，光晕不覆盖结构。
- 能力模块共享青绿材质，权限边界用暖色及锁形共同辨认，不能只靠颜色表达限制。
- 核心先建立，能力模块和第一个问题随后展开；能力连接完成并短暂停留后，才开始权限段。
- 边界建立后操作模块接近，在边界前停止；接触亮线提供受阻提示，随后展开第二个问题。问题文字不跟随模块移动。
- 第二个问题出现时，左侧降低亮度但保持可辨认；结束保留完整画面，无离场、字幕或声音。

## 可调整项与失败方式

适合围绕同一对象提出两个相关问题，例如能力与限制、输入与条件。两个问题若属于不同对象或必须同时呈现，应重新设计结构。

可调整模块数量、造型、构图、配色、问题长度、边界形态、展开顺序、节奏及结束方式。中央构图、能力段后接权限段和无离场属于当前示例设计，其他内容按实际表达重新安排。正式视频按用户确认的分镜与真实Timeline改造，７．４秒不是生产默认时长。

长文字溢出裁切区、主体过小、所有对象同时发光、边界所限制的操作身份不清、声称受阻却穿过边界，或提出问题时画面已给出不相符的答案，都会损害表达。模块接近边界的路径及停止位置须随布局重新核对。

## 实际验证范围

原创静帧及７．４秒独立Shot无声交互预览获用户质量认可，并明确要求入库。提取222帧状态与SVG一致，组件源码核对及定向严格类型检查通过。

依赖浏览器Canvas 2D及SVG解码，无新增依赖或外部媒体。尚未渲染Remotion成片；其他内容改造、真实Timeline适配、完整视频观看／试听及用户确认、跨视频复用仍待验证。
