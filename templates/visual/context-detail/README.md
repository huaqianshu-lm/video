# 背景总览与局部解释

## 表达任务

在输入、处理、输出的结构中展开处理节点，解释内部变化，再回到结构关系并送出结果。背景与局部解释表达同一件事；示例使用三项中性字母的重排，不代表真实产品执行结果。

## 画面变化

默认8秒，1920×1080、30fps、240帧，无章节标题、字幕或声音。

- 输入与原始内容先建立，再出现连接线和处理节点。
- 节点展开，其他已出现的上下文降低亮度；同一组内容进入节点。
- 内部重排C、A、B为A、B、C，保留身份与颜色。
- 重排完成后，卡片和内容一起收回处理节点。
- 收回完成后才建立输出连线、箭头、圆圈和标签，再送出内容。
- 输出保留结果供确认，最后整体上滑离场。

串行流程按步骤完成后推进，不让下一步与当前步骤的必要收尾重叠。实际并列流程需要按依赖重新设计，不能套用此串行时序。

## 使用入口

`ContextDetailMotion` 接收 `data` 与可选正数 `timeScale`。

```tsx
<ContextDetailMotion data={exampleData} timeScale={1}/>
```

`data.input`、`process`、`output` 为三个对象的短标签，`description` 为内部动作的短解释；`items` 是按初始顺序排列的三个短标识。示例组件、数据及注册信息见 `example.tsx`，Composition ID：`ContextDetailExample`。

`timeScale` 整体缩放时间，Composition帧数采用 `Math.round(8 * timeScale * fps)`。正式应用按冻结分镜与真实Timeline改造各阶段，不强行倍速适配讲解。

## 视觉不变量与改造边界

- 内容始终为同一组三项：输入离开后不留下副本，输出收到后不在处理中重复保留。
- 节点本身展开并收回，解释卡不是无关浮层；上下文位置保持稳定。
- 收回前不建立输出，输出对象建立完成后再送出内容。
- 颜色表示对象身份，不表示优劣，文字及顺序变化说明含义。
- 输出完成后保留结果；处理卡片不在送出途中继续收拢。

可按内容改造标签、短解释、标识、材质、配色和时间。当前固定三节点、三对象、横屏布局，内部动作固定将初始第2、3、1项排为输出第1、2、3项；没有自动排序引擎。只替换标识不会改变动作规则，必须核对文案与实际排列一致。小节点标识宜保持一至两个短字符，长文字或更多对象需要重新设计。

不适用于并行分支、任意数量对象、长段说明或其他处理过程。失败方式包括背景与解释无关、复制对象冒充传递、输出提前出现、收尾与下一步骤抢焦点、文案声称与固定重排不同的规则，以及压缩时长导致动作或结果无法看清。
