# 独立内容归入数字工作空间

## 表达任务

文档、图片和代码各自保留身份，依次归入同一个数字工作空间。左侧保留原始内容作为来源对照，右侧通过导航、内容画布和关联列表体现组织关系。适用于软件与AI内容的整理、关联和统一工作空间解释；界面是原创概念示例，不是某个真实产品截图或功能实证。

## 画面与变化

深蓝环境承托独立文档页、图片缩略图和代码窗；右侧单一大窗口建立主焦点，浅色文档画布与冷色界面形成层次。三类内容沿用各自造型和色彩身份，不能只给同类矩形换标签。

- 独立内容错峰建立，空工作空间随后进入。
- 文档2.00～2.85秒归入，形成文档画布与关联项。
- 图片3.05～3.90秒归入，补充图片内容与关联项。
- 代码4.10～4.95秒归入，生成实现片段与关联项。
- 各结果内容与关联项在相应移动结束前0.14秒开始显现，与移动副本淡出短暂重叠。
- 所有内容落位后才显示「已整理」，保持完整构图供阅读。
- 6.15秒开始窗口收为顶栏，再缩窄上移；来源内容错峰向左离场，标签一起收尾。

默认7.8秒、1920×1080、30fps、234帧，无章节标题、字幕或声音。沿路径运动的是内容副本，左侧有意保留作为来源，不能解释为原文件被移走或删除。

## 使用入口

```tsx
<DigitalWorkspaceMotion
 labels={{separate:'独立内容',organized:'统一工作空间'}}
 timeScale={1}
/>
```

示例Composition ID：`DigitalWorkspaceExample`，注册信息见`example.tsx`。输入`labels`只控制两组短对象标签；`timeScale`由调用方传入正的有限数，组件没有自动校验该参数，按倍数缩放整个Shot。完整示例的Composition帧数可采用`Math.round(7.8 * timeScale * fps)`。正式应用按用户确认的分镜及真实Timeline改造，需要分别调节阶段时修改实现。

## 内容对应关系

- 完成状态与已组织的内容一致，不在仍缺少必要内容时显示完成。
- 三类来源与工作空间内容保持可辨认的对应；左侧来源保留，不制造含义不明的重复内容。

## 当前实现、可调整项与边界

当前文档、图片、代码依次归入，上一项完成后开始下一项；阅读期间主窗口固定，结束时收为顶栏再缩窄上移。构图、配色、动作及收尾均可按当前设计改造；改动时同步检查来源、画布与关联项，避免移动或裁切遮住必要信息。

可改短标签、造型细节、内容和节奏。当前固定三类内容、宽画幅和来源／工作空间构图；不是任意产品界面生成器。内部文案与图形位于parts.ts，正文、关联项及运动副本需一起改造。实际视频文字必须来自当前资料；只换两组标签不能声称表达了不同功能。

不适用：硬件部署、真实产品操作录制、原文件删除或搬移、不同数量的对象及并行任务。此类内容需要重新设计。

失败方式：只改来源不改结果；内容或完成状态抢先出现；把归入理解为复制数量或容量数据；缩字导致无法阅读；原有路径无法容纳新内容；窗口移动与逐项阅读同时发生。

## 实际验证范围

静帧设计与7.8秒独立Shot无声交互预览均获用户画面认可，并明确要求入库；网页和候选Remotion使用同一画面函数。提取234帧逐帧SVG一致，模板入口定向严格类型检查通过。
