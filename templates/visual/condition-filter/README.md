# 条件筛选

## 表达任务

保留同一个筛选装置和输入类型，改变条件，再展示通过与拦截的差异。圆形、三角形、方形是中性属性示例，计数仅对应图中对象，不代表真实业务数据。

## 画面变化

- 装置与路径建立，第一轮三种形状依次通过并进入右侧收集区。
- 第一轮结果统一淡出，筛选条件切换，开口形态与旋钮同步改变。
- 第二轮圆形通过，另外两种形状落入下方拦截区。
- 保留结果供阅读，再整体淡出收起。

默认示例8.4秒，1920×1080、30fps、252帧；无章节标题、字幕或声音。

## 使用入口

`ConditionFilterMotion` 接收 `labels` 与可选 `timeScale`：

```tsx
<ConditionFilterMotion
 labels={{input:'输入',before:'全部通过',after:'仅圆形',passed:'通过',blocked:'拦截'}}
 timeScale={1}
/>
```

`labels` 五项分别是输入标签、前后条件、通过区和拦截区标签。保持短文案，条件必须与实际图形及动作一致，不能只换文案声称演示了其他筛选规则。

`timeScale`由调用方传入正的有限数，整体时间按该倍数缩放；组件没有自动校验该参数。完整示例的Composition帧数可采用`Math.round(8.4 * timeScale * fps)`。正式视频按用户确认的分镜和真实Timeline改造；需要独立调整动作或阅读停留时修改实现。

示例组件：`ConditionFilterExample`，注册信息见 `example.tsx`。未修改共享Root或注册具体生产视频。

## 当前实现与改造边界

- 条件切换时装置、输入路径和通过区位置保持稳定。
- 当前两轮输入种类相同；第二轮圆形通过，另外两项出现可见拦截反馈。这是代码中的演示逻辑，不是可通过标签配置的筛选规则。
- 计数与到达结果区的时刻一致；第一轮完成后再切换条件。
- 形状、装置厚度、通过区与拦截区共同表达含义，颜色不能独自承担差异。

可以按内容调整标签、时长、颜色和材质，也可改造动作及收尾。更多对象、不同筛选属性、不同画幅或复杂规则需要重新设计对象、路径及计数；当前实现没有自动布局、真实筛选引擎或任意条件配置。改造后，条件、通过／拦截行为及计数仍须一致。

失败方式：只换标签导致条件与图形不符；缩短停留使两轮结果无法读清；添加过多输入造成遮挡；用筛选隐喻冒充具有依据的产品执行结果。
