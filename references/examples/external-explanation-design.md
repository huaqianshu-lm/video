# 外部案例：结构、原理与可见变化

以下包含视频配套文章及交互解释。它们扩展教程的表达方法；交互文章不计为视频样片。本文依据官方正文、章节与已查看配图推导方法，未完整播放视频或操作交互模型，不能据此声称原片动态效果已观察或迁移已验证。

本页把官方解释依据与原创镜头设计分开。官方正文能够支持讲解关系，不自动提供一套已观察的运镜；下列布局、变化链与实现模型属于**原创推导，未实现**。需要具体的动作源码时，结合 [GitHub 场景研究](github-explanatory-animation.md)；需要当前成片质量判断时仍须实际制作、观看与试听。

| 当前解释缺口 | 优先对照 | 最终应看懂的变化 |
|---|---|---|
| 两种图形各自好看，却不知道怎样对应 | 3Blue1Brown | 同一输入、局部与抽象表示有可追踪的映射 |
| 系统组件很多，不知先讲哪一个 | Animagraffs | 一个运行单元先成立，再看支持它的系统关系 |
| 新增配置或部件只是背定义 | Mechanical Watch | 当前不足被看见，新增部分有必要性，再回到整体核对 |
| 对象有光晕却没有体积 | Lights and Shadows | 光向、表面、观察与遮挡分别怎样影响可见结果 |

## 3Blue1Brown：同一对象的多种表示相互对应

来源：[But what is a Neural Network? 官方文章](https://www.3blue1brown.com/lessons/neural-networks/)；[局部特征配图](https://storage.googleapis.com/3blue1brown-website-bucket/lessons/2017/neural-networks/loops-and-lines.jpg)。

**资料依据**：正文将输入像素、神经元数值和输出联系起来，并用亮度表达激活值。已查看配图把数字与环、线等局部特征分栏对照，同一局部在不同组合中沿用颜色；作者明确将局部特征解释作为动机性的希望，而非所有网络实际学习结果的保证。

**新增设计图观察**：[像素值原图](https://storage.googleapis.com/3blue1brown-website-bucket/lessons/2017/neural-networks/pixel-values.jpg) 把同一数字表示成带数值的灰度格，右侧局部放大仍保留同样的格值，红色圈线连接原位置与放大区。放大增加的是阅读分辨率，没有引入另一份输入；亮格使用深字、暗格使用浅字，文字对比随底色处理。这支持局部与整体对应的静态判断，不证明其放大动画或模型推理已经观察。

**可迁移方法**：复杂系统可先建立观众认识的输入，再揭示它的表示和处理关系。总览图帮助定位，局部图负责解释一个对应关系；两者通过相同对象、颜色角色或局部轮廓相连。图形简化要交代省略，不能让示意节点数量被理解为真实规模。

**教程设计推导**：讲“配置如何影响行为”时，把配置项、当前值和对应行为放在能逐项对照的位置；先解释一项，再回到整体。若讲同一数据的文本与结构表示，保留字段对应，避免两种表示只是无关地轮换。

**失败条件**：随机亮点被当作计算；用好看的网络图代替真实关系；把启发性比喻当成经过验证的内部机制。图上颜色、亮度等映射仅在有内容依据时使用。

### 表示转换先建立映射，不能只追求变形流畅

**官方正文依据**：文章先把像素亮度与数值关联，再说明输入、层和输出的表示；局部特征的解释明确带有教学动机和局限。这里只采用“先定义单位、再建立对应”的解释顺序，不把示意结构推广为其他模型的实际机制。

**原创推导**：两种表示最好至少共享一个可识别单位，例如字段、像素、位置或样本 ID。整体转换前，先展示一个单位两端怎样对应；再扩展到其余项，最后稳定全貌。多对一和一对多要按真实关系画线，不能每个来源都随意分配一个终点，制造不存在的一一对应。

构图让原表示、映射通道和新表示有清楚分区，不要求始终三栏。画面过密时，整体退为定位，当前一项获得局部阅读，下一项由同一规则派生。颜色用于身份对应时不要同时承担大小或置信度；亮度表示数值时，先说明尺度，不用随机呼吸当计算。

### 原创演绎：同一配置的文字与结构表示

前提是当前资料有一小段确定的配置及其合法结构。观众应从“这是一段文字”走到“同一个字段、值和层级能在另一种表示里找到”。原文不是飞散后换一棵树，结构不是独立的装饰网络。

| 状态 | 原表示与新表示怎样组织 | 观众得到什么 |
|---|---|---|
| 建立单位 | 文字片段正视可读，保留父子缩进或实际语法 | 先知道哪些是字段、值与归属 |
| 选择一项 | 一个完整字段和值获得重点，父级仍保留定位 | 这次转换的是哪一项 |
| 对应定位 | 同名字段在结构中获得合法位置，短连线从真实原句出发 | 两边是同一内容的两种表示 |
| 展示层级 | 父子关系由包含或分支显现，值仍归属当前字段 | 布局解释层级，不是假装数值在传播 |
| 扩展其他项 | 重复机制简化，只给有区别的字段额外阅读 | 理解这是一条可复用映射规则 |
| 回到全貌 | 临时引线减少，整体中保留当前项标记 | 从局部理解返回原结构 |
| 接下一镜 | 沿一个有实际作用的字段进入行为解释 | 配置表示与运行结果仍需另一段有依据的关系 |

**美术选择**：原文用清楚等宽角色，结构标签按阅读任务使用中文字体，字段和值有字重差别，父级与子级以位置和连接共同辨认。底色低竞争，当前字段用一处强调，不能整棵树每个节点发光。节点的圆、框或点只是表示，不伪装成物理电路。

**实现关系**：用同一字段路径派生两端标签与连接，稳定 ID 不随排序变化；父节点的位置变化带动相关端口。收起子树时保留父项，重新展开能找回原处。没有实际树结构时不用树，没有数值矩阵时不为了数学感添矩阵。适合明确切换的两种表示，也不必须逐字变形。

**中段与通过证据**：文字出发位置和结构终点都正确仍可能在线路交叉时丢失身份，先检查主要映射通道、标签碰撞与焦点先后。通过时能在两端指出同一项，解释归属，不依赖旁白猜图；若亮点很忙却无法核对字段，就回到数据映射与构图。中文长标签、实际动画与完整观看仍待验证。

## Animagraffs：从一个运行单元展开到完整系统

来源：[How a Car Engine Works 官方项目页](https://animagraffs.com/how-a-car-engine-works/)；[作者发布的视频及章节](https://www.youtube.com/watch?v=ZQvfHyfgBtA)。

**资料依据**：作者视频说明列出四冲程、点火顺序、凸轮轴、曲轴、进气、冷却等章节，末尾回到完整模型；作者说明使用 Blender 建模。本次只核对说明及章节，未观察剖面、镜头运动或材质，不给出原片时间参数配方。

**可迁移方法**：解释系统时，先给一个能独立理解的运行单元，再补充让它持续工作的配套关系，最后回到系统。各子系统的展开应回答新的问题；不能把完整结构从头到尾一起转动，期待观众自行找到原因。

**教程设计推导**：解释多步骤工具执行，可先展示一次有依据的输入—处理—输出，再加入调用条件和异常分支，最后恢复总览，标明各段作用于哪里。抽象软件结构宜用有身份的对象和明确边界，不必伪装成发动机。

**失败条件**：拆解后失去与整体的位置对应；在讲运行原理时只做零件爆炸展示；演示速度与真实耗时混淆；直接引入 Blender 成为制作前提。

### “一个单元先成立”与“整个系统都出现”的差别

**原创推导**：系统总览只负责告诉观众单元在哪里，不需要同时解释每条线路。先选一个可闭合的输入—变化—结果，让一次事件真的走完；后续新增部分回答它此前不能回答的问题。讲运行的镜头与讲组成的爆炸图分工，不能把三张层片升起当作输入已被处理。

对象造型要表示职责：输入载体、处理边界、结果对象可以有不同轮廓，仍共享同一场景的边缘、字体与光向。通道起止点落在真实端口或边界，不能穿过物体中心。要观察局部动作时用清楚近景，进入总览时保留该单元的名称或标记，避免看完局部找不到它属于哪里。

### 原创演绎：一次处理先走通，再补必要检查

前提是当前资料明确输入、处理和结果，且有一个真实需要解释的检查条件。完成态是一条能追踪到结果的关系链，检查负责什么可观察；不虚构系统本来不存在的阶段。

| 状态 | 镜头与对象 | 观看目的 |
|---|---|---|
| 局部建立 | 一个输入靠近清楚的处理边界，结果区有预留空间 | 识别参与一次处理的对象 |
| 走完一次 | 输入或其表示进入，结果在有依据的时刻形成 | 先理解最简单的完整变化 |
| 提出条件 | 当前输入出现资料支持的差异，原边界与结果槽保持 | 明确新增问题在哪里，不突然展示全系统 |
| 加入检查 | 检查只出现在实际作用的边界，当前条件与反馈对应 | 看懂新增部分解决什么 |
| 核对两种情况 | 合法与不满足条件的结果有实际依据，并保持同一参照 | 不用所有路径最后都绿色成功 |
| 回到总览 | 观察范围扩大，已理解单元仍有定位 | 其他单元作为关联，不抢先解释全部 |

需要暂停过程解释条件时，当前对象可以在边界外稳定，说明读完再继续；不让信号在画面里永远循环等待。真实执行不能暂停的录屏则用明确的讲解冻结或另给示意，不能冒充软件本来有该停顿。演示运动速度与实际耗时分开，计时数据必须有证据。

**实现与美术**：同一输入身份驱动条件与结果，连线建立、信号抵达、状态改变有顺序。低对比支撑面与清楚轮廓让主体站稳，当前事件一处强调，已完成单元退为上下文。总览需要多节点时，先设计整体边界再反推局部放大，不把最后一镜缩到全是小点。

通过证据是既能说明一次处理发生了什么，也能指出新增部分作用在哪里。只看到零件排队入场，或最后有个“完成”徽章，都不足以证明过程已经讲清。本段是原创教学方法，不描述未实际观看的发动机机位与材质，也不承诺当前已有同等三维实现。

## Mechanical Watch：先暴露不足，再引入必要部件

来源：[Bartosz Ciechanowski 官方交互文章](https://ciechanow.ski/mechanical-watch/)。

**资料依据**：正文从储能弹簧讲起，说明直接连接指针的问题，再解释齿轮与擒纵机构的必要性；作者用颜色关联部件和名称，并说明可调整视角及查看内部。未实际操作模型，不把正文的交互描述写成自己的动态观察。

**可迁移方法**：复杂结构的每次新增，应解决先前已看得见的不足。对象身份贯穿整体、局部和运行解释，颜色帮助找回部件，形状和位置仍提供额外识别。学习的是必要性与因果链，不是要求每幕都增加复杂度。

**教程设计推导**：讲某工具为何需要额外配置时，先展示资料支持的限制，再加入对应配置，最后核对受影响行为；若没有可展示的失败证据，就明确作条件示意，不能编造产品故障。

**失败条件**：先列齐全部组件再逐个背定义；上一处问题未讲清就出现新部件；用颜色替代名称；把示意模型当成实际软件执行。

### 让新增部分成为对前一个问题的回答

**官方正文依据**：文章先解释简单动力和直接连接的不足，再讨论齿轮传递及后续控制；新增部件承担新的问题。这里只采用解释的必要性链，不复述未经操作观察的齿轮动作或制作自己的钟表工程规范。

**原创推导**：先安排“没有这个部分时会怎样”的可见状态，再展示新增部分的作用。新增不必每次从天外飞来，可以从整体的原位被揭出、从旁侧展开，或在同一结果上加一个清楚边界。前后比较共享输入、视角与尺度；否则观众难以判断改善来自新增部件还是场景全部换了。

如果资料只给了规则而没有失败录像，采用明确的条件示意；不模拟一个产品实际崩溃再当成测试记录。如果没有可展示的不足，也可以从目标直接解释必要职责，不强编“失败→救场”的戏剧故事。

### 原创演绎：为什么需要一项范围配置

前提是资料说明某配置控制操作范围，并给出范围内外的行为。观众最初只知道“存在一个配置项”，结束后应理解“它把作用对象限定在哪里”。结果画面保留同一操作、范围边界与目标对象，配置值与覆盖范围有依据地对应。

| 状态 | 画面变化 | 必须可核对的关系 |
|---|---|---|
| 明确目标 | 一个操作与预期作用对象同屏 | 不是抽象地讲“配置很重要” |
| 显示已有范围 | 对象处于可辨的当前边界内或外，边界名称清楚 | 当前条件而非任意红色遮罩 |
| 暴露限制 | 有依据的操作结果与范围同时可见 | 不满足条件发生在哪里 |
| 解释配置 | 配置条目与边界对应，其他代码保持稳定定位 | 这是哪个值控制的范围 |
| 改变或保持 | 只有内容支持时修改范围；拒绝情形则维持边界 | 不自动扩大范围来制造成功 |
| 再核对 | 使用同一对象与参照检查结果 | 变化与配置相符，其他对象未被暗示一并改变 |

**造型和焦点**：操作对象有具体身份，范围用围合区域、括号或真实界面边界表达，不把所有范围都画成玻璃盒。当前配置在相邻的清楚阅读区，边界和字段共享标记；已读说明退出，避免围着主体贴满提示。范围外对象保持定位，需要表明未受影响时才持续保留。

**实现与中段**：离散范围切换不硬插出一个不存在的中间授权；连续范围变化从同一参数派生边界与标注。改变范围时不同时重排对象位置，否则无法比较谁进入、谁退出。回到整体后仍能指出原来限制，才说明新增配置的作用已经讲清。正常速度要给条件与结果各自可读窗口，不按组件数量均分时间。

## Lights and Shadows：通过单项变化理解空间与材质

来源：[Bartosz Ciechanowski 官方交互文章](https://ciechanow.ski/lights-and-shadows/)。

**资料依据**：正文分别讨论光源功率、位置、观察方向、反射与阴影，并明确说明简化模型的限制。本文未操作滑杆或验证画面，只借助作者解释理解变量关系。

**可迁移方法**：判断主体为什么扁平时，分别考虑光源方向、表面朝向、观察位置和遮挡，再决定是否增加纹理。比较两个材质方案时保持其他条件一致，才能知道差别来自材质还是布光；不是给对象加一圈外晕就算完成体积设计。

**教程设计推导**：制作一个有厚度的文件或工具对象，可先确定受光侧、暗侧及落地关系，再检查与背景的分离。若需要写实镜面反射或复杂折射而当前实现无法支持，应选择可成立的简化风格，不用不一致高光伪装物理真实性。

**失败条件**：同一场景物体各有不同光源；阴影方向与高光矛盾；相机移动但依赖视角的反射完全不变；为了质感牺牲主体信息可读性。

### 用单项对照诊断质感，避免一起改所有参数

**官方正文依据**：文章区分光源功率、位置、表面朝向与观察方向；阴影部分解释光源面积与遮挡过渡，并指出接触处仍可有较清楚的暗部。本文未拖动模型，只把这些关系用于设计诊断，不把简单 CSS 阴影称为物理光照认证。

| 想判断什么 | 对照时保持什么 | 只改变什么 | 看哪里 |
|---|---|---|---|
| 主体为什么扁 | 对象、机位、材质、背景 | 主光方向或对象朝向之一 | 亮暗是否交代正面、侧面与轮廓 |
| 主体为什么像漂浮 | 对象、光向与支撑面 | 物体高度及相应投影 | 接触暗部、投影位置与软硬是否配合 |
| 材质为何混乱 | 机位、光源、对象形体 | 当前表面响应 | 变化来自表面还是环境全部换掉 |
| 文字为何读不清 | 字体、字宽、文字位置 | 背景／高光／遮挡中的一项 | 文字对比与实际笔画是否恢复 |

**原创推导**：亮面、暗面、厚度边与影子共同交代空间。不能一边称左上主光，一边让所有物体投影都朝左上；也不能把浮层自己的暗侧误当成落在底板上的影子。对二维示意，允许简化为几块稳定色面和受控软影，只要表面朝向与接触关系一致。需要反射、折射或自遮挡而当前做不到时，改用可成立的风格，不堆外晕冒充写实。

### 原创演绎：同一薄面从贴合到抬起再归位

这个练习服务文件页、界面薄面或工具部件的接触关系，不声称实际物体被真实摄影。先排贴合态和最大离位态：支撑面清楚，薄面有可辨边缘，正文正面可读；注记在屏幕平面，不随主体透视变形。

| 状态 | 需要一起变化的线索 | 不应一起变化的东西 |
|---|---|---|
| 贴合 | 薄面与支撑面边界吻合，局部接触暗部明确 | 背景不为起飞先闪一下 |
| 离位 | 法线位置、侧边显露和底板投影协调 | 正文字形不因高度被拉成长条 |
| 检视 | 相机停在能看清当前结构的角度，关键边缘从环境中分离 | 已无必要的反光和引导不继续抢眼 |
| 回落 | 距离减小，投影回到原位，接触关系恢复 | 不用全屏闪光掩盖错位 |
| 阅读 | 高度与镜头稳定，正文获得清楚面积 | 影子不继续漂移制造假活性 |

实现可把底板投影放在支撑平面，薄面厚度另画；由一个高度状态派生位移与投影，避免影子粘在浮层背后。投影的位移、扩散与透明度是示意模型，要按所选光向调校，不能认为“高度越大就一律更黑”。真实三维与简化示意采用不同计算方式，但视觉关系都需要看实际画面。

**通过证据**：贴合、离位、回落三态都能认出同一对象及支撑关系；不靠注记也能分清前后；文字仍读得清。若阴影方向正确却画面很脏，先减多余影层、检查背景明度与边缘，不再加颗粒。更多分层和投影细节见 [界面拆层与复合](exploded-interface-layers.md)，本例不替代其完整空间核对。

## 补充方法来源：先建立隐喻，再完成插画

[Kurzgesagt 官方制作说明](https://kurzgesagt.org/what-we-do?visit=videos)介绍在草图阶段推敲场景隐喻，以插画、信息图及角色解释内容，并以旁白提供动画时间依据；这是一份制作方法说明，不是单条视频拆解。

由此可推导：主体的辨识度应在轮廓、结构和行为上成立，再细化材质。比如讲“筛选”，先确认对象如何进入、按何种依据分离、结果在哪里，再决定视觉风格。拟人化可帮助记忆，但不能暗示工具具备资料没有支持的意图或自主权。

交互解释还可参考 [Nicky Case 的作者方法文章](https://blog.ncase.me/how-i-make-an-explorable-explanation/)：从具体经历出发，以问题及因果逐步提升抽象程度。迁移到线性视频时，需要主动安排变量和结果的对照，不能假设观众能自己拖动模型探索；此项是文章方法的迁移建议。

## 从交互解释迁移为线性视频时，要主动替观众安排对照

交互文章可以让读者反复拖动一个变量，视频则必须选出有解释价值的状态。**原创推导**：先建立基准，再只改变当前变量，保留参照，显示有依据的结果，最后回到具体问题。不是录一段随意拖动滑杆，也不是把作者文章的全部交互压进几秒。

设同一参数为 `p`，对象几何、标注与结果从同一模型派生；相机与颜色强调只负责引导观看。若结果是离散分支，应明确切换；没有可连续变化的业务状态时，不为平滑插值编造中间结果。必要的基准痕迹可以保留为细轮廓或并排对照，不能让前态完全消失后要求观众凭记忆精确比较。

每次提高抽象层级，保留一条能回到具体对象的线索。输入变成结构、局部变成整体、部件变成系统，都应能回答“刚才那个在哪里”。最后不是只剩术语，而是回到原问题，用同一对象核对新认识。若观众需要理解的是实际操作，抽象示意结束后由真实操作接管。

| 审查对象 | 成立的实际画面证据 | 失败时回到哪里 |
|---|---|---|
| 内容映射 | 同一单位在原表示、新表示和结果中都可追踪 | 先修对象身份与真实关系，不能靠发光连线补逻辑 |
| 新增必要性 | 原问题可见，新增部分改变有依据的条件或行为 | 先减少无解释作用的组件，再重排叙事 |
| 美术与阅读 | 主体有具体造型，材质一致，当前文字有完整阅读面积 | 静态构图先成立，再修速度与曲线 |
| 动态对照 | 基准不丢，改变来自明确变量，关键结果停稳可读 | 取消并行变化、无理由运镜与连续装饰 |
| 证据范围 | 示意、教学推导与实测结果各有清楚身份 | 不把作者说明、静图或动画完成写成运行通过 |
| 段落连接 | 每次回到整体能找回局部，下一镜继续回答原问题 | 重设锚点与接管主体，避免孤立演示拼接 |

本页把方法推进到可设计的状态、造型和实现关系，尚未证明当前原创镜头能达到原作观感。正常速度、中文真实内容、声音及最终衔接仍需实际制作验证；不增加新的必填表或人工 Gate。
