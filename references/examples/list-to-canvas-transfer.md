# 列表行迁入画布：跨容器飞行、形态变化与结果对应

这类镜头要让人认出：刚才被选中的内容，变成了画布上的这些对象。需要同时设计选择反馈、起飞、跨容器路径、行到卡的版式变化、落位，以及来源如何留下状态证据。只在左侧淡入几张卡，无法解释它们来自哪里。

## １．舞台不是左右对称的两列说明卡

**抽帧可见**：样片右侧是竖向来源面板，里面有五行候选和底部提交按钮；左侧是更宽的开放画布。左上标题保留，初始画布空着，供稍后的三张结果卡占据。三项选中后向左迁出，最后两张在上、一张在下，右侧仍可看到未选内容及已上板占位。

具体的视觉组织有以下作用：

- 来源面板保持稳定边界，作为飞行的起点和结果核对的参照。不要在提交时把它整个擦掉，丢失来源记忆。
- 画布的留白是为结果预留的空间，不需要用装饰图形填满；卡片飞入后，舞台密度发生有依据的变化。
- 来源的紧凑横行与目的地的较高卡片承担不同阅读任务：列表便于挑选，卡片便于展开详情。形态变化因此有意义。
- 样片采用暖浅底、浅色表面、暗色主字，少量红色同时用于勾选、数量和卡片边缘，帮助追踪关系。颜色可重设，但不要让无关高饱和装饰抢走迁移对象。
- 结果卡有微小不同倾角，表达落到开放画布；如果当前教程讲的是严格对齐的网格或精确定位，则应取消倾角。

原卡正文没有给完整终点排版坐标；实现中的 `TARGETS` 则明确给出落点。查正文与读实现是不同深度的证据，不能因正文没写就认为作者没有设计，也不能把估计坐标写成作者参数。实际制作应先排好当前资料的结果布局，再反求各行的飞行终点。

### １．１　字体、表面与环境怎样共同组成画面

**源码可见**：实现用衬线标题配无衬线操作文字；暖浅表面、赤陶强调与少量藏青标签来自同一套 sand 色板。舞台渐变、柔光、暗角和颗粒由 `Stage` 组织，点阵只在画布区域渐隐。面板与卡片用相近的边缘亮线和带暖色相的阴影连接到环境。这里是二维分层营造空间，并非物理灯光模拟。依据见上表的准确实现及两个视觉工具文件。

**制作推导：先决定阅读角色，再决定长相。** 大标题宣布当前整理任务，列表短标题服务快速挑选，落位后的主体内容服务解释，来源或状态只负责核对。中文应用不必照搬衬线混排：如果标题是编辑性主题，可用笔画有对比的标题字体配清楚的正文；如果是终端或文件操作，正文先保持真实的文字结构。字体选择后，用实际长标题检查字面宽度、标点和换行，不能靠换成窄字或缩小文字挤回英文示例外壳。

**制作推导：画布、面板和当前对象应有不同的视觉重量。** 先看无运动的完成态：画布是低竞争承托面，来源面板是稳定上下文，结果中正在讲解的对象是阅读主体。若背景纹理比正文笔画更显眼，先降低纹理；若来源面板比结果更抢眼，先收弱无关区域的边界和对比，不通过给结果加一圈强光补救。密集界面里若需要读原文，就另给稳定近景，不能整块压暗后还要求观众读它。

**制作推导：表面质感要能解释对象状态。** 稳定行贴近来源表面，离位时边缘与阴影交代分离，结果落位时重新建立支撑关系。纸面语言可以表现为哑光底色、细边和柔影；若当前内容属于精确界面操作，就采用界面自身的边界与控件，不强加纸纹。只给一个面板加玻璃反光、其他对象仍是纸卡，会破坏同一场景的材质关系。主体文字不应被暗角、颗粒或高光压住。

### １．２　最终画面先回答“它们组成了什么”

**抽帧可见**：官方完成态是三张已选内容的自由画布陈列，没有额外的流程箭头。能据此理解的是“这些对象已经上板”，不能把三角排布解释成作者演示了因果或处理顺序。

**制作推导**：按当前真实内容选择结果组织，不能把三卡陈列当作唯一终点。

| 要解释的真实关系 | 结果画面怎样设计 | 为什么不只是换了排版 |
|---|---|---|
| 从候选中选出一组 | 结果形成可核对的集合，保留来源身份及未选项；主项大、辅助项弱仅在内容确有主次时使用 | 观众能核对选了谁，而不是只看数量增加 |
| 材料支撑一个结论 | 结论占主要阅读位置，依据以短摘录与来源标记靠近相应论点；有对应关系再连线 | 位置与对应解释结论从哪里来，不把相关性画成因果 |
| 构成一个目录或对象 | 结果落进真实层级与接口，入口与附属内容用位置、缩进和形态区分 | 不同位置表达组成职责，不能散放成同等权重的三卡 |
| 具有执行先后 | 在有依据的步骤位置落位，当前步骤展开，其余保持定位；方向和连接只表达真实顺序 | 迁移结束后可以继续观察执行，而不是停在步骤名称上 |

先决定最终主体的边界、主要内容的读序、辅助信息的去向，以及下一镜需要保留的对象，再安排来源区。结果复杂到无法兼顾来源时，可以先迁移一个代表项，随后让来源让位，扩大结果。不能为了保留两栏外形把双方缩到都看不清。

### １．３　主对象、跟随对象和中段构图

**制作推导**：第一次需要观众理解“行变成另一种表示”时，选一个内容最容易辨认的对象完整展示选择、提起、迁移与落位。其余对象只需让人确认同类变化，可减少内部显露或合并为一次跟随；若三项分别有需要解释的差异，才逐项给阅读，不把“单主角”误写成永远只能一个对象动。

在主对象经过画面中央时，来源里的新高亮、下一对象起飞和结果区的连线都可能抢走视线。优先错开语义重的动作；允许低竞争的跟随并行。主对象清晰到位后，下一项的运动才接管焦点，已落位的对象不继续回弹。若时间只够一次完整迁移，就减少演示对象，而不是三项齐飞再靠旁白补说明。

起点和终点正确仍可能得到难看的中段。把飞行主体的完整外框、旋转角、模糊外扩及投影一起放进构图检查：

- 刚离开面板时，轮廓要与原行分开，不能贴着边缘像被切断；确认飞行层不会遮去按钮的关键操作反馈。
- 跨过两区之间时，主要对象的轮廓应能单独辨认；若与另一对象重叠，当前主体保持在前，次要对象的轨迹或起点时间让开。
- 行变高卡的阶段最容易突然占满空间，应检查变形后的上边缘是否扫过大标题，下边缘是否侵入字幕。
- 接近落点时，检查角度和过冲后的真实外框，不只看中心路径。已落位内容正在阅读，后到对象不能从它正文上横穿。
- 多条路径若交叉，先改对应落点、飞行高低或先后；先确定身份可追踪，再决定是否需要模糊。交叉点不能恰好同时进行内容替换。

这些检查落实为当前镜头的关键状态和实际观看问题，不新增必须提交的表格。静帧证明边界与层次，正常速度观看才能证明观众确实跟得住。

## ２．选择、提交与结果必须是一条能核对的链

**原卡给定**：示例在第１４／２４／３４帧依次选中三行，按钮在第５２帧按下；三行约在第５６／６２／６８帧开始拔起，每行起飞前有约４帧的提起过程。源片约１５０帧、３０fps。

**抽帧可见**：选中的并非连续三行，而是第一、第三、第四项。第二、第五项仍留在来源面板中。按钮出现与选择相应的数量，结果侧随后出现三张对应内容卡，并有已固定数量反馈。

**制作推导**：不要分别手写勾选动画、按钮数字和三张卡的数据。使用同一组选中 ID 派生它们，让选择、飞行实体、来源反馈及结果保持一一对应。若实际产品是复制／引用，不能为了符合“迁移”手法而删除原数据；先确定业务动作，再设计来源状态。

| 阶段 | 需要看到的变化 | 该阶段不应发生什么 |
|---|---|---|
| 逐项选择 | 光标抵达目标；复选框反馈；按钮数量更新 | 结果在提交前无理由出现，光标点在错误位置 |
| 提交确认 | 按钮短促下压或状态改变 | 来源面板整体跳位，破坏起点参照 |
| 拔起预备 | 当前行略放大、阴影变深，开始与表面分离 | 只把行透明度降为零，让它像被删掉 |
| 错峰迁出 | 三行依次越过容器边界，路径可追踪 | 来源裁切掉飞行实体，或同一项出现两份 |
| 形态交接 | 行的内容退去，卡片结构接管同一外壳 | 旧行与新卡的两套文字同时清晰叠放 |
| 落位收束 | 逐个到位、短暂制动，目的地内容清晰 | 已到位的卡继续模糊／摇晃，阻碍阅读 |
| 结果核对 | 来源显示已处理项，未选项仍在；结果数量一致 | 把实际保留的来源误描述为物理删除 |

源卡把原位变化概括为“塌陷成虚线留白”。**实际抽帧可见的是：处理过的行槽仍占有空间，内部变为带虚线边界的已上板提示。** 它不是整个列表无痕收紧。迁移时要区分文字退场、槽位占位和业务数据是否保留，不能把“必须塌陷”当作通用规则。

## ３．跨容器的坐标和遮挡先于动画参数

**制作推导**：来源面板通常会裁切内部列表，而飞行对象必须能越过这个边界。可以为迁移主体建立独立覆盖层，来源行、飞行实体和目的地卡片共享同一 ID；任何阶段只保留一份承担当前身份的主实体。

起点取当前行的实际矩形，终点取结果卡的最终矩形，两者先换算到同一个舞台坐标系。若用舞台缩放预览，屏幕 `getBoundingClientRect()` 的值不能直接当作设计像素；要除去外层缩放或进行逆矩阵变换。Remotion 任意跳帧时也需要可重建，不能依赖上一个播放帧触发的 DOM 状态。

建议的层级职责：背景与固定标题在底层；来源面板和目的地框架在各自稳定层；迁移实体在不会被来源 overflow 裁掉的覆盖层。内部遮罩只负责行／卡内容交接，不裁掉整段飞行。最前层不应还有无关装饰挡住主体。

起飞前实体要与来源行完全对齐，落定后与目的地完全对齐。若中途换 DOM 所属容器，应保持同一屏幕变换、尺寸和不透明度；更简单的方案是在同一覆盖层完成整个动作，结束后才无痕交接给稳定结果层。不要把重挂载造成的跳帧误当成“弹性”。

## ４．位置、尺寸、角度并非全部同时到位

**原卡给定**：飞行用 `spring(damping:17, stiffness:95, mass:0.9)`；路径是二次贝塞尔，控制点上抬约２２０像素；宽高比位置晚约３帧收敛。起飞前放大约２％并加深影子；各行约６帧错峰。

这里的重量感来自：先有脱离表面的准备，再移动主体，外壳形态稍后追上，最后制动。把所有属性同一帧线性补间到底，会失去这种前后关系。

**制作推导**：先定义起终点中心 `S、D`，控制点 `C` 位于两者之间且高于连线，用路径参数 `u` 求位置：

```text
position(u) = (1-u)²S + 2(1-u)uC + u²D
pathTangent(u) = 2(1-u)(C-S) + 2u(D-C)
```

屏幕 Y 轴向下时，上抬控制点意味着减小其 Y。２２０像素是作者演示的控制点抬升量，不等于轨迹最高点一定比直线高２２０像素。更换飞行距离、起终点高度后，应重新检查路径包围盒，防止卡片飞到标题上或越出画面。

位置与尺寸可以从同一个动作起点派生不同的局部进度：位置先走，宽高延后；同一 ID 仍维持一条动作链。不要把“同一个 spring”误解为所有属性数值和启动帧都必须完全一致。

弹簧可能过冲。如果直接拿超过１的值评估路径，会延伸到终点以外；这可以是有意的制动，也可能撞上邻卡。用实际布局决定位置是否保留过冲、是否单独限制路径参数。透明度必须限制在０至１，尺寸不能进入负值或产生不必要的超宽文字重排。

## ５．行到卡：外壳连续，内容分阶段交接

**原卡给定**：示例外壳约从 `626×104` 变成 `486×300`，圆角约从１８变为２４；行内容在局部进度约０．０８—０．４退去，卡内容约０．５—０．８显露。原卡另一处把旧内容撤净边界概括为约０．４５，实际实现应保证旧内容先净退，不把两个近似阈值当成不同模式。

**源码差异**：本轮可读实现用面板宽６５６减去两侧各２４，行宽实际为６０８，并非原卡的６２６。保留两种依据，不拼成同版精确参数；真实起点由当前行矩形决定。

外壳由扁长变为较窄较高，长宽比变化很大。这里需要区分三件事：

1. **位置和外形**：同一实体的中心、宽、高、圆角和影子连续变化。
2. **行内容排版**：短标题、勾选或标签按行布局，退场时保持其字形比例。
3. **卡内容排版**：分类、标题、说明、署名等按卡的最终结构布局，再在合适阶段显露。

**制作推导**：两套内部内容可以叠在同一个壳内，但每套都有自己的裁切与透明度。中途只露外壳或弱化内容，允许短暂留白；不必为了“不断字”让两套完整文字叠在一起。别把行内容通过 scaleX／scaleY 拉成卡内容，也不要在每帧改变文字容器宽度后任由自动换行到处跳。

使用弹簧进度驱动透明度时，对输入区间和输出都明确限制。仅在两端钳制数值，还要检查运动中是否反向穿越交接区，导致旧文字重新闪回。必要时给内容交接单独采用单调进度，保留外壳的弹性。

行和卡中应保留可认出的内容身份，例如同一标题、编号或语义色。不能飞出去的是一行操作名，落下来却变成无关的概念总结卡，否则连续运动掩盖了内容断裂。

## ６．落位、影子与速度模糊要同步收住

**原卡给定**：三卡的最终倾角约为负２．５°、１．８°、负１．２°；落位用约６帧的 `scaleY:0.97` 轻微压缩后恢复。速度模糊描述为 `amount:0.32、max:14`，仅在飞行段生效。**源码可见**：`Polish.SpeedBlur` 用每帧位移的速度乘 amount，再以 max 封顶，作为沿运动方向的 SVG 高斯模糊标准差；接近静止时跳过滤镜。因此１４是该实现坐标下的模糊上限，不是给任意元素固定写 `filter: blur(14px)`。

**抽帧可见**：中途行／卡带方向性拖影，落定的卡恢复清晰，顶边有细强调线，底下有柔和投影；右侧面板保持稳定。小倾角打破严整网格，但文字仍可读。

**制作推导**：

- 落地压缩的锚点应与接触边一致；若绕中心压扁，会像整张卡凭空变形。正文阅读性优先，可以只对外壳做极轻反馈或取消压缩。
- 起飞时阴影从紧贴面板变为分离阴影；落位后转为画布表面的稳定支撑影。不要从出发到结束始终挂同一团黑影。
- 若需要方向性模糊，方向可从逐帧实际位置差分计算，强度随速度变化；用未缓动的直线方向代替，会在弧线顶部拖错方向。位置变化包含弹性时，实际差分也更能反映减速和反向。
- 卡落定、文字需要被阅读时，模糊归零、角度归位、透明度稳定；邻卡继续飞行时也不该让已到位卡继续震动。
- 无法提供合适运动模糊时，先把路径与制动做好，不用固定模糊掩盖双字、跳位或低清素材。

**声音建议，未试听验证**：选择可有轻短反馈，提交是一个明确触发，三次落位声可随错峰区分，但不必每一项都加声。飞行声若存在，应随速度和落位结束，不持续覆盖后续解说。官方文件未检测到音轨，不能把这些建议写成原片听感。

### ６．１　实现正文与注释不一致时怎样判断

**源码可见**：整体取景实际是小幅 scale，没有注释所说的横向位移；落地压缩由固定偏移触发，并非检测首次越过终点；完成数量也由时间阈值产生。落地注释写４帧，表达式使用６帧。函数调用、注释、原卡与样片各是不同证据，不能互相代替。

**制作推导**：当前镜头需要左移，就要设计真实的取景变化和边界，而非认为照用相同倍率就已完成“跟随”。需要表现任务完成，就让状态依据当前真实事件产生；教学示意可以按固定时间安排，但不能把装饰计数当成软件确已执行成功。落地反馈应对齐本项目实际到位时刻，不能照抄源代码偏移再声称已经同步。

## ７．在口播教程中怎样改造

以下是原创设计推导，未实现。选取“一个目录包含入口说明与按需附属资料”这一组成问题。具体名称、必须项与可选项由当前教程资料核实；不是演示某个产品具有“批量加入画布”功能。

### ７．１　从内容确定视觉目标

观众容易误以为各类资料同样必需，或以为目录只是几张无关说明卡。镜头前只有分散的资料角色，镜头后应看懂：一个共同目录中，入口负责说明，其他资料按需要附属。借鉴的是连续身份、跨容器落位和阅读交接，放弃三卡散放、同等戏份和虚构的提交按钮。画面标记为机制示意，不能当作真实文件操作录屏。

### ７．２　先设计结果，再决定从哪里来

**原创结果布局建议**：左侧用一个有开口轮廓的目录容纳物建立共同归属，内部以缩进或细分支显示层级；入口条目位于最先阅读的位置，附属资料位于其下。右侧展开入口正文，保留文件页眉及名称，正文使用能被读懂的短行结构。两侧用入口条目的同一名称与强调标记保持对应。不要把目录画成黑盒，再仅用外部三张说明卡讲它的内部。

标题靠上，与目录左边界对齐；正文展开区获得最大的阅读面积。两者之间留出移动通道，底部留给当前视频的字幕。来源候选只在建立组成时短暂占用右侧，任务完成后退出，让同一空间转为正文近景。这样结果画面是“层级＋当前文件内容”，而不是“来源面板＋三张卡”。左右选择可以按实际文案调整，不能靠缩字维持比例。

**原创美术选择建议**：目录承托物与文档页共用哑光浅表面和细边界，环境比纸面稍暗，当前入口使用一处强调。目录轮廓负责归属感，正文行与文件页眉负责用途辨认；去掉说明标签后仍能看出容纳关系和可阅读对象。正文保持端正，目录外轮廓可有轻微厚度，文字本身不做透视。不要添加无依据的金属扣、锁、发光线路来暗示安全性或执行能力。

### ７．３　完整观看顺序与镜头接管

| 状态 | 画面怎样组织 | 主动作与焦点 | 下一步成立的依据 |
|---|---|---|---|
| 建立 | 目录轮廓在左；右侧候选中，入口说明先清楚，附属资料更弱 | 稳定正视，先认入口 | 观众知道即将进入的是哪一个对象 |
| 主对象迁移 | 入口条目从来源位置移动到目录入口槽位；来源身份在交接前保持可辨 | 主对象完整运动，其余不同时展开内容 | 同一名称、标记与轮廓说明是原对象，不是另生成一张卡 |
| 落位确认 | 入口对齐目录真实层级，阴影与边缘收稳 | 目录中的入口成为唯一当前重点 | 终点的缩进和共同容器说明归属，不使用随意倾角 |
| 按需补充 | 只有资料支持需要时，附属条目才进入各自层级；最小情形可完全不出现 | 跟随动作简化，避免重演完整主动作 | 不把可选资料的出现误画成创建目录的必经流程 |
| 正文接管 | 保留目录入口定位，右侧候选让位给同一入口的正文展开 | 焦点从已落位名称转到正文内部，其他条目收弱 | 迁移解释组成，正文展开负责真正的内容解释 |
| 接下一镜 | 继续放大或强调正文中当前讲解的字段／步骤 | 静下来阅读，必要时进入同一文件近景 | 下一镜沿现有对象推进，不重新淡入另一套说明卡 |

迁移过程中不要把正文压缩进扁行再拉伸出来。扁行只保留可追踪的名称与身份，正文在独立阅读区按最终布局出现。若需要展示来源仍存在，就明确这是引用或表示迁移，不制造原文件被删除的暗示。需要讲述真实创建过程时，应改用有依据的操作与结果；本示意不能证明文件已经写入。

### ７．４　为什么不采用另外两种容易想到的做法

**不把入口、脚本和参考资料做成等大的三卡**：它会削弱入口与附属之间的角色差别，也不能证明共同目录归属。**不把整个目录做成爆炸图**：当前解释的是文件层级与阅读入口，并非厚度组成；大透视会增加阅读成本。只有后续内容确需讨论实体空间或物理分层，才考虑拆层镜头。

这些取舍针对本例的表达问题，不是对卡片或三维的全局禁令。字体实测、最终构图、完整动作与下一镜衔接仍须实际制作验证。

## ８．失败诊断

| 失败画面 | 可能的结构问题 | 优先修正 |
|---|---|---|
| 只看到左侧卡出现，不知道从哪来 | 没有选择、触发或连续身份 | 补上有依据的操作链，保留可追踪的文字／编号 |
| 刚出面板边缘就被切断 | 飞行层仍受来源 overflow 控制 | 统一到独立舞台覆盖层，内部裁切与外部飞行分开 |
| 起飞或落位突然偏一下 | 两容器坐标系、缩放或锚点不一致 | 用同一舞台坐标比较真实起终点矩形 |
| 飞行中两套文字糊在一起 | 行内容退场与卡内容显露重叠 | 分开交接窗口，必要时改成单调内容进度 |
| 字在途中不停换行 | 外壳插值直接驱动正文自动排版 | 两套内部布局独立，按阶段揭示，不拉伸字形 |
| 三张卡像复制粘贴／最后一张掉队 | 同时起飞，或错峰超过可读动作窗口 | 按实际路径与语义调错峰，不盲用统一间隔 |
| 来源变化暗示错误业务行为 | 把引用、复制、移动混成一种动作 | 按真实语义处理原位、状态和数量 |
| 飞得热闹，结尾仍像 PPT | 动作只用于进场，没解释结果关系 | 落定后继续表达真实结构或操作结果，不能仅换卡片文案 |

## ９．怎样判断设计有用，而不只是技术正确

下列是本技法的观察问题，沿用项目既有设计审查和观看要求，不新增人工 Gate。每个问题都要指出具体对象、状态与结果，不能仅回答“高级、流畅、统一”。

| 检查对象 | 成立的画面证据 | 失败时回到哪里改 |
|---|---|---|
| 内容目标 | 来源、选中项与结果可以对应；结果位置表达真实集合、层级或步骤 | 只见三次飞行：先改结果关系，再重排动作 |
| 完成态设计 | 暂停时有明确的第一阅读对象；字体、轮廓、表面与留白共同支持主次 | 三卡权重平均、全靠旁白解释：调整造型、内容层级和占用空间 |
| 中段构图 | 主对象轮廓连续；交叉、变形和过冲时仍能辨认；标题与字幕不被扫过 | 中段拥堵：改路径、落点或先后，不靠加深模糊 |
| 动态注意力 | 正常速度下能从选择跟到结果；次要动作不抢走尚未完成的阅读 | 眼睛追不上：减少并行重点与重复动作，保留理解窗口 |
| 真实内容 | 实际中文、最长条目和正文内容可读，字段与业务含义均有依据 | 占位英文好看、换内容崩溃：回到排版和取景，不继续缩字 |
| 衔接与声音 | 结果供理解后接到实际下一镜；若配声，触发和结束对应动作，口播保持清楚 | 镜头像孤立 demo：设计结果接管；有声错位则对齐实际时间 |

静态抽帧和源码能够支持布局与机制分析，不能证明正常速度的焦点转移、声音同步或商用成片质量。中文字体、实际长标题、非等长行及完整动态仍待实现验证；本文不能据此标记为商用级已验参考。相关方法见 [界面与数据动作](../interface-and-data-motion.md)。
