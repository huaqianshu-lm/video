# 界面拆层与复合：让构件真的属于同一个空间

拆层镜头适合解释“这个对象由什么组成、各部分原来在哪里、怎样重新组合”。高质量的关键不是把几张卡片沿 Z 轴拉开，而是让原位、遮挡、材质、投影、注记和复合共同证明这些构件属于同一个对象。

来源：[Shotcraft 原卡 A 式](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/camera/space-camera-moves.md)／[exploded-view 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/exploded-view.mp4)。本文只研究其中的 exploded-view，不混入俯冲镜头。**原卡给定**表示作者描述；**源码可见**表示实现表达的关系；**抽帧可见**表示样片静态状态；**制作推导**是原创设计及实现建议。已阅读准确 demo 和下表相关视觉实现，未运行上游代码、未正常速度完整观看；原卡也声明真实内容仍需回验。不是已验模板。

## １．先决定是否应该拆层

适用对象要能回答两个问题：这些部件在完整对象中有什么位置关系？分开后，能解释什么原来难以看清的组成关系？

真实界面可以按侧栏、主视图、辅助区等拆分来解释功能组成，但这种展示是空间示意，不证明软件内部真的物理堆叠。串行任务、因果链、权限继承等关系通常需要路径或过程图；仅为炫技堆成五层，会制造错误理解。

**抽帧可见**：官方样片用一块斜置的完整仪表板建立身份，随后可见侧栏、主图表、助手区、指标区和顶部窄条被分离；外侧注记解释它们。文字仍主要在画面平面上阅读，界面本体则保持透视。

### １．１　先决定观众需要认识多少部分

**源码可见**：实现是一个底板加五个可动功能区，指标区内部又包含三张指标卡。顶部注释概括成“六层”，并不等于六个可动层，也不是把每张指标卡单独升起。功能分区的面积、内容形态和位置各不相同，不能把它理解为五张等尺寸白卡。

**制作推导**：只拆本段需要解释的部分，其余可以作为整体上下文。要讲三项职责就先评估三个分区，而非默认复制五层；要教某项具体操作，则组成展示结束后把阅读权交给该部件的正视近景。关系是上下游、权限继承或时间顺序时，Z 高低不能代替真实关系图。

先问每个部件是否需要观众认出名称、读懂职责，还是读清内部原文。这是三种不同负担。若同时要读几个部件内部的小字和外侧注记，就应减少同时展开的内容或拆成相连镜头。能在五秒多演示一次爆炸动作，不意味着五秒多足够讲完五个功能。

## ２．构图先容纳“最大展开态”

**原卡给定**：示例以 `perspective: 2400` 和约 `rotateX(54°)、rotateZ(-34°)` 建立斜俯视；展开时整体倍率约从０．５６退至０．４７，同时下移，悬停时再旋转约１０°、俯角减小约４°。

这些量共同处理一个问题：构件向上展开会把占用范围推高，相机若仍按完整页取景，顶部构件容易出画。不能只调 Z 距离，最后再把整个场景缩到文字全看不清。

**制作推导**：先在最大展开态摆好以下四组边界：

1. 底板与所有构件的投影包围盒，包括靠近镜头后变大的前层。
2. 左右注记栏和最长说明文字，避免贴画边或撞字幕。
3. 从构件外缘到注记栏的引线路径，预留折点而不是临时穿线。
4. 阴影扩散区域；大软影不能被外层容器裁成矩形。

然后回到完整态检查：主体是否仍足够大、是否能辨认内部结构。若两态难以兼顾，减少需要展开的构件，或分段检查局部，不要继续增加层数。

### ２．１　主光、表面与背景要组成同一个环境

**源码可见**：实现使用冷白／蓝灰环境、白色界面和钴蓝强调，背景主光斑在偏左上，补光偏右下。底板使用蓝灰渐变与独立的较暗背片，浮层以薄的蓝灰背片和亮边交代厚度；图表、数值与助手区有不同的内容轮廓。层投影落在底板上，随高度向右下偏移并扩散。它是 CSS 平面、颜色和投影共同构建的空间示意，不是使用真实光源得到的三维材质。

**制作推导：按面分配明暗。** 正面是承载内容的浅哑光面，边缘是略暗的窄厚度带，底板是更低对比的支撑面，底板下方的大软影把整组放进环境。所有部件遵守同一光向，不能左边构件向右投影、右边构件又向左投影。需要更多立体感时，先检查厚度与接触关系，而不是同时加金属反射、玻璃折射、外发光。

**制作推导：背景亮度服务轮廓。** 最亮的表面与背景之间仍需有可见分离；白底白面粘在一起时，优先调整环境明度、薄边和支撑影。背景柔光大而弱，注记附近保持平静，不把光斑放在细字背后。暗场也可以成立，但应重新设计正面、厚度和影子的明度关系，不能只把背景切黑、留下原来的浅灰投影。

**制作推导：强调给当前要理解的部位。** 先靠面积与形状认整体，再让当前部件的内容、边缘或锚点获得少量强调。其他层仍可见，保持归属线索，但不同时闪烁。钴蓝只是原例选择；颜色应由当前视频风格统一分配，不为五层各发一种强色。独立注记保持清楚的字重和对比，编号弱于名称，职责说明弱于当前名称，但仍能读。

### ２．２　摄影机为什么动，以及什么时候停

| 观察阶段 | 机位要解决的问题 | 不应发生的事 |
|---|---|---|
| 完整态 | 先认出一个完整对象及主要分区；必要时先给正视全貌再倾转 | 一上来就是陌生薄片，观众没有原物记忆 |
| 离位中 | 退让与下移给升高构件留空间，同时保留底板原位 | 只拉远到所有内容都变小，或最高层穿出画边 |
| 结构揭示 | 小幅视角变化使前后高度产生可辨的视差 | 旋转与展开同时抢主角，转到另一侧却没有多揭示任何关系 |
| 职责阅读 | 当前锚点、部件与注记稳定；可以停相机 | 文字已经出现，相机还持续环绕，迫使观众追线找对象 |
| 复合确认 | 让观众看见部件准确归位并恢复同一整体 | 用大扫光或闪白掩盖接缝与错位 |
| 正文接管 | 将需要读的部件转到正视、放大到实际可读，保留其身份 | 在斜视远景里硬读小字，或直接换成无关说明卡 |

这里的相机语言可以由世界变换实现；重点是观察到的关系，不是代码是否真的实例化相机。展开时已经足够说明间距，就不必为“电影感”再加一圈旋转。进入正视近景时，先确认所选部件，再协调姿态、位置与尺度，防止一边急转一边换内容造成身份断裂。

## ３．完整动作链与各段职责

| 阶段 | 主体怎样变 | 观察位置与辅助信息 | 应保留的阅读关系 |
|---|---|---|---|
| 建立整体 | 完整界面落在底板上 | 斜俯视，暂不铺满注记 | 先认出对象，再解释组成 |
| 构件离位 | 各构件沿页面法线分离 | 整体适当退让、下移 | 离位前后仍能对应原来位置 |
| 最大展开 | 远端构件抬得更高，近端避免挡住远端 | 微小角度变化带出视差 | 看见构件间距，也看见底板上的原位 |
| 注记建立 | 主体以稳定状态供观察 | 锚点出现、引线延展、文字随后显露 | 先定位“指哪里”，再读“是什么” |
| 注记撤离 | 不再需要的文字和线先退出 | 为复合路径清场 | 不让移动构件穿过悬空注记 |
| 逆序复合 | 构件回到各自的准确原位 | 视角与倍率向完整态收敛 | 看到确实装回同一个对象 |
| 接触收束 | 底板与构件成为整体 | 短促接触反馈后稳定 | 完成感来自接触，不依赖整屏闪烁 |

**原卡给定**：全段示例约１７０帧。展开用弹簧 `damping:15、stiffness:120`，构件约５帧错峰；注记先用约８帧收走；复合为约１４帧 ease-in，构件约３帧逆序错峰。示例的简短悬停只供展示，不代表当前教程已经获得足够解释时间。当前资料要讲几部分、讲多久，仍由真实口播与 Timeline 决定。

## ４．分层素材与原位：先解决“拆开的到底是什么”

**原卡给定**：需要每个构件独立素材，并按完整页面网格绝对定位；一张完整截图不能直接形成独立构件。

**制作推导**：可以使用独立截图、SVG 或 React 重建构件，但要同时保存它们在完整对象中的局部矩形 `x、y、w、h`。所有构件的 `z=0` 应能重建同一张完整页面，不应在回位时留下双边框、重复文字、露底缝隙。

如果底板继续保留完整截图，升起的构件会在原位留下第二份相同内容；这会被读成复制而非拆层。底板应是去除对应内容后的支撑面，或在构件离位时遮去原内容、露出有解释作用的槽位。擦除区域要跟随页面坐标，不可在屏幕坐标里贴一个矩形补丁。

构件整体可以有厚度边，但不要把小块文字也挤成厚重积木。材质先统一：这里是界面功能分区的示意性薄面，而非玻璃、金属、纸张同时出现。没有真实依据，不增加螺丝、芯片或内部结构来假装工程拆解。

## ５．展开量、遮挡与弹簧怎样配合

**原卡给定**：示例五层的 Z 位移约为１５０／２７０／４００／５２０／６４０；页面远端的构件分配更高位置，避免近端升起后挡住远端。

它们不是一个按数组下标自动生成的阶梯。Z 高度要配合构件在页面上的原始位置、面积、倾角与视角共同决定。面积很大的前层尤其容易遮住后层。

**制作推导**：为每个构件独立保存 `baseRect、targetZ、startFrame`。展开时局部进度驱动法线位移，少量相机退让则使用全局展开进度。两者有协调关系，但不必让每层在同一帧达到同一相位。检查中途的相互遮挡，不能只检查完整态与悬停态。

弹簧表达离位后的制动与轻微稳定过程。若过冲造成前后层碰撞、注记跳动或文字持续震动，应提高阻尼、减少运动量或改变错峰；不要因为源卡给了一个弹簧参数就把它用于所有尺寸和质量的对象。悬停进入阅读后，可以完全停止。

视差来自观察角度变化时不同高度构件的投影差异。分别给五层做五种无关平移也会“动”，却不能维持同一个空间。保持一个共享世界，先用相机／世界姿态定义观察，再用构件 Z 定义组成关系。

## ６．厚度、接触影与远离底板的影子

**原卡给定**：各层有厚度边；底板保留虚线插槽；投影随构件抬高而下移、变软、变淡。

**抽帧可见**：在中段，界面构件不是纯粹的无阴影白矩形，底板和浮层之间存在软影与薄边。整体浅色环境中，蓝色折线、锚点和注记承担辨认作用，没有给每层加不同的强光晕。

**制作推导**：把阴影分成两个角色处理：

- 接触线索：构件贴近原位时，紧贴边缘的局部暗部说明它落在支撑面上；离位后不应仍保持同样紧密的接触影。
- 底板投影：始终落在底板平面中，位置、扩散和透明度随高度变化。若直接把同一个 CSS box-shadow 粘在浮层上，影子会跟着构件漂在空中。

可在底板坐标系单独画投影，令偏移、模糊和透明度由高度派生；例如高度越大，投影偏移和扩散越大、透明度越低。这是可控制的示意模型，数值由当前光向与尺度调校，不当作真实光学模拟。支撑面本身的落地影另行处理，不跟浮层一同升高。

复合接触帧，原卡给整组约８像素下沉后阻尼恢复，并让接触影短暂收紧，随后扫光。迁移时可保留“位移与影子同步确认落座”的关系；下沉、扫光都不是必加项。以精确阅读为主的教程，轻微接触变化甚至完全无弹动也可能更合适。

## ７．注记锚点必须来自同一个投影

**原卡给定**：引线从构件外缘中点的三维投影出发，注记分左右两栏，水平引线在接近文字栏处转折；线约８帧描出，文字约１２帧升起，组间约６帧错峰。示例注记标题约４４像素、说明约３０像素；其表格另提醒小字不足，不能把这组示例字号当作可读性已验结论。

**制作推导**：每个锚点先在构件局部坐标中定义，再经过与构件相同的完整变换：

```text
clip = P × V × W × L_i × [anchorX, anchorY, 0, 1]
screenPoint = viewportMap(clip.xyz / clip.w)
```

这里用列向量约定：`L_i` 包含构件自身位移，`W` 是页面／世界变换，`V` 是观察变换，`P` 是投影。使用 CSS 时，必须同时复现 transform-origin、变换顺序、父层变换与 perspective-origin；只有角度相同仍可能对不上。不要把这段示意矩阵直接当成任意 CSS 结构的现成实现。

注记文字可以放在屏幕平面以保持端正；引线起点跟随投影，末端跟随文字栏。这使主体可以被斜看，说明仍能正读。若锚点直接写死为屏幕坐标，稍微环绕就会脱离构件。

选外缘靠注记一侧的锚点，避免线从构件中心穿越其他层；必要时调层高、换注记侧或减少同时注记数量。世界层和屏幕注记层要分开，防止投影后的坐标再被父层变换一次。装回前先撤线和说明，避免悬空线在原处乱指。

### ７．１　从准确实现里保留方法，同时识别它的局限

**源码可见**：`camAt` 将展开高度与整体退让关联，悬停改变观察角度，复合后又把整组移向右下，为左上收尾文字留位置。展开倍率还叠加全段小幅推进，因此０．５６与０．４７不是每帧最终倍率的完整描述。注释里的起始 Z 转角写负３２°，表达式则先从负３４°趋近负３２°再叠环绕；应区分局部阶段与整条取景轨迹。

**源码可见**：五个构件按逆序复合，最终落座表达式为 `108 + (5-1)×3 + 14 = 134` 帧，与顶部注释的１３２帧不同；接触反馈由实际计算出的落座帧派生。注记虽每条约８帧撤离，但五条错峰撤净不在同一帧，并与部分复合过程重叠。当前教程若要求先读完再复合，应重新安排，不把原卡一句“注记先撤”误读成所有注记必须在首层移动前完全退出。

**源码可见**：注记取四角的投影后，按屏幕左右排序，选择外侧两个角的中点作为引线起点；每侧按投影高度排注记，保持间隔，底部溢出时整列上移。它解决了当前短英文的基本分布，没有对任意中文长注记提供完整的二维避让。旋转幅度变大还要检查外缘选取是否换边跳动。迁移时依据实际长文案计算文字框与线的碰撞，不能只保证锚点坐标正确。

**源码可见**：浮层的底板投影按高度增加偏移和模糊，透明度同时受升起进度影响，不能概括成从离位第一帧就单调变淡；底板下的大软影负责整组接触。扫光被放在底板内并裁切，不能据此推断所有浮层正面都接受了同一次光照。若需要当前主表面反光，应设计正确的承载面与遮挡，不凭原代码已有 `Sheen` 就声称材质照明完成。

这些差异用于理解画面如何形成，不要求重现上游每个实现选择。每项时序都应回到当前对象的实际到位、阅读与接管时刻；具体像素和角度仍只属于该示例。

## ８．如何收回，同时给下一镜留下依据

**抽帧可见**：完整样片后段撤掉注记、构件复合，左上出现总结短句；对象没有被替换成另一个全屏版式，仍保留之前的空间身份。

**制作推导**：复合结束时应核对每个构件的局部边界、底板轮廓与影子是否回到一个完整对象。不要用全屏白闪遮住错误回位。下一镜如果解释某一部件，可以先回整体确认，再转到它的正视局部；若仅总结组成，可保持完整对象稳定并给结论让出空间。总结文案必须来自当前资料。

大角度斜视更擅长交代组成和形体，小字号界面读数则需要另留正视窗口或近景。不能拿“电影感”替代对实际文字的可读性判断。

## ９．原创演绎：同一份说明书中的名称、描述与步骤

以下是原创设计推导，未实现。教学内容是：一份能力说明文件顶部有名称和描述，正文写执行步骤；名称用于识别，描述说明适用范围，正文规定怎样做。实际字段、原文和用途必须有当前资料依据。此处将文档分区空间化以解释职责，不声称它们是三份文件、物理堆叠或软件处理流水线；画面保留“结构示意”的身份。

### ９．１　先判断为什么值得拆，再设计结果

观众可能把三类文字看成一大段说明，不清楚各自作用。展开态要让人同时认出“同一文件中的三个区域”与“它们的不同职责”。如果当前任务只是逐行朗读原文，正视高亮已经够用，应放弃爆炸图。采用拆层的理由是先建立整体组成，随后把注意力交给描述或正文的实际写法，而不是展示三次升起。

**原创布局建议**：完整态是一张带文件页眉的长文档面，名称、描述和步骤沿原文顺序排列；展开时三个区域仍保留各自的局部位置，沿共同法线抬出，底板显示它们原来的边界。名称区短、描述区按真实文案占高、步骤区保留编号与行距，不做等高三卡。展开后的主体偏向一侧，另一侧只给当前需要解释的职责注记留阅读空间。完成解释后再回成一份连续文件，避免结尾仍像三张各自独立的说明卡。

**原创美术建议**：采用统一的文档表面，正面偏亮、薄边略暗，底板比正面更低对比；正文端正，展开时不为制造厚度给每个字挤出侧面。字段名可用等宽角色，中文说明与步骤以连续阅读为主，编号和名称服从同一基线。环境柔光从同一方向建立，阴影落在共同底板；当前区域只用一处强调，其余保持可辨。保留文件身份和原文结构，不添加齿轮、电路或处理进度来虚构执行含义。

### ９．２　按观众认识安排取景和动作

| 状态 | 画面组织与观察位置 | 主焦点与信息增量 | 下一步的依据 |
|---|---|---|---|
| 认整体 | 先正视或轻斜显示文件页眉与三处原文区域 | 确认这是一份文件，不要求同时读完全文 | 名称、描述、步骤都有可追踪位置 |
| 倾转与离位 | 将整张文件转为能看见薄边的姿态，随后各区沿共同法线分开；取景协调退让 | 先跟当前讲解区域，其他区低竞争跟随 | 原位槽与文件页眉保留共同归属 |
| 看组成 | 停在最大展开态，用空间间距露出原来难分辨的区域边界 | 看懂三个区域职责不同，顺序仍与原文一致 | 注记从对应区域外缘连接，不穿过正在阅读的文字 |
| 读当前职责 | 先让一处注记可读，例如描述负责适用范围；其他注记按需要简化或不出现 | 一次读一个关键区别，主体和引线停止晃动 | 具体字段及解释互相对应，不把“名称在上”画成“名称先执行” |
| 撤线复合 | 当前解释完成，注记退出，三个区域准确归回原位 | 重新看见它们属于同一份说明文件 | 不用闪光掩盖边界，文件不换名称、不重排正文 |
| 正视近景 | 保留当前描述区域的身份，协调转正与推近；其他内容仍作上下文 | 阅读实际描述如何规定使用边界 | 下一镜从这一原文改写或对照实际请求继续，变化须有资料支持 |

不默认在很短一镜里完成三份职责的全部朗读。真实 Timeline 容量不足时，第一镜只建立组成，第二镜沿同一区域正视阅读；也可只抬出当前区域，另两区留在底板。选择哪种取决于本段信息，不按上游层数或总帧数机械裁剪。需要展示原文改写时，先完成空间复合，再在正视状态更新，避免文字变化和三维归位同时发生。

### ９．３　最大展开与中段应具体检查什么

展开态里，三个区域的投影轮廓都要有可辨的分离边，且能看见相关原位。前方较大的步骤区如果挡住后方短字段，先联合调整层高、观察侧与间距；不要单独把被挡层横移到另一个无对应位置。若既无法看见组成又无法保留足够主体尺寸，就减少同时展开的区域或分镜处理。

离位和复合途中检查完整外框、厚度边与底板影，不只看中心点。弹性过冲时，浮层不能穿过另一层；最靠近镜头的边不能侵入标题或字幕。引线开始出现时，锚点已经能稳定对应；正文需要读时，不让其他区新升起吸走视线。所有这些都应在当前实际文案和字体下检查，短英文占位不能代替长中文。

**取舍**：不直接使用官方仪表盘，会把文档教学变成产品展示；不让三个区域各用一种材质，会削弱同一文件身份；不保留全程环绕，会增加职责阅读负担。此例借的是完整对象、离位对应和复合接管的方法，实际构图与内容重新设计。

## １０．失败修正

| 失败画面 | 常见原因 | 修正方向 |
|---|---|---|
| 看起来只是五张漂浮截图 | 没有共同底板、原位或厚度线索 | 先让 z=0 重建完整对象，再增加离位关系 |
| 前层遮住后层 | 只按数组设置 Z，没有检查投影 | 联调层高、构件大小与观察角度；检查运动中段 |
| 构件升起，原位还是同一份内容 | 完整截图作为底板，未处理重复 | 去除对应底图内容，或显露有意义的原位槽 |
| 引线环绕时飘走 | 锚点与 CSS 不共享变换，或重复变换 | 逐层对齐局部点、世界点和屏幕点 |
| 注记像贴在斜坡上读不清 | 说明无必要地跟随主体透视 | 说明留屏幕层，引线连接三维锚点 |
| 影子像浮层背后的脏边 | 投影跟着构件走，没落到底板 | 把底板投影与构件厚度／接触暗部分开 |
| 合体像软性淡入 | 缺少明确的到位与接触变化 | 准确回位，安排适度制动与接触线索，不必抖屏 |
| 动作很大，却不知道讲什么 | 功能组成与执行过程混淆 | 先明确解释关系，必要时换成过程图或真实操作 |

## １１．怎样判断拍出了组成，而不只是三维效果

沿用项目既有设计审查与观看要求，不新增人工 Gate。要指出具体部件、画面和可见关系，不能用“有空间感”代替证据。

| 检查对象 | 能证明成立的画面 | 失败时先改哪里 |
|---|---|---|
| 解释目标 | 不依赖 Z 高低猜顺序，能指出各部件原位、职责及共同归属 | 像流程或独立卡片：重新确定关系与载体 |
| 静态美术 | 完整态与展开态各有明确主体；薄面、厚度、背景与阴影一致 | 白面粘背景或材质混杂：先调明暗与表面，再加效果 |
| 中段空间 | 实际运动中层不穿插、关键边界不被遮；底板影不悬空 | 只有终帧正确：联调层高、机位、错峰与投影 |
| 观众视角 | 先认整体，再看组成，读职责时稳定，内部原文最终获得正视近景 | 旋转热闹但无法解释：停相机、减少同时内容、重新分镜 |
| 注记与真实内容 | 每条线指向正确部件，长中文不撞线、不越界；内部内容有依据 | 短英文成立、中文崩溃：重排文字框和取景，不继续缩字 |
| 正常速度与声音 | 首次观看能跟到当前区域，复合接触清楚；若配声则随分离／接触发生且不压口播 | 追不上或声画脱节：减少并行动作，重排真实到位与阅读窗口 |
| 衔接 | 正视近景延续刚解释的部件与内容，后续有实质信息变化 | 结束成孤立技术演示：先补主体接管与下一镜 |

**声音建议，未试听验证**：若采用声效，分离可用轻短的离面声，复合用与薄面质量相符的克制接触反馈；不让每层都像重金属砸落，也不以持续呼啸填满阅读段。现有官方文件未检测到音轨，不能把这些写成原片听感。

源码和抽帧支持机制及构图研究，不证明动态手感、正常速度阅读和声音同步。当前原创实现、实际中文注记、最长说明、中段遮挡及完整衔接仍待制作与观看，不能宣称已有可复用模板或达到商用成片对标。相关方法见 [机位与空间叙事](../camera-and-staging.md)。
