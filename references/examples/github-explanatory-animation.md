# GitHub 案例：让图形变化对应内容变化

这里研究具体场景及其实现依据，补充代码差异、表示对应、图层关系、搜索范围和反馈传播的表达方法。所列项目有作者提供的成片、预览或交互入口；既有研究核对了仓库说明、下列源码片段及三张官方示例图，未完整播放成片、运行仓库或操作交互。源码能支持状态关系和动作组织判断，不能代替正常速度下的视觉与声音判断。迁移示例均为设计推导，尚未在本项目视频中验证。

以下保留原固定来源；追加研究另外读取了可访问分支的嵌入矩阵场景、视差组件、layers 场景、Code Hike、频谱与信号代码。分支正文未与原固定提交逐字同版校验，不能把新观察冒充同版原片实测；二分搜索固定原卡本轮未重新取回，相关旧依据保留，新增教学演绎独立核对数学关系。所有布局、时序改造均标为原创推导，不搬运上游源码与业务文案。

## 1．3Blue1Brown：词表到嵌入矩阵的对应

来源：[视频场景仓库](https://github.com/3b1b/videos)；[IntroduceEmbeddingMatrix 场景](https://github.com/3b1b/videos/blob/306a1346a356c7a7b097875ceb51c5cd67d0a56c/_2024/transformers/embedding.py#L341)。成片检索入口见[作者视频站](https://www.3blue1brown.com/)。

**资料依据**：已读该场景第341～463行。词表先纵向排列，使用省略号表达未展示部分；随后同一组词移到矩阵上方并与各列对齐。逐列解释时，对应词和列保持高亮，其他项降低透明度，最后恢复全貌。这是源码定义的变化链，未核对其与最终发布片段的逐帧一致性。

**可迁移方法**：从熟悉表示转到抽象表示时，保留对象身份，并通过位置对齐交代映射；局部高亮同时作用于两端。用省略结构表达规模，不把全部内容挤进画面。

**教程设计推导**：解释配置表如何成为运行参数时，让同一字段移动到对应参数列旁；选择一项时，同时突出来源字段、参数值和有依据的行为结果。先建立对应，再解释局部。

**失败条件**：对象只是飞向一张无关的新图；词、列、结果错配；示意矩阵被当成真实维度。这里的词表教学抽象不等同于所有实际模型的分词方式。仓库亦说明旧场景可能依赖旧版 Manim，不据此承诺可直接运行。

### 几何映射与阅读先后怎样配合

**源码补读**：[可读分支场景](https://github.com/3b1b/videos/blob/master/_2024/transformers/embedding.py) 中，同一组词生成目标布局后逐项对齐列；列框由列本身求得，选中时两端一同提高对比，其余降低。随后还能把一个词和对应列单独复制为局部检视，同时保留整体定位。这是身份、几何与焦点共同变化，不是让两张图无关地切换。

**原创推导**：设计配置项→参数列的镜头时，先确定每个字段的稳定身份与目的地，再求两端位置。列名、值与单位共同排列，不能只对齐标签中心却让数据列错一格。省略结构应两端对应，不能原列表保留省略号、新矩阵却按全部真实数据填满，造成规模误解。

完整调度可以是：先看少量字段和其归属→一项在两端同时定位→相同规则扩展到其余项→单项成为主阅读区→恢复整体核对→沿该项真实行为接下一镜。中文列名过长时采用端正标签或扩大当前项阅读区，不照用原例斜排英语。

美术先让原表示与新表示具有不同但可辨的结构，使用同一身份标记连接；括号、表格线和列框比正文更轻，当前列的一处强调就够。移动中检查整列、括号和标签的外框，避免只看列中心。通过时能从任一端找回另一端并解释映射；数值流动与闪光不作为模型实际计算证据。更完整的表示设计见 [原理解释](external-explanation-design.md)。

## 2．Motion Canvas：Smooth Parallax 的共同驱动与层间差异

来源：[官方案例仓库](https://github.com/motion-canvas/examples)；[作者成片入口](https://www.youtube.com/watch?v=c_3TLN2gHow)；[Parallax 组件](https://github.com/motion-canvas/examples/blob/8ffefed144368d33de4b0e451894c718eb95d574/examples/smooth-parallax/src/components/Parallax.tsx)；[官方缩略图](https://img.youtube.com/vi/c_3TLN2gHow/maxresdefault.jpg)。

**资料依据**：组件用共同的相机变量和各层比例计算横向位置，并含像素网格取整与重复铺排。已查看缩略图：左侧相机符号与多条纵向平面对照，右侧为叠合的蓝色块面；缩略图仅支持构图判断，不是实际运动证据。

**可迁移方法**：层次运动由共同参照和相对差异建立。先交代哪些对象处于不同层，再解释相机变化与各层位移的对应；不能把各对象独立漂浮等同于空间感。

**教程设计推导**：解释界面中的内容层和固定工具层时，先建立层的身份，再用同一个观察变化展示其相对运动。若内容没有空间关系，就使用平面布局，无需附加视差。

**失败条件**：正文、字幕随背景漂移；随意设置速度让前后层矛盾；循环纹理接缝显露。案例中的像素取整属于特定画风条件，不推广为通用规则。

### 共同相机不等于每层独立设一个漂浮动画

**源码补读**：[可读分支组件](https://github.com/motion-canvas/examples/blob/master/examples/smooth-parallax/src/components/Parallax.tsx) 的位移包含 `camera × (ratio-1)`、按纹理周期取余，以及原值与像素网格取整值之间的混合。它有自己的基准约定，不能把 ratio 的数值直接解释为米制深度；周期与重复铺排服务该像素场景，不是普通教程背景必须复制五份。

**原创推导**：若讲固定工具与移动内容，最终画面先明确它们各自的锚定关系。正文滚动或观察范围改变时，工具位置有理由保持；要讲真实空间层次，才让前后部件按同一观察量产生差异。字幕与说明位于屏幕阅读层，不跟着环境慢漂。

可用简化模型 `x_i = baseX_i + k_i × cameraOffset`，但各 k 的含义由设计约定，不假装物理透视。图标、标注与其主体共享同层变换；必须正读的文字另给稳定阅读位置。先建立各层→改变一次共同观察量→停住比较相对位移→回整体或由当前内容接管；不让连续往返代替解释。

美术通过层轮廓、前后遮挡和低竞争环境建立距离，不能只给每层同样影子。中段检查背景边界、循环接缝和前层是否遮正文；前景运动大也不等于前景应是最大阅读重点。通过时能指出谁固定、谁相对移动以及为何如此；只有背景在流动，不足以证明空间关系讲清。

## 3．Motion Canvas：Deferred Lights 的拆层、合成与单层解释

来源：[官方案例与成片入口](https://github.com/motion-canvas/examples#deferred-lights)；[作者成片](https://www.youtube.com/watch?v=R6vQ9VmMz2w)；[layers 场景](https://github.com/motion-canvas/examples/blob/8ffefed144368d33de4b0e451894c718eb95d574/examples/deferred-lighting/src/scenes/layers.tsx)。

**资料依据**：已读完整 layers 场景。代码先逐层建立平面，再改变层的位置、尺寸及观察角度；在 composite 标记后使各层回到叠合位置，之后重新拆开；single_layer 段移走其他层，保留中间层。未核对相关贴图与最终成片，不推断每层实际材质和全部渲染含义。

**可迁移方法**：拆解不仅展示“有哪些部分”，还要让观众看到这些部分怎样组成同一结果。拆开时保留空间顺序，合成时保留对应，解释局部时让其他层有明确退场理由。

**教程设计推导**：解释“资料、规则与输出”如何形成结果时，只有内容确实存在叠合关系才使用叠层；若是先后执行，应改用流程。对于真实分层的界面，可展示完整画面 → 拆开内容层 → 聚焦一层 → 恢复合成。

**失败条件**：将执行顺序画成空间层叠；拆开后身份丢失；仅靠层片旋转显示技术感，却没有解释组合关系。源码里的标记及秒数不成为当前视频的时间基准。

### 拆开、合成与孤立一层，是三种不同问题

**源码补读**：[可读分支 layers](https://github.com/motion-canvas/examples/blob/master/examples/deferred-lighting/src/scenes/layers.tsx) 在 `composite` 时将各层位置回到共用平面、协调改变尺度和观察姿态；`single_layer` 时其余层移走，保留中间层。标题与图标独立于三维层。未取回其 three/layers 依赖与全部贴图，不能据调用参数宣称已核验每层渲染含义和物理材质。

**原创推导**：要解释图层怎样组成同一结果，先显示完整对象，再拆出有真实叠合关系的部分。部件需要保留共同基底和对齐参照；合成时应重新形成同一边界，不能回到一张近似的新图。解释一层的作用时，其他层退为细轮廓或暂离，不让它们继续环绕抢焦点。

完整观看链为：认完整结果→展开层关系→回合验证同一结果→保留一层解释它贡献什么→恢复组合→接实际局部效果。若当前关系只是资料依次处理，应换流程，不把“输入、规则、输出”假堆成三层。平面图层可用二维展开；需要真实纵深再选择２．５Ｄ或现有实现。

材质先采用统一薄面、清楚侧边与同向接触影，注记保持屏幕正读。关键内容未必在透视层上读，必要时另给该层正视窗口。中段检查层的角与遮挡，不能只检查中心。通过时能指出单层缺失会改变完整结果哪一处；若只是几张截图漂亮地分开，仍需补贡献与合成关系。具体原位和投影见 [拆层案例](exploded-interface-layers.md)。

## 4．Remotion Code Hike：让改动可追踪

来源：[官方仓库](https://github.com/remotion-dev/template-code-hike)；[官方演示页](https://www.remotion.dev/templates/code-hike)；[CodeTransition](https://github.com/remotion-dev/template-code-hike/blob/af1e1819b65b2c16ed2ffcf3e98774408318d5ae/src/CodeTransition.tsx)。

**资料依据**：已读完整 CodeTransition。它获取旧代码布局快照，计算前后 token 的过渡，并按当前帧推进；注释处理包含行内 token、提示和错误信息。README 将待演示代码与动画实现分开保存。未观看预览，不据此认定长代码、重复 token 或中文注释的实际效果。

**可迁移方法**：讲代码修改时，让未改部分成为稳定参照，让新增、删除与移动承担不同含义。注释解释为什么改，动画负责指出哪里变；输入改动与运行结果另行建立有依据的关联。

**教程设计推导**：展示错误配置 → 标出错误位置 → 修改相关字段 → 稳定展示新版本 → 展示实际反馈。短代码适合前后连续对应；大范围重写可明确切换并标出关键差异，不强迫所有字符变形。

**失败条件**：token 匹配产生错误身份暗示；同时高亮过多项；所有正文套打字效果；代码过渡完成就声称已经执行成功。只学习设计机制，不将外部实现引入当前模板或增加依赖。

### 从差异过渡走到真正的代码镜头

详细设计见 [代码走读与结果](code-to-result.md)：字体与缩进、完整语义组、二维取景锚点、未改上下文、版本身份、推导与实测输出分别展开，并含完整平均值教学演绎。本页不复制同一套细节。

选型时先问当前需要的是读懂代码、看清修改还是验证结果。只有修改才需要前后 token 过渡；解释现有短片段可以完全静置，以局部重点连到输入与推导。代码占主要阅读面积，输出获得足够空间后再接管，不能把两边一起缩小塞进装饰编辑器。

本轮可见 Main 将步骤均分、另设固定过渡时长，这种演示安排不成为教程时序。实际修改先落定，再展示当前输入与有依据的结果；没有执行证据就保留推导身份。连续预览、长中文与重复 token 的动态仍未观察，不能以此条目认定依赖或模板已验。

## 5．Remotion Audiogram：声音反馈与阅读区域分工

来源：[官方仓库及样片入口](https://github.com/remotion-dev/template-audiogram)；[Spectrum](https://github.com/remotion-dev/template-audiogram/blob/867ad8fa68573992a4775d8c0834a237e45f5b30/src/Audiogram/Spectrum.tsx)；[官方宣传图](https://raw.githubusercontent.com/remotion-dev/template-audiogram/867ad8fa68573992a4775d8c0834a237e45f5b30/Promo.png)。

**资料依据**：已读完整 Spectrum，柱高来自当前帧对应的音频频域数据，可截取频段、镜像排列，并用平方根调整视觉幅度。已查看宣传图，示例卡片将封面／标题、黄色频谱条与大号字幕分区；这张推广图不是成片截图序列，也未验证听感和同步。

**可迁移方法**：声音可见反馈与文字阅读分工，反馈不必占据主焦点。非线性幅度和频段选择会改变观感，因此频谱不能默认被解释为精密测量图。

**教程设计推导**：只有讲声音、播放状态或语音处理时，才选择与真实音频对应的可视化；字幕保持阅读位置稳定。普通原理解释仍让主体变化负责讲解，不以频谱代替内容画面。

**失败条件**：随机柱高冒充音频分析；将频谱误称为时域波形；镜像和装饰被解释成实际双声道数据；无词级依据却逐词闪动字幕。这里只借鉴画面分工，不迁入仓库的转写流程。

### 音频可视化要先决定观众在判断什么

**源码补读**：[可读分支 Spectrum](https://github.com/remotion-dev/template-audiogram/blob/main/src/Audiogram/Spectrum.tsx) 按当前帧读取带时间偏移的音频窗口，频域数据截段后可镜像，显示高度再取平方根。它是经过视觉映射的频谱，不是直接画原始波形，也不是测量仪器的原始量纲。

**原创推导**：讲语音输入或播放反馈时，先给实际声音或有来源的音频片段，再让可视反馈指向当前时间；字幕与正文保持稳定阅读位置。讲频率内容时才解释频段与轴，不能把居中镜像的装饰柱图标成左右声道。普通技术教程没有声音主题，不为填空放一条频谱。

原创观看链可为：建立音频身份与播放位置→声音开始时反馈出现→暂停段按实际数据呈现→当前转写或内容获得阅读→播放结束后反馈收束。音频、字幕和图形都取当前真实时间，不能各自从零启动；可视反馈不证明识别内容正确，识别结果要另核对。

美术让音频反馈占辅助条带，柱宽、圆角与配色服从全片语言，强峰不撞正文或字幕；需要解释频段时扩大图形并让正文退为定位。合法的视觉压缩应在需要测量解释时说清。通过时正常速度能看出何时有声音、何时安静，而不是随机柱子一直跳；本页未实际试听及同步验证，不宣称这些已成立。

## 6．Algorithm Visualizer：范围、当前项与结果共享状态

来源：[平台仓库与演示入口](https://github.com/algorithm-visualizer/algorithm-visualizer)；[二分搜索具体示例](https://github.com/algorithm-visualizer/algorithms/blob/fe3adcf890da652e5cda842d7f90b50fa7242e3a/Branch%20and%20Bound/Binary%20Search/iterative.js)；[官方界面图](https://raw.githubusercontent.com/algorithm-visualizer/algorithm-visualizer/master/branding/screenshot.png)。这是交互项目，不能计为已观看的视频样片。

**资料依据**：已读完整二分搜索示例：有序数组、当前搜索范围、中间项、左右分支和命中／未命中结果来自同一算法；图表与数组绑定。已查看的界面图展示的是快速排序，包含柱图、数组、日志和代码区域，并非该二分搜索的运行截图。

**可迁移方法**：把候选范围、当前检查对象、比较依据与结果区分开；多种表示共享同一状态。保留索引位置，利用范围缩小表达排除，而非让所有候选随机消失。

**教程设计推导**：解释筛选资料时，建立候选 → 显示当前条件 → 检查对象 → 展示排除理由 → 缩小范围 → 核对结果。迁移到视频时，提取必要表示，不把侧栏、运行按钮和调试日志一起搬进画面。

**失败条件**：二分搜索忽略有序前提；范围在比较前无依据缩小；图表、列表与状态不同步；演示输入只覆盖成功，却声称未命中分支也已验证。原示例随机从数组中选目标，实际只生成命中情境。

### 保留位置，才能看懂排除了哪一半

**原创推导**：把当前范围边界、被比较项、目标和比较结果分开设计。底层槽位与索引固定，范围之外的项降低优先级但保留位置；不要把它们移除后重新居中，否则“左半／右半”失去参照。数字保持同一基线，当前项用框或短标记，范围用连续带，目标放固定阅读区，避免每种状态都使用整块高饱和卡片。

原创教学例可以先用有序序列 `[2,5,9,13,18,24,31]` 找１８：先比较１３，保留右侧范围；再比较２４，保留它左侧的剩余范围；最后定位１８。这里是独立教学推导，不能当作原项目已运行的截图。每次比较先读稳，结果明确后再缩范围，新中点由新边界计算，不按镜头美观任意挑。

| 状态 | 画面需要保持 | 发生什么新变化 |
|---|---|---|
| 建立 | 有序值、索引、目标及完整范围 | 明确算法前提 |
| 选择中点 | 槽位与目标固定 | 当前检查项获得唯一重点 |
| 比较 | 当前数与目标同屏可读 | 用明确的大于／小于／相等关系决定方向 |
| 缩范围 | 原槽位保持，排除段仍能定位 | 只有有理由的那一段退出候选 |
| 下一轮或结束 | 已排除项不突然回归 | 新中点或命中结果接管 |

缺失目标可用１７独立演示：范围在比较后继续收缩，最终为空，显示未找到；不能仍给成功徽章。实际教程是否讲失败分支由内容决定，但未演示时不能声称已验证。区间、当前值与结果由同一状态派生；颜色仅辅助，文字与位置仍能读出含义。通过时观众能解释每次排除理由，而不只是看到数字渐渐变少。

## 7．LOOPY：信号到达后才改变接收对象

来源：[作者仓库](https://github.com/ncase/loopy)；[作者交互演示](https://ncase.me/loopy/)；[Edge 实现](https://github.com/ncase/loopy/blob/2d8e13f0a006f4024f27ad1712d7f9c2c1ad7cd9/v1.1/js/Edge.js)。这是系统思考交互工具，未操作其模型。

**资料依据**：作者说明以圆和箭头建立模型。已核对 Edge 中的信号推进、绘制及交付逻辑：信号沿箭头前进，到达后按连接强度改变增量，再交给目标节点；连接有正负标记。传播速度属于该演示模型，不能解释成真实系统的延迟测量。

**可迁移方法**：连线表示关系，沿线信号表示一次具体影响，目标反馈表示接收后的变化。三者分工；有向、正负和返回路径可以使反馈闭环可读。

**教程设计推导**：讲任务执行与反馈时，建立发送者和接收者 → 发送有身份的请求 → 到达后出现响应 → 若资料存在反馈，再画返回路径。并发与串行按真实关系安排，不能为画面整齐而改写因果。

**失败条件**：目标在信号到达前成功；所有连线永久流光；负向影响被画成失败状态；定性反馈模型被当成定量预测；画面暗示外部操作实际发生。

### 把关系、一次影响和接收后的变化分开

**源码补读**：[可读分支 Edge](https://github.com/ncase/loopy/blob/master/v1.1/js/Edge.js) 维护每条边上的信号，按箭头长度换算前进速度，抵达逻辑终点后才按连接强度修改增量并交给目标；绘图又有自己的端点外扩与颜色混合。传递逻辑与视觉缓冲分开，不能照抄绘图位置就认定业务接收时刻。负向连接表示影响符号，不是故障颜色。

**原创推导**：讲请求与反馈时，先建立发送者、接收者与通道方向；一枚有身份的请求沿通道走，抵达后目标才变化；若资料包含回复，再沿独立方向回传。请求、处理中与结果是不同状态，线路本身持续存在也不等于每帧都在发送。

可把局部状态写成当前帧可重建的关系：未发送→传递中→已到达→有依据的响应→必要时返回。路径、端口与标签共用几何；发送 ID 与响应 ID 对应。只有教学示意时才自行分配运动时间，不能把图中的飞行距离或速度当成真实延迟。

美术先让主体有发送与接收职责，当前信号采用一处强调，静态通道低对比，标签不压在线头。回路与去路分开避让，主请求未读清时不同时放多枚相反信号。进入结果阅读后结束装饰流动，接收主体或响应内容接管下一镜。

通过时能在正常速度指出哪次请求导致哪次响应，且目标不会在抵达前完成；静帧能看清方向和对象身份。定性系统的正负影响与软件成功／失败不能混用。未实际操作 LOOPY 或制作当前动画，声音、时序手感与反馈闭环仍待验证。

## 选择时先看表达缺口

| 当前缺口 | 优先参考 | 需要保留的关系 |
|---|---|---|
| 抽象表示与来源脱节 | 嵌入矩阵 | 来源与列／字段一一对应 |
| 物体都在漂，空间仍不清楚 | Smooth Parallax | 共同观察参照与层间差异 |
| 拆出部件后无法解释整体 | Deferred Lights | 拆层、合成、单层的身份连续 |

| 声音反馈抢字幕 | Audiogram | 实际音频驱动与阅读分区 |

| 连线只是装饰 | LOOPY | 发送、到达、接收反馈 |

不同项目的实现框架不决定本项目技术选型。这里只保留可复用方法与来源；实际代码、数值、文案和时间安排按当前内容独立设计。

## 各案例共同的设计通过条件

静态画面先要有明确主体、可读内容与能指出含义的空间关系；运动再揭示对应、范围、组合或影响。不能因为代码里已有某个效果就默认采用，也不能只以“同一个状态变量驱动”认定画面美术合格。

检查具体的起点、中段、结果及下一镜：身份是否仍能辨认，实际中文有无裁切，辅助表示是否抢主体，结论是否超出证据。正常速度需要读得完、跟得住；有声音时按实际音频核对。上述设计均未形成已验原创实现，源码阅读、官方示例图和计算关系检查不能冒充商用成片验证。
