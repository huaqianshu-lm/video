# 大标题连续变为节标签：位置、尺度与阅读权的交接

当一段内容需要先宣布主题，再进入具体解释时，可以让同一个标题从画面中心缩移到固定的栏目位置。真正要设计的是身份连续、阅读完成和内容接管；仅做“大字缩小到角落”，很容易变成页面切换的装饰。

来源：[Shotcraft 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/typography/title-demote-to-label.md)／[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/title-demote-to-label.mp4)。**原卡给定**是作者报告的做法和参数；**源码可见**是实现表达的关系；**抽帧可见**是官方样片的静态状态；**制作推导**是原创设计及实现建议。已阅读准确 demo 和下表相关视觉实现，未运行上游代码、未完成正常速度观看；原卡也注明真实素材仍需回验。本文不是已验模板。

## １．先把完成态排好，再设计标题怎样到达

**抽帧可见**：样片是偏暖浅底、深色主文字、少量红色标记。初始大标题处于画面中央区域，末态左上是节编号与小标题，下面有水平分隔线、导语和三组内容。第二节沿用同一舞台和标签位置，上一节标签变小变灰并上移。

这套画面的秩序来自几个具体关系：

- 大标题阶段，正文区域基本空着，眉题与标题组成一个紧凑的阅读组；强调色只落在编号、句点等少量部位。不要先把完整内容铺满，再要求观众看中心标题。
- 标签阶段，编号、分隔线起点、导语和正文列共享左侧网格；小标题为编号留出一段缩进。终点不是随便一个角落，而是后续内容的起点。
- 右侧的次级信息没有与标签争夺重量。样片中的品牌字、页码和底部状态属于它的演示语境，本项目不能照搬，也不必为填空而补上。
- 三组内容并非同样的白卡重复：中间深底内容形成明暗节奏，左右浅底内容保持关联。迁移时可以改用真实界面、图解或局部证据，不必保留卡片结构。

**制作推导**：先用当前视频最长的标题排出节标签，再确定主标题字号。标签需要占据的宽度为实际字形宽度乘缩放倍率，加编号、间距；如果侵入右侧信息或正文，就先改标签命名或终点布局。不要把超长标题硬缩成不可读的细线。

### １．１　标题先是一幅画面，再是一个运动对象

**源码可见**：主标题采用无衬线、２２０像素、８５０字重和收紧字距，强调句点与黑字形成很小但清楚的色彩重音。眉题用等宽字和疏字距；正文导语、内容标题、说明、元信息各有不同重量。中间的深底引语使用衬线斜体，与左右信息块形成字体和明暗差异。它并不是把所有文案放进相同组件。原实现的具体数值用于解释这套短英文排版，不是中文默认值。

**制作推导：按文字轮廓选择造型。** 先用当前中文标题排出宣告态与标签态，检查粗笔画是否糊成黑团、标点是否悬空、标签的小字是否仍有清楚字腔。可用同一清楚的无衬线家族分出标题和正文；只有内容与风格支持时再引入宋体或衬线。不能把英文负字距原样施加到密集中文，也不能靠系统自动合成粗体冒充预期字形。字体实际可用、加载完成后再测宽。

**制作推导：负空间应通向下一状态。** 宣告态让标题形成最大、最完整的暗色轮廓，眉题贴近它构成一个阅读组，周围空白保持连续。标签终点下方的留白将成为正文空间；不是在任意角落临时塞小字。需要偏心构图时，让标题的光学重心与未来主体形成呼应，检查真实字形左右重量，不机械对齐文本框中心。宣告态若留下巨大空白却没有明确主体，应先调整文字轮廓、位置与尺度，不能靠粒子填空。

**制作推导：背景载体由正文任务决定。** 编辑性讲解可用低对比哑光底、细线和清楚版式；真实操作可以在标题后保留弱化的真实页面边界，待交接时恢复当前区域；空间组成教学可以让标题旁已有完整对象，标题让位后由对象接管。真实页面存在关键状态时，不应为了标题把它抹掉再重新淡入。摄影感环境、抽象图形都必须有内容用途，不能默认给每个章节叠渐变光球。

**源码可见**：paper 舞台将暖白背景、近白表面、深墨文字、朱红强调和带暖色的阴影组织为一套颜色角色，柔光、暗角和颗粒主要在背景中。浅卡有细边、上沿内高光与软影，深卡用明暗差异而非另加一圈强光。**制作推导**：中文正文的笔画应比背景纹理更清楚；标签落位后对比退为定位层，真正需要阅读的界面或证据获得最大面积与对比。共享一个环境，避免正文入场时连背景光和噪点也重新开场。

### １．２　正文接棒必须带来新的认识

**源码可见**：A 式用三类不同内容展示产品能力；B 式先出现脚本文本，再强调其中一句，画出连接，建立与旁侧镜头条目的对应。B 式更值得学习的不是“右边多一张卡”，而是正文内部的一个具体位置成为后续解释的起点。其节拍柱图由函数生成，不能据外观认定它是实测音频波形；旁注匹配也不是当前项目已有的自动能力。

**制作推导**：先写出标签落定后观众应看懂的变化，再选正文载体。

| 正文实际任务 | 接棒后的主体 | 需要看到的信息变化 |
|---|---|---|
| 解释一个操作 | 真实页面中当前控件及其状态 | 从操作前到有依据的操作结果；标题只保留章节定位 |
| 解释选择依据 | 来源原句与被解释对象的对应位置 | 哪一句支持哪一项，连接从真实位置出发，不贴泛泛总结 |
| 解释范围或结构 | 同一对象内部的边界、包含或排除关系 | 变化发生在对象上，不用三段文字重复旁白 |
| 引入一个可执行示例 | 代码、输入或文件中的相关部分 | 由示例继续到实际推导／结果，不能停在“示例”二字 |

标题缩移途中，正文可以先建立轮廓；需要被读的关键差异等标题交接后再清楚出现。这里的先后按实际焦点决定，不把源 demo 的固定延迟写成每个镜头都必须执行的拍数。

## ２．动作拆成有职责的六段

| 阶段 | 画面与焦点 | 原卡提供的具体处理 | 为什么需要它 |
|---|---|---|---|
| 标题显露 | 先读眉题，再读主标题 | 字从裁切边界下方升起；单字约１６帧，间隔约１．６帧；强调句点比标题晚１０帧，带一次过冲 | 显露建立阅读方向，句点提供句末停顿；不是所有字一起淡入 |
| 宣告站稳 | 标题完整且可读 | 显露后留至少１８帧；示例约２０帧，并有约１．５％的微推近 | 没有这段，观众还在辨认，标题就离开；微推近是示例选择，静置同样成立 |
| 标题降格 | 同一个对象向左上缩移 | 约２６帧；位置和尺度共用 `cubic-bezier(0.6, 0, 0.18, 1)`；从约２２０像素字到约４８像素标签 | 同一进度让它被读作一次身份变化；先缩完再移动会成为两次分离动作 |
| 内容接棒 | 视线逐步转向标签下方 | 降格启动约１２帧后，内容开始揭示；单块约１８—２２帧，错峰先密后疏 | 标题尚在移动时已有后续可看，但不在飞行路径上同时制造另一个主角 |
| 结构落定 | 标签、导语、正文建立层级 | 标签前缀从左进入；分隔线稍后展开；内容最后完整停住 | 避免分隔线和标题在同一条路径上争抢，末态留给理解 |
| 下一节接替 | 内容更新，舞台记忆保留 | 旧正文约１２帧向上退出；旧标签约１６帧上移、缩至自身０．７倍并变灰；新标签占原槽位 | 多节接续时交代当前节与上一节，不把每节做成全新幻灯片 |

以上帧数是作者３０fps演示的局部动作尺度，不是当前视频的固定段长。用于口播时，先在真实 Timeline 中找到“主题已说清”和“解释开始”的位置，再安排重叠；若时间不足，减少入场花样，而不是挤掉读标题的时间或加速音频。没有词级依据时，不估算某个字被说出的帧。

## ３．最容易失真的地方：缩放锚点与居中补偿

**原卡给定**：标题的变换原点是左侧中点。起始状态另加水平方向的半宽居中修正；随着降格，修正从负５０％逐渐归零。只插值位置和 scale、保留整段负５０％，标签的终点会向左偏移半个缩放后宽度。

原卡正文用１９２０×１０８０舞台举例：位置由 `(960,540)` 到 `(216,196)`，倍率由１到０．２２。其简介与意图另以约０．３倍概括，但详细动作段与参数表使用０．２２；这里不混成一个精确实测值。实际终点由当前标签的可读字号和版式决定，不能直接套坐标。

**制作推导**：可以把这件事明确成一个模型，避免边调边碰运气：

```text
p = 标题降格的缓动进度，范围 0…1
A(p) = lerp(起始中心点, 终点左侧中点, p)
s(p) = lerp(起始倍率, 终点倍率, p)
标题局部点 q 的屏幕位置 = A(p) + s(p) × [q - ((1-p)W/2, H/2)]
```

`W、H` 是同一份排版框的实际尺寸。开头 `A` 对准框中心，结尾 `A` 对准左侧中点；整个过程不必更换文本节点。若用嵌套 DOM，外层负责屏幕锚点、第二层负责缩放、内层负责局部中心偏移，明确每一层坐标职责。不要把该式与任意顺序的 CSS transform 混用。

这个模型不是上游源码，而是锚点关系的实现推导。也可以采用其他坐标组织，只要起点、终点和中途的实际字形边界一致。调试时同时显示起始框、终点框与实际文字框；调试标记不进成片。

保留同一文本对象，还意味着飞行中不要触发换行、替换字体或重新按另一个字号排版。若必须换成短标签，先找到共有的词或字形作为接续依据，再设计文字替换，不能声称两段不同文字是一次无缝缩移。

## ４．内容是被揭开，而不是被横向压扁

**原卡给定**：内容块的可见宽度从约０．３扩展到１，同时向上移动约３０像素并由透明到清晰。这里改变的是裁切窗口，不是文字的横向比例。

**抽帧可见**：在内容形成的中间画面，卡片只露出一部分，完整文字被边界截住；已露出的字没有被压窄。后续深色块和第三块陆续形成，最终基线与外边界稳定。

**制作推导**：

1. 内容内部先按终点尺寸排好；裁切容器从左向右打开，内部不随窗口宽度重排。
2. 上移只作用于内容组；裁切开合与透明度可错开少量阶段，避免边界滑出时露出一片空框。
3. 先密后疏描述的是节奏，不是任意的等间隔列表。第一组承接标题，后续组承担扩展与收束；若三组没有阅读先后，可能更适合共同揭示。
4. 标题飞行时，目的地附近只出现低竞争的信息。鲜艳光标、弹窗、跳动数值另找时机；否则观众不知道该追标题还是看新动作。
5. 全部落定后停止装饰变化。字体小的时候，持续漂移比静态截图更难读。

## ５．B 式选区：怎样加，什么时候不加

**原卡给定**：第二节标题先出现文本选中态。色块约１０帧铺满，停约１０帧，再用约８帧撤掉；颜色约２０％透明，右缘带插入光标。铺满时左缘固定、右缘推进；撤掉时右缘固定、左缘追上。不是把整块矩形从一边滑到另一边。

设色块左、右边界为 `l、r`，范围均为０至１。扫入是 `l=0，r:0→1`；撤出是 `l:0→1，r=1`。宽度为 `r-l`，光标跟随对应的选区端点。这样高亮覆盖与文字始终对应。

色块撤净后才进入标题降格，否则它会随标题缩移，留下难以理解的彩色残块。选区适合编辑、文档、代码等确有文字操作语义的内容；普通章节标题不需要借它增加热闹。

**抽帧可见**：第二节标题有红色选区和端点光标，随后进入缩移。抽帧不足以核验１０／１０／８帧的实际时序，也不能确认每一帧是否完全撤净；这些仍是原卡报告的设计。

## ６．运动模糊、字体与声音的分工

**原卡给定**：降格飞行的模糊强度跟随位置差分速度，静止时归零，方向与飞行方向相关。

**制作推导**：若使用模糊，采样的是移动的标题，背景与已经落定的正文不应一起糊；接近终点时速度下降，模糊也应减弱。单纯给文字加一个固定 Gaussian blur，既没有方向，也无法表达落稳。模糊不能补救错误锚点或替代真实字体的高清渲染。无需为本案例新增依赖。

大字到小字的字重感可能改变。用实际中文字体检查小标签的笔画、标点、编号间距及基线；不要假定英文字号与中文可直接等比。显露时按语义短组或字形完整单元安排，不能把多行中文逐字拉成长串点名。

**声音建议，未试听验证**：若需要声效，可让轻微运动声随缩移出现、落位时收住，或仅用很轻的定位声。选区不必每帧发声，标签落位不应像重物砸落。当前官方文件未检测到音轨，不能据此推断作者实际使用了何种声音。

### ６．１　原卡、注释和表达式不能互相代替

**源码可见**：标题位置与尺度共用降格进度，但站稳微推近通过另一进度混入起始倍率；不能说所有属性只有一个进度。前缀的表达式从降格开始后２０帧启动，２６帧降格结束后仍在完成，不是注释写的“落位前４帧”。旧标签的调用参数让它在第１６６帧开始退位，恰与新标题降格同时，晚于源码顶部注释所写的１２４—１４０帧。实际制作应安排自己的交接窗口，而不是照注释排时间。

**源码可见**：逐字显露的最后一个字比第一个字晚启动，句点也另有动画。因而顶部注释的“１６帧显露后站稳２０帧”不是整词每个字都完全静止２０帧的证明。当前中文标题应从最后一个需要读的单元落定时计算可读窗口，不能只看第一个字的启动时间。

**源码可见**：`Grow` 改的是裁切与位移，内部保持最终排版；字形显露的遮罩带上下留边，防止笔画被截。速度模糊用降格进度的中心差分乘起终点位移，再交给方向性滤镜。它近似锚点平移速度，没有逐个计算缩放中所有字形的边缘速度。实际中文若出现长拖影、裁字或端点闪回，要检查本次字形边界和完整变换，不能把原实现当作全部情况已验证。

## ７．原创演绎：从“按需展开”进入真正的加载关系

以下是原创设计推导，未实现。教学前提是：系统先看到多个能力条目的简要信息，选择使用其中一个时，再展开这一项的正文，其余项不因此一起展开。具体名称、字段和选择行为必须来自当前教程资料；本例是机制示意，不冒充软件录屏或实际执行结果。

### ７．１　从内容目标倒推完成态

观众应看懂的是“清单与完整正文处在不同的阅读状态，展开针对当前项”。章节标题可以提炼为“按需展开”；它只宣布问题，不充当解释答案。完成态保留一列简要条目作为上下文，当前条目与展开正文共享名称和识别标记，其他条目仍保持简要状态。正文占主要阅读面积。这样空间同时显示“谁被展开”和“谁没有展开”，不靠另放三张定义卡解释。

**构图建议**：标题标签在上方固定，左侧简要清单较窄，右侧正文较宽，两侧保留能看清身份对应的间隔。清单显示实际需要的少量条目，不为显得丰富填满；正文页眉沿同一基线建立，关键正文从稳定左边缘开始。底部字幕区域先留好。若长描述让左右都过密，可在建立身份后将清单收成较窄定位区，正文顺势扩展；不能把所有字段一起缩小。

**美术建议**：标题采用紧凑但字腔清楚的粗字，正文用适合连续阅读的常规字重，字段名才使用等宽角色。清单与正文是同一套哑光浅表面，背景稍暗以露出边界；强调色只用于当前条目、正文页眉的对应标记及当前需要理解的范围。简要信息保持可辨认，未选正文不提前露出。不要用给其他条目加锁、蒙黑或删除来表达“本次未展开”。

### ７．２　六个状态与焦点交接

| 状态 | 画面与主体关系 | 观众此时看什么 | 下一步如何衔接 |
|---|---|---|---|
| 宣告 | 大标题与小眉题形成一个阅读组，正文区保留连续空白 | 先读清章节问题 | 不让光标和清单同时跳动 |
| 让位 | 同一标题缩移为标签；下方先建立简要清单的稳定边界 | 仍跟随标题，清单仅提供空间依据 | 清单在飞行通道之外，不抢先播放选择 |
| 识别清单 | 各项只显示资料支持的名称、描述与定位信息 | 认出当前可以选择的对象 | 清单先读稳，避免入场错峰尚未结束就点选 |
| 选择一项 | 当前条目的名称或标记获得重点；其他条目保持原状态 | 看清这一次选择的是谁 | 选择须有语义依据，不能让任意高亮冒充实测自动命中 |
| 正文展开 | 同一名称在右侧页眉持续对应，正文从最终排版的窗口揭示 | 焦点从名称转到正文中的实际步骤 | 未选项不展开；不将清单整块拉宽变成另一种文字 |
| 继续解释 | 清单收为定位，正文里一个确需讲解的步骤获得稳定近景 | 阅读这一项具体怎样执行 | 下一镜沿该步骤继续；若要讲成本限制，则转到有资料依据的清单范围，而非凭空出现警告 |

这里真正表达机制的是后三个状态，标题动作只是它们的入口。正文的出现意味着教学示意中的信息展开，不意味着技能已经执行。需要教真实调用时，用有依据的请求和选用证据接管，不能只给“已完成”徽章。

### ７．３　中段构图与节奏怎样定

先排宣告态、缩移中段、标签完成态和正文展开态，逐一检查实际文字外框。大字在缩小时仍可能扫过清单标题；移动编号、右侧正文页眉和裁切边界也不能同时挤在落点。碰撞时优先改目的地、正文建立时机或载体位置，不通过把标题模糊得看不清来解决。

宣告的可读窗口从最后一组字完整出现后算；正文的可读窗口从关键内容清楚且停止运动后算。当前 Timeline 如果只容得下一个解释动作，就省掉逐字显露或直接用稳定标签，保留“选中一项→正文展开”。本例不套原片的两式串播总帧数，也不估算无词级证据的口播字点。

**取舍**：不把每个能力都做一次同样的展开，会掩盖“本次只选一项”；不为同一段解释重复章节降格，会打断清单与正文的空间记忆。需要比较多项正文时，应重新设计比较镜头，而不是机械重复此示例。

## ８．看到什么问题，回到哪一层修

| 失败画面 | 常见原因 | 优先修正 |
|---|---|---|
| 标签落点总差半截文字 | 居中偏移没有随缩移归零，或坐标层级混乱 | 用实际文本框核对起终点锚点，不继续微调 magic number |
| 标题像先缩走再飞走 | 尺度和位置使用了不同触发与曲线 | 用同一降格进度关联两者，再检查中途边界 |
| 字还没读完就跑 | 宣告停留不足，显露错峰吃掉可读时间 | 缩短装饰性显露，保留完整标题的稳定窗口 |
| 新内容像橡皮被拉宽 | 对整块内容做了 scaleX，或动态宽度触发重排 | 固定内部布局，用外层遮罩揭示 |
| 标签与内容同时抢眼 | 新动作侵入飞行通道或过早高对比显露 | 降低过渡期内容重量，移动高竞争动作的时机 |
| 第二节开始左上拥挤 | 旧标签未让位，新标签又占同槽 | 先安排旧标签去向；无回顾需要时可退出，不强留历史 |
| 静态终点好看，播放却看不清 | 运动太长、停留太短，或落位模糊未归零 | 先检查正常速度的阅读过程，不能只审终帧 |

## ９．怎样判断设计成立

沿用项目既有设计审查和观看要求，不新增人工 Gate。检查应指向具体画面，不能只写“流畅、高级、有电影感”。

| 检查对象 | 能证明成立的画面 | 失败时先改哪里 |
|---|---|---|
| 镜头职责 | 标题完成主题定位，后续主体展示有依据的状态或关系变化 | 只有标题和说明卡：回到正文要解释的问题 |
| 宣告态美术 | 暂停可见清楚的文字轮廓、字重层级与有用途的负空间 | 空得散、全靠大字：重新排主体、字体与后续空间 |
| 标签与正文 | 标签仍可读但让位；正文获得足够面积；无关角标不争焦点 | 标签过重或正文被挤：改终点布局，不继续缩正文 |
| 缩移中段 | 同一标题可跟踪，字形完整，外框不扫过关键控件与字幕 | 跳位、裁字或拥堵：查锚点、字体加载、裁切与动作先后 |
| 内容真实性 | 当前条目与展开内容对应，未选项状态正确，文案可追溯 | 用参考业务填空：换回当前资料，重设计信息密度 |
| 正常速度与声画 | 首次观看能先读主题再跟到正文，停留足够，若配声则随交接收住 | 眼睛追不上或声效压口播：减少装饰与并行重点，重排真实时间 |
| 接下一镜 | 正文里的对象继续承担解释，没有另起一页重复定义 | 只是漂亮章节页：补实际操作、证据或关系镜头 |

静帧支持构图观察，源码支持机制分析；两者都不能证明正常速度的阅读、声画同步和最终成片质量。当前中文字体、长标题、完整原创动态及衔接仍待实际实现与观看，不能标记为商用级已验参考。相关方法见 [动态文字](../kinetic-typography.md)。
