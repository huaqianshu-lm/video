# 多源汇聚：沿真实通路接入，并让结果说明“汇成了什么”

本镜头适合解释多个输入共同形成一个结果，或几路信息被同一入口接收。线路、沿线运动和接收反馈有不同职责；如果最后只留下一个发光圆，观众可能知道“汇进去了”，却不知道资料怎样参与结果。先决定输入与结果的真实关系，再设计路径和运动。

本文区分 **原卡给定**、**源码可见**、**抽帧可见**、**制作推导**。旧版９６０×５４０参数另行保留，原始素材出处待确认，不混成 Shotcraft 实测数值。下述新增来源已阅读对应实现并查看官方样片定点帧，未运行上游、未正常速度完整观看或试听，不是已验模板。

## ２．先选准确的合并语义

| 当前实际关系 | 来源在结尾怎样处理 | 接收端必须给什么 |
|---|---|---|
| 实体真正归并或材料表示被收拢 | 允许原表示缩小离开，但身份在接收前可追踪 | 共同容器或结果中保留能辨认的组成 |
| 引用／复制材料 | 原材料保留，沿线传递摘录、引用标记或副本表示 | 来源标记与结果位置对应，不能暗示原文件消失 |
| 多路接入同一入口 | 连接仍可有用，按讲解需要保留 | 入口的接入状态与后续实际处理分开 |
| 多项并列列举 | 通常不使用汇入点 | 用分组或比较，不强造处理中心 |

**抽帧可见**：官方片四个灰阶图标圆片沿线路收拢，终点是托有品牌标志的圆片。它表达作者的素材汇流与品牌收束，不展示具体合并后的内容结构。**制作推导**：教程需要多讲一步，展示结果内部的对应、排列或变化；若内容没有共同结果，就不采用吞并隐喻。

## ３．结果画面、造型与光影先成立

### ３．１　来源的形状要能认出职责

**源码可见**：四路使用页面、叠卡、代码、声波四种线性图标，图标共同坐在浅色圆片上；来源主要灰阶，蓝紫强调留给沿线数据点与接收涟漪。节点不是四句同样长的解释文字。

**制作推导**：当前材料是文件、输入值还是信号，就使用与其角色匹配的轮廓。文件可留页角与页眉，参数可直接保留字段和值，声音只有讲音频时才用声波。不能仅靠四个英文缩写解释四种资料。长中文名称贴在起点稳定阅读，运动主体只保留短身份，不把长段文字缩到零再要求观众读。

### ３．２　通道和接收端需要视觉主次

**源码可见**：路径从浅灰渐到近墨色，越接近终点越实；终点圆片不透明，覆盖多条线头和数据点，避免从标志镂空处露出线头。来源与终点共享受光浅面、细边和软影，接收端影子较明显。

**制作推导**：来源是上下文、当前沿线对象是动作主体、结果是最终阅读主体。线条只支持路径辨认，不应比正在解释的文字更重。需要保留全部连接时，让共用入口略大或有清楚轮廓，给线头独立的端口或遮挡，不在一个小洞里叠出黑团。表面语言统一，避免四路各带一种玻璃色、接收端又像无依据的金属机器。

### ３．３　留白是传递通道，不是装饰空地

排版先放真实来源名称、结果结构和字幕，再安排连接。远处来源需要足够弯曲空间；靠近中心的路径可以较平，不为了形式统一让所有线有同样弧高。最大节点运动到中段时不能遮住另一条正在阅读的名称，也不能从结果标题上穿过。终点需要展开正文，就提前留足阅读面积，不能先把接收徽标放正中，再临时把结果挤到边上。

暗场变体应重设计路径亮度、接收面与投影，保证沿线主体有轮廓；浅色原例换黑底并加外晕，不自动成为有质感的另一套场景。背景柔光低于主体，停止运动后不要继续用流光填满画面。

## ４．路径几何、沿线定位和速度的关系

### ４．１　先分清三套坐标

**源码可见**：此实现用４８０×２７０设计舞台，其中４４０×２４０局部画布居中。四条线从局部 `(-22,y)` 到 `(74,y)`，再用三次贝塞尔到 `(332,120)`；来源 y 为３６／９２／１４８／２０４。画面最终放大到合成尺寸，不能把４４个设计像素当最终节点直径。

**制作推导**：明确局部路径、舞台与实际输出之间的变换。接收点、节点、线、引线标签共享同一局部坐标后一起变换；屏幕字幕与导航不跟着平移。重设长宽比时重新排版和取景，不只改变 SVG 的宽高。路径可以出局部画布，但外层舞台和实际画边依然可能裁掉它。

### ４．２　沿弧长走，不能让弯曲程度改变速度感

**原卡给定**用 `getPointAtLength` 解释沿路径定位。**源码可见**的当前 demo 已改用纯函数预计算：把曲线采为１６００段折线，存累积弧长，二分查找目标长度，再插值参数。它不依赖首帧 SVG 挂载后读取 DOM。原卡的 `ready` 与长度 fallback 描述不应原样套到这份实现。

```text
路径总长 L = 起始直线长度 L0 + 曲线弧长 Lcurve
来源驻留比例 f0 = L0 / L
当前长度 s(f) = L0 + progress(f) × Lcurve
节点中心 = pointAtLength(s(f))
```

**制作推导**：可以自己预计算路径采样，也可用已有的可靠能力，不需要为本例新增依赖。采样误差应以当前输出的轨迹与文字边界检查；１６００是原实现选择，不是所有路径所需的固定数量。直接插值贝塞尔参数 u，通常不等于沿弧长等速；若刻意采用不同速度，要能说明所需的加减速，而非无意忽快忽慢。

### ４．３　大小、身份和接触需要一起设计

**源码可见**：汇入主进度来自归一化时间０．３４至０．７４；节点尺寸在前７５％进度从４４变１５，后２５％从１５变０。代码注释称“三段式”，实际尺寸是两段线性插值，另有入场倍率，不能据名称编出第三段。节点中心始终沿同一条曲线，图标随尺寸等比变化。

**制作推导**：缩小表达的是表示被吸收，不是真实资料物理销毁。来源需要保留时，只让副本或摘要表示运动；抵达结果后可转成结果中的来源标记，而非必须缩成零。若保留标签，最后可读时刻与运动主体分开，避免文字压成小点才离场。缩小进度与路径接收时刻协调，不能在线路中段先消失。

### ４．４　光点不是实际进度

**源码可见**：沿线数据点用循环相位和每路偏移，带逐段衰减的尾点；另有总显露包络，收尾前关闭。循环光点并不由实际处理事件驱动。**制作推导**：只有讲传输示意时才使用，不能把循环次数写成已处理文件数量。需要真实过程时，由有依据的发送、到达和响应状态驱动；没有实测吞吐与延迟，就不显示精确速度仪表。

### ４．５　线条与沿线物体必须共用同一曲线

**制作推导**：三次贝塞尔的局部几何可以明确为：

```text
B(u) = (1-u)^3 P0 + 3(1-u)^2 u P1 + 3(1-u)u^2 P2 + u^3 P3
B'(u) = 3(1-u)^2(P1-P0) + 6(1-u)u(P2-P1) + 3u^2(P3-P2)
```

画线与物体定位从相同控制点求值。需要让箭头或长条主体顺着路径朝向时，方向来自当前位置切线；短圆点无需强加旋转。沿线运动与箭头只在实际有方向的关系中使用，关联线不能因为好看就被画成因果箭头。

裁切、线帽与接收轮廓共同影响观感。曲线中心抵达入口，不意味着宽物体边缘已经进入；应按主体外框设计接收遮挡和消失窗口。多个路径共用终点会在中心重叠，可以用不透明接收面盖住末端，也可在真实存在不同接口时分配端口。端口差异必须有含义，不能为了避免碰撞虚构系统接口。

### ４．６　“收线”也有方向语义

**源码可见**：线路先通过正向 dashoffset 逐渐描出，清理改用负偏移；线长来自各自几何，并非统一填一个常量。路径显露和擦除之外还叠加了透明度变化。**制作推导**：描线说明通路建立，沿线对象说明一次传递，收线说明当前不再需要显示此通道，三者不互相代替。

想表现持续接入，就让连接稳定保留，传递完成只结束本次信号；想强调材料已组织成结果，可以让临时路径退出。不要在线还没建立到终点时就让接收端出现完成状态，也不要在物体途中擦掉它脚下的线路。错误、断连或阻断需要对应的内容依据与明确状态，不能把一次未画完的线误做故障特效。

## ５．建立、接收与清场的时序

| 阶段 | 原例做法 | 自己的教程要重新决定什么 |
|---|---|---|
| 建立来源 | 圆片与线路依次显露，几路有小错峰 | 首先读哪一路；来源多时分组，不压缩名称 |
| 接通 | 线条描出，强调点开始沿线运动 | 连接表示接入还是引用，何时允许流动 |
| 汇入 | 节点按共同主进度沿各自弧长移动并缩小 | 是否需要一个主对象完整展示，其余简化跟随 |
| 接收 | 圆片倍率变化与单次涟漪构成反馈 | 接收不等于处理成功，终点应出现什么实质结果 |
| 收回 | 节点消失后，路径沿起点方向擦除 | 连接是否仍需保留来解释来源与结果 |
| 结果接管 | 清场时取景平移，接收标志最后居中 | 教程可以转向结果内部阅读，不必品牌居中 |

**源码差异**：归一化时间由 `frame/(durationInFrames-1)` 得到；１６８帧时分母为１６７。原卡把０．７８至０．９的擦除描述成１２帧，但按此实现窗口约为２０帧。不能把归一化百分比直接当帧数。接收放大与涟漪在节点全部完成前已开始，是视觉预备，不是精确的“所有输入已处理”事件证明。

**源码可见**：末段画布局部左移１１２，使原先舞台横坐标３５２的徽标落到２４０，即舞台中心。**制作推导**：结果是宽文档时，居中目标应是当前阅读区域，不一定是入口几何中心。平移清场要同时检查还未擦净的路径、外缘名称和字幕，不能只看徽标最终位置。

## ７．原创演绎：来源保留，证据进入一份可核对的说明

以下为未实现的原创设计。内容前提：当前资料中有几段分别支撑不同结论的原文，需要整理成一份说明。具体来源、摘录及结论由本视频资料确认；不暗示存在自动汇聚、自动验证或外部文件已写入的功能。

### ７．１　先设计有内容的结果

左侧保留来源页眉与当前摘录，右侧是一份已经排好段落结构的说明文档。终点不是一个黑盒圆，而是当前论点下的实际引用位置；不同依据进入各自对应段落。结果里保留来源标记，能回到左侧材料核对。当前讲解段落占最大阅读面积，下一段只保留标题或定位，不平均展开所有内容。

美术可沿温暖编辑方向：浅纸面、深字、单一强调，文档正文保持清楚行距；引用使用短侧线或小标记，区别于主结论。来源与结果共享材质和页眉语言，但有清楚的角色名称。线路在两区间的留白里经过，不覆盖全文；不为“智能汇聚”添加无依据的处理芯片或流量仪表。

### ７．２　动作组织与焦点交接

| 状态 | 画面怎么变 | 新认识与下一步 |
|---|---|---|
| 建立关系 | 一个来源摘录与一个待说明的论点同屏，其他来源弱化为定位 | 先知道依据与论点各是什么 |
| 选择依据 | 当前原文关键位置被标出，有必要时显示最短限定条件 | 不是任意几份资料都能汇入 |
| 建立通道 | 从该摘录边缘连接到结果的引用槽位，来源原文保留 | 这是一份引用表示的传递，而非删除原资料 |
| 主对象迁移 | 可辨的短摘录或来源标记沿线移动，到结果后转为稳定引用 | 完整展示一次对应机制，避免多个长句同时飞 |
| 结果形成 | 结论与引文在真实段落位置稳定，临时线路退去 | 观众能读清依据怎样支持结论 |
| 跟随补充 | 其他有独立价值的来源按不同论点接入，重复机制简化 | 只有内容差异值得再给完整阅读 |
| 接下一镜 | 来源区收为索引，结果文档获得主画面，聚焦需要继续解释的一句 | 从整理动作进入结果核对，而非孤立品牌徽标 |

若几路都支持同一论点，不人为给每路发一个结论；若互相冲突，保留差异，先比较条件，不能让它们全进一个圆后统一显示绿色成功。引用数量多时按论点分镜，末态可以只保留当前必要证据，不能让飞行数量成为质量目标。

### ７．３　中段与接收面怎样验

主摘录跨越中央时，其完整外框要避开结果段落及字幕；长文字不沿弧线持续缩放变形，可先变为短标记，到位后再展开为结果中的最终排版。后续对象不能穿过观众正在读的首条结论。接收端用稳定背景或明确层级遮住线头，正文不应因涟漪或落位回弹晃动。

时间优先给原句、限定条件与结果核对。演示通道的段落可以短，阅读段可以完全静置；无需复制１６８帧时长或四路同时加速。声效若使用，让一次传递与轻接收对应，不为每个循环光点发声。官方样片未检测到音轨，这些声音选择未试听验证。

## ８．失败修正与通过证据

| 失败画面 | 结构原因 | 优先改法 |
|---|---|---|
| 看着像四条线插进一个 logo | 只设计了输入和汇聚，没有设计结果 | 先排真实结果的组成与阅读顺序 |
| 引用资料被画成删除 | 把副本、引用与实体归并混同 | 原件保留，让摘录表示或标记传递 |
| 节点在弯处忽快忽慢 | 把曲线参数当弧长进度 | 重算沿线定位，再设计速度曲线 |
| 四路交叉后身份丢失 | 路径、时序与收缩同时拥挤 | 先突出一条，调整落点与先后，不加深模糊 |
| 终点镂空处露出线头 | 遮挡层与实体轮廓没有统一 | 给接收面正确背景或真实端口 |
| 光点还在跑，结果却写成功 | 装饰周期被当成处理事件 | 分离示意流动与有证据的状态变化 |
| 全部合完仍像普通 PPT | 运动没有揭示信息对应 | 保留来源与结果的可读关系，接入实质解释 |
| 代码坐标正确但出画 | 局部、设计舞台与输出比例混用 | 统一坐标和全外框取景，含阴影与标签 |

通过应能指出：每路来自哪里、是否保留原件、进入结果哪里、结果发生什么变化。静态完成态的材质与排版要成立，动态中身份可跟踪，正常速度有核对时间，下一镜沿结果继续。源码与本轮抽帧不能证明这些在原创实现中已经成立，完整动态、实际中文与声音仍待制作验证。
