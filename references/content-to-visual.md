# 从内容到画面

## 先找到可见的关系或变化

把一句讲解改写成「哪个对象，因为什么，从什么状态变成什么状态」。对象可以是文件、代码、任务、输出或时间轨道。先明确观众要确认的事实，再安排装饰与动作。

设计从全片开始：先找到各段共同发展的对象、问题与结果，再决定每幕如何推进理解。重点段落应获得更充分的画面展开，简短说明可以借助同一对象的局部变化完成。全片视觉语言可以统一，表达结构随内容改变；无需给每幕分配同样数量的动作。

| 内容关系 | 可见过程 | 须保留的证据 |
|---|---|---|
| 从材料提炼要点 | 来源呈现 → 来源让位 → 要点依次出现 | 来源身份及各要点的内容依据 |
| 代码改变结果 | 相关代码可读 → 强调修改处 → 显示结果变化 | 代码与结果的因果对应 |
| 多路输入合成结果 | 输入及目的地建立 → 输入沿关系路径汇入 → 结果形成 | 每路输入的身份和共同终点 |
| 两种做法不同 | 同一任务、同一比较维度，展示不同过程或结果 | 可直接对照的差异；按当前内容设计 |

## 用三个状态检查方案

写清开始、关键变化中、结束时的主焦点与对象关系。若这三个状态只是更换标题和卡片，继续具体化执行过程。若静态图已经能说明全部关系，可以保留阅读停留；运动应承担强调、追踪或因果表达。

例：讲「修改口播会使字幕错位」，可设计口播、字幕两条同尺度轨道，修改前对应、修改后边界错开。重新生成是否恢复对齐必须有当前资料依据。具体边界应依照当前真实时间关系设计。

## 把关键变化设计完整

下面的原创教学推导解释如何作决定，不是已验收的画面、产品事实或固定模板；前提、文案与行为须由当前视频资料支持。沿用“内容难点 → 视觉选择 → 观看顺序 → 关键状态 → 实验修正”的过程，不要求另交这套提纲。

**故障解释：先建立情境，再安排连续性。**假设教程先演示“登记 → 可用 → 执行”的核对过程，再解释三种故障。观众容易把持续存在的记录当作同一次执行。保留三层轨道作为认知参照，但切换到独立故障假设时结束原执行结果：第一种为“缺少登记／未执行／未执行”，第二种为“已有登记／不可用／未执行”，第三种为“已有登记／可用／结果不符”。指示器只负责定位，完整层级状态负责解释原因。若保留原成功结果，就算指示器准确，整幅画面仍然矛盾。用连续关键状态或短动画确认假设切换明确，不能只检查括线是否挡住文字。

**用户选择：先写要理解的意思，再共同安排口播和动作。**假设资料规定当前请求需用户决定，且不存在绕过这次等待的覆盖条件。观看顺序为“请求等待 → 用户作选择 → 本次请求继续 → 外部内容仍需判断”。等待、选择和继续各自对应解释这些行为的口播；进入风险提醒时，焦点已转给外部内容和权限范围。若在风险提醒时继续强调批准成功，缺少安全盾牌也无法消除相反暗示。冻结前可调整台词来提供动作落点。先用台词与状态图判断共同含义，再按需要做局部动作研究；没有真实音频不宣称同步通过。

**建立对比：先设计视线，再分配运动。**假设需要从单个设备近景转为两种连接方式对比。先让相机拉远，观众建立两侧空间，再让第二个对象入场，最后描出关系路径并保留阅读。允许末段少量重叠，但重叠量由可追踪性决定，不给通用帧数。若相机、第二对象和路径同时争夺焦点，应先改变先后和构图，无需先增加镜头。静态终态只能验证并排关系；需要短动画才能判断交接是否清楚，查看后再确定动作预算。

三类推导最终仍回到现有字段：情境及保留／退出对象写进前后态和生命周期；共同含义落实为口播与锚点；视线顺序落实为 Shot 焦点、动作先后和结果停留。内部审查从观众能看到的结果出发，允许否定这些决定，不能复述设计意图就写通过。实际查看范围、修正与待验问题记录在紧凑审计 summary／findings。

## 选参考时写明调整

例如：「借鉴文档让位的焦点交接；本幕要点为中文长句，因此改为两项可换行文本，并按真实口播安排停留。」这比只写「使用文档动画」更能约束实际设计。参考的业务文字和固定时长不能直接成为本片输入。

错误迁移：把所有输入关系都画成汇聚、把所有结论都放进药丸、只拼接动效而不设计内容变化。表达类型由当前内容决定。

## 从抽象名词找到对象的造型理由

[具象解释案例](examples/concept-to-visible-scene.md) 提供了不同于文档／代码／汇聚的表达：名字所指的事物先成为有辨识度的对象，解释文字随后补充；陌生交互则由执行者、可操作区域、信息缺失和尝试状态共同建立。

设计时先列出「观众知道什么／不知道什么，谁能做什么，动作改变哪里」。再选择能体现这些关系的轮廓、材质和空间组织。文件的层叠可以表达多个来源，时间片的边界可以表达先后，操作区域可以表达可交互性；这些只是候选造型理由，必须与当前内容相符。

对象换掉文字后仍应能传达部分角色或关系。若只能依靠标签区分，继续补充有意义的形状、位置或状态差异；不要求每个概念都做成写实插画。物体大小用于重要性或比喻时应说明，不能让观众误以为是有数据依据的比例。

## 总览、解释和执行分别承担什么

总览帮助定位类别或比较维度，解释展开当前概念，执行展示动作与后果。可以在同一视觉体系中切换表格、主体特写和场景，具体形式随问题改变，不必整片都是同一种卡片。

原片末段建立了未知条件并出现尝试和流程总结，但录屏没有展示完整成功过程。因此「建立交互情境」有观察依据，「已演示完整尝试闭环」没有。设计我们自己的执行过程时，应让状态变化和反馈实际可见，而非仅写出步骤名称。

## 完整设计推导示例

下面是两个原创教学推导，用于说明导演如何作决定。均未经过实际画面与用户验收，不是可直接套用的镜头模板、默认参数或优秀成片基线。示例设定须替换为当前资料支持的事实；具体口播、数量、时长及实现以当前视频为准。两例选择不同的观看方式，因为一个问题需要追踪筛选，另一个问题需要同时对照。

### 示例一：让观众看懂一次主动筛选

**内容与难点**：假设资料要求用户将后续有用的工作线索整理到索引中，临时信息不必保存。观众需要理解「按用途选择」及来源到结果的对应关系；纸张全部飞入目录无法说明筛选，也容易夸大系统自动判断能力。

**视觉选择**：一张工作台上，左侧是已有材料，右侧是打开的索引页。材料以不同内容结构区分角色：带明确规则的便笺、附定位行的处理记录、注明仅本次有效的临时提醒。它们从开场就可见，索引页先为空。操作指针代表用户选择；不设计自动拒绝边界。纸张与索引共用版心、线条和文字层级，空间分工表达「来源与整理结果」。

**镜头组织**：采用能同时看清来源和去向的固定中景，筛选过程保持空间稳定，观众可以跟踪身份。选择依据需要阅读时，让当前材料前移并放大局部内容，其余材料降为背景；选定后材料归位，索引新增与其对应的条目。这里无需为每次选择切镜头。

| 关键画面 | 构图与焦点 | 观众得到的信息 |
|---|---|---|
| 开始 | 材料在左侧展开，空索引在右侧；焦点先落在用途有区别的内容上 | 输入包含不同用途的信息，结果尚未形成 |
| 变化中 | 用户指针选中材料，当前内容局部展开；随后来源位置保留，独立索引条目生成并指向来源 | 选择有具体依据，索引是整理结果，来源与结果可以核对 |
| 结束 | 索引条目成为主焦点，未选材料仍在原处；保留阅读 | 只有选中的信息进入索引，未选不等于系统禁止保存 |

**动作与衔接**：选择、展开依据、生成对应条目依次发生；下一个动作不抢走尚未读完的焦点。若下一幕讲查找，就保留这张索引页及条目身份，让查找直接作用于既有结果；到用途完成再退出。若下一幕改讲另一主题，则交代结果后结束本组对象，不无理由常驻。

**落实数据**：材料、内容子元素、指针、索引页、结果条目分别有身份；父子坐标、层级与阅读区对应上述布局。Event 的 before／action／after 分别写明未选、用户选择并展开、对应条目形成，execution 引用实际参与对象。跨幕保留的索引只声明一次，以后续事件终止。触发锚点随当前口播确定；不先固定事件数与统一时长，不能用单纯出现代替选择过程。

**需推敲的画面问题**：展开材料会不会遮住索引？条目文字能否看出来源对应？指针是否足以表明动作发起者？对有疑问的部分先画关键状态或做短动作实验，未查看前只记录设计意图。

### 示例二：让观众同时比较两种配置的差异

**内容与难点**：假设资料比较「仅本次任务生效」与「后续任务沿用」两种作用范围。观众要理解的是范围差异；如果把两份配置轮流满屏呈现，容易忘记上一份的作用对象。

**视觉选择**：采用同尺度、同起点的两条任务轨道，上方一条表示本次配置，下方表示持续配置；每条都包含当前任务与后续任务。配置标记放在各自起点，影响范围通过轨道上的覆盖带表达，任务间距不表示真实时间。只显示比较所需、资料能够支持的配置文字。

**镜头组织**：使用正面总览，先让观众建立相同任务序列，再展开范围差异。两条轨道的对应任务保持垂直对齐，文字就近归属；固定视角有利于比较，无需追逐移动标记。这里保留同时可见的两套配置，不采用上一例的来源到索引结构。

| 关键画面 | 构图与焦点 | 观众得到的信息 |
|---|---|---|
| 开始 | 两条轨道等宽排列，共同标出当前与后续任务 | 比较维度一致，不存在被版式制造的大小差异 |
| 变化中 | 上轨覆盖带止于当前任务边界，下轨延伸到资料支持的后续范围 | 作用范围的差异直接可见 |
| 结束 | 范围端点与配置值同时可读，动作停止 | 可以将具体配置与实际影响逐项对应 |

**动作与衔接**：覆盖带起点一致、终点不同，按讲解顺序展开，完成后静置供比较。若下一幕讲修改某项配置，聚焦对应轨道时保留另一轨的低优先级参照，明确配置值变化先于范围变化；若资料没有验证变化结果，不能画成已证实的成功反馈。

**落实数据**：配置、轨道、任务、范围带、必要标签分别列出，覆盖带的父子关系保证不会越过对应轨道。事件记录两套范围从未建立到各自终点的变化，终点须符合内容依据；静置写入 holds，不用装饰动作填满。后续需要追踪的配置对象保留身份，具体镜头数由是否需要改变观看方式决定。

**需推敲的画面问题**：两条范围是否容易辨别？必要文字在总览中能否读清？颜色之外是否还有边界和标签支持区分？这些决定构图与阅读停留，不能以 JSON 合法替代画面判断。
