# 场景表达选择

这里提供表达方向，不限制对象类型、镜头数量或实现方式。先读 [内容到画面](content-to-visual.md)，再根据真实关系选择。

同位比较的完整设计见 [前后对比滑杆](techniques/comparison-and-data/before-after-slider-scrub.md)：先核对对象、尺度、裁切和真实变化，再设计揭示方向、证据停留和完整结果。布局已经重排或两版尺度不同，应改并排／对象对应等表达，不强行用一条分界连接。

需要更细的操作、集合与数据动作时，查 [界面与数据动作](interface-and-data-motion.md)；需要把多个镜头组织成一段解释时，查 [段落与声音](sequence-and-sound.md)。按当前关系选择方法，不按卡片名称拼接场景。

| 表达问题 | 可选组织方式 | 设计参考 | 不适用情况 |
|---|---|---|---|
| 材料怎样支持一个认识 | 原句定位、可读摘录、结论对应；多来源可逐次接力 | [文档到要点](examples/document-to-key-points.md) | 没有来源支持，或用不可读缩略代替必须阅读的原文 |
| 代码怎样产生当前结果 | 语义组走读、必要修改、推导或真实运行、结果核对 | [代码走读与结果](examples/code-to-result.md) | 逐行照亮冒充执行，或过渡结束冒充成功 |
| 多个输入怎样参与共同结果 | 通路、可追踪传递、实际结果槽位；引用时保留来源 | [多源汇聚](examples/sources-to-unified-structure.md) | 只是并列列举，没有共同结果；引用却使用实体吞并 |
| 两种方案哪里不同 | 同任务、同尺度、前后或并排对照 | 按内容设计 | 两边内容不可比较、只用颜色声称优劣 |
| 多条轨道怎样对齐 | 共同时间尺度、对应边界、同步游标 | 按真实时间设计 | 没有真实时间依据却画出精确对齐 |

代码走读用于阅读引导；显示业务结果需要内容依据与可见变化。汇聚表现来源进入共同结果；展开为时间轨道时，还需设计时间关系与边界。

## 从表达方向走到关键画面

[镜头设计推导](shot-design-recipes.md)将七类关系展开到可设计的关键状态；不是已实现模板。先选当前要让观众理解的变化，再选择观察方式。

| 表达任务 | 动作链 | 选择构图的依据 |
|---|---|---|
| 认识集合中的一个主体 | 建立整体 → 选定 → 局部解释 → 交代归属 | 密集界面局部取景；稀疏对象可前移；正文优先可读 |
| 看懂筛选原因 | 候选 → 条件 → 有依据的排除／保留 → 查看结果 | 少量逐项核对；大量整体收敛并展开代表理由 |
| 看懂参数影响 | 基准 → 调整 → 共同变化 → 结果核对 | 连续几何直接操纵；离散状态明确切换 |
| 比较同一维度 | 同参照 → 差异揭示 → 局部核对 → 保留结论 | 同机位用滑杆；代码留上下文；流程并排；范围双轨 |
| 理解组成关系 | 完整主体 → 展开 → 局部作用 → 复合 | 真实层叠用纵深；平面组成用展开图；执行关系用流程 |
| 看懂结果形成 | 骨架 → 来源映射 → 分组形成／关键修正 → 完整阅读 | 按字段语义分组，不把所有元素等间隔弹出 |
| 从具体对象理解不可见关系 | 现象 → 选定锚点 → 展开图解 → 返回核对 | 局部、插图或全屏图解按复杂程度选择；影像不是空白填充 |

形式不能替代内容判断：聚光不等于重点已讲清，部件浮起不等于组成关系成立，输入后卡片消失不等于筛选理由可见。是否需要换观察范围，由当前阅读任务决定。

## 外部案例扩展的表达方向

| 表达问题 | 可选组织方式 | 资料入口 | 失败条件 |
|---|---|---|---|
| 主体缺少具体身份 | 轮廓、内部结构、少量一致的体积线索 | [Headspace](examples/external-motion-design.md) | 为所有概念套一个物体比喻 |
| 相同基本单位形成不同关系 | 改变邻接、密度、分组和观察范围 | [IBM Sustainability](examples/external-motion-design.md) | 示意数量被当成数据，所有幕只是同点阵换标题 |
| 信息正在被处理 | 词组或片段以可追踪身份排序、提取、组合 | [Gemini](examples/external-motion-design.md) | 中文句义被拆碎，结果与来源不对应 |
| 限制如何影响操作 | 对象与边界、路径及条件的空间关系 | [Procreate Dreams](examples/external-motion-design.md) | 装饰性撞墙或无依据突破 |
| 能力能产生什么 | 当前输入、相关操作与同对象结果对照 | [Spline](examples/external-motion-design.md) | 无关的华丽产物冒充能力证据 |
| 一个系统为何需要多个部分 | 运行单元 → 配套关系 → 整体定位 | [Animagraffs／Mechanical Watch](examples/external-explanation-design.md) | 罗列组件却不解释必要性 |
| 同一对象如何变成另一种表示 | 输入、局部特征、数值及结果的对应 | [3Blue1Brown](examples/external-explanation-design.md) | 漂亮网络图掩盖错误映射 |

这些是设计候选，不是固定模板；来源支持范围与迁移推导见案例正文。

## GitHub 具体场景补充

以下方法的源码依据、示例图范围和失败条件见 [GitHub 解释动画案例](examples/github-explanatory-animation.md)，未作为本项目已验模板。

| 表达问题 | 可选组织方式 | 优先对照 | 不适用情况 |
|---|---|---|---|
| 来源与抽象表示对不上 | 保留对象、调整位置、两端同步聚焦 | 3Blue1Brown 嵌入矩阵 | 两种表示没有实际映射 |
| 改了哪里难以看清 | 稳定上下文、强调新增／删除／移动、再核对结果 | Remotion Code Hike | 大范围重写却强求逐字符连续 |
| 多层如何组成完整画面 | 完整结果、分层定位、合成、聚焦单层 | Motion Canvas Deferred Lights | 部件实际是串行步骤 |
| 条件怎样排除候选 | 建立范围、当前检查、依据、缩小范围、结果 | Algorithm Visualizer | 没有真实筛选规则或比较依据 |
| 影响如何传播并返回 | 关系先建立、信号到达、目标响应、必要时反馈 | LOOPY | 内容只有静态关联，没有因果证据 |

交互工具的多面板便于探索；视频中可只保留当前解释需要的图形、来源和反馈。音频频谱适合声音相关情境，其动态不能代替主体的内容变化。

组合前说明每次焦点交接的内容理由。若只能说「把已有动效接起来」，继续设计，不能称为新的优秀案例。

## 新增观察：具象解释与交互情境

结合 [从概念解释到可见场景](examples/concept-to-visible-scene.md)，按表达问题选择对象与布局。

| 表达问题 | 可选组织方式 | 观察支持 | 失败条件 |
|---|---|---|---|
| 名字或术语难以理解 | 有含义的对象造型先建立，名称与解释分层补充 | 原片的具象命名解释 | 造型与语义没有关系，只换图标装饰 |
| 新旧对象如何直接比较 | 旧组保持位置，新对象进入对照区域，用造型及主次辅助阅读 | 原片比较构图 | 比喻性大小被误认为量化比例，比较维度不一致 |
| 多项数据如何横向比较 | 同行同指标、固定名称与数值位置，总览后展开重点 | 原片对齐表格与后续解释 | 字太小、读不完、展开内容却无来源关系 |
| 陌生操作意味着什么 | 建立执行者与操作区域，显示条件缺失，再出现尝试与反馈 | 先建立情境，再展示实际动作和反馈 | 只有流程口号，操作区不发生可辨认变化 |

全片保持配色、文字角色及材质一致，画面形式仍按内容选择。上述方法不要求使用原片的天体、角色、网格、图标、文案或布局。
