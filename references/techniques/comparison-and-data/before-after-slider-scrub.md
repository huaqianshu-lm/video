# 前后对比滑杆：用同一位置的差异证明变化

滑杆不是用来把两张不同图片接在一起，而是让观众在同一位置核对两种状态。应先确定“什么变化、什么不变、凭什么比较”，再设计揭示方向、速度、停留和结论。快扫可以宣布变化，慢扫必须经过值得观察的区域，最终画面要能证明一项具体差异。

来源：[Shotcraft 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/shots/data/before-after-slider-scrub.md)／[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/before-after-slider-scrub.mp4)。本篇是独立研究及原创应用设计，不是原文翻译。**原卡给定**、**源码可见**、**抽帧可见**、**制作推导**分开标明。原卡与实现读取的是 main，未与此前 135 篇清单的固定版本逐字同版核验；不能将分支读取冒充固定提交证据。

## １．先确定这项比较是否成立

**源码可见**：样片两侧调用相同的 `FakeDashboard variant="A"`；Before 一侧另外加失焦、降饱和、低对比和灰罩，After 是未经过这些处理的界面。它演示的是同一图像的视觉差别，不能证明数据变好、任务完成更快或某项 AI 能力有效。

**制作推导**：画面的比较依据要能独立于滑杆成立。移除滑杆后，两版是否确实来自同一对象？变化是不是当前内容所解释的变化？无关差异是否影响判断？这些问题未解决，精致的分界线只会使错误比较更有说服力。

| 比较任务 | 可以采用 | 应改用其他表达的情况 |
|---|---|---|
| 同一图像的处理差别 | 同构图、同裁切、同尺度，用实际两版素材 | 换了画面、曝光或拍摄机位，却归功于算法 |
| 同一页面的主题／样式变化 | 同一数据、对象及位置，揭示真实样式差异 | 新旧页面重排到不能逐点对应，仍强行叠放 |
| 局部缺陷修正 | 明确缺陷位置，分界经过证据区域，最后给完整结果 | 差异是长流程或后台状态，图片不能证明 |
| 文字／代码版本变化 | 在排版稳定且差异局部时谨慎使用 | 多行增删、换行变动；应采用语义差异与上下文对照 |
| 统计结果对比 | 保持相同单位、尺度、样本范围 | 用图像清晰度暗示数值更高，或不同坐标轴冒充提升 |

“同布局同机位”是逐点比较成立的条件，不是所有前后比较都必须同布局。真实布局重排可以采用并排、匹配对象迁移或先后全景；此时应放弃用单条分界解释所有变化。

## ２．先排比较画面，而不是先画滑杆

**抽帧可见**：样片采用近正视的完整仪表板，侧栏深、内容区浅；两排卡片在两版中保持相同位置。清晰侧的靛蓝图表与深色文字对比明确，灰罩侧更柔、更低饱和。主体是整张界面的同位差异，白色圆手柄只是中部的操作提示。

### ２．１　确定一处主证据与少量辅助证据

**制作推导**：一整页都“变清晰”并不意味着观众知道哪里值得看。先选一处主要证据，例如字形边缘、照片细节、某字段的状态或一个图表的实际差别；其余区域只负责证明上下文一致。主证据不能恰好位于手柄中心、角标背后或屏幕边缘。

如果目标是字形细节，构图应让实际笔画可辨；如果目标是整体色彩关系，则需要更大的画面范围。不要在一个全页镜头里同时要求看清细字、理解所有指标并感受配色。先选择观察尺度，再选择分界经过哪里。

主证据靠近画面中部时，手柄可移到比较窗的上沿或下沿，以细线指示边界；不必照搬纵向居中的圆钮。分界是测量式边界，不是必须遮住重点的装饰主角。

### ２．２　字体、角标与版本身份

**源码可见**：Before 为浅色胶囊暗字，After 为深色胶囊白字，并配小色点；标签字号 20、字重 600，高度 42、圆角 21。Before 放在 x=1372，After 放在 x=646；它们对应各自图层的状态，After 随揭示区被裁切。

**制作推导**：版本标签服务辨认，不应比差异证据更醒目。教程可以用“修正前／修正后”或具体状态名，不只用 A／B。中文标签宽度、内边距、字面高度重新测量，不能用英文胶囊尺寸硬装中文。颜色只是辅助，还需明确文字，不能只靠灰色表示旧、蓝色表示新。

标签随图层裁切可避免错误标示，却会短暂剩半个词。需要持续清楚说明左右身份时，在比较窗外设稳定标签；若放窗内，则检查每次分界经过标签的时刻。不要让“后”版标签覆盖尚未揭开的“前”版区域，也不要让看不全的标签承担唯一版本说明。

### ２．３　表面、光影与背景克制

**源码可见**：手柄采用白到浅灰的微渐变，顶部内高光和两层软影；分界为白色细线，辅以弱暗描边及两侧阴影。After 内侧靠边还有 24px 的轻微暗影，使揭示边缘有接触关系。界面采用暖中性底与少量靛蓝，比较控件没有再引入大块高饱和色。

**制作推导**：白色手柄要在深浅两侧都能辨认，细暗边比增加大光晕更可靠。阴影应让人识别可拖动控件，不应把截图分界塑造成厚重翻页或真实撕裂。比较的是图像本身时，阴影、反光与背景纹理都要远弱于被比较的细节。

两版的曝光、色彩管理、锐化和缩放方式应一致，除非这些正是被解释的变量。不能给 After 单独加更亮的环境光、给 Before 加灰雾，然后把整体观感称为功能收益。样片滤镜是机制演示，不是可迁移的“优化前素材生成方法”。

### ２．４　完成态和负空间

**制作推导**：先把最终分界放到证据能读的位置，再确定初始位置和路径。最终停 40% 只是示例，不能保证当前主体的关键差异正好在左侧 40% 内。若差异位于右边，应改终点、方向或先给全 After 再回到可比较状态。

说明区、比较窗、状态标签、字幕各自有位置。说明区只写本镜需要核对的一项结论；背景留白承担版本名称与证据注记，不塞三张总结卡片。完成态即使不播放动画，也应能指出具体差异及它属于哪一版。

## ３．配准：两幅图怎样共享同一个位置

**制作推导**：先统一素材自身的视口、滚动位置、设备缩放、字体加载、内容版本和固定／悬浮元素。相同图片尺寸不代表内容已配准：侧栏宽度、浏览器工具条、字体换行和滚动条都会移动对象。

至少核对主证据角点及远离它的稳定地标。只对齐一个中心点，仍可能存在尺度或旋转差；局部看似接上，边缘却漂。文字界面通常应从一致视口重新取得素材，而不是用透视变形把两个真实不同布局硬扭成一致。

统一图像到比较窗的映射，例如：

```text
screenPoint = windowOrigin + sharedScale × (sourcePoint − sharedCropOrigin)
dividerLocalX = p × windowWidth
dividerScreenX = windowOriginX + dividerLocalX
AfterVisible = localX <= dividerLocalX
```

两版必须使用同一组 `sharedScale、sharedCropOrigin`，滑杆与裁切也使用同一局部坐标。不能让 After 自己 `cover` 一次、Before 再 `contain` 一次；也不能用屏幕百分比驱动局部窗口裁切，却用页面像素定位手柄。

**制作推导**：高分辨率图像展示细节时先等比缩放，再共同裁切；不要让每侧单独自动锐化。若取放大窗，两版放大窗使用同一证据坐标和同一倍率。显示的差异应来自源素材，而非边界附近的双线插值、透明接缝或不同像素取样。

## ４．裁切、分界线与手柄只共享一条位置函数

**源码可见**：After 全幅叠在 Before 上方，以 `inset(0, W−x, 0, 0)` 显示左侧部分。分割线中心、手柄中心和边缘阴影都从同一 `x` 派生。揭示的是图层可见范围，内容本身不横向移动。

**制作推导**：不要把“After 容器宽度变大”写成其内部图片也跟着变宽。若用宽度裁切的容器，内部图仍保持完整比较窗尺寸；缩放式展开会造成界面拉伸，看起来像两张不同图。边界移动时，跨边界的一根真实线条应能接上。

运动模糊只作用于分界与手柄，不应把刚揭出的证据也糊掉。裁切边界本身保持精确，白线的拖影是视觉提示，不是另一条延迟的揭示位置。若模糊后无法确认正在看哪侧，降低模糊，不能让影子替代真实边界。

外层圆角只裁比较窗，不把手柄必需的外扩误切掉；手柄若突出窗边，可采用共享坐标的独立覆盖层。字幕和对比解释文字通常不进入被擦除的图层。

## ５．动作全过程与参数关系

**源码可见**：位置以下列分段变化，单位是全幅宽度百分比。示例 30fps、150 帧；帧段是研究坐标，不是口播固定时长。

| 阶段 | 实际位置与时间 | 导演职责 |
|---|---|---|
| 建立 | 0—10 帧停在 8% | 让人先知道比较对象；此时已有少量 After，不是完整 Before |
| 预备 | 10—14，8→6.5%，smooth | 提供手感，但真实拖动不能无依据多演一次反向操作 |
| 快甩 | 14—26，6.5→76%，out | 建立显著变化；此段不承担细读 |
| 回弹 | 26—38，76→70%，smooth | 回收至观察位置；它是分段轨迹，不是弹簧模拟 |
| 停留 | 38—56，保持 70% | 核对首个结果；不能此时又重排页面 |
| 回扫 | 56—104，70→40%，smooth | 经过需要比较的证据，注意它不是匀速扫描 |
| 收束 | 104—149，保持 40% | 位置稳定供理解；仍需检查颗粒和标签，而非宣称全像素静止 |

**源码可见**：`out` 为贝塞尔 `(0.22,1,0.36,1)`，`smooth` 为 `(0.65,0,0.35,1)`。快段和慢段的速度均随曲线变化。原卡称快段为 out cubic，实际不是直接使用三次 ease-out 公式，不能混算轨迹。

### ５．１　快慢不是“12 帧比 48 帧”这么简单

快段实际行程 69.5 个百分点，慢段 30 个百分点。平均速度分别为 `69.5/12` 和 `30/48`，其比约 9.27∶1。12∶48 只比较时长，既不是原卡的约 5∶1，也不能预测曲线峰值速度。

**制作推导**：根据证据所在位置决定通过时的速度。重要细节刚好落在回扫最快的中段，就不能靠“慢扫 48 帧”证明已经看清；应放慢该段、安排一次稳定对照或改终点。不要为追求强节奏快速来回三次，让观众始终只追手柄。

### ５．２　手柄的形变、按压与模糊

**源码可见**：用前后半帧的位置差求每帧速度。横向伸展因子 `1+min(abs(vx)/110,1)×0.18`，再与按压因子相乘；按压由 10—26 帧的正弦包络产生，最多缩到 0.94。最终横向比例是两者的乘积，不保证可见手柄恰好达到 1.18。

圆钮尺寸 76，位于画面高度中点；白色分界宽 2，线中心与钮中心在同一 x；双箭头是矢量描边。`SpeedBlur` 使用 amount=0.12、max=14，根据速度计算横向高斯模糊，静止时退掉。钮的软影高度参数为 `14+min(speed/8,18)`，这是视觉模型参数，不是实际物体高度。

**制作推导**：先保证手柄与界面风格一致，再决定是否需要拉伸。教学不讲拖拽手感时，普通细边与清楚方向已经足够；形变与模糊不能让分界临时读成两根线。手柄外形可以压缩，证据内容不跟着变形。

## ６．必须保留的来源差异与限制

| 容易被照抄的说法 | 核对结果 | 使用处理 |
|---|---|---|
| 初始画面全是 Before | 初始左侧 8% 已是 After，预备时为 6.5% | 要交代完整基准，可另给全 Before，再建立比较控件 |
| 快段从 8% 出发 | 实现完成预备后从 6.5% 出发 | 不拿不同起点计算速度或边界 |
| 快慢约 5∶1 | 计算实际平均速度为约 9.27∶1 | 区分时长比、行程比和速度比；不能写成通用规律 |
| before 已是可信真实未处理态 | 实现仍人为加滤镜和灰罩，两层调用同一个界面 | 只研究技法，不当产品效果实证 |

| f110 后全静止／末段 40 帧 | 位置函数从 f104 即到终点；颗粒仍按帧变化 | 单独描述分界稳定、阅读窗口与全画面变化 |

## ８．完整原创演绎：用裁切修正解释“构图改变，主体没有被拉伸”

以下为**制作推导**，未实现。内容是图片编辑中的横向裁切：同一照片和同一人物，裁切去掉边缘干扰物，让人物在新画幅中获得更明确位置；人物比例应保持不变。目标不是笼统说“优化后更高级”。

### ８．１　先确认素材与比较坐标

选择有明确边缘干扰、主体完整且留有裁切余地的真实素材。先按构图目的确定新裁切矩形，不能先套滑杆再随机裁。用同一原图保留脸部、身体比例与光色，修正过程只改变取景边界，不修脸、不换背景、不另加饱和度。

裁切后若把新版单独放大填满同尺寸画框，人物会变大，无法再逐点对齐。此时有两种不同叙事：比较取景范围，用共同源图坐标展示裁切边界；比较最终画幅的观感，用并排或先后完整展示，不强求单滑杆。不能把两个尺度不一致的人物硬叠在一起。

本例采用前一种：共同源图固定，在外侧保留原图范围，新裁切外的区域用明确的中性遮罩表示“被排除”，不是用另一张被放大的图片替换。滑杆揭示的是裁切决策示意，标签写“原范围／裁切范围示意”，避免冒充两张最终导出图片。

### ８．２　完成态与美术

完成态先让观众看到完整的新裁切框、被排除的边缘杂物和仍然完整的人物；之后才回到局部滑杆核对。人物轮廓是主视觉，取景边界是次级几何说明，版本名与短注记负责命名。旁边一句“去掉边缘干扰”指向实际被排除物，另一项“不拉伸主体”在必要的核对态出现，不做同权重总结卡。

背景用安静中性色承托真实照片，框线采用与照片区别足够的单一强调色；遮掉的范围以低对比网纹或半透明中性层表达。照片本身保持同一色彩和清晰度，不为了强调结果让原图变灰。主体面部不放手柄，操作钮移至比较窗下沿；中线清楚而克制，保留两侧真实轮廓。

照片是主材质，外框是编辑界面的辅助层，手柄可以有轻微实体感，但不加金属灯柱、玻璃反光或整窗发光边。文字采用清楚的正文体系与短标签，字重强调“裁切”，不抢人物。最终尺寸检查脸部、轮廓、边缘干扰物和文字是否都能辨认。

### ８．３　具体构图与映射草案

1920×1080 画幅中，比较窗初稿为 `x=240、y=200、w=1440、h=720`；标题与版本说明在上方，实际字幕另留区域，必要时上移或缩短比较窗，不能覆盖人物。假设源图为 2400×1200，统一缩放 0.6，正好映射到该窗。

原图坐标的 `x=400` 对应屏幕 `x=480`，`x=2200` 对应 `x=1560`。若新裁切范围为原图横向 400…2200，左右被排除部分的屏幕宽分别是 240 与 120；原图主体的一段 200px 宽度在两版中都应显示为 120px。裁切范围还需根据实际人物与干扰物确定，这组数值只是可复算的设计例，不是任意素材的推荐比例。

该示意的新框为 1800×1200，与原图 2∶1 的比例不同；因此“示意裁切”与“新比例导出”是两个阶段。下一镜若展示导出，明确换到新的完整画框，不暗中把人物拉宽来填满旧比较窗。

### ８．４　从内容到动作的完整链

| 状态 | 画面设计 | 新认识／焦点 |
|---|---|---|
| A．基准 | 原图完整出现，指出边缘干扰物，暂不显示运动滑杆 | 为什么需要改构图 |
| B．目标预告 | 新裁切框短暂显现，人物比例保持原样 | 修改的是取景范围，不是人物形状 |
| C．建立比较 | 明示两种状态名，手柄在下沿；照片保持同一源坐标 | 知道在比较什么、该看哪里 |
| D．首次揭示 | 分界快速通过无关背景，接近干扰物时减速 | 用速度把注意带到证据，而不是匀速扫完整屏 |
| E．证据停留 | 分界停在能核对边缘干扰的位置，短注记指向被排除物 | 具体说明删去了什么 |
| F．主体核对 | 同一人物轮廓在两侧接合；必要时共同放大同一局部 | 没有拉伸、换脸或额外调色 |
| G．完整结果 | 去掉滑杆，展示完整裁切范围与主体关系 | 不把半张对比图当最终构图效果 |
| H．下一镜 | 进入真实裁切确认／导出操作，明确新画幅比例 | 从观察结论转到实际使用，不伪造保存成功 |

这条镜头不照搬自动回弹：裁切教学没有真实拖回操作，就不让滑杆假装用户重新选区。示意比较与真实裁切控件也要区分；移动比较杆不应改变实际裁切框，防止观众把两种操作混淆。

### ８．５　中段构图、声画与真实内容检查

**制作推导**：当边界经过人脸、细发丝或斜线时，检查两侧是否接合，有无双边、缩放误差或不同锐化。手柄在下沿仍可能碰字幕，需连同阴影、伸展和出界范围一起检查。主注记不要贴着移动边界走，以免文字速度比证据更抢眼。

原始照片与实际裁切需完整核对人物边缘，不能只凭两个角点判断没有拉伸。若真实变更包含旋转校正，另作解释，不再假定逐点配准仍自然成立。若新裁切错误地切断手指或必要上下文，应返回构图设计，而非用一段更顺滑的动画掩盖。

声音可在建立比较时给一次轻提示，慢扫与证据停留通常保持安静，留给旁白；若配摩擦声，其长度与速度应对应实际滑杆运动，不能在静止后仍持续。时间取真实口播与 Timeline，不能为了塞进五秒删除理解窗口。

## ９．失败与验收证据

| 实际问题 | 优先修正 | 可观察通过条件 |
|---|---|---|
| 两侧像两张不同页面 | 统一对象、尺度、视口、裁切和数据 | 远近地标及主证据跨边界准确衔接 |
| 只有 After 好看，说不出差异 | 确定一个内容目标与主证据 | 能指出具体改变与不变量，而非只有“更清晰” |
| Before 被故意做丑 | 换成真实基准或明确标示机制示意 | 变化有可回查来源，不靠额外灰雾制造优势 |
| 分界经过但读不到 | 重排速度、停留和局部取景 | 正常速度能核对证据，不用暂停补全部解释 |
| 线与揭示边界不同步 | 同一位置函数与局部坐标 | 线中心、裁切边、手柄中心对应，没有滞后一帧 |
| 新版图像随窗口拉伸 | 固定内部图尺寸，只裁可见范围 | 主体比例在整个揭示过程不变 |
| 手柄遮住证据 | 改手柄位置或主证据取景 | 关键轮廓、字段或像素差异不被控件挡住 |
| 标签被切得无法辨认 | 调整稳定标签与图层标签分工 | 全过程都知道两版身份，不凭颜色猜 |
| 结尾只剩半幅图，无法看整体效果 | 补完整结果态再接实际操作 | 观众能看见完整结果与下一步入口 |
| 静帧成立，动态或声音嘈杂 | 减少重复回扫、形变与竞争音效 | 焦点依次落在基准、证据、结论，旁白清楚 |

这些是沿用现有设计审查与实际观看要求的具体问题，不新增 Gate。本文已完成来源机制与九张静帧研究及原创镜头设计；动态跟随、实际中文、真实素材和声音仍待实现验证，不宣称商用级成片已验。相关选型见 [场景表达](../../scene-patterns.md)、[界面与数据动作](../../interface-and-data-motion.md)；比较代码语义变化另见 [代码走读与结果](../../examples/code-to-result.md)。
