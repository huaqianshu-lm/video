# 元素全家福收场：让已经见过的内容围成一个结果

本镜把前文出现过的代表元素召回，在同一画面中围绕身份合影。重点是观众能认回“这些东西属于同一主题”，其次才是四方飞入、机位落下和舞台氛围。收场的九件东西如果从未被解释过，就只有杂乱素材，没有回顾。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/outro/outro-group-photo-launch.md)、[OutroGroupPhotoLaunch.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/outro/outro-group-photo-launch/OutroGroupPhotoLaunch.tsx)、[官方演示](https://vincentwei1021.github.io/video-shotcraft/media/outro-group-photo-launch.mp4)。另核对 [PageCam2D](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/PageCam2D.tsx)、[Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx)、[布局数据](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_textures/live-layout.json) 和 [Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)。固定卡已核验，main实现与媒体不冒称同版执行。

本文分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、145帧、约4.83秒，无音轨；查看16帧。未正常速度完整观看、运行上游、审核纹理原页面业务或实现原创镜头；未观看模板整片。参数解释案例，不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先选有内容身份的代表，而非把所有素材搬回

| 收场目标 | 选择依据 | 应避免 |
|---|---|---|
| 回顾多个已讲能力 | 每件有对应的前文镜头 | 临时增加未解释的新功能 |
| 让不同结果归属同一主题 | 形态和来源能认回 | 九张外观一样的小卡片 |
| 展示完成作品的关系 | 最终布局表达实际结构 | 只是为填边缘随意摆放 |
| 教程结束 | 知识结论先成立，再低权重收场 | 无条件把结尾推成全片最吵峰值 |

原卡规定发布会式最高能量，来自宣传片模板语境。**制作推导**：口播教程可借“代表召回、中心让位”的结构，是否加光带／金尘另按内容与风格判断。九件不是通用配额，三件有辨认价值的实物通常优于九件看不清的窗口。

## ２．结果构图先画：中心是主位，四周是记忆线索

### ２．１　九件最终位置与尺寸

**源码可见**：周边元素来自页面纹理，各自保持原资源比例，最终轻旋转不超过约5°；以下是父层相机之外的名义尺寸：

| 元素 | 中心坐标 | 最终显示宽×高约值 | 构图职责 |
|---|---|---|---|
| 导航条 | 960／84 | 1190.4×37.82 | 上部横向边界 |
| 左上卡 | 280／300 | 257.76×224.64 | 左侧体量 |
| 右上卡 | 1640／318 | 243.44×195.84 | 右侧平衡 |
| 右下内容条 | 1460／730 | 552×112.5 | 下方斜向延伸 |
| 左下卡 | 260／800 | 214.8×187.2 | 左下支撑 |
| 底部内容条 | 620／930 | 529.92×108 | 下缘横向重量 |
| 搜索框 | 760／180 | 558.8×24.2 | 上部功能身份线索 |
| 统计条 | 1560／950 | 283.5×50.4 | 右下轻量收口 |
| 文档头 | 1620／170 | 550.4×43.2 | 右上细长形态 |

这些不是九个等权入口。细条多、方卡少，长短与密度变化围出中央的名称区。搜索框最终只有约24px高，不能承担读输入细字的任务；它只供认形。真正要读的结果应留在更大主体或前镜中。

**抽帧可见**：奶白背景上，卡片与长条分散在四边，中间大片负空间让品牌成为唯一大字。整体明亮克制，粒子不抢主体。当前小接触表不支持读取周边所有业务文字，不应据此宣称九件都被观众完整理解。

### ２．２　背景页退成环境，召回对象保持较清楚

背景页高1746，PageCam对准960／700、zoom0.75，得到横向居中、纵向15平移的页面取景。背景0→24由0到14px模糊；暖白径向幕再压低其细节。召回元素是背景相机的未过滤兄弟层，不放进同一个blur子树，否则全场只剩标题清楚、代表物失去身份。

文档头从1920宽整页纹理裁出，背景位置−576／−173，盒688×54，再缩0.8。它取的是原页坐标的一块，不是把整张长页塞进54高盒。换材料时先核裁切来源和实际布局，不能复制旧负偏移。

**制作推导**：召回物可以保留真实内容，不需要重绘成上游页面。若资源只是低清缩略图，放大后认不回，先换对应清晰裁片。背景页只作来处，不要求读；召回物只作记忆线索，也不应同时承担读整页的新任务。

## ３．飞入链：方向、次序和落地都要服务构图

**源码可见**：九件cue4、7、10、13、16、19、22、25、28，各用12帧位移。上方条由上来，左右卡从对应边缘来，下方条由下上来。起点不仅有±360—500横向，还有导航−120、搜索−240、纸条320等不同偏移，不能把全表都写成相同大位移。

飞入缓动`bezier(0.34,1.4,0.44,1)`确有超过1的区间：位置可短暂越过终点再返回；角度从最终rot的2倍收回rot，尺度从最终值的1.12倍到1，透明度前三帧建立。出现顺序等于DOM叠放顺序，后到者压在前到者上。

**制作推导**：不是所有对象都值得同等飞行。先给最重要的两三件较清楚路径，其余简洁跟随。检查中段叠放与中央负空间，不能到终点才发现一张长条横穿中心标题。需要遮挡时，按真实空间与信息主次排层，不用“后到者一定在前”替代导演判断。

### ３．１　落地压实是一段独立小余量

cue＋9→12→16，land0→1→0；主体轻压1.5%，投影从10px位移／24模糊向5／12收紧，透明度稍提高，再放回常规影。最后一件到40帧位移完成，44才结束该落地余量。

原实现旧注释还有“每件落地强调色glow”，当前正文实际是接触影与轻压，没有每件单独加发光。原卡的“不逐个发光”与实际更接近，不能把旧注释当现有效果。

### ３．２　方向模糊是速度近似，不是全变换采样

位移速度用前后半帧中心差分求vx／vy，SpeedBlur将其模长×0.3、封顶22，沿方向做单轴高斯；低于0.35时不模糊。它不包含对象旋转、尺寸变化和父层相机的完整屏幕速度，因此“按屏幕速度”是近似描述。

**制作推导**：先检查路径，再决定模糊。不要把静止的小字仍模糊着当景深，也不要为了表现速度加滞后实心副本。父层运动较大时，应考虑完整投影速度或真正采样，但是否采用由当前镜头需要决定，不新增通用依赖。

## ４．机位落下：是平面姿态，不是实体吊臂摄影机

**源码可见**：整个合影层做`perspective(1400) rotateX(4→0) scale(...)`，0→40收倾角并从1.06回1；36起另用smooth缓推最多0.035，与前段交叠。支点50%／45%。这是页面层的2.5D姿态变化，不是场景里有真实吊臂、地板和摄影机轨迹。

字标、粒子、舞台光位于该相机层之外，保持端正屏幕阅读。召回物与背景共同落机位，标题不跟着斜。若把标题也塞入父透视层，字形会倾斜并压缩，主次关系会改变。

**制作推导**：空间动作可以很小，但要有理由——建立合影、再把视线交给身份。如果原文要读的是某张卡，先正视该卡，不在斜拍中强求阅读。慢推从零速开始能缓解接棒，仍需正常播放确认40附近是否有速度变化。

## ５．主角登场时，配角真正让位

42→50，周边元素opacity降低12%、saturate降低8%，并不全部退到失焦背景。中央字标使用118px／700，标志154px；纸面字影为1px暖白边与一层很软的14／36环境影，形成压印暗示，不是浮空发光字。

标志38→46先出现，文字首字42起；第i字符delay＝round(42＋1.8i)、各8帧。15字符末字67起、75完整。每字从下偏28、尺度1.35、模糊8回到端正完整，实际是由下向上归位，不是物理从上砸下。

**制作推导**：身份不一定要逐字压印。中文主题名可按语义组整体落位，避免每字像独立按钮。最重要的是字形稳定、周边有退让、最终层级明确。别让字标和九件物品全都用同样的过冲峰值。

### ５．１　横线和字距不是都等全词结束才开始

rule58→70长到260宽；延长线58→66各长190，再66→72淡去。字距62→66从约0.02em变0.035em，末字符75才完整，因此“全词到位后呼吸一次”的注释不是精确时间关系。标语68→80进入，也与末字符尾部交叠。

**制作推导**：横线如果只是装饰，不能抢在识别名称的最快阶段变成第二主动作。想让主角真正站稳后再有注脚，应从最后字符完成倒排；否则明确这种交叠是设计选择，不能在审核表写全都串行。

## ６．光、尘与实际结束时间

| 通道 | 实际代码 | 画面职责 |
|---|---|---|
| 开场光带 | 2→14，宽600、峰0.12、overlay | 进入合影的环境铺垫 |
| 字标舞台光 | 42／50／58，0／0.55／0.32 | 主角登场时中央变亮 |
| 暗角建立 | 42→54，0→0.1 | 保持中央焦点 |
| 金尘 | 20颗、2.4—4.2px，位置与闪烁确定性变化 | 前景轻微空气层 |
| 大失焦斑 | 6颗、14—28px、2px模糊 | 更近一层，不承载信息 |
| 标语完整 | 80起 | 全套结果可见 |
| 收尾熄灯 | 133→144，整体opacity1→0 | 最末帧是`#0f0d0a`暖墨底 |

原卡给舞台光峰0.5／尾0.25，当前代码0.55／0.32；145帧演示还包含最后12帧熄灯，不能把模板30帧sign-off的外部时间线直接套到这条媒体。80—132有53张完整组合可看，但相机、粒子和光斑仍活动，不是严格冻结。

原卡声音的945／980／1005是模板整片帧号，不是当前145帧局部时间；本媒体没有音轨。可以学“铺入—主角重音—细节收尾”的声音层级，不能声称本轮已经听到或直接把全片绝对帧写进本镜。

## ７．关键帧观察

实际查看0、4、12、24、36、42、50、58、66、75、80、104、120、132、138、144。

| 帧组 | 抽帧可见 | 应审查 |
|---|---|---|
| 0—24 | 背景页退糊，周边代表件陆续飞入 | 来处是否能认、物件是否互相挡住 |
| 36、42 | 周边基本成形，标志开始 | 最后落地余量与主角入场是否冲突 |
| 50—75 | 名称逐字建立，横线与标语跟进 | 读名是否被横线、粒子和小字分散 |
| 80—132 | 完整明亮合影 | 中央负空间、各代表身份、层级统一 |
| 138、144 | 整场退向暖墨，最后全暗 | 与下一镜／片尾实际结束是否一致 |

## ８．原创演绎：三份证据围成一个可回查的结论

以下为**制作推导**，未实现。教程已展示原文、实际数据表和实验记录如何共同支持一个判断，最后把三者与结论合影。重点是保留来源，而不是把它们都压成品牌背景。

### ８．１　先画结果关系

1920×1080里，中央放已被证明的短结论，四周只召回三件实际资料：左侧原文页局部，右上数据表，右下实验记录。结论按最长实际文案排成两行，主字72px，次行44px；下方保留可辨认的来源索引。背景暖灰`#ece8de`，纸白`#faf8f2`，墨绿`#253f33`，主定位线低饱和铜色。

资料不对称但有内容逻辑：原文给条件，表格给比较，记录给检验。每件都有已出现过的名称和固定关键内容，不能新造三张空白卡。为中央预留至少约900×430的实际字区，再按素材比例安放，不套用上游九件坐标。

### ８．２　从前文对象回到共同结果

| 阶段 | 画面动作 | 认识推进 |
|---|---|---|
| 接前镜 | 最后一份实验记录仍清楚 | 回顾有实际对象 |
| 召回来源 | 原文、表格回到各自位置，采用较短的原位延续路径 | 三份不同证据共同在场 |
| 结论接管 | 三份资料稍退弱，中央完整结论出现 | 结果有明确主次 |
| 对应核对 | 每份来源只定位一处实际支持点 | 合影表达关系而非数量 |
| 阅读 | 全部相机和临时提示停止 | 允许核对条件和结论 |
| 下一镜／结尾 | 进入方法的另一例，或保留结论结束 | 不以品牌盖章抹掉证据 |

不要求三份从画外飞来；如果此前已经在画内，原位缩移更连续。只有主要原文页做一次清楚迁移，其余简洁跟随。背景页、光带与金尘可全部省去，用真实纸面、线条和柔影获得层次。

### ８．３　实现和真实资料边界

每份资料的源文件、页号、裁切矩形和关键锚点同源，终点保留身份；结论来自既有讲解，不由三份资料飞到一起就自动成立。若表格原图1600×900缩到480×270，字号30只剩9px，因此合影只识别表格与高亮位置，必读数值仍交前镜或局部放大。

一次结论落位音可作收束，但不配三次成功音，除非真有三个独立完成事件。让旁白把条件与判断说完，最后一处高亮退去再留清晰停留。真实资料、字形、原创实现和声音目前未验证；图形关系正确仍须成片观看确认。

## ９．失败诊断与通过条件

| 失败 | 修正 | 可观察的通过证据 |
|---|---|---|
| 九件全是陌生碎片 | 只选前文已讲代表，减少数量 | 观众能认回各自身份 |
| 中央无位置放结论 | 先排中心字区，再反推周边 | 无动画时已形成主次 |
| 代表物跟背景一起糊 | 分离模糊子树，保留清晰兄弟层 | 来源有形体和身份，不只剩白块 |
| 中途长条穿过主字 | 调整路径、cue和叠放 | 最忙帧仍有清楚焦点 |
| 说有落地glow实际只有影 | 核对正文与旧注释 | 设计描述匹配真实实现 |
| 把近似速度写完整屏幕运动 | 明确只求位移或补完整投影 | 模糊方向、强度与真实动作相符 |
| 字尚未完整就有太多装饰 | 以末字符为依据排横线／标语 | 名称可完整读一次 |
| 合影很丰富却没有证据关系 | 重做结论与每件的支持点 | 能指出它们为何共同出现 |
| 把模板音效帧当局部帧 | 从当前真实Timeline重排 | 声音对应当前镜头事件 |

Storyboard应交代召回对象与前文对应、最终关系构图、中央字区、路径和层级、背景退让、最后完成与退场时刻。静态、全速、声音和真实内容分别验收；当前不宣称原创实现或商用成片已通过。
