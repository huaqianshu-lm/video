# UI变成身份符号：最薄处换形与几何构件拼装

本篇有两套不同机制。A把熟悉图标压薄，在几乎看不见形态时换成另一符号，再展开；B让一个矩形控件保留身份，变成标志的一根构件，其余构件有预告地依次归位。共同目标是让前文对象参与最后身份的形成，而不是突然插一段无关logo动画。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/outro/ui-to-brand-morph.md)。A见 [IconFlipBloomLogo.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/outro/ui-to-brand-morph/IconFlipBloomLogo.tsx)、[官方A样片](https://vincentwei1021.github.io/video-shotcraft/media/icon-flip-bloom.mp4)；B见 [InputMorphsIntoLogo.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/outro/ui-to-brand-morph/InputMorphsIntoLogo.tsx)、[官方B样片](https://vincentwei1021.github.io/video-shotcraft/media/input-morph-assemble.mp4)。另核对 [Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)、[Look](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Look.tsx)、[Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx) 与 [Fixtures](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Fixtures.tsx)。固定卡已核验，main实现与媒体不冒称同版执行。

以下分**原卡给定、源码可见、抽帧可见、制作推导**。两片均1920×1080、30fps，无音轨；A130帧约4.33秒，B168帧5.6秒，各查看16帧。未正常速度完整观看、运行上游、取得原卡所述Perplexity／Slack原片或实现原创镜头。案例参数不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．两式选型：隐藏交换与持续变形不是一回事

| 条件 | A：最薄处换形 | B：矩形到构件 |
|---|---|---|
| 起终轮廓差异大 | 用极窄状态遮蔽交换 | 不强做无依据的顶点映射 |
| 前文反复出现输入框／卡 | 可以，但连续性较弱 | 保留矩形作为一根构件更直接 |
| 最终身份可拆成几何部分 | 不一定需要 | 必须先有清楚的构造与槽位 |
| 需要表达真实软件结果 | 交换只是导演语汇 | 拼装也只是导演语汇 |
| 主要风险 | 换形露馅、文字落位太慢 | 中途散架、构件残影、拼缝跳边 |

**制作推导**：不要把UI变标志当作真实操作的产品响应。前文真实结果先成立，身份收束随后进入。教程若尚需解释输入内容、消息发送或生成结果，就不能让输入框过早变成标志，把证据一并拿走。

## ２．先排两个完成态，而非先调弹簧

### ２．１　A：柔光亮场中的横向身份

**源码可见**：起点是340px自绘笑脸笔记本图标，深墨轮廓、白色屏幕与轻接地影；背景近白、上方柔光、少量暖色环境。终点是300px标志，墨色框与琥珀斜切，名称112px／700、0.03em字距。标志中心最终x489，名称起点x676，与标志可见右缘留呼吸空间。

图标不是带照片纹理的实体电脑，标志也不需要继续保留接地影。影在46→60退去，让“物体图标”转为平面身份，材质职责随对象角色改变。标准标志与其可见图形不是同一包围盒：300px SVG内的框实际约225px高，不能用300直接当可见高度。

**抽帧可见**：A由一个有表情的图标转成开口框，随后出现琥珀斜片，最后左标右字，周围大片浅底。没有每个阶段都加新背景或卡片，形态变化本身承担信息。

### ２．２　B：构造图式亮场

**源码可见**：背景从`#f5f6f2`到`#e3e5de`，主墨`#10121a`、钴蓝`#2446ff`、琥珀点缀。初始输入框1040×132，中心960／690、圆角34；字44px，发送键84圆形。上方有频道与两条示意消息，34px消息正文、次字较弱，为输入框提供上下文。

终态标志中心从960左移466到494、纵坐标492，缩到0.7；标志几何高330变231。名称110px，起点由标志可见右缘加60计算，约688.75，副句位于y682、46px。构造线与十二栏网格建立秩序，不把完成身份做成浮空发光玩具。

**抽帧可见**：B先是消息输入场景，文字飞离，输入框变黑并挤成长竖笔，横笔与斜片依次补上；终点是品牌海报。这里的消息、人数、渲染命令是构造内容，不能作为真实协作或渲染结果证据。

## ３．A完整动作链：晃动预备、压薄、换形、展开

### ３．１　预备动作要有支点和递增幅度

**源码可见**：0起图标弹簧入场；12／18／24／30／34依次为0、−12°、14°、−18°、0，段内inOutSin。变换支点在图标78%高度附近，像底部带住上方的晃动。接地影随角度横移，并随压薄收窄。

**制作推导**：预备不是固定要晃两次。短章节连接可以一小次预备或直接翻薄，避免小动作消耗口播。图标底部若没有承载体，强接地影会与漂浮造型矛盾。先定它是符号还是物件，再定支点。

### ３．２　34→46是scaleX，不是真rotateY

图标以inCubic将横尺度1→0.04，整体不执行rotateY。它是侧翻的二维视觉近似，不能拿来解释真实图标三维侧面。飞行中超过某进度加普通blur，另叠两张稍宽残影。

残影gs＝当前iconScaleX＋0.12／0.24，封顶1；不是读取前0.12／0.24帧姿态，也不是两张真实历史采样。层透明度0.22／0.14、6px模糊，用于保持甩动的宽尾。

46帧分支从旧图标切成标志，旧形理论横尺度此时0.04，新标志也从0.04展开。整数45帧旧形约仍为0.2606，46已是新形；最薄旧形并没有单独显示一整帧。是否穿帮要看实际播放与采样，不能只因连续函数有0.04就认定视觉交换无痕。

### ３．３　展开与斜切分成两拍

46起标志横尺度由damping11、stiffness130、mass0.9弹簧从0.04回1，允许过冲。53起琥珀斜切用另一弹簧进入；Brand组件将cutProgress钳0—1，再沿45°裁切揭示，不是整片做同样横向弹跳。

`BLOOM_END=62`只是未用于控制的常量，不能据此宣称62后弹簧严格停止。名称66起出现时标志可能尚有很轻的余量，需按实际正常播放判断是否应冻结或调整。

### ３．４　名称不是横扫，是每字缩落并对焦

标志64→82左移−471，名称也跟随markX。每字从66＋2.6i起，12帧尺度1.9→1、模糊14→0，透明度独立5帧进入，支点50%／78%。15字符最后102.4起、114.4到位，整数115完整，115—129只有15张完整名称展示。

**制作推导**：名称很长时，保留2.6错峰可能明显拖尾；不能一边增加字符一边只压缩最后的读取时间。可按语义组落位、减少独立缩放，或延长镜头。标准组合宽度仍要用真实字体测，不盲用−471与＋187。

## ４．B完整动作链：先送出文字，再让控件承担新角色

### ４．１　点击、文字飞走与上下文退出

**源码可见**：光标0→18到发送键，20—24压到0.84，20—25发送键短闪；21→32文字加速向右760、向上420、旋−9°，并逐渐变淡／模糊。文字放在输入框外，避免被圆角裁断。光标23→31退，上方上下文22→32退。

原卡称“文字先飞离再灌色”，但灌色28开始，文字到32才完整离开，两者有重叠；应检查28—32的实际字位和墨色边界，不能把它们写成绝对串行。文本还乘`1−uiOut`，morph开始后退得更快。

**制作推导**：如果要展示真实发送，应保留真实发送结果和错误状态。此演示只有导演时间，没有网络响应，输入指令也不保证实际渲染完成。隐喻应明确结束真实操作阶段，不能把飞走的文字当消息已成功送达的唯一证据。

### ４．２　灌色是实色遮罩，不是透明度变黑

28→40，墨色圆形clip从发送键附近扩散，半径按当前bw／bh对角计算，中心随morph几何更新。完成后底色直接接手同一墨色，移除重复色层，避免抗锯齿边缘叠深。

注释有“蓝色灌入”的旧称，实际填入的是MARK_INK，不是钴蓝。钴蓝只承担焦点与构造线，琥珀属于最后斜切，颜色各有身份。

### ４．３　五量共用一个spring，位置也不是静态终点

30起m由damping15、stiffness95控制，x／y／宽／高／圆角一起派生。目标竖笔宽26×330／96＝89.375、高330，中心在标志中心左120.3125；y从690到492。圆角由34收0，并钳住，避免过冲变负圆角。

框的投影和焦点环随m退去，附属工具在m达到约1／3时已退净。morph快段用m的前后差做最多3px普通模糊，非真实方向采样。变形过程中不再塞入独立文字弹跳，五量的共同进度是物体连续性基础。

**制作推导**：共用spring不代表所有几何一定合法。过冲可能使宽度比目标更窄、位置越界；换更极端起终尺寸时检查每帧宽高、圆角和裁切。保留控件的一条稳定边或中心，有助于观众认回同一对象。

## ５．B拼装：槽位先说明去处，构件再落下

上横58起、下横72起、琥珀斜切86起，间14帧；各从上方760落向真实槽位，damping13、stiffness120、mass0.9。按每帧速度将纵向拉伸最多约14%、横向收约9%，支点在底部；回弹时反向压扁。空中有影，靠近后影退，不让标准标志永远悬浮。

构造线在各构件前10帧开始描，历12帧；也就是说构件启动时，槽位尚有最后2帧描线，不是完整轮廓已静置10帧。矩形外扩10，斜切四角按45°边的法向外扩，不能用外接矩形冒充斜片槽位。

guide从落下开始后14帧渐退10帧，最后guide到110结束。它用连续描线mask控制虚线轮廓，不是改变dashoffset让虚线自己跑。中心十字另存在，需与目标构件同源位置。

### ５．１　拼齐后换单一路径，防止同色拼边加深

108起，竖笔和上、下横换成同几何的单一框路径，斜切仍独立。这样避免三块抗锯齿叠合处出现深边与1px台阶。交接必须几何重合；若原构件仍有未结束的位移，换路径会跳。

斜切86起弹簧到108已有22帧，但没有硬钳位；assembled只替掉墨色框，斜切继续由spring控制。不能笼统写108全体严格静止。实际换形前后应分别检查107／108／109。

### ５．２　让位、网格与文字尾部

108→128，标志中心左移到494并缩到0.7，名称起点始终由标志可见右缘加60计算。名称114起、15字符、间1.5、每字16，末字151完整；副句130起、6词、间3、每词16，161完整。输出到167，完整副句只有161—167的7张。

原卡注释“140—168完整海报hold”不涵盖最后字与副句的实际结束。124→168还整组缓推2%，末帧167仍接近但未到最大。网格gridA末尾另有＋0.25基础项，所以没有全部消失，只有构造十字与临时槽位退出。

**制作推导**：区别“构造线已退”“字标完整”“副句完整”“相机停止”。新结论或口号不能只有7帧阅读；延长尾部、减少文本或改语义组，不用“海报hold”一词掩盖未完成的通道。

## ７．原创演绎：资料入口收成一个章节符号

以下为**制作推导**，未实现。教程前文已完成真实资料整理，结尾希望把反复出现的“资料入口”收成“整理资料”章节身份。符号是教学图形，不冒充软件商标；真实操作结果先由界面／文件证据确认。

### ７．１　先设计自己的标准态

终点用一枚自绘书签／资料夹组合符号，高约220，旁边四字标题“整理资料”72px中黑；副句“内容归位，来源保留”30px。背景暖纸`#efebe3`，主墨`#2d3731`，强调深绿`#3d7059`，不沿用上游取景框＋琥珀斜切。

符号拆成资料夹脊、上缘、下缘和一枚绿色来源标签，构件数量由自己形状决定；绿色标签代表来源，不是装饰性斜片。最终先检查留白、字重、符号面积与名称宽度，再选择A或B。

### ７．２　A方案：只需要一次身份交换时

前文的资料入口图标在原位被认出，撤掉真实光标后进入章节收束。图标做一次轻预备，横向压薄，在最薄处换为自绘资料夹符号，再回到完整宽度；符号左移让出四字标题。少字符可整组出现，不必每字1.9倍缩落。

压薄前后保持同一视觉中心和笔画重量，交换时先做前一帧、交换帧、后一帧的放大核对。短图标没有接地情境就不用强影。结束立即给稳定标题与来源标签，不再额外开粒子和扫光。

### ７．３　B方案：控件形体可以真正贡献构件时

如果前文反复出现的是矩形“资料入口”面板，可在真实整理结果确认后，让面板缩成资料夹脊；上、下缘沿明确槽位归位，最后来源标签进入自己的位置。面板原有文字先退出，不把文字压成一条难辨黑线。

所有构件的槽位来自最终符号同一份几何数据。构件与整体路径重合后才交换为标准符号，保留来源标签独立身份。若资料入口的形状与新符号关系牵强，就选A或更直接的缩移，不为拼装多造三个无来源部件。

### ７．４　完整内容接棒与规格推导

| 阶段 | 画面 | 认识 |
|---|---|---|
| 实际结果 | 三份资料已经归入同一主题，来源可查 | 操作完成有证据 |
| 身份承接 | 同一资料入口保留并获得焦点 | 认回刚才使用的东西 |
| 换形／构件归位 | 采用A或B一套，不同镜头重复双收尾 | 形成共同章节身份 |
| 标准态 | 图形、标题、副句完整，临时线全撤 | 记住方法而非特效 |
| 下一镜／结束 | 回到真实来源入口或结束章节 | 学习内容有可行动的落点 |

假设符号可见宽190、与标题间44、四字实测宽288，组宽522，符号中心相对画心为−261＋95＝−166；不要套−471或−466。若B起点面板1000×140变脊60×220，用同一进度驱动几何，逐帧核最窄宽度与交接位置；这是草图规格，实际字体和图形尚未验证。

声音只服务主要节点：A一次翻薄、一次回正；B入口转变后最多给几次轻接触，进入名称段退声。最后一行完整后留阅读，不让末句只剩7帧。真实资源、中文实排、源码实现、正常速度观看和试听目前均待完成。

## ８．失败诊断与合格判据

| 失败 | 修正 | 可观察的通过证据 |
|---|---|---|
| A交换时看见两种形状 | 重新定最薄状态和交换帧 | 前后形体在窄态有连续支点 |
| A称真Y旋转实际只是scaleX | 明确视觉近似或另建三维 | 描述与实际空间一致 |
| A长名称拖到结尾仍模糊 | 从末字符倒排，改语义组或时长 | 完整名称之后有实际阅读段 |
| B文字压在墨色上 | 调文字飞离、灌色时序与路径 | 旧文案退净，不出现脏重叠 |
| B五量不同步，中途裂开 | 用同一语义进度，核每帧几何 | 始终认得出同一个矩形主体 |
| B落点随机，无预告 | 槽位先出现，位置由同几何生成 | 构件去向在落下前可预期 |
| B拼合后深边／台阶 | 完全重合时换单一路径 | 107—109无轮廓跳变 |
| 声称网格全退，实留基础项 | 区分永久网格与临时构造线 | 终态说明与画面一致 |
| UI变标志被当发送／生成成功 | 保留真实完成证据，明确收束身份 | 动画不制造未发生的结果 |

Storyboard应分别选择A／B，写清前文对象身份、终点自己的几何／美术、交换或构件关系、文字与槽位时序、最后阅读及下一镜。静帧、全速、声音、真实结果与标准身份各自核验；本文不宣称原创或商用成片已通过。
