# 界面逐层退场：把一次终结动作收成单一焦点

本镜从完整界面开始，外围区块有顺序地退开，只留下被操作的按钮，再把焦点交给最终身份。它的价值是减法：观众逐步不再需要看辅助控件，最后只记住完成动作。界面蒸发是一种导演隐喻，不能冒充真实软件发布后会消失，也不能用按钮发光替代成功证据。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/outro/ui-strip-away-outro.md)、[UiStripAwayOutro.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/outro/ui-strip-away-outro/UiStripAwayOutro.tsx)、[官方演示](https://vincentwei1021.github.io/video-shotcraft/media/ui-strip-away-outro.mp4)。另核对 [Fixtures](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Fixtures.tsx)、[Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx) 与 [Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)。固定卡已核验，main实现与媒体分别研究，不宣称同版执行。

本文分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、144帧、4.8秒，无音轨，查看16帧。未正常速度完整观看、运行上游、取得Framer原片或实现原创镜头。参数解释案例，不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先判断什么能退，什么必须留下

| 本镜内容 | 可退的部分 | 必须保留的证据 |
|---|---|---|
| 一次真实完成操作的回顾 | 已不需阅读的编辑工具 | 实际结果与操作对象身份 |
| 章节从操作进入总结 | 临时注记与外围控件 | 核心结论／最终状态 |
| 发布会式视觉隐喻 | 明确作为设计演示的UI | 不伪装真实发布链路 |
| 普通保存或确认 | 不必全场蒸发 | 实际保存状态与正确位置 |

**制作推导**：原卡倾向终结性按钮，取其“动作能量要与语义匹配”的理由，不写成所有Save都禁止使用。真正决定表现强度的是当前内容任务。教程要教发布，应先看真实返回状态、链接或成品，再进入视觉收束，不能按34帧点击就自动宣布成功。

## ２．起点美术：一扇有结构的编辑器

### ２．１　暗侧栏、亮属性、浅画布有明确层次

**源码可见**：左240宽深灰图层栏，顶60高近白工具栏，右300宽属性面板；中部浏览器预览框位于320／130、1180×850，圆角18、细边与两层软影。画布为`#ececea`、24px点阵，主预览内四卡按2×2排列，每卡480×280。

左栏层级用缩进和不同图标表达，当前选择有靛蓝浅底；右侧坐标、布局、填色与阴影字段分节，字号12—13px。它们属于构造的工作台示意，不是实际产品功能的运行证据，也不是本镜必读信息。

按钮150×40，中心1821／30，初态处于工具条右上。底从`#6a72e0`到`#545cd0`，白字15px、600字重，10px圆角，顶内高光与小接触影；整场唯一强色指向操作目标。

**抽帧可见**：开头能辨认图层、属性和画布，光标由中部移到右上；中段不是整屏同时消失，而是外围区域依序退开。最终按钮独处暗场，再交给上游标志与名称。

**制作推导**：真实界面优先用实际素材。分层必须对应语义区块，按钮要从原位置精确取出；不能重绘一个相似按钮替换后让形状、字号与边缘跳变。用截图分区时注意顶栏共享底板与跨区阴影，切缝不能留下断裂线。

### ２．２　终点先排好，按钮不能只是“漏删的小块”

按钮到中央后以布局尺寸放大到225×60，字22.5px、圆角15，配同色520×320径向光盘，周围近黑`#0b0c10`带极弱冷光。焦点仍是按钮的完整轮廓，不是光盘本身。

最终身份为132px标志、68px名称、30间隔，浅纸白字；两者居中成组。标准态是否应换为结论、成果文件或章节身份，按内容决定，不必总以品牌接棒。

**制作推导**：暗场中的225宽按钮依然很小，只能读一个短动作。要讲“导出了哪一个文件”，应让实际文件或预览接管，而非继续放大按钮。先决定结果画面，再倒推外围退场。

## ３．六组退场不是六个互不相关的淡出

点击基准34。各组用14帧inQuad，使离场逐渐加速，透明度1→0、模糊0→7，并加各自位移。

| 组 | 开始→结束 | 位移 | 语义与层级 |
|---|---|---|---|
| 左侧栏 | 38→52 | −140／0 | 先撤外围导航 |
| 右属性面板 | 42→56 | −90／20 | 实际向左内侧，不是所有部分都往画外 |
| 四内容卡 | 46／49／52／55，各14帧 | 左右±70，向下50—80 | 子内容再错峰 |
| 顶栏两端 | 50→64 | 左−80／−60、右80／−60 | 按钮单独保留 |
| 预览框／画布底 | 54→68 | 0／40 | 承载容器最后退 |
| 顶栏中段 | 58→72 | 0／−50 | 按钮迁移时清掉最后工具壳 |

**源码可见**：四卡嵌在预览框退场层里。父层54→68变淡、下移、模糊，会与子卡动作相乘／叠加；最后一张子卡计划到69，父层68已透明，所以它并非独立显示到69。不能把六组时间简单相加得到总时长。

背景压暗另从54→74，用20帧将浅画布交给近黑底；不是14帧内容框结束时全场立即纯黑。临时图层有退场关系，按钮始终z30、光标z40，避免被散开的块压住。

**制作推导**：先检查最残缺的中间态。原位切图应仍像正在有序退场的界面，而不是删掉半个控件。容器与子内容的透明度相乘可能太快，应选择只让子层承担某一通道，或明确这种加速淡出的目的；不能只看每层单独动画正确。

## ４．操作与光标：点击要有触点，退出要有次序

光标从4→32到达按钮附近，x用inOutQuad、y用另一条贝塞尔，所以路径略弯，不是额外设控制点的严格三次弧线。SVG笔尖位置需计入路径的M1／1与30×38视框缩放；触点落在按钮内即可，不要求光标div左上等于按钮中心。

33—36短压到0.88；按钮34起使用damping12、stiffness220的弹簧进度再经正弦形成最多12%压缩。不是把整个按钮直接绑到spring尺度，让它无限弹跳。

光标40→50淡出，即点击后6帧才开始、到点击后16帧全退。原卡“点击后10帧内淡出”应区分淡出时长和相对点击结束时间。它没有跟按钮飞到中央，避免两个主角一起移动。

**制作推导**：实际触发发生在什么帧取自真实操作／Storyboard语义，不因一个压缩弹簧就自动成立。真实按钮若有loading、禁用或返回确认，先保留它们；视觉退场不能覆盖会改变观众理解的状态。

## ５．按钮迁移、背景建立和字标交棒

### ５．１　迁移是几何同源，不复制第二颗按钮

58→76，用inOutCubic将中心1821／30移到960／540，宽高和字号从1到1.5倍。父层额外承担点击压缩；位置与布局尺度共用btnCenter，光盘强度又同时受btnCenter和bgDark控制，按钮到中部时环境才完全支撑主角。

代码按相邻帧位置差算速度，模糊最多3，但使用普通`filter:blur`，**不是单轴方向拖影**。旧注释虽说方向性，当前视觉机制应按实际代码说明。真正需要沿路径拖尾时要另设计，但不能为修正文档随意加实现。

### ５．２　按钮独占与字标不是十帧空窗

按钮86→98退场，且用out曲线轻微放大6%；图标96开始，名称99开始。96时图标弹簧0，97首次可见，按钮直到98才严格0，因此存在短交叠，而非“按钮全退后约10帧才有字标”。

按钮76到中央，背景74已压暗，76—85约10张无新退场的按钮主位。它的“仪式感”来自周围信息减少，不来自很长的纯黑等待。

图标damping14／stiffness90，组尺度0.86→1；名称晚3帧，另从左偏16回到原位并解糊。弹簧未设有限帧硬结束，不能将“144帧共4.8秒”直接推出末段精确一秒完全静止。需要按实际视觉与数值容差检查，再决定是否留足阅读。

### ５．３　真实功能与导演层严格区分

演示没有发布网络请求，图层退场完全由frame控制，按钮也没有确认真实链接或文件。真实教程必须先取得与内容相符的结果；收束阶段可以明确是讲解镜头抽离，不把编辑器被分解拍成真实应用响应。

**制作推导**：当结果比身份更重要，把字标接棒改成实际作品预览或文件定位。顺序仍是外围退让、主角迁移、结果接管；视觉隐喻不应改变操作事实。

## ６．关键帧观察

实际查看0、24、32、34、38、46、54、58、66、72、76、86、96、99、120、143。

| 帧组 | 抽帧可见 | 应审查 |
|---|---|---|
| 0—34 | 完整工作台、光标到按钮 | 触点与实际操作对象一致 |
| 38—58 | 侧栏、属性、卡与工具栏陆续退开 | 是否存在断裂残片、父子透明度叠乘过重 |
| 66—76 | 背景变暗，按钮向中央走 | 主角是否真迁移、光晕是否压过按钮 |
| 86、96、99 | 按钮淡出，身份开始接棒 | 交叠和空窗是否符合实际描述 |
| 120、143 | 中央标志名称，暗场轻颗粒 | 末段阅读、弹簧余量和实际结尾 |

静帧能查层级、状态与端点，不能证明全速蒸发手感、真实点击因果或声音。本轮未实际操作上游工作台，也未核验它是否具备真实Publish能力。

## ７．原创演绎：从裁切工具退到实际导出照片

以下为**制作推导**，未实现。教程已在真实软件完成方形裁切并导出，本镜回看“工具只是过程，照片是结果”。要先有真实导出文件及尺寸，不能由一次导演动画自动宣布成功。

### ７．１　先设计结果画面

终点为真实800×800照片居中，以约760×760显示，周围暖灰`#e8e5dd`，下方30px文件名与“800×800”实际尺寸；照片的主体、侧光与纹理承担质感，只有克制细边和轻投影。不要让最终结果只剩一个“导出”按钮。

起点用实际裁切界面，保留同一照片的裁切位置与文件身份。将已不用的工具栏、参数与侧栏按语义分区；临时标注先撤，照片与实际导出结果在整个镜头中保持同一内容，不因转场换裁切。

### ７．２　完整调度

| 阶段 | 画面动作 | 内容认识 |
|---|---|---|
| 实际确认 | 展示已存在的导出文件及正确尺寸 | 结果有证据 |
| 回看界面 | 短暂定位此前“导出”入口，不再执行一次假点击 | 连接过程与结果 |
| 退工具 | 侧栏、参数、画布辅助线依次退弱 | 辅助工具完成职责 |
| 照片接管 | 同一裁切照片进入中央，按钮不成为最终主角 | 真正留下的是照片 |
| 阅读 | 画面停止，文件名与尺寸完整 | 核对输出对象 |
| 下一镜 | 展示照片实际应用场景或结束教程 | 不再重复一轮品牌动画 |

这是讲解层对界面的抽离，应保持前后语境清楚；若真实软件导出后本来还停在编辑器，不暗示应用真的蒸发。可通过“回看结果”的旁白和无光标的摄影式变化表达这一层切换。

### ７．３　坐标、材质与时间

假设源图1600×1000，裁切区域为左300、顶0、宽1000、高1000，再输出800×800；展示800文件到760框是0.95，不能把未裁的1600×1000强拉方。源图、界面裁切框和导出预览按真实同一矩形对应，若实际裁切值不同必须替换规格。

外围退场保持轻位移而不夸张蒸发blur，照片需要准确辨认，避免七层噪声与光晕同时出现。照片到中央后让界面只剩低权重来源提示，尺寸字在照片下方，不遮主体或字幕。结尾从最后尺寸字完整后算阅读时间。

声音按真实操作与结果回看分工，实际导出时才有相应反馈；导演层退工具不再配一次成功音。当前实际软件、照片、文件、音频与原创实现均未验证，不能将此设计稿记作导出成功证据。

## ８．失败诊断与合格判据

| 失败 | 修正 | 可观察的通过证据 |
|---|---|---|
| 全UI同帧消失像故障 | 按语义区块分层，重排cue | 退场有外围到核心的秩序 |
| 控件被像素切残 | 重做完整区块边界、共享底板 | 中段仍是合理界面而非碎图 |
| 按钮还在角落像漏删 | 先定中央终点再迁移 | 主角身份和空间变化清楚 |
| 光标跟着按钮抢戏 | 完成触发后退光标 | 单一焦点接管 |
| 模糊被描述成方向拖尾却是普通blur | 纠正机制或按需要另实现 | 文档与实际画面一致 |
| 按钮与字标同时强亮 | 复算86／98／96／99的交接 | 接棒时只有一个明确主阅读对象 |
| 软件没有成功证据就黑场庆祝 | 先补实际返回／文件，再做收束 | 动效不伪造产品结果 |
| 结尾只有按钮，没有作品 | 让实际结果接管最终构图 | 观众知道得到什么及其身份 |

Storyboard需写清真实完成依据、可退区块、按钮／结果身份、父子层关系、唯一焦点、交接时刻、阅读段及下一镜。静帧、全速、声音与真实结果分别验收；本文不宣称原创或商用成片已通过。
