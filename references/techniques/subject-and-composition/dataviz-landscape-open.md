# 数据景观开场：把汇聚关系拍成有纵深的地景

这个镜头把“不同来源进入同一条工作流”转成可见空间：近处支流经过观众，中景标签提供具体身份，远处主干指向唯一汇点。它首先是关系隐喻，其次才是发光线特效。若真实内容没有汇入关系，或观众需要逐项检查输入输出，就不应把几条光线当作解释已经完成。

来源：[原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/opening/dataviz-landscape-open.md)、[当前实现](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/opening/dataviz-landscape-open/DatavizLandscapeOpen.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/dataviz-landscape-open.mp4)。固定清单原卡已核对；当前main代码与媒体分别研究，不宣称三者已经同版运行验证。视觉工具另见 [Look](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Look.tsx) 与 [Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx)。

本文区分**原卡给定、源码可见、抽帧可见、制作推导**。样片为1920×1080、30fps、180帧、6秒，无音轨；实际查看16帧，未正常速度完整观看、运行上游或实现原创镜头。参数解释案例，不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．镜头职责与使用边界

| 需要表达的内容 | 地景能承担什么 | 后续必须补什么 |
|---|---|---|
| 多来源进入同一工作流 | 来源身份、汇流方向、唯一主干 | 真实材料怎样进入、结果是什么 |
| 大系统包含许多具体对象 | 从几个可辨认实例建立规模感 | 可核对的组织结构与实际数量 |
| 新章节从整体关系进入局部 | 建立一个空间母题与阅读方向 | 切到端正、可读的具体内容 |
| 两种方案的效果比较 | 通常不适合 | 同尺度、同条件的实际对照 |

**原卡给定**的5—8秒、同片一次、与相邻发光线镜头拉开距离，反映的是避免同招反复的考虑。迁移时按口播任务和整片节奏判断，不新增固定次数限制。教程若只需一句“把三份资料放进同一项目”，直接展示真实资料与项目关系可能更清楚；地景适合先建立空间认识，再由实物接棒。

不要将分支数量理解成处理吞吐量。演示里的镜头编号是构造标签，线条不是后台请求轨迹，脉冲也没有对应数据包。

## ２．先画完整海报：天空留字，地面承载关系

### ２．１　构图的两块职责

**源码可见**：地平线在y420，约画高38.9%；消失点x＝960＋1100×0.29＝1279，落在右侧三分区附近。地面约占下方六成，标题左120、顶128，眉题28px、等宽、600字重、0.12em字距；两行主标题108px、650字重，第一行浅白，第二行黄绿。

标题不是在中间盖住流线。左上负空间负责读句，右侧汇点负责引导，下方曲线负责纵深。最终海报同时有三个尺度：大标题、可辨认标签、细线和点阵。标签再多也不能与标题平权；标题出现后，观众应先读主句，再扫回地面。

**抽帧可见**：结尾是偏黑的绿灰地景，黄绿主干从下缘弯向右侧亮点，灰绿支流横向切入；最前方主干虚化、较宽，远处细而淡。六个标签依深度大小不同，没有排成一条水平菜单。天空仍有大面积暗部，发光没有把全屏洗成绿色。

**制作推导**：先检查无动画的完成态。遮去标题时，主干仍应能被辨认；遮去所有标签时，画面仍应有近、中、远；遮去光晕时，线的粗细、雾化和方向仍应支撑空间。任何一项只能靠一大团辉光勉强成立，都要退回构图重做。

### ２．２　材质与光的实际组织

**源码可见**：环境底色为`#070806`，背景光在`#141612／#0c0d0b／#070806`间组织；主干`#c6f432`，支流`#aab09e`，主字`#f6f8f0`，次字`#5f6556`。地面在地平线附近叠灰绿，再向前景压暗；天空只有极淡浮尘，地面点阵与世界坐标锁定。

主干锐利层另复制一层，线宽乘3、透明度再乘0.45，经7px高斯模糊和外层0.75透明度形成辉光。支流没有同样的主干泛光层；不能将原卡“主干／支流都给微辉光”照写成当前代码事实。近景统一11px模糊，混入主干与支流，位于标签之上。

汇点不是突然闪白：1040×520的径向光团中心位于消失点，用screen叠加，118→168逐渐升亮；中心另有8px亮点和18px软晕。地平线细线只在接近右侧汇点处偏亮，左右逐渐消失，避免出现硬水平分割。

**制作推导**：保留主干与支流的亮度差，远雾先消除拥挤，再考虑加光。不要给每个节点一圈同样强的光。标题用最稳定的实色字形，不能与地面一起虚化。更换配色时同时检查暗部压缩后的支流可见性，不能只改强调色。

## ３．空间来自同一套投影，不是三层各自漂移

**源码可见**：世界在X／Z平面，摄影机离地220，焦距1100，屏幕投影为：

```text
Zr = worldZ - cameraZ
screenX = 960 + 1100 × (worldX - cameraX) / Zr
screenY = 420 + 1100 × 220 / Zr
```

摄影机前移950世界单位，同时横移：`cameraX＝0.29×cameraZ＋lat`，lat由−140到110。前移使用`bezier(0.3,0.3,0.55,1)`，进度以frame／179归一化；横移使用对称smooth缓动。开场前进速度非零，结尾速度趋零；不应把它写成全程匀速。

同一静态点在Zr变小时自然变大、下移；横移会使近点比远点横向移动更多。不需要额外给近、中、远各乘一套横移倍数。把独立漂移再叠到标签上，会让图钉离线。

**制作推导**：先固定一枚世界点，逐帧检查线、图钉与标签是否共同投影，再扩到整场。若采用另一种平面分层方案，应明示是视觉视差近似，不把两套模型混在同一坐标推导里。摄影机沿主干前进不等于沿主干精确曲线运动：当前cameraX走线性斜向加横移，主干本身还有正弦摆动。

### ３．１　支流切向接入，主干必须保持唯一

主干`X(Z)＝0.29Z−160＋150sin(Z／950)`，其导数决定支流终点切线。每条三次贝塞尔的倒数第二控制点沿该切线后退，末段因此顺着主干进入，而不是直角撞上去。11条支流中一条贴近镜头形成前景掠过，其余提供中远层。

支流先用241个参数样本估计弧长，再重采样为90段；同样的生长进度因此近似对应世界弧长。主干则使用261个按幂次分配Z的样本，**没有做同样的弧长重采样**。不能把原卡“每条等弧长”当成当前主干的精确机制。即使等世界弧长，透视后的屏幕速度也不会恒定。

线段使用butt端帽，避免半透明接头反复叠成珠串。更换曲率或采样数时要检查尖角、短段接缝和光晕连续性；不能只看路径控制点在数学上相切。

### ３．２　深度同时控制粗细、虚实与雾

| 层次关系 | 当前实现 | 设计意义 |
|---|---|---|
| 近裁剪 | 两端任一Zr＜70就跳过该段 | 避免投影除数过小，仍需检查边缘突断 |
| 线宽 | 世界宽×1100／Zr，再钳0.9—46 | 近大远小；钳位是可见性折中 |
| 近虚焦 | Zr420—1050连续交叉混合 | 不按单一阈值骤然切换锐利／模糊 |
| 近层强度 | 宽乘1.3、透明度乘0.7 | 宽前景让出阅读权 |
| 远雾 | Zr2600—11000逐渐压到0 | 汇点不挤成亮白线团 |
| 标签尺度 | 1500／Zr，钳0.7—1.7 | 保留可辨认程度，但不是纯物理透视 |

**制作推导**：近景不应只是一条沿自身方向移动的直线。曲线拐点、端点或横向穿越才能让观众看出视差；参数写了前进量不代表画面具有可察觉的运动。近虚焦也不能长时间挡住本镜唯一必读标签。

## ４．完整动作链：生长、流动、标签、标题是四套交接

| 动作 | 源码时序，30fps | 核对重点 |
|---|---|---|
| 暗场建立 | 0→12 | 外层从0.35升至1，首帧不是纯黑 |
| 主干生长 | 0→36，EASE.out | 当前曲线是贝塞尔近似强减速，不是精确out-cubic |
| 支流生长 | 开始4、8、11、16、20、25、29、34、38、43、47，各34帧 | 最后一条到81，不是注释所说70结束 |
| 标签启动 | 44、53、62、73、84、96 | 非均匀间隔；96是最后开始，不是全部完成 |
| 标签内部 | 图钉10、立杆晚2用12、胶囊晚6用14 | 最后胶囊到116才完整，不是104全完成 |
| 眉题 | 104起，透明度14帧、位移18帧 | 两通道结束分别118、122 |
| 两行标题 | 第一行110起、第二行121起；每词20、词间5 | 空格不消耗错峰，末词分别135、146结束 |
| 汇点升亮 | 118→168 | 标题落定后光仍在变 |
| 收尾 | 输出到179 | 摄影机、脉冲、浮尘仍有变化，不是全画面冻结 |

### ４．１　图钉先落线，立杆再把名字送入阅读层

图钉12k见方、圆角2.5k，出现时有短过冲；脚下留暗色外圈，与亮线分开。立杆高44k、宽1.5；胶囊高46k、圆角10k、深色82%底、淡边与低位软影。ID是25k等宽600字重，说明文字为其0.82倍、较低对比度。

标签不做地平面斜切，而作为端正的屏幕牌固定在投影锚点附近；这是阅读设计。由远到近排序，近标签遮住远图钉。近景虚线再叠其上，建立前景经过的关系。换成长中文时先重做胶囊宽度、避让和行距，不能只换字符串。

原卡提出字号约18px等效；代码下限25×0.7＝17.5px，说明文字更小。是否可读还受暗部、最终播放尺寸和压缩影响，不能凭字号下限宣称通过。

### ４．２　生长结束后仍流动，但不伪装真实数据

主干生长结束36之后用24帧逐渐加入脉冲；各支流也在自身长完后用24帧加入，最后一条到105才充分建立。沿线相位为`u×n−frame×speed＋seed`，主干n4、speed0.022，支流n2.2、speed0.018；正余弦峰再取四次方形成窄峰。

近处脉冲影响被减弱，Zr500→1400才逐渐充分显现，避免一条很长的屏幕线段忽亮忽暗。亮峰向参数u增加方向传播；这是场景流动语汇，不能用来计算延迟或吞吐量。

**制作推导**：读标签时让运动退后。若旁白在讲三项来源，分别留读取窗口，其他标签只作环境；不要六枚一浮现就各敲一次提示音。原卡建议低频铺底与交棒一次音效，但本样片无音轨，没有试听依据。

## ５．关键帧与设计审查

实际查看0、12、24、36、44、54、64、84、96、110、121、136、148、160、168、179。

| 帧组 | 实际可见 | 制作时检查 |
|---|---|---|
| 0—36 | 暗地平线、主干与两侧支流逐渐显露 | 未读字前是否已经有主方向，线端是否像无意义粒子 |
| 44—64 | 第一、第二标签出现，近线较宽且虚 | 图钉有无离线，牌面与光线是否争夺焦点 |
| 84—110 | 更远标签补入，左上眉题开始出现 | 此时不能再强迫观众逐枚读完所有标签 |
| 121—148 | 两行标题成为主位，地景仍运动 | 字形裁切、两行间距、标签是否压到标题区 |
| 160—179 | 完整海报、汇点亮部、前景曲线 | 结尾接棒位置是否明确，所谓hold是否只是慢动 |

抽帧支持构图和状态观察，不支持“低速手感自然”“脉冲不抢眼”等正常播放判断。实现后还要看相机减速是否连续、字幕与标题是否冲突、暗部压缩后支流是否丢失。

## ６．原创演绎：三份资料进入同一研究主题

以下为**制作推导**，未实现。真实内容任务设为：观众已有三份不同材料，要理解它们进入同一研究主题后仍保留来源身份。不是演示三条光线自动生成正确结论。

### ６．１　先设计结果，再选择隐喻强度

终点不是品牌口号，而是“来源仍可追溯”的空间关系。1920×1080画面将地平线放y470、汇点放x1340；左上两行中文分别为“集中资料”“保留出处”，建议先用84px中黑、实排再调整，第一行暖白，第二行低饱和青绿。背景墨绿`#101914`，支流灰绿`#81998b`，主干`#78cda2`，不沿用上游荧光黄绿与品牌。

只保留三条有身份的支流，分别标“访谈节选”“产品说明”“实验记录”。标签是教学资料名称，不是假装真实软件对象编号。每枚牌预留约300×66、28px正文与小型文件类别符号；同一符号在后续资料页继续使用。主干不再用11条分支制造不存在的规模。

可用真实材料缩略片而非纯发光地面：标签下面带一小段确有依据的页面边缘／文本纹理，近景仅用一张不可读的纸面掠过，空间质感来自纸张亮面与暗环境的边缘差，不增加“扫描成功”图标。实际素材未取得时必须标为示意，并在后续换成真实材料。

### ６．２　镜头从来源走向主题，不从光线跳到三张卡

| 阶段 | 画面设计 | 新认识与接棒 |
|---|---|---|
| 起点 | 先看一枚“访谈节选”及其纸面符号，中景清晰，其他两条来源尚弱 | 主角是具体材料 |
| 扩展 | 摄影机低速横移，另外两枚在各自原位进入视野；不按同节拍弹出 | 来源不同，但共处一个关系空间 |
| 汇流 | 三条线切向接入唯一主干，三个来源标识不消失 | 集中组织不等于丢掉出处 |
| 结果 | 主句完整，三来源与主干共同静态成立 | 观众能指出每份材料来自哪里 |
| 接棒 | 沿主干到主题页入口，以同色细线匹配真实页面的来源引用边 | 隐喻结束，真实引用操作开始 |
| 下一镜 | 正视真实资料页，定位一段原文及其引用记录 | 用实际内容证明追溯能力 |

先定三个标签完整字框与相机路径，再决定飞行距离。以同一投影计算线和锚点，每帧检查字框交叠、标题区及字幕区；不能只保证图钉中心没出画。图钉与立杆只作身份锚点，不给全部牌做强过冲。临时亮峰在结果阅读前收掉，相机归位后留实际阅读时间；旁白较长时宁可拆成建立关系与实际操作两镜。

### ６．３　原创参数怎样重新推导

若借用本例焦距1100与高度220，地平线改470，则标签锚点想落y690，其Zr应为242000／220＝1100；想落y600则Zr约1861.54。再由目标screenX反求世界X，而不是凭感觉把六枚牌改成三枚。字牌属于阅读层，尺寸可以按任务钳位，但要明示不是实体纸片的精确物理尺寸。

交棒到亮页面时，先设计页面真实构图与暗场末态共同的颜色、线端或来源符号，再选择遮挡／亮部匹配；不能用全屏闪白掩盖两边完全不相关。配音进入原文阅读时撤低频和气流，真实操作声只对应实际交互。当前没有音频与连续播放验证。

## ７．失败、修正与可观察的通过条件

| 画面问题 | 返回设计哪一步 | 修正后应看见什么 |
|---|---|---|
| 线束像科技屏保 | 减分支，补来源身份与汇入目标 | 能说清楚谁进入哪里 |
| 全部线条同亮，远处成白网 | 重排主干、支流、远雾和光晕 | 眯眼仍只有一个主方向 |
| 近中远写了不同速度，实际像平面滑动 | 加曲线特征或改真实投影，核实际位移 | 固定点随深度产生可辨认差速 |
| 图钉浮在线旁，标签各自漂移 | 用同一世界锚点生成线与牌 | 脚点始终落在同一条线上 |
| 标签全挤在地平线 | 重设世界位置、杆高与牌面尺寸 | 近中远牌上下错开，文字无遮挡 |
| 尾段仍不断新增对象 | 从最后一枚完整时间倒排 | 标题阅读不被新的入场打断 |
| 说是静止但地面一直在流 | 明确慢动氛围或冻结阅读的职责 | 描述与实际运动一致 |
| 隐喻之后又出现三张空说明卡 | 先设计真实资料接棒镜头 | 下一镜立即提供可核对内容 |
| 字能看见但读不完 | 减必读标签，延长阅读或分镜 | 正常播放能复述本镜核心关系 |

Storyboard应写清来源身份、唯一主干的含义、终点认识、静态美术、近中远职责、标签读取顺序、投影与遮挡、最后一项动作和下一镜证据。实现后分别审核关键帧、全速动作、声音与真实资料；本篇是具体设计参考，尚不是原创镜头或商用成片的实测认证。
