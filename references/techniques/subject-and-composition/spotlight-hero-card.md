# 聚光主体展示：从页面中认出一个对象，再进入它的实际内容

这类镜头解决“页面里有很多东西，观众该先认识谁”。完整表达应是：建立所在位置→有理由地定位→改变观察距离→展示对象身份与特征→进入操作或返回原位。灯光、悬浮和轮廓都服务这条链。只有一张卡被放大、描金边，再配一句口号，仍然没有解释它为什么值得看。

## １．决定主角的依据，不是任意挑一张卡

**原卡给定**：希望把一个核心对象建立为产品的基本单位。**制作推导**：教程需要进一步回答它承担什么知识任务。例如解释一个任务条目的状态、一个配置对象的组成、一张资料卡的证据入口。对象形式可以不同，但定位依据必须来自内容。

| 内容需要 | 适合保留的动作 | 应删掉或改写的部分 |
|---|---|---|
| 认识一个可操作对象 | 保留来源位置、突出身份、靠近、进入真实操作 | 与内容无关的两圈光束和宣传口号 |
| 看清表面或形体 | 光向、轻微侧角、轮廓、离面关系 | 大段必须在斜面上读的正文 |
| 解释页面里的某个字段 | 定位、局部正视取景、字段关联 | 为一行字段把整个页面戏剧化悬浮 |
| 确实存在搜索／筛选过程 | 按真实操作顺序定位目标 | 随机游灯冒充系统正在检索 |
| 需要比较多个对象 | 先建立共同参照，再按比较任务组织 | 永远只照亮一个对象，其他依据全部压黑 |

聚光游走只是导演引导，不自动表示软件扫描、风险识别或检查完成。悬浮是观察示意，也不证明真实产品支持把条目拖离页面。对象不适合被物体化时，采用局部亮区与平面取景即可。

## ２．先设计近景完成态：主体、注记与环境怎样构图

**抽帧可见**：样片先给整体资料页面，随后锁定中部的一张浅色卡；近景中主体偏右，左侧是两行粗字注记。周围卡片仍留下位置线索，但整体退暗。主卡不是孤立摆在纯黑背景上，空出的原位和邻卡持续解释它从哪里来。

### ２．１　用轮廓和实际信息建立主体

**制作推导**：主体首先要在无光束的静帧里成立。确定完整边界、标题、关键字段、状态与内部空隙的阅读顺序，再确定外形比例。卡片标题承担身份，关键内容承担教学，标签和时间只作辅助；不能把一段真实正文缩成纹理，再让大口号替它解释。

样片的卡是页面截图的局部纹理，文字没有因为抬升重新排版。迁移时应选择当前内容自己的载体：配置片段保留缩进和文件身份，任务条目保留状态与名称，资料条目保留来源与证据入口。不要全部换成相同的圆角卡壳。

在最终观看尺寸检查最细笔画、最长标题、中文字面与数字。主体标题读得清，不意味着内部字段也能读。斜角只够辨认整体时，就将正文阅读交给下一段正视近景，不宣称整个对象已经被观众读完。

### ２．２　左侧说明不是第二个主角

**源码可见**：示例注记是两行粗无衬线，页面空间字号 34、字重 760、字距 −0.035em、行高 1.1；第二行背后逐步生长暖金标记，文字随后转深。它借用了画面空隙，而不是覆盖卡片正文。注记后还有柔暗衬底，抑制邻卡文字。

**制作推导**：教程注记应给出当前需要理解的关系，例如“对象身份保留”“这是同一条任务”，不能替换成另一句无信息的宣传语。字体用与当前视频匹配的真实字形，粗字只强调短结论，正文仍由主体承担。说明太长，应缩短或另安排解释镜头，而不是把原来两行的槽位塞满。

马克条、文字变色和文字内容须协调：底色尚未覆盖的字不能提前变成低对比深字。中文可能跨行或超出底色，必须按实际字块重算。衬底在页面坐标中避开卡片仍不够，注记比卡高时会产生不同投影，需要检查最终屏幕上的重叠。

### ２．３　侧角为何存在，何时必须回正

**源码可见**：近景以 Y 轴倾斜为主，小幅 X、Z 轴旋转配合；焦点不正对卡心，而向左偏移，给注记让位。卡片被看作有空间位置的对象，但仍是二维纹理的平面，不是具有实际厚度的三维实体。

**制作推导**：用侧角交代离面、轮廓和原位关系，用正视保证精确阅读。不要把“斜一点更高级”当成结论。近侧边过大、远侧正文压缩、标签出现镜像或注记挤出屏幕，都说明机位超过当前内容承受范围。教程可只轻倾斜一次，观察完成后回正，靠主体内部变化继续讲解。

### ２．４　负空间按最大状态预留

**制作推导**：以“卡最高、注记最宽、光束最亮”的组合排近景。主体、注记、字幕之间各有独立区域；留白用于视线转移，而不是补满小图标。检查抬升时卡的屏幕包围盒、投影、发光外扩和最大过冲，不能只看落地态。

若卡太大，先决定哪些字段必须读，再改取景；若注记压住邻卡，先降低邻卡竞争或改变注记位置。全局缩小所有东西会同时损失主体尺度和文字可读性。

## ３．灯光有两个阶段，不是一只圆形手电筒

### ３．１　定位阶段：在屏幕空间引导注意

**源码可见**：开灯亮度通过第 1／3／4／6 帧的 `0→1→0.62→1` 建立短暂回闪。光池位置在屏幕百分比中变化，停靠在几个不同位置后锁定目标；圆形到椭圆形的多段衰减让边缘逐渐退暗，低强度暖色混合补充灯的色温。

**制作推导**：先让观众知道页面是什么，再让光引导到有内容依据的目标。若目标已由上一镜或旁白点名，直接锁定即可，不需要绕三个位置凑动作。游走经过的区域不能包含随后要求读出的新信息；暂时照到不等于已讲过。

原卡所谓“压到约 6—14% 亮度”是视觉近似，不能直接从遮罩 alpha 推导实际像素亮度。暖色 multiply、原图颜色和其他混合层都会影响结果。以真实画面检查必要上下文是否保留，不能照抄透明度然后认定阅读合格。

### ３．２　检视阶段：亮区必须依附页面与主体

**源码可见**：第 38—58 帧，屏幕空间圆光池逐渐退出，页面空间的暗场接管。在主卡原位挖一个圆角软孔：紧孔使用 σ22 的模糊，更宽的弱溢光使用 σ60。暗场位于页面上方 Z=1，主卡最低仍在 Z=2，所以主体不被该暗场从边到边盖暗。

这一步解决了透视推近之后“圆灯只照亮卡中央，两端变黑”的问题。**制作推导**：定位时可以有圆光池；开始读对象时，应让它的实际形状决定可读区域。软孔负责环境退让，不能把主卡本身做成被光烧白的色块。

背景变换、遮罩、原位和主卡须共享同一个页面几何。用屏幕上的固定圆角矩形去追随倾斜卡片，通常会露出亮区错位；加大模糊只会让漏光更明显。主卡已单独置于暗场前方时，不再给整张主卡叠一层失控的 screen 泛光。

### ３．３　体积光、边缘光与表面受光各做什么

**源码可见**：光柱由屏幕空间梯形、纵向透明渐变、外层模糊和确定性浮尘组合，模拟远处右上光源。它不是物理体积散射。近景后整体降低光柱强度，减少它和主卡竞争。卡面仍有随离面程度变化的暖色渐变，卡边另有细轮廓与轻微外溢。

**制作推导**：光柱交代方向和空气，表面明暗交代朝向，边缘光分离轮廓，三者不能互相代替。若画面主题是软件文本，体积光可删；若保留，柱内浮尘不穿过前景文字形成噪点。柔光可以在背景扩散，反射应依附表面，阴影应有明确的承接面。

颜色先按角色分工：环境偏暗且低饱和，主卡保留原有材质与文字对比，短暂的暖色强调服务轮廓和当前注记。不要把所有邻卡都加同等金边，也不把光的扫过当成产品“已处理”的状态。

## ４．相机、卡片与注记怎样保持同一个空间

**源码可见**：相机用页面焦点 `cx、cy`、倍率 `zoom`、三个旋转角和透视距离定义。页面与独立注记层使用相同的插值与变换数学。透视容器的距离乘以 zoom，内部仍使用页面坐标，并以焦点为变换中心。

迁移时有三个需要明确的坐标系统：原页面像素、统一三维页面空间、最终屏幕像素。卡原位矩形只属于第一个；截图经过缩放和透视后，不能直接拿原始 x/y 当作屏幕坐标。

**制作推导**：页面、抬升对象、暗场、补丁和注记共享相机状态；分别控制本地位置与深度。固定在屏幕上的字幕不进入这套三维变换。外置注记若随对象存在，仍须同机位；如果只是给观众阅读的说明，可选择正视屏幕文字加跟随锚点，但不能一半随页面、一半随屏幕漂移。

变换顺序会改变结果。该实现的变换字符串为平移后列出 Y、X、Z 旋转，CSS 实际复合顺序不能随意交换。也不能把 CSS `zoom` 直接换成 `scale()`，同时保留原来的透视距离、焦点补偿和子层坐标，假设结果不变。

### ４．１　抬起的身份：原位、实体与影子

**源码可见**：起飞后在原卡处铺页面底色补丁，避免整页截图里还留一张同样的卡。补丁边缘提示原位，卡片独立纹理沿 Z 抬升。落回时补丁退场，最终保留同一对象与其页面位置。

**制作推导**：从实际截图拆出对象时，先处理背景中的原对象，再移动前景实体。原位是位置证据，不应变成第二张同样清晰的卡。底色补丁只适合底面近似均匀的场景；原位下面有网格、插画或渐变时，必须还原对应背景，不能用一块平色盖出明显洞口。

**源码可见**：样片将两层 CSS 阴影附在浮卡外壳上，朝左下偏移，尺寸与透明度随 lift 变化。这能提供离面线索，但不是对页面支撑面求交的真实投影。**制作推导**：若需要严格展示高度、光向或物体与地面接触，应把影子放在承接面并根据相对位置计算，不应把这套简化阴影直接称作物理正确。

### ４．２　悬停、回位与真正结束

**源码可见**：`lift=rise×(1−reseat)`，`z=110×lift+4×sin(相位)×lift`；主卡实际深度还有额外 2px 防止与暗场共面。回位时浮动幅度也随 lift 消失，不是突然关闭一条独立正弦动画。

**制作推导**：卡片若不需要连续展示高度，阅读时可以完全静止。回位必须让屏幕位置、角度、尺寸和来源接口一致，不能只让 Z 回零却换了另一套排版。落地的微压、边缘脉冲和音效是可选反馈，不能代替实际对齐。

注记在上层合成以保持亮度，不等于它真的是自发光物理材质。其与卡同步落回平面可以收束展示，但若教程下一步是进入内容，就让注记退让、机位回正，接到真实操作，不必永远以一张“海报”结束。

## ６．原卡描述与实现不能直接画等号

| 原卡容易被当成保证的表述 | 实际范围与差异 | 制作处理 |
|---|---|---|
| 结尾 30 帧“真静止” | 相机锁定，但落地光到第 156 帧仍衰减，浮尘、暗场呼吸和全屏颗粒仍可变化 | 分开检查相机、主体、临时效果和环境，不声称整帧静止 |
| 卡上“不叠泛光” | 屏幕空间暖色 soft-light 退出，但悬浮卡仍叠了随 lift 变化的表面暖色渐变，还有边缘外溢 | 检查文字和白底是否过曝，不把一句注释理解成全部光层为零 |
| 光柱降低 45% | 公式乘 `1−0.45×进度`，完成后保留 55% | 不是变到原强度的 45%，也不是完全消失 |
| 两圈扫描 | 实现是短亮段沿圆角边界行进，与实际内容检查没有业务绑定 | 只当观察强调，不暗示真实系统扫描或分析完成 |
| 34px 注记推进后约 100px | 受倾角、深度与透视共同影响，不是单一字号×倍率 | 测实际字高和字形，中文另检，不把原卡估值当保证 |
| 升起一定产生正确地面投影 | 阴影附在浮卡，未对支撑面求交 | 展示可用简化，严格空间教学须改影子模型 |

纹理清晰度同样有边界。**源码可见**：推近开始的六帧内，普通卡图与高分辨率卡图交叉过渡。**制作推导**：先保证两图内容、裁切、圆角和位置一致，再交接；否则高低清切换会表现为文字或布局跳变。只加锐化或关闭景深不能补回原图不存在的像素。本文未读取图片原始尺寸，不能给出已验证的采样倍率保证。

## ８．完整原创演绎：任务条目中“状态”与“下一步操作”的关系

以下为**制作推导**，不是上游样片，也未实现。内容目标是让观众认识一条任务：名称表明任务身份，状态说明所处阶段，操作入口决定接下来能做什么。不是展示某个产品已真实执行成功。

### ８．１　结果画面先成立

完成态是一条可辨识的任务对象，包含“整理资料”、状态“待处理”和操作入口“查看资料”；周围任务退弱但仍保留列表关系。旁边只有一句短注记“状态说明阶段”，与状态字段相邻，而不是三张解释卡片。操作入口保持可读，为下一镜进入资料预留明确落点。

这三处文字是原创教学示意，不是某软件现有字段。若当前教程针对真实产品，必须改为有来源支持的真实对象、字段和操作，不能把示意界面包装成产品录屏。未发生操作时，状态不得因聚光或扫描而自行变成“已完成”。

### ８．２　具体美术方案

用浅暖灰页面、墨色正文和一个低饱和蓝色强调角色。任务条目是页面上的实际行块，保持名称、状态和操作的原始空间次序；不强行改成高厚度卡片。状态用清楚的标签形状，操作入口用真实按钮或链接形态，不能让两者长得一样。

近景主体占画面主要宽度，说明留在左上或邻近状态的空区；底部为实际字幕保留。主体高光只用于边缘分离，表面保持哑光；环境压低对比而不是关到纯黑，仍能认出上下相邻条目。无须体积光柱和两圈金光，这个镜头的质感来自准确的形态、字体、空间和阅读调度。

名称采用较重的正文标题，状态短词保持足够字面，辅助日期降低权重；操作文字不能因不是主角就缩到不可读。当前关注状态时，以局部对比突出状态，名称保留作为身份参照；接到操作时才把强调交给入口。

### ８．３　构图草案与尺寸核对

以 1920×1080 设计空间为例：来源列表左端约 240、宽 1440；目标行为 `x=240、y=480、w=1440、h=160`。名称、状态、操作三个区分别占据行内左、中右、右侧区域，实际按最长文字测量，不用文字中心替代控件边界。

基础阅读构图可将目标行等比取到宽 1480 左右，保持正视；轻微离面展示另安排短状态，不能在已接近屏边的构图里再加大透视和升高。若需要精读状态，二次取景到行内状态区，保留一部分名称或持续身份标签，避免观众以为切到了另一条任务。

平面取景可用 `screenX=960+s×(pageX−cx)`、`screenY=540+s×(pageY−cy)` 核对角点。它只适用于无旋转的取景；加入透视后必须投影完整外框。该示意的主阅读态选择 `s=1.03、cx=960、cy=560`，行框约为 `x=218.4…1701.6、y=457.6…622.4`，有空间放置上方说明及下方字幕；这不是对某个实际产品截图的测量。

### ８．４　全过程与焦点接力

| 状态 | 画面与动作 | 观众获得什么 |
|---|---|---|
| A．环境建立 | 展示任务列表，目标名称可辨认，保持自然页面对比 | 知道这是一条列表里的任务 |
| B．有依据定位 | 旁白点名目标，邻行退弱；亮区依附整行，不随机游灯 | 认出当前解释哪一项 |
| C．短暂观察 | 可选一次很小的离面或边缘分离；原位保持参照 | 理解它是一个整体对象，不表示真实拖动操作 |
| D．回正阅读 | 主体稳定在正视近景，环境光不再变化，名称作为身份支点 | 具备阅读字段的条件 |
| E．状态解释 | 焦点落在“待处理”，短注记与状态对应；其他内容保持位置 | 状态说明阶段，不等于操作按钮 |
| F．操作接管 | 状态强调退弱，操作入口获得对比；光标只在确有操作演示时出现 | 从“是什么”进入“接下来做什么” |
| G．下一镜 | 点击有依据的入口，进入对应资料；目标任务身份继续可核对 | 这是一条连续操作链，而非孤立展示 |

时长来自实际口播和 Timeline。旁白需要读字段时取消浮动；已经点名目标时取消寻灯；原始条目没有体积时取消夸张厚度。取舍服务当前内容，不以删去特效降低构图和美术要求。

### ８．５　中段与交接的硬问题

**制作推导**：观察态最高处检查目标行是否扫到说明；回正期间检查文字不发生形变或双影；亮区交接检查对象四角而非只看中心。若来源是整页截图，原对象与前景对象必须处理成单一身份，不能看到两条同名任务。

进入资料的点击点必须落在真正入口；不能把一束光落到按钮上当作点击。资料页内容也必须与目标任务对应。若没有实际资料页素材，就停在解释完成的示意态并标明范围，不制造一页虚构“执行成功”结果。

声音若使用，只服务定位或真实操作；聚光不配“识别成功”，悬浮不必配夸张起飞。正常速度试听确认口播清楚，不能把上游四个拟声逐一当必选项。

## ９．失败诊断与可观察验收

| 失败画面 | 优先修正 | 通过证据 |
|---|---|---|
| 主体和环境都亮，眼睛不知道看谁 | 重排对比和信息重量，不继续加光 | 无光束暂停态也能指出第一阅读对象 |
| 只认得卡壳，内容仍是小字 | 改观察距离、精简本镜信息或分开阅读镜头 | 实际中文名称与当前字段在最终尺寸可读 |
| 圆灯只照到中间，卡两端发黑 | 交接到依附主体几何的亮区 | 近景四角与正文对比稳定，环境仍退弱 |
| 抬升时留下另一张同样的卡 | 修来源背景与原位补丁 | 身份连续，原位只表达位置，不像复制 |
| 注记被压灰或盖住主体 | 修合成层次、同机位投影及衬底边界 | 文字清楚且不产生压到卡面的暗楔 |
| 光向与影子互相矛盾 | 先确定光源、承接面，再选简化或真实投影 | 同一高度变化下离面线索一致 |
| 卡已落地但镜头像没结束 | 清理尾部光效、浮动与不必要注记 | 收束状态可稳定理解，下一镜有明确入口 |
| 看起来精致，讲完却不知道什么 | 重做内容目标和完成态 | 能指出一个新认识或实际操作关系，而非只记得金边 |
| 静帧成立，播放时读不到 | 调整信息引入与动作重叠，留阅读窗口 | 正常速度能跟随环境→目标→字段→操作，不靠暂停补理解 |
