# 四宫并行：用错开的焦点组织同屏密度

四格不是把四条视频缩小后同时播放，而是在共同时间线上安排关注顺序。观众先知道四个现场各是什么，再被最重要的一格吸引，其他格提供环境或结果。若每格都要求完整读字与跟操作，四倍信息会变成四倍遗漏。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/rhythm/quad-split-parallel-scenes.md)、[QuadSplitParallelScenes.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/rhythm/quad-split-parallel-scenes/QuadSplitParallelScenes.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/quad-split-parallel-scenes.mp4)，另核对 [Look](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Look.tsx)、[Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx) 和 [Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)。固定卡已核验，main代码与媒体分别研究，不宣称同版执行。

本文分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、90帧、3秒，无音轨，查看16帧。未正常速度完整观看、运行上游、执行实际审批／渲染／发布或实现原创镜头。案例参数不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先分清四格是比较、并行还是流水线

| 内容关系 | 同屏应怎样安排 | 容易误导的做法 |
|---|---|---|
| 同一对象四种观察 | 比例／身份一致，关注点不同 | 四个不同版本却说同一对象 |
| 四个独立现场 | 各有身份，事件错开 | 暗示它们存在未经证明的因果 |
| 顺序操作的四个阶段 | 明确是过程回顾，标先后 | 同时播成实时并发 |
| 四种方案精确比较 | 同条件与稳定读取优先 | 每格都强动画，无法比较 |

**制作推导**：原卡追求“信息轰炸”，适合很短的音乐密度峰，不等于所有教程都要让观众来不及读。真实口播需要一个主要认识时，其他格必须退为背景。没有并行关系就不以“同时发生”包装流程。

## ２．静态四格先有可辨认的角色

### ２．１　画幅与明度棋盘

**源码可见**：外边与格缝都8px，每格948×528，20圆角。四格位置为8／8、964／8、8／544、964／544；不是四个960×540贴满。亮、暗、强橙、浅拿铁交错，避免同色界面融成一整页。

左上奶油`#f7eee4`是浏览器；右上暖黑`#160d09`是终端；左下橙实底承载132px重字；右下拿铁`#e9d7c4`承载审批卡。每格内部大字、实物轮廓与颜色能迅速区分身份，角标20px只作纹理。

**抽帧可见**：起点四格已占好位置，浏览器和终端从少量内容开始，橙格的大词逐步补齐，审批卡与光标在右下。末态四格分别形成网页、文件准备、三词与上线通知的海报式组合。

**制作推导**：真实素材不必强染四色。可以用画面明暗与构图差异建立角色，边框统一即可。若同屏比较照片，统一色彩管理更重要，不能为棋盘色调改变照片本身。每格必须有一个足够大的可辨认主体，不以20px小角标承担全部身份说明。

### ２．２　浏览器与终端的质感分工

浏览器窗口740×390，左104顶112，轻内高光、短接触影与长软影；标签栏暖灰，地址栏浅填充，页面以96px标题为主。终端没有再包一层厚卡，等宽36／32／40px字体、橙色提示与暖白输出直接建立深场阅读。

**制作推导**：同屏体量要平衡，不要求四格都有相同卡壳。浏览器有窗口边界，终端靠字与暗环境，橙格靠海报排印，审批格靠交互控件；不同载体仍可以共享一套颜色与阴影语言。

### ２．３　大字格与交互格各有主位

左下三词实际为Prompt.、Render.、Ship.，不是旧注释的Write.／Ship.／Repeat.；最后一词暖白，前两词深墨，构成结果重音。右下白卡包含标题、评审身份与两个横向按钮，批准由边框／底色／勾共同表达，不只靠变绿。

这些业务状态都是构造演示。当前代码按frame宣布Approved、Published与3214 views，没有真实人工确认、外部发布或数据来源，不能作为本项目审核／发布规则，也不能迁用这些数字为真实成果。

## ３．四条微场景的完整动作链

| 格 | 实际事件 | 该格的新认识 |
|---|---|---|
| 左上 | 标签6／11／16／21起各9帧；地址0→40；页面44→58；副句50→60；进度条56→62退 | 从浏览器身份到页面内容 |
| 右上 | 命令0→24；输出27、33起各5帧；37末行与37→47急推 | 从执行环境到准备好的文件 |
| 左下 | 三词14、30、49起各8帧落位 | 三个短阶段被组织成一组 |
| 右下 | 卡4→14；光标14→25；按钮25起短压；批准27→33；巡游38→50；52再按；54发布标签；56通知 | 交互串联到定时结果状态 |

**制作推导**：错拍表写的是主要事件开始，事件持续区间还会交叠。先画出每格“需要眼睛追踪”的时段，再分配主次，不能只检查四个开始帧不相等。打字、指针、数字滚动同时存在时，实际注意负荷仍然很高。

## ４．错拍的真实边界：当前也有同帧事件

原卡与注释称相邻重事件至少3帧、从不齐动。实际27同时启动终端第一行输出与批准反馈；另有14大词进入与光标巡游开始、16标签进入等短间隔。按开始时间判断也不满足严格“任何重事件不重叠”。

此外，起点处透明度／进度通常为0，首次可见还要下一帧；27起的两个反馈都可能在28变得明显。不能把函数启动帧直接当观众感知到重音的帧。

**制作推导**：把事件分为主重音、跟随反馈、环境活动，给主重音排错峰；允许必要的因果反馈紧跟同一动作，不为满足3帧数字把按钮结果延迟得奇怪。主事件是否争焦由实际画面强度与观看判断，不以表格间距替代。

### ４．１　终端急推是全场主要空间动作

37→47，smooth进度让尺度1→1.85，y−40，支点在局部0／225；模糊`5sin(πp)`，进出都归0，旧行压到8%。这样只把末行留给观众，而非整个终端同样强地放大。

**制作推导**：急推期间其他格最好只有弱活动；若其他格也在同一时刻放大、高亮或出现新词，会削弱指令感。末行必须实际落在948×528有效区，不能从800宽源盒放大后仍假定完整。

### ４．２　右下两次指针路径保持同一触点语义

光标用两段二次贝塞尔，先从右下到Approve，再沿另一弧到Publish；两按钮短压5帧、视觉反馈晚2帧左右。指针在68→76退，不跟着通知持续停留。

**制作推导**：按钮真实位置、padding、字体行高改变后，旧触点270／318与560／318会失效，应以实际布局框核对。两段路接点需要连续，不能第二段从新位置瞬移。不同格内坐标记得加象限原点，别把局部560误当全屏560。

## ５．“62以后都停”与实际动态不一致

| 通道 | 62以后实际情况 | 对读取的影响 |
|---|---|---|
| 网页主内容 | 标题／副句已完整 | 可以认读网页身份 |
| 网页窗口尺度 | 到90仍持续inQuad推近1→1.1 | 不是完全静止 |
| 终端 | 47以后机位和主要字已固定 | 适合承担一个稳定结果 |
| 三词 | 最后一词57完整 | 可形成静态排印 |
| 通知弹入 | 56起10帧，到66才完整 | 62不是该格完全落稳 |
| 通知数字 | 56起30帧，到86插值结束 | 仍有长计数尾部 |
| 右下光标 | 68→76退场 | 主体之外仍有活动 |

62—89共28张是“收尾阶段”，不能称所有通道都静止28帧。最终数字与光标完整处理后只剩很短全套保持，并且左上仍慢推。若四格都要读，必须从最后一项必要变化结束之后重新分配时间。

两处插入符设16与14帧不同周期和相位，但左上44后、终端27后已经撤掉，所以尾段并非还有两处打字光标持续闪。应以条件渲染判断，不照搬注释的笼统尾段描述。

## ６．关键帧观察与使用限制

实际查看0、6、14、21、25、27、30、33、37、44、49、52、56、62、76、89。

| 帧组 | 抽帧可见 | 应审查 |
|---|---|---|
| 0—21 | 四格建立，各自补身份 | 初始四个现场能否迅速分清 |
| 25—37 | 批准与终端输出、第二大词接力 | 同帧反馈是否争焦，主位在哪里 |
| 44—56 | 网页载入、末词、发布反馈 | 密度峰是否仍能理解一个主要关系 |
| 62、76、89 | 完整组合逐步形成，通知还计数 | 真实尾段读取与状态来源 |

格内部分标签24／20px，只作环境纹理；原卡“辅助≥32”不能解读为所有字已达该规格。真正必须读的字段按最终播放尺寸核对，不能用大屏截图证明移动端或缩小播放也清楚。

## ７．原创演绎：同一物体四种光位的观察地图

以下为**制作推导**，未实现。摄影教程已有同一只杯子在正光、侧光、逆光、顶光下的真实材料，本镜用四格建立差异，随后只进入一格详细解释。没有这些受控素材时，不凭空宣称四张示意图证明真实光位效果。

### ７．１　先设计四格完成画面

每格尽量满幅使用真实杯子与背景，杯子大小、位置和拍摄距离一致，保持同一中性灰白平衡。取消四种染色背景，格缝改12px深灰，圆角可以减到8或直角，避免观察资料变成四张浮空卡。

四格左上都用32px简短光位名，次字24仅给必要条件；一个低饱和橙色细角标指出当前关注格，其他格不变色。主体的真实明暗、杯把阴影和釉面反光负责画面差异，不能后期强拉每格对比制造结论。

### ７．２　完整导演链

| 阶段 | 画面动作 | 新认识 |
|---|---|---|
| 建立 | 四张同尺度图同时成立，先不加光圈动画 | 这是同一对象的条件比较 |
| 第一关注 | 正光格只定位一处真实阴影 | 看见阴影弱而非听抽象评价 |
| 第二关注 | 侧光格接管高亮，另外三格安静 | 看见形体与纹理如何呈现 |
| 第三／第四 | 逆光、顶光依内容逐项定位 | 认识各自差异，不要求瞬间全记住 |
| 回看整体 | 临时圈线全退，保留四个光位名 | 同条件比较图可读取 |
| 下一镜 | 有理由地放大侧光格中的釉面 | 从四格地图进入一项真实解释 |

不必复制90帧信息轰炸。口播要讲四种差异，就分别留理解时间；只需一秒建立“有四种情况”，则四格可短留，但不能声称观众已经学完四种用法。

### ７．３　真实素材与几何

每张若为2400×1350，等比装入948×528需要先按实际比例决定contain或裁切；四张采用同一规则和同一主体基准，不能每张独立自动裁切造成杯子大小不同。要做单变量比较，记录光位之外的曝光、相机、物距和后期条件，未受控就只说观察到的图像差异，不作因果定论。

关注框与杯子细节的锚点来自各格源图，同源映射到全屏。进入单格近景时沿原图连续放大，并由其余三格退让，不切成另一张更精致但条件不同的素材。

声音按关注顺序轻接力，其他格不各自配响；真实口播逐项解释时，四格照片可以完全静止。当前素材、实排、原创实现和正常速度观看／试听均待验证。

## ８．失败诊断与合格判据

| 失败 | 修正 | 可观察的通过证据 |
|---|---|---|
| 四格像四条独立视频 | 编排共同焦点与事件表 | 每时刻有可指出的主要任务 |
| 串行流程被拍成实时并发 | 明确回顾／对照身份，补顺序 | 观众不会误解实际因果 |
| 四处同时要求读字 | 减必读字段，放大当前格 | 正常播放能复述主认识 |
| 宣称严格错拍，实际27两格同起 | 按最终可见强度重审事件 | 表格与实际重音相符 |
| 62后仍计数却写完全冻结 | 从最后必要事件倒排 | 尾段读取有真实时间 |
| 四格照片主体大小不一 | 统一取景、比例与条件 | 能比较光而不是比较裁切 |
| 通知／发布数值是定时假结果 | 换真实来源或明确示意 | 每项状态能回到证据 |
| 全景之后没有具体接棒 | 先选一格与实际细节 | 下一镜立即继续解释 |

Storyboard需交代四格关系、各自主体、同屏主次、错拍而非绝对不重叠、真实终态、下一格接管与声音。静态、全速、真实条件和声音分别验收；当前不宣称原创或商用成片已通过。
