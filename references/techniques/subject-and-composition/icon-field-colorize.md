# 图标原野翻色：用一次有方向的变化统一全景

本镜先让大量灰阶图标形成有秩序的底景，再用几道快速色波改变整场视觉归属。关键是“灰阶铺垫、定向翻色、结果落版”三个层次，而不是把很多图标一起染亮。图标的数量和形状只有在确实代表内容时才具备信息价值；装饰场不能冒充产品集成数量。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/opening/icon-field-colorize.md)、[IconFieldColorize.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/opening/icon-field-colorize/IconFieldColorize.tsx)、[官方演示](https://vincentwei1021.github.io/video-shotcraft/media/icon-field-colorize.mp4)。另读 [Look](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Look.tsx)、[Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx)、[Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)。原卡已与固定清单核对，main实现与媒体不冒称同版执行。

下文区分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、170帧、约5.67秒，无音轨；实际查看16帧。未正常速度完整观看、运行上游、取得Bear原片或实现原创镜头。参数只说明案例，生产默认查 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先判断图标场承担什么

| 任务 | 本技法可表达 | 不能据此宣称 |
|---|---|---|
| 章节从零散工具进入统一主题 | 多样性与共同视觉归属 | 工具已经连通或请求成功 |
| 功能能力全景 | 有依据的不同类别 | 重复170枚就等于170项能力 |
| 装饰性片头／收束 | 丰富纹理与一次能量释放 | 真实产品改变了主题或开启全部功能 |
| 教观众操作某个具体按钮 | 仅适合作环境或连接 | 一次翻色已经解释实际使用方法 |

这与 [同布局主题切换](../interaction-and-feedback/theme-switch-moves.md) 不同。主题切换需要同一真实内容前后配准，这里是装饰性集合被定向染色。若用真实工具图标，应挑确有关系且可使用的资源，并说明图标在该场景的含义。

## ２．完成态先成立：外围发光，中心可读

### ２．１　网格不是随手撒点

**源码可见**：17列×10行，共170枚，格距108×106，奇数行横错54。键帽边长66、圆角18，图形32；最初横向包络从36到1884，纵向从30到1050。网格很接近边缘，后续4%推近会进一步压缩留白，不能在边缘放必须读的文字。

中心落版由小型字标、两行132px／750标题构成，上方间距30、两行间6。第二行用第一道波的暖金，避免整行渐变与子词变换合成问题。标题不是贴在所有亮键帽之上硬读，而是用径向暗幕局部压低中央，保留四周色彩规模感。

**抽帧可见**：最后四段暖色从金到珊瑚红，中心标题附近明显变暗，外圈仍亮。上方金色、中间橙色、下方红色构成纵向秩序；不是170枚各选一种任意颜色。图标形状能辨认心、星、云、相机等，但并非170种独立功能。

### ２．２　熄灯态、通电态是两套表面

**源码可见**：熄灯键帽由`#2a1e17→#1d1510`形成暖黑渐变，顶边7%暖白、细轮廓6%暖色，短黑影向下；图形从三档暖灰选取。不是把通电彩色图统一降低透明度。

通电后，键帽顶部比基色亮8%、底部暗8%，顶部45%白细边、底部低明度压边，带同色26px泛光和低位投影。图形切为深色，保持亮底上的识别度。相机只做整场极慢推近，没有真实三维翻转；“翻色”指裁切擦入和尺寸pop。

**制作推导**：先分别审核熄灯和亮灯静帧。暗键帽要能认出形状，却不能像一排禁用按钮暗示不可用；亮键帽要保留轮廓，不能被泛光连成一片。若内容需要表达“功能尚未启用”，要有真实状态依据，不靠灯光隐喻代替产品事实。

### ２．３　颜色按行形成归属

四波RGB依次为金255／196／84、琥珀255／150／62、橙255／108／46、珊瑚240／70／86。起始行分别0、3、5、8，因此最终是0—2行金、3—4琥珀、5—7橙、8—9珊瑚。后波覆盖更低的行，不是四波都完整扫过全场后只留下最后一种颜色。

**制作推导**：若四种颜色代表实际类别，类别与行位置必须有内容依据，不能为了得到漂亮横带任意改分类。纯装饰时无需强加图例；教学分类时，颜色以外还要有名称或形状线索。一个共同强调色也可成立，四波不是必选项。

## ３．铺满之前先有主次：距离主导，噪声只破齐

**源码可见**：固定种子的mulberry32依次产生每枚的批次噪声、灰阶／起始抖动、形状／波到达抖动。相同种子生成同一场，不逐帧改属性。

浮现批次由距画面中心的归一化距离乘0.75，再加0—0.35噪声，乘10取整并限制到9。启动时间`2＋batch×4.4＋r2×3`；透明度7帧，尺寸0.6→1用13帧overshoot，上浮10px用13帧snappy收回。

因此大致从中间向外扩展，但不是整齐同心圆。不能把噪声幅度调到主导排序，否则中心向外的方向会消失；也不能完全去噪，使入场看成逐圈点名。

**独立复算**：当前170枚最晚启动约43.889，最晚入场尺寸到位约56.889，即整数57帧才全部结束。注释“0—48浮现／48后静置”只大致描述透明度，不涵盖13帧的尾部尺寸。需要“全部铺满后再吸气”时必须按最后一个通道计算。

**制作推导**：这种场景中每枚不需要独立被读到，入场服务整体密度。若实际需要观众认识六种能力，应改为六个有内容的主体，逐个与实际画面关联，不能用大量背景图标代替解释。

## ４．翻色链：先按到达时刻决定当前波，再画完整表面

### ４．１　波前不是整行硬切

**源码可见**：某波到达一枚的时刻为：

```text
波起始帧 + (当前行 - 波起始行) × 1.4
           + 当前列 × 0.25 + 形状随机数 × 1.5
```

行推进提供向下方向，列微差提供斜切边，随机项避免机械直尺感。四波从66／72／78／84起。每枚只考虑能覆盖它的波；后到波覆盖已有色，不重新回灰。

单枚翻色持续4帧。旧色完整层保留，新色层用`clipPath inset`由上向下灌满，裁切进度另走EASE.out；尺寸使用线性p的正弦，最高1.22。两通道共用到达时刻，但曲线不同，不是整个图标绕轴翻面。

**制作推导**：不要用透明度混合代替擦入。暖色半透明叠暗底的中途会变脏，失去清楚的颜色替换。新层、旧层必须采用同一图形和键帽边界，否则波前出现双图。波速度较快时减少同时发生的额外动作，让翻色成为唯一爆点。

### ４．２　白闪在灌满之后，泛光从到达开始

白闪从since≥4开始，再用5帧线性消退，screen叠暖白；刚到达时不闪白。泛光倍数从2.2在12帧内回1。这样擦入阶段保持新色清楚，满色后再有短亮峰，不用灰白半透明层遮住颜色关系。

每行背后的横向光带强度来自该行已经开始翻色的比例，背景光源强度另随66→100提高。行光颜色取当前遍历最后一枚已亮对象的颜色，不能理解为真实混色平均值；其职责是整体舞台染色，不适合承载精确数据。

### ４．３　尺寸与间距要一起审查

满pop时键帽66×1.22＝80.52，横向格距108仍有约27.48的边界间距，主体不会直接相碰，但同色泛光可以相互叠加。实际还叠入场尺寸和全场推近；当前翻色时入场已完成，避免两次尺度峰值相乘。

**制作推导**：换成更大真实图标后重算，不照搬1.22。如果格距紧、外发光强，尺寸虽未相交，视觉上也可能糊成连续色砖。检查中间帧而非只看最后排列整齐。

## ５．吸气、落版与真正的阅读时间

| 通道 | 实际时间 | 与注释的差异／审查点 |
|---|---|---|
| 压暗吸气 | 56→66建立，66→74撤回 | 不是注释58起；与入场尾部有少量重叠 |
| 最后颜色灌满 | 约94.327，整数95 | 全场“约30帧翻色”可作近似 |
| 最后白闪结束 | 约99.327，整数100 | 灌满不等于余波停止 |
| 最后泛光过冲结束 | 约102.327，整数103 | 读字应与这段分工 |
| 中央暗幕 | 118→140 | 暗幕并非在全部标题结束才出现 |
| 字标 | 120→134透明度，120→138位移 | 两通道收尾分别看 |
| 第一行 | 124起，两词、每词20、间隔5 | 149全完 |
| 第二行 | 132起，同样两词 | 157全完 |
| 最终整句 | 157—169共13张 | 不等于注释140—170的一秒终态hold |
| 全场推近 | 0→170，最多4% | 最后输出169，背景仍有极慢变化 |

**制作推导**：排一秒终态阅读要从最后一个必读词完整之后开始算。若标题变中文长句，不能把“逐词rise”直接改成逐字同间隔而不加时；先按语义分组，重算最后完整时间，再分配停留。也可先让标题静态就位，再让外围完成翻色，前提是主体清楚且旁白任务一致。

## ６．关键帧观察与验证边界

实际查看0、12、30、48、56、66、70、74、80、86、94、106、118、136、156、169。

| 帧组 | 抽帧可见 | 实现后再检查 |
|---|---|---|
| 0—56 | 暖黑键帽从中心区域扩展到满场 | 暗场形状是否能识别，浮现是否拖沓 |
| 66—80 | 金色从上部推进，后续暖色在低行接力 | 正常速度是否感到方向，是否像随机闪屏 |
| 86—106 | 橙红到下方，多色横带成立 | 白闪峰值、泛光叠加是否过强 |
| 118—136 | 中央暗幕起，字标与首行进入 | 暗幕覆盖范围、文字边缘是否压亮键帽 |
| 156—169 | 完整双行标题、外围保留亮色 | 实际整句阅读时间是否够，字幕放哪里 |

原卡提到Bear原片的四色快波；本篇没有取得并观看该原片，不把其原速、配乐或逐帧结论冒作本轮亲见。当前官方演示的同色系暖波应按自身画面判断。

## ７．原创演绎：把常用入口组织成四类，而非假装全部启用

以下为**制作推导**，未实现。教程要帮助观众分辨“输入、整理、检查、输出”四类入口。若当前真实工具确有这些能力，先收集对应入口与操作截图；若只是通用原理课，则清楚标教学示意，不冒充真实软件首页。

### ７．１　先设计结果画面

采用6列×4行、24个确有身份的图标，中心不再盖一句品牌口号。左侧约1100宽是集合，右侧约500宽为当前一类的实际界面局部，顶端标题“按任务找入口”。画面底为米白`#efece5`，图标承载面`#fbfaf7`、文字`#282b28`；四类只用同一绿的不同明度辅以类别名和小编号，不用颜色独自区分。

每行代表一类，每枚入口有28px名称和可辨识的真实图形，不重复心形／星形充数。一次只突出当前行，其他行保留60%左右视觉重量；每行的完整信息和总数来自实际清单，不写170+。真实界面局部要展示所选入口引起的具体内容，不能只是一张漂亮空卡。

### ７．２　让一次翻色服务分类认识

| 阶段 | 画面动作 | 内容推进 |
|---|---|---|
| 建立全景 | 24入口已经就位，按四类组织；无需每枚浮现 | 先看清四行组织 |
| 焦点进入 | “输入”行由左向右被轻色擦入，其他行退弱 | 本次只讲这一类 |
| 真实接棒 | 主入口的相同图形与名称在右侧真实界面定位 | 分类落到实际操作位置 |
| 一次操作 | 展示真实打开材料后的变化 | 颜色变化本身不充当成功反馈 |
| 回看全景 | 保留该类的小型位置标记，下一行获得焦点 | 在同一地图中进入下一类 |
| 结果 | 四类都可辨认，但不全部持续发光 | 观众能按任务找到入口 |

这里借用“方向明确的局部擦入”和“背景为阅读退让”，不照搬170枚键帽、四色瀑布与品牌落版。光波变成阅读引导，不表示入口刚获得权限或被启用。若真实内容只有六个入口，就按六个设计，不为网格数量补虚构项。

### ７．３　实现与声音落到同一内容身份

每个入口的图形、名称、类别、右侧截图锚点来自同一个对象。颜色波只控制视觉呈现，不改可用状态。右侧截图中的操作目标通过裁切映射定位，不能用随便摆在按钮附近的圈替代。格距须按最长中文名称和图形宽度实排，当前未验证字形。

正文讲解时取消多次pop和白闪，只在第一次类别交接保留短幅擦入；进入真实操作时，图标场退为安静导航。声音以旁白为主，一个类别一次轻提示即可，不让24枚各自打点。下一镜直接放大真实内容结果，证明入口用来做什么，而不是再列四句解释文字。

## ８．失败诊断与通过条件

| 画面问题 | 修正 | 可观察的通过条件 |
|---|---|---|
| 满屏图标只有数量没有意义 | 减少重复，换实际入口或明确装饰身份 | 能说明集合是什么，不虚报能力 |
| 全场同帧变色像换图 | 按行／列到达设计方向 | 中段能看出推进的波前 |
| 暖色过渡脏灰 | 用完整新色层裁切替换 | 新旧两侧各自保留纯净表面 |
| 白闪先于颜色满覆盖 | 延后闪光，降低叠层数量 | 颜色先成立，亮峰随后退去 |
| 外圈漂亮、中心标题读不清 | 重做局部暗幕、行宽和字色 | 静帧字边与亮键帽分开 |
| 改图标后互相碰撞 | 重算pop包络、格距与光晕 | 全速与峰值帧都不糊成色墙 |
| 结尾写一秒却只剩13帧完整句 | 从末词完成重排时间 | 观众能在全句完整后读一次 |
| 翻色被理解为全部功能启用 | 分开导演引导与实际产品状态 | 旁白、标签和真实界面一致 |

Storyboard应交代集合身份、图标差异、完成态构图、颜色语义、波前方向、阅读层与真实内容接棒。静态层级、动态波前、正常速度阅读和声音分别验收；当前文章不宣称原创画面或商用成片已通过。
