# 卡片翻面：让正面的条件在背面得到可核查的回答

## 1．翻面为什么发生

翻面适合一对紧密关联的信息：条件与结果、问题与解释、原图与其实际处理结果。保留同一张卡的外形和位置，正面建立身份，背面回答“这意味着什么”。如果两面只是无关图片，翻转仅是换图装饰；如果结果没有依据，大号数字反而会把虚构结论放得更醒目。

来源：[card-flip-reveal 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/transition/card-flip-reveal.md)、[CardFlipReveal.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/transition/card-flip-reveal/CardFlipReveal.tsx)、[官方演示](https://vincentwei1021.github.io/video-shotcraft/media/card-flip-reveal.mp4)。辅助实现核对 `Stage`、`springAt`、`TextReveal`、缓动与字体关系。原卡提到 Apple bento 语法，本次没有观看其所指原片，不能把此示例等同于原片实测水平。

**原卡给定**的是双面、错峰、角度受光、地面倒影；**源码可见**的是以下坐标与曲线；**抽帧可见**的是翻到不同阶段的构图；原创段为**制作推导**。已查看 30fps、150 帧演示的 0、21、22、26、31、34、38、42、46、54、62、66、72、88、110、149 帧。未正常速度观看、试听或运行上游；原创镜头尚未实现。

## 2．先画翻完之后的海报

三张竖卡宽 480、高 620，间距 48，横排总宽 1536，左边 x=192，顶部 y=330。上方标题左对齐卡组，而非居中贴在每卡头上。翻前是一排暗色功能界面，翻后是一排瓷白数字卡：明暗由局部逐张改变，观众的注意力自然依次移动。

| 部分 | 原例的美术细节 | 需要重新设计什么 |
|---|---|---|
| 环境 | graphite 深灰，顶光 0.5／−0.05，底填光 0.5／1.1，horizon=0.88 | 深背景仍要分清卡边，不用大面积纯黑吞掉轮廓 |
| 正面 | 深色纵向渐变，34px 圆角，1.5px 淡亮内边、2px 顶部内高光 | 统一薄面语言；不是实体厚砖，不凭高光声称物理真实 |
| 正面内容 | 40px 内边距，主内容从 y112 起；底部名称 52／750、副句 28 | 让每卡有一个可认的条件，元信息 22–24 不能承担主要说明 |
| 背面 | #fbfaf7→#f1f0ec，深墨字，淡灰对照条，少量金色身份点 | 保留正面名称，防止翻后失去对应关系 |
| 大数字 | 158／800，−0.06em，lineHeight0.9，左 36、右30，底128 | 按实际字宽测量；“−41%”比“0.2s”宽，不能只看字号 |
| 结论标签 | 34／550，底48，左右40 | 说清数字的对象与口径，不写空泛“更快”“更强” |
| 标题区 | 金色26眉题，84／760主标题，位于 x192、y118 | 先定义这一组比较，不把三卡标题另写三遍 |

背面静态应当不靠运动也能理解：名称、对照值、比例和结论有顺序。原例大数字很醒目，但 Before／With 的 22–24px 标签很小；正式教程若需要读这些比较，应扩大卡片或切局部，不以三卡完整同屏作为不可改的版式。

抽帧中 f34 第一张已翻到白面、另外两张仍暗；f46 中卡侧向，右卡仍暗；f62 三卡都已露白，但右卡还在收敛；f88 才能看到三组缩短后的对照条完整状态。这个明暗接力比三张同时转更容易跟踪，但同时展示多个数字仍有内容容量上限。

## 3．双面的层级与翻转链

每卡有 1600px perspective；旋转父层 `preserve-3d`，两面都隐藏背面，背面预转 Y180°。这样父层转到 180° 时，背面文字正常朝向观众。不能用同一平面把文字 scaleX 反过来代替：那会在斜角阶段暴露错误的镜像和透视。

第 i 卡起始 `s=22+12i`：

1. s→s+4，角度 0→−10°，反向蓄势。
2. s+4→s+20，`bezier(0.55,0,0.3,1)` 从 −10→194°，穿过侧向后略过终点。
3. s+20 起，按 damping15、stiffness190 的弹簧从 194 回到 180；代码没有在“约10f”后强行封死。

三张主翻阶段分别 26–42、38–54、50–66。第一张还在回弹时第二张已经转动，属于有重叠的波次，不是每张完全停下再下一张。

抬起量 `lift=max(0,sin(clamp(angle,0,180)))`，translateZ=60×lift，在侧向附近最大，预备负角时为零。源码是 Z 位移，旧注释称“scale+6%”不准确；在1600透视中心附近，60Z带来的比例约1600／1540≈1.039，而非固定1.06。父级还叠全段1→1.03慢推，两者不能混成同一参数。

需要看真实投影包络：卡转侧向时宽度缩小，但边缘因透视深度发生不同位移。把卡间距缩得太窄可能在转动中碰到邻卡；检查25%／50%／75%进度，不能只验证正反两张满态不重叠。

## 4．光与倒影必须服从同一角度

面压暗使用 `1−abs(cosθ)`，暗面最大0.55、亮面最大0.4。窄受光带在56°–124°区间出现，以90°为峰，从卡左扫到右。正面传 θ，背面传180−θ；两面接近侧向时都暗、都有局部亮带，回到正视后不再扫。

这是一套程序化的受光近似，没有真实灯光、厚度和粗糙度求解。它的价值在于光跟随角度，而不是固定时间播放一条白线。若更换材质为无光纸面，可以减弱甚至去掉亮带；若是照片，不能让高光洗掉需辨认的证据。

地板线在 y950，卡倒影从 y956 起，复制同一张 FlipCard 并 scaleY(−1)，opacity0.22，遮罩约26%范围内渐隐；接地影宽度按 `max(0.12,abs(cosθ))` 收缩。倒影和主体共享角度，所以不会一张翻了另一张没翻。

但复制2D容器不等于真实镜面渲染：它没有完整计算地面透视、遮挡和反射光。改相机俯仰或卡离地方式后，要重新看接触线和倒影位置，不能只保留“有倒影”就算空间成立。无需镜面地板的教程可以采用浅哑光底，减少反射对文字的干扰。

## 5．翻后信息实际什么时候完成

`land=s+20` 是主翻段终点，不是所有效果结束：

- 数字弹簧从 land−2 起，比例1.08收至1，尚在翻转时已开始。
- 标签 land+2 起，用14f升起／显露；不是原卡泛称的晚4f。
- 对照第二条从 land+4 起，18f内由全长收至目标长度。各卡完成帧分别64、76、88。
- 第三卡标签到82，对照到88；因此原卡“72后真静止78f”与实际不符。整段相机还继续推到150，Stage纹理也不能自动视作静止。

原例三组数据为3.2×、−41%、0.2s，都是实现中硬编码的演示数值；没有来源支持真实效果。48／15=3.2，(6.1−3.6)／6.1≈40.98%，0.2／3.4≈0.0588，对应条长0.31、0.59、0.06是近似归一化关系。学比例与排版，不把这些数字带入新产品结论。

背面“结果”应与正面同一条件成对。若数据有置信范围、样本条件或其他变量，不用翻面把限定全部藏掉；可以改为一张卡，一个真实结果加一行口径，然后切入证据。

## 6．原创演绎：三种导出设置，对应什么真实文件

**目标。** 教用户理解导出设置与文件结果的关系。用同一张实际照片，保持尺寸不变，分别导出三种已记录质量设置；用实际文件大小和局部纹理观察回答“减小体积牺牲了什么”。没有取得文件前不填写比例或假设视觉差异。

**先决定结果构图。** 正面显示设置项与同一照片的小图；背面显示实际文件大小及设置名称，底部留一条同部位裁切。三张排在一起时比较的是统一尺寸、同一照片、不同质量，而非无关格式的混合条件。最终下一镜放大最需解释的一张裁切，展示真实压缩痕迹或说明差异不明显。

**美术。** 暖灰工作台、哑光白卡、深墨字体，质量档位用同一强调色的线性深浅变化；不使用暗正面／白背面制造“优化前差、优化后好”的价值暗示。照片始终原色，卡片角落的文件身份稳定。大数字按实际单位自适应排版：例如KB与MB先统一口径或明确单位，不能让字体大小暗示错误数量关系。

**动作链。**

1. 先有一张原图与固定尺寸说明，明确比较的共同条件；再分成三张设置卡。若只讲两种设置，不加第三张凑队形。
2. 第一张翻面前，旁白指出它的质量设置。翻到侧向期间不出现新解释文字；等数字可正视才讲文件大小。
3. 其余卡依次翻出，保持同样的字体与数值基线。第一张承担完整翻转示范，后两张可缩短蓄势，避免三个同样的动作平均分走注意力。
4. 全部结果保留足够时间，分别展示同一位置的真实裁切。若文字与细节同时读不完，先读数字，再切单张近景；不要把局部纹理缩到不可辨仍要求判断。
5. 下一镜接选定卡的裁切区域，扩为同倍率比较。卡片翻面的结束成为证据镜头的入口，而非视频的结论终点。

**内容约束。** 文件体积从实际导出文件读取；所有裁切用同一原图坐标、同一输出倍率。若某档体积未按预期排序，保留真实结果并解释影响因素，不改动画条长去迎合“更小更好”。这个方案尚未实现，不能当成已验证的压缩结论。

## 7．失败诊断与审核

| 失败 | 具体修正 | 通过证据 |
|---|---|---|
| 翻到一半文字倒着透出来 | 双面分开，检查背面预转与backface | 中段只见朝向观众的一面，无镜像重影 |
| 三张像果冻 | 控制角度过冲与弹簧，不把文字另加大弹跳 | 卡片整体有一次收敛，数字不会撞边或连续抖动 |
| 亮条贴在卡上横走 | 用角度驱动压暗、亮带与强度，检查背面角度 | 最窄姿态最暗，亮带随转向出现后消失 |
| 倒影与卡片分家 | 共用角度和时间，复核地面线与镜像锚点 | 起点、侧向和终点的倒影都对应同一主体 |
| 数字很大却不知代表什么 | 保留身份、单位、样本条件与结果证据 | 不看旁白也能匹配正面设置与背面结果 |
| 所谓停留仍有条形变化 | 按最后条形完成与弹簧收敛重新分配阅读 | 结果完整后再留读取时间，不用“72f落定”变量名自证 |

先审核正面、侧向、背面、全组三种构图，再正常速度看焦点是否清楚，配口播检查数字与证据的交接。此文保留技术与美术参考，不代表原演示数据真实或原创镜头已获商用验收。
