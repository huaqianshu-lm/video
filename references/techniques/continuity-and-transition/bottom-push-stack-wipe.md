# 底边上推换章：整幅场景共同进入下一步

## 1．物理关系与适用边界

新场景从底部顶上来，旧场景以相同位移向上离开；背景、主体、标题和章内装饰都属于各自场景。观众读到的是两块完整场景交接，不是一张小卡在固定背景上飞入。

适合几个并列步骤或连续章节建立重复节奏。要先设计每章本身的内容表达：第一步做什么、实际发生什么、结果怎样进入下一步。若每章都只是大标题加一张说明卡，推得再有重量也仍像翻页演示。教程中章节长度由口播和操作决定，不沿用宣传片每章一秒多的容量。

来源：[bottom-push-stack-wipe 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/transition/bottom-push-stack-wipe.md)、[BottomPushStackWipe.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/transition/bottom-push-stack-wipe/BottomPushStackWipe.tsx)、[官方演示](https://vincentwei1021.github.io/video-shotcraft/media/bottom-push-stack-wipe.mp4)，并核对 `TextReveal`、`SpeedBlur`、`velocity`、`softShadow` 与品牌辅助实现。原卡提及 slack-promo 22–27s，本次没有观看那条原片，不据此评价其实际表现。

原卡给定的是整屏顶出、26f 重 ease-out、连续三章和色板。源码可见的是下文坐标、层级、UI 与时间链。抽帧可见的依据为 30fps、170 帧样片的 0、21、22、25、34、48、57、66、78、92、101、110、122、136、154、169 帧。原创部分为制作推导；未正常速度观看、试听或运行上游／原创实现。

## 2．静态海报先成立，运动才有承载物

原例是四个整屏章节：近黑引题，钴蓝输入，朱橙节拍，酸柠交付。色板不是随意轮换，而有同一版式和光向。每章左侧文字、右侧 UI，底部品牌与短刻度固定在章内坐标。

| 美术要素 | 源码关系 | 应学的方法 |
|---|---|---|
| 边距与版心 | 左眉题 x=120、y=150；正文标题 x=116、y=268；页脚左 120、底 96 | 字形视觉左缘略作补偿；不要把所有东西机械贴同一几何边 |
| 标题 | 0 章 168px，其余 116／850，字距 −0.038em，行高 0.98，两行 | 先做紧凑大体块；中文换字形后重新测宽，不能直接按英文断行 |
| 说明 | x=120，宽 620，40／500，行高 1.28；普通章 y=560 | 说明从属于主体目标，不能塞完整口播 |
| 右 UI | 靠右 120，纵向居中，圆角 36；内部宽 760，左右 padding 各 44 | 内部内容宽与外宽不同；不能按 760 误算与左栏的间距 |
| 色板 | 蓝 #2d4cff、橙 #ff4d1f、柠 #cdf23a，各有高亮／基色／暗档 | 保留同一家族的明暗组织；不强迫所有教程都使用高饱和三色 |
| 光向 | 左上 18%／6% 柔光，右下带色阴影；卡片用同色相远影 | 页面虽然平，但前后层次统一，不能每张卡向不同方向投影 |
| 字色 | 蓝／橙章白字，柠章深墨字 | 按实际底色检查对比，不把统一白字当作风格一致 |

蓝章白色聊天卡，橙章深棕节拍卡，柠章白色流程卡。颜色交替不只有背景变化，UI 表面的明暗也在配合主体对比。卡内信息采用为镜头重排的大字，而不是把完整桌面截图缩进小窗。原注释声称 UI 字号≥30，实际还有 24、26、28 等纹理与元信息；重要知识不能依赖这些小字。

前三步构图共享网格，内容形式有差异：聊天的上下回复、节拍的横向对象与波形、交付的竖向连线。真正可迁移的是“同一空间秩序容纳不同信息关系”，不只是给三个普通卡片换背景。

## 3．两幅画面怎样保持刚性接触

令画高 H=1080，新章推入进度 p，旧章 y=−pH，新章 y=(1−p)H。旧章底边 y+H 与新章顶边始终相等，二者速度相同，因此没有露缝、追赶或穿透。p 在每次开始后 26f 用 `cubic-bezier(0.12,0.9,0.2,1)` 完成，先快后慢。

多章实现把第 i 章位置写成 `y=(1−自身进入进度)H−下一章进入进度×H`。进入与离开共用进度，不给旧页另做一条差不多的弹簧。超出 ±H 的章卸载；当前模型推入间隔 44f，大于 26f，不会让同一章同时处在进入、离开的交叠阶段。若改为更密集的节奏，要重新审查公式和接触关系。

所有章内内容随父级平移。固定在 viewport 的标题、注记或粒子若被误放到外层，会在色板上漂移。可以有全片固定字幕，但那是明确的屏幕层，不能假称是章内物体；字幕也应避开转场接缝的快速扫过区。

新页上缘的 56px 接触影放在 y=−56 到 0，**压向旧章**，不是往新页内部涂一条黑带；色相取新章 shade，近边透明度 0.42，40% 处 0.12，再到透明。上沿 2px 白亮边帮助读出接触边。只在新章尚未进入完成时挂载，落定撤掉。原卡意图段另有“40px”的描述，实际核心和代码是 56px，不能混写。

整体纵向模糊来自三次推入累计位移的速度，`SpeedBlur vx=0、vy=−velocity(stackY)`，amount=0.1、max=22。它模糊整个叠层，不给文字与底色各用不同方向。半帧差分会在标称起推帧检测到即将发生的速度，因此 f22 即使几何刚起步，画面已可能出现模糊；不是 source frame 漂移的证据。

## 4．真实时间链比“落定后动画”更复杂

| 时间 | 原例实际安排 | 审查重点 |
|---|---|---|
| 0–21 | 黑底引题，标题起始驱动 −10，第一帧已有部分字 | 非完整空白进场；不要说 0f 从无到有 |
| 22–48 | 蓝章顶入；标题从 34 起，第二行到 57 才完成 | 标题在进入尾段重叠，不是严格等 48 落定后才开始 |
| 36–47／48 起 | 聊天打字点，再弹第三条消息 | UI 参与章节末段，原卡“全部避开26f”并非实际严格执行 |
| 66–92 | 橙章进入；标题 78→101 | 第二行完成后到下次起推 110 仅约 9f |
| 82–90 | 镜头环由 Hook 交给 Zoom | 实际 handoff=8f，注释另一处写 6f；波形、呼吸环按全局帧运动 |
| 110–136 | 柠章进入；标题 122→145 | 卡内流程先于标题全部完成开始变化 |
| 126／134／142 | 三个流程勾选依次开始，连接线向下生长 | 最后一个弹簧仍需收敛，不把142当全部稳定帧 |
| 142–169 | 整体 scale 向 1.015 慢推 | 原例最后 28f 保持的是场景内容，不是绝对静止 |

两行标题通过 `TextReveal` 每行 18f，间隔 5f，完整态因此在起始后 23f；说明透明度起始再晚 8f，持续 14f，位置持续 16f。不能只用“章间 hold18f”判断内容是否读得完。

抽帧显示 f34 蓝底基本占画面、标题未完整，f57 蓝章两行与第三消息已经可见；f78 橙章到位而标题仍在建立，f101 才较完整；f122 柠章标题未完，f136 流程前两项已出现，f154／169 完整尾版仍在缓推。静帧能核对阶段，正常速度的推入重量和阅读节奏仍待实测。

## 5．UI 小动作要讲事实，不借转场替产品背书

聊天、128 BPM、合成波形、38s／2.4s／0.6s 等是源码编排的演示。没有证据证明实际发生了生成、渲染、导出和发布，也不能把正弦叠加波形称为真实音频分析。新教程若解释真实流程，应使用对应结果或明确标作结构示意。

右侧不是只要有动作就足够：聊天最后一条应真的改变任务状态；节拍交接应能对应实际 Timeline 或声音；流程打勾应有已完成结果。若这些都只是装饰，强色板与重推入会放大空洞感。

## 6．原创演绎：照片从选择到裁切再到导出

**内容目标。** 教用户把一张横幅照片裁成竖版，确认主体保留，再导出指定尺寸。三章不是三个卖点，而是同一照片身份连续通过三个真实操作。素材、软件版本和最终文件均需在实际制作时取得，本设计尚未实现。

**先画第三章结果。** 右侧展示真正导出的竖版照片，左下显示实际像素尺寸；旁边保留原图的小轮廓与裁切窗关系。重点是主体是否保留、导出是否符合尺寸，不能用三项勾选代替结果图。下一镜接最终文件在实际查看器中的检查。

**统一美术。** 中性暖灰底作为主要工作环境，三个章节只在底边与大面积低饱和色温上变化；一条暖橙色始终标记同一裁切区域。照片保留原色，避免三章滤镜变化让用户误认进行了调色。标题用稳定的中文黑体，两行以内；数字尺寸用等宽字，宽高之间采用一致分隔。边缘、窗口圆角和影子沿用同一尺度。

**章一：辨认原图。** 大幅真实照片占右侧主要区域，左侧只有“先确定主体”。在照片上短暂指出要保留的眼睛或建筑顶端，实际软件文件名保持可追踪。原图四周留出足够空白让横幅轮廓成立，而不是塞入一张白卡再套照片。

**交接一。** 新章与旧章整屏刚性上推，使用相同照片的下一工作状态。进入尾段不立刻让裁切边框四边同时乱动；先落到可辨的原图与裁切框，再由旁白引出拖动。旧章已经标过的主体位置在新章仍能认出。

**章二：真的改变裁切。** 展示实际裁切框从横向调整到竖向。图像位移和裁切窗口关系来自同一操作状态，不用整张图片 scaleX 拉窄假装裁切。框外适度退暗，框内保留原始曝光；拖动时关键主体始终可见。最终构图应有意决定主体与留白，不仅是“没有切到头”。

**交接二。** 原裁切范围作为第三章导出图的可认形状。若使用新拍软件画面，保持裁切结果一致，再整屏推入。不能让原图像素内容在过渡中突然换成另一版本。

**章三：拿结果验证。** 展示真实导出图与实际尺寸。打开文件再检查主体与比例，不伪造“导出完成”勾选。若原图不足以支持所需尺寸，直接说明限制，不能靠放大预览掩盖。

**时间分配。** 每章用真实口播与操作时间定长。转场期间避免必须读的小字，章内以一个主动作推进，再给结果观察时间。若整条只有一次章节变化，可直接使用一次上推；不为了形成“三连节拍”加无意义章节。颜色、方向和版式是连续性工具，内容成立优先。

## 7．失败与可观察验收

| 失败 | 根因与修正 | 成功证据 |
|---|---|---|
| 两页间露出第三种底色 | 新旧页没有共用进度或尺寸不含边框 | 逐帧检查边界接触，半程无缝、无重叠穿透 |
| 字留在原地，底色先走 | 章内容器与平移容器分离 | 任意章内锚点与色板相对坐标固定 |
| 进入像卷帘、没有重量 | 缓动与距离未匹配，或模糊过强 | 正常速度先快后稳；落位能看清主体，不用额外震屏补救 |
| 接缝像黑边 | 阴影画在新页内、过宽或落定仍保留 | 阴影只在接触阶段压旧页，满态无残留粗边 |
| 全程所有东西都在动 | 内容动作与上推重叠过多 | 推入中有清晰主边界；落定后只由一个主操作接管 |
| 满版强色压住照片 | 配色照抄宣传片，主体对比不足 | 缩成小图仍先看照片与裁切关系，色板退居章节提示 |
| 看完只有三个标题 | UI 无真实操作和结果 | 同一照片经过选择、裁切、导出，结果可独立核查 |

审核起点、推入 25%／50%／95%、章内结果、末章与下一镜。逐帧几何检查通过后，还需正常速度检查信息交接、配口播试听，并对真实导出图核验。本文的文档研究与原创成片验收分开，不能因父子坐标正确就宣称商业画面通过。
