# 横条撕裂：用短促断裂表达状态跳变

## 1．故障语义先于风格

有效变体glitch-displace，把完整页面切成16条不等高横带，短时错位，在最强撕裂帧切到新状态，再归位。它适合解释信号中断、状态突变或有意的段落冲击；正常保存、成功完成若都配故障，会把「成功」拍成「系统坏了」。教程需要连续看操作时，优先保留真实过程。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/transition/tear-streak-transitions.md)、[GlitchDisplace](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/transition/tear-streak-transitions/GlitchDisplace.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/glitch-displace.mp4)。原卡给定条带审美与包络，源码可见确定性分带、两态页面和合成；抽帧可见135帧样片的16个等距状态。原创为制作推导，未正常速度观看、试听、运行上游或原创实现。

## 2．完整控制台比撕裂更先决定画面质量

原例是深蓝控制台：左侧132px两行标题，右侧196px等宽数字和84px单位，中间560×220曲线，下方18个区域格及日志／统计。两态共享网格，强调色从电光蓝转为青绿；上沿标识、页脚版本与路径维持身份。主光左上、底部少量冷暖余辉；点阵40px周期，暗角和颗粒只在最外层绘制一次。

这让撕裂中的信息仍是「同一控制台」，不是两张随机海报。字号尺度、栏宽与空隙决定首先看标题还是数字。若改成真实日志教程，应先决定一个主要变化，不能把所有辅助行一起放大；深色底也不能把次级字段压到无法辨认。

注意：A右侧显示流量百分比，B显示p95毫秒；两条曲线也换了指标。**同一槽位不代表同一指标连续变化**。不能把99%→41ms做成数值变形；应明确切换到另一项观察。全部版本、延迟和可靠性数字均为示意。

## 3．条带配准、重影与缝边

每条权重0.45～1.35，归一化到1080，最后一条吸收舍入余数。外层只裁自己高度，内层整页top=−条带top，再做X位移。两端文字在未错位时应拼成同一页；不能给每条重新排版或分别缩放。

底层保留一份完整不透明页，防止条带移开后露底。动条也自带同样的不透明背景，避免文字和底页双影。每条能量固定：部分静止、部分满幅、其余轻颤。逐帧伪随机`h(i×31+f×7)`经过符号和0.6次幂，把位移推向两端；AMP70是峰值上限，不是每条每帧都移动70。

重影是**内容的两份单色透明剪影**，向±12错开、screen合成，不能复制整张带底色的页再染色，否则会泛灰。其强度随条带位移与包络变化；条带上沿亮线仅在|dx|>25后增强，下沿暗边随幅度出现。所有条都亮边会像横格纸。扫描线每帧两条，只在撕裂阶段存在。

## 4．节奏、余波与原卡差异

| 帧 | 实际行为 | 设计含义 |
|---|---|---|
| 0～40 | 流量0.86→0.99、日志进入、区域格点亮 | 是建立过程，不是40帧全静止 |
| 30、31 | 第5、12条±12前兆 | 先给不稳定感，不能影响正在读的关键字 |
| 44～47 | out-cubic冲起 | 撕裂迅速达到可感强度 |
| 47～54 | 高能平台，54切B | 切点在主撕裂内，54亮度1.28、55为1.12 |
| 54～60 | 包络线性归零，60撤条带和扫描线 | 不是把所有页面动画一起停止 |
| 58～84 | p95计数到41ms，区域波继续传播 | 不要将刚换景的数字误记为终值 |
| 64～94 | 三项统计错峰进入，最后一项94完整 | 结果阅读应从完整内容算起 |
| 100～134 | 主要内容保持，Live脉冲、慢推、颗粒仍在 | 原卡的静止描述不等于像素恒定 |

源码A显示`floor(prog×100)`；浮点与取整会影响接近99时的显示，抽帧到36仍见98，不能按注释认定30帧一定卡99。原卡写p95从58开始，样片切点54可见58，后续才下降。源码kick切前0.006蓄力、切后0.016收回，与整体1→1.018慢推相加。

抽帧45见强条带，54换成新标题同时仍撕裂，63已归位但计数未完，98以后结果完整。只有等距抽帧不能证明16帧动作在正常速度中是否刺眼，还需完整观看。

## 5．原创演绎：解释一条损坏记录如何被定位与恢复

**内容目标。** 从一次真实可复现的读取错误进入修复后的可读内容。先设计最终态：同一文件身份、实际解析结果、被修复字段与核对依据；下一镜重新运行读取，证明成功。不能只把红字换成绿字就宣布修复。

**美术。** 两态同一中性编辑器，主角是错误位置和修复字段，背景行保留上下文；等宽字用于内容，说明用独立无衬线。撕裂仅放在「断裂」解释拍，不覆盖必须阅读的报错。取消发布控制台的区域格、伪延迟和庆祝光。

1. 先显示真实错误与文件路径，口播指出缺的是分隔符、编码或其他已经证实的原因；未知原因不写死。
2. 将注意力锁在同一行，必要时用局部放大。极短前兆提示接下来是讲解转折，而非真实软件故障。
3. 横条在说明层发生，硬切到实际修复版本；保留文件名和行号身份。此时不做虚假的逐字自动修复动画。
4. 归位后先展示修复差异，再实际执行。若结果仍失败，保留失败信息，不能因预定结尾而强行变绿。
5. 下一镜显示解析出的结构与一个真实字段，让视觉结论落实到内容。

若内容不涉及断裂或错误，整套撕裂可取消。声音只在短包络内提供克制数字噪声，口播报错和解释时保持清楚；以上声音未制作或试听。

## 6．原创修复镜头的画面容量

未实现的教学草案可使用一份明确标为示例的文本文件，让一个缺失分隔符成为唯一问题；实际制作如果换成真实故障，应重新核实原因，不能照用示例结论。

| 关键状态 | 正向设计要求 | 不靠动效也能理解的内容 |
|---|---|---|
| 错误建立 | 编辑区占左中主要空间，错误信息在右侧窄栏，文件名固定上沿 | 哪个文件、哪一行读失败 |
| 局部解释 | 缺失位置前后各留必要字符，标点用清晰等宽字；指示线不压文字 | 为什么这里需要分隔符 |
| 撕裂中段 | 身份栏仍可追，临时彩边集中在非关键段；不同时让报错滚动 | 这是讲解转折，非再次错误 |
| 修复版完整 | 同一行同一缩放，新增标点轻强调；真实输出在次级区待接管 | 改了什么，而非只看到绿勾 |
| 验证接棒 | 实际解析结构变为主画面，文件名和字段值对应 | 修复后的文件确实能读 |

初始错误、修复差异和验证结果三种信息分三次交出阅读权。报错若很长，先截取错误类型和真实位置，完整日志放到需要时的后镜；不要把长报错缩成微字，再用大标题宣布「已修复」。技术噪声可以给转折力量，修复的可信度必须由清楚的标点、行号与实际输出建立。

## 7．诊断与验收

| 失败 | 修正 | 通过证据 |
|---|---|---|
| 画面像方块爆炸 | 保留横条内完整内容，撤碎块运动 | 观众能跟踪同一页面的水平断裂 |
| 未撕裂就有缝 | 同源全页裁切，最后条补足高度 | 静态拼合文字和背景连续 |
| 重影泛灰 | 剪影只画内容，核对混合模式 | 暗底仍深，彩边只伴随高能条 |
| 归位后仍故障闪烁 | 条件卸载临时层，另查颗粒／脉冲 | 转场结束清楚，持续内容动态有明确用途 |
| 成功被误解为新故障 | 调整使用语境或取消效果 | 观众能分清错误、修复与实际验证 |
| 换指标被当作改善 | 保留标签、单位，另做对照 | 能分别说出两个数是什么，证据口径一致 |

检查旧态、前兆、最大错位、54／55切点、60撤层、结果满态和下一镜。技术归位、静态美术、正常速度、真实内容与声音分别审核；原卡的项目内淘汰记录只解释其取舍，不是所有碎块技法的普遍禁令。
