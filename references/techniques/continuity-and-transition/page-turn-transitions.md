# 对开门裂幕：让旧画面分开，为新状态让位

## 1．研究的是对开门，不是所有翻页

本卡当前有效变体是 barn-door-split：旧页从中央分成左右两半，各向外加速，新页从裂缝下显露并稍作迎上。它表达替换、翻篇或新阶段出现。不是卷纸、书页弯曲，也不是两个场景随相机平移；不因目录名含page-turn就推断已经覆盖所有纸张物性。

教程中可用于已讲完旧方案，再进入新的实际结构。若要严格比较两种图像质量或性能，原例“旧冷暗、新暖亮”的美术会预先暗示优劣，应改用中性一致的呈现。转场自身不能证明新版更快、更好。

来源：[page-turn-transitions 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/transition/page-turn-transitions.md)、[BarnDoorSplit.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/transition/page-turn-transitions/BarnDoorSplit.tsx)、[官方 barn-door-split 演示](https://vincentwei1021.github.io/video-shotcraft/media/barn-door-split.mp4)。核对了SpeedBlur、velocity、Stage、Dust、TextReveal、stagger和字体辅助。

**原卡给定**预裂、双门加速、新页迎上与缝光；**源码可见**具体层级和参数；**抽帧可见**阶段画面；后文为**制作推导**。已查看30fps、150帧演示的0、19、20、29、30、39、40、48、56、63、64、76、97、110、130、149帧。未正常速度观看、试听、运行上游／原创实现。版本号与性能数字均为原例示意，不能引用为实际发布证据。

## 2．两幅海报先共享一个版心

两页共用Layout：眉题从y214起，占40高；再留26，到高230的主字标；副题间隔34、高60；再间隔92是三组统计。统一槽位让“3→4”能被认出，同时允许材质和强调层次改变。

| 部分 | 旧页 | 新页 | 要学习的关系 |
|---|---|---|---|
| 背景 | #1d1f23等冷灰，顶部灰光，极淡4px周期横纹 | ember暖黑、橙色中央余辉与少量上浮尘点 | 材质差异支持段落转变；公正比较时应中和色彩偏向 |
| 主字 | 220／760、灰色，−0.055em | 220／800、近白；数字4是暖亮渐变 | 位置相似、身份连续；字重不同意味着并非逐像素注册 |
| 眉题 | 30／650、低对比Current release | 30／700橙字，前接44px标志 | 新身份先被看见，辅助信息不与220主字抢焦 |
| 副题 | 48／450静态说明 | 同字号，逐词升起 | 新信息在门离开后接管，不在最窄裂缝里要求读句子 |
| 统计 | 三组300宽、间隔56，72主数、30标签 | 同槽位，值滚动、线条带橙色 | 单位和指标必须保持对应，不只把数字调得更好看 |

新页数字4有垂直暖色填充与随时间呼吸的drop-shadow；其他文字不一起泛光。门面近缝部分染暖，内边缘10px亮→橙→暗的渐变带，模拟板材切面的受光。这里是二维层合成，不是真正建了有体积的门板和物理灯光。

原例的旧页刻意低对比，有“熄火金属”语气；若当前内容需要读旧数据，先保证可读，不因它即将退出就任意压灰。新旧两端构图完整，转场才有比较基础。

## 3．双半页怎样拼成同一页

左右门各有960×1080的overflow:hidden视口，左门x0，右门x960。每个视口内都绘制一整张1920×1080旧页；右门内页left=−960，显示同一整页的右半。这样中央拼合的是同一坐标系，不是两个各自缩放到960的截图。

静态拼合时应看文字跨缝处、横纹、背景径向光是否连续。真实截图使用同一源图与裁切比例，奇数画幅宽度需明确拆分规则，避免一列像素重复或漏掉。若旧页本身有动态内容，两份复制必须用同一时间与状态；随机数、视频时间或独立弹簧不一致，会在未开门时就出现接缝。

门单边位移 `d=gapAt/2+slideAt`；左右用−d／+d。gapAt在30→40由0长到16，所以预张最大是两门各8px；slideAt从40→64额外0→1000，用bezier(.42,0,.8,.25)加速。终点单边1008，不是只移动1000。

外层旧页整体还有0→40的1→1.015慢推，绕屏幕中心。新页从42→78由1.08收至1，随后78→150向1.018慢推，支点50%／46%。**同版式不等于转场期间同像素位置**：新旧缩放不同，字重也不同，裂缝中看到重叠字形属于其设计结果，不能保证严格图像匹配。

左右分别按±velocity(d)挂SpeedBlur，amount0.09、max22。滤镜方向一致于各自门的移动，门面、内缘与旧页一起模糊；如果缝光被错误放入门容器，会跟着门一起离开，失去“从后面透出”的关系。

## 4．预告裂点、开门与新页的时间链

| 输出帧 | 实际动作 | 观看目的 |
|---|---|---|
| 0–19 | 完整旧页，整体已经缓推 | 建立旧状态；不是严格30f静止 |
| 20–30 | 2px中缝亮线从中心向上下伸展 | 让观众先注意裂点，避免突然分屏像渲染错误 |
| 20–32 | 门面光染渐强 | 预告下方另有空间，不能过早洗掉旧字 |
| 30–40 | 裂缝从0扩到16px；新页从30挂载 | 门还未主滑，新景已在缝后存在 |
| 40–64 | 双门加速滑出 | 前慢后快，主体“让位”；不可用末帧突然卸载替代完整滑出 |
| 40–44 | 原中缝发丝线淡出／撤去 | 后续由真正开缝接管，避免屏幕中央残留一条假线 |
| 42–78 | 新页迎上，1.08→1 | 与门同时运动，内容阅读等主体稳定后再接 |
| 64起 | 新副题六词，各18f、间隔3f，到97完整 | 不是110前一直只靠一张静态海报 |
| 72–110 | 三组数值错峰滚动，每组26f | 最后组到110，其他组更早；单位与标签保持 |
| 110–149 | 结果保持，尘点、发光呼吸、慢推继续 | 原卡hold并非全画面静止 |

过曝光束实际从30开始建立，30→42增亮，再46→76退去；不是注释概括的40→74。门面光染40→54退到原来的0.4，未完全消失，随后随门出画。门在frame>64才卸载，64时几何已超出；逻辑卸载帧和视觉离屏帧不能混为同一个判断。

抽帧29只见中线与暖染，39裂缝很窄；48新旧主字在中间短暂叠读，56新页主体已露、两侧旧字仍在；63／64门已基本退场；76新统计还在变化，97第三组接近终值，110三组完整。实际播放中这些阶段是否过亮、能否辨认仍需正常速度检查。

## 5．光照叙事与数值真实性要分开

门边不向缝内画深投影，是因为本例设定光从新景向观众透出；暗影若盖住缝会把亮源压灰。但这是一种图形光照设计，不是所有空间里门都不投影的物理结论。换成侧光、无背光环境，应重新组织受光与阴影。

原例新数据64s→11.8s、12→0、6→30，均为写死的示意；3／4也是示意版本号。动画同时改变数值、主题色、字重与亮度，不能作为产品性能对照实验。严谨教程应使用实际测量、相同任务与条件，或明确“界面结构示意”，不能靠暗旧亮新制造结论。

需要清楚读数时，原三组平均权重可能不合适。选一个主要变化，配实际证据；其余结果延后到下一镜。高能转场适合段落交接，不能承担所有解释与证明。

## 6．原创演绎：从混乱文件列表进入按用途组织的目录

**内容目标。** 讲解把同一批文件按明确用途整理后，如何更容易定位；不是宣称一键自动整理，也不虚构耗时降低。实际制作先取得允许展示的文件或明确创建教学示例，保留文件名、数量与归属事实。本设计尚未实现。

**先画最终态。** 同一文件管理界面，目录名称对应真实用途，打开目标目录后能定位一个具体文件。下一镜执行真实查找或打开，验证路径。若最终只是三张写“分类清楚”的卡片，仍没有证明整理结果。

**美术。** 新旧采用同一中性主题、同一缩放和文字大小；强调色仅用于正在跟踪的目标文件。旧列表不人为压暗成“坏画面”，新目录也不加庆祝粒子。主体窗口占主要画幅，背景低对比，章名留在上沿；对开门只在内容转折的一次使用，门缘可用轻薄明暗，而不照搬余烬发布场景。

**完整调度。**

1. 旧列表先有足够时间辨认目标文件及难点，例如同类名称混在一起。选一个真实例子，不凭空把文件打乱制造问题。
2. 讲清分类依据后，暂时保持列表，中央出现克制裂点提示。若中缝正好切开最重要文件名，应调整取景，让身份标签仍完整；转场不能切断正在阅读的证据。
3. 双门向外让位，新景预先包含整理后的真实目录。保持同一窗口边界与路径区域，使“同一批内容进入新组织”成立，不用全新的空白界面冒充结果。
4. 门离场后先保留全貌，再沿真实路径进入目标目录。目标文件沿用同一名称与图标，短暂高亮只是讲解标识，不冒充系统选择状态。
5. 展示文件数量与归属核对：文件没有因动画消失或复制；有不确定归属时保留待整理目录，不强行塞入某类。
6. 下一镜真正打开目标文件，或者用实际搜索验证新路径。教程结论来自可见结果，不是新页更亮。

**使用边界。** 这是讲解层的章节转场，不意味着文件管理器真实会把页面裂成两半。如果教程强调逐步操作，优先展示实际移动过程，可能无需此转场；如果过程已说明，才用它从旧状态进入结果复核。不要为了使用参考动作省掉真实操作和数据校验。

**声音。** 可用短而克制的材质滑动声，落定后交给口播；缝光不必配巨响。声效与输出时间对齐，最亮帧是否对应音峰由实际试听决定。没有完成声音制作前不写“声画卡点已验”。

## 7．失败诊断与验收证据

| 失败 | 修改方向 | 可观察通过结果 |
|---|---|---|
| 门没开就有接缝 | 两半用同一完整源页和同一时间，核对右侧−960裁切 | 横线、文字和背景在中央连续，无漏列／双列 |
| 两扇门像擦除遮罩 | 内容与边缘共同移动，检查加速与受光 | 旧页被可追踪地移开，新景从后方出现 |
| 中央重叠字难受 | 缩短有冲突的阶段、调整取景／新页显露，不靠更强曝光盖住 | 正常速度重点身份可认，重叠不误导文字内容 |
| 新景第一眼过曝 | 降低缝光与screen强度，检查最亮帧 | 主字和实际结果仍有层次，没有大片白色吞细节 |
| 以颜色暗示不存在的提升 | 统一新旧主题和呈现条件，增加真实结果 | 结论由文件、数据或画面支持，不靠暖亮偏好 |
| 门走了仍有残线 | 及时撤发丝线、临时边缘与模糊 | 新景完整态不留无意义中线，焦点交给真实内容 |
| 结果读不完又转场 | 按最后数值／副题完成重新留停留 | 结果完整后可理解，并能自然进入下一次操作 |

至少看旧态、预裂、窄缝、中段、离屏、新结果满态与下一镜。技术拼合后还需正常速度观看、配口播试听和真实内容复核。完成文档研究不等于演示性能真实，也不等于原创镜头已经商业验收。

与 [底边上推换章](bottom-push-stack-wipe.md) 比较：上推是新页与旧页同向刚性接触，本篇旧页向两侧让位、新页留在后方。应按内容的进入关系选择，不能把二者当作每个接缝轮流播放的装饰菜单。
