# 渐变参数变奏：让背景变化服从前景的阅读

## 1．背景有动作，不等于内容有解释

本例以线性、径向、圆锥渐变连续变奏，文字随类型更换。它可为低动作段落提供环境变化，也可用于真正讲解渐变参数。若讲的是其他内容，渐变只能保持从属，不能代替真实对象、操作或结果。把一段口播分成三句大字再配彩色流动，仍不等于视觉叙事。

来源：[gradient-transition 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/transition/gradient-transition.md)、[GradientTransition.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/transition/gradient-transition/GradientTransition.tsx)、[官方演示](https://vincentwei1021.github.io/video-shotcraft/media/gradient-transition.mp4)。另核对 TextReveal、Grain、缓动与品牌辅助。

**原卡给定**三种渐变、参数插值、短交叉淡化、小画布与前景压暗；**源码可见**下文参数和时间链；**抽帧可见**对应构图；原创段为**制作推导**。已查看 30fps、200 帧样片的0、26、52、56、62、68、91、114、118、125、132、140、154、162、180、199帧。未正常速度观看、试听或运行上游／原创实现。语法与合成判断另参考 [W3C径向渐变](https://www.w3.org/TR/css-images-3/#radial-gradients) 和 [W3C透明度合成](https://www.w3.org/TR/compositing-1/#simplealphacompositing)；规范不作为美术效果已验的证明。

## 2．三种空间形状怎样保持一套颜色

色彩范围集中在紫、品红、冰蓝，使用深紫近黑作为暗部；不是每次换类型就换一套完全不同色板。亮区在画面里迁移，而文字主要留在左侧，深色scrim为它保留稳定阅读区。

| 渐变 | 源码形状与颜色 | 静态构图任务 |
|---|---|---|
| linear | 角18→198°；亮色HSL300／86／64→330／88／66，中色268／76／40→250／78／44，暗档250／62／7 | 亮、中、暗差异让方向可见；不是只让全屏同时变色 |
| radial | 中心24%／72%→68%／38%；半径按小画布宽的48%→80%换算 | 光斑沿对角游走，外沿近黑，形成聚焦与空间层次 |
| conic | 中心64%／54%；紫→品红→冰蓝→紫，from0→250° | 首尾同色消除色标接缝；中心放文字右后方，避开尖点抢焦 |

linear还叠了一个低透明径向亮区，其中心x18%→70%、y10%→22%。因此原例前段不只是在旋转一条线性渐变，亮斑也在移动；若教学要单独解释角度，应先关闭这层。

radial的半径数值rr虽记作百分比，实际 `rpx=rr/100×480`，即230.4→384px，在4倍放大后相当于921.6→1536px。圆形显式半径采用长度，不能把底部展示的 `circle 48%` 字串直接复制为可运行CSS；若要两个百分比半轴，应采用ellipse语法并说明形状改变。[W3C渐变语法](https://www.w3.org/TR/css-images-3/#radial-gradients) 支持这一区别。

conic的旋转不是光源真实绕物体运动；它改变的是平面色标分布。不能用这段背景声称讲清了实体物体的反射、折射或三维照明。若主题是光学，需要相应真实对象或物理模型，而不是只显示“Bend light.”。

## 3．小画布、柔化与前景层级

三层渐变先画在480×270，再以scale4铺到1920×1080；文字、图标与技术注记在输出尺寸上独立绘制，不随低分辨率背景一起放大。conic内层向外扩14px，blur9px，约对应全画幅56px外扩、36px柔化，避免模糊边露黑。

原卡“代价1／16”来自像素面积比，只是成本估计，不是测得的渲染加速。合成、滤镜、字符串重绘、导出编码都还有开销；服务端渲染同样有时间与资源成本，不能照抄“Remotion无此顾虑”。具体画幅和渲染环境应实测。

文字区的可读性由多层处理维持：

- conic内部外圈暗角以64%／54%为中心，外侧压到高透明深色；另有左侧线性压暗。
- 前两段左侧加0.42的深色scrim，随conic权重退去，避免同时叠满两套左暗层。
- 全幅再有低对比外圈暗角，grain0.1以soft-light叠加。
- 前景近白文字有柔暗影，但不能靠扩大textShadow挽救过亮底色。

原例前两句位于x160、y404，display级大字，主词形成宽体块；最后品牌区位于x160、y300，156字标与168标志、44px间距，底部30px等宽参数注记。在教程应用中，参数注记若是主要知识就要放大到主阅读层，不能继续当画面脚注。

颗粒可减轻纯渐变的观感单调，却不保证编码后无色带。抽帧的背景存在可见压缩与纹理，不能凭grain参数宣称“防色带已通过”。需检查最终输出格式、亮暗过渡和实际观看尺寸。

## 4．过渡权重和真实合成的差别

linear参数0→68，radial56→132，conic118→200。换类型窗口56–68与118–132，两层在窗口内都继续运动，避免一层完全停止后另一层才接管。权重为w1=1−x12、w2=x12−x23、w3=x23，名义总和为1。

但普通DOM层从下到上source-over叠加，**透明度加起来为1不等于两幅图按相同权重线性混合**。第一窗口中点，linear与radial都opacity0.5，新层贡献0.5，旧层贡献0.25，底色贡献0.25；因此中段可能变暗。公式依据 [W3C source-over合成](https://www.w3.org/TR/compositing-1/#simplealphacompositing) 推导，不是本次像素测量。

若设计需要严格的两图交叉淡化，可保持下层不透明，只让上层0→1，或在明确合成空间内处理；若接受原例的短暂压暗，也应有意选择，不把它误称为恒亮混合。三层权重公式还假设两个换段窗口不重叠；改密时间轴后应防w2变负。

HSL三通道由脚本逐帧lerp，负责**同一色标随时间的变化**；渐变色标之间的空间插值是另一件事。不能由脚本使用HSL推出浏览器也在相同空间插值全部像素。HSL也不是感知均匀空间，“比RGB一定不灰”过于绝对；近邻色可以保持较高饱和，但远色相需要明确路径并观察亮度，不能只给h加360就认定好看。

| 时段 | 源码实际动作 | 需核查的问题 |

| 52–64 | 旧句模糊上移退去，66卸载 | 换背景从56起，两者重叠 |
| 66–91 | Focus it.建立 | 新句不是86就满态 |

## 6．原创演绎：把“渐变”讲成可见的参数关系

**目标与输入。** 真实教学内容是CSS三种渐变的区别，使用可运行的简化样例；在正式制作时核对目标浏览器渲染结果。观众要能说出“线性沿方向分布、径向从中心扩展、圆锥绕中心按角度分布”，而不是只记住三团漂亮颜色。以下尚未实现。

**先画结果版面。** 同一个大方形实验区位于右侧，左侧是短名称和一个当前可变参数。最终保留三种静态小对照，但在展示过程中始终只有一个主实验区，避免三幅彩色动画同时运动。下一镜进入实际样式代码并运行验证。

**美术。** 实验区外是中性深灰，不用满屏极光；三种都使用同样两种颜色与相同明暗范围，边框、标签与字体一致。角度箭头、中心十字、半径线采用近白细线，只在解释相关参数时显示。名称用清晰中文黑体，代码用等宽字体；装饰渐变和被研究渐变不能混成同一层。

**动作链。**

1. 线性实验区先保持固定色标，只改变角度；显示一条与方向相应的轴线。旁白指“方向”时，只有角度在动，色相与亮斑不另漂移。
2. 停在一个角度，显示实际CSS中的角度值。读数来自同一变量，不手打另一组动画数字。
3. 切到径向时保持实验区边界、颜色与文字位置。中心点先静止，让观众识别从中心向外的层次；再只移动中心，最后只改半径。每一步都有短暂结果态，不同时改变全部参数。
4. 圆锥段中心固定，显示一根半径作为0°方向标识，改变from角。首尾同色避免突兀接缝；若讲接缝本身，可明确保留并解释，不用模糊把问题遮掉。
5. 三种静态结果同框，参数注记只保留必要差异。随后选择其中一个，切到真实代码和输出，证明字串合法并产生相应画面。

**可用的背景版本。** 若教程主题并非CSS，只取同一段缓慢渐变，前景真实内容保持主体；按内容出现位置规划亮区，文字读到关键处时背景可停。没有必要把linear、radial、conic三种都塞进同一条视频。

## 7．失败、修正与通过条件

| 失败 | 修改 | 可观察结果 |
|---|---|---|
| 字在某一帧突然不清 | 找最亮背景帧，重新规划亮区／scrim，不只调起始帧 | 全时段主文字对比稳定，背景不穿透字形 |
| 交叉淡化中间发黑 | 区分opacity权重与source-over，按设计调整底层透明度 | 窗口中段明暗符合意图，无意外掉亮 |
| 圆锥中心像尖刺 | 中心避开主体，必要时局部柔化；教学时保留真实形态说明 | 前景焦点稳定，不把滤镜结果冒充原生渐变 |
| 径向段变黑或没有图 | 核对circle半径单位及实际生成字符串 | 真实渲染与读数一致，不用错误百分比示意当可运行代码 |
| 画面彩但内容空 | 用真实对象或参数因果接管，减少标题更换 | 看完能指出某参数改变了哪个可见关系 |
| 尾段叫保持却一直转 | 按阅读需要固定参数或明确缓动环境 | 主结果有可读窗口，不能只凭hold注释验收 |

验收从起点、两次换段中点、最亮文字背景、最后满态到下一镜。文档参数核对后仍需最终尺寸正常播放、配口播试听和编码后画面检查。未经实测不宣称性能提升倍数、没有色带或原创镜头达标。
