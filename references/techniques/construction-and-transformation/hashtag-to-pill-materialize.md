# 输入词变成标签实体：先确认身份，再让它进入有内容的页面

这个技法把一串正在输入的字符，变成可以归类、检索和继续操作的对象。它的节奏骨架是「硬切成标签→停留辨认→一次连续缩移→硬切出完整页面」。第一切改变对象身份，缩移交代它属于哪里，第二切补齐使用环境。最终页面必须说明这个标签与什么内容有关；只出现一个漂亮胶囊和几行泛泛文案，还没有完成教程表达。

来源：[Shotcraft 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/shots/interaction/hashtag-to-pill-materialize.md)／[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/hashtag-to-pill-materialize.mp4)。本文为独立设计分析与原创演绎，不是原卡翻译。以下区分**原卡给定**、**源码可见**、**抽帧可见**与**制作推导**。实现分析依据main演示及实际调用的辅助文件，未核实它们与早期固定提交逐字同版。

## １．先判断这里发生了什么

**原卡给定**：居中输入带井号的话题词，红色实心光标恒亮；直接切成大胶囊，缩小移到成品页的标签位，再硬切揭示完整页面。**源码可见**：实际词为`#shots`，胶囊去掉井号、加入场记板图标；完成页标题为“My favorite shots”，正文讲镜头动作。不存在回车事件、请求、保存或真实标签检索。

| 当前内容 | 适合采用的表达 | 需要另行交代的事 |
|---|---|---|
| 输入一个分类或话题，确认后成为对象 | 字符状态切成标签状态 | 确认由什么实际操作触发，标签属于谁 |
| 从概念讲到页面中的具体位置 | 大标签归位，再揭示上下文 | 揭示是讲解取景变化，不能伪造软件自动生成页面 |
| 演示中文标签输入 | 完整词确认后成为标签 | 拼音组合、候选选择与最终汉字不能混成同一种状态 |
| 解释标签如何组织内容 | 先赋予标签，再进入实际匹配集合 | 归类与筛选是两个行为，结果必须有真实匹配依据 |
| 表现一段文字改成标题或备注 | 可以借鉴身份确认与归位 | 若没有标签实体语义，不必强套胶囊和井号 |

**制作推导**：这里的“实体化”是表示方式改变，不是把文字变成可触摸的三维物体。它可以是软件真实的token确认，也可以是清楚标明的教学示意。标签出现不自动意味着云端保存成功；成品页出现也不意味着正文是输入这个词后生成的。当前软件若需要空格、回车或点选候选才能确认，就如实展示；没有资料就不编造按键。

这是一段从输入走向上下文的连接镜头，不适合承担整段标签教程。若要讲标签继承、批量操作、层级规则或多条件筛选，完成页之后还应由实际关系镜头接管。连续几个章节都用「大词→胶囊→页面」，即使每段都流畅，整片仍会重复。

## ２．先画完成页：标签是关系入口，不是唯一主角

### ２．１　样片完成态怎样成立

**抽帧可见**：暖纸底铺满画幅，上方低对比面包屑和编辑时间，中上部深绿大标题，左侧一枚鼠尾草绿标签，下方三行深灰正文。标签与标题、正文沿近似相同左边界组织，不是把四种信息各装一张卡。右半保留大片浅底，页面具有连续的纸面感。

**源码可见**：元信息左右为164／160，顶边86、字号32；分隔线y144；标题左160、上168、字号122、字重700、字距0.5。正文左152、上618、字号70、字重500、行高1.33、字距0.3，并以显式换行控制三行。三行行盒总高约279.3，布局范围约到y897.3；这不是对字形墨迹边界的测量。标题和正文左缘相差8px，不应笼统写成“所有对象精确同轴”。

标签落定包围盒左约156.02、上407.628、宽409.96、高130.744，与标题左160差约4px。此处轻微光学错位可以在当前字体下评估，但不能把示例坐标当作万能栅格。正文与标签底边约留79.63px，靠空白区分元数据与正文，不靠粗分隔线。

**制作推导**：先用当前视频真实标题、实际标签和两三段必要内容画静态完成页。确认观众能辨认“这是什么页面”“标签属于谁”“标签改变了什么”，再设计输入近景。如果正文与标签没有语义联系，只是在同页出现，运动再顺也不能补出关系。页眉的编辑时间如无真实依据，删去或标示意，不能把“刚刚编辑”当作质感装饰。

### ２．２　从完成页倒推前景与负空间

前段不是空白页中央随便打几个字，而是暂时只展示需要确认的对象。样片把输入和大标签中心放在`(960,540)`，完成页标签中心放到`(361,473)`。运动以左移599px为主、上移67px为辅。观众先看对象身份，再被引向完成页左侧阅读轴；不是从画面底部飞入一张新卡。

**制作推导**：确认前的中心负空间帮助看清字符；归位后的右侧空间留给正文与后续内容。如果真实页面标签在标题右侧，就重算到真实槽位，不因原卡“左移”而改造产品布局。最终标签不能占满标题与正文之间所有空间，也不能缩到只剩一个不可辨认的色点。先决定最终可读字号，再反算缩放和初始标签大小。

## ３．把字体、图标、胶囊与纸面作为一套美术设计

### ３．１　字形决定的是轮廓与重量，不是只选一个字号

**源码可见**：字体栈为Futura、Century Gothic、Avenir Next、Trebuchet MS及系统无衬线回退；输入与标签正文名义字号132、字重500、字距2。完成页沿用同一字体家族，以122／700的标题和70／500的正文形成层级。没有随镜打包或证明实际命中的字体文件，因此不能声称样片已精确使用Futura，或中文沿用这条字体栈就有相同效果。

**抽帧可见**：输入短词具有紧凑、圆润且较重的轮廓；成品标题比正文更厚，标签缩小后仍能读出shots。**制作推导**：中文先选择实际可用且覆盖全部字形的字体，检查“待补材料”等连续方块字的密度。主标题可偏重，标签保持中等重量；不要把中文字横向压窄以迁就英文胶囊，也不要给每个汉字沿用2px字距后再强缩到槽位。

输入光标为7×150、圆角2、左距8，颜色`#e0453f`，始终显示到输入层退出。它是此段唯一明确红色焦点，作用是标明正在输入；不应同时把页面警告、背景光晕和正文重点都染成同样红色。若实际软件光标闪烁，真实操作演示优先保留实际状态；本例恒亮不是全项目输入规范。

### ３．２　胶囊的实体感来自表面与比例

**源码可见**：大胶囊740×236、圆角118，无外描边；图标104×104，左内边距96，图标与文字的flex间隔66。文字槽从胶囊左侧266处开始。灰态底色`#e9e9e7`、字`#4b4b49`、图标`#7e7e7c`；归页后底色`#d5e0cf`、字`#3f5e4c`、图标`#5c7a63`。图标是场记板的实心剪影和镂空拍板纹，不是一个直接替换井号的同宽字符。

上表面叠加白色32%到透明、再到黑色2.5%的微渐变；内阴影含顶部3px白色70%和底部2px深色3%。因此灰标签不会完全融进纸底，也没有高饱和边框抢走词本身。**制作推导**：实体感先依靠明确外轮廓、内外留白和受光面，再决定需不需要弱影。不能通过堆厚阴影、强描边和玻璃反射，把分类标签做成一个呼叫按钮。

原卡称“加描边读作按钮”，应理解为此设计语言下的风险，不能推广成所有带边标签都是按钮。实际产品有描边标签时如实保留，通过尺寸、图标、位置和上下文区分角色。标签如允许点击，也不需要为了证明“实体”而假装不可交互。

### ３．３　背景与色彩在第二切共同换角色

**源码可见**：前段背景是`#fdfdfc→#fbfbfa→#f6f6f3`的纵向渐变；完成页为`#f6f3e8→#f3f0e4→#eeeadc`。标题`#2d5c47`，正文`#4c4b43`，元信息`#a7a392`。第83帧，背景、标签配色与完整页内容同帧切换，没有交叉淡化。

**制作推导**：第一次硬切主要确认对象，第二次主要揭示环境，两者不必都靠大幅色相跳变。页面采用当前片统一材质，保持字与底的对比；低对比元信息只承担辅助，若其中包含必须读懂的条件，就不能沿用样片那么淡的处理。纸面颗粒不是设计主角，最终交付压缩后若看起来像脏点或闪烁，减弱或停用，不以“电影感”为理由保留。

## ４．按真实代码拆开节奏，不把注释当成实际时序

| 阶段 | 源码时点／实际关系 | 设计作用与重排原则 |
|---|---|---|
| 等待与输入 | 0起有光标；字符在8、14、20、26、30、34帧依次出现 | 先有输入焦点，短词以有控制的差异节奏形成 |
| 完整词辨认 | 34帧已完整，48帧切换，间隔14帧，约0.47秒 | 观众先认出词，再看到表示改变 |
| 标签确认 | 48帧直接换层，同时1.03倍，51帧回到1 | 没有透明度交叉、外壳展开或连续字形变形 |
| 标签停留 | 48到66相隔18帧，约0.6秒 | 含头3帧微落定；严格稳定的51—65仅15个展示帧 |
| 统一缩移 | 66到80，14帧，约0.47秒 | 位置、尺度共用同一个缓动进度 |
| 落位辨认 | 80—82保持到位，83揭示 | 不是落点一到就马上再滑入另一个容器 |
| 完成页阅读 | 83—119共37个展示帧，约1.23秒 | 足够辨认版式，不等于足够读完三行英文或中文教程 |

**源码可见**：确定性种子20260717仅控制每次4—6帧的间隔；实际六个字符是`#`、s、h、o、t、s。注释里“4—8帧”与运算不符；时间轴标题还写132帧，导出的时长常量与取得样片均为120帧。原卡中的“原片约6字／秒”、25fps测量注释和这个30fps重做片不能混在一起当作同一速度。

**制作推导**：汉字词不要按英文字符数机械扩展。教学示意可只呈现确认后的完整汉字；如需解释真实输入法，单独安排拼音、候选与确认，不用“人手抖动”掩盖错误输入过程。实际口播较长时，把时间增加到完整词、标签确认或完成页的可读停留，不把14帧的缩移拉成长途飘动。

第一次硬切的含义是状态已经确认，不是特效爆炸。样片并没有回车键帽、手指或提交声；制作时能否加入取决于真实操作。第二次切换是完整上下文登场，不是新页面从无到有的生成证明。需要表现实际等待或网络失败时，另设计对应状态，不能让这两记切换代替所有系统过程。

## ５．缩移怎样保持一个对象，而不是位置和大小各演一次

### ５．１　中心、左上角与内部排版分开求

**源码可见**：设共同进度`u=bezier(0.5,0,0.25,1)(clamp((f−66)/14))`，中心为`(960−599u,540−67u)`，尺度为`1−0.446u`。外层原点在`0 0`，先把对象局部原点送到目标中心，再缩放；内层以自身尺寸作`translate(-50%,-50%)`，让胶囊中心与该原点重合。不是把左上角坐标直接设成中心值。

完成态宽`740×0.554=409.96`，高`236×0.554=130.744`；左上角为`(361−204.98,473−65.372)`。字体132缩成73.128，图标104缩成57.616。若最终中文字需要更大，就修改最终尺度、初始字号或槽位宽度，不能只把外壳变宽而让内部仍按旧比例挤在一起。

若使用一张明确740×236的变换盒，却把应该按左上角推导的变换改为绕中心，误差量可达到`(1−0.554)×(370,118)=(165.02,52.628)`。这是指定盒尺寸和变换写法下的解释，不是所有DOM层级的固定误差；实际外层宽高、嵌套和变换顺序改变时要重新推导。改一个`transformOrigin`之后凭肉眼拖坐标抵消，容易只在最后一帧看似正确。

### ５．２　“字号一样”不等于“文字原位”

**原卡给定**：实体化前后字号不变、原位等大。**源码可见**：输入是“当前已输入文字＋8px空隙＋7px光标”这一整个flex组居中；每增加字符，组宽变化，左边界也跟着向左。胶囊内却是固定96内边距、104图标、66间隔，shots文字左边从x856起；第48帧还有1.03尺度，名义字号实际放到135.96。

**抽帧可见**：47到48时，井号和红光标消失，图标与宽外壳出现；词的整体位置关系有重新排布，不能说字形逐个精确叠合。本文不在缺少实际字体度量时编出像素级文字位移。

**制作推导**：硬切允许清楚的表示变化，但仍要选支点。可以让词的首字基线连续，井号原位换成图标；也可以像样片一样让整个实体保持中心，接受内部文字重排。两种都能成立，前提是切后仍能立即认出同一个词。若要求字面位置不跳，先测当前字体词宽、图标槽和光标宽，再调整输入起点；不能同时宣称整组居中、图标加宽、字完全原位而不做补偿。

### ５．３　路径中段与模糊不能破坏身份

胶囊中心沿一条直线左上移，不走抛物线，也没有旋转。位置和缩放同进度，远看会像对象在落向页面槽位；仅提前缩小再移动，会变成两件事。中段需要检查的是包围盒连同阴影仍在安全区域、字没有被裁切、重心正往目标阅读轴靠拢。

**源码可见**：速度由位置函数的`f±0.5`中心差分得到，方向取`atan2(vy,vx)`；模糊强度为`min(7,速度×0.1)`，小于0.35就不加滤镜。它是沿位移方向的单轴高斯模糊，没有根据边缘缩放速度逐点计算，不是物理快门的完整仿真。**抽帧可见**：72帧有横向为主的拖影，80／82帧已能辨认落位小标签。

**制作推导**：文字在快段暂时不能逐字读没有问题，观众应已在hold看清对象；但头尾必须清楚。模糊不能留到完成页，也不能覆盖整页标题。把外层滤镜裁切范围与影子一起检查，不能只看标签中心没出画。若当前内容中段必须读字，就减速或减少模糊，不用“参考片就是这样”压过阅读任务。

## ６．离地与落地：用影子辅助空间，不额外制造漂浮

**源码可见**：这里的`lift`不改变胶囊的实际y坐标，只驱动阴影。hero阶段为10，缩移进度前35%仍保持10，后65%降到0。不要把注释“浮起10px”解释为主体真的上移10px。

| 影层 | lift为10时 | lift归零时 | 视觉作用 |
|---|---|---|---|
| 近影 | y2.2、模糊5、透明度0.070 | y1、模糊2、透明度0.040 | 保留贴近表面的接触关系 |
| 远影 | y16、模糊40、扩展−6、透明度0.090 | 位移／模糊／扩展／透明度归零 | 大实体受承托，归位后取消悬浮重量 |
| 内高光／底沿 | 固定的3px亮边与2px暗边 | 同一造型随整体缩放 | 保持表面，不在移动途中突然换材质 |

这些数值发生在大胶囊局部坐标，最终还乘0.554。完成态保留微弱近影与内高光，并非所有影子完全消失。**制作推导**：这是一种二维表面提示，没有真实光源、厚度或景深；能让观众感觉它从重点展示回到页面即可，不必加3D旋转来证明落地。

另一个应保留的差异：源码称83帧后“真静止”，但上层`Grain opacity=0.05, step=2`每两帧更换纹理及偏移，120帧里并未冻结。准确说是文字、页面和标签几何静止，颗粒仍变化。制作时若要完全静帧，固定纹理；若保留动态纹理，需实际正常速度检查是否闪烁，不能仅凭几张抽帧宣称安静收尾。

## ７．十二张关键帧分别回答什么

以下均指官方重做样片的精确帧号，时间按30fps换算；通过 [官方样片](https://vincentwei1021.github.io/video-shotcraft/media/hashtag-to-pill-materialize.mp4) 回查。本文不把未取得的Bear原片画面当作已看过的证据，也不把外链可用等同于未来制作时一定能读取。

| 帧／时间 | 抽帧可见 | 导演需要核对的问题 |
|---|---|---|
| 8／0.27秒 | 井号与恒亮红光标 | 能否认出输入焦点；起始字有没有被图标替代得太早 |
| 34／1.13秒 | 完整#shots已出现 | 词何时真正可读，后面留多少确认时间 |
| 47／1.57秒 | 仍是输入词和光标 | 第一切的上一态，不存在半透明外壳 |
| 48／1.60秒 | 直接出现完整灰胶囊、图标和shots | 字符身份延续，同时承认内部排版重置 |
| 51／1.70秒 | 胶囊微缩回常态 | 3帧落定已经收清，不继续弹跳 |
| 66／2.20秒 | 大胶囊仍在中心，开始缩移区间 | hold足够辨认，没有提前移动 |
| 72／2.40秒 | 左移缩小中，有方向拖影 | 中段包围盒、视线方向和文字身份仍成立 |
| 80／2.67秒 | 小灰标签已在左侧槽位 | 终点尺寸、位置、影子与目标页相容 |
| 82／2.73秒 | 页面仍未揭示，标签保持到位 | 两次事件之间短停可辨，不凭空多出飞入段 |
| 83／2.77秒 | 暖底、绿标题、绿标签与正文同帧出现 | 第二切是否让人立即明白所属页面 |
| 100／3.33秒 | 完成页版式保持 | 主次阅读明确，标签不继续抢标题焦点 |
| 119／3.97秒 | 末帧仍为完整页 | 检查实际结尾；不能据此声称观众已读完正文 |

**制作推导**：只审48／83两个端点不够。47／48查身份，66／72查连续构图，80／82／83查落位与切页；100／119再确认收尾没有新增动作。以后当前片若不能读取官方视频，就先取得对应画面再评估；不能把这张文字观察表当作能替代全部视觉证据的素材。

## ８．完整原创演绎：给报销笔记添加标签，再找回需要补材料的两篇

### ８．１　从真实内容问题确定结果，不从胶囊外形开始

这是独立教学界面示意，不冒充某个已核验软件的录屏。教学问题是：“材料未齐的报销记录，怎样放到同一入口，之后一起找回？”当前笔记叫“10月差旅报销”，正文两条：“车票已齐。”“住宿发票待补。”给它添加“待补材料”标签。另有“设备采购报销”，正文明确“验收单待补”，此前已有同名标签。

场景资料只设三篇笔记：上述两篇，以及没有这个标签的“本月报销说明”。添加前标签匹配集合为设备采购报销一篇，添加后为设备采购报销与10月差旅报销两篇；笔记总数一直为3。筛选结果数量是这组教学资料的可核对结果，不是示意数字随手从1跳到2。添加标签不代表发票已补齐，更不代表报销提交或审核通过。

先设计两个完成画面：本镜末态是带标签的当前笔记；下一镜是两篇实际匹配笔记的列表。第一镜说明归属，第二镜证明组织用途。不能让所有正文消失，只剩巨大“待补材料”和一个成功勾。

### ８．２　完整态的具体美术与空间

1920×1080初稿采用暖灰背景、石墨色文字与低饱和琥珀标签。保留纸页的连续表面，弱分隔线区分左侧导航和右侧笔记，不给每条正文套漂浮卡。待补标签是分类，不用错误红；正文“住宿发票待补”可用克制的细底线与局部对比提示，不把整段标成警告弹窗。当前片如已有配色与字体，沿用其体系重新分配角色，不另起一套品牌。

工作区初稿为`(160,120,1600,800)`，左栏宽300，分隔线x460；正文阅读起点x540，右界x1640，有效宽1100。顶部辅助路径位于y160附近，笔记标题x540／y220，中文初稿64px、偏重；标签槽顶边360，目标高72；正文起点y490，字号40、行高约1.6，两条共用左轴。底部920以下不放新的关键字段，实际字幕区仍按当前构图核对。

目标标签宽280、高72、圆角36，左540、中心`(680,396)`，标签文字初稿34px。中文“待补材料”按当前字体实测；初稿可给图标28、间隔12、左右各40的空间，四字字身按136估算，总需求256，280尚有24余量，但不把估算当成字形测量。真实超宽时增宽或改写标签，不挤压字形。

前段确认态可放大2倍，即560×144，中心仍在960／540，字号68，图标56。归位尺度为0.5，终点仍是280×72，不能照搬740×236与0.554。当前页面的标题、标签和正文拥有自己的比例，不需要复现样片的大英文标题与三行宣传语。

### ８．３　从输入到归位的完整镜头调度

| 状态 | 画面与动作 | 内容作用 |
|---|---|---|
| A．建立需要 | 先在完整笔记中看到标题、两条正文，强调住宿发票待补 | 先知道为什么要加标签，标签有真实对象 |
| B．切入输入特写 | 进入清楚的教学局部，旁注“为10月差旅报销添加标签”；只保留必要对象身份 | 大词画面是操作局部，不是凭空换题 |
| C．形成输入词 | 按实际输入方式呈现#待补材料；教学示意若省略输入法则明确只示确认文本 | 观众看清词与需要一致，不误学拼音输入过程 |
| D．确认成实体 | 真实确认动作后硬切成带标签图标的琥珀浅底胶囊，光标退出 | 字符已成为标签，不等于提交报销 |
| E．辨认再缩移 | 胶囊停稳，中心从960／540移到680／396，同时缩到0.5 | 同一标签进入当前笔记，不添加虚构弧线飞行 |
| F．完整页接管 | 落位后硬切出工作区，标签保留位置与词义，正文仍是材料待补 | 标签归属明确，内容没有被自动解决 |
| G．核对当前状态 | 读清“待补材料”和住宿发票这一条；不立即再推镜 | 给观众建立操作与信息关系 |
| H．下一镜按标签查看 | 明确点击左栏同名标签，再展示两篇匹配结果及各自待补原因 | 从单篇属性转为集合检索，实际用途成立 |

如果是实录软件，不应额外制造一个软件并不存在的巨大标签飞行；可把D—F作为明确的解释插镜，再回到真实界面同一笔记。标签的实际生效方式与确认动作先核对；软件如果不接受井号输入，就取消井号，不能为了引用本技法而教错操作。

### ８．４　原创几何、中段与镜头容量

原创缩移以共同进度u计算中心`(960−280u,540−144u)`，尺度`1−0.5u`；起始左上`(680,468)`，终点左上`(540,360)`。大标签虽然中心向左移动280，左边界只向左140，必须区分中心轨迹与边界轨迹。终点文字68×0.5=34，与页面原生标签字号相同，揭示时不突然再缩一次。

当u为0.5时，中心`(820,468)`、尺度0.75、包围盒`(610,414,420,108)`。注意这是缓动进度一半，不保证发生在时间中点。运动时保留的笔记身份小注应放在这条包围区域之外；标签阴影不能压过旁注，下一页标题不提前淡进中段争夺视线。

先让确认词和完整标签各有可辨认停留，再缩移；完成页之后的停留由口播“这篇笔记现在有了待补材料标签”所需时间与实际阅读决定。三篇资料、两次集合变化、正文理由无法压进原样片最后1.23秒。A—G可按实际口播拆为相连的局部与完整页镜头，H单独承担筛选，不要求一条4秒动效解释全部过程。

### ８．５　下一镜必须真的按同一标签找到对象

左栏同名标签是一个检索入口，正文区标签是当前笔记属性；它们可以同时存在，不能让观众以为复制了一篇笔记。若显示数量，添加前1、添加后2的变化应发生在操作实际生效后；不展示数量就不额外加一个动画计数器。讲解视角切回时，当前笔记名称、正文与标签身份保持。

点击左栏之后，内容区切成两行结果，名称分别为“设备采购报销”“10月差旅报销”，每行保留一句真实原因：“验收单待补”“住宿发票待补”。未匹配的“本月报销说明”不在结果里，但仍存在于全部笔记中。未定义排序规则，就不声称先后代表最近编辑或优先级。下一步如进入某篇补资料，应明确打开的是哪一篇，不能切成无标题泛用详情。

声音可在真实输入时轻用按键声，确认成标签时用一次短促触感，缩移最多保留极轻的方向提示，完整页揭示让位给口播。不要两次硬切都配巨响，也不模拟原片未听过的音效。添加与筛选各有不同动作依据，音效不能把确认标签包装成“报销成功”。这些均为原创声音建议，未制作或试听。

## ９．用可观察画面判断哪里失败

| 失败画面 | 优先修正 | 通过时应能看到什么 |
|---|---|---|
| 词变成胶囊，但不知道给谁加的 | 先建立对象，局部镜头保留身份 | 能复述标签名称及所属笔记 |
| 硬切后词像换了一个，首字跳得难跟 | 测量字宽，选择中心或首字支点 | 图标变化清楚，同一词立即可辨 |
| 硬切被展开／淡化拖成普通入场 | 回到明确状态切换，另审微落定 | 上一帧是输入，下一帧是完整标签 |
| 标签像主按钮，正文成为陪衬 | 减少体积、边界和阴影，恢复页面层级 | 完整页首先读到对象与内容关系 |
| 缩小先完成，再慢慢挪位置 | 使用一个位置／尺度共同进度 | 归位作为一个连续动作完成 |
| 终点偏约半个标签，靠补坐标勉强对齐 | 核对中心、盒尺寸、嵌套原点与变换顺序 | 大小变化前后中心与目标槽位一致 |
| 标签到位，揭页时文字又缩一次或跳一格 | 共用最终字号、盒尺寸与字形度量 | 82／83对应的槽位连续，配色可以明确切换 |
| 颗粒不断跳，却写“完全静止” | 冻结纹理或如实描述动态表面 | 实际速度看不分散阅读，静止声明与画面一致 |
| 完成页只够看版式，却要求读完正文 | 以实际文字和口播重留阅读窗口 | 关键理由可读后才继续操作 |
| 标签出现就说已保存／提交／审核通过 | 区分属性确认、持久化与业务处理 | 只宣称有实际证据支持的状态 |
| 筛选结果随便放两张卡 | 按标签匹配核对对象与数量 | 两篇都有同一标签及对应待补原因 |
| 端点漂亮，中段模糊或旁注遮住标签 | 审刚起步、运动密集处、到位前后 | 轨迹与身份可跟踪，文字不被无关层盖住 |
