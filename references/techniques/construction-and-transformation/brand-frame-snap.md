# 同帧翻色的模式画框

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/effects/brand-frame-snap.md)、[BrandFrameSnap](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/effects/brand-frame-snap/BrandFrameSnap.tsx)、[brand-frame-snap 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/brand-frame-snap.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 画框是一套语义编码

这不是给录屏加彩色边框。画框表示当前处于哪个模式，光标操作、窗口内容、模式文字和框色共同证明模式切换。适合一个产品两种工作视角的对照。章节如果没有稳定的二分关系，翻框色只会变成装饰；颜色也不能单独承担识别，必须有可读模式名。

## 2. 先把框内真实内容做成主角

原例钴蓝表示Design，橘红表示Dev，中央瓷白工具窗口共用一张推广卡，保证切换前后比较的是同一对象。设计态左右是图层、属性，开发态对应tokens和CSS面板。框带用纯色面积建立外壳，薄釉上亮下暗，角标贴在框带，主UI保持中性。模式切换不是整屏无关画面换页。

画框厚度60px只对应1920×1080示例。框带要容纳文字又不吃掉内容，内孔22px圆角与窗口18px圆角应有明确层级。不要在三层外壳重复大圆角和大阴影；窗口落进框内之后要有安静的空白隔开边框与UI。实际关键按钮、数值和代码在最终缩放下可读才是优先级，不能为保住60px框宽把真实界面压成缩略图。

## 3. 动作和同帧关系

f−1起19f框带长出，窗口f10起从下方660px进入，rotateX18°→0、scale .88→1，共用spring damping15/stiffness115。先立框，窗口在框生长中途落入。影高度70→22收紧，纵向拖影随速度消失。若内容先满屏再包框，会失去“装裱”的空间动作。

| 阶段 | 原例锚点 | 要核对的关系 |
|---|---|---|
| 建立模式 | 窗口落稳到光标操作前 | 框、模式角标、当前选中态一致 |
| 操作 | f56–80向Dev开关滑，80按下，84松开 | 鼠标与开关真实位置同源，切换由此发生 |
| 状态翻转 | f84判断dev=f≥FLIP | 框带、窗口模式、开关和文字同帧变，不能分四次淡入 |
| 冲击余波 | 3f白闪.6/.4/.2，框厚12px指数衰减振荡 | 这是可减弱的包装反馈，不能盖过真实结果 |
| 内容解释 | 注记线FLIP+2起3f错峰，数值FLIP+6起 | 切换是同帧，解释可以随后分主次展开 |

窗口小顿挫约1%，随后仅慢推。框厚度变化会改变内孔可用区，检查整个余波期间的裁切，不只看f84静帧。源码准确表达的是四条实体色带配角补色，不应只改borderColor后声称完整复刻了同样几何。

## 4. 观察与边界

16幅官方帧能见框先出现、窗口落入，蓝框内同一按钮从设计选框变成橘色尺寸注记，右栏转成深色代码。末态仍是同一推广卡，所以比较身份连续。等距抽帧不能证明三帧白闪舒适，也不能验证click同步；原例手工窗口不是本项目真实产品功能的证据。

## 5. 原创制作推导：同一照片的编辑与导出

内容目标是区分“正在编辑”和“即将输出”的设置职责。先设计结果：同一真实照片保持大小和裁切，右侧导出栏显示实际格式与尺寸；框带写“导出”，色相对应输出阶段。编辑态框带写“编辑”，右侧为裁切属性。不能用蓝框/橘框代替文字说明。

起始窗口从已有照片编辑画面建立；光标只操作真实的导出入口。若真实软件开启的是弹窗而非整体换模式，就忠实保留弹窗行为，画框只在该状态确认时变色，不伪造整页开发模式。框内照片的位置不跳，观众可以追踪同一对象。

切换后先强调格式选择，再强调输出像素，顺序服从口播，不把每个值都做弹簧。下一镜从这个导出按钮接到真实文件的尺寸检查，证明框色对应的操作确实改变了结果，而非只是包装。

## 6. 失败诊断与审核证据

- 蓝框里已有橘色主强调，观众分不清当前模式：减少包装色进入无关内容，保留真实图片本色，不能为了编码给照片整体染色。
- 先翻框再换UI：统一状态事件锚点；逐帧比较切换前、切换帧、切换后，三者不应相互矛盾。
- 窗口落进来但角标压住标题：重算框带、内孔、窗口尺寸和安全区，不能只缩字解决。
- 切换白闪盖住操作证据：降低或取消闪光与厚度回弹，优先保持按钮和结果可见。
- 框颜色变了但产品没变：删这次翻色或给出真实状态变化；不得用装饰冒充功能证据。

设计通过须有两个模式的完整静帧、同一主体的位置对照、真实交互触发和结果阅读段；视觉包装的次数取决于叙事，不复制原卡的全片次数上限为新规则。动态与声音需具体成片验证。

## 原创镜头的关键画面调度

下表是上述原创应用的设计草图说明，不是已渲染关键帧，也不代表动态已验。以实际内容、字体与画幅重排，检查每个状态及状态之间的完整运动包络。

| 状态 | 画面安排 | 观看焦点与接棒 |
|---|---|---|
| 编辑态 | 同一照片居中，实际编辑控件在右，框带有模式名 | 框是外围导航，照片本色不随包装染色 |
| 状态切换 | 实际导出入口触发，照片保持位置，框与模式名一起变 | 闪光弱于功能结果，余波期间检查全部裁边 |
| 导出态 | 格式／像素依次点明，照片与文件身份保留 | 结果读完才去文件属性，不连放第二次换色 |
