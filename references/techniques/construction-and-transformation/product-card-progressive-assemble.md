# 详情对象逐字段形成：用信息分组组织动作，把真正的变化留给重点

本技法解释“一个对象怎样由有意义的字段组成”，而不只是让图片、标题、标签、按钮逐个入场。先设计完整对象的内容和版式，再决定字段的分组、来源、形成顺序和一次需要观众理解的关键变化。完整结果必须可读、可核对，并能进入下一步使用。

来源：[Shotcraft 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/shots/ui-entrance/product-card-progressive-assemble.md)／[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/product-card-progressive-assemble.mp4)。本篇为独立研究与原创演绎，不是原卡翻译。**原卡给定**、**源码可见**、**抽帧可见**与**制作推导**分别标明。main 原卡和实现未与 135 篇来源清单的固定提交逐字同版核验。

## １．先区分出现、填写与改变

**原卡给定**：用填充光标带观众经历图片、标题、分类、价格、正文、色卡、按钮，中间加入价格降级与新值出现。**源码可见**：内容来自预先定义的常量，没有实际网络抓取、识别、表单校验或提交。外观可以暗示自动填充，但不能当作已经发生的产品过程。

| 表达目标 | 可以采用的动作 | 必须有的依据 |
|---|---|---|
| 介绍已有详情结构 | 预留完整位置，逐组显露当前讲解字段 | 字段真实存在，顺序服务解释，不暗示实际加载 |
| 从材料整理字段 | 来源先可见，字段与依据逐项对应 | 数据由材料支持；缺失值明确留空或待确认 |
| 展示真实自动填充 | 按实际操作与结果安排填充过程 | 实际输入、输出及状态有当前资料依据 |
| 修正一个关键字段 | 旧值先读清，再表现修改理由和新值 | 修改确实发生，不能把任意数字跳变当能力 |
| 展示组成关系 | 字段按角色分组，形成可读对象 | 位置说明职责，不只是七个等权卡片 |

“出现”只改变可见性，“填写”改变对象内容，“修正”还需要旧值、新值和理由。不要给所有字段同样的弹跳、描边和音效，让真正的变化淹没在入场里。教程如只在认识字段，无须强加改价事件；如内容是确认条件，也不能为了结尾漂亮而自动显示成功。

## ２．先画完整详情，再倒排组装过程

**抽帧可见**：样片是一张横向浅色详情面板，左侧大图承托品牌主体，右侧按标题、分类、价格、说明、选项和入口向下组织。整张面板在亮底环境中有独立边界与柔影；字段未出现时，右侧仍有预留骨架，最终不会因内容逐次增加而把后续区域推来推去。

### ２．１　左右关系来自内容职责

**源码可见**：面板宽 1520、高 840，位于 `(200,126)`。内边距 60；图片区宽 640、高 720，右列起点为局部 x=764，有效正文宽 696。图与右列之间留出 64 的空隙。左侧解释对象身份，右侧承担描述和操作，二者不是对称的两列说明卡。

**制作推导**：先确定当前对象最需要被看见的部分。实物详情适合大图与属性；文档提炼更适合来源页与字段；配置对象适合代码／文件结构与说明。不要为了沿用此布局，把没有视觉内容的概念硬塞一个大图标占半屏。

完整态先排最宽标题、最长正文、最复杂值与最后的入口。若右列内容已经挤满，增加整张面板宽度不一定有效：可能应调整图文比例、分镜容量或解释方式。字段未出现的空位是结果布局的一部分，不是用来放装饰图形的空白。

### ２．２　标题、数值与正文的字形层级

**源码可见**：眉标采用小等宽字、疏字距；主标题使用大号粗无衬线，价格也使用大字号但在变更后让旧值退为辅助。正文为较轻的字重、较小字号与稳定行距，重点词通过字重及底色提升。分类与选项承担索引，不与价格同等竞争。

**制作推导**：标题首先说明对象是谁，主数值说明当前最重要的属性，正文说明依据或用途。主数值并不必然是价格；对于教程可能是当前状态、一个确切结果或需要核对的条件。若实际内容没有主数值，不要为填满视觉槽位制造一个大数字。

实际中文必须重排。英文标题单行成立，不代表“会议记录整理助手”也能用同样字号单行塞入。先检查字面宽度和换行，再修改字段区域与后续纵向位置；不要只缩字，让整卡失去层级。系统字体回退与连续字重也要看实际渲染结果，不能仅凭 CSS 声称字形一致。

### ２．３　表面、材质与背景怎样统一

**源码可见**：面板采用白到极浅冷白的渐变、细边、上沿内高光及两层带色相的软影；图片窗是更深一点的冷灰空间，有亮处向外渐退的背景与下方承托明暗。画面右后方还有极弱蓝色光晕，背景舞台不直接盖在主要内容之上。

**制作推导**：背景、外面板、图片承托面和字段至少能凭明暗分开，不能全靠四圈投影描边。白色物体放在白色环境时，用轮廓、局部明暗和接触关系保持完整，不通过给所有对象加蓝色辉光补救。若教程载体是纸面或代码界面，应采用其自身的材质语言，不给每类材料统一套“商品棚拍”。

左图标志在样片中看似立在浅色环境里，源码明确另放一团接触影，但未建立物理投影模型。本轮未读标志内部实现，不能因此声称存在真实三维厚度。原创实物可以使用可靠素材；原创文档则保持纸面与文字结构，不借一个类似实体的阴影制造不存在的功能。

### ２．４　强调色的职责与例外

**源码可见**：填充框、新值、说明 chip、正文重点采用同一蓝色角色；大面积外壳和正文以中性色为主。但左侧品牌图及四枚色卡还包含其他颜色，所以“全卡只有蓝色一个色相”的说法并不严格成立。

**制作推导**：应学习的是“操作强调有统一颜色含义”，不是抹掉内容本身的颜色。分类若已有业务颜色，应保留其语义，并与临时填充框区分；不能让蓝框经过某项就把它变成已验证。已填内容稳定后，强调应退让给下一项，不能整张面板留下七个同样亮的框。

## ３．字段不是七个互不相关的动画

**源码可见**：字段表同时存储区域矩形与到达时间。光标框的 x、y、宽、高在相邻区域间共同插值；字段内容在框到达后约 2 帧才开始出现。相同角色内部采用较短错峰，跨类型的间隔则较大。

**制作推导**：先把字段按身份、属性、解释、选项和操作分组，再决定组间顺序。对于来自材料的字段，还要考虑证据与依赖；不能把“图片最先、按钮最后”当作任何内容的规则。

字段记录至少应让内容、区域、身份与触发依据保持对应。文本更长时同步更新字段盒，来源位置改变时同步更新证据锚点。一次字段修订不能只改显示文字，却保留原来为短词写死的框和下一个字段起点。

### ３．１　框形移动的几何

在相邻区域 `A=(x₀,y₀,w₀,h₀)` 与 `B=(x₁,y₁,w₁,h₁)` 间，用同一个进度 `q` 插值四个量，形成 `box(q)=A+(B−A)q`。再用统一外扩量计算描边外框，而不是把中心移过去之后再突然换宽高。

**源码可见**：常规跳格持续 6 帧，使用 swift 曲线；第一张图片框从开头就已经采用图片区域，不存在从另一处飞到图片的首次跳格。描边之外有外扩、浅色填充、外圈弱光和小签，它们的实际外框大于字段本身。

**制作推导**：光标经过图片与标题之间时可能形成一个很宽或很高的中间矩形，需检查是否扫过其他已读字段。若几何插值的中段没有意义，可先收窄再移动再展开，但必须保证连续可辨；不能以“同一进度”作为中段构图好看的证明。

这个光标是导演层的字段提示，不是操作系统鼠标，也不一定是真实输入焦点。真实表单如果同时显示自己的焦点框，应选择一套明确的表现，不再叠第二个虚构的系统控件。

### ３．２　骨架退去与内容接管

**源码可见**：骨架按落位进度淡出，内容则用更快的透明度上升，同时从小幅下移和失焦回到原位；因此某些中段两者会短暂同时可见。单组内部的多行正文、分类和色卡也不是等上一项完全结束才开始。

**制作推导**：骨架表达已有结构或待填位置，不能误成真实系统仍在请求数据。交接时骨架亮度与正文笔画不能合成难读的重影；若长中文使骨架穿过字形，先降低重叠或改为稳定遮罩交接。不要一边填内容、一边让整体布局突然长高，把阅读焦点推走。

已存在的内容不必先抹成骨架再重新显露。若是在解释真实完成页，可以保留全貌，按组提高对比；“组装”不是强制制造加载过程。

## ４．动作、参数和阅读时间完整对照

下列为当前实现的具体值与研究位置，不是教程时长规范。帧号基于 30fps；实际时间仍服从真实口播与 Timeline。

| 字段组 | 框到达／内容开始 | 内容机制与检查 |
|---|---|---|
| 图片 | 8／10 | 14 帧揭示进度；主体另有 10—50 帧的 1.08→1 慢收，不能认为图片在24帧一切结束 |
| 标题 | 20／22，主标题额外晚2帧 | 眉标与完整主标题分别上移，实际不是逐字组装 |
| 分类 | 30／32 | 三枚分别晚0／3／6帧起弹；一组字段同类并行 |
| 原值 | 42／44 | 14帧落位，严格终点在58；62开始变更 |
| 正文 | 76／78 | 三行分别晚0／3／6帧，行程14帧；高亮86／90各6帧 |
| 色卡 | 96／98 | 四枚相隔3帧；色名从108开始，历时12帧 |
| 按钮 | 114／116 | 底色12帧填满；文字122起、8帧淡入；框122起、8帧退出 |

**源码可见**：通用 rise 采用 `snappy=(0.16,1,0.3,1)`，不是直接调用指数 ease-out；`opacity=clamp(p×1.8)`，上移幅度依据字段为10—26，模糊从最多6逐渐退去。小件 pop 的弹簧为 `damping=13、stiffness=260`，尺度从0.4映射至1，透明度另在4帧内上升。

**制作推导**：字段入场持续时间可以重叠，但新的阅读任务不能无限叠加。先看身份再看条件，关键值改变时弱化旁边普通显露；如果真实旁白较长，让已落位字段稳定等读，不能坚持每3帧继续弹下一项。

### ４．１　真正的语义事件：旧值怎样退，新值怎样成立

**源码可见**：原值从第62帧起在6帧内缩到0.46，颜色在进度越过阈值后变弱；删除线用5帧从左伸出。新值从63帧起淡入并用 `damping=14、stiffness=240` 从1.18映射至1，附加 chip 从69帧起10帧滑入。旧、新与说明共同构成一处值变化，不是三个独立装饰。

**制作推导**：若内容是修正，先交代旧值为何存在、哪里有问题、新值由什么支持。旧值可以保留删除线作为比较证据，也可在用户确认后移除；不能把样片的示意价格当作真实历史价格或真实优惠。修改理由缺失时，即使变色与回弹很准确，观众仍只看见数字被任意替换。

实际文字长度和单位必须重排。旧值、新值、条件说明不应依赖某一组字符宽度写死横坐标；从实际字块和间距求布局，检查新值最大过冲时也不会撞到 chip。若业务不允许未确认的中间值，修订过程中标明草稿，而不是将其当作有效状态展示。

### ４．２　高亮在文字之后，但不必等整组完全结束

**源码可见**：三行正文从78／81／84起，重点底块分别在86／90起，以6帧从左展开。第一行完全走完落位在92，第二行在95，因此底块和行落位有重叠，而不是文字完全静止后再高亮。

**制作推导**：高亮服务当前重点短语，不能先刷到空位、文字后到。中文折行后应按实际行片段画底块，不用一个绝对矩形横跨两行。改变行起点时同步改变重点出现时间；若文字尚糊，高亮又较亮，应让正文先稳定，不能一味追求作者的帧差。

### ４．３　最后的操作入口与收束

**源码可见**：按钮背景横向填入，文字稍后显露；描边框外扩量同时收回并淡出，落到按钮区域结束。整卡从0—132帧由1缓推至1.035；入场还叠加0.96→1的尺度和30px上移。父层变换必须同时作用于卡片、字段和提示框。

**制作推导**：按钮填满只证明视觉入口成立，不是提交、保存或付款已成功。字段有待确认值时，入口应服务确认或编辑，不应写“完成”掩盖未解决条件。按钮结束后给整体阅读窗口，再从真正入口进入下一镜，而不是动画结束就切走。

若正文需要精确读数，可以取消整卡持续微推；已有内容稳定也是有效画面。极缓尺度变化不应被当作解决PPT感的主要方法，画面是否有设计感仍取决于信息关系和美术。

## ６．原卡、注释与实际实现的差异

| 表述 | 核对结果 | 应如何处理 |
|---|---|---|
| 原价落稳后hold18帧 | 内容44起、14帧结束于58，62开始降级；严格停稳约4帧。18是从落位开始算到改变 | 需要读旧值时另留真实阅读时间，不能凭18的说明认定充分 |
| 标题逐字升起 | 实现中主标题是完整字块，用统一rise，没有逐字循环 | 真要逐字应独立设计中文分组，不能声称样片已实现 |
| 标题108px | 当前实际type传入112 | 原始叙述与实际字形布局分开核对 |
| 新值是唯一放大回弹 | 分类和色卡也使用弹簧pop；新值是一次突出的语义变化，但并非唯一尺度弹簧 | 保留“重点变化”的层级，不把技术事实说反 |
| 最后字段约128全部结束 | 按钮底色128完成，文字与光标到130；整卡前推132才结束 | 收尾检查最后一条通道，不按底色结束就切镜 |
| 全卡唯一色相为蓝 | 品牌图和色卡还带其他色相 | 统一的是操作强调色，内容颜色另有身份 |
| 改look强调色即可换品牌 | 品牌标志与SWATCHES还从BRAND引入，改强调色不会替换全部品牌内容 | 原创重做图、字、选项与色彩角色，不只替换一个变量 |
| 价格变更可代表真实优惠 | 原卡明确示意价格，代码为固定内容 | 不把演示数值当商业事实；原创需有自己的变化依据 |

## ８．完整原创演绎：从一句安排形成可核对的任务，保留不确定条件

以下为**制作推导**，未实现。教学内容是结构化整理时“有依据的字段可填，缺少依据的值不能猜”。示意来源句为“周五下班前，把会议纪要发给项目组”。结果应该保留任务动作、接收方和时间条件，同时明确具体时刻并未给出。

### ８．１　先设计结果与真正的变化

完成态左侧保留原句，右侧是一份可编辑任务：任务名称“发送会议纪要”，接收方“项目组”，时间“周五下班前”，旁边明示“具体日期与时刻待确认”；入口为“确认时间”，不是“创建成功”。没有责任人就不自动填一个姓名，没有具体日期就不把“周五”解析成某天。

需要表现的重点不是三个字段都出现，而是从一个明确标为“错误草稿示例”的17:00推测，回到来源真正支持的条件。旧值必须先标明其未确认身份，修改时同时指向原句“下班前”；最终新值和待确认提示共同保留。若当前教程不需要错误对照，直接保留待确认状态，不必人为制造纠错戏码。

这是一套教学示意，不能配成某个真实软件已经抓取、推断、提交的录屏。后续接实际产品时，字段、入口和状态均以真实资料为准。

### ８．２　构图与具体美术

用一张连续的浅色工作画布连接左侧材料与右侧任务表单，不把来源和每个字段都做成独立悬浮卡片。左侧原句采用较大的正文与稳定行距，关键词由语义片段标记；右侧标题、字段标签、输入内容、待确认提示有四个阅读层级。

画布为低对比暖灰，来源像平整纸面，表单保留清楚行与控件边界；墨色正文、蓝色的当前整理提示，未确认条件使用形状加明确文字提示，避免只靠颜色。错误草稿标记与普通字段不同，不能使用“成功绿”。背景不再加一套竞争光效。

当前字段有一枚克制的定位框，已经完成的字段退为稳定内容；原句的对应片段可短暂提高对比，框到目标后来源强调退弱。主次接力不等于左右两边同时跳动，读者应先看到依据，再看到字段。

### ８．３　空间草案与真实中文容量

以1920×1080为设计画幅，工作区初稿 `(180,170,1560,700)`；左来源区局部 `(48,84,500,420)`，右表单局部 `(620,84,880,520)`。两区间留72，右区距外壳右边60。右侧按实际标签和内容排任务、接收方与截止条件三组，最后保留确认入口。

右侧字段内容区初稿宽600，待确认短说明另占一行，不与时间文字挤在同一行。最复杂时间字段先排：若真实字体放不下“周五下班前”，就换行、调整行高或减少本镜信息，不能把字缩到只剩纹理。底部实际字幕另占区域，工作区阴影和前推动作不得压入字幕。

所有框位置由最终排版求出。不能从英文商品卡的670宽价格框直接套来解释中文时间；“17:00”和一整句条件有不同宽高，应先确定真实新旧字块，再设计过渡。

### ８．４　完整动作链

| 状态 | 画面与动作 | 新认识／阅读焦点 |
|---|---|---|
| A．来源建立 | 原句完整出现，右侧只见结构化字段区 | 材料先于结果，知道整理依据在哪里 |
| B．任务形成 | 原句“把会议纪要发给”作为动作依据；右侧任务名称出现 | 自然语言形成明确任务，不是标题装饰 |
| C．接收方形成 | “项目组”片段与接收方字段依次接棒，任务名称保持原位 | 同一信息进入合适字段 |
| D．时间问题 | 明示的错误草稿17:00可读，旁边明确“未确认推测” | 不能把常见下班时间当作原句事实 |
| E．依据检视 | 原句“周五下班前”获得主要对比；旧值退弱并划线 | 修改有具体依据，不是数字随机替换 |
| F．条件修正 | 新值“周五下班前”在同一字段稳定，日期／时刻待确认提示随后出现 | 区分保留已知条件与承认缺失信息 |
| G．结果核对 | 来源与三个字段共同可读，临时框退出 | 完整结构可核对，没有丢失原句含义 |
| H．进入使用 | “确认时间”成为焦点，接到真实确认或明确结束示意 | 入口回应未解决条件，不伪造完成状态 |

状态D是专门讲“不要猜”的错误示例，需要口播和标识共同说明。没有这个教学目标，就删除D／E，直接从来源形成条件与待确认说明；不能为了用一次删除线而故意输出错值。

### ８．５　中段、过渡与声音

**制作推导**：新时间文字比17:00长，先预留完整结果高度；旧值缩小与新值出现时两者仍应分清，不清晰叠字。来源片段与字段的关系可以用同色小标记或短连线辅助，但线只在需要核对时出现，不能多条同时交叉。

框从任务名称移向接收方时，检验中段宽高不遮住旧字段；进入时间组时不要让框吞掉“未确认”标识。按钮出现后不立即模拟点击；确认内容未取得就不能展示保存成功。下一镜若需要放大时间字段，保留任务名称或来源身份作为连续支点。

可用轻声提示区分普通填入与需要复核的修正，但不能每行都配相同弹跳音。对“待确认”的出现尤其不配完成提示。留给口播解释不确定性的时间，比把七组动作压进5.7秒重要。

## ９．具体失败与通过证据

| 失败画面 | 优先修正 | 可观察通过条件 |
|---|---|---|
| 字段都飞进来了，仍不知道对象是什么 | 先设计完整结果的身份与内容关系 | 不播放动画也能指出对象及其关键属性 |
| 框先圈到空白，文字出现在别处 | 共用真实排版矩形与触发关系 | 框、骨架、内容和外扩在实际长文案下对齐 |
| 中段框扫过一大片内容 | 重排跳格路径或先收后展 | 经过阶段仍能看清当前主角，不误示多字段同时被修改 |
| 所有字段同时弹、每项同等强调 | 按内容角色分组，降低普通入场能量 | 一次关键变化拥有明确阅读窗口 |
| 旧值还没读清就被划掉 | 从真正落稳之后计算停留 | 能说出改前值、理由与改后值 |
| 新值回弹撞chip或长中文越界 | 按实测字块重排，检查最大过冲 | 极值与完成态都不碰撞，单位和条件完整 |
| 高亮先到、字仍模糊 | 联动行开始与重点出现，必要时错开 | 标记依附实际词句，当前重点清楚 |
| 按钮先亮出“完成”但仍有缺项 | 让入口与真实结果状态一致 | 待确认条件显式保留，入口服务解决问题 |
| 结尾最后标签还在动就切走 | 查所有通道的真正结束 | 完整结果可通读，再自然接到下一步 |
| 只有逐项入场，像PPT | 增加内容依据、关键值的变化与实际结果组织 | 观众理解一项关系，而不仅记得字段出现顺序 |

这些问题沿用项目设计审查和实际观看要求，不新增Gate。本文完成来源机制、九帧状态与原创设计研究，不证明正常速度可读、真实中文渲染、声音或商用成片已验。相关选型见 [界面与数据动作](../../interface-and-data-motion.md)、[构图与字体](../../layout-and-typography.md)；来源支持结论的设计另见 [文档到要点](../../examples/document-to-key-points.md)。
