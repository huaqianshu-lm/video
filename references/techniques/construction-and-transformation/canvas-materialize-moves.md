# 从列表迁移到画布，与从输入长出结构

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/interaction/canvas-materialize-moves.md)、[DiagramCascadeBuild](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/interaction/canvas-materialize-moves/DiagramCascadeBuild.tsx)、[PanelToCanvasMaterialize](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/interaction/canvas-materialize-moves/PanelToCanvasMaterialize.tsx)、[panel-to-canvas 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/panel-to-canvas.mp4)、[diagram-cascade 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/diagram-cascade.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 整卡两种因果，不能互相替代

A说已有内容换形态，B说输入引出一套结构。A的完整动作、美术、主次迁移、真实结果布局与路径审核继续复用[列表迁移案例](../../examples/list-to-canvas-transfer.md)。该案例不是B的替代解释，本篇重点补齐级联生成和整卡选型。若本来就是已有图，不能用B把它重新弹出当作“生成”。

## 2. A的原卡补充与适用边界

原例14/24/34f逐选，52按按钮，56/62/68f三项拔起。行626×104迁成卡486×300，spring17/95/.9配上抛弧，尺寸晚3f跟随，原位塌成虚线“已上板”。来源状态保留的是迁移对应关系：真实功能若是复制，原位就应保留并明确已添加，不能照搬“必须塌陷”误改产品语义。

同一内容从行态转卡态中间有两个内容透明度窗口，row先退、card后入，中段可只剩容器；宽高与圆角连续，字不能非均匀拉伸。其他细节与原创演绎查上面的完整案例，不在这里另造一份简版取代它。

## 3. B先画最终结构，不先安排弹窗

原例深紫场，顶部细长prompt，下方一根两层树，玻璃节点含表名、主键／外键及类型。根居中，第二层两分支、第三层四叶，左右对称但内容身份不同。连线从父底端口到子顶端口，中线圆角转折，标签不能压线。

真正的设计问题是每个节点代表什么、为何连在一起。ER关系不能仅凭树形暗示一对多或数据依赖，真实模型需要明确关系口径；示例的数据结构属于演示内容，不成为本项目新增数据库架构。小字段如果最终读不清，只承担信息密度；需讲解时另取局部，不能全树缩小后还要求观众读七张表。

## 4. 输入、提交与级联时序

输入从f8起，非空格间隔.95+.25|sin(i·2.17)|，空格1.7；敲完后round(TYPE_END)+4提交。换文案应重算，不固定“提交f50”。确认描边与按钮反馈让输入结束和开始生成有因果扣。

| 关系 | 原例实现 | 换图后的检查 |
|---|---|---|
| 根出现 | SUBMIT+14 | prompt底滴线先开始，明确来源 |
| 层间 | 每层22f，同层按较小ID计数×5f | 是整层排序，不只同父兄弟；不同分支也被错开 |
| 节点 | spring14/190，顶边中点为原点 | 像从端口牵出，不是中心弹窗 |
| 连线 | 比节点早10f起，描16f | 节点出现时线已走一部分，并非必然已到终点 |
| 相机 | prompt特写1.3→1，提交后约72f退 | 下方新空间随结构出现，不能先露大量空白 |
| 成树 | 最后节点之后再呼吸，树心(960,620) | 呼吸是句号，不能用全屏中心把图推走 |

圆角折线路径用直段和1/4圆弧分别算长度，彗星头按弧长取点与描线端点同源。若新父子垂直间距太小、端口间无转角空间，原r=min(22,|dx|/2)还不够，须同时限制竖向可用长度，避免负直段；dx=0应单独直线处理，不能套零半径除法。

## 5. 官方观察与范围

A、B各16帧：A能见选中项变卡、来源虚线占位和最终三卡；B能见输入后根、分支、叶逐步出现，末态完整树。无声抽帧不证明打字人感、72f相机节奏、连线领先的实际可感性；也不能验证生成结果真实可用。

## 6. 原创制作推导：把资料整理成论证结构

内容目标是“同一结论下分清证据与限制”。先做最终画布：根是一句真实结论，左分支是证据、右分支是限制，各自叶节点显示真实来源短摘与定位，不默认2+4凑满树。字号由需要阅读的最短摘句决定，背景保持安静。

已有资料从列表来时用A：主证据承担完整形态迁移，其余简洁跟随，落位按论证关系而不是均匀散卡。若示意从一句整理请求建立结构，用B：先读清请求，提交后线从“结论”牵出“依据”，再牵出具体来源；不凭动效声称AI已正确分析。

完成后只让当前要讲的证据分支更亮，限制分支仍可辨但不同时闪动。下一镜沿一个叶节点进入真实原文正视近景，核查摘句是否遗漏条件；结构图由此成为可追溯的阅读地图。

## 7. 失败修正与合格证据

- 同层所有节点一起弹：核对nodeStart的层级与排序，若时长紧先删非必要节点而非全压一拍。
- 线和光头脱节：共享弧长与路径分段，检查圆角半径和零横距特例。
- 树长完像普通卡阵：重审节点内容、空间关系与端口语义，不能用背光掩盖关系缺失。
- 相机退完字太小：保留总览任务，再给局部读镜；不能把所有字段都当同一读窗。
- 输入和输出不对应：逐节点回查真实请求与来源，无依据的节点删掉或标示示意。

通过要能追踪输入／来源到具体结构，结果静帧有关系而非只排列，下一镜可回查。已认可案例保持原文，动态、声音和原创实现仍待具体成片验证。

## 原创镜头的关键画面调度

下表是上述原创应用的设计草图说明，不是已渲染关键帧，也不代表动态已验。以实际内容、字体与画幅重排，检查每个状态及状态之间的完整运动包络。

| 状态 | 画面安排 | 观看焦点与接棒 |
|---|---|---|
| 来源／请求 | 真实资料列表或短请求，未来结构有足够空间 | 先读内容来源，不让空画布占多数时长 |
| 关系长出 | 结论到依据再到具体来源，端口、线头、节点同源 | 只重点演一个分支，其他顺序服从理解 |
| 结果图 | 证据与限制有不同职责，摘句和定位可核查 | 总览后沿叶节点进原文，不要求七张小表同时读 |
