# 实时语音波形：让声音、转写与录音状态各有依据

## １．先分开三种经常被混用的“波形”

| 真正要表达的事 | 画面怎样组织 | 不应暗示什么 |
|---|---|---|
| 当前正在收音 | 输入状态、即时强弱与当前字词形成因果 | 波峰不是识别准确率或理解程度 |
| 展示刚才录下的历史 | 时间从新到旧有稳定方向，停顿成为历史中的空隙 | 旧波峰仍在，不代表人此刻还在说 |
| 配乐包装或装饰性频谱 | 跟配乐、节拍或明确的装饰系统运动 | 不冒充用户输入或真实声音分析 |

**制作推导**：先选“即时活动反馈”还是“滚动历史”，再决定停顿长什么样。前者可以在停嘴后整体回落；后者应在最新端出现空隙，过去的句子继续移走。把历史展示写成“停嘴就整排变点”，会让实现与语义互相打架。

若教程只介绍开启语音输入，镜头停在可辨认的输入与转写即可；若讲提交，必须有真实提交依据或明确的教学示意。录到声音、形成转写、停止录音、发送、对方收到、执行指令是不同状态，不能用一个勾代替全部结果。也不因旁白正在讲解就让录音控件随旁白跳：教程解说与示范输入可能是两条不同声源。

## ２．先把静态画面设计成立：两层主体，而非一条工具栏撑满全片

### ２．１　大字负责内容，胶囊负责状态

**源码可见**：上方是两行转写，字号92、字重760、字距−0.035em、行高1.08；系统无衬线回退栈。第一行六词，第二行五词，分别组成一项拍片请求及其开场要求。转写初始垂直参照372，容器通过`translateY(-50%)`围绕自身内容居中；372不是第一行文字的顶坐标。最后文本上移到参照330，整体缩至0.72，视觉字号变为66.24。

两行与全部词槽从开始便参与排版，未出现的词使用透明度隐藏，第二行有最小行高。因此前缀逐词变长时，整段不必反复重新居中；第一行的起笔位置与预留第二行共同建立稳定阅读支点。最终最长行的宽度仍由实际字体和词距决定，不能把英文占位宽度当作中文实排结果。

下方胶囊宽1240、高196、圆角98，中心在`(960,760)`，正常位置左340、顶662。标签在`(364,600)`附近，32px／600字重；计时32／600、70宽、等宽数字。主内容的92与状态的32形成清楚等级：观众先读说了什么，再确认正在录音，不让品牌标签比转写更重。

**抽帧可见**：文字和胶囊之间保留了大块空气，波形没有贴着字幕下缘跳；句子成形后可读作一张完整的录音画面。结尾由有体积的赤陶气泡取得主位，下面胶囊变灰退后。高级感主要来自稳定大字、充分留白、同一强调色与柔和受光，不依赖相机巡航。本镜没有相机运动，也没有指针实际点按。

### ２．２　暖背景、暖白表面、赤陶信号、深墨操作

**源码可见**：舞台从`#efe6da→#e8ddce→#ddd0bd`纵向渐变；主字`#221a12`、次字`#6d5d4c`、弱字`#a4927d`，强调`#c4552d`。主光位于画幅30%横向、顶部，偏暖白；78%／90%处只有弱的蓝灰补光。背景暗角0.16、颗粒0.05，主文字与胶囊放在舞台之后，不被舞台暗角再次压暗。

胶囊自身使用`#fffcf7→#f8f1e7`，顶缘1.5px白色内高光、低透明度内边、贴地小阴影，再叠宽而淡的落地影。大影为`0 40px 80px -30px`、另一层`0 14px 30px -12px`，以带暖色的阴影色统一；不能只加一团黑模糊，让白控件像脏贴纸。

麦克风是120直径的赤陶圆，填色`#d8673a→#b8481f`，白色SVG麦克风56×56；录音信号与输入入口共用强调色。提交钮也是120直径，但使用`#2c241b→#191410`深墨底，箭头52×52，形成明确操作端点。两个按钮同样有顶缘高光与小落影，属于同一种表面系统，而不是一边扁平图标、一边玻璃球。

波形的非静默条以浅陶`#e8956a`和强调色纵向渐变，旧条透明度更低、新条更实；低条改为弱字色的0.55透明度。颜色同时表达活动与历史层次，不给每根条分配一种颜色。字幕新词先赤陶、随后沉为墨色，将短暂注意力交给刚说出的内容，已有句子保持可读。

**制作推导**：迁到暗场时，应重新设计面板、字、边缘与光的对比关系；“换成玻璃”不会自动改善质量。迁到真实应用时，应沿用产品的输入入口和状态语言，保留这套主次关系，不必照搬赤陶、品牌名、92px或整个胶囊外观。

### ２．３　实际波形区有多宽，要从整个控件算

**源码可见／几何推导**：1240宽中，两侧padding各38，麦克风120、计时70、提交120，四个子区之间有三处30间隔。因此波形区实际宽：

`1240 − 2×38 − 120 − 70 − 120 − 3×30 = 764px`

64根条间有63处5px间隙；每根条约`(764−315)/64=7.015625px`，横向节距约12.015625px。波形从x528到1292，中心910，略偏画幅中心左边；不能根据“胶囊居中”认定波形也居中。条高最低6，配99圆角，实际是约7×6的短圆头形，不是几何上直径6的圆点。

波形区高160、理论最大条高150，顶部和底部各留少量安全区；左边14%渐隐、右边不渐隐，配合旧条变淡建立历史出口。先检查首尾按钮、计时与波形的间隔，再加遮罩；不要用遮罩掩盖条挤进计时或按钮的布局错误。原卡写波形区“约820”与当前764不同，选64根之前必须按实际留给波形的宽度复算。

## ３．波形怎样连续：保存时间关系，不靠每帧重抽随机数

### ３．１　可复现的值噪声只是合成演示，不是声音测量

**源码可见**：噪声先取`x`两侧整数采样值，种子是整数乘7919加13，通过mulberry32得到确定值；小数部分`u`用`u²(3−2u)`平滑，再在两值间插值。因此同一帧、同一索引得到相同结果，相邻时间也连续。没有逐帧`Math.random()`引起的跳闪。

说话包络是两段梯形的最大值：第一段15—57，第二段80—124，每段前5帧爬升、最后7帧下降。再乘`0.55+0.45×noise(t/4.5+200)`制造音节强弱。这里的起止、字词和“音节”都来自预设，不是音频识别或采样；即使看起来像说话，也只能证明合成信号连续。

**制作推导**：如果有人声示范，先从那条输入音频取得时间和强弱，再决定如何美化显示。一个可解释的起点是短窗均方根`RMS=√(Σx²/M)`：计算哪个时间窗、静默门限、增益和上升／回落平滑，均围绕真实输入校准。它描述响度包络，不是声纹身份、准确率或频谱；不把合成噪声替换音频后仍称“完全同步”。当前未制作音频分析实现。

### ３．２　64个固定槽读取不同过去，而不是64个物体一起平移

**源码可见**：第`i`根，`i=0…63`，采样时间为：

`tᵢ = f − (63−i)×1.6`

最右槽读取现在，最左槽读取100.8帧以前，整段历史跨度3.36秒。固定槽不需要横向transform；新的信号逐槽向左出现，产生流动。空间权重为`sin(iπ/63)^0.8`，中间强、两端弱；逐条细节为`0.35+0.65×noise(1.7tᵢ+0.13i)`。最终高度是：

`hᵢ = max(6, envelope(tᵢ) × spatial(i) × jitter(tᵢ,i) × 150 × collapse)`

中心附近对应约50.4帧以前，约1.68秒的历史；不能拿中间最高的峰当作“此刻声音最大”。另外，细节噪声含索引`i`，同一个历史时刻从右移到左时，既受到空间权重影响，也可能改变局部细节；这是美术化历史，不是保真音频波形。要展示可回听的真实幅值，应让历史样本身份稳定，再明确区分显示窗的边缘衰减。

### ３．３　为什么这份实现的停顿不会整排变平

**源码可见／数值复算**：第一段57结束，第二段80开始，完整间歇是57—79，共23个展示帧，约0.77秒。它短于3.36秒历史窗；旧句子仍在往左走。独立按上述公式复算，57—79各帧的最高条约86.94—103.04px，不接近最低6px。68帧即时包络已为0，但历史最高条约100.32px；对应抽帧仍有明显波峰。

因此可以说“停顿时最新端回到点线，麦克风呼吸停止、光标等待”，不能说当前实现“停顿时整排缩为点线”。原卡参数表把80—124标成停顿，实际上那是第二段说话。若原创目标就是整排停下，有两条不同路线：即时活动显示让整体受当前包络控制；历史显示保留旧峰，用新端空隙与明确状态告诉观众现在安静。选择其中一种并贯穿，不用偷偷清空历史冒充自然滚出。

两端空间权重接近0，所以最右一根即使读取现在，也始终被最低6px钳住。本实现只给“最右条且非静默”的条加辉光，这个条件实际上不会触发。要强调实时入口，可用独立输入标记，或重新设计最右侧权重；不能照抄一段从不显现的光效，然后声称样片已验证。

### ３．４　麦克风、地面光和波形不是同一个数值

**源码可见**：麦克风的两层呼吸圆跟当前`nowEnv`，半径增量为`8+(14+14k)×nowEnv`，透明度上限随层数降低；停嘴时两层都透明。提交后即时包络被强制设为0，不表示整段历史立即清空。

地面暖光取末12根条平均高度除150，再乘一次`collapse`；条高内部已经乘过塌缩，所以提交阶段有二次衰减，且受6px底线影响。地面光不是纯粹“当前音量”：它有末12槽的历史与空间加权，静默时也保留基础亮度。不要用这束光证明刚说出的某个音节。

舞台传入`breathe=0.4`，但当前亮场分支主光强度固定，呼吸变量只用于暗场主光。结尾仍有每2帧更新的颗粒与轻微历史条变化，不能把源码注释“暖光极缓呼吸”或“海报定格”直接当成实际完整行为。

## ４．转写怎样和声音并行，而不把画面变成逐字打字机

**源码可见**：第一行词槽起点17、22、25、32、40、45；第二行82、88、92、102、112。每词8帧完成透明度0→1、模糊10→0、上移0.22em→0，使用`snappy=(0.16,1,0.3,1)`。17或82是开始显露的帧，起始透明度仍为0；不能把“词到点”写成该帧已清楚可读。

每词出现3帧后，强调色开始以6帧线性沉到主墨色，即第9帧完成颜色归位；这是短时焦点标记。不要把整句保持强调色，让下一词没有视觉优先级。已完成句子的笔画仍需稳定，不能跟波形上下振动或每次新词都缩放整段。

尾光标只挂在最后到时的词后面。当前包络大于0.05时常亮，否则以每8帧切换一次显示／隐藏，完整周期16帧；提交后消失。光标是6px宽、0.8em高，靠负边距减少对行宽的影响。其计时参照最后词起点，不是独立的全局8帧循环；中文替换还要核对符号、行尾、换行与光标占位。

提示语先以低对比度占据上方，4—14显露，15—19线性消失；首词17开始出现，所以有短暂交叠，不是“首词前已经完全退掉”。标签6—18显露，与胶囊入场重叠；说话从15开始时标签尚未完全收束。原创应检查这些交叠有没有造成第一词被提示语盖住，不能只核对各自首尾。

**制作推导**：真实识别常会回改中间结果。教程介绍真实服务时，保留必要的修订与最终文本，不预设“每词都在发音起点准确出现”；这份预排转写只能用作明确示意。中文以真实词组、标点与呼吸断句分组，避免逐个汉字上浮。上一词还没可读就连续冒出三组时，先放缓展示或改分组，不追加模糊掩饰。

## ５．提交是一组有先后关系的变化，不是一声响后全部消失

| 实际帧段 | 变化与曲线 | 画面职责及风险 |
|---|---|---|
| 0—14 | 胶囊透明度入、模糊6→0、scale1.04→1，snappy | 建立输入主体，不能始终漂浮失焦 |
| 15—57／80—124 | 两段包络；转写各词独立入场 | 声音内容与收音活性并行，历史与当前分开读 |
| 126—129—135 | 提交钮scale1→0.82→1，分段线性 | 是3帧压下、6帧回原位，总9帧，不是3帧完成整次回弹 |
| 127—133 | 箭头退出，上移30、透明度退，exit | 旧操作身份先退出 |
| 130—138 | 对勾以overshoot落入：Y16→0、scale0.7→1 | 确认符号不表示服务器已送达 |
| 126—138 | 波形塌缩系数1→0.06，exit | 12帧数学区间不等于12帧均匀收小 |
| 128—150 | 转写参照372→330、scale1→0.72，swift | 原话保持身份，改变为已提交文本的视觉地位 |
| 132—142 | 气泡填色0→1、墨字→暖白、右下角64→18 | 文字对比需全程成立，不只看最终白字 |
| 140—152 | Sent行透明度入、从下16px回位，out | 结果标签在足够依据下出现 |
| 140—154 | 胶囊下移24、scale1→0.94，swift；麦克风变灰、监听标签退 | 录音结束，不把旧活性留在结果旁竞争 |
| 154—171 | 剩余18展示帧，约0.60秒 | 实际成片是否读完要另验，不把0.7秒注释当保证 |

**源码可见／数值复算**：`exit=(0.7,0,0.84,0)`很陡，129帧塌缩系数仍约0.9978，134约0.9087，137约0.4649，138才到0.06。峰高还受到历史继续滚动影响，不会严格单调下降。若希望观众看见“收走”，必须实际看末几帧的速度与气泡形成是否抢焦点，不能用“12帧”代替动态判断。

所有条先乘塌缩，再取最低6，因此波形没有缩到原高的6%后消失。系数小于0.25时条统一改成中性弱色；138帧仍可能有约7.11px的残条，视觉近似点线，而非全部严格6px。要绝对静止待机，需要单独定义待机信号，不是继续采样后称为冻结。

气泡底在同一个文字容器内：左／右外扩64、上下44，主圆角64，右下角渐变成18；跟文字共用0.72缩放，最终实际侧内距约46.08、上下31.68，主圆角46.08、右下12.96。容器按文字排版，不是一个预定宽高的大矩形；先换中文再实排，不能把气泡硬拉成与英文同宽。

**制作推导**：提交阶段保留原话的连续身份值得学习，但“文字飞进气泡”与“发送成功”是两层事。当前126帧是时间驱动，无指针、键盘事件、网络请求、失败或重试。若真实软件只支持停止录音／保存草稿，就把接棒画面设计成草稿与回听；不要为了复用勾和Sent字样制造服务能力。

## ６．计时和状态必须单独核查

**源码可见**：计时为`floor(max(0,min(f,126)/30−0.4))`，提交后固定，最后显示0:03。它把开始后0.4秒当偏移，记录的是截断后的经过时间，不是语音活动累计时长。两段说话窗合计86帧、约2.87秒，片头至提交则4.2秒；三者不是同一量。

当前JavaScript数值复算，整数显示变化在43、72、102帧；第一秒边界因浮点表示落到43，不能拿简单手算42作为像素级断言。原创更重要的是选对语义：录音总时长、有效发声时间、文件长度、播放位置分别用对应真实时间，标签不能混叫“说话时长”。

进入待机后，胶囊还保留0:03与勾，新一轮开始是否归零、按钮是否回到录音／提交入口，当前样片没有演示。单镜头止于结果可以成立，若下一镜继续录制就必须设计状态接续，不能把上一条的计时和成功符号留给下一条。

## ８．原创完整镜头：给封面第二版留一条语音评审

### ８．１　内容先确定：录音在评什么，而不是只让一句话飘着

**制作推导，未实现**：教程介绍“对当前设计留下语音意见”。教学句为：“封面先用第二版，〔短暂停顿〕把右下角的日期放大一点。”观众要理解三件事：意见针对第二版；停顿期间录音仍开着；最终保存的意见可以回听和核对，不代表设计已自动修改。

使用两张确有差别的封面设计作为内容：同一摄影主体与标题，第二版日期位于右下角。这里是教学内容设定，不是已经取得的真实设计、截图或授权素材。正式制作先拿到可用封面、真实输入音频与软件实际反馈，再决定录制、保存、回听的表现。若软件只保存音频不转写，就撤去实时转写或明确它是教程字幕，不能装作产品能力。

先画结果：主画面仍显示第二版封面，右侧是一条隶属第二版的录音意见，保留原句与真实音频长度，并有实际可用的回听入口。右下日期尚未变大。这样看完结果便能区分“意见已记录”和“设计已返修”，下一镜才有真实操作可接。

### ８．２　画面要有设计对象和可阅读的关系

初稿按1920×1080：工作窗`(96,100,1728,880)`。左侧主封面`(160,220,880,550)`，以教学1600×1000封面为例等比0.55完整显示，实际素材比例不同就重算，不强拉。两版缩略图在`(160,820,144,90)`与`(332,820,144,90)`，第二版用一圈细而明确的选中框，版本名放在下方；缩略图只负责身份，主封面承担日期位置与画面判断。

右侧内容区x1120、宽608；标题“第二版的语音意见”与当前版本对应，避免漂在画布中央像没有归属的广播。转写从y300开始，以48—52px、约1.28行高、最多三行作初稿；按“封面先用第二版，／把右下角的日期／放大一点。”预留语义行，实际中文实排后调整，不为保留三行随意改原话。字幕占位不能盖住左侧日期。

录音控件初稿`(1120,640,608,112)`：两侧各20，麦克风64、提交64、计时56、三处间隔16，波形剩`608−40−64−64−56−48=336px`。若用40根、gap4，条宽`(336−39×4)/40=4.5px`；这只是依显示宽度推出的起点，不受原卡“少于40”的表格绑住。若压缩观看后过细，减少根数或扩大区，不继续塞64根。

美术采用冷白工作面、低饱和蓝灰分区、深墨字，单一青绿表示录音与选中；让暖色摄影主体仍是封面的内容主角。窗口边缘一条淡灰蓝内边，控件使用实体浅面与贴地小影，取消赤陶消息大底和整片暖光，避免意见控件与封面争夺色彩。真实产品既有样式优先；这套是可检验的教学初稿，不是替它发明一套软件皮肤。

静帧先验：第二版主图、右下日期、右侧意见归属能够在同一视野中辨认；看不清时调整版面或拆镜，不把所有物件分别推近一遍。画面最亮的区域属于封面主体或当前输入，而不是四个按钮同时发光。

### ８．３　先建立对象，再说话；让停顿成为理解点

| 镜头阶段 | 连续画面与焦点安排 | 必须保留的事实 |
|---|---|---|
| 建立当前版本 | 两版缩略图与第二版主图同屏；选中状态稳定 | 两版身份清楚，尚未录音或改图 |
| 开启输入 | 真实点击录音入口；右侧出现录音状态与经过时间 | 权限或启动延迟按真实产品，不能跳过后伪称立即可用 |
| 第一句 | 听见“封面先用第二版”，相应词组显露；主封面保持 | 波形取示范输入，教程解说此时让位 |
| 短暂停顿 | 新端归低、当前状态仍是录音；已有词组稳定，尾光标等待 | 历史可以继续移走，不能误标停止或提交 |
| 第二句 | “右下角的日期”可读后，编辑性细线短暂指出真实日期区域 | 这是指示意见对象，不是软件自动理解并执行 |
| 说完与核对 | 收音结束后按真实方式停止，保留文字核对或回听 | 停止不等于保存，输入原文不被美化改写 |
| 保存意见 | 真实触发保存／发送，按实际反馈形成意见条目 | 失败或处理中不能提前出现成功勾 |
| 结果接棒 | 同一版本的意见条目稳定；入口可回听，封面日期仍原样 | 有依据才说已保存，不说设计已修改 |

示范输入开始后，录音条只承担低位状态，大字转写取得主要阅读权；提到日期时由主图对应位置短暂接棒，波形不再加一道大幅缩放来抢焦点。指示线沿内容边缘出现，避免穿过人脸、标题或日期本身；指示后收掉，结果帧仍是清楚的封面与意见关系，不是一堆批注残影。

此处优先采用滚动历史，最新端保持足够显示权重，并以独立录音状态表达当前是否安静；不照搬两端为零的山丘权重。历史窗先以约1.6秒试排，40槽间时间差约`1.6/39≈0.04103秒`，在30fps下约1.23帧／槽。它与像素间隔分别控制时间和密度，不能因删了条数便意外把时间窗缩短。所有强弱、停顿和总长最终来自真实输入，不能先写57—80再找声音硬凑。

### ８．４　让保存后的构图证明关系，再进入真实返修

实时转写若确实由软件提供，保存后仍用同一段文字与同一输入身份，收进右侧意见条目；可借鉴共同容器缩移，但不强行照抄0.72。原文字初稿52、结果正文仍需40—44，则缩放约0.77—0.85只是候选，先以最终可读尺寸决定结果框，再反推运动。控件退后让出空间，版本名、真实长度、播放入口稳定，监听灯与光标退出。

若结果条目有波形预览，改为这条音频的静态历史，并把播放头与回听时间同源；未播放不继续跳，播放时不让BGM驱动录音条。展示一次实际回听，定位到“日期”附近，对照主图右下角，才能证明声音、转写与反馈对象一致。没有音频、没有实际入口时只能交付设计示意，不得称回听已验证。

下一镜进入真实编辑：选择日期文字，改变字号或文本框，保持封面摄影、标题和第二版身份。把“意见保存”与“字号改变”之间留出明确操作，不能借气泡收缩直接换成返修后封面，让观众误以为语音自动改了图。若教程到记录意见即结束，就停在可回听的完整结果，不额外拼三个无关功能卡。

### ８．５　声音、节奏和实际内容怎样一起验

示范人声出现时，教程口播暂停或明确让位；波形只跟示范轨，配乐下让，不在每词入场加提示音。按录音入口可以有一次轻反馈，保存完成按真实语义有一次短反馈；停顿本身保留安静，不用升调音效填满，观众才能感到系统仍在等下一句。

不先把这句中文硬压进原例5.73秒。先使用最终输入音频的实际长度与词组时间，再安排启动、停顿、核对、保存、回听及结果阅读。转写如果服务存在延迟就如实表现；若只是教学字幕，应与产品区域的真实文字有可辨认区别。节奏目标是能跟着听、看清所指日期并理解提交边界，不是让按钮、波形、字幕、指示线每一帧都动。

## ９．失败、修正与可观察通过条件

| 看到的失败 | 先修什么 | 通过时能看见／听见什么 |
|---|---|---|
| 每帧竖条乱跳，重复渲染形状不同 | 固定时间采样与确定性，分开随机与音频依据 | 同一时刻可复现，相邻帧连续 |
| 没人说话还随配乐起伏 | 选正确声源，分开示范输入和解说／BGM | 只在输入对应时间有当前活动 |
| 已停嘴仍有峰，就被标成“同步错误” | 先判断是历史还是即时显示 | 新端安静、旧峰迁移，与状态一致 |
| 声音在右端却一直没有可见响应 | 检查端点空间权重与最低条高 | 新输入的反馈位置清楚，不等1.68秒才在中间显著 |
| 旧波形一路变形，却称精确音频历史 | 取消索引相关扰动或标明美术化 | 回听位置与历史采样身份能对应 |
| 首词与提示语叠在一起 | 调整提示语退出、字槽或入场时点 | 先知道入口，再能清楚读第一词 |
| 逐词出现导致整句反复左右跳 | 预留语义槽、稳定起笔与换行 | 视线能沿句子读，不追着中心跑 |
| 新词全都赤陶色，旧句也一直闪 | 限制强调持续时间，停止旧词运动 | 当前词取得短时焦点，旧句保持可读 |
| 条挤满胶囊，计时被顶走 | 按真实内宽计算条数、gap与固定区 | 按钮、时间、波形各有安全间隔 |
| 按钮已成勾，听感仍在录，标签也说监听 | 调整结束输入、确认与待机的重叠 | 观众知道何时停止、何时保存 |
| 塌缩几乎不动，最后两帧猛缩 | 看实际曲线和峰高，重排焦点 | 正常速度能感到收束，不像一帧替换 |
| 声明待机静止但点线还细微起伏 | 给待机独立固定信号 | 需要稳定时真正稳定，而非仅颜色变灰 |
| 气泡白字过早、底色太淡 | 核对填色与字色交叠期间的对比 | 中段也读得清，不只有最终帧好看 |
| 0:03被当成有效发声总长或文件长度 | 统一时间口径与实际音频数据 | 数字、标签、回听进度同义同源 |
| 一条输入被展示成执行指令成功 | 分开记录、发送与实际操作结果 | 保存的是意见，原封面尚未自动修改 |
| 每个控件都像漂亮示意，却认不出评谁 | 恢复主图、版本与意见的归属构图 | 看到结果就知道哪句话针对哪个对象 |
| 静帧很好看，正常速度读不完或听不清 | 联合观看／试听真实输入与下一镜 | 语音、文字、焦点、停顿和结果都能跟上 |
