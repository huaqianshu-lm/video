# 分段控件切换主体：用特写讲清决定，再回到内容证明变化

这个技法把一个二选一控件拍成镜头主体：先建立旧状态，指针进入并按下，白色滑块移向另一段，新身份随后显现。它擅长让观众看清“从A切到了B”，但不能独自证明B做了什么。教程应在特写之后回到实际内容，让模式改变产生可见后果；只有胶囊、指针和图标，再精致也只是微交互演示。

来源：[Shotcraft 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/main/references/shots/interaction/segmented-thumb-hero.md)／[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/segmented-thumb-hero.mp4)。本文是独立设计研究与原创演绎，不是原卡翻译。以下区分**原卡给定**、**源码可见**、**抽帧可见**和**制作推导**；main实现未与早期固定提交逐字同版核验。

## １．先决定切换的是模式、表示，还是执行动作

**原卡给定**：用超大分段控件宣告模式切换，强调光标→按下→滑块→图标的因果。**源码可见**：标签是Prompt与Film，开始选Prompt，之后选Film；没有把一句提示词变成真实影片的处理过程。笑脸场记板表示新模式身份，不是生成成功证明。

| 当前内容 | 本技法适合承担 | 不能用控件替代的解释 |
|---|---|---|
| 二选一模式 | 说明当前从哪段切到哪段 | 新模式实际提供什么能力 |
| 同一文档的编辑／预览 | 确认表示方式改变 | 内容是否保存、正文是否被修改 |
| 同一内容的列表／网格 | 表明当前浏览方式 | 对象身份、数量和排序是否保持 |
| 操作需要额外应用或确认 | 展示暂时选中的条件 | 应用成功或提交完成 |
| 自动介绍两个状态 | 通过取景与状态变化建立对照 | 用户确实点击过，或系统已响应真实请求 |

**制作推导**：指针能交代交互来源，涟漪能增强按下可见性，图标能帮助确认身份，但这些不是所有镜头都必须配置的四件套。触屏可以用真实触点，键盘可以用实际焦点反馈，自动演示可以明确是讲解；不能把“没有涟漪就不算点击”“图标必须带笑脸”变成通用规则。

适用边界是短标签、简单决定、清楚的两个终态。三个及以上选项、不同长度的复合条件、需要逐项比较的解释，不宜只把8帧位移横向拉长。若实际产品没有分段控件，也不能为了采用这个技法改造软件操作；可用明确的教学示意，或选择真实控件的拍法。

## ２．先设计完整新状态，特写才知道该把注意力交给谁

### ２．１　样片完成态的主次

**抽帧可见**：大面积浅色环境中，横向凹槽居中；右侧白色凸起面承托Film和小场记板，左侧Prompt退灰，指针留在右下附近。焦点来自白滑块、近黑文字、图标与阴影的共同组织，不靠背景不停扫光。两侧负空间留足，控件是这一镜唯一明确主体。

**源码可见**：控件1080×220，位于画幅中央，名义左上为`(420,430)`，圆角110。16内缩，名义两段各524，滑块高188、圆角94；左右标签72px、字重650、字距−0.025em。图标78，图标与文字之间gap22。这里是原生1920×1080坐标，没有480设计舞台，不要再乘一次4倍。

这张静态完成态可以宣告“现在是Film”，却不能解释该模式如何工作。**制作推导**：把这一镜定义为操作特写或章节内的决定瞬间，再安排内容镜头接管。若下一镜只是再出现一个Film标题，视觉证据没有增加；应展示当前题材真正变化的内容、结构或操作范围。

### ２．２　特写的造型不等于控件越大越好

宽轨道提供明确的左到右路径，短词和大字让一次小位移可读。若换成长中文标签，先排两段的真实文字、图标和间隙，保证新旧图标交接时都能容纳，不把文字压窄。原卡“小于600px就读不出重量”是此片的特写判断，不是所有视频控件的最小宽度；实际观看距离、构图和内容决定比例。

需要拍真实界面时，先有页面中的位置，再推近同一控件；需要独立宣告时，可以让控件独占舞台。二者都成立，但同一次点击不要在页面里演一遍、切到特写又演一遍，让观众误以为操作了两次。下一镜继承已选状态，不重置回旧态。

### ２．３　边框与内部坐标要按实际盒模型核对

控件使用border-box，1080宽中包含左右1px边框和各16px padding，真正内容宽是1046；两个标签仍声明各524，合计1048，默认flex收缩时各约523。源码绝对定位滑块的宽度却保持524。它们名义共用“半宽”，不代表实际所有边界完全一致。

按这段DOM的默认flex与绝对定位规则推导，滑块初始左缘约437、末态左缘约961，末态右缘1485；标签内容范围约437—1483。竖向滑块从约447到635，而标签中心仍在540。这里是盒模型推导，未用浏览器实测；不能把一两像素偏差写成抽帧测量。**制作推导**：原创应从同一内部有效矩形求两段、滑块与点击坐标，避免边框扣一遍、padding又混用一遍。需要检查的是终态、双边拉伸的中段及阴影余量，不只看大致居中。

## ３．轨道、滑块、字形和光线怎样形成一套美术

### ３．１　凹槽与凸起面承担不同材料角色

**源码可见**：轨道渐变`#e2e2df→#e9e9e6`，边框为近黑9%，上方内阴影`0 2px 5px`、8%，底部有1px白色70%的内亮边。它像浅凹槽，不是一块与白滑块同等悬浮的卡。

滑块白到`#fbfbfa`，顶部1.5px内高光，外沿1px低对比轮廓；近影下移2、模糊4、8%，远影下移12、模糊28、扩展−8、20%。白面亮，阴影偏冷，轨道自身偏暖灰，使选中区即便不染成品牌色也能被认出。

**制作推导**：先建立上下表面的层次，再决定装饰。轨道、滑块、指针三者不能都配同样的大软影，否则画面会变成三块漂浮物。浅色画面仍需要边界，深色风格则要重新设计暗面反差，不能把整张图做反相就算新的材质。

### ３．２　文字是状态，图标是身份补充

近黑来自`G.ink1=#17181c`，未激活文字`#8e9097`。字体沿用系统无衬线栈，650字重可能受实际字体支持影响，不能声称任意环境都会得到完全相同的字形。中文先确认字体覆盖与实际粗细，避免回退字形混入。

旧图标是对话气泡，新图标为略倾的场记板，图形均使用一致的近黑线条。新图标眼睛和笑脸用`#5b63d3`，呼应涟漪与背景极淡强调色；不是整枚图标都变紫。**制作推导**：图标的形状应帮助识别模式，而非仅作为“切换奖励”。编辑／预览可以用代码符号和页面图标，不需要为了保留表情而给每种软件功能加笑脸。

### ３．３　环境给主角承托，不追加一个抢戏的运动

背景使用`Backdrop light`：浅灰纵向渐变、主光中心50%／30%、另一处低对比靛蓝余光、默认0.14暗角和0.05颗粒。光斑漂移默认0，没有缓慢环绕相机。控件下方另有1400×260的白色接触光池，左260、上580，随浮入显现；它不跟随滑块横移。

轨道外影由浮入弹簧驱动，下移30→14、模糊80→44、透明度0.32→0.20，扩展固定−18。原卡提到的“24→12px”不是当前演示的实际轨道影子。浮入有过冲时这些数值也略越过终值，不能说严格线性收束到第18帧。

**制作推导**：页面接棒后，环境光应让位给真实内容，不要保持一个高亮光池让已缩小的控件持续成为焦点。颗粒是动态表面，本镜默认每两帧变化；末尾控件看似稳定不等于逐像素静帧，正常速度是否闪烁仍待观看。

## ４．把实际时间链拆开：8帧只是主滑动

| 状态 | 源码实际时点 | 导演需要保留的关系 |
|---|---|---|
| 控件建立 | 从0起弹簧浮入，下方200到最终位置，同时显现 | 是弹簧函数，不是18帧后硬钳在终点 |
| 指针接近 | 20—44，24帧outCubic | 从真正画外到右段，先有目标再按下 |
| 到位辨认 | 44—48之间 | 指针不是仍在高速经过时直接触发 |
| 按下／释放 | 48到51压至0.86，51到55恢复 | 指针压缩与滑块可部分重叠，不互相替代 |
| 涟漪 | 48—60的12帧进度，严格0＜进度＜1才绘制 | 第48帧本身无环，49首次可见，60已移除 |
| 主滑动 | 52—60，8帧 | 发生在按下后4帧，边缘使用两条不同曲线 |
| 旧图标退出 | 52—58，6帧 | 视觉缩小，布局占位并非连续缩小 |
| 标签色变 | 跟主outCubic进度 | 新字在56帧已全深色，早于60到位 |
| 新图标进入 | 从60起算弹簧 | 60尺度为0，61才真正可见，并有后续过冲 |
| 滑块到位后回弹 | 60—66 | 双边同向短位移，不是滑块再次增宽 |
| 新状态保留 | 66以后仍有图标弹簧尾段与颗粒 | 不能把60以后50个展示帧全叫完全静止hold |

**源码可见**：浮入参数damping14、stiffness120、mass0.9，没有duration或18帧钳位。用本项目现有Remotion纯函数复算，18帧仍有约−0.83px位置偏移；整数帧11附近上冲约11.42px。此复算说明“0—18”是注释性节奏概括，不能替代实际函数，也不保证与上游环境逐帧完全一致。

新图标参数damping10、stiffness220、mass0.6。同样复算，61尺度约0.165，65约1.2085，70约0.9619，80约0.9998；还会有很轻尾振。原卡仅写damping／stiffness，mass同样影响手感，不能遗漏。实际是否稳定可读应看成片，不用“理论弹簧还未精确等于1”无限延长镜头。

**制作推导**：按压、主滑动、旧身份退出、新身份确认分工不同，允许重叠，但要有一个主要运动焦点。口播在讲新模式时，新名称和身份应已可读；不能到第60帧就立刻切走，只留下还没出现的图标。8帧是本案例的研究起点，实际帧率、控件尺寸、真实软件反馈与Timeline仍需重新安排。

## ５．滑块双边、色变与模糊：保留实际机制，也保留风险

### ５．１　不是一块刚性白矩形平移

设`q=clamp((f−52)/8)`，名义段宽W524、内缩P16。后缘进度`T=1−(1−q)^2`，前缘进度`L=1−(1−q)^4`；左边`P+WT`，右边`P+W+WL`。宽度为`W[1+(1−q)^2−(1−q)^4]`，中段先增宽再回到524。

连续最大值发生在`(1−q)^2=0.5`，宽655，增加25%；实际整数帧54宽约652.95，增加约24.61%。源码注释“拉长约10%”与公式不符。**抽帧可见**：54帧白面明显跨在两个名称之间，不是固定宽度移到一半。

**制作推导**：拉长能提供柔韧感，也会让两段暂时共享一块白面。如果内容语义要求绝对互斥，不要把中段当成“两项都选中”；真正状态由已确认的目标决定。可保留更克制的形变，或使用刚性滑块；调整后说明当前设计选择，不把原例夸张拉伸当成所有控件的品质要求。检查影子与轨道边缘，不让拉长面穿出控件却没有合理裁切。

### ５．２　到位后的1.5%是公式系数，不是实测回弹幅度

60以后，设`u=clamp((f−60)/6)`，两边同时加`0.015W×sin(πu)×(1−u)`。相同位移不会改变宽度，只让整个滑块略向右再回。整数帧62最大偏移约4.54px，66回零；不能直接写成“横移7.86px”或“整体放大1.5%”。

文字颜色使用另一条主进度`M=1−(1−q)^3`，新段激活度`clamp((M−0.2)/0.6)`，两种颜色按RGB通道连续插值。由于M到0.8时已全激活，第56帧新标签已全近黑，而滑块边缘还没最终归位。**制作推导**：连续色变表达过渡，不一定是业务生效时点；实际软件何时更新内容要另按真实逻辑定，不能从字变黑倒推出请求成功。

### ５．３　模糊跟的是名义中心进度，不是每个边缘的真实速度

速度用主outCubic位移的`f±0.5`中心差分求得，强度0.06、标准差上限6，低于0.35时不加滤镜。按本片数学关系复算，52—58启用，快段触及上限；没有对前缘、后缘与回弹分别做物理快门积分。

只有白滑块放进速度模糊层，标签在独立z2层，涟漪在z3层。**制作推导**：白面可以在快段略带拖影，关键名称仍清楚；把整控件连同字一起模糊，会失去这个分工。滤镜外框、阴影和圆角需一起审，不能只检查滑块几何。完成态不继续挂一层模糊制造“质感”。

## ６．指针尖端、涟漪与图标回流怎样真正对上

### ６．１　指针定位的是尖端，不是SVG左上角

**源码可见**：SVG130×150、viewBox26×30，路径尖端`(4,2)`换算为局部`(20,10)`；从SVG左上`(2020,1200)`移动到`(1210,590)`，未按压时尖端在`(1230,600)`。起点整只在1920×1080画外，轨迹为同进度的直线，没有弧线。

指针按压绕15%／10%原点，即局部`(19.5,15)`缩放。压到0.86时，尖端约变为`(1229.93,600.70)`，所以源码的“涟漪精确锁尖端”仅对未缩放的名义尖端严格成立。偏差很小，不应夸大成肉眼必见错误；但改指针尺寸、原点或形状后必须重新计算，不能仍复制这组偏移。

涟漪相对轨道内边缘坐标`(809,169)`，补回轨道左上和1px边框后回到`(1230,600)`，还随轨道自身的极小浮入尾振变化。它不跟随横移滑块，z3高于标签和白面，指针作为后绘制的独立层覆盖其上。若后续有相机变换，屏幕坐标、页面坐标和指针尖端必须经同一映射；不要只改`left/top`试到看似接近。

### ６．２　涟漪确认按下，不持续抢正文

半径130×涟漪进度，最大直径接近260，3px强调色边；透明度`0.9×(1−进度)`，另有很弱的外缘色。它在固定点击点扩散，不是白滑块的拖尾。第48帧严格没有环，49才出现，60移除；当前片不应在指针尚未到位就先扩散。

原演示没有让指针退出，末帧仍留在Film下方。**制作推导**：特写里它可保留操作来源，教程回到正文后则要避开阅读；可在按压与环收清后移到空白处或按真实操作退场。没有涟漪也能用真实按压与状态反馈交代点击，不强制给所有软件加同一种环。

### ６．３　原卡说连续回流，实际布局宽度却是阈值切换

旧图标视觉尺度从52到58按inCubic缩到0，但占位宽写成`scale＜0.05 ? 0 : 78`，所以52—57仍占78，到58突然归零。新图标60尺度0，占位0；61尺度约0.165，已经大于0.05，占位立刻跳到78。它不是宽度随scale连续变化。

两个span仍在，gap22没有随占位归零，所谓“幽灵缝”没有完全消失。按当前居中flex组推导，单次78宽的增减可让文字中心移动39px；新图标才刚可见时就分到完整宽度，Film字会先让出位置。**抽帧可见**：58／60两端均无可见图标，61新图标很小但文字已重新排布，65／66才形成明显的新身份。

**制作推导**：要保留连续回流，就把图标槽、实际图形尺度和间隙分别设计：槽宽按受控进度连续变，间隙也跟随，整体词组重新求中心。弹簧可用于图形，不必把弹簧过冲原样用于布局宽度，避免文字来回挤动。若选择固定槽，始终预留即可，但接受两端存在图标空位的版式；不能一边使用阈值跳变，一边宣称已经实现自然连续回流。

## ８．完整原创镜头：源码切到预览，证明内容没被改写

### ８．１　从教学问题确定结果，而不是给Film换个词

目标：“Markdown标记怎样变成可阅读的排版？切预览会不会改掉原文？”采用明确的教学编辑器示意，不冒充某款已核验软件。两段是“源码／预览”，切换只改变表示方式，文稿字符串保持同一份。预览不是保存、发送或发布。

使用以下可完整核对的小文稿，四个语义块为标题、强调段、两项列表、文件名段：

```markdown
# 发布说明

**重点**：先预览，再发送。

- 核对标题
- 检查段落

文件名：`release-notes.md`
```

最终画面必须看见：井号成为标题层级；双星号不作为正文显示，重点二字变粗；两行短横线形成同一列表；反引号内文件名成为行内代码样式。字符标记不显示是渲染语义，不是删除源码，更不是AI重写。不能在预览里偷偷增加总结、替换句子或把两项列表合成一项。

### ８．２　先画完整文稿，再找控件特写

1920×1080初稿，连续编辑工作区`(160,140,1600,760)`，顶部工具栏约100高，正文从x240／y300阅读，右边界1680。背景冷暖灰有轻层次，正文面偏暖白、石墨色字，分隔线低对比；只给当前表示和必要标记一处克制蓝色，不把每个Markdown符号染成不同霓虹色。

源码正文初稿36px，等宽英文与覆盖中文的实际字体配合，行盒64，八行含空行约512高，落在y300—812。左侧行号可淡化辅助定位，但不在预览中继续占一个代码栏。预览标题初稿64px／偏重、上300；强调段上420、36px／行高约54；列表两行上520／580、36px，文件名段上700、34px，代码片段仅用浅底与等宽字。真实字体与行盒仍需实际渲染，不把这些初稿值当成项目默认值。

两态都用同一文稿标题身份，外壳不换成另一张卡；正文没有各自飞入的悬浮底板。完成态靠排印层级、段落间距、列表缩进与代码片段的局部表面获得设计感。若静态预览看上去只是四行同字号黑字，先修排版，不用弹簧补救。

控件原生位置`(1180,160,480,72)`。把“内缩6”明确定义为从轨道外边到共同有效矩形的距离，得到468×60，两段各234，滑块从`(1186,166,234,60)`移到`(1420,166,234,60)`，目标中心`(1537,196)`。边框已经包含在这套矩形约定中，不再重复扣一次；两个标签与滑块同源。初稿文字32px、图标16、间隙8，完整词组先按真实字体度量。

### ８．３　推近同一个控件，不把它复制成另一个舞台

特写以控件中心`(1420,196)`为取景锚，放大2.25倍，送到屏幕中心`(960,540)`。映射为`screenX=960+2.25(x−1420)`、`screenY=540+2.25(y−196)`；控件变1080×162，文字32变72。高度不同于原样片220，因为这里从实际页面比例推出，不强行变形去凑原卡。

点击选在预览段内、文字下方的`(1537,218)`，特写屏幕位置约`(1223.25,589.5)`，仍在滑块有效矩形内。指针先按实际SVG尖端求屏幕位置，再处理页面与相机映射；不要把源例1210／590的左上角直接复用。指针可留在独立屏幕层，保持观察尺寸，镜头推近时不跟着变成一把巨大箭头。

页面推近时正文会自然出画，不需要把原正文逐项淡走；拉回时同一工作区再进入视野。外壳、控件和正文共用相机映射，不能控件一套缩放、标签一套缩放、背后的旧副本又没遮掉。明确只是一次操作，状态不因切镜重置。

### ８．４　完整动作链与焦点交接

| 状态 | 画面与动作 | 观众新增理解 |
|---|---|---|
| A．建立原文 | 完整编辑区展示标题、标记、两项列表和文件名；当前源码段选中 | 明确处理的是这一篇原文，不是泛用切换演示 |
| B．提出问题 | 用短句指出“看排版，切预览”，保持原文身份 | 知道为什么要操作 |
| C．推近控件 | 相机围绕同一控件收紧，旧模式保持 | 视线到操作目标，没有重复点击 |
| D．按下预览 | 指针到空白点击区，局部压缩与一次反馈 | 先操作，后控件改变 |
| E．滑块切换 | 两段共用几何，滑块移到预览；旧身份退让，新身份成立 | 当前是预览模式，不等于保存完成 |
| F．确认收清 | 控件落稳，图标／间隙／指针反馈结束，指针避开阅读 | 给后面的内容留一个稳定接点 |
| G．拉回同篇文稿 | 相机回到完整工作区，预览已按同一字符串形成 | 看到的变化属于同一篇内容 |
| H．查三种排版证据 | 标题→粗体与列表→行内文件名依次取得阅读权 | 标记改变表示，不是系统增删内容 |
| I．下一镜 | 如需编辑，明确回源码改一处并再次预览；或停在完整预览结束 | 阅读检查、修改、保存与发布分开 |

控件反馈可从原例8帧主滑动作为研究起点，按真实软件和实际口播重新决定；不要求照搬25%拉长。原创若保留柔韧，只给白面克制形变，文字不拉伸。图标槽与间隙连续交接，图标自身可以有轻微落定，但不让弹簧把整组字反复挤动。

真实软件若切换后立即重绘，录屏如实保留；教学示意可以在特写中完成模式更新，再通过拉回揭示结果。不要为填充“处理过程”安排加载、扫描或AI生成，渲染Markdown不等于调用外部服务。

### ８．５　预览不是一堆内容依次入场，而是同一文稿的新表示

拉回的完成态先整体成立，之后用局部对比引导阅读。标题先取得焦点，旁侧可短暂对照小范围源码`# 发布说明`与已成形标题；核对后让标记提示退出，保留标题。重点二字只加强原有字重，列表用共同缩进与两项数量说明关系，不再给每项套独立卡。

文件名保持`release-notes.md`，代码片段的底色不扩成一个抢戏按钮。所有小范围对照都来自同一字符串和明确语义块；长文稿时只选当前需要解释的两个或三个特征，另镜头继续，不靠缩小到整篇塞满。

源码到排版的字形并非必须逐字符飞行。井号、星号、短横线与反引号有语法作用，不能把它们变成装饰碎片四处飞散，好像源文档被删除。需要连续对应时，可用稳定的段落定位或局部叠合建立关系，再让渲染版接管，不伪造两种排版每个字都能数学原位吻合。

### ８．６　镜头中段、声音与最终阅读

推近、滑块运动、拉回、正文检视分阶段主导。滑块跨中线时，相机先保持稳定，不让页面同时倾斜、字色闪动、图标又大幅弹跳；涟漪收清后再拉回，避免点击环在页面和屏幕坐标间漂移。回来后指针移到留白，正文不再随浮入弹簧轻晃。

原生控件480宽，近景1080宽；拉回途中无论缩放多少，滑块都保持预览段内同一归一位置，不因换取景重新从左走到右。正文的工作区身份、原文内容和两项列表数量一直对应，不能切成另一张更好看的示例稿。

声音可在真实按下时用一次短触感，在滑块落定时轻收；图标不再配第二个更响的奖励音。拉回和正文阅读让口播占主位，解释“内容没有改写”时完整预览已稳，不继续给每行配whoosh。声音属于设计建议，本轮没有制作或试听。结束时应能复述当前模式与至少一个排版变化，不能只记得滑块弹得好看。

## ９．可观察失败、修正与通过条件

| 失败画面 | 优先修正 | 通过时应看见什么 |
|---|---|---|
| 控件精致，却不知道切换后有什么变化 | 先设计新模式实际内容与接棒 | 完成态能指出至少一个真实变化 |
| 指针路过，滑块先动，按下后才补环 | 统一进入、按压与状态时点 | 操作与响应顺序清楚 |
| 圆环跟着白面走 | 点击点独立定位，经相同坐标映射 | 环留在实际触点，白面自行滑动 |
| 一边写拉长10%，一边实现25% | 以边缘公式和中段画面核对 | 数值描述与实际宽度一致，形变不过度混淆选择 |
| 60就切走，新图标未可见 | 从实际可读状态重留窗口 | 新名称和身份先成立，再接下一镜 |
| 旧图标缩小但字突然跳，新图标很小就挤开字 | 分开设计图形尺度、槽宽和间隙 | 两端和交接中段词组稳定，不留阈值跳变 |
| 白面到边缘露出不一致内缩 | 两段、边框、滑块共用内部矩形 | 头尾与中段均不碰撞或露缝 |
| 框拉伸时文字也横向变胖 | 白面与标签独立层 | 名称字形不变形，模糊只作用在该作用的层 |
| 大指针压在新标签上直到阅读结束 | 移到空白或按真实操作退出 | 新态名称与内容清楚可读 |
| 到18帧就称浮入完全结束 | 看实际弹簧、读取与可见偏差 | 不用注释代替实际稳定判断，也不追求无意义数学静止 |
| 页面和特写各点一次 | 连续继承同一状态与相机关系 | 观众只理解为一次切换 |
| 预览多了句子或少了列表项 | 核对同一源字符串及语义块 | 文稿内容、名称和列表数量保持 |
| 控件选预览，却配保存／发布成功 | 区分表示、持久化与业务动作 | 每一项完成声明都有对应操作和证据 |
| 技术全对，拉回仍是一页平字号字块 | 先修静态排印、层次与负空间 | 暂停完成态也能清楚阅读结构 |
