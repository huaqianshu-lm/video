# 协作光标群演与真实编辑接棒

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/interaction/collab-cursor-moves.md)、[CursorCastEnsemble](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/interaction/collab-cursor-moves/CursorCastEnsemble.tsx)、[cast-ensemble 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/cast-ensemble.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 在场感与协作证据是两件事

多枚具名光标可以表达团队在场，但漂移不能证明多人同时编辑、权限正确或内容已同步。真正的协作镜头应至少有一个明确贡献：谁修改了什么、别人看到了什么。若只是五个名字围着空白卡飘，视觉活性很高，信息仍然为空。

## 2. 先排好白板和主卡

原例瓷白点阵画布，中央宽白简报卡，两侧较小便签斜放，近便签影更实、远便签稍虚，右上头像组与名牌颜色对应。中央标题88px黑字、眉题小等宽、底部作者与进度细节形成字阶，便签不能和主标题同样大。

五人各一色，在名牌、头像、便签作者标识中始终一致。色彩是身份，不等于蓝色都是设计师、绿色都是负责人。主卡周围给光标与名牌预留路径安全区；名牌比箭头占用更大矩形，不能只检查箭头尖是否离开正文。画布点阵低对比，主卡阴影柔和，避免将名牌做成五团霓虹。

## 3. 入场、驻场、编辑与围观

原例156f，延迟2/7/11/16/22f，spring15/80飞入，名牌晚10f出现，头像另在delay+8f弹入。原卡“头像同帧”是身份响应概述，不是每枚头像与箭头同一帧出现。

| 通道 | 准确实现 | 设计关系 |
|---|---|---|
| 漂移 | X双频.055/.021rad/f，振幅40/26；Y.047/.017，32/20 | 各人相位不同，确定性近似人手，不是真实用户轨迹 |
| 介入 | 飞入后20f起12f渐开漂移 | 不让刚落位立刻反向摇摆 |
| 打字 | f48起，1.6–2.4f/字，空格额外.9 | 使用固定种子，文案变化重算结束时刻 |
| 编辑者 | 行内零宽锚点承载箭头偏移(12,−8) | 换行随浏览器排版，不另按字符数估x |
| 围观 | f98起28f聚拢，保留25%漂移 | 聚拢目的地不能压住正文、眉题或进度 |
| ready | 源码固定106起8f | 换句后应与真实输入完成和任务状态绑定，不盲用固定常量 |

编辑者打字期间手稳，其他人让出当前行；输入后光标可继续小幅活跃。箭头、名牌和插入点同一缩放世界，屏幕外的工具栏可以另层固定。多光标的共同汇聚只表示关注焦点，不代表所有人点了确认。

## 4. 官方观察

16幅可见五枚不同色身份入场，一枚粉色光标跟随主标题输入，文字换到第二行时箭头也跟着下移，其他光标在卡片外围。进度和Ready是演示设计状态，不能作为真实多人完成的证据。未正常速度观看或试听，抽帧不证明漂移自然、名牌始终不挡字。

## 5. 原创制作推导：一人提出修改，另一人落实

内容目标是“评论与正文修改保持位置对应”。先做最终画面：同一篇真实文档的修改段与一条评论同框，两名贡献者身份明确，一人提出条件、一人修改，不需要五人凑热闹。

主卡换成实际文档局部，评论占一侧窄栏，正文主段落获得最大面积。提出评论时，该人的箭头停在具体句尾，名牌退在空白侧；编辑者沿同一插入点补上遗漏条件。其他协作身份若无动作，只保留小头像，减少无意义漂移。

修改后保持新旧条件可核对，评论作者的回应必须是真实操作或清楚标注的示意，不能自动把围观当批准。下一镜沿修改句进入完整上下文，说明这次协作如何避免误解，头像和名牌退出主阅读区。

## 6. 路径审查与失败修正

- 名牌扫过主标题：按箭头+名牌联合包络检查整个sin周期和聚拢段，重设home/gather或限制幅度。
- 换行后箭头还在旧行：改用行内锚点；中文换行与标点避头尾规则需实际字体排版验证。
- Ready早于最后一字：计算真实TYPE_END，状态应从业务事件来，不按源例106拍死。
- 五个光标都抢戏：明确一个编辑主角，其余作为身份背景，取消无任务的共同点击。
- 颜色中途变了：统一身份映射，确保头像、便签和名牌同源，不能按组件独立随机色。

通过证据是具体贡献可辨、身份连续、输入点准确、正常速度下名牌不遮挡、下一镜能核对真实修改。氛围层不能替代协作功能验证；本篇未实现原创成片。

## 原创镜头的关键画面调度

下表是上述原创应用的设计草图说明，不是已渲染关键帧，也不代表动态已验。以实际内容、字体与画幅重排，检查每个状态及状态之间的完整运动包络。

| 状态 | 画面安排 | 观看焦点与接棒 |
|---|---|---|
| 白板 | 真实文档居主位，评论侧栏较窄，身份颜色固定 | 外围头像可表达在场，不需五人一起动 |
| 贡献 | 一人评论、一人编辑，箭头跟真实行内锚点 | 输入中的正文最亮，其他名牌避开当前行 |
| 核对 | 修改条件与对应评论保持可见，状态来自实际操作 | 下一镜看完整上下文，不把围观当批准 |
