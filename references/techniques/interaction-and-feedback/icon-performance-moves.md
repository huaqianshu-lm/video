# 图标求关注与递增弹跳

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/effects/icon-performance-moves.md)、[AttentionBounce](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/effects/icon-performance-moves/AttentionBounce.tsx)、[attention-bounce 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/attention-bounce.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 表演服务一次真实召唤

图标是镜头中的主角，先请求注意，再让观众看到它为什么请求注意。适合轻快的软件提醒或新入口；不适合严肃警报、故障或需要立刻执行的安全操作。反复弹跳而没有结果会像加载，不能拿运动本身证明新功能有价值。

## 2. 主角、环境和留白

原例奶油色Dock横贯画面下部并出画裁切，暖沙墙有斜窗光；主角奶油圆角方块中是深墨标志，邻居鼠尾草、石板蓝、沙色和炭黑都压低饱和。真正的层次来自主角清楚、邻居逐渐虚化、墙面比图标更平，不是给每个图标轮流加阴影。

先设计落定海报：主角在左下，右上功能面板有眉题、主标题和真实内容行，面板与图标之间保留呼吸。再预留最高跳的包络。原例ICON360、GROUND960、最高1.2×ICON即432，因此不计拉伸的图标顶点是960−360−432=168px；镜头推近8%后还需按实际原点重投影，不能只用168px判安全。

图标面上有上部柔光、边缘内暗和薄外影，标志自身不发光。地面影应在图标离地时更软更淡，落地时收紧。图标可以被轻度压扁，品牌标志若严重变形应通过外壳变形与内部反变换控制，避免牺牲识别。

## 3. 动作参数与代码核对

四跳起点12/28/48/72f，空中时长14/18/22/26f，高度.35/.6/.85/1.2倍图标高。抛物线y=H·4t(1−t)，速度符号由1−2t给出。原例时长近似随√高度增加，但不是精确同一重力模拟，不必为严格物理牺牲观看节奏。

| 动作 | 实现关系 | 观看任务 |
|---|---|---|
| 蓄力 | 6–12f小幅下蹲 | 让第一跳有动机 |
| 空中 | 速度大时拉伸，顶点速度0 | 不是在最高点最夸张拉长 |
| 接触 | 每次落地约2f压扁，末跳约.2 | 接触要贴地，图标底边不穿Dock |
| 末跳 | 实际落地72+26=98f | LAND100是角标等后续触发，不是物理接触帧 |
| 视线 | 邻居30–96f失焦，镜头72–90f推8% | 注意逐渐集中，别同时弹邻居 |
| 接棒 | 100角标，106面板，114起行内容 | 提醒之后有真实信息，读窗从内容落稳后算 |

落地涟漪和碎点使用各跳实际落点数组；若统一拿100f配最后接触音，会晚于98f的压扁。声音可以有不同语义落点，必须说明究竟配触地还是通知，不可糊写“同帧”。

## 4. 官方画面观察

16幅可见稳定横Dock、主角逐渐跳高、邻居失焦、最终角标与右上面板。暖窗光使环境有方向，主角不靠高饱和夺目。末帧仍保留背景和邻居，非空白底图标表演。抽帧不证明四跳手感和拟音音高变化；本轮未正常速度播放或试听。

## 5. 原创制作推导：有待处理的一条评论

内容目标是“评论提醒之后如何定位到具体修改”。先设计结果：真实文档中某段有一条待处理评论，评论面板与原文同框。Dock或入口图标只作为引路，不能以通用“New”面板结束。

开场文档退成柔和背景，评论入口在下方有足够尺度，轻跳最多承担一次召唤过程；是否保留四跳由叙事时长决定，不为照抄把等待拉长。周围入口低对比，背景原文仍能辨认版面。跳跃落地后出现真实未读数量，数量不能凭动画编造。

点击入口后，面板展开显示实际评论和定位操作；视觉焦点由图标转到评论中的具体修改建议。随后原文滚动至对应段，评论名牌和段落标记保持相同身份色。下一镜直接编辑这段并观察评论处理状态，图标表演交给了真实协作结果。

## 6. 失败与审核证据

- 高跳出框：检查图标外壳、拉伸、阴影和相机后的联合包络，不能只测中心点。
- 连跳像loading：高度与时长有层次，并尽快出现要处理的真实内容；无内容就删表演。
- 图标空中也压扁：将速度拉伸与接触压扁分开时窗，固定接触原点到地面。
- 落地音与角标混为一拍：分别标98接触、100通知，按实际设计选择，不盲用源码常量名。
- 面板仍是三条口号：换成待处理对象与操作结果，使提醒有明确后果。

通过时静态图标可辨、最高点安全、落地接触连续、后续面板能读且指向真实任务。完整速度、声音材质和当前产品适配须另验，原例参数不作为通用默认。

## 原创镜头的关键画面调度

下表是上述原创应用的设计草图说明，不是已渲染关键帧，也不代表动态已验。以实际内容、字体与画幅重排，检查每个状态及状态之间的完整运动包络。

| 状态 | 画面安排 | 观看焦点与接棒 |
|---|---|---|
| 提醒前 | 文档背景可辨，评论入口下方留地面，上方留最高跳空间 | 周围入口低饱和，主图标字形清楚 |
| 表演 | 最高点与推近联合计算安全包络，影子留地 | 落地压扁与空中拉伸分时，不抖整个文档 |
| 具体任务 | 真实未读评论面板接管，正文定位标记保持身份 | 通知数量与实际资料一致，随后修改原句 |
