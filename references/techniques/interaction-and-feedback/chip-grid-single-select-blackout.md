# 单选与候选退让：先证明选中了什么，再让选择组织结果

这个技法的价值，是把一次决定分成可辨认的阶段：候选可比较、指针指向、按下反馈、选中确认、未选项退为背景，最后由所选条件引出实际结果。黑底白字只负责让决定可见；决定究竟改变什么，必须由当前内容回答。不能选择之后只把一个胶囊搬到中央，底下再放一句结论。

## １．先判断这是选择、比较，还是已经完成操作

**原卡给定**：五个选项分两行建立，点击一项后反黑，其余项在原位退弱；停留后剩余项退出，所选项上移缩小，为结算结果让空间。**源码可见**：固定选择第一项Annual billing，价格也是写定的示意值，不存在根据真实套餐返回金额的计算服务。

| 要讲的内容 | 本技法可承担什么 | 不能省掉什么 |
|---|---|---|
| 从互斥选项中做决定 | 比较候选→按下→唯一选中 | 选项确实互斥，所选项有可辨认标记 |
| 选择一个参数并查看结果 | 保留选择身份，结果由参数变化引出 | 当前参数与结果的实际对应 |
| 解释为何选择这一项 | 未选项原位退弱，保留对照背景 | 理由先可见，不能只靠黑色表示“正确” |
| 展示真实软件操作 | 如实表现系统已有选中反馈 | 选择、应用、保存、提交的实际边界 |
| 从选择段转入解释段 | 已选身份成为下一段标签 | 说明视角发生变化，不能冒充软件自动收走控件 |

**制作推导**：按下只是交互反馈；选中是当前状态；结算展示是结果说明；支付或保存则是另一个操作。它们可能在真实系统里紧邻发生，也可能需要额外确认。影片不能把一个勾出现解释为付款完成，也不能把未选项淡出说成它们被删除或失去可用性。

如果题目要求同时选择多项，单选反黑不适用；如果还要逐项比较，不要把其余选项降到无法阅读。原卡的18%是此片段退背景的办法，不是所有真实界面未选状态的推荐对比度。“保留候选位置”有助于识别选择，位置不是永远不许变化，后续重组应有明确的新任务。

原样片五项混合了年度／月度／两年等周期与学生／非营利等资格类别。**制作推导**：只有真实产品规则明确它们互斥时，才能作为同一单选组；否则应把周期和资格分开设计，不能仅因它们都是胶囊就暗示同一维度。本轮未取得其业务计费规则，不据此断言原产品实际如何售卖。

## ２．先设计结尾：选中的身份怎样支撑一个完整结果画面

### ２．１　完整态的视觉重心

**抽帧可见**：样片前段为上方眉题、大问句和两行宽胶囊；后段问题与其余候选退场，选中胶囊居中变小，下方形成旧价、巨大现价、计费单位与蓝色说明的整体。结尾不是五张卡重新排成一列，而是从“比较”变成“决定后的结果”。

**制作推导**：先问最后要读的是数值、文档、预览还是结构。数值关系适合一大一小的主次排印；排序结果更适合真实条目顺序；模式选择更适合内容在同一载体里改变。不要所有题材都把结果写成一个180px大词。选择标签只是条件身份，主要空间应该交给能证明条件作用的内容。

结果主体、条件标签和辅助说明要组成一张成立的静态构图。主结果不是简单几何居中：旧值和新值作为一个组居中，主数字本身会在中轴右侧；顶部标签仍提供条件锚点。原创设计要选择“整组平衡”还是“主对象对轴”，不能两种同时要求。

### ２．２　初始构图：三加二来自实际宽度，不是五个等宽占位

**源码可见**：五个宽度为346、364、476、236、330，高96、圆角48、横向间距22；两行顶边y452／570，行间净距22。第一行总宽1230，左起345；第二行总宽588，左起666。最长选项占更宽的476，不把长文字硬压进等宽胶囊。

首行三个左边分别345、713、1099；第二行分别666、924。选中项初始中心为`(518,500)`，并不在画面中央。中线回收时需要向右442、向上170，最终中心到`(960,330)`。题目和胶囊之间留出的负空间，使指针接近、反黑和后续移动都可辨认。

**制作推导**：选项数量和分行服从内容，不必凑五项或三加二。先排最长标签、选中标记和实际字体，再确定胶囊宽度及组间距。中文字号变化会改变视觉密度，不能只把英文文字换成汉字继续沿用固定宽表。数量多到需要小字时，应改成列表、分组或另一个镜头，而不是缩满一屏胶囊。

### ２．３　字形、留白与结果数字

**源码可见**：主问题84px、字重700；候选文字36px，未选560、选中600；眉题品牌26px，类别22px并有疏字距。现价180px、字重750、字距−0.05em；旧价60px、字重500，单位48px，蓝色辅助说明32px。type统一提供等宽数字特性和字号对应行高，现价行高0.94。

**制作推导**：问题负责建立判断，候选负责辨别，结果负责解释后果，各自有阅读优先级。眉题小字可以作为身份层，不能把关键限制藏进仅作纹理的小字。大数字要把货币、单位、周期一起核对，不能漂亮地放大金额，却把“每月等值、每年扣款”挤成读不清的角落。

这里的180px不是表现质量的来源。真正需保留的是主值、比较依据、条件说明的关系；结果若是长中文，先定其形态和阅读距离，不用极大字号制造溢出，再靠横向压缩救场。

### ２．４　冷白、墨蓝黑和少量强调色

**源码可见**：舞台是冷白至浅蓝灰的纵向渐变，上方中部有白色柔光，填充光关闭；Stage保留暗角与细颗粒，未传入呼吸参数。普通选项白至浅冷白，细边、上沿内高光及两层蓝灰软影；选中后并非纯黑，而是上缘`#1d2438`到底部`#0b1020`的深色渐变。

**制作推导**：浅色实体靠边界、上沿亮度和接触影从环境分离；深色主体靠明暗差和字形反白获得重量，不需要再加粗外框。钴蓝主要承担结果提示和局部落地光，标志内部还含琥珀色，不能称作全片只有一种色相。原创应使用自己的内容身份和色彩职责，不复制品牌标志。

背景光不跟着按钮移动，按钮下方的强调光才依附主体；两者不能混为同一个三维主光。当前实现没有真实地面、光源投射或摄影机透视，是二维渐变、尺度和阴影组成的视觉离面。设计文档要说明这种方法怎样建立层次，不能把它描述成已经完成物理灯光验证。

## ３．入场、读题和指针接近：先给决定一个上下文

**源码可见**：问题从第3帧起按词揭示，六词间隔2.5帧，每词16帧，最后一词完整落位在31.5，整数帧32才到终点。五个选项从8起，每项隔3帧，各16帧升起；最后一个从20到36。注释“8—28完成”并不对应全部结束。

问题用TextReveal的逐词遮罩升起，不是透明度淡入；字块从105%字高加0.3em的下方偏移进入，外层遮罩带上下留白以容纳字形。空格不计入词序。选项则整体透明度上升，top额外从30px偏移回归原位；未选项虽然写着`transform:none`，入场时仍在改变top，只有落稳后的选择阶段才位置锁定。

**制作推导**：先让选项可读，再指向目标。问题和普通入场可以少量重叠，但不能指针已按下，最后一项还没出现；也不必每个候选都做明显弹跳。中文分词应按语义单位设计，不能直接依赖英文空格拆分。字的遮罩要同时检查顶部、下伸部和选中标记，不能只看字框中心。

**源码可见**：指针24—32淡入，26—54沿swift缓动从`(1500,960)`移动到选中项内的`(559.52,507.68)`，纵向减去`60sin(πp)`形成上拱；56定义按下。指针按压尺度在55—62之间暂时收小，70—82退去。SVG外框46×50，未抵消整组的1.5%缓推，所以不能声称其屏幕尺寸严格恒定。

指针位置使用SVG外框左上定位，真正尖端在路径内部，并非`left/top`本身；要做精准按钮命中测试，需把viewBox到实际像素的偏移一并算入。此例点击落在宽胶囊内，不能直接将这套坐标用于很小的图标。

**制作推导**：指针接近可以预告决定，但不应挡住关键词。没有输入设备动作要解释时，可以采用明确的选择提示，不必每个镜头都补一只鼠标。需要严格保持指针尺寸时，应采用独立屏幕层或同源反缩放，具体方法可对照 [输入与筛选](type-and-filter.md)。

## ４．按下、反黑、勾选与回弹：不同通道怎样共同确认一件事

### ４．１　单帧灰块先表示按压

**源码可见**：灰层只在56帧存在，颜色`rgba(120,128,146,0.5)`；它铺在目标表面上，但文字在更上层保持可辨认。57起灰层已经退出，深色表面的插值才开始。30fps下单帧约33毫秒，这不是真实指针事件触发的`:active`，而是时间轴对该状态的模拟。

**制作推导**：按压与确认应有可区分的先后，但“一定只有一帧”“两帧就必然像hover”只是原卡的手感判断，不能跨帧率当规律。实际素材若有自己的点击反馈，保留真实状态；经过编码压缩后若灰闪不可辨，应调整对比或时长再观看，不用提高到整屏闪白来补。

### ４．２　线性反黑带动文字、边界和勾选

**源码可见**：反黑进度`b=clamp((f−57)/5)`，到62完成。上下渐变色、文字颜色、边框与内高光共同变化；勾选SVG宽从0到30，透明度也由同一进度上升，左外边距从0到−12，所在flex组始终保留14间距。不是只在白底上叠一张黑矩形，文字和边缘也必须适配。

勾出现时，文字和图标组成的居中组会重新分配内部宽度，标签可能发生小幅横移；“外壳没动”不等于内部字完全不动。**制作推导**：如果标签必须保持原位，就预留勾的位置或另层定位；若允许内部排版微调，检查全程字形与标记不碰撞。不要用横向缩放文字来容纳突然长出的图标。

**制作推导**：线性是这个短确认的有意选择，使深色状态迅速成立；并非所有颜色过渡都必须线性。判断标准是确认清楚、文字对比够、边框不闪白。选中标记与文字身份同时保留，有助于在颜色辨识弱或背景变化时仍看懂当前状态。

### ４．３　轻回弹与未选项退弱同起，不逐项表演

**源码可见**：`p=clamp((f−57)/9)`，目标尺度`1+0.04sin(πp)`，57和66精确回到1，中点连续极值1.04。整数帧不必采到连续极值。它并没有先缩小按钮再回弹；缩小的是指针，按钮本身是确认后的轻放大。

同时其余项用outQuad把不透明度1降到0.18，57—66完成，外壳不重排。**制作推导**：按压层、变色、勾、目标放大、候选退弱都服务一次决定，不能再给每个通道追加独立闪光与提示音。目标尺度极值时检查邻项和行间净空；不是仅在尺度1时看布局不碰。

若结果还需要对照候选，保留其可读性；如果视频要说明“选择是可撤回的”，也要保留切换入口或明确后续解释视角。18%只适合已经完成阅读、即将退出的背景，不适合作为还要操作的默认控件状态。

## ５．停留与收束：从候选区域转交阅读权

**源码可见**：56按下，101开始收束，两者相隔45帧、1.5秒；但反黑和回弹到66才全结束，因此严格稳定选中态至101只有35帧，约1.17秒。“选择后1.5秒”不能写成“完全稳定停留1.5秒”。实际是否够读仍取决于文案与口播。

101—110未选项从18%到0，仍留着自身几何位置；当前绝对定位保证它们退去不触发同行重排，不是靠flex的运行时测量。选中项101—119用smooth位移，中心从`(518,500)`回到`(960,330)`，尺度从1到0.88。变换依附原对象，不复制一份黑标签后让原对象消失。

**制作推导**：用最终布局求中心位移，再用同一收束进度派生位置与尺度。若缩放围绕对象中心，目标位置按中心算；绕左上角缩放则公式不同，不能一边按中心求位移、一边改了transform-origin。固定宽方案替换长中文时必须重排，运行时测量也需等字体和尺寸可靠后再取，避免每帧追着变换后的矩形重算。

**源码可见**：最终宽约304.48、高84.48，边界约x807.76—1112.24、y287.76—372.24。辅助字号36乘0.88得到31.68；即使原卡写“仍约32”，也不能说严格不低于32。当前项目采用什么字号仍查项目规范，不照搬这项近似判断。

问题从97起在16帧内上移30并淡出，先于101收束4帧；眉题整体随之退出。整组相机20—80缓推至1.015，101—131回到1，背景舞台不随主体组缩放。主体回中线到119并不代表所有通道都停止，131之前仍有父层变化。

### ５．１　落地光与阴影：强调只给当前主体

**源码可见**：选中项下方是一团椭圆钴蓝渐变，模糊6；最大alpha随反黑升到0.2，收束后降为0.1。位置和尺寸依附目标外壳。阴影使用的名义离面量从6到16，再随收束到42；近影与宽影随辅助函数共同变化。

源码注释提“呼吸”，但这团光只由反黑和收束进度驱动，没有周期明暗函数；Stage也未启用呼吸。**制作推导**：不要为了兑现一个形容词而补无意义灯光动画。若已有深色主体和勾，局部蓝光可以更弱或取消；同一主角不必同时有光圈、描边、放射线和粒子。

## ６．结果形成：读得见旧值，也看得懂条件

**源码可见**：原值从108起用14帧升入高82的遮罩；118起用8帧划线退灰。原值严格落定在122，早于此4帧就已经划线，因此不存在一个“完整静止、尚未划掉”的原值阅读段。现价从116起、六字符间隔1.2帧、各14帧遮罩升起，最后字符在136结束；单位124—134淡入。

**制作推导**：需要观众理解变化幅度时，先读原值，再划掉，再确认新值；不能用调用起点先后冒充阅读已完成。原价逐渐出现时可以提前引出新价，但必须观看判断旧值是否仍能认清。原值不要因为退灰而小到只剩一条无含义横线。

**源码可见**：原值与现价以flex底部对齐、间隔44；现价与单位基线对齐、间隔10，旧值字块内部删除线在54%高度伸出。旧值108之前显式隐藏，避免未升起的字顶漏出；TextReveal自身遮罩也为字形留了余量。真实字体变化后仍需复查货币符号、数字顶端、下沿和裁切边缘。

128—142蓝色说明用overshoot升起与缩放，强调18%及年度总额。42×0.82=34.44，34.44×12=413.28，算术相符；但$/mo与yearly表达的是月均展示和年度计费，不能让观众以为实际每月只扣一次34.44。示意值不是现实优惠承诺，真实视频需替换为有依据的金额、周期、税费或其他条件。

全体到142才严格结束，而样片终点为164，最终状态共有23个显示帧，约0.77秒；不能按注释的134起、31帧来认定完整结果停留。短段落中可以先后分担阅读，但当前教程是否能看清金额和周期，需要正常速度观看，不是再增加一个“hold”标记就算通过。

**制作推导**：数字关系成立还不够，说明必须可读。新结果、原值、周期和辅助条形成统一构图，但辅助条不能藏起决定性的限制。非价格内容无需删除线和优惠胶囊；例如选择排序应直接展示真实顺序，不凭空制造一个“提升18%”大数字。

## ８．完整原创演绎：选择排序规则，让文件关系真正改变

以下为**制作推导**，未实现。教学目标是“按修改时间排序，最新文件会排到上方；改变的是顺序，不是文件本身”。采用明确标注的教学文件示意，不冒充某款软件录屏。只有三种互斥排序依据：名称、修改时间、文件大小；不为套五个胶囊编出额外选项。

### ８．１　先定义内容与结果，避免空结果海报

示意文件保留四项：会议纪要.md／10月28日09:10／12KB，预算说明.md／10月31日16:40／8KB，发布清单.md／10月29日14:20／5KB，操作指南.md／10月30日11:05／24KB。日期年份均明确为2026。初始只标“示例原始顺序”，不冒称已经按名称排好。

选择“修改时间”，方向另用清楚的“从新到旧”文字和向下排序标记表明，结果依次为预算说明、操作指南、发布清单、会议纪要。标题、图标、日期和大小跟随各自文件，数量仍为4。不能因为最新项成为第一，就给它标“新生成”或“更重要”；此镜只解释时间顺序。

最终画面主体是一张可读文件表，排序身份位于上方，修改时间列形成稳定纵向对照。第一行获得较强对比，观众同时能看见其日期确实最新；其余三行仍可核对。不要把文件列表变成一个“最新文件”大标题，再让实际文件全部消失。

### ８．２　具体美术、取景和中文容量

使用一张连续浅色资料工作区，薄边界与低对比承托影，文件图标是克制纸页形；表头与数据行共用列，不给每个文件套独立悬浮卡。标题较重、时间采用稳定数字排印、大小退为辅助；选中规则用墨蓝底、反白字与勾，当前排序列用细线和箭头承接。未选项与结果不是同一种强调色。

1920×1080初稿，外壳`(160,140,1600,760)`，内容左右内边距60，有效宽1480。上方问题“怎样把最新修改的文件排到前面？”初稿采用适中偏重中文，先排完整问句，过长就拆语义行，不强塞原案例84px单行。选择区顶边300，高72，标签初稿34px；三项宽220、300、260，间隔20，总宽820，左起550。选中中项中心为940，比画面中线左20；选择确认时仍原位，后续解释标签如需居中，再向右20，不能把整组居中误当成每项都居中。

表头在y430附近，四行从y470起，每行86，最后到814，距壳底900尚留86。名称列x220、修改时间列x1050、大小列x1510，分隔线延至x1700；最宽日期和中文文件名先用真实字体排，名称不能侵入时间列。底部字幕另保留，不用表格阴影或排序说明挤入字幕。

前段三种选择位于同一控制行，下方四个文件已可见，选择要改变的对象先成立。后段结果表不整体大幅放大，优先局部提高日期列对比，必要时再推近第一行；这样保留文件间的顺序关系，而不是仅展示一个孤立高亮。

### ８．３　完整动作链与选择理由

| 状态 | 画面与动作 | 观众新增理解 |
|---|---|---|
| A．建立对象 | 原始四文件和日期／大小可读，问题提出“最新修改” | 知道要比较哪一类信息 |
| B．比较规则 | 三种排序依据同处控制行，日期列短暂获得对比后恢复 | 问题对应修改时间，不是文件大小 |
| C．指向与按下 | 指针到“修改时间”，局部按压后选中反白／勾成立 | 先有操作，再有选中状态 |
| D．决定落定 | 候选仍原位；当前规则和“从新到旧”清楚，其余项轻退弱 | 选择依据与方向共同确定 |
| E．结果重排 | 四个文件整行移动到对应位置，日期与名称不分离 | 改变的是文件顺序，数量和身份不变 |
| F．核对最新 | 第一行预算说明与10月31日16:40取得焦点，下面日期仍可比较 | 为什么这一项到了最上方 |
| G．转入解释 | 明确切到讲解视角，所选规则成为结果上方小标签，未选候选淡退 | 这是从操作到解释，不是软件删掉控件 |
| H．下一镜接管 | 从第一行进入同名文档预览，或保持完整排序结果结束 | 排序用于找到对象；未发生打开就不演成功 |

若是在真实软件里教学，G不必发生：保留原控件的真实样式及可切换入口，不强行把它们收走。只有独立教学示意、且明确进入结果解释时，才采用本技法的候选退出与标签上移。能保留关系比完整复现一次收束更重要。

### ８．４　文件移动中段不能用重叠糊过去

原行索引0、1、2、3对应会议、预算、发布、指南；目标索引分别3、0、2、1。行顶由`470+86×索引`计算，位移依次+258、−86、0、−172。发布清单保持原位，是整个重排的稳定支点；新旧顺序由真实时间比较得到，不能只按导演想突出的名称排。

不要让会议纪要下移时与另外两行在同一平面互相穿字。可采用两阶段编排：先给将上移的两行克制提层／轻微侧移，让下降的会议行经过背后通道；再一起回到共同列和基线。移动期间暂时隐藏细分隔线，但标题与元数据作为一个对象，不复制出两份让观众误以为数量增加。

如果四行交叉仍难以跟踪，就把镜头拆成“规则确认→完整排序结果”，用同一规则标签、四项数量和准确日期保持连续；不必强行连续变形所有行。路径方案需检查刚起步、交叉最密、回列前和落稳后，不能只有两个好看的静态端点。

### ８．５　结果标签、声音和下一镜

解释段标签若上移，从真实选中控件的中心到结果标题附近求位移；选中身份连贯，文字不压缩变形。问句退去时让出的是表格阅读空间，日期列不随外壳额外跳动。已选标签不再继续呼吸或弹跳，第一行及其日期取得下一次焦点。

按下可有一次轻触声，选中使用很短的确认；行重排如需声音，用一次轻微集合变化，不给四行各配相同whoosh。口播说“十月三十一日最新”时画面应已落稳，指针不横穿日期。下一镜如打开预算说明，文件名、年份和路径身份要对应；若只到排序结果就结束，不伪造打开、保存或处理成功。

此原创不使用旧价删除线、优惠百分比或计费胶囊，因为排序没有这些语义。移植的是选择确认、原位候选与阅读权交接的方法，结果表达完全由文件关系决定。
