# 前置三连切与黑场：先提出视觉问题，再给正式入口

## 1．这是一种段落结构

三个短镜头先给出可辨认的视觉线索，黑场把这口气收住，正式标题再说明接下来讲什么。它安排的是“观看冲动→短暂空白→主题建立”，不能靠三张无关画面和一个品牌字标自动成立。

本项目做口播教程，适合把它改造成一组真实现象的预览，或先展示一个需要解释的矛盾。不是默认宣传片片头，也不应覆盖已选系列的片头规范。若三镜需要读段落文字、复杂操作或详细数据，9 帧容量远远不够，应减少信息或改为正常解释镜头。

来源为 [trailer-grammar-moves 原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/rhythm/trailer-grammar-moves.md)、[TrailerBumper.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/rhythm/trailer-grammar-moves/TrailerBumper.tsx) 和 [官方 trailer-bumper 演示](https://vincentwei1021.github.io/video-shotcraft/media/trailer-bumper.mp4)。相关画面由 `FakeDashboard`、`Backdrop`、`Grain`、`Vignette` 与品牌辅助文件生成。

原卡给定的是三镜 9f、6f 黑场、标题进入与静止；**源码可见**的是下文具体时序，**抽帧可见**的是对应画面状态，原创方案标作制作推导。已查看 30fps、140 帧演示的 0、8、9、17、18、26、27、32、33、40、49、55、62、63、100、139 帧。未正常速度观看、未试听、未运行上游或原创工程；卡中三次打点与黑场消音是设计要求，本次没有声音实测证据。

## 2．先选三幅能够迅速辨认的画面

原例不是三个连续操作，而是仪表盘 A 全景、项目列表 B 全景、回到 A 的 Top pages 中列近景。前两镜共享相同外壳，第三镜改变观看距离。优点是空间身份可保持，局限是灰色复杂界面里，九帧只能留下“界面规模／列表／一个重点”的印象，读不完数值。

| 镜头 | 静态构图与主体 | 怎样保证其有意义 |
|---|---|---|
| A 全景 | 深色左导航，浅灰主区，六张统计卡；曲线、柱形、热图形成不同密度 | 全景负责交代对象和范围；不要求同时读所有图表 |
| B 全景 | 同一导航与页头，主区变宽横列表，行内有曲线及状态 | 与 A 的密集卡片产生形状差异；若只是另一组相同卡，切换价值偏弱 |
| A 局部 | 中列上方 Top pages 以 2.2 倍放大，标题、排行与数值成为主体 | 最后一镜必须提出可承接的问题，而不是随便挑一个局部 |

每镜叠同一套暗角：strength=0.18、inner=0.5、偏冷深色；颗粒 opacity=0.05。统一质感能把切换连成一组，但不能代替内容联系。复制到素材摄影时，优先统一曝光、黑位和白平衡，再判断是否需要同样的颗粒；本来有强纹理的照片不应重复加脏。

三镜选择应反向来自正式讲解：这三个线索后续分别在哪个镜头被解释？若只有“好看”而没有返回它们的内容，观众得到的是一个没有兑现的承诺。可以只保留两镜，或改为同一对象的整体／异常／细节；不以“三”作为必须凑齐的数字。

## 3．切点、内部推进与近景坐标

| 输出帧 | 内容 | 实际容量 |
|---|---|---|
| 0–8 | A 全景，微推 | 9f＝0.3 秒，识别体块，不做详细阅读 |
| 9–17 | B 全景，微推重新从 1 开始 | 零过渡硬切，靠画面差异形成节拍 |
| 18–26 | A 的 2.2 倍近景，继续微推 | 焦点从整页转为指定卡片 |
| 27–32 | #000 纯黑空画面 | 恰好 6f＝0.2 秒，没有字、颗粒或暗角 |
| 33–48 | 正式标题显露／上升 | f33 背景和文字透明度均为零，仍是黑画面 |
| 49–62 | 主标题已满态，辅助文字完成，字距继续收拢 | 不是 f49 就整帧静止 |
| 63–139 | 字距固定，背景子树冻结到 63 | 源码意义上的 77f 保持，未据此声称压缩像素完全相同 |

各短镜的 scale 从 local0 到 local9 定义为 1→1.04。但每镜只输出 local0–8，最后一张实际约 1.03556，不是都展示了恰好 1.04。切换后微推重新起步；在统一节拍下形成连续的向前观看冲动，而非一条物理连续相机轨迹。

第三镜使用 CSS zoom=2.2，焦点源码坐标为 1071、335。容器 left=`960/2.2−1071`，top=`540/2.2−335`，让焦点在布局放大后落到 960、540；外层微推又绕屏幕中心，因此焦点仍居中。这里与“绕原焦点放大、焦点留在原屏幕位置”的方法不同，不能混用公式。

裁切范围也要审核。2.2 倍时，屏幕对应源区域约宽 872.73、高 490.91；围绕焦点的可见范围约 x634.64–1507.36、y89.55–580.45，外层推进后还会略收。相邻卡片被切边是近景的一部分，但不要把目标标题或决定意义的单位也截掉。CSS zoom 可以按目标尺寸布局文字，不会恢复低分辨率截图不存在的细节。

原卡把“每镜微推”列为避免幻灯片的重要点。制作时仍需判断：若静态画面本身缺乏主体，轻推只会把普通页面慢慢放大，无法替代构图。九帧镜头的轮廓与焦点比几百分比 scale 更关键。

## 4．黑场与标题的美术接棒

黑场是这一组节拍的断句。27–32 返回纯黑空容器；f33 正式段开始但尚未显露，因此按可见黑画面判断可能包含第 33 帧，不能只靠变量名推断观众感受。黑场后背景用 12f 从黑亮起，不是突然切到大白。

标题画面采用对称居中构图：顶部 34／600 的大写眉题，字距 0.18em；下方 176／800 的全小写品牌字标，lineHeight=1；再下方 40／500 的副题，间距 38。眉题与主标题间距 30。背景主光在中上方 0.5／0.36，暗角 0.2，把高亮中心与文字中心联系起来。

主标题 33→49 用 outQuad 淡入，整体 y 从 44→0 用 outCubic 上升；字距则 33→63 从 0.05em 收到 −0.012em。176px 字号下，单个字间距约从 8.8px 到 −2.112px，整条字标的宽度变化不能忽略。副题不随字距收缩，避免全体文字像同一块橡皮。

眉题 35→51、副题 39→57，各自渐入。最后一项动态是主标题字距，到 63 完成；背景的颗粒通过 `Freeze frame=63` 固定。文字虽在 Freeze 外，但自身参数已夹定。抽帧的 63、100、139 呈现相同的标题布局，这支持状态保持，不足以证明正常速度下标题的弹性、节奏和声音已经优秀。

改写中文教程标题时不能按英文字符数量套 176px。先用实际字形测试总宽、字重、行距与负空间；双行标题也不应每行同样收字距。若题目长，删去眉题或缩短标题，比把整组文字缩成小字更可靠。正式标题出现后应接实际对象，不以另三张文字卡继续延迟正文。

## 5．原创演绎：同一张照片，为什么边缘看起来不同

**内容目标。** 讲解照片缩放与锐化造成的边缘差异。使用同一张有细密轮廓的真实照片与可核验处理设置。镜头前观众看见“同物却不同”，镜头后进入处理原因，而不是收到一个夸大画质提升的广告承诺。以下为待实现方案。

**先选结果与下一镜。** 正式标题写“清晰，还是锐化？”；标题后立即给同一眼部／羽缘的配准对比，保留原图、缩放和锐化三个状态的真实名称。选择何种部位取决于素材，不预设每种锐化都会出现明显白边。

**三镜美术。** 第一镜是照片完整构图，主体眼睛或轮廓处在右上三分区域；第二镜是同一照片的中景，让轮廓占据较大面积；第三镜为同一局部处理后的近景。中性深灰衬底，照片保持原色，不用不同调色暗示谁更优秀。全组只使用一个小色标标明处理状态，背景不放装饰性图表和假数据。

**动作与阅读层级。**

1. 全景建立同一主体，镜头内部轻推围绕该主体，不能把人眼推到画框外。此时只求认出照片，不求读文件名。
2. 硬切中景，眼睛保持在相近屏幕位置，观看距离缩短。裁切来自同一原图；不能用另一张表情不同的照片制造“前后”变化。
3. 再切局部，显示实际处理导致的边缘状态。若要观众识别细小光晕，应把此镜延长到能看见，而不是死守 9f；三镜等长只是原片节奏，不是本教程证明质量的条件。
4. 极短黑场关闭速剪节拍。是否全消音按旁白断句决定：若口播还在说关键词，不为照搬黑场把字切掉；需要静默就安排在句间。
5. 标题从暗到亮建立。中文字形用清晰、有稳定重心的黑体，标题与副句“先比较同一位置”分层，副句不再解释整套原理。
6. 标题后同一眼部切入配准对比。细线标出共同位置，原图和处理图使用同一裁切与倍率，讲解开始证明“变化发生在哪里”。到此，开头的三镜得到兑现。

**不同素材的边界。** 若第三镜没有实际可见变化，不用增强过量锐化伪造案例。可换一张真实存在差异的素材并如实说明设置，或取消预览，直接在对照镜里操作参数。标题承诺由实际证据决定。

## 6．声音与段落，不靠“轰”补救

原卡建议三个切点各有一声打点、黑场消音。本次未试听，不能断言演示有这些声音。实际教程可以把第一声留给首镜、第二声轻一些、第三声收紧，让标题入口得到一个明确停顿；也可以只在第三镜与标题处用声，避免三连打点盖住开头一句。

声音锚定输出切点 0／9／18／27／33，不能锚定另一个被冻结的素材时间。若旁白先提出问题，三镜应落在语义短组之间，不为了均匀节奏拆断名词。标题保持期间不持续加升调噪声维持紧张，观众需要从钩子转入学习。

## 7．失败、修改与通过证据

| 失败 | 修改方向 | 可观察判据 |
|---|---|---|
| 三镜像随机截图 | 为同一问题选择整体、变化、细节；说明后文如何回收 | 关闭标题也能认出同一对象与一次明确的观看距离变化 |
| 九帧里什么都没看清 | 去掉小字，放大单一主体；需要辨细节时延长 | 正常速度能指出每镜主要对象，不能只凭逐帧才知道内容 |
| 特写仍糊 | 使用足够分辨率真实图，检查最终裁切，不靠 CSS 数值自证 | 关键边缘在最终输出中真实存在，无伪造锐化 |
| 黑场像加载故障 | 检查前后节拍、黑场长度与声音断句；无关叠层全撤 | 黑场是一处可感知的标点，而非突然中断正在解释的信息 |
| 标题像默认幻灯片 | 重新设计字形、宽度、主副层级与留白；减少无用眉题 | 静态标题成立，入场只是强化它，而非唯一看点 |
| 所谓真静止仍漂 | 核查背景粒子、光源、文字字距等所有驱动 | 稳定段布局和主体不再运动，是否保留底噪按设计明确 |
| 开头承诺没有兑现 | 标题后直接进入对应真实对象与证明镜头 | 第一个正文镜承接第三预览镜的问题，不另起无关介绍 |

检查六个位置：第一幅、第二切点、第三近景、黑场、标题满态、正文接棒。再以正常速度及口播核查，不用关键帧漂亮代替整段有效。原卡的高能结构是可研究的节奏选择，不是每条教程都要附加的一段固定片头。
