# 硬切作为节拍：同一对象的三次取景与停留

本镜用几次明确切点把观看距离逐步拉近，让同一对象被“拍下”。重要的是取景方向、预备提示与最后阅读，而不是白闪数量。三个无关画面加三次闪光只会增加刺激，不会形成逐步逼近的视觉叙事。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/rhythm/beat-cut-moves.md)、[PaparazziFlash.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/rhythm/beat-cut-moves/PaparazziFlash.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/paparazzi-flash.mp4)，另核对 [Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx)、[Look](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Look.tsx)、[Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)。当前固定原卡只列连闪定格这一式，历史加速剪辑文件不冒作当前已观察变体。

本文分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、140帧、约4.67秒，无音轨；查看16帧。未正常速度完整观看、试听或运行上游／原创镜头。固定卡与main实现、媒体分别核对，不宣称同版执行。案例参数不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先明确切串最终让观众读什么

| 内容目标 | 合适安排 | 失败安排 |
|---|---|---|
| 从整体找到一个关键字段 | 页面→对象→字段，身份不断 | 三张不同页面随节拍换 |
| 给已证明结果一次强调 | 切后固定清晰结果 | 没有证据就授奖／庆祝 |
| 摄影式回顾 | 同一场景活态到照片态 | 原本全是静图，却称真实摄影抓拍 |
| 解释因果链 | 切串只负责聚焦 | 跳过前因，用闪光当结果成立 |

**制作推导**：画面里最值得强调的必须是真实信息，而非数字越大越好。原演示的年度奖项、首次提示成片、RAW45MP和保存状态均为构造的摄影舞台，不是实际获奖、拍摄规格或服务结果，不可直接迁用为产品事实。

## ２．三张取景先各自好看，再设计闪光

### ２．１　全景建立对象与环境

**源码可见**：深石墨背景上，700×780、左610顶176的竖向奖牌卡居中。背板9行、每行交错标志与字标，压到9%—10%亮度；顶部一层柔光，卡面深灰渐变、40圆角、细内边、长软影。香槟色只给奖项和关键短语，不铺满所有边框。

卡内层级为桂冠／小型奖名、72px标题、110px辅助词与280px主数字、44px右侧短语，底部为身份。全景可认对象、标题和数字，底部小字不是当前重点。

**抽帧可见**：开头取景器与卡共同存在，卡比背板亮；小型远闪提供环境活性。第一次闪后仍是同一整卡；第二次更近，第三次只保留最关键的大词与数字。

### ２．２　卡片态与特写态有明确裁切关系

视图分别为全景scale1、中心960／540；卡片scale1.6、中心960／466；特写scale2.8、中心960／588。特写对应源范围约x617.14—1302.86、y395.14—780.86，刻意不再展示卡顶与底部身份。

**制作推导**：每级取景都必须让本级任务完整。例如最后讲数字与单位，就保留两者；讲文件扩展名，则保留文件名尾部和扩展名分隔点，不只留下“.jpg”却失去对象。不能因为2.8倍是原卡参数，就裁掉中文半行。

最终视图还叠外层1.012基础overscan、快门回落和后段慢推，实际取景比名义视图更紧。检查字框和画边时用完整变换，不能只按viewRect算一次。

### ２．３　HUD是摄影隐喻，不是事实装饰

屏幕层固定四角取景框、曝光读数、张数和充电状态，不随世界裁切放大。字为等宽24—40px，白与香槟区分次级状态；红点只作取景器身份。它们不是软件真实控件，使用教程通常可减成一个必要定位框。

**制作推导**：若内容不涉及摄影，去掉ISO、快门、RAW和Saved等无关信息，防止装饰假数据抢阅读。取景器完整不等于画面高级；应让当前对象的构图和材质先成立。

## ３．动作链：活态、预备、硬切、余韵

### ３．１　0—29建立活态

**源码可见**：前30帧全景尺度1.04→1.1，背板有六次短远闪，起于3／9／13／18／23／27，每次约3帧；本体其他内容静态。它不是一段真实人物动态摄影，活性来自平面慢推和程序光效。

30之后Scene关闭远闪，固定在对应时刻；但镜外仍有余韵、HUD、颗粒与慢推。所谓“照片冻结”指场景内部不再更新，不代表整张输出画面全静止。

### ３．２　对焦框先告诉观众下一步看哪里

第一组从21开始，不是注释22；目标是整卡外扩30，而第一次闪实际切到全景，所以它首先是“锁主体”，并非严格投影下一张视图边界。后两组44／62起，分别投影下一视图的源矩形，6帧从1.3倍框收回；闪前3帧变香槟色。

**源码可见**：project用当前名义视图计算，没包含外层1.012、余韵与慢推，因此不是全变换的精确屏幕投影。若原始边界必须精确，用同一完整矩阵生成HUD位置。

**制作推导**：预备框应该指向下一次真正需要读的区域。别总往屏幕中心收一个框，目标却在右上；也不要把完整下一裁切框画得超出屏幕而让人找不到四角。边界提示与待读对象之间有意义，比精确复刻一个取景器更重要。

### ３．３　三切点与闪光层分别有自己的职责

切点30／52／70，相邻间隔22、18帧，呈轻微加密。源视图在该帧直接按区间切换，没有A／B画面交叉淡化。白闪同时以0.95峰值覆盖，4帧强减速回落；中心近白、四角略透原图，不是全屏纯白4帧。

闪后外层6帧scale1.03→1、y−16→0，另7帧过曝回落，期间亮度、对比和饱和度各自调整。±2px确定性抖动只在闪后最初4个整数帧出现。

**制作推导**：硬切与闪光是分开的。可以保留硬切而降低闪强，或只在一个最重要切点闪；前提是正常速度仍有清楚的观看指令。若声音拍点与信息阅读冲突，优先重新分配剪辑与阅读，不硬塞三次相同重击。

## ４．最后70帧不是70帧完全稳定阅读

| 最后一切之后 | 实际时序 | 还在变化的内容 |
|---|---|---|
| 白闪 | 70→74 | 高亮遮盖逐渐撤 |
| 尺度与沉降 | 70→76 | 3%尺度与16px偏移回落 |
| 过曝 | 70→77 | 亮度／对比／饱和继续恢复 |
| 充电HUD | 70→86 | 状态从充电到就绪 |
| Saved | 84→96 | 文字逐步进入 |
| 最终慢推 | 76→140 | 最多1.5%，末输出139 |

70—139确实有70张特写阶段帧，但辅助状态到96才完整。Saved是定时出现的摄影示意，不是文件写盘证据。若末态需要读一个新知识结论，应从画面恢复清晰、必要状态完整之后算实际可读时间。

**制作推导**：原卡要求切后长hold，取其强动作后要归还理解时间的理由；实际时长按真实文本、口播和声音定，不把70帧硬定成所有镜头底线。复杂文字需要更长或另镜，熟悉单数值可以更短。

## ５．关键帧观察与动态边界

实际查看0、21、27、29、30、34、44、51、52、56、62、69、70、77、96、139。

| 状态 | 抽帧可见 | 应检查 |
|---|---|---|
| 0—29 | 整卡、环境、定位框变色 | 对焦是否真告诉下一步看哪里 |
| 30、34 | 第一闪与全景照片态 | 活到静有无对象位置跳变 |
| 44—56 | 对焦后切到卡片近景 | 必读标题是否仍完整 |
| 62—77 | 最后框、闪光、Take1特写 | 目标是否在正确区域，不被HUD遮 |
| 96、139 | 特写与Saved完整 | 最终阅读和实际含义是否清楚 |

当前媒体无音轨。原卡说声音强依赖，说明应为切点设计声音，不证明本轮听到了快门。不能把无声静帧的正确切点当成声画节奏已经通过。

## ６．原创演绎：从文件列表定位真正的扩展名

以下为**制作推导**，未实现。教程要让观众找到实际文件名中的扩展名，前面已建立文件身份。这里借逐级取景，不复用颁奖卡和摄影假数据。

### ６．１　先画最终特写

选真实文件列表，其中一项为有依据的“会议记录.txt”。最终保留完整文件名、扩展名分隔点及同一行图标，左右还有少量列头或邻行作为来处；不能只放一个巨大的txt。采用实际界面的浅底与中性字色，扩展名用低饱和绿底、深字强调，不改变文件名本身颜色语义。

取景顺序为资料文件夹全景、选定行近景、文件名尾部特写。每一层都有实际截图锚点与同一对象ID。标题“看名称最后一段”只在最终特写之外排36px，主要文件文字以实际像素可读为准，不能把说明盖在扩展名上。

### ６．２　完整调度与内容接棒

| 阶段 | 画面动作 | 新认识 |
|---|---|---|
| 起点 | 文件夹实际全景，当前行有位置线索 | 这是哪一个文件 |
| 预备 | 一个轻框定位同一行 | 接下来关注这一项 |
| 第一切 | 到文件行，文件名完整 | 图标、名称和列关系可核对 |
| 第二预备 | 定位点号与后缀 | 关注更具体的字段 |
| 第二切 | 端正特写，后缀高亮完整 | 知道扩展名在哪里 |
| 阅读与下一镜 | 静止读取，再解释后缀与真实格式关系 | 不把改名字误作转换格式 |

本任务不需要三次强白闪，可用两次直接切和一次很轻的定位反馈。切串节奏由“这个文件”“最后一段”两段旁白决定，不为了凑100BPM加第三张无用视图。

### ６．３　坐标、素材与声音

假设源截图1920宽，文件名框左420、顶360、宽520、高52。近景想显示1040宽，尺度2，中心680／386投到960／540；进一步只读文件名尾段时，先用实际字形测后缀字框再取中心，不按字符串长度乘固定字宽猜。

若源字号24放到2倍只剩48px可辨，但位图字边仍可能软，需要更清晰截图或原生字层；不能把摄影模糊当字清楚。切后保持同一行内容和时间状态，不在新裁切中偷偷改扩展名。

声音可各给一次轻定位／切点，不配摄影Saved或成功音。最终读字段时动作声退，让旁白解释真实含义。实际软件、素材、中文字形、原创实现与正常速度试听均待验证。

## ７．失败诊断与通过条件

| 失败 | 修正 | 可观察的通过证据 |
|---|---|---|
| 三切像三页PPT | 同一对象逐级取景，补明确预备 | 每次切都更接近同一个问题 |
| 切后半行字出画 | 先排最终字框再定倍率 | 本级要求读的内容完整 |
| 预备框与下一裁切无关 | 用完整坐标变换投影真实目标 | 切前就能知道接下来读哪里 |
| 闪光盖掉关键信息太久 | 缩短或减弱闪层，增加清晰阅读 | 动作有力而不牺牲信息 |
| 70帧hold仍一直出状态 | 分开余韵、HUD和最终阅读 | 真实稳定时间说得清 |
| Saved／奖项成了虚构事实 | 去掉无关摄影数据，换真实证据 | 画面没有未经证明的成功或荣誉 |
| 对拍但观众读不懂 | 从文本与旁白重新排切点 | 正常速度可复述聚焦结果 |
| 多次重复削弱效果 | 按整片内容减少切串次数 | 强动作只出现在值得强调处 |

Storyboard要交代三个或更少取景各自的新认识、源对象身份、完整字框、预备与硬切关系、余韵、最终阅读和声音。静态、全速、音轨与真实内容分别核验；本文不宣称原创或商用成片已通过。
