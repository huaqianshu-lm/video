# 三级跳切推近：用观看距离的顿挫明确指向

本镜不连续飞向目标，而是在同一个支点上分级跳近。第一次看见整体，第二次认出目标区域，最后一档读核心内容。跳变要让观众更确定“就是这里”，不能只把页面抖大两次。最终近景若没有新认识，就应删掉多余档位。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/rhythm/rhythm-interrupt-moves.md)、[JumpCutPunchIn.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/rhythm/rhythm-interrupt-moves/JumpCutPunchIn.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/jump-cut-punch-in.mp4)。另核对 [Fixtures](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Fixtures.tsx) 与 [Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx)。固定卡只列当前跳切式，历史黑帧闪切文件不混称本轮已观看变体。

下文区分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、135帧、4.5秒，无音轨；查看16帧并检查末49张的解码哈希。未正常速度完整观看、试听、运行上游或制作原创镜头。固定卡与main代码／媒体各自作为证据，不冒称同版执行。案例数值不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先设计每一档为什么存在

| 档位 | 本级观看任务 | 下一档应增加的认识 |
|---|---|---|
| 全景 | 确认页面、集合、对象原位 | 具体看哪一块 |
| 中景 | 认出目标卡／字段组 | 目标里哪个信息最重要 |
| 近景 | 读关键名称、数值与条件 | 接解释、对照或实际操作 |

**制作推导**：三档是案例组织，不是必须数量。一个字段在中景已经足够清楚，可以直接停。长文、复杂图表不能用强制聚焦替代阅读；跳近后必须有足够稳定时间，尤其不能把单位、时间范围或条件裁掉后只留下大数字。

与 [连闪定格](beat-cut-moves.md) 的区别是：这里坚持同一支点，主要变化是观看距离；连闪可以分别安排不同取景中心和摄影式预备。这里也没有真正重映射场景时间，主要是空间尺度阶梯，不能把所有跳切都叫时间轴冻结。

## ２．三档共同美术：同一页面，主角逐渐明确

### ２．１　全景是可信的页面组织

**源码可见**：浅灰画布、左220宽深侧栏、72高顶栏，下方3×2网格、内边距36、缝28。六张卡有不同信息形态：曲线、列表、柱形、进度、活动格点、会话曲线。目标为第二行中间的Deploys卡，浅白面、深墨数值、靛蓝局部格点。

整页数字来自确定性示意内容，不是本项目真实部署记录。全景的任务是交代组织与来处，卡里的小字在这一档只当层级和身份，不要求同时读完六卡。

**抽帧可见**：一档看完整控制台；第二档保留目标与左右邻居；第三档目标卡明显占主位，邻卡只剩边缘。页面内容没有每跳一档就换成另一版本，身份保持连续。

### ２．２　近景仍然需要排印与负空间

目标有名称、1284数值、12周条件、小格点图与底部辅助信息；选择环沿卡边，颜色靛蓝，与图表同色域。近景不另盖一张说明卡，主角来自原页面自身。

**制作推导**：先审最后一档的字框与边界。卡可以大，不意味着每一部分都要被读；关键认识若是“近12周1284次”，数值和时间条件必须同时留下。若目标是看活动分布，就让格点和条件成为主位，数值不必更大。静态构图先成立，再决定35／70的跳切。

### ２．３　高亮是导演引导，别擅自改产品选中态

源码在目标外另叠1.5px环与弱晕，最后一档70→78从0.42加深到0.85；它是额外视觉层，不是FakeDashboard内部真实点击事件。原注释称它“真实选中态”不能据此推断产品真的被选中。

**制作推导**：真实截图上可以加导演定位框，但要与原产品状态区分，不让观众误以为刚发生选择或过滤。没有操作意图时不要配鼠标点击或成功音。高亮结束后保留的若是教学指示，而非软件状态，应在画面语境中清楚。

## ３．固定支点的完整几何

**源码可见**：名义倍率1／1.6／2.6，35与70帧直接切换，无尺度插值。内层用CSS zoom，并设：

```text
left = originX / scale - originX
top  = originY / scale - originY
```

zoom同时放大left／top，因此任意世界点p最终为`origin＋scale×(p−origin)`，支点屏幕位置保持不动。外层的微推也以同一origin为中心，不能只设transform-origin却忘记布局级zoom自身的偏移。

当前origin约1071.005／817，不在屏幕中心960／540。目标保持原来偏右下的位置，而非每档都重新居中。这样保留原位记忆，也意味着近景下缘余量较小，要检查关键信息是否被裁。

### ３．１　原代码的卡宽近似与实际网格有小差异

3列实际宽为`(1920−220−72−56)／3＝524`，Fixtures也用524；镜头文件写524.67，导致目标左缘和中心有约0.67／1.005的偏差。放到2.6倍仍是几像素级差异，不必夸大成严重错位，但不能把硬编码坐标当永远精确。

**制作推导**：实际材料的布局数据与取景锚点同源。换分辨率、列数、侧栏或字体后重算目标框；不要把旧截图上的1071／817照搬到新页面。框的边宽、圆角和外扩也要按完整屏幕投影检查，不能只让中心对上。

### ３．２　名义档位之外还有0.8%微推

前两档各35帧内1→1.008，第三档70→86在16帧内完成同样微推。实际总倍率末态分别接近1.008、1.6128、2.6208。跳档时微推进度重置到1，但名义尺度同时改变，跳变仍是一帧发生。

**制作推导**：如果想精确比较同一尺寸，不加这层微推；如果微推只提供环境活性，就不把档内称完全冻结。目标近景需要像素级测量时，固定尺度更合适，不能拿2.6名义值直接计算所有后续注记位置。

## ４．两帧暗脉冲与阅读层的收束

35—36、70—71，内容层brightness0.92，随后直接回1。不是白闪，不是渐变交叉，也不改变HUD暗角。作用是给跳档一个短促视觉顿点，不是必要的现实光效。

暗角随档位0.10／0.14／0.18收紧，中心横向跟目标、纵向约0.56；它用于退环境，不能把目标的浅灰条件文字压到难读。最后一档高亮70→78完成，微推70→86完成，颗粒从86起包Freeze固定驱动帧。

| 画面阶段 | 实际范围 | 阅读与运动 |
|---|---|---|
| 一档 | 0—34 | 页面整体建立，微推仍在 |
| 第一跳 | 35—36暗脉冲 | 名义尺度已1.6，没有补间 |
| 二档 | 37—69 | 认目标与邻居，微推继续 |
| 第二跳 | 70—71暗脉冲 | 名义尺度已2.6 |
| 近景收尾 | 72—85 | 环与微推分别完成 |
| 尾段 | 86—134共49张 | 源码各主要视觉通道固定 |

**证据边界**：末49张压缩媒体解码得到48种帧哈希，不能宣称当前MP4逐像素一致。压缩、颜色重建等因素可造成差异，本轮没有据此归因为某个代码问题。源码冻结关系、解码字节相同与正常观看静止是不同判断。

**制作推导**：冻结时检查颗粒、噪声、光晕、计数、插入符等全部通道，不只锁相机；但不为追求哈希一致误伤正常压缩视频。要求视觉安静就按真实播放检查，要求原始帧完全一致则另外用未压缩输出验证。

## ５．关键帧审查

实际查看0、20、34、35、36、37、54、69、70、71、72、78、85、86、110、134。

| 帧组 | 抽帧可见 | 应审查 |
|---|---|---|
| 0、20、34 | 同一页面与目标原位 | 是否先建立来处，目标是否已经能找到 |
| 35—37 | 一帧跳近及短变暗 | 支点有无漂、是否误像播放器丢帧 |
| 54、69 | 中景保留邻居 | 中景有没有新增阅读价值 |
| 70—78 | 再跳近，环变强 | 数值、单位／时间范围是否仍完整 |
| 85—134 | 近景稳定在目标 | 真正阅读窗口、边界和下一镜 |

静帧不能认证两次跳变的语气和tick听感。本媒体无音轨，不能说声音踩拍已验。也不能仅凭某位导演风格类比，声称已经研究过其电影原片。

## ６．原创演绎：在真实表格中定位“单位”

以下为**制作推导**，未实现。教程要说明读数不能漏看单位。起点是一张真实材料表，目标是某列标题旁的“万元”；要先确认材料内容与单位确实如此，不临时造一个表当真实数据。

### ６．１　先设计近景与美术

保持原表纸白与深墨，目标列头、单位和第一行数值同时进入近景；淡砖红细框圈“万元”，不把整个数值染红。画面外部暖灰`#e8e4dc`，说明“数值与单位一起读”36px放在空白区，不能压列头。

全景提供表名、来源、列组织；中景提供目标列和相邻列关系；近景读单位与数值。这比“突然跳到一个红色万元字”更能保留表格语境。真实表格若列头太拥挤，可另设端正放大窗，不硬把整个页面推到出画。

### ６．２　完整调度与同一支点

| 段落 | 画面 | 新认识 |
|---|---|---|
| 全景建立 | 材料名、表格与目标列清楚 | 知道这是什么数据 |
| 第一跳 | 目标列与相邻列成为主位 | 认出需要读的列 |
| 中景停留 | 原数值不变，单位尚不强亮 | 允许建立位置记忆 |
| 第二跳 | 同一支点跳近，单位细框建立 | 明确单位是判断的一部分 |
| 稳定读取 | 数值与单位完整，所有临时运动停止 | 读到准确含义 |
| 下一镜 | 用同一真实单位解释数值换算 | 从聚焦进入实际知识 |

以实际单位框中心作origin，先检查它偏画中还是偏边。如果同支点会裁掉源表名，可在全景先读清、近景用小型来源标签保留身份；若单位位置太偏，另选一次带理由的重新取景，不假称仍是同支点跳切。

### ６．３　几何、取样与声音

假设单位框源坐标左1120、顶240、宽96、高36，中心1168／258。倍率2时该中心仍在1168／258，不会自动到960／540；若要居中，就需要明示平移与共同端点，而不是只复制本例公式。倍率选取从“单位、列名、第一行值”的完整包络倒推，不套1／1.6／2.6。

源字24在2倍后48px，但位图是否清晰仍看输入分辨率；原生文字或高清材料更可靠。高亮跟源字框同一映射，框边与页面不同scale时要决定保持屏幕线宽还是随图放大，两种不能无意混用。

两跳各一声很轻定位音即可，最后读单位时让人声主导。不能配成功音，因为本镜只看清内容，没有修改数据或完成操作。真实素材、中文排版、原创实现与全速观看／试听目前均待验证。

## ７．失败诊断与合格判据

| 失败 | 修正 | 可观察的通过证据 |
|---|---|---|
| 跳大两次却没新增认识 | 删多余档，先定每档阅读任务 | 每一跳都指向更具体的信息 |
| 每档支点漂移 | 共用源锚点与完整变换 | 同一对象保持位置记忆 |
| 最后只剩大数，没有单位 | 从必要字段包络倒推倍率 | 本镜要求读的条件完整 |
| zoom后标注偏几像素 | 从实际布局取框，避免近似常量 | 最快跳变前后框都贴准 |
| 环被误认成真实选择操作 | 区分导演提示与产品状态 | 不发生不存在的点击／筛选 |
| 声称冻结但颗粒仍动 | 核所有驱动通道与实际播放 | 阅读段符合安静目标 |
| MP4哈希不同就认定动画没停 | 分开原始渲染与压缩重建 | 结论限于实际证据 |
| 两跳后立刻切走 | 从最后一项变化结束重排停留 | 正常速度能读完整关键内容 |

Storyboard应交代每档新认识、固定支点、三态构图、完整字段、真实高亮语义、冻结范围及下一镜。静帧、全速、声音和真实内容分别验收；本文不宣称原创或商用成片已通过。
