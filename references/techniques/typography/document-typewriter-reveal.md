# 文档逐块写入：从可读局部退到完整应用窗口

## 1．这不是逐字生成模型的录像

原例使用已排版截图，按内容块揭开，再显侧栏和历史条目；相机从斜侧局部后撤为全窗。它适合展示文档形成与组织，但不能证明文字真的由系统生成，也不能用5秒镜头要求观众读完20块正文。需要解释的句子必须另留近景与阅读时间。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/typography/document-typewriter-reveal.md)、[准确实现](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/ui-entrance/document-typewriter-reveal/DocumentTypewriterReveal.tsx)、[页面几何](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/_textures/live-layout.json)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/document-typewriter-reveal.mp4)。原卡位置在typography，准确组件在ui-entrance。源码可见覆盖法与相机，抽帧可见150帧的16幅阶段；原创为制作推导。未正常速度观看、试听、运行上游或原创实现，未将截图文字当业务事实核实。

## 2．文档本体先有出版质量，舞台再提供空间

页面1920×1080，左栏208、右栏288，正文有20块真实排版位置。暖白纸#fefcf9放在冷紫夜场，窗口圆角26、1.5亮边、顶沿细光与长投影；背光在页面空间Z−40，随页面同样透视。若背光作为屏幕贴纸不随窗口走，就会显得像抠图悬浮。

正文要有标题、段落、列表、分区和可辨缩进；「大量小字」不是细节充分。关键句应在近景读清，后撤全窗只负责建立正文与双栏的组织。历史行13／11／10px是应用缩略信息，不能把它当必须阅读的教学说明。底部84px标语若抢走正文解释，应撤掉或缩小，让实际内容继续成为主角。

原样片可见姓名与研究条目，本篇只研究版面，不推断其真实性或授权。当前制作应使用允许展示的真实资料或明确示例，不能把他人截图里的身份、数据照搬到自己的内容。

## 3．覆盖块、唯一笔尖与强调底

每对内容块cue=`8+floor(i/2)×4.4`，每块9帧擦开。20块最后一对cue47.6，到56.6完成；两两并行，所以不是单一笔尖真逐字走过全部字。程序始终只绘制索引最大的活跃caret，成对同cue时落在后一个块；这会发生笔尖跨块跳转，不能声称一条连续书写轨迹。

遮罩用实测纸色，右锚width100%→0；普通块左扩4、右侧额外覆盖防粗字尾巴露出，列表左扩28把marker一起盖住。底色、纹理和阴影若不均匀，纯色补丁会露矩形；应改为匹配底材的局部补丁或直接逐块重绘，而非假装只有文字变化。

caret宽3、最高22，位置不超实际文字右缘，写完2帧退；不能沿多盖的120px空白继续空写。成员小标题在写完4帧后，8帧长出紫色multiply底，避免洗浅黑字。源码根据第一个之后的h2判断，并未识别人名文本；换资料需按真实语义标注，不自动把全部小标题当人物。

## 4．侧栏、历史与相机共同分配注意力

左栏54～64，右栏62～72向下揭开；各内缘线在cue+10到+24退。原卡「侧栏64完成」只适用左栏，不能说右栏也已完成。六条历史66／71／76／81／86／91起，每条9帧，最后100。历史盒子使用`air=max(0,1−t)`，虽然曲线有>1过冲，位移被air截断，**不产生向下超出终点的可见回弹**，不能照注释写成物理弹跳。

相机逐参数单调Hermite：f0 zoom1.42、rotY−18／rotX8，关注(690,320)；26为1.24；64为0.86、双栏入画；104为0.74、上移78、rotX9；150为0.746、上移80。zoom走布局级，透视距离2200也按zoom缩放；平移把目标页面点送到屏幕中心偏移。窗口、背光、笔尖与条目必须在同一页面空间，底部标语是屏幕层。

100起的第一段标语两词、each16／gap3，到119；108起第二段到127，非注释126。整个窗口继续慢移／缩放，舞台呼吸与尘点持续，不是真静止。抽帧0仍见窗口左上边和暗场，60左栏出现右栏未完整，79双栏可见，119标语尚有尾部动作。不能把全窗缩略图当全文可读证明。

## 5．原创演绎：让一篇可核查的会议摘要形成结构

**目标。** 教观众把一段资料组织为主题、决定和待办，并保留来源。不虚构历史记录、不暗示一次自动生成就准确。先设计最终文档：真实标题、三类有内容的段落、每条决定对应出处；右栏只保留必要来源，左栏为实际版本。下一镜点击一条来源核查。

**美术。** 页面选适合中文阅读的字体和行距，用真实段落长度排版，先圈定一个会在近景读的关键句。深色舞台只托住纸面，主光和投影方向统一；强调底仅给当前决定或人名之一。不要同时给所有标题染紫，最后变成满页彩条。

1. 开始从文档标题和一段真实原文建立，窗口边界入画，让观众知道这是应用文档而非全屏字幕。
2. 按语义块揭示主题、决定和待办，关键句慢下来；非重点可成组出现，不能所有块同样戏份。
3. 后撤显示各块如何组织，侧栏顺次接管来源与版本，不同时弹一屏历史。
4. 历史列表只来自实际保存记录；没有历史就省略。保留不确定内容，不用高亮冒充核实。
5. 回到一个决定近景，下一镜打开其来源，证明摘要忠于原文。窗口全貌只承担结构理解，证据阅读交给近景。

声音建议书写段有连续但低音量键盘质感，停止揭示即停止；历史项可以递减轻声，未实际试听前不宣称六连pop准确。原卡音频来自其他模板调用，本演示mp4本身无音轨。

## 6．原创文档的关键画面与阅读容量

| 画面 | 具体安排 | 此时不要求读什么 |
|---|---|---|
| 标题近景 | 文档名、一个主题句与窗口边缘同框，光只托纸面 | 全部侧栏和历史 |
| 主要块写入 | 先主题、再决定、后待办，关键句的主体与条件都完整 | 未出现块的小字内容 |
| 全窗结构 | 三类段落有清楚标题／间距，左右栏同属一窗口 | 每条历史的全部元数据 |
| 核对局部 | 一条决定放大，来源标记在相邻位置 | 大口号和所有无关工具 |
| 来源接棒 | 同一引用进入原文定位，关键句仍可辨 | 「自动生成很快」等无关宣传 |

未实现的教学草案可以使用明确标注的模拟会议：决定只写一个方案、待办写一个负责人角色和一个实际动作；不凭空填真实人名、截止日期或批准记录。关键句的阅读窗口由口播与中文长度决定，不能把20块同时逐步揭示当「每个字都读清」。如果最后需要解释三条待办，就拆成三个内容镜头，窗口后撤只作为结构总览。截图与DOM补绘交界处检查字体灰度、行高、左右内边距和纸色，缺任何一项都会像另贴了一层假UI。

## 7．失败与通过证据

| 失败 | 修正 | 通过时看到 |
|---|---|---|
| 圆点、粗字尾提前露出 | 校准块边界与marker留量 | 尚未写入区域没有残字，补丁不露矩形 |
| 多根笔尖同时写 | 明确唯一活跃块，检查成对覆盖关系 | 只有一个视觉焦点，不误称连续真打字 |
| 全窗完整却没人读得清 | 挑关键句近景，正文结构与细读分镜 | 观众知道组织方式，也能读到一条真实内容 |
| 历史行与截图错位 | 共用页面坐标、真实行高和基线 | 原有条目与新增条目看起来属于同一应用 |
| 相机退远后只剩标语 | 撤无关口号，安排证据接棒 | 结果文档和真实来源仍是主角 |

验收标题近景、半写入、侧栏未全出／全出、最后历史、标语完成及来源近景；还需正常速度、口播阅读、真实资料和声音审核。与 [文档到要点](../../examples/document-to-key-points.md) 配合：本篇讲文档形成和空间展示，不能代替后者的证据到论点设计。
