# 文字作为观看窗口：从读词进入真实画面

本镜让文字轮廓保持可读，画面只从笔画内部透出；随后文字遮罩放大，内部世界接管全屏。关键不是把一个词放到46倍，而是让字形与产品画面分开运动、让进入方向有实心支点，并在接管后得到值得观看的完整构图。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/opening/text-as-mask.md)、[TextAsMask.tsx](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/opening/text-as-mask/TextAsMask.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/text-as-mask.mp4)，另核对 [Look](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Look.tsx)、[Polish](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Polish.tsx) 与 [Brand](https://github.com/Vincentwei1021/video-shotcraft/blob/main/demos/_fixtures/Brand.tsx)。固定卡、main代码、当前媒体各自作为证据，不混称同版运行验证。

本文分**原卡给定、源码可见、抽帧可见、制作推导**。样片1920×1080、30fps、165帧、5.5秒，无音轨；查看16帧并复算接管阈值。未正常速度完整观看、运行上游或实现原创镜头。案例参数不替代 [质量规则8.6](../../../docs/VIDEO-PRODUCTION-RULES.md)。

## １．先定词与世界之间的内容关系

| 使用任务 | 成立条件 | 常见失效 |
|---|---|---|
| 从章节词进入对应产品 | 字内画面确实属于该章节 | 随便塞一个无关炫彩循环 |
| 规模、连接、结构等概念开场 | 完整画面随后给实际证据 | 用虚构滚动数字当真实能力 |
| 品牌名与主视觉统一 | 字形轮廓有足够面积容纳画面 | 细字重只露几道难辨色线 |
| 精确阅读界面或数据 | 接管后安排稳定阅读态 | 要求观众从字缝里读完正文 |

**制作推导**：字内阶段通常只看质感、方向和结构，不读细项；全屏之后才核内容。如果口播在解释具体数值，提前进入正视画面，不能拖着遮罩等转场结束。它是章节连接，不是每段必用的表现方式。

## ２．两张静态画面都要先成立

### ２．１　标题态：大笔画是窗口，负空间保证读词

**源码可见**：五字母词，系统字体900字重、470px、字距−22、基线y712，横向居中。舞台瓷白，眉题在y214，30px字标与44px标志；副题在y804，40px，关键短语较重较深。字形下另有同轮廓的带蓝软影，向下26、22px模糊、20%透明，像一扇挖入亮舞台的深窗。

**抽帧可见**：标题读作深色超粗词，蓝青曲线穿过腰部，面积图给下半笔画颜色；外围亮底与暗字内世界形成明确边界。图像没有把字轮廓破坏成碎纹理，字仍是第一个阅读对象。

**制作推导**：先看黑白轮廓，再看字内取景。中文笔画密、字腔小，可能只露出许多不连续小洞，不一定适合；可用更短词、更厚字或自定几何题字，但要保护可读性。不要给字另加多重高光描边，轮廓重叠可能暴露字体内部构造。

### ２．２　接管态：完整产品必须有自己的主次

**源码可见**：内部是手工构造的渲染看板，不是真实服务截图。背景`#0a0f1e`，面板由`#131d3b`到`#0f1730`，文字浅蓝白，次字灰蓝，强调蓝`#4d7cff`和青`#19d3b4`。左侧230宽导航，主内容从x290开始，上方页名与三块指标，中部大面积图，下方四类进度。

主图卡1570×470、顶376，曲线区1560×380、97个样点，5px蓝青线加渐变面积与末端圆点。大色块和亮线适合从笔画里被辨认；浅白产品页面放进浅白舞台，会降低“里面有世界”的识别度。

**制作推导**：真实产品浅色界面不宜未经说明强改暗色。可以改外围为深底，换能体现结构的真实局部，或选择另一技法。为了窗口有颜色而重绘一个与产品不符的假界面，会牺牲教程准确性。最终全屏的标题、数据来源、图表单位和状态必须独立审查，不能只因转场好看就通过。

## ３．遮罩资源：透明底与黑底不是同一件事

**源码可见**：文字生成SVG data URI，内部只有白字，字外默认透明。CSS mask-image使用这张图。原卡有“白字黑底”的概括，但当前SVG没有黑色背景矩形；在alpha遮罩中，黑色若仍不透明并不会自动成为洞。

**制作推导**：先确定遮罩以alpha还是亮度解释，再制作资源。字外必须正确透明或明确采用luminance，不让整个1920×1080矩形都可见。字体必须在实际遮罩环境中可用；系统字体回退会改变字宽、笔画厚度和支点位置。运行时看到主文字与影子不同字体，也会出现错位。

文字遮罩与软影使用相同排印参数。换词、字体、字距或画幅时，两者一起更新，不拿旧影子套新标题。真实字体／最终环境未实排前，不保证注释里的某笔画坐标仍正确。

## ４．字形和内部世界必须分层

### ４．１　外围放大，内部做精确逆变换

**源码可见**：遮罩wrapper以origin1236／546为中心，做平移d与缩放S；内部层用同一origin，反过来写`scale(1／S) translate(−d)`。CSS复合变换的逆必须反序，不能写成同方向或任意调换。

```text
外围：T(d) × ScaleOrigin(S)
内部：ScaleOrigin(1/S) × T(-d)
合成：内部产品的整体尺度与位置不被遮罩放大带走
```

内部真正想要的产品取景，另由dash层自己的平移与1.32→1尺度控制。逆变换只抵消门的几何运动，不抵消产品本身的设计动作。两个通道混在一层会把界面文字放大几十倍，结束时难以回到标准构图。

### ４．２　支点要在实心笔画里

原实现选L竖笔中线1236／546，注释给该笔画大约x1195—1278、y383—709。支点若落在A字腔等透明处，放大后屏幕中心仍是舞台底色；“钻进字”与“放大字腔”不能混用。

同时d＝(960−1236，540−546)×rush，把实心笔画拉向屏幕中心；只围绕偏右支点缩放，左缘可能迟迟盖不到。换词后必须测实际实心区域和到四边的覆盖距离，不能只把origin改成新词div中心。

### ４．３　无蒙版接管层必须共享同一画面

冲入后段另叠无遮罩的同一dash层，透明度仅在rush0.86→0.95建立。两层用相同帧、平移、缩放与数据，交接时不会忽然换图、换时间或换内容。

**制作推导**：提前淡入会把亮舞台覆盖一层半透明暗图，像灰纱，破坏从字内自然接管的关系。接管层的任务是补齐字缝和边缘，不是掩盖支点选错；先证明实心笔画足以覆盖，再开保险层。

## ５．完整时序与参数实际意义

| 阶段 | 当前源码 | 注意事项 |
|---|---|---|
| 入场尺度 | 0→18，1.04→1 | 不与接管46倍视为同一段 |
| 初始裁切 | 0→16，底部裁去706.4→0 | 实际可见下边界向下扩，不是从基线上升的文字位移 |
| 眉题／副题 | 6→26、14→32 | 文字与遮罩各自完成 |
| 字内取景 | 18→96，x150→−150、y−110，尺度1.32 | 面板自己仍有内容动画 |
| 吸气 | 96→104，遮罩1→0.965 | 眉题／副题退场96→106，稍跨入冲入段 |
| 字形冲入 | 104→128，0.965→46 | 对数空间按线性时间的1.8次幂推进 |
| 产品归位 | 104→132，尺度1.32→1、漂移归0 | 比冲入晚4帧，不是注释的6帧 |
| 全屏阅读 | 132—164共33张 | 曲线、柱形和在线点仍在动 |

**制作推导**：原卡平均漂移300／78约3.85px／帧，只是未计缓动和产品1.32尺度的参数平均，实际屏幕速度不恒定。若必须跟踪字内某个特征点，应用完整变换求屏幕轨迹，不据这个均值认定可读。

## ６．指数冲入和接管阈值复算

设线性时间u＝clamp((frame−104)／24)，p＝u^1.8，则`S＝0.965×(46／0.965)^p`。这是对数尺度上的加速，不是线性把S从0.965插到46。

| 帧 | p约值 | S约值 | 接管层透明度 |
|---|---|---|---|
| 104 | 0 | 0.965 | 0 |
| 120 | 0.4820 | 6.2146 | 0 |
| 124 | 0.7202 | 15.6044 | 0 |
| 126 | 0.8550 | 26.2701 | 0 |
| 127 | 0.9263 | 34.5935 | 约0.7362 |
| 128 | 1 | 46 | 1 |

接管起点p0.86对应约126.071帧、S26.780；完成p0.95对应约127.326帧、S37.918。因此整数输出只在127出现中间透明度，128全满，**不是代码注释“约121—126”**。不能把这段当作五六帧的慢交叉淡入。

按注释中的竖笔矩形估算，p0.86时竖笔屏幕横界约−99.33到2123.39，已覆盖1920宽；该估算依赖实际字体笔画矩形，不能替代字形实排。纵向覆盖、字边弧度、抗锯齿及画幅变化仍要另查。

**制作推导**：把接管阈值从最终字形覆盖反推出来，不先定透明度时刻再勉强加倍率。另测冲入最末几帧的速度跳变、字体边缘与图像采样，不能只看128已经全屏。

## ７．内部动画不是实时服务证据

**源码可见**：面积图由固定正弦组合生成，frame×0.55控制相位，表示样本向左流；没有接入真实渲染数据。1.92M→2.48M由固定进度推算，42秒、−18%、四类进度、24条呼吸柱也是构造内容。

**制作推导**：实际教程只能展示真实测量或明确标识的示意。动态图表必须有量纲、时间和数据来源才能承担解释；没有依据时，换成真实作品／照片／代码画面，或让图形只作抽象视觉，不给它真实业务数值与Live标签。

132以后产品取景归位，但曲线、柱和在线点仍在变化，不能写“完整面板冻结33帧”。需要读某个数值时，可以冻结相应数据或另选稳定页面，明确这是教学暂停，而非真实系统停止。

## ８．关键帧观察

实际查看0、8、18、32、60、96、104、112、120、124、126、127、128、132、148、164。

| 帧组 | 抽帧可见 | 应审查 |
|---|---|---|
| 0—32 | 冷白舞台、超粗词、暗内容亮线、上下辅助字 | 字形是否完整，字内图像能否读成独立世界 |
| 60、96、104 | 同一词里曲线位置变化，吸气后准备冲入 | 内容与字形运动是否分开，字号是否误缩正文 |
| 112、120、124 | 大字边界逐渐溢出，画面保持正常界面尺度 | 中途大白缝是否有意，支点是否在实心区域 |
| 126、127、128 | 全屏看板建立 | 换层是否闪灰、跳位置或跳时间 |
| 132—164 | 标准面板构图，图内仍有变化 | 阅读任务、细字与实际数值是否成立 |

静帧和公式能查遮罩几何与交接状态；完整速度的冲入是否舒服、明暗变化与声音是否协调，仍需真实播放。本篇不以未运行的逆矩阵描述代替实际引擎验证。

## ９．原创演绎：从“细节”走进照片的真实纹理

以下为**制作推导**，未实现。摄影教程要说明“判断锐度应看同一张照片中的具体纹理”，标题阶段只建立主题，接管后必须给可判断的实际纹理，不使用虚构仪表板。

### ９．１　先设计照片近景结果

选择已获许可、清晰的织物／木纹照片，实际源图至少覆盖预定输出取景；光线以侧光显示纹理，主体在中右，左侧保留可解释的纹理区。背景用深棕`#1b1814`，两字标题“细节”先以160px左右的厚黑造型实排，暖白辅助句“在同一位置看清变化”。不要套470px英文与硬编码L支点。

标题内部只透出纹理和一条有意义的边界，不透大量小字。字形本身保持可认，选择一块足够厚的实心笔画作为门；若两字无合适大实心区域，就改用一个几何粗体字或另一种转场，不能为了技法把字形改坏。

### ９．２　完整导演链

| 阶段 | 画面 | 内容上的变化 |
|---|---|---|
| 前镜 | 已建立原始照片与文件身份 | 素材是真实同一张 |
| 标题窗 | “细节”内看到纹理，小幅平移只为揭示材料 | 先认识观察对象的质感 |
| 准备进入 | 辅助句退出，字形轻收，不新增说明卡 | 焦点集中到纹理区域 |
| 接管 | 遮罩扩展，照片反向补偿保持正确比例 | 字成为观看入口 |
| 阅读结果 | 同一纹理以清晰近景静置，标明源图位置 | 观众知道正在检查哪里 |
| 下一镜 | 在同一位置显示确有依据的两种处理结果 | 进行真实锐度判断，不靠模糊伪造优化 |

不要把字内漂移误当“自动增强中”，也不在接管时显示处理成功。只有实际处理与结果存在，下一镜才安排前后对照；对比设计见 [前后滑杆](../comparison-and-data/before-after-slider-scrub.md)。

### ９．３　取景与几何同源

假设源图4000×2500，最终截取源矩形左800、顶500、宽2400、高1350，等比0.8得到1920×1080。字内与全屏共用该源矩形，内部轻漂移以该世界为基础，不在接管帧换另一张裁切。

新字形先导出可核对的alpha遮罩，选取实心支点并测它到四边的距离，求覆盖所需尺度；再反推接管阈值。遮罩与影子同源，内部照片与接管层共用同一取景、时间和数据。原始4000宽能否满足字内预备放大，还要按实际内部尺度检查，不能从“4K照片”直接推出全程清晰。

进入最终纹理阅读时，相机与临时光效停止，正文注记端正且不遮纹理；语音讲具体纹路，音效只在接管做一次很轻的气流。当前没有实际照片、字形、音频与原创实现，以上是导演设计与后续验证任务。

## １０．失败诊断与通过条件

| 失败画面 | 修正 | 可观察的通过证据 |
|---|---|---|
| 白底字内也是白界面，像普通文字 | 改外围对比或选真正有结构的内容 | 同时读得出词和字内世界 |
| 字外整块都透出画面 | 检查alpha／亮度语义与资源背景 | 只有笔画区域可见 |
| 字形放大后中心仍是空洞 | 重选实心支点并核覆盖 | 中心进入实际内容而非舞台底色 |
| 产品被字一起放大46倍 | 分离wrapper与精确逆变换 | 界面尺度只服从自身取景 |
| 无遮罩层提前造成灰纱 | 按字形覆盖反推接管阈值 | 亮底不经过无意义半透明暗层 |
| 128后位置仍跳 | 同源取景、帧与归位进度 | 两层交接无位置／数据／锐度突变 |
| 变字体后原origin失效 | 在实际环境测笔画而非照抄坐标 | 必要边界在目标帧被完整覆盖 |
| 动图被误当真实性能 | 换真实内容或明确示意 | 数值与状态能回到证据 |
| 转场完成却没有可读内容 | 先完成最终构图与下一镜 | 接管后立即进入具体观察任务 |

Storyboard应交代词与内容的关系、两端美术、透明遮罩、实心支点、逆变换、接管覆盖、实际阅读任务和下一镜。静态、全速、声音与真实素材分别验收；当前不宣称原创或商用成片已通过。
