# 误删重打：把一次改口拍成有内容的修正

## 1．打字只是载体，修正必须有意义

先打出旧表述、停顿、退格，再更快写出新表述；保留前缀使观众认出同一句在修正。适合讲一个实际措辞／条件错误，或一次明确的概念转折。不能把所有观点都做成「先贬低再夸大」，也不能伪称这是用户实际键盘录像。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/typography/typewriter-moves.md)、[TypewriterErrorRetype](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/typography/typewriter-moves/TypewriterErrorRetype.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/error-retype.mp4)。原卡给定三幕与三档速度，源码可见字符计数、光标和保留前缀，抽帧可见160帧样片16幅阶段；原创为制作推导。未正常速度观看、试听、运行上游或原创实现。

## 2．排版先固定最终句的边界

100px／600等宽，字符槽60，最终24字符宽1440、left240；输入过程中左缘固定，不随当前字符串长度居中。光标6宽、4px左距，随实际字符数站在句末；上方34眉题与同左轴，底为浅柔光、淡靛蓝和暖色余光。

这保住了「正在修改同一行」的身份。字体、字号、固定槽和基线要一致；中文不能继续用60宽装100px全角字，要以实际字形或语义组重新测量。长句超1440时应拆段／减字，不能让光标出画后还继续打。

最终强调底在全句第10槽起，长度14槽，下半身36px高，放在文字下层，不洗浅字。原例位置是按固定英文字符索引写定，换词必须重算，不把固定HL_FROM当「自动找到卖点词」。

## 3．准确计数与光标表演

第一句16字符，f2开始，每2帧添一个：第一字符在2，最后在32。32～48停顿，光标4帧亮／4帧灭两轮；48起每1.5帧删除，计数含起始帧的+1，第11个删除在63，64已只剩5字符前缀。原注释64.5是按不含起始字符的另一种口径，不能混用。

重打68起，19字符每1.5帧添一个，95完整，最终句为保留5＋新19＝24；不是把整行清空。删完到重打有数帧小停，原卡所谓「零犹豫」指重打过程无额外停顿，不是删除结束同帧立刻写。

| 帧 | 字符／光标／标记 | 观看目的 |
|---|---|---|
| 0～1 | 行空，仅光标 | 建立输入位置，不是完整字卡 |
| 2～32 | 第一遍2帧／字符 | 让旧表述能读到，不为删而赶 |
| 32～47 | 两轮短闪 | 给观众理解和质疑的空隙 |
| 48～63 | 逐尾退格到保留前缀 | 明确修的是哪一段 |
| 68～95 | 1.5帧／字符重写 | 新表述更果断，但仍须真实可读 |
| 95～109 | 光标亮95～99、105～109 | 完稿两轮，不再无限闪 |
| 96～110 | 强调底长满 | 和完稿光标并行，不开启第二场大动画 |
| 110～159 | 光标视觉已灭、主体完成 | f115才逻辑永久关闭；背景颗粒仍动 |

抽帧42旧句完整、53已删尾、64只保前缀、85新句途中、95完整、106强调底已展开。源码保证字符离散变化；正常速度是否像自然改口，仍需完整观看与声音。

## 4．原创演绎：把模糊指令改成能执行的具体要求

**目标。** 教观众从「整理一下」改为明确的对象、依据和输出。先设计最终态：一条真实可执行指令及对应输入资料；下一镜按指令实际得到可核查结果。改口不是替工具写万能承诺。

**美术。** 保留中性输入框或文档语境，正文等宽／实际界面字体一致，强调底只给补充的限制条件；不用上游品牌眉题。中文输入若要拟真，需考虑输入法候选和组词，不能把逐汉字硬切当真实键入；本镜可明确作为文字说明层。

1. 显示旧指令，指出缺少哪个条件，例如按什么分类、输出到哪里；未知需求不凭空填。
2. 停顿让观众发现模糊处，只删需要改的后缀，保留对象身份。
3. 重写为具体条件，速度差服务果断感；约束词与标点完整，不为了动效省略否定条件。
4. 新句完整后轻标条件，再展示实际输入和执行，不立刻用成功勾替代过程。
5. 下一镜核对实际结果是否满足这些条件；若有例外，回到相应词句修正，让改口有事实依据。

此设计未实现。键击拟音应按可见字符事件而非每帧等响循环，退格用不同轻音色，停顿时安静；新中文词组不必每字一声。音轨尚未制作，不能声称逐键同步。

## 5．原创指令修正的关键画面

| 状态 | 文本与构图 | 观众得到的新认识 |
|---|---|---|
| 旧指令 | 左轴固定，短句完整可读；真实输入缩略在侧 | 哪里含糊，为什么需要条件 |
| 犹豫 | 光标短闪，文字不晃；指示只圈缺少条件的范围 | 修正有具体原因 |
| 删除 | 保留对象／前缀，尾部逐字退格 | 不是换题，是修改同一要求 |
| 新指令 | 明确对象、条件、输出，强调底只给新增限制 | 可以执行和检验的要求是什么 |
| 执行结果 | 实际资料与结果对应，文字转小标签 | 新指令是否真的有效 |

尚未实现的教学草案可将「整理这些文件」修为「按扩展名分组，保留原文件名」，明确这是示例要求。删除范围按语义决定，不为复刻KEEP5留下不通顺前缀；若需要改整句，就清楚展示全句重写，而非硬保几个字。结果画面应看见真实分组与保留的文件名，最好跟踪一份主文件，其余简洁呈现，避免变成「完成整理」一张卡。口播与打字文字不完全同文时，优先保证观众不会同时追两种说法。

## 6．失败与通过证据

| 失败 | 修正 | 通过时看到 |
|---|---|---|
| 整行随字数横移 | 按最终宽度固定左轴和槽位 | 同一句在原位修改，光标自然跟随 |
| 删掉了应保留的对象 | 明确KEEP和真实语义边界 | 观众知道修的是条件，而非换了话题 |
| 新句被强调底切错范围 | 从真实文本映射范围，查字槽 | 标记准确落在新增条件，不盖字 |
| 完稿仍闪或留微光标 | 条件卸载，查110／115边界 | 结果阶段不再有输入状态干扰 |
| 只把平庸词换夸大词 | 以具体要求与执行结果收束 | 能检验修正后的指令是否有效 |

验收旧句完整、保留前缀、新句完成、强调范围、最后光标及真实结果；正常速度、输入语义、声音分别验证。文档的50帧主体保持不代表背景全静止。
