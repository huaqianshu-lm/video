# 文字与声音同步：节拍脉冲和口播跟读分别怎样设计

## 1．两种同步依赖不同证据

font-weight-pump让已在场的字随音乐重拍变粗；karaoke-fill-sync让词随口播逐个填色。前者需要真实鼓点，后者需要真实词边界。原例都用写定时间表，官方mp4均无音轨，**本篇验证的是视觉调度机制，不是声画同步效果**。不能凭序列格或伪波形声称听过且已卡点。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/typography/type-rhythm-sync.md)、[FontWeightPump](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/typography/type-rhythm-sync/FontWeightPump.tsx)、[KaraokeFillSync](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/typography/type-rhythm-sync/KaraokeFillSync.tsx)。样片：[脉冲](https://vincentwei1021.github.io/video-shotcraft/media/font-weight-pump.mp4)、[跟读](https://vincentwei1021.github.io/video-shotcraft/media/karaoke-fill-sync.mp4)。分别查看165／150帧的16幅抽帧；源码可见机制，抽帧可见层级，原创为制作推导；未正常速度观看、试听、运行上游或原创实现。

## 2．A的美术：细体空隙与粗体闭合形成节奏

原例主词实际240px，非注释250；细体字重250，峰900，最终780。每字先用900字重隐藏占位，再在槽中心叠可变字重字，使脉冲不改变整行布局。静态细体有字间空隙，命中时笔画填满槽位；字号／字重变化和字形内白一起决定力度，不靠整屏缩放。

深紫舞台、紫粉强调，第一小节只有主行；64～74上下描边回声出现，距离204并被后续拍推开。回声是低权重纹理，不能像两行同样实心的大标题。底部8+1音序格为视觉节奏参照，眉题和BPM次级，不与主词同步抖动。

字重能否连续变化取决于实际字体。组件直接写fontWeight，**并没有实现原卡提出的跳变＋stroke后备方案**。渲染字体若只有离散字重，会出现档位跳；必须实际核对字库、字体就绪和峰值轮廓，不把CSS数值连续误认为字形连续。

## 3．A的包络、真实拍距与收尾

八拍16／30／44／58／72／86／100／114，drop128。30fps每14帧实际约128.571BPM，标示128只是近似；真实128BPM应每14.0625帧，用累计时间映射到输出帧，不能每拍强行减到14导致长段漂移。

`env=(1−t/D)^.8`，中心D9，外侧最大12.2，下一拍14前已归0。回声晚2帧，重音拍0／4额外横撑6%、染粉；drop额外8%横撑，主字从900按各自D+4衰到780，回声drop晚2且推开60再归位。不是把整幅相机也做同节拍泵。

drop渐变按字符取色，128～144光带扫一次；副句136起6词、each14／gap2.5，到162.5，163才完整，片尾165只余2输出帧完整副句。原卡140起hold显然不覆盖副句阅读；需要延长或缩句。Stage颗粒与呼吸持续，不能声称整图静止。

抽帧44主词粗、55细，66回声在形成，131为drop，142副句仍残缺，164完整。静帧能证明属性变化，不能证明变化点与音乐重拍同帧。

## 4．B的美术与词内揭示

浅底两行150px／800，行间1.18、词gap56，未读字13%墨色；当前词强调色，已读词10帧退为深墨，不一直彩色。每词两层同文，上层绝对叠放，用柔边mask从左到右填充；每词独立百分比无需整行总宽换算，但仍须保证字体、字距、换行完全同源。

edge=p×108−4，前后±4%柔边，使p0全藏、p1全露。词内进度线性，不加ease伪造语音起落；下8px读指随p增长，读完6帧从左向右收。读指不留作永久下划线，否则几词读完后满屏线条。

四词20～38、42～75、85～103、107～130，是模拟语速，不来自音频。最后词130填满、136收线、140退色完成，140～149仅10帧主体完整保持，非130起真静止20帧。48根波形高度由预设词时间和hash生成，**不是实际音频振幅**；波形本体不逐帧起伏，只是播放进度改变颜色，136后全染完。

未读字低对比仅用于预告，不能把仍需要提前理解的教学指令放在灰字里；中文分词要以真实发音、停顿与语义确定，不把整句均分或按字数猜时长。标点、数字读法、英文缩写要与实际音频核对。

## 5．原创演绎：音乐段和教学跟读分别如何使用

**A用于解释节奏，而非让所有教程字蹦迪。** 先设计实际拍格、一个短词与真实音频的对应。最终态是短词和可核对的击拍位置，下一镜显示音轨／事件时间。第一小节仅主字，第二小节加弱回声，最后一拍形成完整视觉结论；所有拍点从实际音频取得。若口播正在讲复杂概念，应降低字重幅度或撤脉冲，把注意给内容。

**B用于读清一条真实操作提示。** 先画实际界面局部和一句短指令，指令分语义组、配真实旁白，界面当前操作是主对象。用已生成音频的词级边界驱动填色，不重新按演示帧数朗读。若要显示波形，使用该音频实际采样，并标明它只是时间参照，不代表识别准确率。

B的完整调度：先给对象定位→口播说「先选中」时指令对应短语填色、真实选择可见→说「再调整」时下一个短语接棒、真实参数变化→已读字退墨、临时读指收走→结果保持并让观众检查→下一镜展示参数改变后的真实差异。不要把整段口播压成两行大字在空白底上唱完。

两种设计均未实现。音频先成立，再决定输出帧与视觉范围；句子或音乐长度变化后重建时间，不把固定帧表当最终TTS时间轴。音效不能再盖在每个口播词上制造双重节奏。

## 6．原创声画镜头的画面与证据表

| 状态 | 音乐脉冲镜头 | 口播跟读镜头 |
|---|---|---|
| 建立 | 真实音乐的拍格、短主词，先不加回声 | 实际界面对象与短指令，未读文字可预见 |
| 当前事件 | 字重峰与真实鼓点对应 | 当前短语填色与所听发音对应 |
| 递进 | 第二段弱回声出现，主行仍最亮 | 真实操作接管，已读字退墨 |
| 结果 | 最后一拍形成完整海报，副句有阅读时间 | 最后操作结果稳定，读指与临时波形退弱 |
| 下一镜 | 进入真实音轨／事件时间说明 | 查看实际结果差异或下一步操作 |

草案尚未实现。口播指令可选「先选中段落，再调整行距」，画面先看到真实段落选区，再看到行距参数及换行／段落高度变化。文字和界面不应同样大：指令辅助阅读，真实段落承担结果。若指令本来已由字幕清楚表达，可以只保留关键词或界面标记，避免重复三份同文信息。音乐示例和口播示例也不应强叠在同一段，复杂解释时优先保证真实语音和操作的因果清晰。

审查音频边界时既看波形也正常听：词末可能有尾音，发音可能连读，不能把机械时间戳当最终审美裁决。视觉标记可以按语义组适度调整，但应如实记录它是导演选择，而非伪称每字边界都由模型精确测得。

## 7．失败与可观察通过

| 失败 | 修正 | 通过证据 |
|---|---|---|
| 字重峰值挤字 | 按最粗字重排槽，查实际字库 | 细粗切换时基线与整行宽稳定 |
| 只在数值上连续 | 核对字体实例，必要时另做经过验证的后备 | 实际字形平顺，不突然跳档 |
| 用14帧循环却与128BPM越走越偏 | 用真实拍时间累计映射 | 完整音乐段各拍都吻合，不只开头准 |
| 跟读比声音抢先／落后 | 用实际词边界，正常速度试听修正 | 当前强调与所听语义一致，停顿保留 |
| 伪波形像真实收音证据 | 使用真实采样或明确示意 | 视觉不误导声音来源与测量范围 |
| 末词刚出就结束 | 从A163／B140等真实满态重留时间 | 完整句、结果和下一镜能被理解 |

验收静态排版、最粗字重、回声最大包络、每个词中段、最后退色／收线和实际内容。正常速度完整听看是本技法核心验收，抽帧和时间表只能作为准备证据。
