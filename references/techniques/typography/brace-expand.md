# 括号拉幕：让符号真正控制内容显露

## 1．适合有容器含义的短标题

一对小花括号先建立身份，再放大向两侧弹开，标题只在内缘之间露出。适合代码、数据对象、配置范围或开发者章节；若正文与括号毫无关系，只剩符号装饰。它是开场／连接镜头，后续仍须展示实际结构，不能让每段教程都止于一行发光标题。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/typography/brace-expand.md)、[BraceExpand](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/typography/brace-expand/BraceExpand.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/brace-expand.mp4)。原卡给定拉幕意图，源码可见同源几何、裁切与速度模糊，抽帧可见120帧的16幅阶段。原创为制作推导；未正常速度观看、试听、运行上游或原创实现。

## 2．先组织标题的视觉重量

原例深蓝黑编辑器舞台，32px点阵径向淡出，顶光与地平线分层；300px等宽电光蓝括号夹164px／800白蓝标题。括号比字高，但颜色与边光控制在两侧，不让泛光吞没标题。上方32等宽注释、下方44副句，中心y520，下方一条随展开增长的冷光反射带承托主体。

静态时要看：主字是否占据合适内腔、两端留白是否均衡、括号有没有被误读为标题内容。短标题太窄会在括号没开完就露全，动作和阅读失去联系；长标题又会裁掉两端。中文应实测字宽和内白，不能照抄原卡「中文字宽约英文两倍」作为精确计算。

## 3．内缘、字形尺度与裁切框同源

设弹簧进度ex，`sc=0.4+0.6ex`，幕布半宽`x=(676−64)ex·sc`，括号中心为±(x+64sc)。内缘正好落在±x，标题裁切宽为2x；标题与括号共用sc。最终内腔1224，括号中心半距676。裁切框高度220，字号变化时要重算上下留量。

两侧渐隐宽`min(14,clipW/4)`，让窄窗不会一开始只有半透明灰字。文字没有独立透明度入场；如果另加淡入，会让符号控制变成巧合。居中绝对定位避免clipW改变时flex重新排版。字体本身的内缘64是原字形的近似测量，不是任何花括号都适用的常量。

过冲时x不只线性超出：若ex=1+ε，`x/612=(1+ε)(1+0.6ε)`，约有1.6ε的一阶放大。故「弹簧过冲9%」不等于幕布宽只多9%；边缘包络要按实际几何检查。SpeedBlur速度仅由braceX求差，没有包含64sc项的完整括号中心速度，是近似；不要声称精确匹配所有像素速度。

## 4．动作和阅读时间

| 帧 | 实际行为 | 判断 |
|---|---|---|
| 0～5 | 光标仅0～2亮，3～5灭 | 第0帧不空不代表光标全程可见 |
| 6～13 | 小括号硬切出现，ex0、sc0.4 | 先认出符号，标题仍被零宽窗隐藏 |
| 14起 | d14／k130弹开，括号与字一起放大 | 过冲和回落需看真实曲线，不按注释直接写死收敛帧 |
| 34～64 | 泛光回落；40～64字距−0.05→−0.03 | 松弛会增加标题宽度，要留最终内腔 |
| 44～64 | 注释字距收拢，透明度44～58 | 不让辅助动作变成第二个主峰 |
| 54～82 | 五词副句each16、gap3 | 原卡80保持略早，最后词82完整 |
| 70～120 | 主体缓推到1.012 | 背景与主体缩放分层，非全画面静止 |

抽帧8见小括号，16仅露标题中部，24已大幅展开，40主字稳住，56副句刚出现，79接近完整。16幅图不证明弹簧峰值和完整速度可读性，需要补看动作峰与正文收尾。

## 5．原创演绎：把配置对象从符号变成真实字段

**信息目标。** 让观众理解「这几个字段属于同一个配置对象」。先设计最后的真实代码构图：对象名、花括号、两三个关键字段和实际输出，缩进与标点都可读；下一镜修改一个字段并运行。不是写一句「智能配置」再淡出。

**美术。** 用与实际编辑器一致的等宽字体，正文高对比但不发光；强调只给当前字段或同一对括号。背景网格可省，标题占位改为真实对象名。字段不是把长JSON硬塞进1224宽标题窗，而是展开后切到适当观察距离。

1. 小括号建立「容器」意象，随后拉开露出对象名。语义与即将讲的代码一致，不把花括号当任意装饰。
2. 完整标题读完，两侧括号沿同一世界坐标收成真实代码范围；若字体轮廓差异大，采用明确连接镜头，不硬称无缝变形。
3. 字段按实际缩进出现在对应范围，先一个主要字段，再补必要上下文；保留真实冒号、逗号和闭合符号。
4. 用轻量范围标记说明共同归属，撤掉标题光效。展示实际配置和值，不写虚假的保存成功。
5. 下一镜修改其中一个值，实际运行并展示可核对结果；观众能把结果追溯回那个字段。

这是尚未实现的设计演绎。可给拉开一声短机械音，后续代码阅读保持安静；不按每字加声效。

## 6．原创对象名到代码正文的关键画面

| 状态 | 字形与空间设计 | 内容必须保留 |
|---|---|---|
| 小符号 | 花括号居中、其余留白；代码语境用低权重眉题建立 | 它是范围容器，不冒充点击反馈 |
| 半展开 | 标题仅在内缘露出，最先出现中心语义部分 | 不能中途拼出误导性的残词 |
| 展开满态 | 对象名完整，括号和字形有均衡内距 | 真实名称与后续代码同名 |
| 代码接棒 | 对象名到上沿，括号对应真实代码范围；字段按缩进排列 | 字段、冒号、逗号和闭合关系正确 |
| 运行结果 | 主要字段和值与输出并置，其余代码降权 | 改动可以追溯到具体结果 |

草案尚未实现。教学示例可选简单配置对象，例如只含宽、高和适配方式的显示设置，明确它是示例接口，不假装真实软件原生字段。美术从发光章题转到代码正文时应减少装饰：括号不再比字段更亮，范围线不压标点。短对象名不足以填满内腔时，缩短半距，比增加无意义副词更合适；字距放松后再次检查两端，不能用透明羽化把裁掉的字符藏起来。

## 7．失败与通过证据

| 失败 | 修正 | 通过时看到 |
|---|---|---|
| 括号开了，字还自己淡入 | 撤独立透明度，让裁切严格绑定内缘 | 字只在符号打开的空间内出现 |
| 过冲越界或遮住注释 | 按ex与sc乘积查最大包络 | 最大态仍有留白，主辅层级不破 |
| 松字距后裁掉末尾 | 实测完整态宽，改字号／半距 | 两端与标点完整，羽化不吃关键笔画 |
| 代码正文仍像发光海报 | 回到真实编辑器字体与语法结构 | 对象归属、字段和值可读并可验证 |
| 效果结束就换下一页口号 | 衔接真实配置操作与输出 | 镜头前后有新认识，动作不是唯一看点 |

检查零宽、小括号、首次露字、最大过冲、最终字距、全部副句和真实代码接棒。正常速度、配音阅读与真实运行须独立验证。与 [文字虚焦收敛](blur-slide.md) 相比，本篇是由符号几何控制揭示，不能再叠一套相同的逐词淡入。
