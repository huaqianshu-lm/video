# 乱码状态轮播：固定槽位中的切换与落定

## 1．状态播报不能冒充真实进度

四个短语在同一位置经历乱码、清晰、轻抖和再次熔断，末条收成干净文字。适合明确标注的系统状态演绎或技术语气连接；教程展示真实任务时，短语与完成时间必须来自实际状态，不能照着动画线性条伪造100%。故障风格也不等于系统真的出错。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/typography/glitch-cycle.md)、[GlitchCycle](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/typography/glitch-cycle/GlitchCycle.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/glitch-cycle.mp4)。原卡给定槽位和概率曲线，源码可见确定性字符与进度，抽帧可见168帧的16幅状态；原创为制作推导。未正常速度观看、试听、运行上游或原创实现。

## 2．美术靠稳定骨架承受噪声

深紫黑舞台、紫色横向柔光、极淡4px扫描纹；104px等宽大字，四角细括号围住槽位。上方30px状态行、工程名与编号，下方1100×4进度轨、32px步骤和百分比。大部分结构稳定，噪声只集中在短语，才能保住「系统在说一句话」而非满屏故障。

MAXCH实际为17，来自最长短语长度，与注释一致。每格0.64em＝66.56，整行1131.52；短语左右填空格，奇数空隙时左右差一格是预期，不是严格视觉居中。换中文要测字宽，不能用半角槽容纳全角字；标点、英文缩写和组合字符也要明确分格，避免按UTF-16单元切坏字符。

强调色粉／冰蓝只给噪声和进度，清晰态冷白。框线、工程名、当前状态不能一起高频变动，否则没有稳定参照。最后的署名可改成真实结果入口，不默认替自己视频显示上游品牌。

## 3．一个浓度g控制多个通道，但幅度要读真实公式

每状态38帧，普通概率关键帧[1,0,0,.1,0,0,1]等分6段；末条最后改为0。每2帧固定bucket重算，字符命中后从字池换字；空格不换，行宽始终固定。g也驱动整行抖动、双色分离、中条撕裂与像素残影。

源码`(rand−.5)×36g`，X范围实际±18g，Y为±5g，**不是注释±36／±10**。双色偏移±10g；g>.25启三段横切，中段±80g；g>.45有三个彩块。不是所有效果始终满开。不能独立随机一个震屏，否则「浓度」失去统一语法。

普通状态清晰窗口约局部6.33～12.67和25.33～31.67，中间轻抽字；可读时间比38帧短。末条114起，到局部25.33即绝对帧139.33后g0；源码landed用p>.66，约140起，两者接近但不完全相同。原卡表中「42帧下限」和实际38矛盾，应按真实文案与正常速度决定，不新增固定下限。

## 4．末态、进度和原卡差异

状态起点0／38／76／114；进度是`f/140`线性，不由四步真实工作量驱动。刻度对应38／76／114占140的位置，不是四等分。140变完成，142～158署名进入；158～167仅10帧完整署名。28帧「干净收尾」不代表全部内容已经静止。

第0帧虽然g1，但外层intro0，因此短语不可见，只剩舞台；「开场满乱码」是参数而非实际可见画面。原例终态仍有舞台呼吸与颗粒，不能宣称像素静止。抽帧78和111明显故障，122可读，134仍可能抽字，145已完成但署名在进入。

## 5．原创演绎：一份文件经过真实的三项检查

**目标。** 让观众理解检查顺序和每项结果，不制造任务已通过的错觉。先画最后结果：文件身份、实际解析／字段／引用检查状态和一个可打开的问题位置；下一镜进入该位置。没有真实百分比就不显示线性百分比。

**美术。** 保留单一等宽状态槽和稳定文件名，噪声只用于讲解层切换，正文错误不乱码。主色中性，错误与通过颜色按实际语义；取消工程号、渲染署名等无关背景。

1. 文件进入，显示真实名称和检查目标；先让观众看清输入。
2. 每项状态在实际结果取得后切换，短乱码仅连接两种讲解状态，不遮关键错误。
3. 当前步骤下方列一条真实发现，例如缺少哪个字段；其余项目保留待验，不自动打勾。
4. 最后状态若失败，干净显示「需修正」与定位入口；清晰落定不等于成功。
5. 下一镜打开实际问题并修复，再运行验证，形成可信闭环。视觉结果必须来自任务事实。

这是尚未实现的演绎。可以用低强度电子开关声标记切换，清晰阅读段不连续加噪声；官方无音轨样片不能证明「必须四拍音效」的有效性。

## 6．原创检查过程的关键帧

| 状态 | 画面要明确画出 | 状态依据 |
|---|---|---|
| 输入 | 文件名与当前版本，下面只留一个检查槽 | 真实输入文件 |
| 解析 | 状态词清晰时显示一个实际字段／错误位置 | 实际解析结果 |
| 条件检查 | 当前条件与发现相邻，未验项目仍弱化待定 | 实际检查输出 |
| 问题落定 | 槽位干净显示结果，具体位置成为主焦点 | 不由动画计时自动判成功 |
| 修正接棒 | 回到真实编辑区对应行／字段 | 后镜可直接执行修正 |

未实现的教学草案可以使用缺少一个必要字段的示例文件，最终明确显示「缺少字段」，再进入补齐与运行。清晰窗口不仅要看字能否读出，也要看发现和状态是否能在同一眼连起来；字段名太长时换到局部近景，不把全路径缩成微字。噪声峰期间不切换错误详情文本，待当前状态稳定后再交出阅读权。进度轨如果没有真实比例，可改为有限步骤位置，避免线性百分比制造测量感。

## 7．失败与可观察通过

| 失败 | 修正 | 通过证据 |
|---|---|---|
| 不同短语导致整行跳宽 | 预建真实最大槽，固定测量与填空 | 切换时框与行宽稳定，中文不溢格 |
| 清晰段总有毛边 | 按g阈值撤色散，检查轻抽字是否必要 | 观众能完整读一次状态，不一直猜字 |
| 最后一帧仍乱码 | 末条专用曲线，末态明确归0 | 结果文字干净，失败／成功含义准确 |
| 进度100却没有真实输出 | 绑定实际状态或撤百分比 | 显示结果可查，与真实任务一致 |
| 只剩状态口号，没有检查内容 | 增真实发现与下一镜定位 | 能说出检查了什么、发现什么、怎么处理 |

审查每条可读窗口、切换峰、最后零概率、署名满态及真实结果；正常速度、配音和实际运行分别验收。与 [横条撕裂](../continuity-and-transition/tear-streak-transitions.md) 不同，本篇以文字内容的槽位轮换为主，不能让两种故障层叠到同一状态切换。
