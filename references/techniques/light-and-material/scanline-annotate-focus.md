# 扫过页面后逐块命名

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/effects/scanline-annotate-focus.md)、[ScanlineAnnotateFocus](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/effects/scanline-annotate-focus/ScanlineAnnotateFocus.tsx)、[scanline-annotate-focus 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/scanline-annotate-focus.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 扫描、命名与分析的边界

页面已经存在，扫描线经过一个区块下缘后，该区被框住并贴标签。它表达“发现与命名”，与从空白生成页面不同。若标签只是H1、CTA等预先写好的说明，不能用画面暗示真实AI自动识别成功。教学中可以明确用示意标注解释版面职责。

## 2. 先设计没有机器层的完整页面

原例暖纸白浏览器窗口，左侧高字重无衬线标题，赤陶强调词与按钮，右侧陶瓶和骨白小碗。陶器有窄口、鼓腹、收足、釉面亮痕、淡轮纹和接触影，因此页面本身具备产品摄影感。主标题与大图平衡，底部四色板补充材质，不是六个一样大小的分析框。

机器层统一钴蓝：扫描线、游标、角标、标签与状态行共享；产品色留在页面里，避免观众把机器注记当原页面按钮。顶部状态在窗外，区块标签在窗内，二者有清晰边界。所有标签出现后的终态也须是一幅可读完整画面，不能只保证各框坐标正确。

## 3. 从几何推导事件，不手写猜帧

窗口1560×840位于(180,168)，CHROME52；目标bbox采用页面局部坐标。扫描f6→80，y−20→860，严格线性。到某块下缘y+h的时刻为6+(y+h+20)/880×74。按下缘排序并钳制至少间隔4f，所以同高区块的第二个标签会晚于真实过线；应说“不早于经过且有节拍排队”，不能声称所有标签精确同帧贴线。

| 环节 | 原例实现 | 换页面需要重做 |
|---|---|---|
| 框收拢 | 外扩76px，spring15/210 | 改bbox留白，目标大与小共用像素外扩但要查观感 |
| 角臂 | 40→26px，晚3f跟随 | 臂长要小于局部短边，不盖正文 |
| 对焦确认 | ft+3至+6，峰填充.075 | 浅底不能一块灰蒙住原图 |
| 命名 | ft+5起，约2.2字符/f，32px等宽 | 中文字宽不是.6em，长词须实测排版 |
| 状态 | 实时统计已触发数量，末项后8f切BRAND READ | “已触发”不同于所有标签已经打完，更不等于真实识别正确 |
| 取景 | 整页1→1.035缓推 | 扫描、框、文字随同一页面变换，窗外状态可固定 |

标签right/above/below/belowRight四种不是随意位置；为每块确定避让，尤其主标题上缘、导航下缘和媒体卡底边。若所有标签同时保留太挤，可以先命名重点区，再把次要结果转入列表，不硬塞六份解释。

## 4. 官方抽帧观察

16帧可见先完整陶器页面、扫描下降、蓝框和标签逐步增加，最后六项与06/06状态。原页面的暖色和机器蓝保持区分。接触表不足以证明每个短标签都能在正常速度读完，也不能验证识别算法或字体名称的真实性；本轮仅研究演示机制。

## 5. 原创制作推导：区分正文、图注与来源

内容目标是让观众知道一篇图文中的信息职责。先排一份真实文章局部：主照片占最大面积，正文有稳定行长，图注靠照片，来源行在对应内容下方。色彩来自照片，标注只用一种机器色。

扫描从上到下，只选三个要讲的区域。标题区先显示“主题”，照片下缘经过后显示“证据画面”，来源行经过后显示“回查入口”。文字应说明职责，而非仅复述“TEXT”“IMAGE”。为避免标签盖住正文，给外侧留注记栏，连线回到精确区块。

最后来源标签退到弱态，光标点击真实来源入口，下一镜打开原文位置核查上下文。扫描提出的结构认识在真实阅读中得到验证，不能以“识别完成”四字代替这一步。

## 6. 失败与可判定修正

- 标签早于扫描线：检查bbox坐标、chrome偏移、最小间隔排序，逐帧比较实际下缘。
- 全部框最终互压：先做终态标签版面，按真实字宽调整位置或减少常驻项，不能只缩字体。
- 状态06/06但末词没打完：区分触发计数和内容完成；需要完成状态时取所有标签最后结束时刻。
- 扫描线浅底看不见：用有反差的深机器色，保持细光芯，不能无限加白辉光。
- 页面自身没有美术：暂停机器层检查原页面；标题、图像、留白和材质不成立时先修页面。

通过应有完整原页面、可追溯的bbox触发、标签内容与真实区域一致、结果到后续操作的接棒。正常速度和声音仍需具体实现验证。

## 原创镜头的关键画面调度

下表是上述原创应用的设计草图说明，不是已渲染关键帧，也不代表动态已验。以实际内容、字体与画幅重排，检查每个状态及状态之间的完整运动包络。

| 状态 | 画面安排 | 观看焦点与接棒 |
|---|---|---|
| 页面 | 主照片、正文、图注、来源自有成熟排版 | 先遮机器层审美，不靠蓝框补设计 |
| 命名 | 依下缘次序贴主题／证据／来源，标签在外侧注记栏 | 机器蓝与页面色分工，不覆盖正文 |
| 回查 | 来源入口成为唯一活跃对象，其他标签退弱 | 下一镜打开原文，上下文核对继承来源身份 |
