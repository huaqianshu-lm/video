# 用贴边光决定界面何时可见

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/effects/spotlight-sweep-moves.md)、[CornerSpotlightReveal](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/effects/spotlight-sweep-moves/CornerSpotlightReveal.tsx)、[GlowWakeSleepPanel](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/effects/spotlight-sweep-moves/GlowWakeSleepPanel.tsx)、[SlideSpotlightPan](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/effects/spotlight-sweep-moves/SlideSpotlightPan.tsx)、[glow-wake-sleep-panel 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/glow-wake-sleep-panel.mp4)、[slide-spotlight-pan 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/slide-spotlight-pan.mp4)、[corner-spotlight-reveal 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/corner-spotlight-reveal.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 光在这里承担剪辑

A醒睡：光到即见，光走即退；B横摇：面板与光相对运动，逐区浏览；C角落扩张：从局部逐渐建立全貌。与金属卡扫光不同，这三式决定观众能看到哪些内容。适合暗场短巡礼，不适合把全部教学藏在一圈只出现几帧的光里。

## 2. 共同的美术基底

原例界面偏白灰，但放在黑场里通过显影罩露出；紫色贴边光沿侧缘、顶边、标志穿行，光向内染进表面，未照处沉黑。白界面不是全片白底。主体边缘要有真实位置、圆角和版面结构，紫光才像触碰实体；把光随便悬在屏幕中部会变成无关霓虹。

光有宽糊晕、中层色、窄亮芯和少量偏粉层，模糊26/9等为源例尺度。明亮主体的内部内容仍需层级，不能只用骨架占位条得到“官网质感”。真实项目应先做完整原页面，再决定哪些区域被光按顺序展示。字幕和关键操作说明不必跟着光一起隐藏。

## 3. A：醒来后也会睡去

radial显影罩跟随光头横行，贴顶紫光和标志受光共享几何。尾段光头越过右缘，面板重新沉黑；所以A没有最终全亮的阅读画面。需要读的对象必须在光经过期间有足够暴露时间，或之后切到正视近景。不能把A末尾黑场写成完整UI停留。

目标位置用页面局部边界定义，页面倾斜、缩放时边光一起变；屏幕空间径向罩与世界空间边光若分开计算，要明确投影。最容易错的是顶部光在变换后落到底边，先检查坐标再调光强。

## 4. B：相对速度不能凭肉眼猜

准确实现面板f0–132从x180滑至−1100，光头在面板本地从−360到2600。负本地位置表示左竖缘上爬，过角后onTop=max(0,head)沿顶边。屏幕光头x=slide+onTop；因此面板与本地光头各匀速不代表屏幕全程一条匀速轨迹，转角阶段路径与速度会变化。

竖边光头y从TOP+620上移到TOP，过角后顶边光渐强、竖边光渐弱。内侧泛光的宽度和位置依附同一head，不能只有细线贴边、色晕仍在旧位置。面板内部是三列看板，真实讲解应给各列名称与内容，而非靠滑动骨架条假装信息丰富。

## 5. C：半径线性不等于亮度线性

| 通道 | 准确实现 | 应检查什么 |
|---|---|---|
| 半径r | f0–100，160→1300线性 | 不能终值过大导致前段就全亮 |
| 光心 | f0–96，(140,90)→(420,260) | 光心会移动，不是固定左上角圆扩张 |
| 羽化 | .85r，外沿约1.85r | 受照面积与平均亮度并不随r线性增长 |
| 页面 | scale1.75→约1.47，平移缓变 | 这还是取景中的一部分UI，不能据全亮断言完整页面在画内 |
| 结束 | 光最终覆盖取景 | 要用四角最远距离与软边覆盖验证，不凭1300常数推断 |

源例把“匀速”当特定机械探照风格，不是所有灯光动作都必须linear。若当前内容需要主观搜索，可以有意加减速，但应另设计，不能仍声称复用同一种匀速显影机制。

## 6. 官方观察与原创制作推导

三条各16帧。A确实从黑场露出界面后再次暗去，B光沿顶边带着内侧紫晕横行，C从左上局部逐渐照满取景。接触表不能证明正常速度上光速恒定、转角平滑或有原片色散；源码说明原片转角色散未做，不能写成这版已具备。

原创内容是“定位深色照片中的边缘瑕疵”。先设计结果：同一真实照片的边缘细节放大，瑕疵和正常区域能比较，坐标位置有对应。A可用于短暂提出“这里藏着问题”，光走后切入清楚局部；不要让观众在黑里猜结论。B适合沿照片边缘逐段检查，光轨迹必须沿实际边缘，不能在无关空白巡游。C则建立整张照片的取景，随后收去特效，回到真实亮度检查。

下一镜使用同一局部与相同裁切，显示处理前后，保留曝光口径。不能用灯光人为提亮后的观感当照片本身处理成功。

## 7. 失败修正与判据

- 光线不贴边：先对齐世界边缘和圆角，再调整径向罩；不以扩大晕染遮错位。
- C前段就饱和：测可见覆盖范围，缩小终半径或改光心行程；平均亮度曲线不是“线性半径”的充分证明。
- B转角跳：分查竖缘到顶边路径与光强交接，两者不能各自硬切。
- 关键字只亮一瞬：减行程、加暴露时间或另拍近景，不让扫描替代阅读。
- 显影后仍是骨架页：补真实内容和美术，光效不能替代版面本身。

通过需明确每式可见与消失的范围，主焦点和真实内容对应，接棒画面可读。正常速度、音轨和原创结果未验。
