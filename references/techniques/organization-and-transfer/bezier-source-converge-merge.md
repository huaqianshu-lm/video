# 多源曲线汇聚：路径、来源身份与结果结构一起设计

## 1．「汇入」要说明究竟发生了什么

四个来源先接通路径，再沿各自曲线缩小汇入接收点，撤去通路后让结果接管。适合真实多源整合、入口汇总或资料组织；不适合把四份证据吞成一个无出处的结论。来源被引用、复制、转换或删除是不同操作，不能仅凭「缩没了」让观众猜。

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/ui-entrance/bezier-source-converge-merge.md)、[BezierSourceConvergeMerge](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/ui-entrance/bezier-source-converge-merge/BezierSourceConvergeMerge.tsx)、[官方样片](https://vincentwei1021.github.io/video-shotcraft/media/bezier-source-converge-merge.mp4)。原卡给定三段汇流，源码可见纯函数弧长、遮挡与收束，抽帧可见168帧的16幅阶段；原创为制作推导。未正常速度观看、试听、运行上游或原创实现。

## 2．先画结果，再反推四条来源

原例在480×270设计舞台中放440×240画布，输出放大4倍。来源Y36／92／148／204、X74，接收点(332,120)；四个44直径白瓷盘，接收盘46、标志34。主线.9设计像素、从浅灰渐深至近墨，数据包为唯一靛蓝重点，避免四个来源各自抢色。

白瓷盘有浅渐变、细边、内高光与两层软影；接收盘不透明，盖住曲线和数据包终点，防止开口标志缺口露出线头。受光方向统一，不能每盘用相反亮边。真实来源logo若多色，可放入中性容器控制重量，但不篡改身份。

最终原例只是居中标志＋短句，适合身份收束，**不足以独立讲清整合结果**。教程应先设计真实结构：例如来源列表、引用关系、生成的具体内容和可回查入口；接收点只是中间态。结果画面的主次、材料与阅读距离要在路径之前决定。

## 3．节点和数据包必须走同一条路径

路径为直线(−22,y)→(74,y)，再经控制点(186,y)、(214,120)到(332,120)。直线96保证四节点原位X精确一致。准确实现已用1600段模块级弧长表和二分反查，不再依赖DOM getTotalLength或首帧ready；原卡的DOM测量坑是旧实现背景，不能继续写成当前机制。

整条长度len=96+曲线长，来源比例f0=96/len；节点位置`pointAt(len[f0+(1−f0)conv])`。数据包与九点彗尾也从同一f0向终点采样。不能让路径用Bezier、节点却直线插值，或给四路相同总长，导致沿线速度与原位错乱。

四路同conv但曲线长度不同，实际屏幕速度不同；这是同时到达而不是同速输送。要让一个主来源解释完整迁移，其余跟随时，可另排主次节拍，但要明确这是原创改造，不伪称源例已做到。

## 4．缩小、淡出与数据包的真实含义

size在conv0～.75由44→15，后.25由15→0。它是**两段线性尺寸函数**，不是三段物理加速；每单位conv前段斜率约−38.67、后段−60，后者约1.55倍，原卡「四倍多」不成立。屏幕时间速度还叠inOutCubic，不能只比参数斜率决定运动观感。

节点conv>.92开始淡出，此时size仍4.8设计像素；并非只有缩到0才消失。宽高还以.1保底，最终真正不可见依靠opacity0。若要强调「进入容器」而非消失，应让接收盘遮挡承担主要交接，不靠额外长淡出。

数据包在t.1～.74走两轮，各路相位+i×.13；端点生命权重最小.7而非0，周期复位并不因整数圈就自动无跳。当前接收盘和pkOn包络提供掩护：.1～.16入、.7～.76退，t.76后全部消失。原卡「全程滑行」「末帧停半路」不能当当前尾段事实。

## 5．准确时间、擦除方向与末态

t=f/167。路径draw从.04+i×.045开始、每窗.17，末路到.345，约57.615帧；节点汇聚.34～.74，56.78～123.58，因此**最后一路还未完全draw完，汇聚已开始**，不是完全分离三段。数据包也可能先于某路显线到达其曲段，需按内容需要决定是否延后。

| 阶段 | 实际窗口 | 审查 |
|---|---|---|
| 来源建立 | .02+i×.04起，各.1 | 四盘不同到达时间，但身份必须先可认 |
| 接收盘出现 | .16～.26 | 不是汇聚结束才突然生出标志 |
| 主汇入 | .34～.74 | 四路径中段不交叉错认，接收端遮挡真实 |
| 接收脉冲／涟漪 | .70～.86／.72～.86 | 与末段汇入重叠，别比节点更抢焦 |
| 相机平移 | .76～.93 | 画布左移112，将舞台X352送至240 |
| 路径擦除 | .78～.90，约130.26～150.3帧 | 从源端消失，剩余近接收端；不是线头向左倒走 |
| 字幕显露／加深 | .84～.90／.84～.95 | 最后词约157帧才完全深，尾部11帧完整 |

dashoffset由正到0画线，擦除变负，把可见段起点向终点推进；「反向」说的是dash符号，不应误读为空间上撤回源节点。t.9后线opacity归0但SVG仍挂载，源码没有真的卸载路径。背景颗粒继续动，末态不是真静止。

抽帧56来源仍原位，78开始合流，100盘已很小，122接收圈出现，145相机与擦线中，156附近字幕接近完整。等距图不证明路径细线在正常速度中都可追踪，仍须实际看。

## 6．原创演绎：四份资料形成一段可回查的论证

**目标。** 观众看清不同资料支持同一段说明的不同部分，而非「越多来源越正确」。先画最终态：一段真实论证，句旁保留来源标记与引用列表；下一镜点击其中一项回原文。来源冲突与不确定性必须保留。

**美术。** 四来源用真实类型图标、短名称和清楚身份；强调只给当前主来源与引用标记。接收点改为论证区域的汇入接口，最终展开为真正的段落／关系图，不落到无信息品牌图标。画幅保留段落阅读空间，线条比文字弱一档。

1. 先建立四份真实资料及各自作用，选择一份主来源完整解释，其余不同时弹同重注释。
2. 路径从来源连到它实际支持的句子位置或共同入口，线和节点同源几何。引用不是删除来源，原位保留弱化副本／引用计数，说明身份仍可追溯。
3. 主来源沿曲线迁移为引用标记，其他简洁跟随；资料正文不被强行缩成无法读的小字，迁移主体可用图标与身份短签。
4. 接收端展开真实段落，标记与具体论点一一对应。不能把四条线一律接到同一个「已验证」勾；不支持某句的来源不接。
5. 结果阅读后，下一镜打开一个引用核对原句与上下文；若资料冲突，展示分歧而非把它们吞没。

此设计未实现。声音可用一条连续低强度汇入质感，主对象落位稍清楚，其余弱跟随；最终阅读时撤流动音。节点数量与声音密度由内容决定，不机械复制四声同响。

## 7．原创论证结构的关键画面

| 状态 | 来源与结果怎样摆 | 阅读焦点 |
|---|---|---|
| 来源全貌 | 四份实际资料左列，短名称、类型和作用明确 | 先知道每份资料是什么 |
| 主源接通 | 一条主要路径到实际论点，其余弱化 | 看清一次完整映射机制 |
| 迁移中段 | 图标／短签沿同一路径，原位来源保留引用状态 | 身份连续，不误解为删除 |
| 结果展开 | 段落、关系和引用标记组成真正版面 | 读到具体结论与出处关系 |
| 回查 | 一个标记进入真实原句，其余退为上下文 | 核对支持范围与潜在冲突 |

草案尚未实现。可以先用两份来源支持一个具体论点，确认方法成立后再加第三、第四份；来源多不是画面更专业的保证。若真实来源存在冲突，结果应保留两条不同主张与各自出处，不能把它们全吸进一个「正确答案」。汇入接口可以是一段文本的引用区，白瓷圆片仅作为空间接收体，展开后便让内容接管，不必保留品牌标志。最终静帧遮去所有流动线后，也应仍有可阅读、可追溯的结构。

## 8．失败与通过判据

| 失败 | 修正 | 可观察通过 |
|---|---|---|
| 四来源原位不齐 | 直线段长96与f0同步更新 | 开始四节点同X，路径与节点相接 |
| 节点偏离曲线 | 共用弧长点函数，审世界／屏幕坐标 | 每个运动中心始终在线上 |
| 汇聚点露线头 | 不透明接收底板与正确层级 | 节点进入盘后被遮挡，没有穿标志 |
| 全部同时抢焦、看不懂谁去了哪 | 一个主对象讲机制，其余降权跟随 | 来源身份可追，结果关系清楚 |
| 只剩logo，没有整合结果 | 先设计段落／关系结构再反推路径 | 能读到具体结果、找到引用与下一步 |
| 来源缩没被误解为删除 | 保留原位状态和真实引用语义 | 观众知道是引用／复制／转换中的哪一种 |

验收来源全貌、路径半绘、主迁移中段、接收遮挡、擦线、完整结果和引用下一镜。与 [多源汇聚案例](../../examples/sources-to-unified-structure.md) 共用弧长／来源追踪基础，本篇补准确原卡变体、白瓷视觉和结尾平移差异；不把两个文件当两项独立源资料重复计数。
