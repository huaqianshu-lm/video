# 三站终端空间叙事：命令、执行和实际结果不能混为一段打字

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/camera/terminal-3d.md)、[Terminal3D](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/camera/terminal-3d/Terminal3D.tsx)、[terminal-3d 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/terminal-3d.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1．空间只是把步骤摆清楚

三个终端窗前后错落，相机到站才输入命令，再看输出，最后出现文件。适合三步相依的CLI教学，不适合把不存在的命令做得像真的执行成功。原例shotcraft init／render／export及所有DONE是示意脚本，不迁为本项目工具入口。教学需真实命令、实际日志与验证结果，只有动画不能证明文件已生成。

## 2．先设计每站完整的阅读面

准确窗口1180×620，命令52px、输出38等宽，顶栏24／22分步骤与路径；源码早期注释1240×700、46／34不是当前常量。只用深石墨面与黄绿提示符，正文接近白，次级字段更灰，最后READY才有一次明确亮点。输出每窗控制必要几行，不能把完整长日志缩成纹理。

每窗背后560px描边步骤号、脚下反光与远处背光是空间参照；不能与真正命令同等亮。到站仍留约9／−8／10°相对侧视，能感到体积而不压坏等宽字。若真实命令长，先重新断行或改取景，不把字体无限缩小。

## 3．窗口、世界、地面投影必须共用数学

窗口pose定义x／y／z／ry，world链为退Z−pull、X倾−4、Y转yaw、负pose平移；地面SVG逐线执行同样平移、旋转和透视投影。线宽在屏幕保持恒定，深处渐淡，避免近线粗远线闪。修改窗口姿态只能改共同表，不能让背景反光仍按旧位置。

两次飞行62～92、152～182，用swift沿pose插值，pull叠sin(πraw^.85)×1250。鼓包由原始归一化时间raw算，不是同样的缓动u；它让中途可瞥见三窗。早期注释820不是当前值。开场260退距0～24收，尾部222起再推36，所谓末段hold仍有机位变化。

## 4．打字、回车、状态和输出是独立事件

TYPE_AT8／94／184。每字符先记录出现时刻，再累加.75+rand×.9，空格加.6；TYPING.end包括最后一个字符后的停顿。enterAt=TYPE_AT+end+2，所以不是严格「最后字出现后2帧回车」，还含最后字自身间隔。换中文、长参数、路径后必须重算，不沿用注释18帧完成。

输出从回车后2帧开始，各行at0／4／8等、每行6帧显，菊花在局部t>6才变勾。第二站进度20帧走0→24、后续三行DONE与总行独立；第一窗写12recipe cards，第二写24shots，源例未解释这两个口径，不能拿它直接证明一一对应。

按当前固定伪随机公式复算，三窗回车约27.673／116.023／203.999帧；第二条命令最后字符约113.261，并非早期注释111。第三窗READY约220.999开始，14帧弹出到234.999，26帧光加深到246.999；文件末帧245，光效没有在镜头内彻底完成，且局部pulse继续。文件可读、光效完成与镜头结束不是同一时刻。光标打字时常亮，之后8帧半周期闪，只渲已输入文本，避免空白字符把光标顶到行尾。

抽帧见第一窗命令与输出、两次飞行全貌、最后真实感文件名，但日志全是确定性绘制；它不是实际终端执行证据。

## 5．原创制作推导：读取一份文件、转换、打开结果核对

先画结果：同一输入文件和真实输出文件，格式或字段变化可核查；下一镜打开输出内容。空间站点只组织三步，不增加新的项目流程或工具依赖。

1. 第一站显示当前已存在工具的真实读取命令与输入路径，输出只截必要字段；敏感路径先脱敏，身份在各站保持一致。
2. 第二站执行真实转换，用真实返回结果说明成功或错误。动画可重建输入过程，但标清演示，不能编造DONE。
3. 第三站不是仅写READY，而是显示验证命令及实际得到的尺寸、行数或关键内容；输出文件名与第二站一致。
4. 相机在每次日志阅读完成后再出发，不在长命令还打字时飞走。若三站超过时长，减少输入表演、保留结果解释。
5. 下一镜打开文件，检查具体内容和未保留的信息。声音用稀疏打字质感与回车，不为每字精确敲一声掩盖口播。

## 6．原创草图的美术与中段取景

三个终端窗应按同一命令字阶、行距和语法色组织，步骤号弱于实际命令，成功标志弱于结果文件。长路径可在说明后使用稳定简称，但输入与输出身份必须能对应。每站保留必要工作目录、命令和两三条关键输出，错误时用真实错误信息，不用整段红字增加戏剧性。

末站文件核查最好呈现实际值与期望值的对应，例如尺寸、行数或关键字段，而不是把所有检查都折成绿色勾。进入真实文件下一镜时可从终端输出的文件名引到内容标题，让观众确认打开的确实是这份结果。空间网格、背光和数字编号在此应退下，具体文件内容获得最大阅读面积。

## 7．关键画面与失败条件

| 状态 | 视觉／空间检查 | 内容证据 |
|---|---|---|
| 命令输入 | 字号、光标与上下文清楚 | 命令真实有效 |
| 输出形成 | 先输入、后执行、再状态 | 日志来自实际结果 |
| 飞行中段 | 地面与窗口同投影 | 空间没有滑移穿帮 |
| 末站 | 文件身份与验证口径一致 | 不是只有成功口号 |
| 文件打开 | 实际内容可读 | 教程结果得到核查 |

失败修正：地面滑动查三处矩阵；光标悬空查占位字符；输出太密先删无关日志；READY早于实际验证则重排事件。静帧审命令和文件身份，正常速度审飞行、输入和阅读，声音另试听，不能用终端美术逼真代替真实执行。
