# 空间拆解与俯冲降落

来源：[固定原卡](https://github.com/Vincentwei1021/video-shotcraft/blob/5a2e98daade313c4f376120f38427eb19a108e8c/references/shots/camera/space-camera-moves.md)、[DroneDiveLanding](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/camera/space-camera-moves/DroneDiveLanding.tsx)、[ExplodedView](https://github.com/Vincentwei1021/video-shotcraft/blob/1266a3ec4831289c4d893d42dd5102723658039a/demos/camera/space-camera-moves/ExplodedView.tsx)、[exploded-view 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/exploded-view.mp4)、[drone-dive-landing 官方样片](https://vincentwei1021.github.io/video-shotcraft/media/drone-dive-landing.mp4)。下文区分原卡给定、准确实现、官方样片抽帧观察和原创制作推导；抽帧每条16幅，未完整正常速度观看、试听、运行上游或实现原创镜头。参数用于解释原例，不能直接作为当前视频默认值。

## 1. 先选镜头任务，再选机动

这张卡有两种不同的观看任务。爆炸分解让观众理解同一系统的组成；俯冲降落让观众从整体地图找到一个具体操作区。两者不能因为同属三维运镜就互换，也不适合每个章节重复一次。

爆炸分解的完整构图、美术、分层、原位影、注记和原创导演演绎复用[界面空间分层案例](../../examples/exploded-interface-layers.md)，该正文继续作为 A 式的详细依据。本篇补齐整卡选型和 C 式，不把已完成的解析压成摘要。需要阅读细字的镜头最后必须转入正视局部；展开态负责关系，近景负责证据。

## 2. 两幅结果画面怎样设计

A 式最大展开态要先装得下底板、层间空隙和外侧注记。光从同一侧来，界面薄面、侧棱和底板用同一套冷白材质，影子随离面高度变软。区块数量由要解释的关系决定，五层是原例而非默认层数。若两层已能说明问题，额外三层只会增加阅读负担。

C 式先设计落定的真实局部：保留操作标题、当前状态、图表单位或按钮上下文，不能只有一块放大的空白卡。再反算开场总览。原例用浅灰摄影棚、向远处隐去的点阵地面、左黑侧栏和冷紫图表；侧栏提供方向，点阵提供速度参照，均不能比落点更亮。页面与地面在同一透视世界，屏幕字幕另留稳定安全区。俯冲时暂时不可读的远景字不承担教学，落定后真正要读的对象必须够清晰。

## 3. C 式动作和坐标关系

准确实现为 105f：f0–24 建立俯视并作预备，24–49 主俯冲，49–69 气垫制动，69–104 落定。主行程吃 82%，气垫吃 18%；预备把行程推到 −0.025。三段是有意强调速度变化的导演曲线，不是物理连续相机模拟，也不能保证拼接点速度连续。

同一行程 p 驱动 rotateX 72°→0、scale 0.42→1.35 和平移。HERO 是真实卡中心 (518,335)，transform-origin 固定在那里。CSS 中 translate、rotateX、scale 的顺序有意义，不能改成三个各自独立的补间。终点平移 (960−518,540−335) 的成立依赖这个原点和完整父变换；换页面后应重新投影真实卡中心。

| 通道 | 原例关系 | 换素材后要检查什么 |
|---|---|---|
| 离面高度 | 150·(1−clamp(p))^1.4 | 地面与页面是否真的分离，落定是否接地 |
| 地面影 | 高时偏下右、大而软；近终点淡至零 | 最后不是保留一块脏黑色板；主体自身边影仍在 |
| 采样 | 页面按 1.35 的布局尺度重绘再缩回 | 位图本身是否有足够像素；CSS zoom 不会凭空补截图细节 |
| 速度模糊 | CameraMotionBlur 220°、12 samples | 背景大渐变与颗粒留在采样外，快段拖影与停段清晰分开 |
| 末段聚焦 | 屏幕空间对 HERO 外围轻压暗 | 罩孔随最终投影匹配，不能压住单位、按钮或字幕 |

同一行程不等于全程同速。先快速逼近，再把最后一段距离交给制动；若把全行程直接 ease-out，观众会只看到平滑放大，缺少从远处降落的层次。

## 4. 官方画面观察与证据边界

两条样片均查了 16 幅等距帧。爆炸式可见底板、悬浮部件、分栏引线和合体后的整页；俯冲式前段近乎平躺、地面软影明显，中段页面向观看者展开，末段稳定在左侧图表区域。总览→俯冲→局部的构图关系可观察，但等距帧不证明制动手感、模糊连续性或声音同步，不能据此标成商用验证。

## 5. 原创制作推导：从图层全貌进入裁切控制

内容目标是教观众“裁切改变画布边界，不会删除原始图层”。先做最终画面：真实编辑器正视近景，裁切边界压住一张照片的外缘，图层面板仍保留完整原图缩略图。照片用有明确地平线和边缘人物的真实素材，避免抽象占位图掩盖变化。

起始总览包含画布、图层栏和属性栏，照片是最主要的色块；背景只用低反差灰白点阵。相机落点预先钉在照片与裁切控制能同时进入的区域，而不是几何中心。俯冲期间不增加光标点击，先完成空间定位；落定后才出现裁切手柄，手柄收缩带来真实边界变化。保留原图缩略图的状态作为证据。

如果还需解释原图、蒙版和画布三者关系，可单独使用 A 式三层展开，注记只标这三个职责；它与 C 式不必同镜连放。展开后切到正视裁切，是从关系认知到具体操作的接棒。下一镜保持同一照片和裁切边界，进入恢复原图的操作，证明内容仍在。

## 6. 失败诊断与合格证据

- 落点只剩大图表，观众找不到操作：重新裁镜，让状态标题和控制入口同框；通过证据是无需旁白也能指出“正在操作哪块”。
- 中段卡片突然横跳：检查原点、变换顺序和 lift 是否共享 p；对照俯冲前、中、落定三个投影，主体身份不能断。
- 页面像悬空纸片：补同一世界的地面、接触影和一致光向；若仍解释不清空间，减少倾角而不是加辉光。
- 终点文字糊：查实际截图像素与最终放大倍率，再查布局栅格化；静止原尺寸截图应能辨认关键字及单位。
- 爆炸态层数太多：先删与口播无关的层，再扩大层间投影空隙；不能靠缩小整个场景塞入更多标签。

交付设计时应能指出总览的方向锚、运动中段不交叉的包络、末态的真实操作证据、下一镜延续对象。实际成片还须完整正常速度观看、音画核对和真实素材实现；本篇没有代替这些验证。

## 原创镜头的关键画面调度

下表是上述原创应用的设计草图说明，不是已渲染关键帧，也不代表动态已验。以实际内容、字体与画幅重排，检查每个状态及状态之间的完整运动包络。

| 状态 | 画面安排 | 观看焦点与接棒 |
|---|---|---|
| 建立 | 编辑器全貌，照片为最大色块，图层栏提供原图身份 | 读同一照片与画布的位置，不读远景微字 |
| 机动中段 | 页面、点阵地面与接触影同世界，目标区域始终在包络内 | 俯冲先于点击，字幕在稳定屏幕层 |
| 落定／交棒 | 照片边缘和裁切控制正视可读，外围UI仅弱化 | 松手后才核尺寸，再接恢复原图 |
