# 1. 核心目标

视频不是文章的 PPT 版，也不是文章的朗读版。

正确目标是：

> **文档和视频共享同一套知识，但拥有独立的表达结构。**

要求：

- 看完文档，不需要再看视频
- 看完视频，也不需要再看文档
- 两者信息密度接近
- 视频必须发挥时间、动画、演示、对比、流程和状态变化的优势

禁止：

```text
文章
↓
改成口语
↓
配几张图
↓
视频
```

应该采用：

```text
Source
↓
Content Analysis
↓
Video Narrative
↓
Gate 1 内部检查
↓
Narration Script + Storyboard 联合收敛
↓
Gate 2 人工审核并冻结方案
↓
tts-script.json → 真实 TTS／字幕／Timeline
↓
Remotion
↓
Gate 3 实际画面与试听
↓
共享渲染交付 → Gate 4 成片验收
```

# 2. 内容设计原则

## 2.1 先提取知识，再设计视频

不要按文章章节直接生成 Scene。

必须先完成：

```text
原始文章
↓
核心命题
↓
知识骨架
↓
认知关系
```

需要识别：

- 核心命题
- 必须保留的信息
- 因果关系
- 对比关系
- 流程关系
- 案例
- 可视觉化内容
- 可删除的辅助内容

---

## 2.2 Video Narrative 独立于文章结构

视频叙事应该按照观众的认知过程重新组织。

优先：

```text
问题
↓
对比
↓
发现差异
↓
解释原因
↓
建立概念
↓
制造转折
↓
形成结论
```

避免机械使用：

```text
定义
↓
功能列表
↓
特点
↓
总结
```

除非内容本身确实最适合这种结构。

# 3. Scene 与 Event 规则

Scene 是视频的基本叙事单位，每幕只承担一个主要认知任务。Storyboard 中明确 objective、narrationRef、sourceRefs、focus、layout、elements、events、holds、handoff、assets 和 implementation；字段结构以对应数据版本的 schema 为准，不另造一套 Scene Script。

设计必须回答：这一幕为什么存在，声音解释什么，画面演示或证明什么，谁是焦点，状态如何改变，以及为什么需要用视频表达。没有明确视频价值时返回设计。

每个 Event 有稳定 ID，明确 before／action／after 和纯口播语义锚点；重复锚点注明 occurrence。每个屏幕文字与素材有当前资料依据。分镜必须声明对象身份、父子关系、生命周期、布局与 具体视觉动作，按 SQ-1～SQ-10 完成设计审计。

Gate 2 前使用语义锚点，不伪造音频时刻。Gate 2 后映射真实 Cue／Segment／Timeline；同 Cue 内的顺序动作缺少可信精细时间时，按质量契约阻断并调整设计，不能按字数猜偏移。

# 4. 声音与视觉分工

核心原则：

> **声音负责解释，视觉负责演示、证明和建立直觉。**

理想状态：

```text
声音：解释意义
+
画面：展示过程
=
完整理解
```

错误方式：

```text
旁白：
Claude Code 可以修改文件。

画面：
Claude Code 可以修改文件。
```

正确方式：

```text
旁白：
Claude Code 可以直接参与项目修改。

画面：
auth.ts      Modified
user.ts      Modified
tests.ts     Created
```

# 5. Narration Script 规则

Narration Script 不直接从原文生成。

必须基于 Content Analysis 和 Video Narrative，与 Storyboard 在同一个收敛任务中相互校准。先明确认知任务和变化链，不能先写完朗读稿再随意配画面。

口播主要承担：

- 解释
- 推进
- 因果
- 转折
- 结论
- 建立认知

口播不需要重复视觉已经明确表达的信息。

`narration-script.md` 的 Scene 正文只能包含实际口播；口播全文只在此维护，不在分镜 JSON 中另存一份可修改副本。Gate 2 后先派生并校验 `tts-script.json`，所有音频、字幕和 Timeline 仅从它生成。TTS 默认显式使用 `+25%`；底层实现按专项 Skill 与环境文档执行。

# 6. Storyboard 视觉设计规则

Storyboard 整合场景与视觉设计，不是“配图说明”。

它必须描述：

- 画面结构
- 视觉动作
- 状态变化
- 动画顺序
- 信息重点
- 场景类型
- 视觉与口播的互补关系
- 对象进入／退出、跨幕承接、阅读停留与实现条件

分镜必须同时提交 `storyboard-design-audit.json`；审计格式和版本绑定以分镜质量契约为准。审计通过表示设计资料满足契约，不表示动画已观看或人工 Gate 已通过。

## 6.1 具体画面、镜头目的与因果动画

先把内容需要的画面设计清楚，再选择组件或编写实现。Storyboard 的 layout、elements、Shot、events 和现有审计 evidence／note 应共同说明对象的具体造型、材质／线条、文字层级、颜色语义、比例、留白、视觉重点及变化方式；只写「文件」「目录」「沙箱」或组件名不足以指导实现。数值采用 9.6，画面是否协调仍须实际观看，不靠增加字段或参数数量证明设计成熟。

每次镜头变化须说明观众因此获得什么新信息、关注哪个对象，以及为何采用硬切或连续运动。整体对比后聚焦结果、由局部拉远揭示外部关系、跟随同一对象进入更大结构，均可按内容选择；不把它们做成固定镜头菜单，不以增加镜头数量或持续推拉代替设计。

动画应让内容中的因果过程可见：触发了什么、哪个对象改变、结果如何区别于前态。例如写入是否成功须通过文件内容的结果体现，文件进入目录结构须保留身份线索，隔离边界变化须显露对应环境关系。不能仅移动元素、换颜色或出现标签就声称演示了过程；硬切、静置和阅读停留同样按表达目的选择。

# 8. 避免 PPT 化与视觉收敛

这是一条适用于所有 Workflow 的公共质量基线，但不是简单禁止标题、卡片、代码界面或静态画面。判断标准是：画面是否通过动作、证据、关系或状态变化提供了视频特有的价值。

## 8.1 所有 Workflow 的公共基线

尽量避免：

- 大段文字承担主要信息
- 多层列表或多张卡片承担整幕叙事
- 大量静态页面连续出现
- 口播全文上屏
- 每个 Scene 都是同一套“标题 + 卡片 + 转场”模板
- 画布左上固定显示醒目的 Scene 大标题，让主体画面成为标题的配图
- 只替换文案，不改变视觉机制
- 场景之间仅靠翻页、淡入淡出或版式切换连接

优先使用：

```text
变化
移动
连接
扫描
执行
比较
展开
替换
状态变化
持续对象
视觉证据
```

一个短暂的静态停留可以用于阅读或强调，但不能成为整条视频默认的组织方式。如果任意代表帧都可以脱离上下文被当作 PPT 页面，必须判定视觉收敛失败。

新制作的 Remotion 画面左上只保留有资料依据的简短内容文字，不显示 `SCENE 01`／`场景 01` 一类编号标识或固定大标题。例如「SCENE 05 · 上下文」只显示「上下文」。需要强调概念时，让文字跟随正在变化的对象、操作或证据出现；不能先摆一个标题，再逐项填充内容。历史冻结资料不因本条自动失效，正在修改的视频须重新走对应人工 Gate。

## 8.2 分镜设计与实际预览的分工

Gate 2 按同一 reviewVersion 联合审核纯口播、Storyboard、资料依据、素材及适用设计审计，冻结方案。可选静态图帮助理解布局，但不是动态观看证据；不要求制作 HTML 原型，不依赖 Gate 2 后才产生的 TTS 资源。

Gate 3 对照冻结方案与实际音频 Timeline，完整观看关键动作、阅读停留和跨幕承接，并正常速度完整试听。没有当前版本的观看证据时，只能报告结构或设计已校验，不能声称视觉已验证。

修改冻结设计须通过 Harness 返工并重新审核 Gate 2；仅实现偏差返回 Remotion／Gate 3。旧审核事实保留，下游按契约失效；completed 永久只读。

---

### 8.2.1 新视频的动态视觉设计

每个 Scene 先选一个当前最值得看的主体：可以是产品、界面中的操作、代码差异、流程节点、人物或有资料依据的视觉比喻。画面需要让观众看见它的**前态、触发动作和后态**；配角提供必要语境，不与主体争抢注意力。一个 Scene 若包含多个主体，须说明焦点何时从谁转到谁。

Storyboard 的每个关键视觉事件至少写明：触发它的口播语义、变化前的可见状态、主体如何变化、变化后的可读状态，以及旧主体的去向。相邻 Scene 要交代承接对象或转场理由；不能把三张彼此独立的页面当作连续过程。Gate 2 检查这些变化是否具体、可理解且可实现，正式 Remotion 再按冻结分镜和实际时间基准兑现，Gate 3 检查实际动作。

主体动作完成后可以静置，让观众阅读、比较或听清口播。只在聚焦、空间关系或状态传递确有需要时使用缓慢运镜；不要为了避免静止检测结果而添加循环漂浮、扫光、无意义光效或强行切镜。检查的重点是“说到这里，画面是否提供了新的理解”，不是每秒是否有像素在动。

## 8.3 `narrated-tutorial-v1` 的适用方式

- `TUTORIAL-1 [MUST]`：可以使用标题、代码、终端、UI、流程图、对比卡或解释面板，但它们必须推进口播中的认知过程或提供可核验的视觉证据。
- `TUTORIAL-2 [MUST]`：允许短暂的教学标题或总结卡，但不能让每个 Scene 都退化为同一套标题页模板。
- `TUTORIAL-3 [MUST]`：代码、界面和流程图应通过执行、修改、扫描、连线、高亮、状态改变或结果出现来表达信息；静态界面不能只是口播的背景图。
- `TUTORIAL-4 [MUST]`：视觉可以解释口播没有直接说出的过程、状态和关系，不得只是把口播重新排版上屏。

## 8.4 标题作为视觉事件

缩小标题或把标题移到左上角，不足以解决逐页演示的问题。Storyboard 必须说明标题为什么出现、解释哪个对象／状态、如何交出焦点和何时退出。允许的处理包括：

- 开场概念文字短暂承担主视觉，随后缩小、移动或变形，交给实际主体；不能每幕重复一遍。
- 对象标签跟随对象，状态文字在状态改变后出现，结论文字在证据成立后突出；不能提前透露尚未发生的结果。
- 到达目标后，在落点附近揭示结果文字；下一动作开始前让旧文字退出或有意降权。

片段名称和导航留在预览控件区，最终视频不输出这些控件。标题、主体和字幕不能争夺同一阅读区域；依据 9.2 和 14.2 检查完整进入、移动、让位及退出过程。具体文案来自当前视频资料，不复制样片的任务名称或结论。

## 8.5 同一空间持续演进与跨幕承接

对连续过程，优先把 Scene 作为同一对象／空间的不同阶段：主体移动、展开、拆分、合并、处理、变形或交付，镜头按需要接近、拉远和跟随。不能默认每幕创建一套独立版式，再用转场连接。确需切换到另一个证据、地点或视角时，Storyboard 写明切换理由与接续关系。

Storyboard 必须记录持续主体的标识、空间中来源／处理端／目标的位置关系、各阶段状态、镜头焦点和视野变化、上一阶段留下的语境及其退出时机。背景、已建立的关系和主体可以跨 Scene 延续，但未来节点与路径必须按 9.2 隐藏；空间连续不能成为全片元素常驻的理由。

Remotion 在跨幕时保持对象身份、位置、比例、状态和运动方向的可理解连续性；需要变化时呈现变化过程。持久空间与主体在共同容器维护，Scene 负责事件区间，不能因切幕卸载并重建主体而重播入场。连续状态按统一时间求值，显式处理全片帧与局部 Sequence 帧的换算；不能每幕把镜头和动画进度归零。

转场合成须明确底层背景、前后景层级及透明度重叠，避免两幕同时透明而露出默认画布、造成无意闪白／闪黑。连续背景可在淡出层之外持有稳定的不透明底，前后景的覆盖关系按实际转场设计；不强制所有场景使用同一种淡入淡出。检查交界前／中／后及正文首尾的实际帧，并连续播放复核对象接续和视觉节奏；静帧或背景像素采样只能排查漏底，不能证明转场自然。有意的亮度变化须有设计理由。

可采用以下承接机制，并按视觉任务选择：

| 机制 | 使用方式 |
|---|---|
| 对象延续 | 同一个主体接住上一动作的结果，继续改变状态或进入下一操作。 |
| 展开／合并／变形 | 从主体中展示组成关系，再收回主体或形成结果，保留身份线索。 |
| 运镜承接 | 在既有空间内推近检查、拉远建立关系、平移跟随对象；给观看者留足定位时间。 |
| 遮挡／遮罩揭示 | 借当前主体、视野或遮罩引出下一证据，交代前后关系，避免只加一个全屏擦除效果。 |
| 有理由的切换 | 更换证据或地点时说明叙事原因，保留必要的对象、方向或结果线索。 |

Gate 2 审查交界设计，Gate 3 连续观看每个交界，并检查交界前、交界时和交界后的主体、镜头、文字与可见元素；出现位置跳变、背景重置、重复入场或独立页面替换时返回视觉设计。允许为理解静置，不强制整片一镜到底。

# 9. 动画规则

动画必须传递信息。

动画分三层：

## 一级：信息动画

必须优先。

例如：

- 节点出现
- 文件被扫描
- 代码被修改
- 测试运行
- 流程连接
- 状态改变

## 二级：注意力动画

少量使用。

例如：

- 高亮
- 放大
- 聚焦
- 淡化其他元素

## 三级：装饰动画

尽量少用。

例如：

- 粒子
- 无意义漂浮
- 无意义旋转
- 过多弹跳
- 炫技式转场

如果删除动画后信息完全不受影响，说明它可能只是装饰。

## 9.1 动作语义与通用组件复用

口播教程应根据当前视觉任务选择动作。同一种语义在同一视频中使用一致的动作表达；跨视频优先延续已验证的表达，颜色、对象和布局按当前资料与 Style 调整，不照搬其他视频的业务文案。不能为了套用组件而虚构传递、状态改变或焦点切换。

代码执行与路径表达必须遵守以下三条：

1. **代码执行优先通过逐行高亮、条件成立／不成立、变量与返回值变化表达。** 高亮须对应实际执行步骤，并配合判断或结果变化；已执行行让位，不能只移动焦点框而省略执行含义。
2. **路径用于确有意义的数据传递、调用关系或空间移动。** Storyboard 须说明传递的对象、来源、目标及路径所解释的关系；组件可用不能成为添加路径的理由。
3. **路径的分叉、绕行、回环必须有内容依据。** 不得让观众误读为不存在的分支、循环或执行步骤。仅为避让文字而产生的大幅绕行，应改布局或换表达方式，不能用满足遮挡检查代替动作语义检查。

| 动作 | 表达的含义与适用条件 | Remotion 通用组件 |
|---|---|---|
| 路径传递 | 表达对象、任务或信号从来源到达目标；来源、目标和方向必须清楚。路径揭示可说明连接关系；若口播强调对象到达，还需对象沿路径移动或目标接收后的状态，单纯画出连线不等于完成传递。 | `PathTransfer`：揭示 SVG 路径，不自动实现对象移动或目标接收。 |
| 状态替换 | 表达同一对象从旧状态变为新状态，例如待处理变为完成、草稿变为已发布。旧状态退出，新状态接替；对比任务可以有意保留旧状态，但须说明对比关系。 | `StateReplacement`：在同一区域让旧内容退出、新内容出现。 |
| 焦点转移 | 表达关注点从一个对象转到另一个对象。焦点框、高亮或配角降权用于引导阅读，不能用焦点变化代替实际操作或状态改变。 | `FocusTransfer`：移动焦点框；配角降权由场景按需要实现。 |

Storyboard 应说明动作含义、可读结果和阅读停留。Agent 按冻结分镜编写 React／Remotion 组件，可复用公共动作；不要为迁就现有组件降低设计要求。

动作起点必须来自当前 Workflow 已校验的事件时间绑定，持续时间按可读性和实际节奏安排，不另设一套固定间隔时间轴。Gate 2 检查动作是否解释了变化，Gate 3 检查它是否对应真实时间、是否完整发生及是否留足阅读时间；组件调用或类型校验通过不能替代实际画面检查。

## 9.2 元素的显示与退出时机

口播教程必须为视觉元素明确进入触发、可见区间、退出触发，以及跨 Scene 保留的理由。同一空间持续演进不等于所有元素全程常驻；尚未发生的路径、箭头、节点、结果和提示不得提前显示，已完成视觉任务的元素须按设计退出或有意降权保留。路径底线、描边、箭头、标签、光效和相关子元素必须一起受显示时机控制，不能只隐藏动画主体而留下底层轨迹。

跨幕保留必须指出该元素在后续哪个具体事件中仍有何用途，以及用途结束时的退出边界；只写“保持空间连续”“保留来路”或“降低透明度”不能作为保留依据。已完成的传递轨迹在后续展开、处理、检查等事件中没有具体用途时，应在交接后退出；降低透明度仍属于显示，必须接受同样的可见区间检查。

Storyboard 记录元素的可见性安排；Remotion 按冻结事件实现进入／退出。narrated 视频的正式时间绑定来自 Cue／Segment／Timeline，不能靠当前页面、播放历史或固定估算补时间。初始帧、暂停、回放、跳帧和反向拖动必须还原目标时刻的可见状态。

Gate 2 审查生命周期及交界设计，Gate 3 实际检查元素出现前、出现时、任务结束后及相邻 Scene 交界，特别检查未来路径提前泄露、旧标签残留和隐藏主体的子元素仍可见。发现错时元素时修正生命周期并重新观看，不能以空间连续、类型检查或时间轴结构校验通过代替此项验收。当前规则不代表 Harness 已具备自动识别画面中错时元素的能力。

## 9.3 React／Remotion 动画能力的选型与复用

先明确动作要解释的变化，再选择适用能力。不能把通用场景的淡入、平移、打字作为默认的全部动作，也不能只添加入场动画就宣称消除了 PPT 感。React 负责组织可复用组件；正式视频中的动画进度由 Remotion 帧驱动，不能假定普通网页动画库可以直接用于逐帧渲染。

| 能力 | 适用视觉任务 | 使用边界 |
|---|---|---|
| `useCurrentFrame`、`interpolate`、`Easing` | 位移、缩放、透明度、进度和镜头参数随事件变化 | 明确起止帧和外推边界，控制图层及阅读区域；单纯淡入不是状态演示。 |
| `spring` | 主体落位、展开、收拢和带重量感的响应 | 按任务设置阻尼、刚度、持续时间与是否允许回弹；延迟前隐藏元素，传入的局部帧不得为负，不让文字无意义弹跳。 |
| `Sequence`／`Series` | 安排局部事件区间与顺序 | 明确局部帧偏移；持久主体放在共同空间中，不按 Scene 重置。区间安排本身不构成转场设计。 |
| `@remotion/paths` | SVG 描边、路径变形、沿路径运动 | 按需要选择 `evolvePath`、`interpolatePath`、`getLength`、`getPointAtLength`、`getTangentAtLength`；描边、对象运动和到达反馈分别设计，共享同一路径／进度。 |
| `@remotion/transitions` 的 `TransitionSeries`、`linearTiming`／`springTiming` | 确需切换视角／证据时的淡化、擦除等过渡 | 不能把页面切换包装为连续空间；转场重叠会改变总时长，必须核对当前 Workflow 的区间、音画映射与总帧数，不得挤压既有时间基准。 |
| `SemanticMotion.tsx` 的三个公共动作 | 路径关系、同区状态替换、焦点转移 | 按 9.1 的实际能力复用；`PathTransfer` 不自带沿路径运动，`FocusTransfer` 不自带配角降权，`StateReplacement` 不自带形状变形。 |
| SVG／CSS 属性的帧驱动组合 | 进度环、接收波纹、错峰展开、合并、遮罩与空间运镜 | 已有能力不覆盖时组合实现；有复用价值的部分提取到通用目录，不把一次性业务写进公共组件。 |

实施顺序：先设计具体行为与变化链 → 核对 React／Remotion 实现方法 → Gate 2 审核方案 → 绑定真实事件 → Agent 编写正式画面 → Gate 3 对照实际画面。没有统一画面执行器或动作白名单；无法实现时明确报告，不用框和标签代替。新增依赖仍须说明必要性。

`@remotion/paths` 和 `@remotion/transitions` 已接入公共组件，使用方法、实际版本和通用 Studio 样片见 `docs/MOTION-COMPONENTS.md`。公共 HTML 样片的弹簧仍是原型近似；Remotion 能力样片使用官方实现，实际观感仍须人工复核。选择其他 React 动画库前，必须确认支持按目标帧确定性求值；正式渲染不依赖 CSS 自行播放的 animation／transition、墙钟计时或播放历史。

官方文档参考（实施时按实际版本确认）：[动画属性与帧驱动](https://www.remotion.dev/docs/animating-properties)、[spring](https://www.remotion.dev/docs/spring)、[路径工具](https://www.remotion.dev/docs/paths/)、[TransitionSeries](https://www.remotion.dev/docs/transitions/transitionseries)。

## 9.4 动作链、节奏与音画映射

全片围绕可观察的变化链安排节奏：开场给出问题／动作／证据钩子，中段交替推进与阅读，结尾明确结果并及时收束。信息先后由内容决定，不要求同屏所有元素一开始全亮，不按每个要点平均时间依次淡入。通过动作速度、错峰、停顿、信息密度和焦点让位组织节奏，不用持续运动替代内容。

关键动作可以包含准备、执行、到达反馈和完成态停留：例如任务离开来源、路径揭示、对象沿路径移动、目标接收、状态更新；展开后看清关系，再合并到下一主体；处理进度完成后才出现完成标记。各环节是否需要以及持续多久由当前资料和理解负担决定，不能虚构步骤或反馈。

分镜可说明预期节奏、动作持续参数和阅读策略，但不能把估算秒数作为正式音频时间；正式 narrated 视频使用已校验 Cue／Segment／Timeline 绑定「说到哪句，哪个元素在何帧变化」，不能继续按字数占比分配正式子时长。口播教程在 Gate 3 复核起点、过程、完成态、阅读时间与跨幕交界。

若当前视频使用 BGM／音效，应在资料中说明氛围、音效对应事件、音量关系及淡入淡出；口播清晰度优先，音效不能替代视觉到达反馈。无声样片不代表配乐、混音或旁白听感已验证。

## 9.6 教程片视觉与声音量化基线

本节是本项目 `narrated-tutorial-v1` 的唯一通用量化参数源，适用于当前 `storyboard-v1` 生产；旧契约资料仅供历史读取，不回写 completed 视频。来源为用户提供的《教程片视觉与声音参数规范（量化基线）》（2026-10-09），合并其教程适用参数，并按本项目的时间、素材、工具授权和人工审核边界明确口径。外部文章用于来源追溯，后续制作以本节为准，不依赖 iCloud 文件或其他视频项目的 Skill。

基准为 1920 × 1080、30fps：15 帧为 0.5s、24 帧为 0.8s。换帧率按秒换算；换分辨率按画面比例复核实际尺寸，竖屏须重新排版。量化值服务于认知清晰与观看质感，不替代 8.3～8.5、9.1～9.4 的动作语义和状态变化设计，不引入宣传片 Workflow 或电影感运镜要求。

### 口径与使用边界

- **底线**：标明「底线」的可读性、素材真实性及遮挡要求必须通过实际画面检查；不能用参数配置或模板存在代替。
- **默认**：未作专门设计时采用表中值；偏离时在当前视频设计／审计资料中记录对象或事件、原值／采用值、原因和待复查项，不静默偏离。
- **参考／可选**：用于起步或诊断，不是机器阻断阈值，不要求每条视频启用相机、弹簧、光效、BGM 或音效。
- 实际音频与已校验 Timeline 优先；不得为凑默认动作时长、钩子时长、字幕字数或布局密度修改朗读文本、音频、Cue／Segment 锚点，或硬拉／压缩全片。时间不足时调整动作与信息安排；涉及冻结设计变化时按原契约返工。
- 用户的「太快／太小／太挤／太乱」反馈须落到具体参数与复查结果。单条视频的调整先记入本地资料；只有明确采用为通用默认值时才更新本节，不因一次反馈自动改全项目。

### A．文字可读性

| 参数 | 基线与适用口径 |
|---|---|
| 字幕字号与可读性 | 1920 × 1080 下默认字号 44px（约帧高 4.1%），正式实现显式设置 `fontSize={44}` 或等效样式；换分辨率按比例换算。取消原有效字高 ≥56px、推荐 60px 的要求。字号是排版参数，不等于实际字形高度；按实际画面和手机正常观看大小复查可读性，必要调整按本节偏离规则留证。 |
| 字幕颜色与轮廓 | 默认无背景底板，使用白字 `#FFFFFF` 加近黑色描边；1920 × 1080 下描边默认 3px、颜色 `#182024`，换分辨率按比例复核。描边置于白色填充下方，避免侵蚀字形内部；正式实现显式采用等效样式。跨浅色、深色和细节较多的背景实际复查，保持字幕区避让；必要偏离按本节留证，不因描边存在就认定可读。 |
| 辅助文字／统计／URL | 需要观众阅读的内容有效字高底线 ≥32px（约帧高 3%）；截图和代码可用裁切、放大或聚焦满足，不要求观众阅读的背景细节须明确。 |
| 画面文字提炼 | 自拟标题、标签、结论短语默认每条 ≤12 字，不照抄整段口播；原始截图、代码、命令、URL 和字幕不套用此上限，按阅读任务控制信息量。 |
| 字幕展示 | 默认 8～20 字短句，一次一条、固定区域接棒，字距 0.1em；长命令／英文等按可读宽度处理。展示切分必须保留真实时间映射，不能无依据拆分 Cue 或按字数伪造时刻；句末标点处理遵守既有字幕规则。 |
| 实际验收 | 检查完整动作、中间状态和交界，确认无遮挡、裁切或文字重叠，并在手机正常观看大小复查。 |

### B．节奏与呼吸

| 参数 | 基线与适用口径 |
|---|---|
| 常规元素入场 | 默认 0.8s，常规上限 1.2s；解释过程的动作不套用普通入场上限。 |
| 转场 | 使用转场动作时默认 0.6s、常规上限 0.8s；不得改变 Timeline 或重复计算重叠时长。 |
| 落定停留 | 默认至少 0.8s，关键信息／结论屏建议至少 1s；需继续阅读时延长，按内容与实际音频复核。 |
| 批量动效收尾 | 默认留 0.5s 静止；若同时承担阅读任务，采用上项更长的停留。 |
| 开场主体动作弧 | 采用完整建立／动作／结果弧时默认至少 3s，给足看清时间；不强迫所有钩子都使用同一种动作。 |
| 钩子场景 | 保持简短，3.5s 仅为参考示例，不是固定 Scene 时长。 |
| 阅读估算 | 无旁白时可用「阅读单元 ÷ 5 + 1s 停顿」起估；中文可先按待读字数计，代码／英文／图表须人工修正。有旁白按真实音频校准，不用此公式生成正式时间。 |
| 布局事件密度 | 每分钟 2～4 次为参考；布局事件指主体组位置／空间组织的显著重排，局部高亮、状态替换、字幕换句不计。不是 Scene 或语义事件数量上限，不据此删减必要动作。 |

### C．运动与相机

| 参数 | 基线与适用口径 |
|---|---|
| 相机 | 默认固定；需要缓慢推拉时参考 scale 1.00 → 1.04～1.06，不加装饰性摇移、旋转或模糊。8.5 中用于定位、跟随和解释关系的视角变化须说明认知任务，复查可读性。 |
| 入场／落定 | 默认非线性缓动；弹簧可参考 damping 16、stiffness 100，右侧 48px 弹入并轻微过冲仅为候选配方，不强迫所有对象使用同方向或弹跳。 |
| 连续流动 | 数据沿连线、路径或时间轴推进可匀速；「入场要缓动」不适用于所有过程动画。 |
| 抖动与落定 | 亮场 UI 禁用 shake；元素落定后静置，不添加无语义的 idle 微动、环境呼吸或扫光。 |

### D．排版预算

| 参数 | 基线与适用口径 |
|---|---|
| 同屏主体组 | 默认 ≤3；主体组按认知任务计，容器及其从属标签可算一组，不能用嵌套容器把多个独立主体伪装成一组。 |
| 留白与主角 | 默认留一个空象限作为视觉缓冲，一屏一个 hero 主体；复杂关系图的偏离须说明理由并检查焦点。 |
| 错峰与分镜 | 可按主体／关系／结果三段错峰，不同时全亮；按语义段落切，不按每句口播换页，不为凑三段虚构动作。 |

### E．让位与转场

| 参数 | 基线与适用口径 |
|---|---|
| 旧主体降权 | 可在新主体入场前 6 帧（0.2s）启动，0.5s 内缩到 0.92、上移、亮度降低约 66%；位移按可读区域设计。若旧主体仍需阅读，调整降权幅度并记录原因。 |
| 降权计数 | 降权留守仍占版面，计入同屏主体预算；降权不等于退场。 |
| 转场重叠 | 使用重叠式转场时参考 15 帧（0.5s）、上移 28px；重叠段单独检查，避免双标题争焦点。 |
| 每个边界的处置 | 必须交代对象延续、让位、退出或有理由的切换；连续空间自然承接即可，不强加特效。禁止无承接的裸切；一个边界默认只用一种转场机制。 |

### F．画面素材

| 参数 | 基线与适用口径 |
|---|---|
| 真实性底线 | 作为真实界面证据的终端／页面／代码画面必须来自实际截图或录屏，禁止 mock 冒充截图。讲机制可用明确标注的示意，不能伪称真实软件操作结果。 |
| 采集方式 | 可使用用户提供的真实素材或经授权的截图／录屏；使用 Playwright／浏览器自动化仍须用户明确要求，本节不自动授予工具权限。 |
| 真图呈现 | 根据解释任务裁切、放大、滚动、巡看或划重点，让观众看清证据；允许必要的静态阅读停留，不为「拍出来」给每张图强加运动。 |
| 表达选择 | 按任务选择对照、图表、截图或关系图；明确区分真实素材与机制示意，文字仍须有当前资料依据。 |

### G．克制红线

| 参数 | 基线与适用口径 |
|---|---|
| 光效／glint | 不群发，一个镜头最多给主角一次；无语义用途时不用。 |
| 装饰 | 粒子、漂浮、旋转、弹跳和炫技转场尽量少用；不得为消除静止增加无意义光效。 |
| 背景光斑 | 默认关闭；风格确需时可参考透明度振幅 0.012、周期约 12.6s；干扰阅读立即关闭，不用其满足运动质检。 |

### H．声音

| 参数 | 基线与适用口径 |
|---|---|
| 三轨音量 | 使用对应轨道时参考口播 1.0、音效 0.3～0.6、BGM 0.08～0.18；这些是素材倍率，不是最终响度或听感保证。教程不强制增加 BGM／音效。 |
| 自动避让 | 使用 BGM 时默认在口播出现的 0.4s 内降到其原音量六成，口播结束后平滑恢复；正常速度试听后按清晰度调整。 |
| 首尾淡入淡出 | 画面默认淡入 8 帧（约 0.27s）、淡出 20 帧（约 0.67s）；有 BGM 时默认淡入 1s、淡出 2s。不得遮掉封面／关键文字或截断口播，不改变既有封面与 Timeline 偏移契约。 |
| 音效 | 只强调少数有依据的动作，不群发；最终必须检查旁白清晰度、音效突兀与避让效果。 |

### 设计、实施与审核记录

`storyboard-v1` 在 Gate 2 的分镜设计资料中记录参数选择与待验事项，纳入设计审计；Gate 3 用实际画面／正常速度试听复核，不恢复 HTML 原型或旧自检文件。旧契约的记录仅供历史读取。记录放在当前契约支持的设计／审计资料中，不向运行时 JSON 强塞未知字段。

至少记录：Scene／Event／对象、参数及采用值、偏离理由（如有）、设计检查／实际观看的区别、真实帧或时间范围与证据、pass／fail／pending、修正。Storyboard 使用当前对齐记录，归入既有设计审计与观看证据，不新增 Gate，不自动写通过。

近似静止约 2s 如被质检提示，只能作为复查线索，不能直接判死画面。本节 0.8s 的落定停留与机器静止提示属于不同用途；有依据的阅读停留可以超过 2s。不得为通过静止提示加入装饰性运动，也不声称本次规则接入已实现自动像素、响度、密度、碰撞或画面质量校验。

## 9.7 调校配方的沉淀与复用

通用组件提供能力，量化基线提供起点；两者都不能单独证明实际效果。值得复用的是在明确使用条件下，经过真实画面与试听检验的参数组合及其失败边界。

需要沉淀时使用 `templates/video-production/tutorial-motion-recipe.md`，记录语义用途、可用 React／Remotion 能力／共享组件、采用参数及相对 9.6 的偏离理由、前态／动作／后态、适用画幅／字体／运行时条件、实际输入版本与帧范围、观察结果及踩坑。配方先标为候选；只有实际观看及适用人工 Gate 的证据齐备，才能标为该条件下可复用。单条成功不代表跨视频通用，未经另一条视频验证不得声称已形成通用质量基线。

稳定配方提取为不含具体视频业务文案的共享资料；具体视频的截图、音频和审核事实留在本地，只记录可追溯证据。复用前核对当前内容、真实 Timeline、字体、风格和运行时，重新检查实际效果。配方须遵守冻结分镜与真实时间约束，也不能把尚未实现的参数写成已生效；新能力仍需正常实现和验证。不为了填配方库而增加动画、BGM 或装饰效果。

存在尚不确定的视觉难点时，可在既有设计／实现任务中先选择代表性片段实验，验证构图、造型、完整动作、镜头衔接和阅读效果，再扩展到整片。选择依据是内容里的难点，不要求固定三个样例或每条视频都做实验。设计阶段的本地实验仅供方案收敛，不是正式冻结实现；正式制作仍按原 Gate 和真实 Timeline 执行，不新增阶段、强制工具或独立审核。只做可见样稿不能替代整片质量；扩展后须逐幕兑现设计并复看全部交界与完整片长，不能用局部认可自动通过整片 Gate。

复用的是经过观察的表达方法和设计质量，不是相同布局或统一画面执行器。双对象比较、结构展开、拉远揭示外部边界可作为设计参考；造型、构图、动作和文案按当前内容重新设计。浅色柔和背景是可选视觉方向，不是所有视频的默认配色；使用时复核主体对比度、强调色和字幕轮廓，并遵守当前风格／封面约定。

# 10. Gate 2 方案审核与冻结

## 10.1 Gate 2 分镜设计审核

Gate 2 审核纯口播与分镜方案，不宣称动画、节奏、遮挡或同步已实际验证。共享审核包展示目标、焦点、布局、状态变化、触发、文字、停留、衔接、素材及实现条件；批准须绑定当前 reviewVersion，过期或未就绪版本不能批准。

当前分镜按 SQ-1～SQ-10 逐 Scene／Event 审计：视觉价值、可观察变化、焦点与让位、对象及子元素、生命周期、请求与结果身份、标题用途、跨幕承接、可用执行能力、时间条件。具体清单和机器规则以 [分镜质量契约](STORYBOARD-EXECUTION-QUALITY.md) 为准，不在本文复制 schema。

人工认为方案仍像逐页课件、主体行为不足或节奏单一时，即使结构和审计通过，也须驳回分镜，不能推进 TTS 或 Remotion。

## 10.2 设计审计与方案冻结

当前分镜设计审计存为 `storyboard-design-audit.json`，绑定当前规则、设计输入和分镜／口播指纹；缺项、失败、pending 或过期输入阻断任务完成与 Gate 2 就绪。机器校验不能自动批准人工 Gate。

Gate 2 冻结分镜、纯口播、依据、素材、风格、系列封面及 Scene／Event 清单。当前生产使用冻结 4 与 alignment 4；旧资料须正常返工并重新审核，旧批准不能视为当前方案批准，不手改状态或伪造指纹。

文字区域、生命周期与动作路径须在 Gate 2 完成设计检查；具体检查方法见 14.2，设计检查不要求真实帧或实际观看记录。

方案审核同时检查第 14.3 节中的视觉价值、口播重复和动作价值，以及 14.4 的审美与感官设计；此时判断的是设计，实际播放结果留到 Gate 3 验证。

# 11. TTS、字幕与 Timeline 的职责边界

Harness 负责调度生成器、记录本次执行、验证音频／字幕／Timeline 并推进阶段；底层 TTS 服务与字幕算法按专项 Skill 和环境文档执行。不能把项目描述为只接收人工提供的外部结果。

唯一输入链：冻结纯口播 → 已校验 `tts-script.json` → 显式 `+25%` TTS → 真实音频／字幕／Timeline。生成成功必须有真实产物与当前任务证据，不能用历史文件存在或占位文件冒充完成。

字幕展示去掉句末标点，不修改朗读文本、音频或真实时间；Remotion 消费标准 Manifest，不重复生成或猜测字幕时间。机器质检之后，Storyboard 的正常速度人工试听合并在 Gate 3，不另增独立试听 Gate。

# 13. Remotion 的职责与实现

## 13.1 Remotion 的职责

Remotion 是：

> **实现层**

不是：

> 内容设计层。

Remotion 不应该重新决定：

- 视频讲什么
- Scene 怎么拆
- 视觉应该怎么表达
- 哪个知识点重要

这些必须在前面确定。

Remotion 主要依据同版本 Gate 2 冻结的 Storyboard、纯口播派生的真实音频／字幕／Timeline，以及当前 Style 与系列封面。历史原型文件存在不代表它们仍是新契约的制作输入。

必须先读取已校验的 Audio Manifest、Subtitle Manifest 和 Timeline Manifest，以 Timeline 为唯一时间基准，复用 `src/lib/timing.ts`。Scene、Segment、Cue 与视觉事件保持一致，不按估算秒数或另建编号补时。

当前生产使用Agent 编写的实现与 alignment 4，绑定冻结计划、运行时、实现、真实音频字节和观看证据。结构与指纹检查不能替代 Gate 3 实际观看；精确字段以生产及质量契约为准。

## 13.2 按冻结分镜编写的实现规则

先确认冻结方案、真实 Timeline 与所需能力均可消费，再经 Harness 领取 Remotion 任务。执行者制作声明产物并回传，Harness 重新校验后推进阶段，不能自行跳 Gate。

- Agent 按冻结分镜与真实 Timeline 编写组件和配置，提交 storyboard-authored-alignment 4。Harness 校验时间、版本、源码和音频指纹，不自动生成画面。
- 逐幕检查是一种验证方法，不要求手写逐幕组件，也不能因一次生成整片计划而省略观看。

实现修复仅返工 Remotion／Gate 3；改变口播、分镜或审核依赖，须经共享返工服务重新审核 Gate 2 并按契约重建下游。

## 13.3 内容驱动实现与组件积累

制作顺序是：内容要表达什么 → 设计画面和变化 → 选择合适的组件；没有合适组件，就编写所需实现。组件库随着实际视频制作逐步积累，不先建立一套组件再根据组件决定视频怎么做，也不把建设组件库作为制作前置环节。

当前画面由 Agent 按冻结分镜编写 React／Remotion 组件。已有组件符合内容表达时才复用；不合适时编写当前视频所需实现，不为了复用而改变分镜表达。现有组件缺失不等于无法实现；核对 React／Remotion 与当前环境确有能力缺口时，才明确报告阻塞。通用外壳、字幕安全区、系列包装、Style 和时间基准仍遵守既有契约，不在单条视频中重复建立执行系统。

实际制作并完成适用画面观看与人工 Gate 验证后，识别其中有明确复用价值的实现，再提取到公共目录，保留适用条件与验证依据。仅适合当前视频的实现留在具体视频中，不为积累组件而提前抽象或要求每条视频产出公共组件。提取时不得修改 completed 视频，使用其只读实现与证据提取独立公共能力；后续视频仍从内容出发选择实现。单条画面验证不等于跨视频通用验收，组件调用、参数达标和结构校验也不能证明画面已兑现。

# 14. Gate 3 实际观看与试听

## 14.1 观看与试听证据

Gate 3 前必须提交当前版本的 `remotion-viewing-evidence.json`，覆盖各 Scene／Event 的完整动作、边界及正常速度完整试听；缺失、过期或失败时阻断任务完成及 Gate 3。旧 alignment 仅供历史读取，不能用于当前生产放行。

新契约不要求旧 `visual-self-review.json` 或 HTML 动态原型。机器输出检查与实际观看分别记录；生成预览输入包不等于制作完成，生成器不得自动填写观看通过。

## 14.2 动画过程中的文字与遮挡检查

本检查适用于口播教程的新视频与未完成视频。Gate 2 检查文字区域、生命周期与动作路径的设计；Gate 3 根据真实时间检查 Remotion 预览；只看完成态截图不足以通过。已完成视频保持永久只读。

- 每个包含文字的移动、路径传递、主体让位或状态替换事件，先按正常速度查看完整动作，再暂停检查开始、途中、到达／完成，以及旧新内容同时可见的时刻。路径转折、跨越其他对象和终点标签出现处须额外检查；几个代表帧不能代替完整播放。
- 当前需要阅读的标题、标签、状态、代码和字幕必须保持可读；不得与其他文字重叠，被卡片、移动对象或焦点框遮挡，或被容器／画布边缘裁切。连线和移动对象应绕开文字区域，终点须为对象和标签预留空间；给文字提高图层不能替代合理布局。
- 同一位置的状态文案替换，应让旧文案退出或分时显示，避免两段文字交叠到无法辨认。互斥状态按冻结分镜设计先退出前态、完成后进入后态，不使用交叉淡入。比较旧新状态时使用分开的可读区域。
- 修正时优先调整文字区域、路径、对象位置、旧内容退出时机或替换方式，不通过把文字缩得难读、隐藏必要信息或加快动作掩盖问题。修改后重新播放完整事件，并检查其前后承接。

Gate 2 将设计检查记入当前分镜资料及适用设计审计，明确 Scene、Event、对象、设计依据、风险和修正；当前生产使用既有 SQ 检查项，不新增字段或改变 JSON schema。Gate 2 不要求实际帧或观看记录，也不能把设计审计通过称为实际画面通过。

Gate 3 使用同样的检查方法，记录实际帧号或时间及复查结果；方案通过不能代替真实音频时序下的 Remotion 检查；实际观看结果记录在版本化观看证据中。遮挡未解决时不得请求 Gate 3 通过或完整渲染；若修正明显改变冻结的主体布局、事件逻辑或跨幕承接，按既有规则重新确认 Gate 2。本规则要求人工画面复核，不代表 Harness 已具备自动碰撞或遮挡识别能力。

## 14.3 视觉表达与视频价值检查

每个 Scene 完成后至少做以下检查，并完整观看全片、正常速度完整试听；逐幕检查不能替代全片检查。

### 视觉收敛检查（Visual Convergence Test）

Gate 2 按 10.1 审查分镜设计；Gate 3 对照冻结 Storyboard、当前 alignment 和实际 Remotion 输出复查，并按 14.2 检查完整动作与交界。结构校验、类型检查、文件存在和指纹一致只能证明生产资料可消费，不能证明视频好看或已经摆脱 PPT 化。

如果开头、中段或结尾的代表帧仍然像独立幻灯片，或者连续播放时只是不断替换标题和卡片，即使所有自动校验通过，也必须判定失败并回到 Storyboard。

### 静音检查（Silent Test）

关闭声音。

问：

> 只看画面，能不能大概理解这一幕发生了什么？

如果完全不能，画面可能只是装饰。

### 口播重复检查（Duplication Test）

问：

> 画面是不是只把口播重新显示了一遍？

如果是，需要重新设计视觉。

### 动作价值检查（Motion Value Test）

问：

> 动画是否真正表达了信息？

如果删除动画没有任何影响，可能只是装饰。

### 视频价值检查（Video Value Test）

问：

> 这一幕为什么必须用视频来表达？

如果没有答案，需要重新设计。

## 14.4 审美与感官自检

教程片除了信息准确、动作有意义和量化参数合适，还须检查真实观看是否协调、清晰、有节奏。精致不等于宣传片特效，不强制运镜、粒子、景深或背景音乐。参数值统一使用 9.6，不另建审美分数或自动通过阈值。

| 维度 | Gate 2 设计检查 | Gate 3 实际观看／试听 |
|---|---|---|
| 构图与留白 | 主体、阅读区和字幕区如何分配；焦点是否明确，空白是否服务理解 | 看实际开始／中间／落定与交界：拥挤、失衡、意外遮挡或大块无用途空白是否出现 |
| 字体与层级 | 标题、主体、辅助文字的优先级，长文案和缩放后的阅读条件 | 检查实际有效字高、对齐、密度和手机尺寸可读性；代码字号不能代替观察 |
| 配色与材质 | 色彩承担什么语义，强调对象是否唯一，风格是否一致 | 检查实际对比度、弱化文字与背景、阴影／边框是否抢焦点，不能只核对色值 |
| 动作与呼吸 | 为什么采用此动作、速度、缓动和落定停留，哪些区域须静置阅读 | 连续播放检查迟滞、机械感、突停、过冲、过忙或未读完就退出；静帧不能证明节奏 |
| 连续性与交接 | 主体身份、空间关系及旧新焦点如何承接 | 观察整段动作和 Scene 交界，排查跳变、重复入场、旧主体残留及无理由重置版式 |
| 声音与画面 | 口播、视觉动作、必要音效的关系；使用 BGM 时的避让方案 | 正常速度完整试听，检查口播清晰度、切句／动作节奏、音效突兀和音乐遮盖；无 BGM 也可通过 |

记录必须指出 Scene／Event／对象、适用维度、依据或真实帧范围、具体发现、结果和修正；“好看”“有质感”“参数达标”不能单独作为依据。不适用的子项说明原因；尚未观察的实际效果保持 pending。失败时先指出症状和影响，再明确调整布局、层级、配色、动作参数或时间关系，按设计／实现影响范围正常返工。

实际复查同时覆盖 6.1 的造型／构图、镜头获得的新信息与因果动画，8.5 的转场合成漏底，以及 9.6 A 的无底板字幕在变化背景上的可读性。采用 9.7 的代表性实验时，记录局部观察及其适用范围，扩展后检查其余场景，不能把代表帧通过写成整片动态观看通过。

Gate 2 将设计依据写入现有 `storyboard-design-audit.json` 的 evidence／note：构图和焦点主要归 SQ-3，文字层级归 SQ-7，配色与可用动作参数归 SQ-9，呼吸和音画时间条件归 SQ-10；跨幕连续性同时遵守 SQ-8。每个 Scene 可用代表事件记录整幕检查并引用其他相关事件，避免逐事件复制空泛清单；原有每个 Event 的 SQ-1～SQ-10 覆盖要求不减少。

Gate 3 在既有 `remotion-viewing-evidence.json` 的 scenes[].note、checks[].note 和 listening.note 中记录实际观察与修正，失败／待解决问题进入 unresolved。必须完整观看全片、正常速度完整试听；代表帧、手机尺寸检查和机器结果只是补充。结构校验能检查完整性与版本，不能自动判断审美或代替人工 Gate。发现值得复用的调校组合，再按 9.7 沉淀；不得先填通过记录再补观看。

# 15. 渲染交付与 Gate 4

Gate 3 通过后使用共享 `render-delivery prepare／start／resume`。单条新交付默认本地、可显式选择 GitHub，批量只允许 GitHub；旧 Job 按原方式恢复，不切换方式或重复派发。具体预检、授权、输入包和恢复步骤以渲染交付基线为准。

准备阶段不提交、推送或派发。GitHub 交付须展示精确文件计划并获得用户明确确认，再定向 commit／push；本地交付无需发布或 commit／push。渲染成功和输出机器检查通过后仍须 Gate 4 人工验收，不能自动标记 completed。Smoke Render 仅为新系列或环境变化时的独立手动检查，不推进生产阶段。

# 16. 最终原则

整个系统必须始终遵守以下几条：

1. **文档和视频共享知识，不共享表达结构。**
2. **先设计视频，再写口播。**
3. **Scene 是基本叙事单位。**
4. **声音负责解释，视觉负责演示和证明。**
5. **动画必须表达信息。**
6. **Gate 2 审核并冻结口播与分镜方案，Gate 3 验证实际画面与试听。**
7. **Remotion 负责实现，不负责重新设计内容。**
8. **当前生产只使用现行分镜与按冻结分镜编写的实现，旧格式仅供历史读取；逐 Scene／Event 检查实际兑现。**
9. **公共规则和单条视频设计必须分离。**
10. **Harness 调度真实 TTS／字幕／Timeline，Remotion 消费已校验的标准结果。**

## Shot 与内容表达顺序

内容表达目标 → Scene 组织内容 → Shot 设计观看方式 → Event 设计状态／关系变化 → 选择组件或编写所需实现。Shot 在 Storyboard 联合收敛内设计，不新增 Gate 或强制生成器。镜头构图、可见对象、状态连续性、衔接及真实时间／观看要求以 `STORYBOARD-PRODUCTION-CONTRACT.md` 的 Shot 章节为准。单镜头可成立；不把字幕更新或元素移动自动计为新镜头，不按固定镜头菜单倒推内容。
