# VIDEO-PRODUCTION-RULES.md

> 本文定义口播教程的内容、视觉与声音质量。Agent按[直接制作流程](DIRECT-VIDEO-PRODUCTION.md)协作；分镜字段查[Schema](../contracts/video-production/current/storyboard.schema.json)，关联和时间细则见[分镜关联与时间映射规则](STORYBOARD-PRODUCTION-CONTRACT.md)，设计及实际观看方法见[质量规则](STORYBOARD-EXECUTION-QUALITY.md)，交付见[渲染基线](RENDER-DELIVERY-BASELINE.md)。
>
> 本文适用于口播教程（`narrated-tutorial-v1`），分镜使用 `productionContract: storyboard-v1`、`schemaVersion: 3` 的 Scene → Shot → Event 格式。
>
> 文档规则、工具实现与实际入口验证分别报告，功能及实片验证状态见 [ROADMAP.md](../ROADMAP.md)。新增强制工具、生成器、表达限制或依赖，按 [项目规范](../CLAUDE.md) 说明变化、实际调用和影响并取得相应授权；已有授权不重复请求，不以文档更新宣称功能生效。
>
> Gate 2 前由 Agent 审核口播，Gate 2 由用户确认分镜；Gate 3 由用户确认真实 Timeline 下的实际画面与正常速度试听结果。TTS 环境与调用见 [TTS-SETUP.md](TTS-SETUP.md)。

## 适用范围与公共规则边界

本文件只能保存：

> 口播教程长期适用的公共质量规则。

本文的质量规则适用于新建或尚未完成的口播教程。未完成视频按实际内容缺口补齐，规则更新本身不触发重制；已标记为 `completed` 的视频及其全部关联产物永久只读。解释性画面同样须完成实际观看检查。

禁止写入：

- 某个具体 Scene 的设计
- 某条视频的配色临时决定
- 某个案例的画面方案
- 某个主题的口播内容

单条视频自己的内容应该放在独立目录中，例如：

```text
content-analysis.md
video-narrative.md
narration-script.md
storyboard.json
tts-script.json（Agent 审核口播、用户确认分镜后）
production-record.md（简要确认、设计判断、变更与实际观看／试听记录）
```

内容分析与叙事策划合并完成，两个文件分别保存知识判断与叙事安排，内部检查后联合收敛口播与分镜。资料链与文档分工以 [直接制作流程](DIRECT-VIDEO-PRODUCTION.md#制作流程资料与文档入口) 为准；实际确认、变更影响及未验事项集中保存在一份 `production-record.md` 中。

## 分阶段使用索引

进入各环节时读取下表对应章节原文；恢复制作时，先根据 `production-record.md` 和当前产物确定工作位置，再重新读取相关章节。策划、口播与分镜可以往返收敛，按当前工作切换阅读范围，不依赖开工时一次通读后的记忆。执行顺序与确认边界以直接制作规则为准。

| 当前工作 | 开始前读取 | 结束时检查的实际对象 |
|---|---|---|
| 内容分析与叙事策划 | 第 1、2 章 | 策划资料是否明确受众、学习目标、内容取舍及教学完整性 |
| 口播与分镜设计 | 第 3～6 章、第 8 章设计原则；第 7 章按表达需要选读，8.6 按涉及的文字、排版、素材、声音等查阅 | 口播是否可直接朗读，分镜是否说清画面、对象变化、焦点与阅读空间，风格与系列安排是否落实 |
| 提交方案前 | 第 9 章，并回查方案涉及的设计规则 | 当前同一版本的口播与分镜，以及独立审查发现的问题是否修正 |
| TTS、字幕与真实时间 | 第 10 章、8.6 中声音及字幕相关内容 | 当前 TTS Script、真实音频、字幕与 Timeline 的文本、配置、覆盖及时间是否一致 |
| Remotion 实现 | 第 8、11 章，按当前实现查阅 8.6 | 实际代码与真实 Timeline 是否兑现已确认分镜，画面调校是否满足相关要求 |
| 提交画面前 | 第 12 章，发现具体问题再回查 8.6 及相关规则 | 当前版本完整动态画面及正常速度声音的实际效果，问题修正及未验范围 |

第 7 章的视觉类型和 8.6 的可选动作参数按表达需要使用，不作为必用效果清单。各阶段 Skill 负责在实际工作位置提示读取，规则正文及数值只在本文维护。

读取不等于落实：内容与设计要求对照实际策划、口播和分镜，结构与时间要求对照真实产物及代码，感官效果通过实际观看和试听判断。机器检查只证明其实际覆盖的项目，不能代替表达与审美判断。具体问题、修正及未验事项沿用一份 `production-record.md`，不新增阅读打卡、逐条勾选表或「全部规则已遵守」结论。

# 1. 核心目标

视频不是文章的 PPT 版，也不是文章的朗读版。

正确目标是：

> **文档和视频共享同一套知识，但拥有独立的表达结构。**

要求：

- 围绕本条视频的学习目标，完整讲清必要知识，不依赖观众另读原文才能理解
- 按受众基础取舍信息，使用适合视频的叙事结构
- 根据内容发挥演示、对比、流程和状态变化等表达优势

禁止：

```text
文章
↓
改成口语
↓
配几张图
↓
视频
```

应该采用：

```text
Source
↓
合并内容分析／叙事策划与内部检查
↓
纯口播 + Scene → Shot → Event 分镜联合收敛与独立设计审查
↓
Gate 2 用户确认分镜
↓
tts-script.json → 真实 TTS／字幕／Timeline
↓
Remotion
↓
完整实际观看／正常速度试听 → Gate 3 用户确认画面
↓
明确授权当前输入渲染 → 本地默认／明确选择 GitHub → Gate 4 用户验收成片
```

# 2. 内容设计原则

## 2.1 先提取知识，再设计视频

先明确目标观众、已有基础，以及看完应理解什么或能够完成什么，据此确定讲解范围和必要信息，不直接按文章章节生成 Scene。这些判断写入现有合并策划资料，不新增文档或人工确认。

必须先完成：

```text
原始文章
↓
核心命题
↓
知识骨架
↓
认知关系
```

需要识别：

- 核心命题
- 必须保留的信息
- 因果关系
- 对比关系
- 流程关系
- 案例
- 可视觉化内容
- 可删除的辅助内容

---

## 2.2 Video Narrative 独立于文章结构

视频叙事应该按照观众的认知过程重新组织。

优先：

```text
问题
↓
对比
↓
发现差异
↓
解释原因
↓
建立概念
↓
制造转折
↓
形成结论
```

避免机械使用：

```text
定义
↓
功能列表
↓
特点
↓
总结
```

除非内容本身确实最适合这种结构。

操作教程须讲清必要前提、具体输入或命令、示例对象、预期结果及核对方式；涉及异常或不一致时，说明如何识别和处理。

策划时确定适合内容的整体视觉风格，并在分镜中落实。新视频开始时按[系列与封面规范](AGENT-SERIES-COVER.md)展示实际选项，由用户选择系列或不加片头；选定风格与封面随方案确认。有系列时，在最后一个视觉事件安排有资料依据的下一集预告。

选择风格时，可按需查看[深蓝科技风格](../styles/current/STYLE.md)或 [Codex 系列风格](../styles/codex/STYLE.md)的配色与材质参考；采用后落实到当前分镜及实现，也可根据内容另行设计风格。

# 3. Scene、Shot 与 Event 规则

Scene 是视频的基本叙事单位，每幕只承担一个主要认知任务；Shot 设计如何观看，Event 设计镜头内的状态或关系变化。按内容表达目标 → Scene → Shot → Event 在 `storyboard.json` 中组织分镜，再选择组件或编写实现。字段结构以 [Schema](../contracts/video-production/current/storyboard.schema.json) 为准，对象关联见[分镜关联与时间映射规则](STORYBOARD-PRODUCTION-CONTRACT.md)。

单 Scene 单 Shot 可以成立，不规定最少镜头数或必须运镜；换字幕、亮标签和对象移动不自动算新镜头。阅读静置放入 holds，不用增加动作数量证明质量。用户确认分镜前以口播语义锚点描述触发，不伪造音频时刻。具体画面设计见第 6 章。

# 4. 声音与视觉分工

核心原则：

> **声音负责解释，视觉负责演示、证明和建立直觉。**

按内容选择演示、截图、代码、图表、对照或文字，避免只把口播重新排版上屏。标题、卡片和静态画面都可以使用；每段让观众知道当前看什么，并留足理解和阅读时间。文字、强调和装饰服务于当前重点，镜头切换与空间延续按表达需要选择。

理想状态：

```text
声音：解释意义
+
画面：展示过程
=
完整理解
```

错误方式：

```text
旁白：
Claude Code 可以修改文件。

画面：
Claude Code 可以修改文件。
```

正确方式：

```text
旁白：
Claude Code 可以直接参与项目修改。

画面：
auth.ts      Modified
user.ts      Modified
tests.ts     Created
```

# 5. Narration Script 规则

Narration Script 不直接从原文生成。

必须基于合并策划中的知识判断与叙事安排，与 Storyboard 联合收敛、相互校准。先明确认知任务和变化链，口播与画面共同调整，不能先写完朗读稿再随意配画面。

口播主要承担：

- 解释
- 推进
- 因果
- 转折
- 结论
- 建立认知

口播不需要重复视觉已经明确表达的信息。

`narration-script.md` 的 Scene 正文只能包含实际口播；口播全文只在此维护，不在分镜 JSON 中另存一份可修改副本。Agent 完成口播审核、用户确认分镜后派生 TTS 输入，真实声音与时间的生成见第 10 章。

# 6. Storyboard 视觉设计规则

Storyboard 整合场景与视觉设计，不是“配图说明”。

它必须描述：

- 画面结构
- Shot 的观看目的、构图、视角及衔接
- 视觉动作
- 状态变化
- 动画顺序
- 信息重点
- 场景类型
- 视觉与口播的互补关系
- 对象身份、父子关系、进入／退出、跨幕承接、阅读停留与实现条件

每幕应说明其认知任务、声音解释什么、画面演示或证明什么，以及焦点与状态／关系如何变化。画面标题、标签、按钮、状态、终端输出、卡片文案和素材须可追溯到本视频资料，不复制参考视频的业务语义；预览导航、调试标签和无关文字不进成片。跨镜头持续对象保持身份和状态，不因 Shot 切换而复制或重置。

## 6.1 具体画面、镜头目的与因果动画

先把内容需要的画面设计清楚，再选择组件或编写实现。Storyboard 的 layout、elements、shots、events 与必要设计说明应共同说明对象的具体造型、材质／线条、文字层级、颜色语义、比例、留白、视觉重点及变化方式；只写「文件」「目录」「沙箱」或组件名不足以指导实现。数值采用 8.6，画面是否协调仍须实际观看，不靠增加字段或参数数量证明设计成熟。

每次镜头变化须说明观众因此获得什么新信息、关注哪个对象，以及为何采用硬切或连续运动。整体对比后聚焦结果、由局部拉远揭示外部关系、跟随同一对象进入更大结构，均可按内容选择；不把它们做成固定镜头菜单，不以增加镜头数量或持续推拉代替设计。

需要解释过程或因果时，动画应让相应变化可见：触发了什么、哪个对象改变、结果如何区别于前态。例如写入是否成功须通过文件内容的结果体现，文件进入目录结构须保留身份线索，隔离边界变化须显露对应环境关系。不能仅移动元素、换颜色或出现标签就声称演示了过程；硬切、静置和阅读停留同样按表达目的选择。

# 8. 动画设计与实现

动画由 Agent 根据当前内容、叙事目的和整体风格自主设计。动作形式、运动方式、节奏、镜头与转场均可自由选择和组合，不设动画等级、动作白名单或固定套路。

## 8.1 根据内容自主设计

Agent 决定怎样让画面更清楚、更有表现力和观看吸引力，并在分镜中说明具体效果。代码执行、关系解释、状态变化等内容不指定统一动画做法；同一主题也可以探索不同表达。

## 8.2 元素状态与播放一致性

元素的出现、保留和退出按当前设计安排，实际显示须与所讲内容一致，避免误导、意外残留或遮挡。暂停、回放、跳帧和反向拖动时，均应还原目标帧的正确状态。

## 8.3 自主选择实现方式

Agent 根据设计选择 React／Remotion 能力、组合现有组件或编写新实现，不受现有组件种类限制。

正式动画按帧确定性求值，保证预览与渲染一致；新增依赖遵守项目授权要求。

## 8.4 与真实音频和时间对应

Agent 自主安排动作节奏、持续时间与阅读停留；正式实现的真实时间绑定按第 11 章执行。

## 8.5 以实际效果检查

动画设计纳入第 9 章的方案审查，实际效果按第 12 章检查。

## 8.6 教程片视觉与声音量化基线

本节是本项目 `narrated-tutorial-v1` 的唯一通用量化参数源，适用于 `storyboard-v1` 制作。来源为用户提供的《教程片视觉与声音参数规范（量化基线）》（2026-10-09），合并其教程适用参数，并按本项目的时间、素材、工具授权和人工审核边界明确口径。制作以本节为准，来源资料用于追溯。

本节涉及动画、运镜、转场及装饰的数值与做法均为可选调校参考，由 Agent 按内容自主采用或调整，不作为动画形式、数量、时长或组合方式的限制；此类选择无需逐项记录偏离。可读性、素材真实性、真实时间映射及声音要求仍按各自口径执行。

默认画幅为 16:9，分辨率为 1920 × 1080，帧率为 30fps；时长由内容和真实音频决定，不用固定总时长硬拉压缩。以此为基准，15 帧为 0.5s、24 帧为 0.8s。换帧率按秒换算；换分辨率按画面比例复核实际尺寸，竖屏须重新排版。量化值服务于认知清晰与观看质感，不替代第 4、6 部分与 8.1～8.4 的表达、动作语义和状态变化设计。运镜和视觉风格由 Agent 根据内容与表达需要自主设计，可以采用电影感手法，以实际观看效果判断是否合适。

### 口径与使用边界

- **底线**：标明「底线」的可读性、素材真实性及遮挡要求必须通过实际画面检查；不能用参数配置或模板存在代替。
- **默认**：适用于文字、排版及声音表中标明的默认值；未作专门设计时采用，调整时紧凑记录采用值、原因及待复查项。动画、运镜、转场及装饰按参考值使用，不套用偏离记录要求。
- **参考／可选**：用于起步或诊断，不是机器阻断阈值，不要求每条视频启用相机、弹簧、光效、BGM 或音效。
- 实际音频与已校验 Timeline 优先；不得为凑参考动作时长、钩子时长、字幕字数或布局密度修改朗读文本、音频、Cue／Segment 锚点，或硬拉／压缩全片。时间不足时调整动作与信息安排；影响已确认方案时按第 9 章重新确认受影响范围。
- 用户的「太快／太小／太挤／太乱」反馈须落到具体参数与复查结果。单条视频的调整先记入本地资料；只有明确采用为通用默认值时才更新本节，不因一次反馈自动改全项目。

### A．文字可读性

| 参数 | 基线与适用口径 |
|---|---|
| 字幕字号与可读性 | 1920 × 1080 下默认字号 44px（约帧高 4.1%），正式实现显式设置 `fontSize={44}` 或等效样式；换分辨率按比例换算。字号是排版参数，不等于实际字形高度；按实际画面和手机正常观看大小复查可读性，必要调整按本节偏离规则留证。 |
| 字幕颜色与轮廓 | 默认无背景底板，使用白字 `#FFFFFF` 加近黑色描边；1920 × 1080 下描边默认 3px、颜色 `#182024`，换分辨率按比例复核。描边置于白色填充下方，避免侵蚀字形内部；正式实现显式采用等效样式。跨浅色、深色和细节较多的背景实际复查，保持字幕区避让；必要偏离按本节留证，不因描边存在就认定可读。 |
| 辅助文字／统计／URL | 需要观众阅读的内容有效字高底线 ≥32px（约帧高 3%）；截图和代码可用裁切、放大或聚焦满足，不要求观众阅读的背景细节须明确。 |
| 画面文字提炼 | 自拟标题、标签、结论短语默认每条 ≤12 字，不照抄整段口播；原始截图、代码、命令、URL 和字幕不套用此上限，按阅读任务控制信息量。 |
| 字幕展示 | 默认 8～20 字短句，一次一条、固定区域接棒，字距 0.1em；长命令／英文等按可读宽度处理。展示切分必须保留真实时间映射，不能无依据拆分 Cue 或按字数伪造时刻；句末标点处理遵守既有字幕规则。 |
| 实际验收 | 检查完整动作、中间状态和交界，确认无遮挡、裁切或文字重叠，并在手机正常观看大小复查。 |

### B．节奏与呼吸

| 参数 | 基线与适用口径 |
|---|---|
| 常规元素入场 | 可参考 0.8s 或 1.2s，由内容决定，不设普通入场或过程动作的时长上限。 |
| 转场 | 使用转场动作时可参考 0.6s 或 0.8s；不得改变 Timeline 或重复计算重叠时长。 |
| 落定停留 | 可从 0.8s 起调，关键信息／结论屏可参考 1s；不是最低时长，需继续阅读时延长，按内容与实际音频复核。 |
| 批量动效收尾 | 可参考 0.5s 静止；同时承担阅读任务时按实际需要安排停留。 |
| 开场主体动作弧 | 采用完整建立／动作／结果弧时可参考 3s，不设最低时长，给足看清时间；不强迫所有钩子都使用同一种动作。 |
| 钩子场景 | 保持简短，3.5s 仅为参考示例，不是固定 Scene 时长。 |
| 阅读估算 | 无旁白时可用「阅读单元 ÷ 5 + 1s 停顿」起估；中文可先按待读字数计，代码／英文／图表须人工修正。有旁白按真实音频校准，不用此公式生成正式时间。 |
| 布局事件密度 | 每分钟 2～4 次为参考；布局事件指主体组位置／空间组织的显著重排，局部高亮、状态替换、字幕换句不计。不是 Scene 或语义事件数量上限，不据此删减必要动作。 |

### C．运动与相机

| 参数 | 基线与适用口径 |
|---|---|
| 相机 | Shot 的取景、观看距离、构图与相机变化由内容和阅读任务决定；固定、切换、推近、拉远、跟随均可采用，须说明帮助观众理解什么。scale 1.00 → 1.04～1.06 仅供装饰性缓慢推拉参考，不限制教学所需的视角变化；摇移、旋转或模糊由 Agent 按表达和风格选择，按 12.2 复查可读性。 |
| 入场／落定 | 可选非线性缓动；弹簧可参考 damping 16、stiffness 100，右侧 48px 弹入并轻微过冲仅为候选配方，不强迫所有对象使用同方向或弹跳。 |
| 连续流动 | 数据沿连线、路径或时间轴推进可匀速；「入场要缓动」不适用于所有过程动画。 |
| 抖动与落定 | 抖动、idle 微动、环境呼吸、扫光或落定静置由 Agent 按表达和风格选择，实际检查阅读与观看效果。 |

### D．排版预算

| 参数 | 基线与适用口径 |
|---|---|
| 同屏主体组 | 默认 ≤3；主体组按认知任务计，容器及其从属标签可算一组，不能用嵌套容器把多个独立主体伪装成一组。 |
| 留白与主角 | 默认留一个空象限作为视觉缓冲，一屏一个 hero 主体；复杂关系图的偏离须说明理由并检查焦点。 |
| 错峰与分镜 | 可按主体／关系／结果三段错峰，不同时全亮；按语义段落切，不按每句口播换页，不为凑三段虚构动作。 |

### E．让位与转场

| 参数 | 基线与适用口径 |
|---|---|
| 旧主体降权 | 可在新主体入场前 6 帧（0.2s）启动，0.5s 内缩到 0.92、上移、亮度降低约 66%；位移按可读区域设计。若旧主体仍需阅读，按可读性调整降权幅度。 |
| 降权计数 | 降权留守仍占版面，计入同屏主体预算；降权不等于退场。 |
| 转场重叠 | 使用重叠式转场时参考 15 帧（0.5s）、上移 28px；重叠段单独检查，避免双标题争焦点。 |
| 画面首尾 | 淡入 8 帧（约 0.27s）、淡出 20 帧（约 0.67s）仅作参考，可按设计选择其他处理；不得遮掉封面／关键文字或改变封面与 Timeline 偏移。 |
| 每个边界的处置 | 必须交代对象延续、让位、退出或有理由的切换；连续空间自然承接即可，不强加特效。直接切换或组合转场均由 Agent 按内容选择，实际检查前后关系是否清楚。 |

### F．画面素材

| 参数 | 基线与适用口径 |
|---|---|
| 真实性底线 | 作为真实界面证据的终端／页面／代码画面必须来自实际截图或录屏，禁止 mock 冒充截图。讲机制可用明确标注的示意，不能伪称真实软件操作结果。 |
| 采集方式 | 可使用用户提供的真实素材或经授权的截图／录屏；使用 Playwright／浏览器自动化仍须用户明确要求，本节不自动授予工具权限。 |
| 真图呈现 | 根据解释任务裁切、放大、滚动、巡看或划重点，让观众看清证据；允许必要的静态阅读停留，不为「拍出来」给每张图强加运动。 |
| 表达选择 | 按任务选择对照、图表、截图或关系图；明确区分真实素材与机制示意，文字仍须有当前资料依据。 |

### G．装饰效果参考

| 参数 | 基线与适用口径 |
|---|---|
| 光效／glint | 使用对象、次数和强度由 Agent 按风格与视觉重点选择，实际检查是否影响阅读或分散注意。 |
| 装饰 | 粒子、漂浮、旋转、弹跳及风格化转场均可按内容和整体风格采用，以实际观看效果调校。 |
| 背景光斑 | 是否使用由 Agent 按风格决定；透明度振幅 0.012、周期约 12.6s 可作调校参考，实际检查对主体与阅读的影响。 |

### H．声音

| 参数 | 基线与适用口径 |
|---|---|
| 三轨音量 | 使用对应轨道时参考口播 1.0、音效 0.3～0.6、BGM 0.08～0.18；这些是素材倍率，不是最终响度或听感保证。教程不强制增加 BGM／音效。 |
| 自动避让 | 使用 BGM 时默认在口播出现的 0.4s 内降到其原音量六成，口播结束后平滑恢复；正常速度试听后按清晰度调整。 |
| BGM 首尾 | 有 BGM 时默认淡入 1s、淡出 2s，按实际听感调整，不截断或遮盖口播。 |
| 音效 | 只强调少数有依据的动作，不群发；最终必须检查旁白清晰度、音效突兀与避让效果。 |

### 参数记录与复查

参数采用值可直接保存在分镜或实现配置中；需要说明的默认值调整及实际问题，在现有分镜说明或 `production-record.md` 中简记对象、采用值、原因和待复查项，再补实际复查结果。可选动作参数不逐项登记。

近似静止约 2s 如被质检提示，只能作为复查线索，不能直接判死画面。本节 0.8s 的落定停留与机器静止提示属于不同用途；有依据的阅读停留可以超过 2s。不得为通过静止提示加入装饰性运动；本规范不表示工具已实现自动像素、响度、密度、碰撞或画面质量校验。

# 9. Gate 2 方案审核与冻结

## 9.1 提交前的独立设计审查

提交方案前，回查第 4、6、8 章涉及的规则，按[分镜质量规则「提交前独立审查」](STORYBOARD-EXECUTION-QUALITY.md#提交前独立审查)完成当前同一版本口播与分镜的审查、修订和记录，口播由 Agent 审核通过后，再向用户提交分镜；口播作为对照资料。

## 9.2 用户确认与方案冻结

向用户提交分镜，附同一版本经 Agent 审核通过的口播及必要资料、素材、风格和系列封面选择，说明 Scene／Shot／Event 的主要表达及待实际验证事项。用户确认对象为分镜，口播审核由 Agent 负责；在 `production-record.md` 中分别记录 Agent 审核结果和用户的明确决定。用户未确认分镜，或指出主要表达仍有问题时，继续修改，不推进 TTS 或正式 Remotion。

“冻结”指用户明确确认的分镜及范围。后续口播修改由 Agent 重新审核；影响分镜时，由用户重新确认受影响分镜。分镜本身变化也须由用户重新确认受影响部分。仅重做真正受影响的内容，原审核及确认事实按实际版本和范围保留。

# 10. TTS、字幕与 Timeline 的职责边界

Agent 在完成口播审核、用户确认分镜且具备有效外发授权后调用 TTS 工具，验证真实音频／字幕／Timeline；脚本负责具体生成与产物检查。底层服务和字幕算法见专项 Skill 及环境文档。

唯一文本输入为从 Agent 审核通过的纯口播派生并校验的 `tts-script.json`；结合明确的 provider 配置生成真实音频，再从该文本与真实音频产生字幕／Timeline。默认使用 Edge TTS，显式设置 `+25%`；显式选择百炼时保持原始语速、不加速，ASR 提供词级时间证据并与审核通过的原文核对，字幕始终取原文；映射不可靠时必须阻断，不自动切换 provider。生成成功必须有真实产物及本次生成／缓存复用证据，不能用历史文件存在或占位文件冒充本次新生成。

字幕展示去掉句末标点，不修改朗读文本、音频或真实时间。

# 11. Remotion 的职责与实现

Agent 依据同版本 Gate 2 确认的 Storyboard、真实音频／字幕／Timeline，以及本条视频的风格与系列封面编写 React／Remotion，兑现已确认的叙事和主体表达，分镜与实现须表达同一状态／关系变化链。

实现时可根据实际画面与音频调校排版、插值、动作速度及阅读停留；改变口播、主体表达或分镜范围时，按第 9 章分别完成 Agent 口播审核及受影响分镜的用户确认。

实现前读取已校验的 Audio／Subtitle／Timeline Manifest，按[分镜关联与时间映射规则](STORYBOARD-PRODUCTION-CONTRACT.md)核对对象引用并完成时间绑定；必要映射在视频代码或配置中维护。

# 12. Gate 3 实际观看与试听

## 12.1 观看与确认

请求用户确认画面前，Agent 须对当前正式 React／Remotion 实现、已校验输入包及真实音频／Timeline 完整观看全片并正常速度完整试听。核对实现是否兑现已确认方案，按 12.2 检查实际效果；截图、局部实验、结构校验和解码不能替代完整感官检查。

发现问题后修正并复看受影响片段及衔接，影响全片时重新完整观看／试听。涉及口播或分镜变化时，按第 9 部分分别完成 Agent 口播审核及受影响分镜的用户确认。

在 `production-record.md` 简记 Agent 实际检查的版本与范围、问题位置、修正结果及未验事项；采用既有经验时，核对是否落实、是否解决同类问题。Agent 的自检与用户确认分别记录，是否通过由用户明确决定。未解决的可读性、遮挡、同步等质量问题须修正后再提交确认。

## 12.2 实际效果检查

结合口播连续观看，按下列维度检查实际效果；需要定位问题时再暂停或查看局部，参数口径见 8.6。

| 维度 | 实际观看／试听重点 |
|---|---|
| 内容表达 | 画面与口播是否配合，是否帮助理解所讲对象、过程或关系，有没有仅重复口播文字、缺少实际解释的情况 |
| 构图与风格 | 主体与视觉重点是否清楚，留白、配色与材质是否协调，画面是否拥挤或信息堆积 |
| 文字与遮挡 | 标题、标签、代码和字幕在正常观看大小及完整动作中是否清楚，有无意外重叠、遮挡或裁切；状态替换时能否分清前后含义 |
| 动作与节奏 | 强调是否指向当前所讲对象，动作、停顿与镜头衔接是否自然，是否来得及理解和阅读，有无机械重复、拖沓或无意卡顿 |
| 画面完整性 | 是否有非设计所需的重复入场、残留、闪白／闪黑或调试内容；具体实现检查见[分镜实现 Skill](../.claude/skills/visual-prototype-remotion/SKILL.md) |
| 声音与同步 | 口播是否清晰，字幕及关键动作是否与真实音频对应；采用音乐／音效时，是否突兀、失衡或遮盖口播 |

记录具体问题及复看结果即可，无需逐幕逐项填表。
