# VISUAL-REFERENCE.md

> 本文档用于代替对 `preview.png` 的直接分析。
> 参考重点是“视频表达方式”，不是具体 UI 样式。

## 核心原则

**不要把文章做成动态 PPT。**

视频应该优先表现：

**真实任务 → 执行过程 → 状态变化 → 得出结论**

------

## 1. 文字先转成“可见过程”

遇到一个知识点时，不要先想：

> 屏幕上放什么文字？

先想：

> 观众能看到什么事情正在发生？

优先使用：

- 软件操作
- 终端执行
- 文件读取
- 代码修改
- 流程推进
- 状态变化
- 前后变化
- A/B 对比
- 结构关系

------

## 2. 技术内容优先 Demo

例如：

不要只显示：

> Claude Code 可以读取项目。

而应该表现：

```text
项目文件树展开
→ auth.ts 被读取
→ api.ts 被读取
→ package.json 被读取
→ Project Context 建立
```

让能力变成“看得见的事实”。

------

## 3. 重要区别用同一个任务对比

例如比较 ChatGPT 和 Claude Code：

不要先放对比表。

先给两边同一个任务：

```text
修复登录 Bug
```

ChatGPT：

```text
复制代码
→ AI 给建议
→ 用户手动修改
```

Claude Code：

```text
接收任务
→ 读取文件
→ 修改
→ 运行测试
→ 完成
```

最后再给结论。

------

## 4. 画面必须有状态变化

优先表现：

```text
Idle → Reading
Reading → Editing
Editing → Running
Running → Passed
```

或者：

```text
Bug → Fixed
Manual → Automated
Pending → Completed
```

动画的价值来自“状态发生变化”，而不是单纯让元素动起来。

------

## 5. 三层信息分工

### 画面

负责：

**证明**

### 旁白

负责：

**解释**

### 屏幕文字

负责：

**强调**

三者不要重复表达完全相同的信息。

------

## 6. 屏幕文字尽量少

优先使用：

```text
READ
EDIT
RUN
AGENT
PROJECT CONTEXT
它进入了你的项目
```

不要把完整段落或旁白直接放到画面里。

------

## 7. 一个 Scene = 一个视觉事件

一个 Scene 不应该只是：

```text
标题
+
文字
+
图标
```

而应该发生一件事，例如：

```text
错误信息从 Terminal 被复制到 ChatGPT，
然后建议又被复制回 VS Code。
```

这个事件本身就在表达信息。

------

## 8. 优先使用这些表达方式

### Demo

真实或模拟软件执行过程。

### Workflow

展示步骤推进和状态变化。

### Compare

同一任务，两种处理方式。

### Transformation

Before → After。

### Architecture

展示系统、工具和数据之间的关系。

### Focus

用极少文字强化一个核心结论。

------

## 9. 动画必须表达信息

好的动画：

- 文件高亮 = 正在读取
- 红色代码消失、绿色代码出现 = 正在修改
- 测试进度推进 = 正在执行
- Passed 出现 = 任务完成

不好的动画：

- 无意义漂浮
- 每张卡片都 Fade In
- 所有文字都 Scale
- 纯装饰性光效

------

## 10. 不要机械跟随文章结构

文章章节不等于视频 Scene。

视频可以重新组织成：

```text
问题
→ 摩擦
→ 新方案
→ 演示
→ 对比
→ 核心结论
```

优先按照“观众理解过程”设计，而不是按照 Markdown 标题设计。

------

## 11. 参考图不需要模仿的内容

不要把以下内容当成固定设计规范：

- 黑色背景
- 荧光绿色
- 紫色
- 发光效果
- 卡片样式
- 描边
- 固定布局

这些只是参考图的视觉风格，不是核心。

------

## 12. 最终检查

每个 Scene 都问：

> 如果去掉旁白，只看画面，我还能理解这一段在表达什么吗？

如果完全看不懂：

说明这个 Scene 仍然过度依赖文字。

------

## 最重要的一句话

**画面负责证明，旁白负责解释，文字负责强调。**

以及：

**先把知识变成“发生的事情”，再交给 Remotion 实现。**
