# 独立渲染交付与成功基线

## 范围与授权

本文用于准备正式预览输入、渲染及交付恢复。单条默认本地，可明确选择 GitHub；用户确认实际画面／试听后，须明确授权当前输入的完整渲染，最终 MP4 由用户验收。GitHub 的输入发布、代码提交推送及派发各按其授权范围执行，已有明确授权不重复询问。

制作顺序、完成态保护与已有资料使用见[直接制作入口](DIRECT-VIDEO-PRODUCTION.md)。工具命令、参数、目录及环境说明统一查[工具说明](../scripts/README.md)。

## 独立输入

为当前未完成视频准备独立快照及 ZIP，包含本视频口播／分镜、生成音频／字幕／Timeline、组件配置、封面和共享运行代码，核对路径、字节指纹及 ZIP。不覆盖历史包，不以准备失败的结果替换当前有效输入。

Studio 与渲染消费同一已校验包；正式输出前明确本次 Composition ID 与输入，不以旧包或旧预览冒充当前画面。预览入口及路径见[工具说明](../scripts/README.md#日常使用)，仓库边界按项目规则处理。

## 本地

先按工具说明检查当前输入包与本机环境；预检不自动安装、升级或提高宿主权限。渲染以前台操作执行，保存独立工作区、进程信息、日志和结果。

本地不发布输入包，不需要 GitHub 认证、commit 或 push。机器核对项目规定的分辨率／帧率、当前输入对应的帧数、H.264／AAC 音轨和完整解码；技术检查不替代成片观看验收。

中断后只查询原进程和结果，不重启渲染。进程存在不证明渲染仍正常，结果需文件 SHA 核对；进程已退出且无有效结果则报告失败。重新渲染须有相应授权，产生新输出目录，不称为帧级续跑。

## GitHub成功基线与认证

在实际交付工作区执行成功基线预检，明确代码仓库、独立输入仓库、实际分支及上一条成功完整 Render Run。报告退出成功且 `ok=true` 才继续；保存报告，不保存 token 值。

工具使用gh系统凭据，清除GITHUB_TOKEN／GH_TOKEN覆盖，检查真实API身份、两个仓库写权限、启用的完整Render Workflow、成功Run及代码提交，再fetch实际分支，核实API与Git一致且当前代码包含成功修复。远端引用可能过期，不能凭同名分支或上条成功推断条件成立。

macOS沙箱读不到钥匙串或网络不代表凭据失效；先在工具批准的宿主环境只读复核。认证、输入发布和后续授权操作须由实际具备权限的同一进程环境执行，不因另一终端检查成功而假定当前进程有权限，不修改token、Shell或登录碰运气。

## 发布、代码与派发

1. 发布前检查既有独立 Release 及资产，不覆盖不一致资产；发布成功但后续失败时复用原资产。发布命令及禁止覆盖的选项要求见工具说明。
2. video-github bind核对本地ZIP与目录及GitHub Release Asset API字节，持久保存slug、Composition ID、包指纹、URL和SHA。只接受独立输入仓库API资产URL，不把临时Shell变量当持久绑定。
3. 提交前展示代码／配置所需精确文件清单，定向 commit／push，不使用 `git add .`，不夹带具体视频、资源或无关改动。工具不自动提交推送。分支分叉时从成功基线准备隔离交付检出，不推送无关祖先；整合未完成明确登记。
4. 派发前核对用户确认的本次 ZIP SHA、输入／能力代码一致、相关文件受跟踪且无未提交修改、本地提交等于实际派发分支，并重新执行成功基线检查。先持久保存唯一 dispatchId 和派发意图，再调用现有 Workflow，Run 名称保持 slug / dispatchId。
5. 网络中断或派发结果不确定时，find查询同dispatchId；有Run ID就status查询原Run和Artifact，禁止自动重发。记录accepted不等于渲染成功，只有实际Run成功且Artifact非空、未过期才可交用户下载和验收。

只有真实远端明确失败且用户明确要求重新渲染时才可重派。超时、网络不通或 Artifact 过期不能自动解释为需要重渲染。

## Smoke 检查

Smoke Render 仅用于新系列或环境变化时独立、手动的 GitHub 检查，不作为额外生产阶段或写历史记录；执行仍须取得对应授权。

## CI与验证

静态 YAML／Shell／内嵌 JS 及隔离入口检查不能代表真实 Actions 执行通过；当前接入、真实交付和跨视频验证状态见 [ROADMAP](../ROADMAP.md)。
