# 独立渲染交付与成功基线

## 范围与授权

本文用于准备正式预览输入、渲染及交付恢复。单条默认本地，可明确选择 GitHub；用户确认实际画面／试听后，须明确授权当前输入的完整渲染，最终 MP4 由用户验收。GitHub 的输入发布、代码提交推送及派发各按其授权范围执行，已有明确授权不重复询问。

制作顺序、统一目录、原位返修及完成态保护见[直接制作入口](DIRECT-VIDEO-PRODUCTION.md)。工具命令、参数及环境说明统一查[工具说明](../scripts/README.md)。

## 独立输入

为当前未完成视频在 `videos/<slug>/render-input/` 内准备独立快照及同层 ZIP，包含本视频口播／分镜、生成音频／字幕／Timeline、组件配置、封面和必要共享运行代码，核对路径、字节指纹及 ZIP。组件和配置来源为本视频 `src/`，媒体来源为本视频 `assets/` 和 `generated/`。源文件仍在原位置修改，快照不作为人工编辑或分镜审核入口，不覆盖已校验或正在使用的快照。

打包前枚举必要输入并冻结清单，从枚举阶段排除本视频 `render-input/`、`output/`、`preview/`、`work/`，禁止递归收录产物。播放所需 public 及资源 ZIP 在快照内构造，不向项目根 public 写入视频素材；封面来源与播放引用按[系列与封面规范](AGENT-SERIES-COVER.md)核对。准备期间检查源文件未变化，校验通过并生成 ZIP 后才更新 `render-input/direct-current.json`，失败保留原有效指针。仅确认记录的收尾不改变播放输入，不因此重新打包。

Studio 与渲染消费同一已校验包；正式输出前明确本次 Composition ID 与输入，不以失效包或失效预览冒充当前画面。预览命令见[工具说明](../scripts/README.md#日常使用)，仓库边界按项目规则处理。

## 预览与会话资料

预览指定单条视频，素材及会话资料放 `videos/<slug>/preview/<session>/`，播放素材在会话内的 `public/`，从同一已校验快照构造。自动发现存在多个候选时列出清单并明确选择，不汇总为跨视频素材目录。

生成共享 `src/RenderInputRoot.tsx` 前，核对已有 Studio 及其入口；正在使用时停止覆盖，不自动关闭进程。完成态已有包允许只读预览，所需会话资料使用项目允许的临时位置，不向完成视频目录写入。加载包或生成入口不代表实际观看、试听通过。

## 本地

先按工具说明检查当前输入包与本机环境；预检不自动安装、升级或提高宿主权限。渲染以前台操作执行，在 `videos/<slug>/output/<task>/` 保存独立 `workspace/`、进程信息、日志、任务结果和 MP4。不覆盖已有任务；项目内工作区须属于本视频的独立任务目录，不安装到源目录、其他视频目录或非空工作区。远端 CI 可使用独立临时工作区。

本地不发布输入包，不需要 GitHub 认证、commit 或 push。机器核对项目规定的分辨率／帧率、当前输入对应的帧数、H.264／AAC 音轨和完整解码；技术检查不替代成片观看验收。

中断后只查询原进程和结果，不重启渲染。进程存在不证明渲染仍正常，结果需文件 SHA 核对；进程已退出且无有效结果则报告失败。重新渲染须有相应授权，产生新输出目录，不称为帧级续跑。

## GitHub成功基线与认证

在实际交付工作区执行成功基线预检，明确代码仓库、独立输入仓库、实际分支及上一条成功完整 Render Run。报告退出成功且 `ok=true` 才继续；保存报告，不保存 token 值。

工具使用gh系统凭据，清除GITHUB_TOKEN／GH_TOKEN覆盖，检查真实API身份、两个仓库写权限、启用的完整Render Workflow、成功Run及代码提交，再fetch实际分支，核实API与Git一致且当前代码包含成功修复。远端引用可能过期，不能凭同名分支或上条成功推断条件成立。

macOS沙箱读不到钥匙串或网络不代表凭据失效；先在工具批准的宿主环境只读复核。认证、输入发布和后续授权操作须由实际具备权限的同一进程环境执行，不因另一终端检查成功而假定当前进程有权限，不修改token、Shell或登录碰运气。

## 发布、代码与派发

1. 发布前检查既有独立 Release 及资产，不覆盖不一致资产；发布成功但后续失败时复用原资产。发布命令及禁止覆盖的选项要求见工具说明。
2. video-github bind核对本地ZIP与目录及GitHub Release Asset API字节，在本视频 `render-input/` 持久保存slug、Composition ID、包指纹、URL和SHA。只接受独立输入仓库API资产URL，不把临时Shell变量当持久绑定。
3. 提交前展示代码／配置所需精确文件清单，定向 commit／push，不使用 `git add .`，不夹带具体视频、资源或无关改动。工具不自动提交推送。分支分叉时从成功基线准备隔离交付检出，不推送无关祖先；整合未完成明确登记。
4. 派发前核对用户确认的本次 ZIP SHA、输入／能力代码一致、相关文件受跟踪且无未提交修改、本地提交等于实际派发分支，并重新执行成功基线检查。本地预检、派发意图及查询结果放 `videos/<slug>/output/github/<sha>/`；先持久保存唯一 dispatchId 和派发意图，再调用现有 Workflow，Run 名称保持 slug / dispatchId。
5. 网络中断或派发结果不确定时，find查询同dispatchId；有Run ID就status查询原Run和Artifact，禁止自动重发。记录accepted不等于渲染成功，只有实际Run成功且Artifact非空、未过期才可交用户下载和验收。

只有真实远端明确失败且用户明确要求重新渲染时才可重派。超时、网络不通或 Artifact 过期不能自动解释为需要重渲染。

实际下载的 Artifact 保存到本视频 `output/`，不因查询成功自动下载或派发；下载按有效授权执行。

## Smoke 检查

Smoke Render 仅用于新系列或环境变化时独立、手动的 GitHub 检查，不作为额外生产阶段或写历史记录；执行仍须取得对应授权。

## CI与验证

静态 YAML／Shell／内嵌 JS 及隔离入口检查不能代表真实 Actions 执行通过；当前接入、真实交付和跨视频验证状态见 [ROADMAP](../ROADMAP.md)。
