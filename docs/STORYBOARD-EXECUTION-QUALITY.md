## 分镜设计方法

### 全片构思

从 `video-narrative.md` 中的学习目标与观众理解难点出发，确定视觉主线、主要对象及其发展、场景承接和重点段落。先考虑全片怎样展开，再安排各幕表达，避免把每段口播分别装进同一种版式。

统筹信息密度、观看距离、动作与静置、重点分配和相邻主体交接，判断哪些段落需要展开、哪些可以简述。

### 逐幕表达与关键变化

先说清本幕让观众理解什么，再设计能帮助理解的情境、对象关系与变化：

- **完整情境**：区分同一次执行、独立比较和故障假设。决定开始、变化中和结束时整幅画面的状态，包含背景记录、结果及后续层级。尚未发生的步骤不展示为已执行；切换假设时清退不再成立的结果。涉及配置、权限及适用条件时，画面行为须与前提一致。
- **可见过程**：明确观众在变化前后能辨别什么，选择能显示差异的对象造型、空间关系与反馈；检查这些变化是否足以解释当前过程。
- **声画含义**：共同安排台词与动作，区分用户选择、产品能力、判断原则和实际验证结果。语义锚点须匹配动作含义；例如提示风险时的成功勾选，也可能造成误导。缺少合适语言落点时，在提交方案前调整口播。

### 镜头与注意力组织

先安排观众依次定位、追踪和阅读什么，据此决定构图、观看距离、主次层级和焦点交接，再确定 Shot／Event／Element 数量。

先安排关键状态和结果阅读，再分配主体、相机与路径的运动。并行运动服务同一理解任务；出现竞争焦点时，通过错峰、让位或调整构图处理。标题与标签有明确用途，按当前主体和阅读任务安排出现、保留及退出。

设计决定写入现有 Scene、Shot、Event 和元素字段，必要说明随分镜保留。具体推导与案例见 [内容到画面](../references/content-to-visual.md)。

### 难点推敲与实现选择

文字难以判断的构图或动作，可按需要做实际尺寸关键帧、简略构图或短动画实验；先明确问题，实际查看后据结果修正。关键帧只支持所见状态的判断，运动观感须正常速度观看；真实音频生成前的动作时序只是设计预算。

参考选读与模板使用分别按 [参考索引](../references/README.md) 和 [模板索引](../templates/README.md) 执行。草图和实验留在本条视频的本地资料中，交付依据须能实际取得。

## 提交前独立审查

初稿完成后，单独从观众角度重新审查，允许推翻创作判断。先看分镜画面描述或已有画面依据，判断无声时会被理解成什么，再对照口播检查含义；同时审视所有可见对象共同构成的情境。已有动画实验的结论只覆盖实际观察范围。

按以下原则检查全片，同时检查各幕合起来是否形成完整教学链，平台／环境是否一致，必要对照和异常处理是否齐全，以及表达有无机械重复。选读的方法须适配当前内容，不能因场景名称或动作名称不同，就认定表达有变化。无需逐 Scene／Shot／Event 重复填表：

| ID | 判断重点 | 典型问题 |
|---|---|---|
| SQ-1 | 画面有资料依据，帮助理解当前教学内容 | 只把口播排成卡片；操作教学缺少必要前提、输入、示例或结果核对 |
| SQ-2 | before／action／after 描述可观察的过程与结果 | 写「请求到达」，只画一条连接线 |
| SQ-3 | 构图、焦点、让位、阅读及承接服务当前理解任务 | 旧主体无理由常驻，所有元素同时强调 |
| SQ-4 | 所有参与表达的对象及其关系已设计清楚 | 只设计文字，容器、路径和状态指示的含义不明 |
| SQ-5 | 状态变化顺序合理，父子对象及互斥状态相容 | 两个互斥状态同时保留，子内容与容器状态矛盾 |
| SQ-6 | 请求、处理中与结果的身份和含义清楚 | 请求面板变绿就声称文件已创建；把能力示意当实际验证 |
| SQ-7 | 标题与标签有用途，并为正文保留合理的阅读空间 | 标题长期抢焦点，独立模板时长挤占正文 |
| SQ-8 | 跨镜头、跨幕的对象延续或退出有内容理由 | 仅以「空间连续」解释常驻，切换假设仍保留旧结果 |
| SQ-9 | 实现条件足以支持所设计的关键变化 | 根据组件库倒推画面，或用组件名称当作实现保证 |
| SQ-10 | 动作顺序及同步需求有可行的时间依据 | 需要 Cue 内顺序变化，却只有 Cue 起点且无补证或调整方案 |

发现主要表达或教学路线问题，先内部修订并重新检查受影响部分，再提交收敛方案。无法判断的设计问题说明具体原因及影响；必须等真实动画与音频才能判断的节奏、遮挡、阅读和同步，明确留待实际检查，不能用设计结论代填。

在分镜说明或 `production-record.md` 中，用紧凑 summary／findings 记录检查范围、全片判断与依据、实际问题、修正和待验事项。先形成判断再记录，不从创作描述复制通过结论，也不为填表编造问题。

结构与时间按[关联与时间规则](STORYBOARD-PRODUCTION-CONTRACT.md)另行核对，工具实际覆盖及待人工核对事项见 [ROADMAP](../ROADMAP.md)。这些技术结果不能代替设计判断。

## 实现与返修核对

对照已确认分镜，检查展开、查找、执行、核对、交接等关键动作是否兑现了对象关系、过程和结果。例如「查找」要能看出查找依据及对应结果，仅让相关元素出现，不能证明已实现该动作。发现实现降级先修实现；确实无法完成时，说明具体能力缺口及影响。

局部返修后，检查改动是否削弱全片主线、造成表达重复或打乱信息分配与主体交接。保留贯穿对象时，重新判断当前段落需要的面积与构图，避免沿用旧版式挤占新的表达空间。

实现的真实时间映射按[关联与时间规则](STORYBOARD-PRODUCTION-CONTRACT.md)核对；完整观看、正常速度试听及实际效果检查按[质量规范第 12 章](VIDEO-PRODUCTION-RULES.md#12-gate-3-实际观看与试听)执行。方案变更与重新确认范围按直接制作规范处理，具体实现操作见[分镜实现 Skill](../.claude/skills/visual-prototype-remotion/SKILL.md)。
