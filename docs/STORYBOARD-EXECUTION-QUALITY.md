# 分镜设计与执行质量

本文是 `storyboard-v1` 的设计与执行质量标准，版本 `storyboard-execution-quality-v2`。阶段、人工审核和返工边界以 `STORYBOARD-PRODUCTION-CONTRACT.md` 为准；教程视觉原则继续使用 `VIDEO-PRODUCTION-RULES.md` 8.3～8.5、9.1～9.7、14.2～14.4。不恢复 HTML 原型，不增加人工 Gate，不恢复独立 TTS 试听审核。

制作分镜及实施前必须读取 [教程片量化基线](VIDEO-PRODUCTION-RULES.md#96-教程片视觉与声音量化基线)。采用值、偏离理由和待复查项记入现有设计审计；Gate 2 检查设计，Gate 3 检查实际有效字高、动作及阅读区间、交界和正常速度听感。参数达标不能代替 SQ-1～SQ-10 的动作语义与对象关系；量化参数接入本身不改变数据契约，Shot 格式升级见生产契约，不代表新增机器画面校验。

同时执行 `VIDEO-PRODUCTION-RULES.md` 14.4 的审美与感官自检：构图／留白、字体层级、配色材质、动作呼吸、连续交接、声音与画面。Gate 2 按该节映射写入 SQ-3／7／8／9／10 的 evidence／note，每幕有具体设计依据；Gate 3 在现有 Scene／Event 观看 note 和 listening.note 中记录真实观察、修正及遗留问题，不以设计 pass 代替实际观看。可复用参数组合按 9.7 和 `scaffolds/video-production/tutorial-motion-recipe.md` 留证，候选与实际验证分开。这些要求属于当前设计规则；权威生产规则及配方骨架纳入现有设计／任务输入指纹，变化使旧审计或已领取任务输入过期，不自动重写视频或继承批准。审美参数仍沿用既有字段；Shot 格式升级按生产契约执行。

Storyboard 先根据内容与 `references/` 完成设计，再查看 `templates/README.md`。视觉模板只有在表达任务、对象关系和适用条件匹配时才可改造使用；不存在合适模板时继续编写当前视频所需实现。模板不生成分镜、不限制实现能力，也不继承旧视频的 Gate 3 结论。

## 导演创作与首次交付

Storyboard 制作 Agent 对全片视觉导演设计负责。首次交付应当是主要表达已经成立、可进入审美与实现细节打磨的成熟方案；若审核后仍需更换多数场景的主体、表达机制或镜头组织，说明首次设计未完成。检查用于发现缺陷，不能替代创作；结构正确、审计齐全和动作名称多样均不能证明设计成熟。不以自动评分或「80 分」阈值认证质量。

在现有口播／分镜联合任务内完成以下创作过程，口播与画面相互校准后再冻结：

1. **全片构思**：从观众的理解难点确定视觉主线、主要对象及其发展、场景承接和重点段落。先决定全片如何展开，不把各段口播分别装进同一种版式。统一视觉语言允许不同表达方式，不要求固定隐喻、视觉高潮数量或连续运镜。
2. **逐幕表达**：把本幕知识转成可见的情境、关系和变化，明确观众在动作前后能辨别什么，以及为何这种表达有助于理解。造型、空间关系和反馈应承载信息，不能只用「汇聚」「高级感」等词代替设计。准确区分用户选择、产品行为与实际验证结果。必要时在冻结前调整口播，使一句话所含变化能够清楚呈现。
3. **镜头组织**：根据表达设计构图、观看距离、主次层级、焦点交接、动作过程、结果阅读及衔接；再确定所需 Shot／Event／Element 数量。为后续 Remotion 明确主体、关键状态、因果与接续，不把导演决定留给实现者临时猜。具体代码、插值和真实音频下的速度调校仍在实现阶段落实。
4. **画面推敲**：用开始／关键变化中／结束的画面关系检验设计。文字不能判断的关键构图或动作，按难点做简略构图、关键状态图或短动画实验，并实际查看后修正。方法和工具按问题选择，不要求逐幕完整预演、不增加强制工具或人工 Gate；仅有文字推演不得声称已观看。未解决且会影响主要表达的问题，继续在本任务内解决或明确报告能力缺口，不能包装成完成。
5. **全片统筹**：连看各幕的设计，主动组织信息密度、观看距离、动作与静置、重点分配及相邻主体交接。重复与静置可以有意使用；不能为消除重复机械加镜头，也不能只凭统一配色声称全片已有设计。
6. **实现选择与数据整理**：在设计成立后查询适配模板或规划新实现，最后整理现有 JSON。格式合法示例只解释字段与引用，不作为视觉质量基线；设计推导参考 [内容到画面](../references/content-to-visual.md#完整设计推导示例)。写入脚本只序列化已经作出的决定。

不新增运行时字段、独立导演文档或必交样片。以既有 `video-narrative.md` 为输入，将视觉主线落实在各幕 objective／focus／layout、Shot 衔接与跨幕对象关系中；逐幕与逐镜头决定写入现有 Shot 和 Event 字段，审查依据、修正和待验事项写入现有 evidence／note。任务完成 summary 概括主线、重点和待验范围，不代替具体设计。必要的草图与实验保存在现有本地工作资料中，说明验证问题与范围，不自动升级为模板或实片质量认证；不把制作说明混入口播。

提交前先确认创作完成：每幕已有具体表达及理解收益，关键变化可以读懂，全片承接与节奏有安排，主要表达不存在尚待重设计的问题。然后执行下述独立审查与结构校验。只向用户提交收敛方案，同时如实展示仍需实际观看判断的事项，不要求用户逐轮审核内部草稿。

改进是否有效须由实际首次交付验证：在用户指定的新视频或未完成视频中保留首次提交版本及画面依据，记录反馈属于构图／速度／层级等打磨，还是主体／表达机制／大量镜头的重设计；由用户判断是否达到成熟方案水平。代码检查只验证任务路由与提交契约，不能证明导演能力提高。首次交付、人工质量认可与跨视频稳定性分别记录，不修改 completed 视频以作验证。

### 关键变化怎样完成导演决策

逐幕表达与镜头组织时，先推演整幅画面，再确定动作参数。以下方法用于完成既有设计，不新增表格、字段、审计项或固定镜头结构：

- **情境与完整状态**：明确正在展示同一次执行，还是独立比较／故障假设。开始、变化中、结束时，除运动主体外，还要决定背景记录、结果和后续层级的状态；未到达的层级不能保留已执行结果。连续身份只保留仍成立的对象；切换假设时清退不再成立的证据。行为所需配置、权限和覆盖条件先确定，再设计交互，不能从默认配置直接推出有条件的行为。
- **口播与动作的共同含义**：先用一句话说清观众应理解什么，再共同安排台词和动作。锚点要匹配意思，不能只匹配相关词；提示风险时，成功通行、完成勾选等视觉强调也会产生含义。动作缺少合适语言落点时，在冻结前调整口播；不把语义问题留给 TTS 或实现阶段补救。
- **镜头内的注意力顺序**：先决定观众依次定位、追踪和阅读什么，再分配相机、主体及路径的运动与停留。并行运动须服务同一理解任务；若要求观众同时追踪两个焦点，就错峰、让位或改变构图。先确定关键状态与结果阅读，再写动作预算；不以增加 Shot／Event 或持续运动代替编排。
- **用实验回答具体疑问**：排版、字号与对应关系可用实际尺寸关键帧；路径、焦点交接及互斥状态切换按需要用短动画。声画含义可先对照台词与关键状态，尚无真实音频时明确时序仅为设计预算；真实同步留给正式 Timeline。实验前明确要判断的问题，查看后据实际结果修正。抽帧与完整解码不能证明正常速度的运动观感；必要观看无法完成时说明具体能力缺口和影响，不转交用户逐轮修内部草稿。交付画面依据时确保关联资源实际可取得，不能只给不可访问的本机相对链接。

这些决定落实在既有 before／action／after、触发锚点、Shot 焦点与衔接、元素生命周期及 evidence／note 中。方法推导见 [内容到画面](../references/content-to-visual.md#把关键变化设计完整)，不把教学示例当成固定视觉模板。

## 设计审计

画面具体化、镜头目的与因果动画按 `VIDEO-PRODUCTION-RULES.md` 6.1 执行：造型／构图和焦点写入 SQ-3，状态变化与结果写入 SQ-2／6，镜头衔接理由写入 shotChecks 及 SQ-8，实现条件写入 SQ-9。代表性难点实验及整片推广按 9.7 留证，不新增审计字段、阶段或强制样稿。

每个 Scene 和每个 Event 都必须接受以下检查。审计独立于创作内容，指出具体对象、事件、依据、问题和修正；不能提交一份无证据的「全部通过」声明。程序能够确定的引用、区间和版本检查交给程序，不默认增加模型调用。

### 设计与审查的执行顺序

先完成上节导演创作，再在同一任务内独立审查。内容理解、Scene 情境、Shot 观看方式和 Event 变化须由内容推导，不能从 JSON 骨架反推设计。量化基线用于校准已确定的设计，不能预先决定画面形式。单镜头与固定视角可以成立，须根据当前内容判断；不规定镜头菜单、最少切换或模板匹配率。写入脚本不能批量默认决定镜头构图、相机或审计结果。

初稿完成后，在同一任务内单独执行一次审查，再形成提交版：

1. 从观众角度检查教学链是否完整。操作教学须落实必要前提、具体命令／输入、示例对象、预期结果及原页面与结果的核对方式；涉及不一致时说明怎样识别和处理，不能只贴「已核对」标签。
2. 逐 Scene／Shot 检查对象造型、构图、观看距离、焦点及变化是否帮助理解。核对隐喻的含义，区分应遵守的原则、产品能力与实际验证结果，不把判断原则画成已证实的自动保证。
3. 通看全片，检查机械重复、信息拥挤、焦点混乱、平台／环境混淆及缺少必要对照。重复固定镜头不直接判错，但须核对各自的内容理由；也不能为消除重复而添加无意义运动。
4. 对照按表达问题选读的案例方法，判断构图、材质、信息组织、运动及焦点交接是否适配当前内容，不以拼接既有效果代替设计。
5. 发现教学路线、主体表达或大量镜头的重大问题，先内部修订，再重新检查受影响部分。用现有 evidence／note 记录具体依据、发现和修正；未能判断时保持 pending，不为了形式强行发现问题，也不预设全部通过。

审查先形成判断，再填写 checks／shotChecks。分别判断无声画面会被理解成什么、配合口播是否仍表达同一意思、连续状态与焦点交接能否跟上；重新审视所有可见对象共同构成的情境，不能只检查当前移动对象。允许推翻原设计；“没有错误标签”或“对象没有重叠”不足以证明没有误导。动态问题未完成必要观看时保留 pending，不能由静图结论代填。禁止从创作描述拼接所谓证据并无条件写入 pass；脚本可以整理真实判断、指纹和覆盖，不能代替教学与视觉审查。局部无法判断时可做必要的关键画面或短动作实验，不升级为强制样片、额外模型调用或新 Gate。

### 机器检查与审核展示的边界

Harness 校验版本、引用、区间、覆盖及审计记录是否满足提交条件，不能判断审美或证明审查有效。Gate 2 分别展示「结构校验」与「Agent 设计审查记录」，后者是待人工审核的判断，不是机器质量认证。全片中多个 Shot 相同的取景／相机描述或重复审计文本仅给出非阻断复查提示，不自动改写结果、阻止合理静置或据此宣布合格。提示按去除首尾及折叠连续空白后的精确文本分组；事件审计仅在相同 SQ 项内对照 evidence／note，镜头审计分别对照 evidence／note，不使用相似度、审美分数或质量阈值。审核包须保留命令、关键对象文案及 Event 的预期结果／对照状态，不能省略 JSON 中已有的具体内容。结构与提交条件通过仍不等于 Gate 2 人工批准或 Gate 3 实际观看通过。

| ID | MUST 检查 | 失败例子 |
|---|---|---|
| SQ-1 | 明确视觉帮助理解的内容及 sourceRefs 依据 | 把口播排成卡片，只有淡入 |
| SQ-2 | before／action／after 在对象状态上可观察 | 写「请求到达」，实际只画连接线 |
| SQ-3 | 焦点、让位、阅读停留与后续承接明确；需强调时指出目标和理由 | 每幕重建版式，旧主体无理由常驻，或所有元素都套醒目边框 |
| SQ-4 | 完整列出主体、容器、文字、路径、箭头、结果及子元素 | 只列文字，底线与状态指示灯游离 |
| SQ-5 | 元素区间及替换顺序可执行，父子区间一致 | 两个互斥状态同事件进入并都留到幕末 |
| SQ-6 | 请求、处理中和结果有明确身份 | 把请求面板换成绿色就声称文件已创建 |
| SQ-7 | 标题有用途、关联对象、焦点交接及退出；章节标题按正文时间让位 | 因有资料依据或字号小而全片保留，照搬独立模板时长挤占正文 |
| SQ-8 | 跨幕身份及终止事件明确，确需换视角说明原因 | 「保持空间连续」充当保留理由 |
| SQ-9 | 按内容设计后核对实现条件，组件缺失时规划所需实现，明确真实能力缺口 | 根据组件库倒推分镜，或把组件名／任意 JSX 当作实现保证 |
| SQ-10 | 时间源可支持动作顺序，阅读区间待真实时间复核 | 同 Cue 多个顺序事件都绑定其起点却称精确同步 |

每项使用 pass／fail／pending，附 Scene ID、Event ID、Element ID（如适用）、问题类型（design／implementation）、依据和修正。Gate 2 审计 pass 只表示方案满足要求，不能表示动画已观看。实际画面、完整动作及正常速度试听在 Gate 3 检查。

## 当前实现契约（2026-10-10）

统一画面执行器已移除。Agent 按冻结分镜编写当前视频 React／Remotion 组件；Harness 不生成组件、配置或对象树，不限制对象类型和动作名称。分镜仍使用 schemaVersion 3、冻结 5，Workflow 和人工 Gate 不变。

对象稳定 ID、资料依据、前态／动作／后态、父子关系及生命周期仍须明确。execution 记录动作说明、涉及对象和持续帧数，capability 是描述性名称，不是固定能力白名单。结构检查不能代替视觉设计。不能因为现有组件不支持而降级成矩形与标签。

## 时间与实现校验

使用真实 Cue／Segment／Timeline 绑定语义事件。durationFrames 只表示动作持续时间；缺少词级时间时，同 Cue 多个顺序动作阻断，不伪造偏移。跨幕身份、请求与结果区别、文字来源、动作区间及父子关系仍须检查。

Agent 提交 remotion-alignment.json，schemaVersion 5、kind 为 storyboard-authored-alignment。每幕保留 layout、visualEvents、screenText、implementationFiles、implementationSymbols、timing、audioSegments、subtitleCues、animationEvents、visualBindings、visualElements、storyboardEvents，并增加实际 startFrame、endFrame 与 events（id、startFrame、completeFrame）。这些数据由真实时间映射核验，不能用自报文案代替实现。

对齐清单还绑定 reviewVersion、storyboardFingerprint、timingFingerprint、implementationFingerprint、runtimeFiles 和 audioFiles。harness/src/storyboard-implementation.mjs 的 buildStoryboardImplementationReview 是只读计算器，返回当前源码／音频指纹及事件区间供制作 Agent 填写，不生成画面、写文件或通过审核。导入的本地依赖递归纳入指纹和输入包；源码或音频改变，原观看证据失效。旧 storyboard-execution-alignment 不兼容，未完成视频必须正常返工，completed 永久只读。

## 实际观看与人工 Gate

按 `VIDEO-PRODUCTION-RULES.md` 8.4～8.5、9.6 A 和 14.4，复查强调是否只落在必要对象、口播提示是否同步、章节标题是否流畅且不挤占正文、转场底层背景与透明度覆盖、交界连续性及无底板白字描边字幕的实际可读性。交界静帧／像素检查只补充漏底排查，局部实验只证明对应范围；两者都不能代替连续播放及整片观看／试听，检查结果记入既有 note／unresolved。

remotion-viewing-evidence.json 的 schemaVersion 升为 2；kind、slug、reviewVersion 和分镜／实现／时间指纹字段继续保留。viewer、viewedAt、scenes、checks、listening 和 unresolved 仍必需：逐幕完整播放、逐 Event 检查起点／中间／完成／交界，正常速度完整试听当前音频。每项记录真实范围、方法、结果、发现和遗留问题；未观看保持 pending，机器检查不能填写 pass。
