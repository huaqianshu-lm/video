# Harness 统一生产契约

Harness 是对话、CLI、Web UI 和批量视频生产的唯一调度器。Agent 领取任务并制作声明的产物；Harness 负责前置检查、持久化任务、真实产物校验、状态推进、返工和人工审核。讨论及只读查询不领取任务。

共享 JSON 写入通过同目录临时文件和原子替换发布，避免 Studio／CLI／后台 worker 的并发读者读到半份状态；失败保留旧记录，替换前再次核对 completed 只读。生产锁、跨文件 Journal 和人工 Gate 继续按原契约执行，原子写入不自动推进阶段。

当前生产仅使用 `storyboard-v1` 与现行分镜契约，使用 [Storyboard 生产契约](STORYBOARD-PRODUCTION-CONTRACT.md) 的阶段、合并任务、分镜审核与冻结。不提供旧生产入口。

## 当前生产与历史读取

所有新建入口由服务端统一设置 `productionContract: storyboard-v1` 和 `storyboardSchemaVersion: 3`，显式请求旧契约或旧格式均拒绝。缺少契约、legacy-v1、unified-v1 和旧分镜格式只用于历史读取，不继续生产。执行、领取、回传、重试、恢复、审批、批量、打包及交付统一检查当前契约，后台恢复不能重新运行旧任务或改写其记录。

未完成视频资料不满足当前规则时，使用共享 storyboard-rework 返工，展示精确范围后按同一计划执行／恢复。只沿用严格校验通过的公共上游，重建当前阶段图并重新审核失效 Gate。不自动改写历史视频，completed 永久只读。未知契约拒绝，不隐式回退。实际验证以 ROADMAP 为准。

## 制作与对话

- 所有入口使用同一任务包。策划为一个任务，产出 Content Analysis 与 Video Narrative；两份资料全部通过校验才推进，Gate 1 是内部检查，不逐份请求人工确认。口播与 Storyboard 在一个收敛任务中完成，不独立生产 Scene Script、Visual Script 或 HTML 原型。
- 对话 Agent 通过 `production-task claim <slug>` 领取任务，读取返回的任务包，完成后用 `production-task complete <id> --summary <制作说明>` 回传。使用 `fail <id> --reason <原因>` 记录失败；`resume <id>` 恢复同一任务。无需再次启动后台 Agent。
- Web UI 后台 Agent 与对话 Agent 共用持久化 Agent Job、任务包及项目执行锁。已有任务时不得启动另一执行者；服务器重启不得取消对话持有的任务。恢复要依据保存的任务 ID，不能依据聊天记忆。
- 上游输入改变后，旧任务不能提交；释放旧任务后由 Harness 刷新安排返工。已有文件或无变化的原样回传不算真实制作。人工 Gate 只在用户明确批准或驳回后记录。

TTS 的相同内容重制是显式例外：共享 TTS 生成器在音频、字幕、Timeline、资源包全部成功生成并校验后，保存本次生成记录。记录绑定视频、任务 ID、执行次数、任务输入指纹、冻结 TTS Script 字节指纹、开始／完成时间以及包含音频和字幕字节的产物指纹；时间戳本身不是制作证据。Harness 核对本次任务、落盘记录、当前输入及产物后，允许内容相同的真实重制推进。新的 TTS 任务使用按任务隔离的缓存；同一任务重试可恢复自身缓存，不借用历史任务缓存。失败不写成功记录，旧记录或只更新时间戳不能推进。对话领取的任务包提供 `context.ttsExecutionTask`，调用共享生成器时作为 `executionTask` 传入，回传时 Harness 读取本次任务的落盘记录；CLI、Web、批量执行器自动传递同一绑定。其他阶段及未接入生成记录的自定义 TTS 执行器保留原产物变化检查；旧契约的独立试听与阶段记录仅供历史读取，completed 永久只读。

## 确认

当前契约只在 Gate 2、Gate 3、Gate 4 请求生产审核。Gate 2 审查纯口播、Storyboard 与设计审计，冻结同版本方案；之后派生并校验 tts-script.json，以显式 +25% 生成真实音频、字幕及 Timeline。机器检查通过后制作Agent 编写的 Remotion，提交当前观看／试听证据后进入 Gate 3，人工检查正常速度试听、字幕／音画对齐、冻结分镜与清洁画面；审核绑定当前实现、音频及 Timeline 指纹。Gate 4 为最终成片人工验收。机器检查不代替实际观看或试听。

当前生产的正常速度试听合并在 Gate 3；旧独立试听记录仅供历史读取，旧项目须先返工。上游修改使相应审核和下游失效；返工使用 Harness 的任务与 Gate 驳回入口。

## 交付

所有交付入口最终复用 `render-delivery prepare／start／resume`。单条新交付默认 local，可选择 github；批量只允许 github，旧记录无 backend 时按 github 恢复。local 的 prepare 校验本机环境和输入，保存计划；确认后启动独立 worker，不发布、不 commit／push。github 的 prepare 执行成功基线预检、独立输入包发布绑定并展示精确提交计划，不 commit／push／dispatch；start 需要用户明确确认当前计划 ID；resume 恢复同一交付和 Job，不切换方式或重复执行。Gate 3 批准与交付授权分别保存，不互相代替；两种方式都停在 Gate 4。批量需要合并文件计划一次提交，每个视频保持独立输入包及 GitHub Job。详情见 `docs/RENDER-DELIVERY-BASELINE.md`。

迭代实现与验证状态以 ROADMAP.md 为准。未接入当前契约的入口必须阻止执行，不得把文档中的目标写成已实现；未完成人工 Gate、实际入口或跨视频验证时，不宣布整个生产流程已验证。

## 视频制作与流程变更的边界

用户授权制作视频，不等于授权改造制作流程。以下边界适用于对话、CLI、Web UI、单条和批量路径，也适用于阶段名称不变但阶段内部制作方式改变的情况。

1. **制作与流程改造分开。** 视频制作任务只制作当前契约声明的产物，不顺手新增通用画面生成器、强制依赖或修改制作契约。需要改流程时，先单独提出变更范围；不以视频制作授权替代流程变更授权。已经明确授权的变更按既定范围继续，不重复请求确认。
2. **影响制作方式的工具必须显式说明。** 新增或替换机制只要改变谁制作、怎样制作、允许怎样表达，或增加必须使用的工具，就属于流程变更。实施前展示原方式与新方式、受影响阶段和入口、表达限制、默认行为及验收方式，获得用户对具体变更的明确确认。不得以“内部实现细节”“共享能力”或阶段名称未变为由隐藏这些变化；Gate 批准不等于流程变更批准。
3. **组件不能反过来决定分镜。** 先按内容设计 Storyboard，再选择合适组件；没有合适组件就编写所需实现。组件库从持续视频制作中经过实际验证的实现逐步积累，提取条件见 `VIDEO-PRODUCTION-RULES.md` 13.3。公共组件不能成为画面表达的固定白名单；确实无法兑现设计时报告具体能力缺口，不能把组件缺失当成无法实现，也不把设计悄悄降级成组件支持的框与标签。
4. **流程检查必须核对实际调用。** 对本次受影响路径，除阶段与产物外，还要检查实际任务包及提示、Skill／规范引用、任务领取与执行时的自动写入或生成调用、产物消费者、校验的拒绝条件和默认／回退路径。列出其中强制工具与表达限制，核对是否与已确认契约一致；未声明或未经授权的限制不能作为生产要求。不能仅凭流程图、文件存在或结构检查通过认定流程一致。
5. **未验收能力不能成为默认或强制依赖。** 新画面制作机制先独立验证实际输出与适用观看／试听证据，明确剩余验证和失败边界。未经用户验收，不替代现有制作方式，不成为所有视频的默认或强制路径。隔离测试、类型或指纹通过不能代替画面质量验收；通用固化还须遵守项目跨视频验证要求。

变更说明和验收记录必须能追溯到具体授权、实际调用入口及对应规则。草案、局部修复、内部实现和测试记录不能自行升级为生产约束。以上是操作与审查要求；程序自动识别未经授权的流程变更是否已实现、实际入口是否已验证，以 ROADMAP.md 为准，不因本节写入而视为已具备机器约束。

## 后续变更的回归要求

新增功能或修改生产流程时，先列出本次实际受影响的入口、任务包、生产者、消费者及新旧契约，并据此选择定向检查。下面各项只测试本次修改涉及的部分，不要求运行对应模块的全部既有测试，也不自动扩大为整套回归。阶段推进、任务记录、执行锁、产物校验和 Gate 记录必须进入共享 Harness 服务；对话指令和 Web 按钮调用这些服务。执行器负责制作声明的产物并回传结果。

- 修改任务契约：同时验证对话 CLI 和 Web HTTP 返回的任务、状态与阻塞原因一致，并验证未领取、无产物、原样回传和过期输入不能推进。
- 修改执行或恢复：验证跨入口排斥、同一任务 ID 恢复、阶段内部断点，以及旧任务不能修改新任务状态。
- 修改审核或产物消费：验证统一契约与 legacy 契约，覆盖上游变化导致审核失效，以及 completed 的资料、状态和任务记录前后完全一致。
- 修改交付：验证未确认与过期清单阻断、准备阶段无提交／推送／派发、授权后定向提交，以及恢复原 Job。批量还要验证一次合并提交、逐视频输入包和 Job。

功能修改完成后，默认只运行覆盖本次修改及其直接受影响行为的定向测试和必要检查；可按测试文件、测试名称或具体入口选择，不能因为修改共享模块、入口或生产契约就自动运行整套测试。文档修改只核对相关规则一致性和差异，不运行功能回归。

只有用户明确要求整套测试时，才运行整套生产回归 `npm run test:production --prefix harness` 或全项目回归 `npm test --prefix harness`，并按用户指定范围选择；用户仅要求整套生产回归时，不再追加全项目回归。不得为了追求更高测试数量自动扩大范围。汇报实际检查范围和结果，定向检查通过不能写成整套回归通过。

命令和覆盖对应关系见 `harness/VALIDATION-MATRIX.md`。自动回归使用隔离项目和模拟外部服务；实际画面、试听、人工 Gate、宿主认证和真实远端交付仍按原规则验收。必要的定向检查未覆盖或未通过时登记到 ROADMAP.md；未执行用户未要求的整套回归不作为功能完成的阻塞，不以补充文档代替机器约束。
