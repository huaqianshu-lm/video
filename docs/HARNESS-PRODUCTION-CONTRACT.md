# Harness 统一生产契约

Harness 是对话、CLI、Web UI 和批量视频生产的唯一调度器。Agent 领取任务并制作声明的产物；Harness 负责前置检查、持久化任务、真实产物校验、状态推进、返工和人工审核。讨论及只读查询不领取任务。

## 版本与迁移

`project.json.productionContract` 为 `unified-v1` 时采用以下统一任务及审核契约。缺少该字段或为 `legacy-v1` 时继续支持既有阶段与独立 TTS 试听确认。不得通过刷新、批处理或读取自动迁移旧项目；completed 永久只读。未知契约必须报错，不得隐式回退。新建项目默认采用统一契约；14 个内部阶段及文件路径保持不变。

## 制作与对话

- 所有入口使用同一任务包。策划为一个任务，产出 Content Analysis、Video Narrative、Scene Script；保留三份文件与内部阶段，三份资料全部通过校验才推进。Gate 1 是内部检查，不逐份请求人工确认。
- 对话 Agent 通过 `production-task claim <slug>` 领取任务，读取返回的任务包，完成后用 `production-task complete <id> --summary <制作说明>` 回传。使用 `fail <id> --reason <原因>` 记录失败；`resume <id>` 恢复同一任务。无需再次启动后台 Agent。
- Web UI 后台 Agent 与对话 Agent 共用持久化 Agent Job、任务包及项目执行锁。已有任务时不得启动另一执行者；服务器重启不得取消对话持有的任务。恢复要依据保存的任务 ID，不能依据聊天记忆。
- 上游输入改变后，旧任务不能提交；释放旧任务后由 Harness 刷新安排返工。已有文件或无变化的原样回传不算真实制作。人工 Gate 只在用户明确批准或驳回后记录。

## 确认

统一契约只在 Gate 2、Gate 3、Gate 4 请求生产审核。Gate 2 审查口播与实际动态原型，冻结基线；之后从纯口播派生并校验 tts-script.json，以显式 +25% 生成真实音频、字幕及 Timeline。机器检查通过后可制作 Remotion，Gate 3 合并正常速度试听、字幕／音画对齐、冻结原型和清洁画面审核；音频审核绑定当前音频与 Timeline 指纹。Gate 4 为最终成片人工验收。机器检查不代替人工观看或试听。

旧契约保留独立 TTS 质检；禁止以新契约的默认值跳过旧项目检查。上游修改使相应审核和下游失效；返工使用 Harness 的任务与 Gate 驳回入口。

## 交付

所有交付入口最终复用 `render-delivery prepare／start／resume`。prepare 执行已验证基线预检、独立输入包发布绑定并展示精确提交计划，不 commit／push／dispatch；start 需要用户明确确认当前计划 ID；resume 恢复同一交付和 Job。Gate 3 批准与交付授权分别保存，不互相代替。批量需要合并文件计划一次提交，每个视频保持独立输入包及 Job。

迁移状态以 ROADMAP.md 为准。未接入的入口必须保留明确旧契约或阻止执行，不得把文档中的目标写成已实现；未完成人工 Gate、实际入口或跨视频验证时，不宣布整体迁移完成。

## 后续变更的回归要求

新增功能或修改生产流程时，先列出受影响的入口、任务包、生产者、消费者及新旧契约。阶段推进、任务记录、执行锁、产物校验和 Gate 记录必须进入共享 Harness 服务；对话指令和 Web 按钮调用这些服务。执行器负责制作声明的产物并回传结果。

- 修改任务契约：同时验证对话 CLI 和 Web HTTP 返回的任务、状态与阻塞原因一致，并验证未领取、无产物、原样回传和过期输入不能推进。
- 修改执行或恢复：验证跨入口排斥、同一任务 ID 恢复、阶段内部断点，以及旧任务不能修改新任务状态。
- 修改审核或产物消费：验证统一契约与 legacy 契约，覆盖上游变化导致审核失效，以及 completed 的资料、状态和任务记录前后完全一致。
- 修改交付：验证未确认与过期清单阻断、准备阶段无提交／推送／派发、授权后定向提交，以及恢复原 Job。批量还要验证一次合并提交、逐视频输入包和 Job。

每次变更运行 `npm run test:production --prefix harness`；改动涉及其他模块时，再运行 `npm test --prefix harness`。命令和覆盖对应关系见 `harness/VALIDATION-MATRIX.md`。自动回归使用隔离项目和模拟外部服务；实际画面、试听、人工 Gate、宿主认证和真实远端交付仍按原规则验收。未覆盖或未通过的路径登记到 ROADMAP.md，不以补充文档代替机器约束。
