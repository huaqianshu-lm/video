# Current Video Style

版本：`1`

## 作用边界

这份文件只定义视频的视觉表达基线，不定义内容生产顺序、口播规则、TTS 规则或 Remotion 执行流程。

Workflow 决定“视频如何生产”，本 Style 决定“画面如何表达”。新视频可以改变知识内容、Scene 数量和具体视觉事件，但应继续遵守这套视觉基线。

## 画布与整体气质

- 画幅：16:9 横屏。
- 设计基准：1920 × 1080，30fps。
- 气质：干净、科技感、克制、教程感。
- 背景：优先深色蓝黑背景，避免花哨纹理和无意义装饰。
- 主体：优先展示过程、状态变化、连接、执行和对比，而不是堆叠静态说明卡片。

## 色彩基线

- 背景：`#080d1d` 至 `#10182b`。
- 面板：`#1c2a3b`，需要覆盖后方内容时使用足够不透明度。
- 主文字：`#f5f7fb`。
- 次要文字：`#aab6c8`。
- 主强调色：浅蓝 `#8bd2ff`。
- 辅助强调色：淡紫 `#a39bff`。
- 成功和警告色只用于表达明确状态，不作为装饰。
- 发光效果保持轻微，不能牺牲文字和边界的可读性。

## 构图与文字

- 每个 Scene 只保留一个主要视觉中心。
- 主标题通常控制在 1～2 行，并给软件界面、终端、文件树和代码区域留出主体空间。
- 字幕放在稳定的底部安全区，控制在 1～2 行，不能与标题、卡片或下一集预告重叠。
- 顶部进度或状态提示必须给标题预留安全距离。
- 字体使用项目已有的 CJK 兼容字体栈，不引入新的字体依赖。
- 画面文字必须能追溯到当前视频生产资料；不得把参考视频的业务语义或制作辅助文字带入画面。

## 动画基线

- 动画必须表达信息：出现、替换、移动、连接、执行、冻结、回路或状态变化。
- 视觉事件应绑定到对应的语义或字幕 Cue，不按整幕百分比盲目平均展开。
- 列表、终端输出和流程节点应按理解顺序逐步出现，并在口播完成前保持必要状态。
- 转场克制，优先使用淡入、位移、缩放和状态切换；避免复杂 3D、粒子和电影级转场。
- 主要视觉元素完成入场后，应留出可读和理解时间；总结画面通常预留约 2～3 秒。

## 推荐表达类型

优先复用现有通用场景能力：

- 开场问题或标题钩子。
- 概念解释。
- 左右对比。
- 步骤和流程。
- 终端、文件树、代码或任务状态演示。
- 总结和下一集预告。

如果现有表达类型确实无法承载需求，先在 Visual Script 中说明缺口，再单独提出新增组件，不在 Style 层偷偷扩张组件体系。

## 输出边界

Visual Prototype 的导航、进度提示、调试标记和制作辅助说明只属于预览，不得进入最终 Composition 或 MP4。
