# Claude Code 第三方模型视频化 · 第四步：Narration Script

> 本文只保留实际口播内容。视觉说明、制作备注和检查项不放入 Scene 正文。

## Scene 01｜先别急着换模型

如果你每天都在用 Claude Code，API 账单高得心疼，或者官方接口连起来总是不稳定，那你可能会想到一个办法：换成 DeepSeek 之类的第三方模型。

但先别急着复制配置。

第三方模型不是人人都该换的省钱神器。轻度用户为了省一点钱，可能要花更多时间排查环境变量；主要做复杂架构和疑难调试的人，也可能用稳定性换来更低的价格。

所以这篇先不从命令开始，而是先回答一个问题：你到底值不值得换？

## Scene 02｜便宜和直连，换来了什么

第三方模型最吸引人的地方有两个：价格可能低很多，而且像 DeepSeek 这样的国内服务，通常更容易获得直连体验。

但交换条件也很明确。

复杂代码任务的能力，工具调用和多步 Agent 的稳定性，还有出了问题之后的官方支持，都可能和 Anthropic 官方模型不一样。

如果你是 API 重度用户，或者确实有连接问题，第三方值得评估。

如果你已经有 Claude 订阅，只做轻量任务，或者主要处理不能出错的复杂重构，那就别只为了小额节省急着切换。

## Scene 03｜你到底换了什么

那接入第三方，究竟换掉了什么？

可以把 Claude Code 想成车壳。它仍然负责读项目、调用工具、修改文件，以及推进整个 Agent 任务。

你改变的是它发请求的后端路径：请求先从 Claude Code 出发，发到一个兼容接口，再由那个接口交给具体模型回答，结果最后返回终端。

所以，Claude Code 没有被换掉，换的是它背后的模型路径。

这里有一个特别容易搞错的点：`ANTHROPIC_BASE_URL` 主要决定请求发到哪里，不负责决定哪个模型回答。

地址和模型名，是两个需要配对的配置。

## Scene 04｜三个变量，三种职责

把配置拆开，其实就是三类信息。

第一类是地址。`ANTHROPIC_BASE_URL` 告诉 Claude Code，请求要发到哪个兼容接口。

第二类是身份。`ANTHROPIC_AUTH_TOKEN` 通常用来携带第三方服务提供的 Token，具体要以供应商的接口要求为准。

第三类是模型。`ANTHROPIC_MODEL`，以及 Opus、Sonnet、Haiku 这些默认档位变量，决定实际由哪个模型回答。

用 DeepSeek 举例时，地址和模型名都只能看作示例。平台会更新接口和模型名称，最终要以当前官方文档为准。

换句话说，地址负责找对门，Token 负责进门，模型名负责叫对人。三者缺一个，配置就可能看起来完成了，实际上却没有按预期运行。

## Scene 05｜当前终端有效，不等于永久生效

还有一个很常见的坑：你在终端里执行 `export`，或者在 PowerShell 里设置 `$env:`，只代表当前窗口暂时拥有这组配置。

终端一关，配置可能就消失。要长期使用，才考虑写进 shell 配置文件或系统环境变量。

但持久化也意味着更长时间暴露密钥，所以 API Token 不要写进代码，不要提交 Git，也不要出现在可以分享的截图里。

画面里的密钥应该始终是占位符，而不是一串真实字符。

## Scene 06｜用 `/status` 验收，而不是凭感觉

配置完成以后，别只看 Claude Code 能不能启动。

进入项目目录，启动 Claude Code，输入 `/status`，重点检查两项：Base URL 和 Model。

如果 Base URL 还是官方地址，通常是环境变量没有生效，或者新终端没有加载配置。

如果提示模型不存在，先回到供应商官方文档确认模型名有没有变化。

如果出现 401 或鉴权失败，再检查 Token 是否错误、过期，或者复制时多了空格。

真正的验收不是“我执行过配置命令”，而是状态输出证明请求已经发到了正确的地址，并且使用了预期的模型。

## Scene 07｜别让所有任务都走同一个模型

如果你的目标是省钱，也不一定要把所有任务都塞给同一个便宜模型。

更稳的做法是按任务分层。

架构设计、跨模块重构和疑难调试，交给能力更强的模型。

日常增删改查、写测试和补文档，可以使用性价比更高的模型。

轻量问答、后台杂活和子代理任务，再交给便宜快速的模型。

这样做的重点不是记住一组固定模型名，而是让模型选择跟任务复杂度匹配。

## Scene 08｜兼容接口，不等于官方支持

最后提醒几个容易被旧教程带偏的地方。

以前常见的 `ANTHROPIC_SMALL_FAST_MODEL` 已经可能被新的模型变量取代，不能看到网上的配置就原样复制。

`ANTHROPIC_AUTH_TOKEN` 和 `ANTHROPIC_API_KEY` 发送的请求头也不一样，第三方接口到底要求哪一种，要看供应商的说明。

而且，兼容 Anthropic 协议，不等于获得 Anthropic 官方支持。接入非第一方主机后，工具调用、MCP 搜索等高级能力也可能出现差异。

所以模型名、接口地址和变量行为，都要以当前官方文档为准。

## Scene 09｜把切换权留在自己手里

现在把整件事串起来。

第三方模型适合 API 用量很高、官方连接困难，或者愿意接受实验性差异的人。

它不适合已经有固定订阅、使用量很小，或者主要依赖复杂任务稳定性的人。

真正的接入也不是只改一个 URL，而是把地址、身份和模型配对，再用 `/status` 看证据，最后按任务分层使用。

所以第三方模型不是必修课，而是一条可以验证、可以分层，也可以随时切回官方的后端路径。

省钱之前，先确认自己真的需要省这笔钱；切换之后，也始终把判断和回退权留在自己手里。
