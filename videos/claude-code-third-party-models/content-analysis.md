# Claude Code 第三方模型视频化 · 第一步：Content Analysis

> 目标：从原文中提取这条视频真正要解决的判断和操作问题，不直接按文章章节生成口播或镜头。

## 1. 内容定位

### 1.1 原文解决的问题

原文不是单纯教观众把 DeepSeek 接入 Claude Code，而是先回答一个更重要的问题：

> **第三方模型到底值不值得接，以及接入后如何确认真的生效。**

它同时覆盖三层内容：

- 决策：什么人适合换，什么人不该为了省钱折腾。
- 原理：Claude Code 作为客户端、第三方接口和具体模型之间如何配合。
- 操作：通过环境变量配置地址、鉴权和模型，再用 `/status` 验证。

### 1.2 内容类型

- 类型：判断型教程＋配置型教程。
- 观众状态：已经知道 Claude Code，想降低 API 成本或解决官方 API 连接问题，但不清楚第三方接入的代价和配置边界。
- 视频目标：让观众能先做出是否切换的判断，再理解配置项的职责，最后知道如何验证和排错。

## 2. 核心命题

### 2.1 主命题

> **接入第三方模型不是给 Claude Code 换一套代码，而是把请求地址、鉴权方式和模型名重新配对；它能用成本或直连性换取一定的能力、稳定性和官方支持。**

### 2.2 观众必须带走的三句话

1. 第三方模型的价值主要是降低成本或获得更容易的网络连接，不是所有人都值得切换。
2. `ANTHROPIC_BASE_URL` 决定请求发到哪里，`ANTHROPIC_AUTH_TOKEN` 负责第三方鉴权，模型变量决定由谁回答；只改 URL 不等于换了模型。
3. 配完必须用 `/status` 检查 Base URL 和 Model，不能凭“能启动”判断配置正确。

### 2.3 视频成功标准

观众看完后能够：

- 根据自己的账单、网络和任务类型判断是否适合第三方模型。
- 解释「Claude Code 壳／接口地址／模型」三者的关系。
- 看懂一组不包含真实密钥的 Mac／Windows 配置示例。
- 知道临时环境变量会随终端关闭而失效，模型名和接口地址应以供应商官方文档为准。
- 通过 `/status` 验证是否真正切换，并根据典型现象排查。
- 理解分层模型的思路，以及第三方接入的实验性边界。

## 3. 必须保留的知识骨架

### A. 先判断：不是人人都该换

第三方模型的两张王牌是：

- 成本可能低很多，适合高频 API 用户。
- 某些国内供应商可以提供更直接的网络连接。

对应代价是：

- 复杂代码任务的能力可能下降。
- 工具调用和多步 Agent 行为的稳定性取决于兼容程度。
- 配置和排错成本更高。
- 非 Anthropic 模型不属于 Claude Code 官方能力背书范围。

必须形成明确判断：重度 API 用户、需要国内直连的用户和愿意实验的人可以考虑；已有固定订阅、轻度使用或主要处理复杂架构任务的人，不应只为省小额费用切换。

### B. 换的不是 Claude Code 本体，而是后端模型路径

需要用一个简单关系解释：

```text
Claude Code：客户端和 Agent 工作流
        ↓ 发送请求
兼容接口：请求要发到哪里、按什么协议接收
        ↓ 路由到
具体模型：谁来生成回答
```

可以使用“车壳、地址、发动机”的类比，但画面必须同时保留真实配置名，避免类比遮蔽技术关系。

关键辨析：

- `ANTHROPIC_BASE_URL` 主要改变请求目的地。
- 接口是否兼容 Anthropic 协议，决定 Claude Code 能否按预期通信。
- 模型名决定供应商实际调用哪个模型。
- 因此「改 URL」和「选模型」是两个需要配对的动作。

### C. 配置由三类信息组成

用 DeepSeek 作为示例，但不把当前模型名或地址表达成永久不变的事实：

1. 地址：`ANTHROPIC_BASE_URL`。
2. 身份：第三方通常使用 `ANTHROPIC_AUTH_TOKEN`，值由供应商提供。
3. 模型：`ANTHROPIC_MODEL` 及 `ANTHROPIC_DEFAULT_*_MODEL` 等模型映射变量。

配置示例必须使用占位符，不能出现真实密钥。Mac／Linux 和 Windows PowerShell 可以保留为两种屏幕状态，但旁白只解释共同逻辑。

### D. 临时配置与永久配置是两个不同状态

- `export` 或 `$env:` 只影响当前终端会话。
- 关闭终端后，配置可能消失；长期使用才写入 shell 配置或系统环境变量。
- 持久化会增加误提交和误泄露风险，必须提醒密钥不进代码、不进 Git、不进共享截图。

### E. `/status` 是配置验收点

配置完成后不能只看 Claude Code 是否启动。

```text
启动 Claude Code
        ↓
输入 /status
        ↓
检查 Base URL
检查 Model
        ↓
确认实际路由
```

需要保留三类排错关系：

- Base URL 仍是官方地址：环境变量未生效或新终端没有加载配置。
- 模型不存在：模型名已变更或填写错误，应回到供应商官方文档。
- 401／鉴权失败：Token 错误、过期或复制了多余空格。

### F. 分层使用比“全部替换成一个便宜模型”更稳

Claude Code 的模型别名和子代理模型可以按任务分层：

- 复杂架构、疑难调试：强模型。
- 日常增删改查、测试和文档：性价比模型。
- 轻量后台任务、子代理：便宜快速模型。

这套思路是 Claude Code 的配置机制，不是 DeepSeek 专属功能。视频要表达“任务路由”，而不是鼓励观众机械复制一组固定模型名。

### G. 实验性边界与两个高频坑

需要保留但压缩：

- 非官方模型的协议兼容、工具调用和高级能力可能存在差异。
- 旧教程中的 `ANTHROPIC_SMALL_FAST_MODEL` 已被新的 Haiku 模型变量取代，应以当前官方文档为准。
- `ANTHROPIC_AUTH_TOKEN` 与 `ANTHROPIC_API_KEY` 的请求头行为不同，第三方兼容接口通常要按供应商要求选择。
- 接入非第一方主机后，部分依赖官方服务的能力可能行为不同。

不把修改 `~/.claude.json` 跳过官方引导作为主流程；它属于实验性绕过，最多作为风险提示，不进入可复制的默认配置。

## 4. 认知关系

### 4.1 决策关系

```text
API 账单高／官方连接困难
        ↓
第三方模型值得评估
        ↓
接受能力、稳定性和支持差异
```

如果只是轻度使用或已经有固定订阅，则不应为了小额节省承担配置成本。

### 4.2 配置关系

```text
BASE_URL：请求去哪里
AUTH_TOKEN：用什么身份进门
MODEL：由哪个模型回答
```

任一项不匹配，都会出现“看似配置了但没有按预期运行”的问题。

### 4.3 验证关系

```text
环境变量
   ↓
Claude Code 启动
   ↓
/status
   ↓
Base URL + Model
   ↓
实际配置结论
```

### 4.4 分层关系

```text
任务复杂度
   ├─ 硬任务 → 强模型
   ├─ 日常任务 → 平衡模型
   └─ 轻任务／子代理 → 便宜模型
```

## 5. 可视觉化内容

### 5.1 最有 Video Value 的内容

1. **决策天平**：省钱／直连和能力／稳定性之间的取舍，适合开场建立判断。
2. **请求链路**：Claude Code → Base URL → Auth Token → Model → 返回终端，适合解释抽象配置。
3. **配置状态变化**：未配置、配置了错误地址、配置正确，用 `/status` 结果区分。
4. **Mac／Windows 双终端**：展示同一组逻辑在不同命令环境中的写法差异。
5. **分层路由**：同一个 Claude Code 任务被分到强、中、快三个模型档位。
6. **故障排查卡片**：Base URL、模型名、401 三种现象与对应修复动作。

### 5.2 声音与画面分工

- 旁白负责解释“值不值得换”“每个变量的职责”和“实验性边界”。
- 画面负责演示请求去向、配置前后状态、`/status` 的验收证据和任务分层。
- 屏幕不完整展示密钥；用 `<YOUR_API_KEY>` 或遮罩替代。
- 不把原文大表格整张搬上屏幕；对比项拆成少量变化或分组卡片。

### 5.3 原文处理规则

- 保留 DeepSeek 作为具体示例，但所有地址、模型名和官方支持状态都标成“以当前供应商／官方文档为准”。
- 保留 Mac／Linux 与 Windows 的配置差异，但不让命令块成为整条视频的主体。
- 弱化文章中的个人经历、夸张口语和系列导航，把“不是必修课”的判断保留下来。
- 不在本阶段引入新供应商、新模型或未经原文支持的性能结论。

## 6. 应该弱化或不进入主线的内容

- DeepSeek 开放平台注册步骤和具体网页路径：作为前置提示，不做逐页演示。
- `~/.zshrc`、`~/.bashrc`、PowerShell Profile 的完整写入操作：只说明持久化边界。
- 精确价格和“省到原来的三分之一”等随时间变化或缺乏可复验范围的数据：改成“可能低很多”，不作为硬承诺。
- `/status` 输出中的账户信息：只突出 Base URL 和 Model。
- 跳过官方登录引导的配置文件修改：作为实验性风险注记，不做主流程。
- 下一篇订阅套餐内容：只保留一句上下文收束。

## 7. 内容风险与实施约束

- 文章中 DeepSeek 的接口地址、模型名和变量支持可能变化，画面与口播必须使用“示例／以官方文档为准”的表述。
- 不展示真实 API Key，不鼓励把 Token 写进代码或提交 Git。
- 不把第三方模型描述成 Claude 的官方替代品；明确它是兼容接口下的实验性接入。
- “代码能力、Agent 稳定性”属于体验判断，口播使用“可能”“取决于模型和接口”，不下绝对结论。
- 任何配置示例都必须能被视觉脚本拆解为地址、身份、模型三类信息，避免出现只展示命令却没有认知解释的画面。
