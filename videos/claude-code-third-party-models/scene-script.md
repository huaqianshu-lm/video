# Claude Code 第三方模型视频化 · 第三步：Scene Script

> 本阶段只确定每个 Scene 的认知任务、叙事作用和视觉价值；口播正文与视觉动作在 Gate 1 通过后继续制作。

## Scene 01｜先别急着换模型

### 目的

把“第三方模型＝省钱神器”的直觉改成一个需要判断的问题。

### 认知任务

让观众先对照自己的 API 账单、网络连接和任务强度，理解换模型不是人人必做。

### 叙事作用

建立冲突，阻止视频直接滑向配置教程。

### 口播方向

从 API 账单高、官方连接困难两个真实动机切入，明确轻度用户和订阅用户不一定值得折腾。

### 视觉方向

账单、网络连接和复杂重构三个标签被放到一架取舍天平上；“省钱／直连”亮起后，“能力／稳定／支持”同时出现。

### Scene Type

`OpeningScene`

### 屏幕重点

```text
第三方模型，值得换吗？
```

### Video Value

用天平的状态变化把“省钱”和“代价”变成可感知的冲突，不能只靠旁白说明。

### 信息分工

- 口播：解释适用人群和不适用人群。
- 画面：展示判断维度和冲突。

## Scene 02｜便宜和直连，换来了什么

### 目的

建立官方模型与第三方模型之间的核心取舍。

### 认知任务

让观众知道第三方的优势不是全面领先，代价可能落在复杂代码能力、Agent 稳定性和官方兜底上。

### 叙事作用

把开场的疑问具体化，为后面的“实验性”埋伏笔。

### 口播方向

概括两边的优势和风险，不朗读完整对比表；强调日常任务与硬核重构的结果可能不同。

### 视觉方向

左右两块模型卡片，第三方卡片突出“成本／直连”，官方卡片突出“能力／稳定”；中间出现交换箭头。

### Scene Type

`ComparisonScene`

### 屏幕重点

```text
省钱 + 直连
换来
能力 + 稳定性差异
```

### Video Value

对比卡片在交换和重新排序中表达“收益与代价同时存在”，比静态表格更有判断价值。

### 信息分工

- 口播：说明不同用户的选择不同。
- 画面：给出四个核心取舍词。

## Scene 03｜你到底换了什么

### 目的

建立 Claude Code、接口地址和具体模型的三层心智模型。

### 认知任务

纠正“改个地址就换模型”的误解。

### 叙事作用

从决策转入原理解释，给配置命令建立上下文。

### 口播方向

解释 Claude Code 仍是负责读项目、调用工具和推进任务的客户端；第三方接入改变的是请求经过的后端路径。

### 视觉方向

一个 Claude Code“车壳”保持不变，请求从它出发，经过地址节点，再到具体模型节点；返回路径回到终端。

### Scene Type

`ConceptScene`

### 屏幕重点

```text
Claude Code 不变
请求路径改变
```

### Video Value

节点和请求流动把抽象的“换后端”变成可追踪的过程。

### 信息分工

- 口播：解释客户端、兼容接口和模型的关系。
- 画面：证明请求先到地址，再由模型回答。

## Scene 04｜三个变量，三种职责

### 目的

把接入配置压缩为地址、身份、模型三类信息。

### 认知任务

让观众知道 `BASE_URL`、`AUTH_TOKEN` 和模型名不能混为一谈。

### 叙事作用

把原理落到可执行配置，但不让视频退化成命令背诵。

### 口播方向

逐一解释“请求去哪里”“用什么身份进门”“由哪个模型回答”，并强调 URL 与模型名必须配对。

### 视觉方向

三张配置卡依次插入一张请求单：地址卡改变目的地，Token 卡通过鉴权，模型卡选择回答者；密钥区域始终遮罩。

### Scene Type

`TerminalScene`

### 屏幕重点

```text
BASE_URL = 去哪里
AUTH_TOKEN = 用谁的身份
MODEL = 谁来回答
```

### Video Value

配置项真实改变请求卡的不同字段，展示职责差异，而不是只显示一段 export 命令。

### 信息分工

- 口播：解释变量语义和示例值的时效性。
- 画面：展示三类变量如何共同组成一次请求。

## Scene 05｜当前终端有效，不等于永久生效

### 目的

解释临时环境变量和持久化配置的边界，同时建立密钥安全意识。

### 认知任务

让观众理解为什么“刚才还能用，重开终端又失效”，以及为什么不能把 Token 写进代码。

### 叙事作用

补足配置教程最常见的实际落差，为验证环节制造合理的失败状态。

### 口播方向

说明 `export`／`$env:` 只作用于当前窗口；长期使用可以写入 shell 或系统环境变量，但要避免泄露和误提交。

### 视觉方向

同一终端窗口关闭后，配置灯熄灭；重新打开窗口后出现“未加载”。旁边的 Token 显示为 `<YOUR_API_KEY>` 并被锁定。

### Scene Type

`StepListScene`

### 屏幕重点

```text
当前会话 ≠ 永久配置
密钥不要进 Git
```

### Video Value

窗口关闭导致状态变化，直接演示临时变量的生命周期和密钥风险。

### 信息分工

- 口播：解释持久化选择和安全边界。
- 画面：展示配置消失及密钥遮罩。

## Scene 06｜用 `/status` 验收，而不是凭感觉

### 目的

建立配置完成后的可验证闭环。

### 认知任务

让观众知道“Claude Code 能启动”不代表“请求已经发给第三方模型”。

### 叙事作用

全片的操作高潮，从配置转入证据检查。

### 口播方向

先展示错误状态，再说明输入 `/status` 只重点看 Base URL 和 Model；随后按地址未变、模型不存在、401 三种现象排查。

### 视觉方向

终端依次显示三种状态：仍是官方地址、模型不存在、正确的 DeepSeek 示例地址和模型。错误状态旁边出现对应修复箭头。

### Scene Type

`TerminalScene`

### 屏幕重点

```text
/status
Base URL: ...
Model: ...
```

### Video Value

状态输出前后变化提供了“配置是否生效”的视觉证据，是视频比文章更有价值的部分。

### 信息分工

- 口播：解释观察证据和排错逻辑。
- 画面：展示输出字段及错误到修复的对应关系。

## Scene 07｜别让所有任务都走同一个模型

### 目的

把“换一个便宜模型”升级为按任务分层路由。

### 认知任务

让观众理解强模型、平衡模型和便宜快速模型适合不同任务。

### 叙事作用

提供兼顾成本和质量的进阶方案，避免观众把第三方接入理解成全量替换。

### 口播方向

用架构设计、日常编码、后台杂活三个任务说明模型分层，并强调具体模型名不能脱离供应商文档固定复制。

### 视觉方向

三个任务卡从 Claude Code 出发，被路由到“强”“平衡”“快速”三个模型档位；复杂任务经过更长的校验路径。

### Scene Type

`StepListScene`

### 屏幕重点

```text
硬任务 → 强模型
日常活 → 平衡模型
后台活 → 快速模型
```

### Video Value

任务卡实际流向不同模型，表达“模型配置是路由”而不是静态变量表。

### 信息分工

- 口播：解释分层依据和适用场景。
- 画面：演示不同任务被分配到不同档位。

## Scene 08｜兼容接口，不等于官方支持

### 目的

收束实验性边界和高频配置坑。

### 认知任务

让观众记住旧变量、鉴权变量和高级能力差异都可能随版本或供应商变化。

### 叙事作用

在结尾前降低过度承诺，保护观众不照抄过期方案。

### 口播方向

快速指出弃用变量、`AUTH_TOKEN`／`API_KEY` 的差别，以及非第一方主机可能影响部分能力；所有模型名和地址回到官方文档确认。

### 视觉方向

三张警告卡依次盖章：“弃用变量”“鉴权方式”“兼容边界”；一张旧配置卡被替换为“查当前官方文档”。

### Scene Type

`ComparisonScene`

### 屏幕重点

```text
兼容 ≠ 官方背书
以当前文档为准
```

### Video Value

旧配置被替换、警告状态升级，表达版本漂移和实验性风险。

### 信息分工

- 口播：给出风险和边界。
- 画面：让“旧方案不可直接照抄”成为状态变化。

## Scene 09｜把切换权留在自己手里

### 目的

给出最终决策和可回退心智模型。

### 认知任务

让观众形成“可判断、可验证、可分层、可回退”的完整闭环。

### 叙事作用

总结全片，不重复操作细节。

### 口播方向

重度 API 用户或连接困难用户可以尝试；轻度用户、订阅用户和复杂重构用户不必为了小额节省增加复杂度。第三方是实验性路由，不是必修课。

### 视觉方向

三层链路重新出现，旁边依次亮起“先判断”“再验证”“按任务分层”；一个切换开关可以回到官方路径。

### Scene Type

`SummaryScene`

### 屏幕重点

```text
先判断
再验证
按任务分层
保留回退权
```

### Video Value

回退开关和四个结论状态把整条视频的决策框架压缩成一个可记忆的视觉模型。

### 信息分工

- 口播：给出适用人群和最终判断。
- 画面：收束配置、验证和回退关系。

## Scene 关系与转场

```text
01 判断问题
   ↓
02 收益与代价
   ↓
03 三层原理
   ↓
04 三类配置
   ↓
05 生命周期与安全
   ↓
06 /status 验收
   ↓
07 任务分层
   ↓
08 实验性边界
   ↓
09 决策收束
```

- Scene 01 → 02：天平两端展开成对比卡片。
- Scene 02 → 03：对比卡片收缩为一个“第三方路径”节点。
- Scene 03 → 04：请求链路停在配置入口，展开三类变量。
- Scene 04 → 05：配置卡保留在终端，窗口关闭触发生命周期变化。
- Scene 05 → 06：重新打开终端，直接进入 `/status` 验证。
- Scene 06 → 07：正确模型状态变成任务路由入口。
- Scene 07 → 08：三个模型档位收束为兼容性警告。
- Scene 08 → 09：警告卡退到背景，回到可切换的三层链路。

## Gate 1 一致性检查

- Scene 数量：9 个，覆盖 Video Narrative 的九段叙事。
- Scene Type：只使用现有 `OpeningScene`、`ComparisonScene`、`ConceptScene`、`TerminalScene`、`StepListScene`、`SummaryScene`。
- 内容覆盖：决策、取舍、原理、配置、持久化、验证、分层、风险、结论均有对应 Scene。
- 视觉价值：每个 Scene 都有明确的过程、状态变化或路由变化，不把口播原样作为画面。
- 屏幕文字：每幕只保留一个主重点，真实密钥、精确价格和不稳定模型名不作为固定事实展示。
