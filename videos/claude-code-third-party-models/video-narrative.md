# Claude Code 第三方模型视频化 · 第二步：Video Narrative

> 目标：不按原文章节机械改编，而是让观众从“我该不该换”走到“我知道怎么配、怎么验、什么时候切回去”。

## 1. 视频叙事目标

这条视频不把重点放在“DeepSeek 配置命令”，而是完成一次判断升级：

```text
第三方模型 = 省钱神器
          ↓
它其实是一笔取舍
          ↓
先判断自己是否适合
          ↓
再理解地址、身份、模型的关系
          ↓
配置后用 /status 验收
          ↓
按任务分层，保留切回官方的能力
```

观众最后应该知道：第三方接入不是必修课，也不是“改一个 URL”这么简单，而是一套可验证的后端路由选择。

## 2. 叙事主线

```text
开场：账单或连接问题
        ↓
取舍：省钱和直连，换来什么代价
        ↓
原理：Claude Code、接口地址、模型三层关系
        ↓
配置：地址＋身份＋模型
        ↓
验收：/status 证明是否真的切换
        ↓
进阶：不同任务使用不同模型
        ↓
边界：实验性接入，保留人的判断和回退权
```

## 3. 观众状态变化

| 阶段 | 观众原本的疑问 | 视频给出的答案 |
|------|----------------|----------------|
| 开场 | “换第三方是不是人人都该做？” | 先看账单、网络和任务类型 |
| 取舍 | “便宜是不是没有代价？” | 代价是能力、稳定性和官方支持差异 |
| 原理 | “为什么改几个变量就能换模型？” | Claude Code 是客户端，请求经兼容接口路由到模型 |
| 配置 | “这些变量到底分别干什么？” | 地址、身份、模型三类变量各司其职 |
| 验证 | “能启动就算成功吗？” | 必须看 `/status` 的 Base URL 和 Model |
| 进阶 | “能不能既省钱又保质量？” | 按任务复杂度分层，硬任务保留强模型 |
| 收束 | “第三方是不是官方替代品？” | 不是，实验性接入要接受边界并保持可回退 |

## 4. 各段叙事设计

### 01 开场：先别急着换模型

从两个真实动机开场：API 账单高，或者官方接口连接困难。画面先给出“省钱／直连”的吸引力，再用一个明显的取舍切断“人人都该换”的期待。

这一段不讲配置，只建立判断问题：**你是确实有成本或连接痛点，还是只是被教程带着折腾？**

### 02 取舍：第三方模型的收益和代价

用一组动态对比表达：

```text
第三方：便宜、可能更容易直连
官方：能力、工具调用和支持更稳
```

不要把原文表格全部朗读。重点让观众理解：轻量日常任务和重度 API 用户的答案不同，复杂重构不能只按价格做决定。

### 03 原理：到底换了什么

用“车壳、地址、发动机”的类比进入真实链路：Claude Code 仍然负责读项目、调工具和推进任务，`ANTHROPIC_BASE_URL` 改变请求目的地，模型名决定实际回答者。

这一段必须强调：**Base URL 不是模型名。只改地址，不等于已经选定了正确模型。**

### 04 配置：三类变量要配对

把配置拆成三张逐步亮起的卡片：

1. 地址：`ANTHROPIC_BASE_URL`。
2. 身份：`ANTHROPIC_AUTH_TOKEN`。
3. 模型：`ANTHROPIC_MODEL` 和默认档位映射。

DeepSeek 只作为示例供应商，屏幕显示示例值和占位符，旁白提醒接口地址、模型名必须以当前官方文档为准。

### 05 配置状态：当前终端和永久生效

让同一组配置经历两个状态：当前终端里有效，关闭窗口后消失。再展示把配置写入 shell 或系统环境变量的选择，同时把密钥遮罩和“不要进 Git”作为画面约束。

这一段只讲边界，不做完整系统设置教程，避免观众把视频重心误解为环境变量语法课。

### 06 验证：用 `/status` 看证据

这是全片的操作闭环。画面先展示一个“看似启动成功但仍指向官方”的错误状态，再用 `/status` 显示 Base URL 和 Model，最后切到正确状态。

排错按现象组织：地址没变查环境变量，模型不存在查供应商文档，401 查 Token。观众要看到的是“观察证据 → 定位类别 → 修正”，而不是死记错误码。

### 07 进阶：不要让所有任务都走同一个模型

把任务拆成三条路：

```text
复杂架构／疑难调试 → 强模型
日常编码／测试／文档 → 平衡模型
后台杂活／子代理 → 便宜快速模型
```

这段把“省钱”从一次性替换升级为“按任务路由”。强调模型分层机制不是 DeepSeek 专属，具体模型名仍需按供应商能力配置。

### 08 坑点：兼容不等于官方支持

用两个快速状态卡收束风险：旧变量名可能已弃用，`AUTH_TOKEN` 和 `API_KEY` 的请求头行为不同。然后补充：非第一方主机可能影响 MCP 搜索等高级能力。

不把实验性跳过登录引导作为教程步骤，只把它放在“不要轻易复制”的风险区域。

### 09 结尾：把切换权留在自己手里

最后不重复命令，而是给出决策句：

> **值得换的人，用第三方降低成本或解决连接问题；不值得换的人，继续用官方，别为了小额节省增加不必要的复杂度。**

画面回到三层链路，并显示“可验证、可分层、可切回”的三个结论，完成从冲动换模型到理性路由的认知收束。

## 5. 信息取舍

### 主线必须出现

- 是否值得换的判断条件。
- 第三方接入的能力／稳定性／支持取舍。
- Base URL、Auth Token、Model 的职责。
- Mac／Linux 和 Windows 配置的共同逻辑。
- `/status` 验证与三类排错。
- 按任务分层使用模型。
- 实验性边界与密钥安全。

### 适合压缩为辅助信息

- DeepSeek 注册并创建 API Key。
- `.zshrc`、`.bashrc` 和 PowerShell Profile 的持久化路径。
- `ANTHROPIC_DEFAULT_OPUS_MODEL`、`SONNET`、`HAIKU` 和子代理变量的完整列表。
- 旧变量弃用和 `AUTH_TOKEN`／`API_KEY` 的差异。

### 不进入主线

- 修改 `~/.claude.json` 跳过官方引导的具体操作。
- 精确价格、固定节省比例和随时间变化的模型名称。
- 下一篇订阅套餐的详细比较。

## 6. 叙事与视觉原则

- 每一段都推动“判断 → 配置 → 验证”中的一个认知变化，不做平铺功能清单。
- 口播解释取舍和变量职责，画面展示链路、状态变化和验证证据。
- 终端命令使用占位符，真实密钥永不出现。
- 第三方模型用“兼容接口示例”表达，不画成官方内置下拉选项。
- 视觉主色可以用绿色表示节省／直连，用蓝色表示官方／稳定，用黄色表示实验性和警告；颜色只辅助语义，不替代文字。

## 7. 叙事验收标准

- 开头 30 秒内明确“不是人人都该换”。
- 观众能用一句话解释 Base URL 和 Model 的区别。
- 至少一次展示配置前后 `/status` 的可见差异。
- 至少一次展示错误现象到排错动作的对应关系。
- 分层使用画面不是静态表格，而是任务流向不同模型档位的变化。
- 结尾保留“实验性、可验证、可回退”三个边界。

## 8. 下一步
