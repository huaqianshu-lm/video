# Claude Code 第三方模型视频化 · 第五步：Visual Script

> 本文根据 `scene-script.md` 和 `narration-script.md` 定义画面结构、视觉动作和声画分工。它不是 Remotion 配置；Visual Prototype 先验证构图、信息密度和状态变化，之后再根据确认后的 TTS 时间轴确定时长。

## 全局视觉原则

### 1. 画面不能只是重复口播

口播负责解释是否值得换、变量职责和风险边界；画面必须演示取舍、请求路由、配置状态和 `/status` 证据。

### 2. 视觉承担证明和演示

本片最重要的视觉证据是：

- 省钱／直连和能力／稳定之间存在交换。
- Claude Code 外壳保持不变，请求路径发生变化。
- 地址、身份和模型是三个不同配置字段。
- 配置失败和配置成功可以通过 `/status` 区分。
- 不同任务可以被路由到不同模型档位。

### 3. 一个 Scene 只表达一个视觉中心

每幕只保留一个主要动作。配置命令、风险提醒和旁白解释只能服务当前动作，不能同时堆成完整文档页面。

### 4. 少做页面，多做过程

优先使用天平变化、请求流动、卡片插入、终端状态切换、任务路由和警告替换，不把原文表格整张搬到画面上。

### 5. 动画必须有意义

动画只表达实际信息：收益和代价出现、请求经过节点、变量完成配对、终端关闭导致状态消失、`/status` 命中正确结果、任务进入不同模型档位。

## 视觉规格

- 画布：16:9 横屏，按 1920 × 1080 设计。
- 风格：深色、干净、克制、科技教程感。
- 色彩：蓝色表示 Claude Code／官方路径，绿色表示成功／节省，紫色表示第三方路径，橙色表示实验性警告，红色只表示失败或鉴权错误。
- 固定结构：顶部显示系列名和 Scene 编号，中部展示主视觉，底部预留字幕安全区。
- 主标题控制在 1～2 行；环境变量和终端输出使用等宽字体。
- 配置命令使用占位符，不展示真实 API Key；具体模型名和地址使用示例标签。
- 每幕停留在一个可读的最终状态，不用快速闪切代替信息推进。

## 通用画面和转场

### 通用画面层级

```text
背景层：深色渐变、低对比网格、轻微光晕
信息层：标题、主卡片、状态标签、路径说明
动作层：天平、请求线、扫描、输入、路由、替换
字幕层：底部固定安全区
```

### 通用转场

- 普通转场：当前主卡片向左收缩，下一幕主卡片从右侧进入。
- 关系转场：保留上一幕的关键对象，用连线带入下一幕。
- 状态转场：保留终端窗口，通过内容替换表达“未加载 → 已加载”或“失败 → 成功”。
- 结尾转场：Scene 08 的警告卡片退到背景，Scene 09 的可切换链路回到中心。

# Scene 01｜先别急着换模型

## 视觉目标

用一架取舍天平让观众看到“省钱／直连”和“能力／稳定／支持”不是同一侧的收益。

## 构图

- 中央为横向天平，左侧是 `省钱`、`国内直连`，右侧是 `代码能力`、`Agent 稳定`、`官方支持`。
- 顶部标题只显示“第三方模型，值得换吗？”。
- 底部字幕区保持空出，不放解释段落。

## 动作顺序

1. 左侧“省钱”标签和账单图形进入。
2. “国内直连”进入后天平向左倾斜。
3. 右侧三个代价标签依次出现，天平回到接近平衡。
4. 中央出现“先判断，再配置”。

## 屏幕文字

```text
第三方模型，值得换吗？
先判断，再配置
```

## 声画关系

旁白解释适用人群，画面只演示取舍，不提前给出绝对答案。

## 转场

天平两端收缩成左右两张模型卡，进入 Scene 02。

# Scene 02｜便宜和直连，换来了什么

## 视觉目标

把收益和代价做成明确对比，而不是完整表格。

## 构图

- 左侧紫色第三方卡：`成本低`、`可能更易直连`。
- 右侧蓝色官方卡：`能力更稳`、`官方支持`。
- 中间一条双向交换箭头。

## 动作顺序

1. 第三方卡先亮起，显示两个收益。
2. 官方卡亮起，显示两个稳定性标签。
3. 双向箭头出现，箭头中间显示“交换”。
4. 卡片底部出现小字“复杂任务结果取决于模型和接口”。

## 屏幕文字

```text
便宜 + 直连
换来
能力 + 稳定性差异
```

## 声画关系

口播给出适用与不适用人群，画面保持对比关系，不展示精确价格或固定性能比例。

## 转场

第三方卡片变成一条发出的请求，进入 Scene 03。

# Scene 03｜你到底换了什么

## 视觉目标

建立 Claude Code、兼容接口和具体模型的三层请求链路。

## 构图

```text
Claude Code  →  Base URL 兼容接口  →  DeepSeek 示例模型
      ↑                                  ↓
      └──────────── 返回结果 ────────────┘
```

- Claude Code 节点使用蓝色，接口节点使用紫色，模型节点使用绿色。
- 下方保留一个不变的“项目／工具／终端”外壳条。

## 动作顺序

1. Claude Code 外壳出现，内部显示 `read / edit / run`。
2. 请求包从 Claude Code 发出，经过 `BASE_URL` 节点。
3. 请求进入 `Model` 节点后生成结果。
4. 返回线回到终端，Claude Code 外壳保持原样。
5. `URL ≠ Model` 作为短暂提示出现。

## 屏幕文字

```text
Claude Code 不变
请求路径改变
URL ≠ Model
```

## 声画关系

旁白负责解释“车壳、地址、发动机”的类比，画面用请求流动证明三层关系。

## 转场

请求节点拆成三个配置字段，进入 Scene 04。

# Scene 04｜三个变量，三种职责

## 视觉目标

让三个配置变量分别改变请求卡片的不同字段。

## 构图

- 左侧为三张纵向配置卡。
- 右侧为一张请求卡，包含 `Destination`、`Authorization`、`Model` 三行。
- 中间用箭头表示卡片写入请求。

## 动作顺序

1. `ANTHROPIC_BASE_URL` 写入 `Destination`。
2. `ANTHROPIC_AUTH_TOKEN` 写入 `Authorization`，值显示 `<YOUR_API_KEY>`。
3. `ANTHROPIC_MODEL` 写入 `Model`，值显示 `example-model`。
4. 三行同时变绿，底部出现“地址＋身份＋模型”。

## 屏幕文字

```text
BASE_URL = 去哪里
AUTH_TOKEN = 用谁的身份
MODEL = 谁来回答
```

## 声画关系

旁白解释每个变量的职责，画面不朗读完整命令，只展示字段如何配对。

## 转场

请求卡片复制成终端窗口，进入 Scene 05。

# Scene 05｜当前终端有效，不等于永久生效

## 视觉目标

演示临时环境变量的生命周期和密钥保护边界。

## 构图

- 中央是一扇终端窗口，左上显示 `session: active`。
- 窗口内显示占位 Token 和三个配置变量。
- 右侧有锁形安全卡，显示“不要进 Git”。

## 动作顺序

1. 终端内配置灯亮起，状态为 `loaded`。
2. 窗口关闭，配置灯熄灭，状态变为 `not loaded`。
3. 新终端打开但没有配置，出现“需要重新加载或持久化”。
4. 安全卡锁定 `<YOUR_API_KEY>`。

## 屏幕文字

```text
当前会话 ≠ 永久配置
密钥不要进 Git
```

## 声画关系

口播说明 `export`、`$env:` 和持久化的差异，画面只演示窗口关闭导致的状态变化。

## 转场

新终端恢复后，光标停在 `claude` 命令，进入 Scene 06。

# Scene 06｜用 `/status` 验收，而不是凭感觉

## 视觉目标

用三种终端状态展示从错误配置到正确配置的验收过程。

## 构图

- 左侧终端占 60％，显示 `/status` 输出。
- 右侧排错卡占 30％，随错误状态切换内容。
- 正确状态使用绿色边框，错误状态只用红色标记问题行。

## 动作顺序

1. 输出一：`Base URL: official`，右侧显示“环境变量未生效”。
2. 输出二：`Model: not_found`，右侧显示“查供应商文档”。
3. 输出三：`Base URL: https://example-provider/...`、`Model: example-model`，右侧显示“verified”。
4. 角落短暂出现 `401 → 检查 Token`。

## 屏幕文字

```text
/status
Base URL: ...
Model: ...
```

## 声画关系

旁白按“观察证据 → 定位类别 → 修正”推进，画面把三种输出状态直接对应到排错动作。

## 转场

正确的 Model 行向右延展成三个任务路由，进入 Scene 07。

# Scene 07｜别让所有任务都走同一个模型

## 视觉目标

演示按任务复杂度分层，而不是全量替换成一个便宜模型。

## 构图

- 左侧任务入口：`架构设计`、`日常编码`、`后台杂活`。
- 右侧三个模型档位：`强`、`平衡`、`快速`。
- 三条颜色不同的路线分别连接任务和模型。

## 动作顺序

1. 三个任务卡依次出现。
2. `架构设计` 走向“强模型”，路径经过额外校验节点。
3. `日常编码` 走向“平衡模型”。
4. `后台杂活` 走向“快速模型”。
5. 底部出现“模型名以供应商文档为准”。

## 屏幕文字

```text
硬任务 → 强模型
日常活 → 平衡模型
后台活 → 快速模型
```

## 声画关系

口播解释分层原则，画面展示任务流向，不固定展示当前供应商的具体模型名称。

## 转场

三条路线汇合成一个“兼容性”警告标记，进入 Scene 08。

# Scene 08｜兼容接口，不等于官方支持

## 视觉目标

把版本变化、鉴权差异和高级能力边界压缩成三个可记忆的警告状态。

## 构图

- 中央为“兼容接口”卡片。
- 周围依次出现三张警告卡：`弃用变量`、`鉴权方式`、`高级能力差异`。
- 下方有一条文档链接占位：`check current official docs`。

## 动作顺序

1. 旧变量卡 `SMALL_FAST_MODEL` 出现并变灰。
2. 新变量卡 `DEFAULT_HAIKU_MODEL` 替换旧卡。
3. `AUTH_TOKEN` 和 `API_KEY` 分成两条不同请求头路线。
4. MCP／工具能力卡显示“可能不同”。
5. 所有警告卡指向“以当前官方文档为准”。

## 屏幕文字

```text
兼容 ≠ 官方背书
以当前文档为准
```

## 声画关系

口播解释风险，画面只表现“旧配置被替换”和“兼容边界出现”，不把实验性绕过方案画成推荐步骤。

## 转场

警告卡片退到背景，中央链路重新亮起，进入 Scene 09。

# Scene 09｜把切换权留在自己手里

## 视觉目标

把全片收束为可判断、可验证、可分层、可回退的四步模型。

## 构图

- 中央为三层链路：`Claude Code → 兼容接口 → 模型`。
- 左侧竖向显示四个结论：`先判断`、`再验证`、`按任务分层`、`保留回退权`。
- 右下角放一个可切回官方的开关。

## 动作顺序

1. 三层链路依次亮起。
2. 四个结论标签从上到下出现。
3. 切换开关从 `third-party` 滑到 `official`，再回到 `third-party`，表示路径可切换。
4. 最终停在“不是必修课，是可验证的后端路径”。

## 屏幕文字

```text
先判断
再验证
按任务分层
保留回退权
```

## 声画关系

口播给出适用人群和最终判断，画面回收全片对象，不增加新知识。

## 结束状态

```text
第三方模型不是必修课
而是一条可验证、可分层、可回退的路径
```

## 全片视觉类型／组件／动画标准

### 视觉类型分布

| Scene | 视觉类型 | 核心视觉事件 |
|-------|----------|--------------|
| 01 | Opening／Decision | 取舍天平回到平衡 |
| 02 | Comparison | 收益与代价双向交换 |
| 03 | Concept Diagram | 请求经过三层链路 |
| 04 | Terminal／Config Flow | 三类变量写入请求字段 |
| 05 | State Change | 终端关闭导致配置消失 |
| 06 | Terminal／Verification | `/status` 三种状态切换 |
| 07 | Task Routing | 任务进入不同模型档位 |
| 08 | Warning／Replacement | 旧配置被新规则替换 |
| 09 | Summary／Switch | 路径可切换、可回退 |

### 组件层

- `SceneContainer`：统一 16:9 场景容器、标题、字幕安全区和场景编号。
- `ComparisonScene`：承载 Scene 01、02 的天平和收益／代价对比。
- `ConceptScene`：承载 Scene 03、09 的三层链路和回退关系。
- `TerminalScene`：承载 Scene 04、05、06 的配置、生命周期和状态验证。
- `StepListScene`：承载 Scene 07 的任务分层和 Scene 08 的警告列表。
- `SummaryScene`：承载 Scene 09 的最终结论。
- 基础元素：`StatusBadge`、`FlowArrow`、`ConfigCard`、`TerminalWindow`、`Caption`。

### 动画标准

- 一级信息动画：状态切换、请求流动、任务路由、旧配置替换。
- 二级注意力动画：错误行轻微发光、正确状态描边、扫描指针短暂移动。
- 三级装饰动画：背景光晕和低对比网格，不能抢字幕和主卡片。
- 所有延迟进入都要从非负帧开始，避免使用负帧调用 `spring()`。
- 动画完成后至少保留足够阅读时间，尤其是 Scene 06 的 `/status` 输出和 Scene 09 的最终结论。

## Visual Script 最终标准

1. 每幕都有一个明确的视觉中心。
2. 画面展示过程、证据或状态变化，不只是重复口播。
3. 真实密钥、固定价格和不稳定模型名不作为事实展示。
4. 9 个 Scene 的视觉动作覆盖 Scene Script 的全部 Video Value。
5. 视觉语言可以直接映射到现有六类场景组件，不新增一次性场景组件。
