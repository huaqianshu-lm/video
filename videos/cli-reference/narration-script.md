# Claude Code 视频化 · 第四步：Narration Script

## Scene 01｜你敲的不是一个入口

很多人用 Claude Code 很久，还是只会在终端里光敲一个 `claude`，进入交互模式。

但这行命令后面，还挂着命令、标志、管道和退出码。今天我们把它们一次摊开：让 Claude 不只是聊天窗口，也能成为脚本和流水线里的一个零件。

## Scene 02｜一行命令拆成两样

先把两个最容易混的词分开。`claude` 是程序，后面的 `update` 这种，是命令，也就是一个子动作。

而 `-p`、`--model` 这种，是标志，用来微调这一趟怎么运行。比如 `claude update` 是执行更新，`claude -p "解释这个函数" --model sonnet` 则是在指定一次 headless 调用和模型。

所以查 CLI 文档之前，先问自己：我要找的是子动作，还是调整运行方式的标志？

## Scene 03｜最近还是指定：会话入口怎么选

启动会话，可以直接敲 `claude`，也可以带一句初始提示。想接着当前目录最近的对话，用 `-c`，也就是 `--continue`。

如果要找某一次特定的会话，用 `-r`，也就是 `--resume`。启动时配合 `--name` 给会话起个名字，之后恢复时就不用对着一串 UUID 猜是哪一件事。

另外，`update`、`install` 和 `auth login`、`auth status`，分别负责版本安装和账户维护。它们是命令，不是进入聊天的方式。

## Scene 04｜`-p`：不进交互，直接出结果

真正的转折是 `-p`，也就是 `--print`。它不会打开聊天界面，而是读取你的提示，完成这次调用，把结果直接打印到终端，然后退出。

这就是 headless，或者说打印模式。有人在场时，你可以用交互模式；脚本、批处理和管道需要无人值守时，就把 `claude -p` 当成命令行里的一个工位。

## Scene 05｜文件和 diff，从 stdin 流进 Claude

headless 模式会读标准输入，所以它能接进命令行管道。比如把构建错误从 `build-error.txt` 送进去，再把解释结果写到 `output.txt`。

同样，你可以把 `git diff main` 喂给 Claude，让它只检查这份 diff，而不需要自己再调用 Bash 去读取。

这条流水线的边界也要记住：从二点一百二十八版本开始，管道输入上限是十 MB。更大的内容应该写入文件，再在提示里引用文件路径。

## Scene 06｜模型、权限、目录：给一次调用加边界

`--model` 可以临时切换这一趟使用的模型，覆盖默认设置。`--permission-mode` 可以在启动时决定权限模式，比如只规划、自动批准编辑，或者更严格地控制工具。

`--add-dir` 可以增加文件访问目录，但不会顺带加载那个目录里的配置。`--allowedTools` 和 `--disallowedTools`，则分别用白名单和黑名单控制工具。

还有一个名字里就写着危险的开关：`--dangerously-skip-permissions`。它等同于完全绕过权限提示，只应该放在明确隔离、坏了也无所谓的环境里。真实项目里，优先精确放行需要的工具。

## Scene 07｜从一大坨 JSON 取出真正要的字段

默认输出是文本。如果脚本需要拿到结果、会话 ID 或成本，就给 `-p` 配上 `--output-format json`。

返回的对象里，`.result` 是结果文本，`.session_id` 可以标记这次会话，`total_cost_usd` 则记录成本。再把 JSON 交给 `jq`，用 `jq -r '.result'`，脚本就只留下真正需要的那句答案。

拿到 `session_id` 之后，还可以把它交给 `--resume`，把多次 headless 调用串在同一条会话线上。

## Scene 08｜追加提示还是整套替换

脚本有时需要给 Claude 临时加一个身份，比如让它做安全审查。这时要分清两个标志。

`--append-system-prompt` 是在默认系统提示后面追加一条要求，原本的编程能力和安全指令还在。`--system-prompt` 则是把整套默认提示替换掉，剩下的工具用法和安全边界都要自己负责。

所以多数场景需要的是追加，而不是替换。

## Scene 09｜零代表成功，非零代表问题

命令行世界里，退出码是给脚本看的成绩单。零代表成功，非零代表出了问题。

比如运行 `claude auth status`，已登录时退出码是零，未登录时是壹。用 `echo $?` 可以查看上一条命令留下的数字。

脚本还可以用 `||` 接住失败：如果登录检查没有通过，就打印“未登录，终止”，不要继续往下跑。达到最大回合数，或者管道输入超过上限，也会以非零状态退出。

## Scene 10｜不用背：按用途查 CLI 标志

标志很多，不需要全部背下来。按启动与会话、模型与权限、目录与配置、headless 输出与控制、杂项分组，查起来更快。

这里还要记住一个反直觉的细节：`claude --help` 不会列出每个标志。所以帮助里没出现，不代表这个标志不能用；要查完整能力，回到 CLI 参考文档。

脚本场景里尤其值得查的是 `--bare`、`--max-turns` 和 `--max-budget-usd`：一个减少自动发现，一个限制回合，一个限制预算。

## Scene 11｜四步跑通 headless

现在把整条链路走一遍。

第一步，直接运行 `claude -p`，看见答案输出，提示符回来，就知道 headless 跑通了。

第二步，用 `cat` 把一段代码或日志通过管道喂进去，让 Claude 只回答这份输入。

第三步，加上 `--output-format json`，再用 `jq` 取出 `.result`，把结构化结果变成脚本真正需要的文本。

第四步，运行 `auth status` 并查看退出码，让脚本知道应该继续还是停止。

单次调用、管道输入、结构化输出和退出码判断，拼起来就是自动化的地基。

## Scene 12｜从聊天窗口到流水线零件

回头看，变化并不是多记了几个参数，而是换了一种使用方式。

命令告诉你要做哪个子动作，标志控制这一趟怎么跑，管道负责把数据送进来，结构化输出把结果交给下一步，退出码让脚本判断成败。

从只会光敲 `claude`，到能把 Claude 接进脚本和 CI，这就是从聊天窗口到流水线零件的变化。
