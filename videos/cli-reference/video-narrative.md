# Claude Code 视频化 · 第二步：Video Narrative

## 视频定位

- 视频标题：Claude Code CLI 参考：从 `claude` 到可编排流水线
- 视频 slug：`cli-reference`
- 叙事命题：当你把 `claude` 当成命令行工具，而不是聊天窗口，脚本、管道、结构化输出和退出码就能把它接进真实工作流。
- 观众起点：会进入 Claude Code 交互模式，但不知道命令和标志如何组合。
- 观众终点：能看懂一行 CLI 调用，知道怎样无头执行、喂入数据、取出结果并判断成功或失败。
- 时长策略：不预设固定时长；由 12 个视觉事件、正常口播和每幕状态变化自然决定。

## 叙事路径

本片不按原文 01–08 章节逐节复述，而按观众的认知过程重新组织：

```text
误区：只会启动交互模式
    ↓
拆解：一行 CLI 到底由什么组成
    ↓
选择：会话怎么启动、继续和恢复
    ↓
转折：-p 让 Claude 变成 headless 零件
    ↓
连接：stdin、JSON、jq 和 session_id 串成流水线
    ↓
控制：模型、权限、目录、保险丝决定边界
    ↓
判断：退出码让脚本知道是否继续
    ↓
实操：四步走完一次完整 headless 链路
    ↓
收束：CLI 参考表是查阅工具，下一步进入控制与模式
```

## Scene 顺序

| Scene | 认知任务 | 视觉事件 | 叙事作用 |
|---|---|---|---|
| 01 | 让观众意识到能力被低估 | 单独的 `claude` 变成一整条 CLI 轨道 | 问题钩子 |
| 02 | 分清 command 与 flag | 拆开 `claude update` 与 `claude -p ... --model sonnet` | 建立基本语法 |
| 03 | 选择会话入口 | `-c` 最近、`-r` 指定、`--name` 命名，旁边接维护命令 | 解决日常选择 |
| 04 | 理解 headless | 交互窗口收起，`-p` 直接输出并退出 | 关键转折 |
| 05 | 看见数据流 | 文件／diff 经 stdin 进入 Claude，结果进入文件或 `jq` | 把工具接进流水线 |
| 06 | 控制一次调用的边界 | 模型、权限、目录、工具、回合和预算逐层加上护栏 | 安全与可控 |

| 10 | 用表查全集 | 按会话、权限、配置、headless、杂项分类的速查板 | 提供长期查阅工具 |
| 11 | 亲手走完四步链路 | 裸调用 → 管道 → JSON + `jq` → 退出码 | 完整实践闭环 |
| 12 | 形成最终心智模型 | 聊天窗口变成流水线零件，并预告下一篇 | 结论与系列承接 |

## 声音与视觉分工

- 声音负责讲清“为什么要区分”“什么时候用哪一个”“结果如何影响下一步”。
- 视觉负责展示命令结构、模式切换、数据流、字段提取、护栏增加、退出码变化和完整执行顺序。
- 画面不逐字复述口播；例如口播解释 `-c` 与 `-r` 的使用时，画面用“最近／指定”的两条恢复路径证明区别。
- `--dangerously-skip-permissions` 作为边界提醒出现，不把危险开关包装成默认推荐。

## 视觉统一原则

- 16:9 横屏、1920 × 1080 构图，深色终端与蓝／紫／绿色状态层级。
- 每幕只有一个视觉中心：拆解、分岔、流动、加护栏、提取字段、判断或收束。
- 终端、表格、流程线和状态标签交替使用，避免每幕都是标题加卡片。
- 代码与命令使用等宽字体；解释性文字使用清晰的短句。
- 底部仅保留原型阶段的画面提示，不生成真实字幕或时间轴。
