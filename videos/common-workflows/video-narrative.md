# Claude Code 常见工作流 · Video Narrative

## 1．叙事目标与命题

不要从“四段模板”直接开始，而是先让观众意识到：日常工作看起来千差万别，但高频任务可以按“是否动代码、风险在哪里、如何验收”分成四类。视频随后把四类任务各自的安全打法拆开，最后用一个真实 bug 练习把方法串起来。

## 2．观众认知路径

```text
我每天到底在做哪些工作？
↓
四类任务动代码的方式不同
↓
每类任务都有自己的标准打法
↓
修 bug 的完整闭环如何实际运行？
↓
把四类模板收成一张可复用的速查卡
```

## 3．叙事结构

### 第一段：先建立任务地图

从“接手项目、修 bug、重构、写测试”四种日常活儿切入，告诉观众这不是四个零散技巧，而是四种需要不同工具的任务性格。用“是否动代码”作为第一条判断轴，快速建立分流表。

### 第二段：按风险拆解四种打法

- 探索代码库：不写代码，从整体架构到具体文件再到执行链路，前两层保持只读。
- 修 bug：不能只让错误消失，要从报错和复现开始，先找根因，再改，再补回归测试。
- 重构：目标是整理代码而不是改变行为，先理解现状，必要时补测试，小步修改，并对照改前改后结果。
- 写测试：正常路径只是起点，要主动逼出空值、零、负数和类型错误等边界情况。

四幕都采用“风险 → 标准打法 → 最该盯什么”的节奏，避免变成四段互不相干的教程。

### 第三段：用一个真 bug 证明方法

把 `average([])` 的除零问题从玩具项目建立、错误复现、根因解释、修复，到回归测试通过，压缩成一条连续的可见证据链。观众看到的不是抽象模板，而是一个从红色失败到绿色通过的执行过程。

### 第四段：收束与承接

用速查卡重新排列四类任务的模板核心和检查重点，最后强调复杂任务也可以是四类工作的组合，并预告下一篇“图片与多模态”。

## 4．视频价值

- 任务分流表能在时间轴上逐项出现，让抽象分类变成快速判断。
- 探索的“大 → 中 → 线”路径适合用缩放和连线表达，文章中的层级关系可以被直接看见。
- 修 bug 和重构都依赖验证，适合用红／绿状态变化、测试日志和前后对照证明，而不是只用文字讲道理。
- 边界测试可用正常输入和异常输入并列，建立“为什么要测边界”的直觉。
- 完整 bug 实战能把“先解释、再修改、再测试”的权限和证据顺序具体化。

## 5．节奏与信息密度

- 10 个 Scene，前 6 幕建立方法，7～9 幕完成实战，10 幕总结并预告。
- 每幕只保留一个主视觉中心：分类表、路径、闭环、行为锁、边界输入或终端结果。
- 画面文字以短标签、函数名、命令和测试结果为主；完整模板由口播解释，不把长段原文堆在画面上。
- 实战部分允许终端信息密度略高，但每次只新增一个状态，保证红色错误、根因、修复和绿色通过的顺序清楚。
