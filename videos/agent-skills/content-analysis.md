# Agent Skills：给 Claude 装一身随叫随到的专项本事 · Content Analysis

## 1. 核心命题

Agent Skill 不是把 slash 命令换一个文件夹，而是把一套可复用的专项流程封装成 `SKILL.md` 加可选配套资源，让 Claude 能在需要时自动调用，也能由用户手动调用；它通过渐进式披露把“可用能力的描述”和“完整执行说明”分开，降低常驻上下文成本。

视频要让观众建立一个可操作的心智模型：

```text
反复说明一套做法
        ↓
SKILL.md + 模板／示例／脚本
        ↓
description 被识别
        ↓
相关时加载完整 Skill
        ↓
Claude 自动调用，或用户用 /name 手动调用
```

## 2. 观众需要完成的认知变化

1. 从“Skill 是 slash 命令的马甲”转为“Skill 是带规则和资源的专项能力包”。
2. 理解 Skill 为什么不会在每次会话里把全文都塞满：平时只暴露 `description`，命中后才加载正文。
3. 理解“加载后常驻”这一代价：正文会留在当前会话中，应该保持精简，长参考拆成按需读取的文件。
4. 分清 slash 命令、Skill 和 Subagent 的发起者、上下文位置与资源能力。
5. 知道自动触发并不等于失控：`disable-model-invocation: true` 可以锁为仅用户调用，`user-invocable: false` 可以锁为仅 Claude 调用。
6. 知道 Skill 的三个来源，以及 `CLAUDE.md` 放事实、Skill 放程序的边界。
7. 能根据目录范围、`description` 关键词和可用列表，判断一个 Skill 谁能用、如何触发、如何排查。
8. 能用 `explain-self` 的最小例子亲眼验证自动触发和手动触发都指向同一套能力。

## 3. 必须保留的信息

### A. Skill 的组成和价值

- `SKILL.md` 是必需的主说明文件。
- YAML frontmatter 说明 Skill 做什么、何时使用；Markdown 正文说明调用后如何执行。
- 可选配套文件包括模板、示例和脚本，Skill 因此不只是一次提示词。
- 反复粘贴相同说明、检查清单或多步骤程序，是创建 Skill 的信号。

### B. 渐进式披露

- 常规会话只加载各 Skill 的 `description`。
- 相关任务命中 description 后，才加载该 Skill 的完整内容。
- Skill 加载后会在当前会话的其余部分保持驻留。
- 正文应尽量精简；官方建议 `SKILL.md` 控制在 500 行以内，长参考拆到独立文件按需加载。

### C. 三者定位与调用控制

| 维度 | slash 命令 | Skill | Subagent |
| --- | --- | --- | --- |
| 发起者 | 用户 | 用户或 Claude | 主对话委派 |
| 上下文 | 当前对话 | 当前对话，默认 | 独立子上下文 |
| 资源 | 通常只有命令内容 | 可带模板、示例、脚本 | 取决于自身定义 |
| 适合场景 | 用户想控制时机的固定操作 | Claude 按需调用的专项能力 | 隔离、较重的子任务 |

- 自定义命令已并入 Skills 体系；一个 Skill 也可以用 `/skill-name` 手动触发。
- 有副作用、必须由人掐时机的能力，可以设置 `disable-model-invocation: true`。
- 只想作为 Claude 背景知识的能力，可以设置 `user-invocable: false`。

### D. 来源、事实与程序

- 内置捆绑 Skill：开箱可用，如 `/code-review`、`/debug`、`/verify`。
- 插件 Skill：随插件提供，用插件命名空间避免同名冲突。
- 自定义 Skill：把反复出现的说明、清单和多步流程封装起来。
- `CLAUDE.md` 适合记录项目事实和工作约定；Skill 适合记录一套要执行的程序。

### E. 范围、触发与排查

- 个人级：`~/.claude/skills/<skill-name>/SKILL.md`，跨项目可用。
- 项目级：`.claude/skills/<skill-name>/SKILL.md`，只对当前项目可用。
- 插件级：`<plugin>/skills/<skill-name>/SKILL.md`，随启用插件提供。
- 企业级：由托管设置提供。
- 同名优先级为企业 > 个人 > 项目；插件使用命名空间。
- 自动触发依赖 `description` 中包含用户自然会说出的关键词。
- 可用列表用“现在有哪些 Skill 可用？”查询；`/` 可查看可手动调用项，`/doctor` 可辅助排查 description 截断。

### F. 最小实操闭环

- 创建 `~/.claude/skills/explain-self/`。
- 写入带 description 和三步解释规则的 `SKILL.md`。
- 启动 `claude`，查询 Skill 列表确认已加载。
- 用自然语言解释请求触发自动调用。
- 再用 `/explain-self` 触发手动调用。
- 两条路径都能按同一份说明工作，形成可观察证据。

## 4. 因果、对比与流程关系

### 核心因果

```text
固定流程反复出现
        ↓
把事实之外的“怎么做”封装进 Skill
        ↓
description 成为匹配入口
        ↓
相关时加载完整正文
        ↓
减少重复粘贴，并让 Claude 按需调用
```

### 关键对比

- slash 命令是用户主动喊；Skill 既可用户主动喊，也可 Claude 自动调；Subagent 在独立上下文执行。
- `CLAUDE.md` 是会话常驻的事实与约定；Skill 是按需加载的程序与资源。
- 模糊的“换文件夹”理解，无法解释 Skill 的配套文件、自动触发和渐进式披露。

### 触发控制关系

```text
Skill
├── 默认：用户 / Claude 都可调用
├── disable-model-invocation: true → 仅用户调用
└── user-invocable: false → 仅 Claude 调用
```

### 实操流程

```text
建目录 → 写 SKILL.md → 查可用列表 → 用人话触发 → 用 /name 对照触发
```

## 5. 可视觉化内容

- 开场用 `.claude/commands/` 与 `.claude/skills/` 的表面相似，转为“多出配套资源、自动触发、按需加载”的三条差异。
- 用目录展开和资源连线展示 `SKILL.md`、模板、示例、脚本如何组成能力包。
- 用“菜单／完整菜谱”式的上下文窗口展示 description 与全文的两级加载。
- 用上下文时间线展示 Skill 加载后继续驻留，以及“500 行以内／长参考拆分”的边界。
- 用三列对照和独立上下文框展示 slash、Skill、Subagent 的差异。
- 用权限闸门展示两个 frontmatter 开关如何限制调用者。
- 用来源汇流图展示内置、插件、自定义三种来源，再把 `CLAUDE.md` 与 Skill 分成“事实／程序”。
- 用目录树展示个人、项目、插件、企业范围和同名优先级。

- 用终端与文件卡展示 `explain-self` 从创建到自动触发、手动触发的闭环。

- 保留原文对 Skill 组成、渐进式披露、调用控制、来源、目录、触发和实操的完整知识骨架。
