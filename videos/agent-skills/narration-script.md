# Agent Skills：给 Claude 装一身随叫随到的专项本事 · Narration Script

## Scene 01｜Skill 不只是换了个文件夹

很多人第一次看到 Skill，会觉得它不过是 slash 命令换了个文件夹。

但 Skill 多了三件事：可以带模板和脚本，可以由 Claude 按需自动触发，而且平时只把一行 description 放在上下文里。

所以，真正的问题不是它叫什么，而是它把一套专项做法封装成了什么。

## Scene 02｜一身本事，从 SKILL.md 开始

一个 Skill，最核心的是一个叫 `SKILL.md` 的说明文件。

文件开头的 frontmatter 负责说明这项本事什么时候该用，下面的正文负责说明调用之后应该怎么做。

它还可以带模板、示例和脚本。也就是说，Skill 不是一句临时提示，而是一整个可以复用的能力包。

## Scene 03｜渐进式披露：先看 description，再加载全文

它为什么不会一开会话就把上下文塞满？关键在渐进式披露。

平时，Claude 只看到每个 Skill 的 description，就像先看一张菜单。

当你的任务和其中一个描述对上，Claude 才把这个 Skill 的完整说明翻出来，就像点菜之后才拿到详细菜谱。

## Scene 04｜省的是平时，成本在加载之后

不过，按需加载不等于用完就消失。

一旦 Skill 的正文被加载，它会在这场会话的剩余时间里继续留着。所以正文不要灌水，官方建议控制在五百行以内；更长的参考内容，拆到单独文件里，需要时再读。

## Scene 05｜三者差在哪？看谁发起、跑在哪

slash 命令，是你输入斜杠之后主动触发的一段操作。

Skill 可以由你主动喊，也可以由 Claude 根据任务自动调用，而且通常能带配套资源。

Subagent 则是主对话委派出去的独立上下文助手。简单记：slash 看手动，Skill 看复用和匹配，Subagent 看隔离的子任务。

## Scene 06｜两个开关，决定谁能调用

自动触发听起来像会乱动手，但调用权是可以控制的。

给 Skill 加上 `disable-model-invocation: true`，就变成只有你能调用；设置 `user-invocable: false`，则变成只有 Claude 能调用。

所以，是否自动，不是一个无法挽回的默认命运，而是可以按风险选择的权限边界。

## Scene 07｜内置、插件、自己写：三条来源

Skill 主要有三种来源：Claude Code 自带的内置 Skill，插件附带的 Skill，以及你自己写的 Skill。

判断要不要自己写，其实很简单：如果你总在聊天里重复粘贴同一套说明、检查清单或多步流程，就该把它封装起来。

这里还要分清两个位置：`CLAUDE.md` 更适合放项目事实和工作约定，Skill 更适合放一套要执行的程序。

## Scene 08｜目录范围，就是能力边界

个人级 Skill 放在 `~/.claude/skills/`，跨项目可用；项目级 Skill 放在 `.claude/skills/`，只对当前项目生效。

插件和企业级 Skill 还有各自的范围。同名时，企业优先于个人，个人优先于项目；插件则用命名空间避免撞名。

所以放在哪里，决定了谁能看到、谁能调用。

## Scene 09｜一句人话，就能触发对应 Skill

你不需要背下每个 Skill 的斜杠命令。

如果 description 里写了用户自然会说的关键词，比如“这段代码啥意思”，你直接这样提问，Claude 就可能自动匹配对应 Skill。

当然，也可以输入 `/explain-self` 手动触发。想排查时，先问“现在有哪些 Skill 可用”，再用 `/doctor` 检查描述是否被截断。

## Scene 10｜从空目录到可用 Skill

现在用一个最小例子把它跑起来。

先创建个人级的 `explain-self` 目录，再写入一个 `SKILL.md`。它的 description 负责匹配代码解释和报错解释，正文只规定三步：先说整体作用，再逐段拆开，最后指出原因和修改方向。

启动 Claude，确认列表里出现它，说明这项本事已经被识别。

## Scene 11｜两条入口，同一份说明

接着故意不喊名字，只说：“这段代码啥意思？”

如果 description 匹配成功，Claude 会自动调用 `explain-self`，并按那三步给出解释。

再输入 `/explain-self`，处理一个报错。它走的是手动入口，但读取的仍是同一份 `SKILL.md`。

这就验证了 Skill 的核心：自动和手动是两条入口，背后是同一套可复用的能力。

## Scene 12｜Skill：让 Claude 会得更多

把整篇内容压缩成一条路径：把反复出现的做法写进 Skill，让 description 负责匹配，相关时再加载完整说明，并用调用开关控制谁能使用。

这就是让 Claude 按需调出专项能力，而不是每次都从头教一遍。
