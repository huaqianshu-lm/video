# Agent Skills：给 Claude 装一身随叫随到的专项本事 · Visual Script

> 目标：用目录、上下文、权限和终端状态展示 Skill 如何从一份说明变成可按需调用的专项能力。口播负责解释机制和判断，画面负责证明展开、匹配、分流和验证。

## 全局视觉原则

### 1. 用过程证明“不是换文件夹”

所有核心差异尽量通过文件树展开、上下文加载、权限闸门和终端状态变化表达，不把文章段落完整铺成文字卡片。

### 2. 两级上下文保持视觉层级

`description` 使用细亮蓝色，代表常驻菜单；完整 `SKILL.md` 使用紫色展开面板，代表命中后加载的详细说明。加载后驻留用一条持续存在的上下文轨迹表示。

### 3. 声音解释，画面展示证据

口播解释“为什么这样设计、三个概念怎么分、什么时候该自己写”；画面展示文件、目录、匹配线、权限开关、命令和结果，避免口播与屏幕文字逐句重复。

### 4. 每幕只保留一个视觉中心

单幕只突出一个过程：目录组成、加载范围、调用者、来源、范围、触发或验证。主标题控制在 1—2 行，标签只保留当前动作所需的内容。

### 5. 横屏教程感与安全区

使用 1920 × 1080 的 16:9 深色画布、圆角软件窗口、轻边框和克制发光。底部预留字幕安全区，结尾预告卡与底部区域分离；预览控件只属于 HTML 原型。

## 逐 Scene 视觉设计

### Scene 01｜Skill 不只是换了个文件夹

- **场景容器**：左右两个文件路径窗口，左侧 `.claude/commands/deploy.md`，右侧 `.claude/skills/deploy/SKILL.md`。
- **视觉动作**：两条路径先并排显示“都能 `/deploy`”，随后右侧依次展开 `template.md`、`scripts/`、`auto match` 三个差异节点。
- **信息重点**：Skill 的多出来的能力是配套资源、自动触发和按需加载。
- **口播互补**：口播纠正“马甲”误解，画面负责展示结构差异。
- **屏幕文字**：`/deploy`、`配套文件`、`自动触发`、`按需加载`

### Scene 02｜一身本事，从 SKILL.md 开始

- **场景容器**：中心文件树连接到右侧的 Skill 能力包。
- **视觉动作**：先亮起 `SKILL.md`，拆出 frontmatter 的 `description` 和正文，再从目录边缘滑入模板、示例和脚本。
- **信息重点**：主说明必需，配套文件可选，但都属于同一个 Skill 目录。
- **口播互补**：口播解释“何时用”和“怎么做”的分工，画面展示文件层级。
- **屏幕文字**：`SKILL.md`、`description`、`template.md`、`examples/`、`scripts/`

### Scene 03｜渐进式披露：先看 description，再加载全文

- **场景容器**：模拟上下文工作台，三条 Skill 菜单并列。
- **视觉动作**：三条 description 各占一行；`explain-self` 被关键词光束命中后，只有它展开成完整 `SKILL.md`，另外两条保持一行。
- **信息重点**：平时只看描述，相关时才加载正文。
- **口播互补**：口播使用菜单与菜谱类比，画面直接表现上下文占用变化。
- **屏幕文字**：`description`、`仅一行`、`命中 explain-self`、`加载完整正文`

### Scene 04｜省的是平时，成本在加载之后

- **场景容器**：一条会话上下文时间线，左侧是命中前，右侧是命中后。
- **视觉动作**：完整正文进入上下文后保持发光；“500 行以内”出现为边界标尺，超出的长参考从正文中抽离到 `references/` 文件卡。
- **信息重点**：正文加载后会驻留，精简和拆分是必要策略。
- **口播互补**：口播说明代价，画面用持续占位和拆分动作证明它。
- **屏幕文字**：`加载后驻留`、`SKILL.md ≤ 500 行`、`长参考 → 独立文件`

### Scene 05｜三者差在哪？看谁发起、跑在哪

- **场景容器**：三列垂直面板：slash、Skill、Subagent。
- **视觉动作**：顶部依次点亮“谁发起”，中部点亮“当前／独立上下文”，底部点亮“配套资源”；Subagent 面板单独推到后方，强调隔离。
- **信息重点**：slash 是手动入口，Skill 是当前上下文中的可复用能力，Subagent 是独立上下文的委派助手。
- **口播互补**：口播给出记忆口诀，画面用空间位置承担比较。
- **屏幕文字**：`用户主动喊`、`用户 + Claude`、`独立上下文`

### Scene 06｜两个开关，决定谁能调用

- **场景容器**：中心 Skill 节点，连接三个调用者状态。
- **视觉动作**：默认状态允许“用户 + Claude”两条线通过；切换 `disable-model-invocation: true` 后只留用户线；切换 `user-invocable: false` 后只留 Claude 线。
- **信息重点**：自动触发是可配置权限，而非不可控行为。
- **口播互补**：口播解释副作用和背景知识的选择，画面展示闸门结果。
- **屏幕文字**：`用户 + Claude`、`disable-model-invocation: true`、`user-invocable: false`

### Scene 07｜内置、插件、自己写：三条来源

- **场景容器**：三条输入轨道汇入 `Available Skills`，右侧再分成 `CLAUDE.md` 和 `Skill`。
- **视觉动作**：`内置`、`插件`、`自己写` 三个来源依次汇流；“项目技术栈／约定”进入 `CLAUDE.md`，“提交流程／检查清单”进入 Skill。
- **信息重点**：Skill 来源多样；事实与程序要放在不同容器。
- **口播互补**：口播说明何时该自己写，画面展示内容归位。
- **屏幕文字**：`内置`、`插件`、`自己写`、`CLAUDE.md：事实`、`Skill：程序`

### Scene 08｜目录范围，就是能力边界

- **场景容器**：四层目录树从上到下排列，右侧是范围标签。
- **视觉动作**：企业、个人、项目、插件节点逐个亮起；同名 `review` 在企业／个人／项目三层形成优先级，插件名带命名空间后移到独立轨道。
- **信息重点**：路径决定可见范围，优先级决定同名覆盖关系。
- **口播互补**：口播讲四种范围和优先级，画面让路径和范围直接对应。
- **屏幕文字**：`~/.claude/skills/`、`.claude/skills/`、`<plugin>/skills/`、`企业 > 个人 > 项目`

### Scene 09｜一句人话，就能触发对应 Skill

- **场景容器**：左侧自然语言输入，中间多个 description 行，右侧命令面板和诊断卡。
- **视觉动作**：`这段代码啥意思？` 被拆成关键词，扫描 `explain-self` description 后连线；下方并列显示 `/explain-self` 和“现在有哪些 Skill 可用？”。
- **信息重点**：自然语言自动匹配、斜杠手动调用、列表查询和 `/doctor` 是四个不同入口。
- **口播互补**：口播解释触发与排查，画面展示关键词命中证据。
- **屏幕文字**：`这段代码啥意思？`、`description`、`/explain-self`、`现在有哪些 Skill 可用？`

### Scene 10｜从空目录到可用 Skill

- **场景容器**：终端窗口与右侧文件卡同步出现。
- **视觉动作**：依次显示 `mkdir -p ~/.claude/skills/explain-self`、写入 `SKILL.md`、启动 `claude`；最后在可用列表中高亮 `explain-self`。
- **信息重点**：一个最小 Skill 的创建、加载和发现流程。
- **口播互补**：口播解释 description 和三步规则，画面展示实际文件状态。
- **屏幕文字**：`mkdir -p ~/.claude/skills/explain-self`、`SKILL.md`、`claude`、`explain-self · available`

### Scene 11｜两条入口，同一份说明

- **场景容器**：左右双路径实验面板，底部汇入同一结果面板。
- **视觉动作**：左路输入“这段代码啥意思？”后走 `description match`；右路输入 `/explain-self` 后走 `manual invoke`；两路汇入三步结果。
- **信息重点**：自动与手动触发的入口不同，但执行的 Skill 和结果结构相同。
- **口播互补**：口播解释验证结论，画面用两条路径汇合建立证据。
- **屏幕文字**：`description match`、`manual invoke`、`同一份 SKILL.md`、`解释结果`

### Scene 12｜Skill：让 Claude 会得更多

- **场景容器**：中央总结路径和右侧预告卡，底部保留安全区。
- **视觉动作**：`反复说明` 经过 `封装`、`匹配`、`按需加载`、`调用` 四个节点，随后右侧卡片切换为 `27「Skills 使用实例」`。
- **信息重点**：把重复程序变成按需调用的能力，并承接下一篇。
- **口播互补**：口播完成总结和预告，画面只保留行动路径与下一集标题。
- **屏幕文字**：`封装 → 匹配 → 按需加载 → 调用`、`27「Skills 使用实例」`

## 全片视觉类型、组件和动画标准

### 视觉类型

- `FolderExploration`：Scene 01、02、08，用于目录、资源和范围关系。
- `ContextLoading`：Scene 03、04，用于 description、全文加载和驻留边界。
- `ComparisonTable`：Scene 05，用于 slash、Skill、Subagent 的定位比较。
- `PermissionGate`：Scene 06，用于调用者开关和权限分流。
- `SourceRouting`：Scene 07，用于来源汇流和事实／程序分工。
- `CommandPanel`：Scene 09、10、11，用于自然语言、命令和可观察状态。
- `SummaryPreview`：Scene 12，用于最终路径与下一集预告。

### 基础组件

- 深色 16:9 画布、圆角窗口、轻边框、低强度发光。
- 文件树、等宽代码块、上下文轨迹、状态标签、权限闸门、流程节点和预告卡。
- 解释性文字使用清晰无衬线字体；路径、命令、文件名和状态使用等宽字体。
- `description` 使用蓝色，完整正文使用紫色，警示使用低饱和红色，验证成功使用绿色。
- 主标题控制在 1—2 行；标签不复述整段口播。
- 上一幕／下一幕、自动播放、进度提示和原型说明只属于 HTML 预览，不进入后续 Composition 或 MP4。

### 动画标准

- 目录展开、节点连线和权限切换使用 300—500ms 的淡入、位移或变色传递因果。
- 命中动画从输入扫过 description，再展开对应正文，保持“匹配 → 加载”的顺序。
- 驻留状态用持续发光或固定轨迹表达，不使用无意义旋转。
- 三列对照只高亮当前维度，避免所有字段同时跳动。
- Scene 10—11 的终端状态按时间顺序出现，最后的 `available`、结果合流和验证状态留出停顿。
- Scene 12 的预告卡至少保留约 2—3 秒可读时间，并与底部字幕安全区分离。
