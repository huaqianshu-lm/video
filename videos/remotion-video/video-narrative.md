# Remotion 视频化 · 第二步：Video Narrative

> 目标：把“用代码做视频”从一个新奇概念，重组为一条可判断、可尝试、也知道何时放弃的观看路径。

## 1. 视频的叙事目标

观众看完后不必立刻会写 Remotion，但应该能回答四个问题：

1. Remotion 为什么能用代码做视频？
2. Claude Code 在这套组合里具体帮什么忙？
3. 看到 `frame`、`interpolate`、`spring` 时，应该如何理解？
4. 我的这条视频到底适不适合用 Remotion？

最终认知变化是：

```text
视频只能靠剪辑软件完成
        ↓
规则生成的画面可以用 React 一帧帧计算
        ↓
Remotion 提供视频代码框架，Claude Code 帮忙写和改代码
        ↓
预览—反馈—再预览才是实际工作方式
        ↓
是否采用，取决于复用、参数化和批量价值
```

## 2. 叙事原则

- 先让观众看到“翻页画面如何变成视频”，再给 Remotion 定义。
- 先解释工具生态位，再讲 Claude Code 的协作价值，避免把 Claude Code 说成视频软件。
- 三个 API 概念只做直觉解释，不把视频变成代码教程。
- 流程场景强调状态变化和反馈循环，不把命令表格整页铺开。
- 结尾用选择分叉回答“该不该用”，保留文章作为选读篇的克制态度。
- 所有命令只作为原型中的文章示例画面，不执行任何外部操作。

## 3. 整体叙事结构

| 段落 | Scene | 认知任务 | 叙事推进 |
| --- | --- | --- | --- |
| 开场直觉 | 01–02 | 从“视频能写吗”进入“一帧一帧的 React 画面” | 先建立翻页动画直觉，再给定义 |
| 工具生态位 | 03 | 切开剪辑软件、在线模板和 Remotion | 让观众知道它解决哪类问题 |
| 组合关系 | 04 | 解释 Remotion 与 Claude Code 的分工 | 从“框架”进入“协作方式” |
| 动画骨架 | 05–06 | 理解帧、插值、弹性 | 让生成的代码不再完全像天书 |
| 最小闭环 | 07–09 | 走过搭建、预览、反馈和输出 | 把抽象优势落到操作节奏 |
| 选型与收束 | 10–12 | 判断适合谁、看见成本和边界 | 从“能不能做”转向“值不值得做” |

## 4. 逐段叙事设计

### 第一段：先让视频变得可计算

#### Scene 01｜视频也可以写

用“参数不同但模板一致的年度总结视频”作为问题入口，让观众看到批量视频为什么会遇到手工剪辑的瓶颈。

#### Scene 02｜一帧一帧的翻页书

用翻页书把 Remotion 的核心模型视觉化：每一页是某一帧，代码决定这一帧画什么，连续帧组成运动。

### 第二段：它到底处在工具链的哪一层

#### Scene 03｜剪辑、模板、代码三条路

用同一条对比轴展示剪辑软件、在线模板和 Remotion 的强弱，不把 Remotion 包装成所有视频的替代品。

### 第三段：为什么 Claude Code 能接上来

#### Scene 04｜框架提供可能，Claude 负责动手

把自然语言需求、React 代码和预览画面连起来，明确人负责审美和拍板，Claude Code 负责搭建和修改。

### 第四段：看懂最小动画骨架

#### Scene 05｜帧与时间

让时间轴上的帧数与 `fps`、`durationInFrames` 对应，建立“秒数 × 帧率 = 总帧数”的直觉。

#### Scene 06｜插值与弹性

把一个值从 A 到 B 的平滑变化与 `interpolate()` 连接，再把有回弹手感的变化与 `spring()` 连接。

### 第五段：从空目录到预览闭环

#### Scene 07｜六步流程总览

把 Node.js、需求、生成、预览、反馈和渲染串成一条带返回箭头的流程，提醒观众预览和修改会循环。

#### Scene 08｜预览才是调试现场

聚焦“字太快、发光太强”的反馈，把口头修改、代码变化和预览变化做成一个小循环。

#### Scene 09｜最小示例的预期输出

用终端状态展示 `node --version`、`npm install`、`npx remotion studio` 和 render 的位置，但把它们作为文章示例，不在本任务执行。

### 第六段：知道什么时候值得上

#### Scene 10｜参数化模板才是主场

用“同模板换数据”和“一次性艺术品”做选择分叉，给出适合、不适合和谨慎的判断。

#### Scene 11｜成本与避坑

把渲染性能、复杂任务拆分、预览优先和 `spring` 负帧数作为四个风险标记，避免只讲爽点。

#### Scene 12｜知道这条路，再回到真实问题

收束 Remotion、Claude Code、预览循环和适用边界，并回到文章的最终建议：有真实的批量或参数化需求再投入；没有就先知道这条路即可。

## 5. 认知节奏

```text
批量视频为什么难做
  ↓
Remotion 把每一帧变成 React 画面
  ↓
它和剪辑软件、在线模板的边界
  ↓
Claude Code 如何帮助写和改
  ↓
帧、插值、弹性三个阅读入口
  ↓
从空目录到预览、反馈、输出
  ↓
适合谁、成本是什么
  ↓
回到自己的真实需求
```

## 6. Video Value 审查

- Scene 01：参数变化和模板复用只有动态关系能快速体现，能建立“为什么值得代码化”的问题。
- Scene 02：翻页动画能把“帧组成视频”的抽象模型变成可见过程。
- Scene 03：三种工具的路径和能力边界需要并排对照，静态文字不如动态聚焦清楚。
- Scene 04：自然语言、代码和预览之间的转换是组合价值，适合用流动连接演示。
- Scene 05–06：时间轴、A→B 和弹簧回弹必须靠状态变化建立直觉。
- Scene 07–09：流程、循环和命令状态能把文章的最小实战变成可跟随的动作链。
- Scene 10–11：选择分叉和风险标记帮助观众判断，而不是只记住“这很酷”。
- Scene 12：收束场景把技术知识转回投入决策，保留选读篇的边界感。

## 7. Gate 1 内部审查结论

- 叙事已从原文的章节顺序重组为“问题 → 模型 → 生态位 → 协作 → 概念 → 流程 → 选型”。
- Remotion 与 Claude Code 的职责边界贯穿开场、组合关系和结尾，没有把 Remotion 说成 Claude Code 内置功能。
- 文章中的最小命令流程被保留为视觉演示内容，未转化为本任务的执行计划。
- 12 个 Scene 均有清晰的视觉事件和 Video Value，信息密度可通过分幕控制。
- 可以进入 Scene Script、Narration Script、Visual Script 和 Visual Prototype。

## 8. 下一步

将 12 个叙事事件拆成 Scene Script，并为每幕分别定义纯口播、画面结构、屏幕重点和 Video Value。
