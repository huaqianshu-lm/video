# Remotion 视频化 · 第四步：Narration Script

> 目标：基于 Scene Script 生成纯口播。每个 Scene 下只保留实际需要朗读的内容。

## Scene 01｜视频也可以写

想象一下，你要给几千个用户各做一条年度总结视频。

每条视频的结构差不多，但播放时长、最常听的歌、排名这些数据都不一样。

如果让剪辑师一条条剪，数量一上来就会非常慢。

但如果视频本身是一套可以传参数的代码，同一个模板换一份数据，就能再渲染出一个版本。

这就是今天要看的问题：视频，能不能也像代码一样被生成？

## Scene 02｜一帧一帧的翻页书

先给结论。

Remotion 是一个用 React 写视频的框架。

它把视频理解成一帧一帧的画面。

这很像小时候的翻页书：每一页单独看都是静止的，但快速连续翻过去，眼睛就看到了动作。

Remotion 做的事情，就是让你用代码描述每一页，也就是每一帧应该长什么样，然后把这些画面按顺序渲染成视频。

所以它最适合文字动画、数据图表、Logo 片头和代码演示这类本来就能按规则画出来的内容。

## Scene 03｜剪辑、模板、代码三条路

这并不意味着 Remotion 要替代所有剪辑软件。

剪辑软件擅长真人实拍和自由创意，你用鼠标拖素材、打关键帧，所见即所得。

在线模板更适合快速出片，但细节通常受模板限制。

Remotion 则把画面写成代码，换来的优势是精确、批量和可复用。

所以它不抢剪映或 After Effects 的实拍剪辑，也不负责替代一键模板。

它更像是专门处理那类需要规则生成、反复复用、还要精确控制的视频工具。

## Scene 04｜框架提供可能，Claude 负责动手

那 Claude Code 为什么会和 Remotion 配在一起？

原因其实很直接：视频一旦变成 React 代码，做视频就变成了写代码，而写代码正是 Claude Code 擅长的事情。

Remotion 提供的是“视频可以用代码写”的框架。

Claude Code 可以根据你的自然语言需求，搭项目、写动画逻辑，再按照你的反馈修改对应的代码。

你可以说：“让这行字从左边飞进来，停一下，再变成绿色发光。”

但这里有一个重要边界：Claude Code 不是自己内置了一个视频软件。

它是在帮你写另一个框架的代码。

你负责把需求说具体，负责审美和最后拍板；它负责代码层面的搭建和修改。

## Scene 05｜帧与时间

要看懂 Remotion 生成的代码，先认识第一个词：帧。

帧就是视频的一页。

`useCurrentFrame()` 会告诉代码，现在正在计算第几帧。

帧和时间的换算很简单：总帧数等于秒数乘以帧率。

比如六秒、三十帧每秒，就是一百八十帧。

所以当你在代码里看到 `durationInFrames` 和 `fps`，它们分别是在描述视频有多少页，以及每秒翻多少页。

## Scene 06｜插值与弹性

第二个词是 `interpolate()`。

它负责把一个值从 A 平滑地算到 B。

比如文字在前几帧完全透明，之后逐渐变得不透明；或者一个元素从屏幕外移动到中央。

第三个词是 `spring()`。

它模拟的是弹簧的手感，让元素冲进来以后轻微回弹，再稳住，而不是机械地匀速移动。

你不需要马上会写这两个函数。

先记住：看到 `interpolate()`，通常是在做 A 到 B 的过渡；看到 `spring()`，通常是在做带弹性的变化。

## Scene 07｜从空目录到预览闭环

把流程串起来，大致是六步。

先确认 Node.js 是十八或更高版本。

然后在空目录里描述清楚视频的时长、尺寸、帧率、背景、主体和动画方式。

接着让 Claude Code 搭项目、安装依赖并写出组件。

代码生成后，启动 Remotion Studio 预览。

如果发现文字太快、光效太强，继续用自然语言提出具体反馈，再回到预览检查。

最后满意了，才渲染成 mp4。

真正的工作节奏不是生成一次就结束，而是预览、修改、再预览，循环几次很正常。

## Scene 08｜预览才是调试现场

预览是这套流程里最重要的地方。

你拖着时间轴看，可能会发现这个字飞得太快，或者绿色发光太刺眼。

这时不需要自己钻进代码里找参数。

直接告诉 Claude Code：“把淡入时间拉长一点，绿色发光弱一些。”

它修改对应的动画逻辑，预览再热更新。

你继续看，继续反馈，直到速度、构图和视觉强度都合适。

所以预览负责发现问题，渲染负责最后出片。

不要为了看一个小改动，就反复等待完整渲染。

## Scene 09｜最小示例的预期输出

文章里的最小示例，可以用几条命令串起来理解。

`node --version` 用来确认环境版本。

`npm install` 用来安装项目依赖。

`npx remotion studio` 用来启动带时间轴的预览。

之后根据真实的 Composition ID 渲染出 `out/hello.mp4`。

每一步都有自己的预期：版本号、安装完成、Studio 地址、最后的 mp4 文件。

这些命令是文章里的示例，画面可以展示它们的顺序，但本次生产资料任务不会执行它们。

## Scene 10｜参数化模板才是主场

那到底谁适合用 Remotion？

如果你要给几千个用户生成同模板的年度总结，或者要做数字增长、图表生长、技术演示和 Logo 动画，它会很合适。

因为这些视频的共同点是：数据会变，结构可以复用，画面还需要精确控制。

但如果你要剪婚礼、旅行 vlog，或者做一次性的创意 MV，剪辑软件通常更直接。

判断标准可以浓缩成一句话：这条视频是一次性的艺术品，还是一套能换数据复用的模板？

## Scene 11｜成本与避坑

这条路也不是没有成本。

视频越长、特效越多，渲染越吃机器性能和时间。

复杂视频不要一上来就要求很多场景、很多转场和音乐节奏，先做最简单的版本，再一个场景一个场景地增加。

还有一个 Remotion 动画里容易遇到的小坑：带延迟的 `spring()` 如果拿到了负的帧数，动画可能只显示第一帧。

所以更稳妥的顺序是，先跑通，再细调；先保证帧数安全，再增加效果。

## Scene 12｜知道这条路，再回到真实问题

把今天的内容收回来。

Remotion 把视频拆成一帧帧的 React 画面。

Claude Code 可以帮你搭项目、写动画、改细节，但它并没有替你做审美判断。

你只要先认识帧、`interpolate()` 和 `spring()`，就能读懂很多生成代码在表达什么。

真正的工作方式，是预览、反馈、再预览，最后才渲染。

而是否值得投入，取决于你有没有程序化、参数化、批量复用的真实需求。

如果有，这是一条很值得试的路；如果没有，先知道它存在，也已经够了。
