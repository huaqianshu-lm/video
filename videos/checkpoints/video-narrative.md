# Claude Code 视频化 · 第二步：Video Narrative

> 目标：按观众的认知过程重新组织“检查点到底能不能救你”，而不是照着文章章节逐段朗读。

## 视频定位

这是一条“边界先行”的 Claude Code 教程。开头先用 `rm` 删除后无法靠 `/rewind` 找回的反例制造认知冲突，再回头解释检查点如何自动产生、如何操作，最后把边界落到 Git 和可复现的小实验上。

核心问题：

> **你以为 `/rewind` 能撤销一切，但它究竟跟踪什么？**

## 叙事路径

```text
安全网失效的反例
        ↓
检查点的正确定义：每条提示前的编辑前快照
        ↓
自动保存的位置、期限与跨会话特性
        ↓
/rewind 的入口、时间点和操作选项
        ↓
真正的边界：编辑工具 vs Bash／外部副作用
        ↓
检查点与 Git 的分工
        ↓
编辑工具改动成功倒带
        ↓
Bash rm 删除无法倒带、Git 找回已提交文件
        ↓
形成“检查点快试错，Git 做永久存档”的工作习惯
```

## Scene 顺序

1. **开场反例：安全网不是万能撤销** —— `rm` 删除的文件没有回来。
2. **快照时间轴：每条提示自动存档** —— 把检查点建立为“编辑前状态”。
3. **快照的去处与期限** —— `file-history`、跨会话和清理周期。
4. **回退菜单：恢复与总结不是一回事** —— 入口和四类主要选择。
5. **边界分水岭：谁改文件决定能不能回** —— 编辑工具与 Bash 的对照。
6. **检查点与 Git：本地撤销叠加永久历史** —— 明确使用时机。
7. **正向实战：编辑工具改错后成功倒带** —— 验证可回滚路径。
8. **反向实战：Bash 删除回不来，Git 接手** —— 验证不可回滚路径。
9. **总结与下一集预告** —— 固化判断口诀和系列承接。

## 声音与视觉分工

- 声音解释“为什么这个结果会发生”，推进观众从误解到边界。
- 画面用时间轴、菜单、状态变化和对照表证明“系统跟踪了什么”。
- 实战 Scene 不重复大段定义，而是用文件状态变化让结论可验证。
- 所有屏幕文字保持短句、命令、路径和状态标签，详细解释留给口播。

## 视觉统一原则

- 深色终端／编辑器风格，使用蓝色表示检查点路径，绿色表示成功回退，红色表示不可回滚或风险。
- 每幕只保留一个视觉中心：时间轴、菜单、边界表、双轨流程或文件状态。
- 画面优先呈现变化和对照，不把整篇文章缩成多栏文字页面。
- 底部字幕只作为原型内的口播提示，不把导航、调试说明或制作备注当成正式视频画面。

## 系列结尾

最后一幕保留 Source 明示的下一篇预告：**38「插件参考手册」**。画面只展示标题和“插件完整结构与字段清单”的承接句，不展开下一篇业务内容，并给预告卡片留出独立阅读空间。

## Gate 1 叙事审查

- 叙事从反例开始，能解释文章开头的核心冲突，避免先给抽象定义再堆功能。
- 机制、操作、边界、分工和实战顺序符合观众理解路径。
- 9 个 Scene 各自只有一个主要认知任务，且都能由视频的状态变化提供额外价值。
- Source 中重要的“编辑工具可回、Bash 不可回、Git 永久历史”均被安排为独立可验证事件。

**结论：Video Narrative 通过 Gate 1，可进入 Scene Script。**
