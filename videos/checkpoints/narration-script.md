# Claude Code 视频化 · 第五步：Narration Script

> 目标：基于 Scene Script 生成纯口播。每个 Scene 下只保留实际需要朗读的内容。

## Scene 01｜安全网没接住 `rm`

很多人听说 Claude Code 有 `/rewind`，第一反应是：那以后让它大胆改就行，反正随时能撤销。

但如果它中间用 `rm` 和 `mv` 动过文件，第三轮发现方向不对，你回退以后可能会看到一个很奇怪的结果：代码改动回来了一部分，被删掉的文件却没有回来。

所以检查点确实能撤销，但它撤销的范围，比你想象的要小。

## Scene 02｜每条提示前自动拍一张

先给检查点下个准确的定义。

它是 Claude Code 自动拍下的、编辑前的代码快照。你每发一条提示，Claude 在开始动手之前，就会先留下一个检查点。

你可以把它想成录像机时间轴上的章节标记。第一条提示有一个点，第二条提示又有一个点，后面想回到某个状态，就从这些点里选。

关键是，这一切是自动发生的。你不需要记得保存，也不用每次先敲一个 commit。

## Scene 03｜快照存在会话历史里

这些快照不是只存在内存里。Claude Code 会把当前会话的文件历史放在 `~/.claude/file-history/<session>/`。

因此你退出以后再恢复这个会话，之前的检查点通常还可以访问。

当然，它也不是永久档案。默认会按照 `cleanupPeriodDays` 清理，文章里给出的默认期限是三十天。

这也是为什么检查点适合临时试错，而不适合拿来保存几个月后的永久版本。

## Scene 04｜先选时间点，再选退法

要打开回退菜单，有两个入口：在会话里输入 `/rewind`，或者确保输入框是空的，然后连续按两次 `Esc`。

菜单里先选你想回到的提示，再选具体怎么回。

恢复代码和对话，是两边一起退。恢复代码，是文件退回但对话保留。恢复对话，则是对话退回但代码保持现状。

另外两个“总结”选项不要和恢复混淆。总结只是压缩一部分对话上下文，不会改变磁盘上的文件。

简单说，恢复是真正倒带，总结只是整理对话。

## Scene 05｜编辑工具与 Bash 是分水岭

真正决定能不能回的，不是文件看起来有多重要，而是这次改动是怎么发生的。

Claude 通过 `Edit`、`Write`、`MultiEdit` 这类编辑工具直接修改的文件，是检查点跟踪的对象，通常可以回退。

但如果它通过 Bash 执行了 `rm`、`mv`、`cp`，或者用重定向覆盖了文件，这些变化不在同一个跟踪范围里。

你在 Claude Code 外面手动改的文件、其他并发会话的改动，以及已经发出去的请求、数据库变化和 `git push`，也不能指望检查点撤回。

判断方法只有一句：后果是不是落在当前会话跟踪的代码文件和对话里。超出这条边界，检查点就够不着。

## Scene 06｜检查点是本地撤销，Git 是永久历史

现在就能理解为什么检查点不能替代 Git 了。

检查点是自动的、粒度很细，适合你改一版、看一眼，不满意就马上退回去。它是会话级的本地撤销，而且会按清理周期过期。

Git 则是你手动建立的永久历史。一个功能做完、测试跑通，就提交一次；以后需要追溯、分享或者恢复已提交的文件，都靠这条历史。

所以比较稳的节奏是：让检查点负责小步试错，每完成一个能跑通的阶段，就用 `git commit` 钉住一个永久存档。

检查点补充 Git，但绝不替代 Git。

## Scene 07｜编辑工具改错，成功倒带

我们用一个最小例子验证它。

先创建一个 `rewind-demo` 文件夹，初始化 Git，让 `note.txt` 只有一行 `hello`。

然后让 Claude 用编辑工具把它改成三行：`apple`、`banana`、`cherry`。再发一条提示，把这三行换成一行不想要的版本。

现在打开 `/rewind`，选择第一次改动之前的点，再选择恢复代码和对话。

如果检查点跟踪正常，`note.txt` 就会重新变回一行 `hello`。两次编辑工具造成的改动，都被倒带清掉了。

## Scene 08｜Bash 删除，Git 接手

接着做相反的实验。

让 Claude 通过 Bash 执行 `rm note.txt`。然后再打开 `/rewind`，尝试恢复代码。

你会发现，`note.txt` 仍然不存在。因为删除动作是 Bash 的副作用，不在检查点的跟踪范围里。

这时就轮到 Git 了。执行 `git checkout note.txt`，文件会根据之前那笔 `init` 提交恢复出来，里面重新出现 `hello`。

一正一反，边界就很清楚：编辑工具改错，检查点能救；Bash 删除，必须依靠提前留下的 Git 历史。

## Scene 09｜把两味后悔药放在正确位置

最后记住这套分工。

小步尝试、随时反悔，用检查点。一个阶段做完、需要长期保存，用 Git。涉及 Bash、副作用或者外部状态时，不要把 `/rewind` 当保险，先确认有没有提交或备份。

检查点是代码改坏时的快速后悔药，Git 是能追溯的永久历史。把两者放在正确位置，你才是真的敢让 Claude 放手做事。
