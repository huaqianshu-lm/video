## 1. 内容范围

本片只处理「检查点（Checkpoint）是什么、如何倒带、能回滚什么、与 Git 如何分工，以及一个最小实战」；文章中关于下一篇插件参考手册的预告只作为系列结尾保留，不展开下一篇内容。

## 2. 核心命题

检查点是 Claude Code 在每条用户提示前自动保存的、面向当前会话的编辑前代码快照；它让用户可以快速回退编辑工具造成的文件改动和对话状态，但不跟踪 Bash 命令、外部编辑或已经产生的外部副作用，因此只能作为本地撤销，不能替代 Git 的永久历史。

一句话结论：

> **检查点负责快速后悔，Git 负责长期留档；先分清它能管到哪里，才不会把安全网当成万能撤销。**

## 4. 知识骨架与关系

### A. 检查点的生成机制

- 每条用户提示创建一个新的检查点。
- 检查点保存的是编辑前代码状态，并与当前会话的提示时间轴对应。
- 快照位于 `~/.claude/file-history/<session>/`。
- 检查点可跨恢复会话访问，默认按 `cleanupPeriodDays` 清理，文章给出的默认值是 30 天。

### B. 倒带操作的两层选择

- 入口：输入 `/rewind`，或在空输入框中双击 `Esc`。
- 先选回退到哪条提示对应的时间点，再选恢复方式。
- 恢复代码和对话：两者一起退回。
- 恢复代码：文件改动退回，对话保留。
- 恢复对话：对话退回，代码保持现状。
- 从此处总结／到此处总结：压缩对话上下文，不改磁盘文件。

### C. 检查点的可回滚边界

可回滚：

- Claude 通过编辑工具直接改动、且被当前会话跟踪的文件。
- 对话历史。

不可回滚：

- Claude 通过 Bash 的 `rm`、`mv`、`cp` 或重定向造成的文件变化。
- 当前会话没有编辑过的文件。
- Claude Code 外部手动编辑或其他并发会话的改动。
- 已发出的请求、数据库变化、`git push` 等外部副作用。

关键判断关系：后果是否落在当前会话跟踪的代码文件和对话里；超出这个范围，检查点就够不着。

### D. 检查点与 Git 的分工

| 维度 | 检查点 | Git |
|---|---|---|
| 触发 | 自动，每条提示 | 手动，按里程碑提交 |
| 作用 | 会话内快速撤销和试错 | 长期历史、恢复、分享与协作 |
| 保留 | 默认按清理周期过期 | 提交历史长期保留 |
| 范围 | 受编辑工具和会话跟踪边界限制 | 能恢复已提交的文件状态，但不能撤回已发生的外部副作用 |
| 使用时机 | 小步尝试、改坏即退 | 功能跑通、阶段完成、需要永久留档 |

检查点补充而不替代版本控制；稳定节奏是边做边用检查点试错，完成小阶段后用 `git commit` 固化。

### E. 最小实战闭环

1. 创建 `rewind-demo`，初始化 Git，并提交 `note.txt` 的 `hello`。
2. 让 Claude 用编辑工具改成三行水果。
3. 再让它改成不想要的一行。
4. `/rewind`，恢复代码和对话，验证文件回到 `hello`。
5. 再用 Bash `rm` 删除文件，回退后验证文件仍不会回来。
6. 用 Git 恢复已提交的 `note.txt`，对照两种安全网的边界。

## 5. 必须保留的信息

- 检查点是编辑前快照，不是普通的 Git commit。
- 每条提示自动创建检查点，不需要手动保存。
- `/rewind` 与空输入框双击 `Esc` 是两个入口。
- 恢复和总结的作用不同：前者改变状态，后者只压缩对话上下文。
- 编辑工具改动和对话可回；Bash、副作用、外部改动不可回。
- 检查点是本地撤销，Git 是永久历史；两者不可互相替代。
- 实战必须同时展示成功回退和 Bash 删除回不来的反例。
