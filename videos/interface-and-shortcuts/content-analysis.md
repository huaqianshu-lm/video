# Interface and Shortcuts 视频化 · 第一步：Content Analysis

## 1. 内容来源与范围

- Source：`source.md`，对应外部原文 `14-interface-and-shortcuts.md`。
- 本视频只处理 Claude Code 的交互界面、快捷键、输入前缀、多行输入、最小练习流程和快捷键自定义。
- 不展开下一篇“怎么提问和给指令”，只在结尾保留下一集预告。
- 文章中的官方文档名称、快捷键行为、版本要求和终端差异均作为本篇 Source 的内容边界，不在本阶段追加外部事实。

## 2. 核心命题

Claude Code 的效率差距，不只来自会不会写指令，还来自能不能在终端界面里看懂状态、用正确的键控制会话，并用特殊前缀和多行输入方式把意图准确送进去。

更具体地说：先认住输入框、状态行、模式／权限提示三块界面，再把“停止、回退、清场、退场、切模式、查历史、重绘”这些动作分清，最后用 `@`、`!` 和稳定的换行方式减少鼠标与重复输入。

## 3. 观众必须带走的信息

### 3.1 界面地图

- 输入框：通常位于底部，带 `>` 提示符，是输入文字、文件引用和特殊前缀的入口。
- 状态行／页脚：显示当前目录、后台任务和可能存在的 PR 状态信息。
- 模式／权限提示：显示普通模式、`plan`、`acceptEdits` 等当前模式，决定 Claude 动手前是否询问。
- 其他滚动区域主要是 Claude 的输出，不需要作为独立操作区学习。
- `Ctrl+L` 可在屏幕花掉或部分空白时重绘，输入和历史保留。

### 3.2 高频快捷键

- `Esc`：中断当前回答或工具调用，已完成部分保留。
- 空输入框按两次 `Esc`：打开回退菜单。
- 输入框有文字时按两次 `Esc`：清空文字并存入历史草稿，不是打开回退菜单。
- `Ctrl+C`：有任务时中断；无任务时第一次清空输入，第二次退出。
- `Ctrl+D`：退出 Claude Code 会话。
- `Shift+Tab`：循环切换权限模式；部分旧 Windows 终端可能使用 `Alt+M`。
- `↑`／`↓`：在光标位于边缘时翻命令历史。
- `Ctrl+L`：重绘屏幕。
- `Ctrl+R`：反向搜索命令历史。
- `Ctrl+O`：切换详细转录视图。
- `Ctrl+C`、`Ctrl+D`、`Ctrl+M` 属于不能重新绑定的保留快捷键，文章将其作为补充说明。

### 3.3 最容易混淆的动作

- `Esc` 一下是刹车，双击 `Esc` 是回退入口，前提是输入框为空。
- `Ctrl+C` 是清场但不一定离场，`Ctrl+D` 是直接退出会话。
- `Shift+Tab` 改的是权限模式，不是普通文本输入状态。

### 3.4 输入框前缀

- `@`：触发文件路径自动补全，用于精准点名文件或目录。
- `!`：进入 Shell 模式，直接运行命令，输出回到对话上下文。
- `/`：命令／Skill 菜单入口，本篇只做识别，不展开命令体系。
- `#`：与记忆／`CLAUDE.md` 相关，行为可能随版本变化，本篇只做识别，不展开。

### 3.5 多行输入

- `Enter` 默认发送，不是换行。
- `\\` 加 `Enter`：跨终端最稳定的换行方式。
- `Ctrl+J`：控制序列换行。
- `Shift+Enter`：多种终端开箱即用，但部分内置终端不支持。
- macOS 可使用 `Option+Enter`，前提是 Option 配成 Meta 键。
- VS Code、Cursor、Alacritty、Zed、Devin Desktop 等内置终端若不支持 `Shift+Enter`，可运行 `/terminal-setup`。
- `Ctrl+G`：在默认文本编辑器中编辑长指令，保存后带回输入框。

### 3.6 可执行练习与自定义

- 文章提供一个六步最小验证流程：启动、`!` 执行命令、`↑` 调历史、`Shift+Tab` 切模式、多行输入、`Ctrl+D` 退出。
- `! echo hello-shortcuts` 用于验证 Shell 模式，输出应进入对话。
- `claude --version` 用于确认是否满足快捷键自定义所需的 v2.1.18 或更高版本。
- `/keybindings` 打开或创建 `~/.claude/keybindings.json`，用于重新绑定可修改的快捷键。
- 新手先用熟默认配置，再考虑自定义；`Ctrl+C`、`Ctrl+D` 等保留键不能改。

## 4. 认知关系

### 4.1 从界面识别到动作控制

界面三块告诉观众“看哪里”；快捷键告诉观众“怎么控制”；输入前缀和多行输入告诉观众“怎么把意图准确送进去”。三层依次建立，不能只展示快捷键清单。

### 4.2 停止动作的对比关系

`Esc` 与 `Ctrl+C` 都可能中断，但前者强调保留已完成部分并继续指导，后者根据当前状态清场；`Ctrl+D` 则直接结束会话。状态和结果必须在画面上分开。

### 4.3 输入方式的选择关系

短指令使用普通输入；文件明确引用用 `@`；临时命令用 `!`；多行内容用 `\\` 加 `Enter` 或其他终端支持的换行方式；长指令可交给 `Ctrl+G` 编辑器。

### 4.4 练习形成肌肉记忆

六步练习把前面讲过的动作串成一次可执行验证。视频要展示“按键／输入 → 状态变化 → 预期结果”，不能只复述步骤名称。

## 5. 可视觉化内容

- 终端界面分区图：输入框、状态行、模式／权限提示用高亮框定位。
- 快捷键板：用“动作 → 结果”的短标签呈现，不把整篇表格塞满画面。
- 双轨对比：`Esc`、`Ctrl+C`、`Ctrl+D` 通过状态线和会话终点区分。
- 前缀路由：`@` 指向文件，`!` 指向 Shell，`/` 指向命令菜单，`#` 指向记忆相关入口。
- 多行输入：展示 `Enter` 发送与 `\\` 加 `Enter` 换行的不同结果。
- 练习流程：六个节点依次点亮，输出和模式提示作为验证结果。
- 自定义边界：可修改快捷键与保留快捷键分流。
- 结尾判断链：看界面 → 选动作 → 选输入方式 → 验证结果。

## 6. 可弱化或删除的信息

- 汽车仪表盘、换挡杆、手机联系人等类比只服务于口播，不作为长屏幕文字。
- PR 页脚的四种颜色只作为状态行的示例，不展开 PR 审查流程。
- `Ctrl+M` 的终端回车背景不单独成幕，保留在保留快捷键的口播中。
- Windows 旧终端与 macOS Option 键差异压缩为局部提示，不抢主线。
- `/`、`#` 的后续篇目编号只保留必要的“一句话交代”。

## 7. 内容边界与风险

- 不把 `Esc` 双击的回退前提省略，否则会把“输入框有文字时清空草稿”的行为讲错。
- 不把 `Ctrl+C` 和 `Ctrl+D` 合并成“退出键”。
- 不把 `!` 描述成经过 Claude 解释或批准的工具调用；文章明确强调它直接运行 Shell。
- 不把 `Shift+Enter` 说成所有终端都支持，必须保留 `\\` 加 `Enter` 的跨终端优先级。
- 不在画面中展示真实秘密或执行任何 Source 中的命令；练习命令只作为视频中的抽象示例文字。
