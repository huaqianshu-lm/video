# Interface and Shortcuts 视频化 · 第五步：Visual Script

> 目标：为 9 个 Scene 明确画面结构、状态变化、动画顺序和声音与画面的互补关系。Visual Prototype 沿用基线的横屏 Scene 容器、幕内字幕、上一幕／下一幕、自动播放和进度提示结构。

## 全局视觉原则

### 1. 先做界面定位，再做快捷键记忆

第一幕把输入框、状态行、模式／权限提示从输出区域中抽出，后续所有操作都回到这三个区域验证。

### 2. 快捷键用结果表达

键帽只显示必要的按键，旁边展示停止、清空、退出、模式变化、历史回填和重绘后的结果，不把口播全文搬上屏。

### 3. 状态差异必须可见

`Esc` 双击是否触发回退、`Ctrl+C` 是否退出、`Enter` 是否发送，都通过输入框状态、对话线和会话终点的变化表达。

### 4. 前缀使用路由画面

`@`、`!`、`/`、`#` 从同一个输入框分流；深入展示的只有文章明确展开的 `@` 文件补全和 `!` Shell 模式。

### 5. 保持克制的教程视觉

深色终端背景、低饱和蓝紫主色、绿色表示成功或保留、黄色表示当前模式或提示、红色表示误操作风险。代码、路径、按键和命令使用等宽字体。

## Scene 01｜先认出你该盯的三块区域

### 画面结构

中央是一块深色 Claude Code 终端模拟界面，顶部是滚动输出，底部依次放置输入框、状态行和模式／权限提示；三个区域用不同颜色的框标出。

### 动画顺序

1. 整个终端从低对比度出现，滚动输出保持模糊。
2. 输入框高亮并显示 `>` 提示符。
3. 状态行／页脚亮起，出现当前目录和后台任务短标签。
4. 模式／权限提示亮起，显示 `default`。
5. 右下角短暂显示 `Ctrl+L` → 屏幕重绘，输入和历史保留。

### 视觉目标

观众只需要先认住三个操作区域，其他滚动区域不作为独立知识点。

### 与口播互补

旁白解释三块区域的职责，画面用空间和焦点证明“看哪里”。

### 屏幕文字

输入框；状态行／页脚；模式／权限提示；`Ctrl+L` 重绘

### Visual Type

OpeningScene + UI Simulation

## Scene 02｜高频快捷键是一张动作地图

### 画面结构

中央是一组简化键盘，四周有“会话控制”“权限模式”“历史检索”“屏幕／转录”四个结果面板。

### 动画顺序

1. `Esc`、`Ctrl+C`、`Ctrl+D` 依次从键盘飞向会话控制面板。
2. `Shift+Tab` 飞向权限模式面板。
3. `↑`、`Ctrl+R` 飞向历史面板。
4. `Ctrl+L`、`Ctrl+O` 飞向屏幕／转录面板。
5. 四组面板收成一张“动作地图”。

### 视觉目标

展示“按键 → 结果”，不展示完整长表格和全部适用时机。

### 与口播互补

旁白负责按动作分类，画面负责把按键与结果建立空间连接。

### 屏幕文字

`Esc`；`Ctrl+C`；`Ctrl+D`；`Shift+Tab`；`↑`；`Ctrl+R`；`Ctrl+L`；`Ctrl+O`

### Visual Type

Key Map + Process

## Scene 03｜Esc、Ctrl+C、Ctrl+D 不要混用

### 画面结构

三列状态对比：左列是 `Esc`，中列是 `Ctrl+C`，右列是 `Ctrl+D`；左列内部再拆“单击”和“空输入框双击”。

### 动画顺序

1. Claude 输出正在进行，按 `Esc` 后停在当前进度，已完成部分保留。
2. 清空输入框后双击 `Esc`，弹出回退菜单。
3. 输入框有文字时双击 `Esc`，文字变为历史草稿。
4. `Ctrl+C` 在任务运行中切断任务，在空闲时清空输入。
5. `Ctrl+D` 让终端会话直接落到“已退出”。

### 视觉目标

把“停止但保留”“清空但不一定退出”“直接退出”用绿、黄、红三种结果标签区分。

### 与口播互补

旁白给出动作前提和语义，画面只承载状态分岔与结果，避免重复解释。

### 屏幕文字

`Esc` 一下：停止；`Esc` 两下：回退；`Ctrl+C`：清场；`Ctrl+D`：退场

### Visual Type

Comparison + State Diagram

## Scene 04｜Shift+Tab 切换权限模式

### 画面结构

终端底部的状态行放大为横向模式选择器，上方是一个待处理的编辑任务卡。

### 动画顺序

1. `default` 高亮，任务卡显示“等待确认”。
2. 按 `Shift+Tab`，状态行切到 `acceptEdits`，任务卡显示“编辑自动接受”。
3. 再按一次，切到 `plan`，任务卡显示“只出方案”。
4. 状态行回到 `default`，旁边出现旧 Windows 终端的 `Alt+M` 兼容提示。

### 视觉目标

模式切换影响的是“动手前是否询问”，不是输入框的发送或换行。

### 与口播互补

旁白解释模式含义和平台差异，画面用任务卡反馈模式改变后的行为。

### 屏幕文字

`Shift+Tab`；`default`；`acceptEdits`；`plan`

### Visual Type

UI Simulation + Mode Switch

## Scene 05｜四个输入前缀，四条入口

### 画面结构

一个带 `>` 的输入框居中，四个前缀从左侧进入后分别连接到文件树、Shell 终端、命令菜单和记忆相关卡片。

### 动画顺序

1. 输入 `@`，文件树出现路径补全候选，选中 `src/auth.ts`。
2. 输入 `!`，Shell 面板直接执行 `git status` 并回传输出。
3. 输入 `/`，命令／Skill 菜单展开后收起。
4. 输入 `#`，记忆相关入口出现版本差异提示。
5. `@` 和 `!` 两条路径保持高亮，其他两条降为边界提示。

### 视觉目标

突出前缀改变输入路由；不把 `/` 和 `#` 的后续主题提前讲成当前教程内容。

### 与口播互补

旁白解释四个符号的分工，画面证明文件补全和 Shell 执行的不同路径。

### 屏幕文字

`@` 文件；`!` Shell；`/` 命令／Skill；`#` 记忆相关

### Visual Type

Task Routing + UI Simulation

## Scene 06｜Enter 默认发送，多行要换一种按法

### 画面结构

左右对比两个相同输入框：左侧是普通 Enter，右侧是 `\\` 加 Enter；下方补充兼容方式和 `Ctrl+G` 编辑器入口。

### 动画顺序

1. 左侧输入“第一行”，按 Enter，文字飞到对话区并标记“已发送”。
2. 右侧输入“第一行 \\”，按 Enter，光标落到第二行。
3. 第二行输入完成后，显示 `Ctrl+J`、`Shift+Enter`、`Option+Enter` 作为可选路径。
4. 内置终端卡片显示 `/terminal-setup`，长指令卡片显示 `Ctrl+G`。

### 视觉目标

“发送”和“换行”必须在同一画面中形成结果对比，`\\` 加 Enter 作为跨终端默认建议。

### 与口播互补

旁白补充平台支持边界，画面只演示动作结果和选择关系。

### 屏幕文字

`Enter`：发送；`\\` + `Enter`：换行；`Ctrl+J`；`Shift+Enter`；`Ctrl+G`

### Visual Type

UI Simulation + Before/After

## Scene 07｜六步把动作跑一遍

### 画面结构

一条横向终端练习时间线，包含六个节点：启动、Shell、历史、模式、多行、退出；右侧是实时终端输出。

### 动画顺序

1. `claude` 节点点亮，终端出现 `>` 输入框。
2. `! echo hello-shortcuts` 执行，输出回到对话。
3. `↑` 将命令回填到输入框。
4. `Shift+Tab` 让状态行模式变化。
5. `\\` 加 Enter 让光标换到下一行。
6. `Ctrl+D` 后显示“回到普通终端”，六节点全部变绿。

### 视觉目标

每个按键都跟随一个可观察反馈，形成从动作到结果的验证链。

### 与口播互补

旁白带领练习并说明预期，画面显示模拟操作结果，不执行真实命令。

### 屏幕文字

`claude`；`! echo hello-shortcuts`；`↑`；`Shift+Tab`；`\\` + `Enter`；`Ctrl+D`

### Visual Type

Demo + Task Execution

## Scene 08｜先用熟默认，再考虑自定义

### 画面结构

左侧是版本检查与 `/keybindings`，中间是 `~/.claude/keybindings.json`，右侧分成“可重绑”和“保留键”两栏。

### 动画顺序

1. `claude --version` 显示 `v2.1.18+` 检查结果。
2. `/keybindings` 打开配置文件卡片。
3. 一个普通快捷键进入“可重绑”栏。
4. `Ctrl+C`、`Ctrl+D`、`Ctrl+M` 进入“保留键：不可重绑”栏。
5. 顶部出现“先用熟默认配置”的黄色提示。

### 视觉目标

自定义是进阶入口，不是本篇的主要练习；不可重绑边界必须清晰。

### 与口播互补

旁白解释版本和使用建议，画面展示配置入口与键的权限边界。

### 屏幕文字

`claude --version`；`/keybindings`；`~/.claude/keybindings.json`；保留键：不可重绑

### Visual Type

Configuration Boundary

## Scene 09｜把手放对地方

### 画面结构

中央是四节点判断链：“看界面 → 选动作 → 选入口 → 验证结果”，下方是一张下一篇预告卡。

### 动画顺序

1. “看界面”点亮输入框、状态行、模式提示三个小图标。
2. “选动作”点亮 `Esc`、`Shift+Tab`、`↑`。
3. “选入口”点亮 `@`、`!` 和多行输入。
4. “验证结果”出现状态行变化和命令输出。
5. 最后出现“下一篇：怎么提问和给指令”，停留约 2～3 秒。

### 视觉目标

结尾复用判断链，不再增加新的快捷键或技术细节；下一篇预告是最后一个视觉事件。

### 与口播互补

旁白完成总结和系列承接，画面将零散动作收束为可复用流程。

### 屏幕文字

看界面 → 选动作 → 选入口 → 验证结果；下一篇：怎么提问和给指令

### Visual Type

SummaryScene + Next Episode Preview

## Gate 2 内部审查

- 9 个 Scene 均有对应 Narration，且画面承担演示、状态变化或结果证明，不只是重复口播。
- 所有画面文字均可追溯到 `source.md`、`content-analysis.md`、`video-narrative.md`、`scene-script.md` 或本文件的视觉拆解。
- `@`、`!`、`/`、`#` 的业务语义没有互换；`/` 和 `#` 未被扩写成文章未讲内容。
- 示例命令 `! git status`、`! echo hello-shortcuts`、`claude --version`、`/keybindings`、`/terminal-setup` 均来自 Source。
- 没有真实密钥、token、密码或无关项目名称进入画面。
