# Narration Script｜Voice 语音模式：把提示词说出来，而不是打出来

## Scene 01｜语音不是替你念代码

程序员本来就不算怕打字。变量名、函数名，还有各种下划线，真让你念给普通语音输入法，没准还得返工。Voice 真正有价值的地方，不是替你精准输入代码，而是替你打那一长段需求描述。

## Scene 02｜Voice 就是把话放进输入框

它的本质很简单：你说话，它实时转成文字，落进 Claude Code 的提示词输入框。之后这段文字和手打进去的完全一样。你可以先说一半，再用键盘补上文件名、函数名，或者一个更精确的条件。

## Scene 03｜声音上云，文字回来

这里有个使用前必须知道的边界：音频不会在本地处理，而是传到 Anthropic 的服务器转写，再把文字放回输入框。好消息是，转录本身不消耗 Claude 的消息或令牌，也不计入 `/usage` 里显示的限制。

## Scene 04｜第一道门：必须是 Claude.ai 账户

先别急着查麦克风。如果你的 Claude Code 是用 Claude.ai 账户登录的，Voice 才有机会工作。直接使用 Anthropic API key，或者接 Bedrock、Vertex、Foundry，都不支持语音听写。组织启用了 HIPAA 合规，也不支持。遇到 `Voice mode requires a Claude.ai account`，根因是认证方式，不是麦克风。

## Scene 05｜第二道门：本地麦克风和运行环境

第二道门是本地麦克风。Mac、Windows 和 Linux 本机可以用，Windows 上的 WSL 需要 WSLg。SSH、网络版 Claude Code，以及 VS Code Remote 都不行，因为真正录音的麦克风在你本地，运行 Claude Code 的进程却在远端。Linux 如果缺少录音工具，Voice 会给出安装提示。

## Scene 06｜按住，还是点击？

Voice 有两种录音模式。默认的 hold 像对讲机：按住 Space 才录，松开就停。tap 像录音笔：点一下开始，再点一下停止。前者更适合精确控制这一小段录音，后者更适合说完就走，不想一直按着键。

## Scene 07｜模式差异藏在“什么时候发送”

按住模式刚开始会有一小段预热，页脚可能显示 `keep holding…`。松手以后，默认只是把文字定稿，等你按 Enter；打开自动发送后，至少三个词才会自动发。点击模式需要更高版本，停止后会自动发送至少三个词的内容，没说够就只插入不发送；没有声音十五秒，或录满两分钟，也会自动停止。

## Scene 08｜把 Voice 调成自己的输入开关

如果你希望它每次开会话就准备好，可以把 `voice.enabled` 写进设置，再用 `mode` 固定 hold 或 tap。按住模式还可以打开 `autoSubmit`，松手后直接发送。这样调一次，之后就不用每次重新选择自己的录音习惯。

## Scene 09｜语言和触发键也有边界

听写语言跟随 `language` 设置，默认是英语。文章列出的支持列表里目前没有中文，日语和韩语在列，所以说中文前要先有这个预期：本机实际提示优先。触发键可以通过 `voice:pushToTalk` 更换，但按住模式别绑定一个裸字母，优先用 `meta+k` 这样的组合键。

## Scene 10｜从 `/voice` 到第一句转写

动手时，先用 `claude --version` 确认版本，再运行 `/voice`。第一次可能会弹出麦克风权限，允许它。清空输入框，按住 Space，说一句英文，比如 `list all files in the current directory`。看到文字实时出现在输入框里，说明听写链路已经跑通。

## Scene 11｜说一半，再用手补完

松开以后别急着发送。你可以在转写文字后面手打 `and show their sizes`，再按 Enter，验证语音和键盘能放在同一条消息里。想试点击模式，就运行 `/voice tap`，说够三个词后点第二次 Space，它会自动发送。最后运行 `/voice off`，Space 就恢复成普通空格键。

## Scene 12｜它省的是描述成本

所以，Voice 不是要替代你精准地写代码，而是让你少打一长段需求。记住四件事：先看 Claude.ai 账户，再确认本地麦克风；按住和点击按习惯选择；语言和触发键要调对。工具不必样样全能，能在它擅长的那一格里替你省力就够了。下一篇，我们把前面学过的零件串成一次从零到上线的综合实战。
