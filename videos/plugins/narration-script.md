# 插件（Plugins）视频化 · 第五步：Narration Script

> 说明：以下每个 Scene 下仅保留实际需要朗读的内容。命令、路径和标签作为口播中的内容表达，不是本任务要执行的指令。

## Scene 01｜散件交接，最容易漏一处

你辛苦给团队配好了一套 subagent、hook 和 MCP。新同事接手时，你得告诉他 agents 放哪儿，hook 加到哪个 settings.json，别忘了还有 .mcp.json。讲完半小时，还是可能漏一处，最后大家的配置跑得不一样。散件管理的问题，不是谁粗心，而是它本来就分散。

## Scene 02｜插件是一个整体盒子

插件就是 Claude Code 给这个问题的答案。它把 commands、subagents、skills、hooks、MCP server 和 LSP server 收进一个自包含的文件夹，作为一个整体来安装、停用和分发。原来散在好几个文件里的扩展，现在可以一起装进一个盒子。

## Scene 03｜散装还是插件，看你要不要规模化

但不是所有配置都值得打包。单个项目自用、个人工作流和快速试验，用 .claude 里的散装配置就够了。要给团队共享、跨项目复用，或者希望带着版本更新，才更适合做成插件。插件里的 skill 还会带命名空间，比如 my-plugin 里的 hello，要用 /my-plugin:hello 调用。

## Scene 04｜市场是两步：先加货架，再装插件

拿别人的插件时，最容易混淆的是市场的两步。第一步，用 marketplace add 把一个市场注册进来，让 Claude Code 看见货架；这一步还没有安装任何插件。第二步，才用 plugin install 从指定市场选择一个具体插件。先加市场，再装插件，顺序不要反。

## Scene 05｜三个市场，三种取用判断

官方市场 claude-plugins-official 是自带的，里面是 Anthropic 精选的插件，日常优先看它。claude-community 是社区市场，要手动添加，插件经过验证并固定到具体提交。claude-code-plugins 是官方演示市场，适合教学和试水。简单记就是：官方优先，社区先看清，演示用来学习。

## Scene 06｜安装前看清内容，安装后刷新生效

装插件前，先在 /plugin 的详情里看“将安装”清单。它可能带来需要主动调用的 skill 和 subagent，也可能带来自动运行的 hook、MCP server 或 LSP server。再看上下文成本，别让用不上的组件占掉工作空间。装好以后运行 /reload-plugins，插件才会在当前会话里刷新生效，命令也会以命名空间出现。

## Scene 07｜plugin.json 在里面，组件目录在外面

自己打包时，插件有一个身份证文件：.claude-plugin/plugin.json，里面声明 name、description 和 version。skills、agents、hooks，以及 .mcp.json 和 .lsp.json，都放在插件根目录。记住一个容易踩的坑：.claude-plugin 里只放 plugin.json，其他组件目录不能塞进去。

## Scene 08｜不用发市场，也能本地测试插件

开发自己的插件，不需要先发到市场。启动时用 claude --plugin-dir ./my-first-plugin，直接加载本地目录。改完文件后运行 /reload-plugins，就能检查本地插件有没有生效。这个路径适合反复测试，不必每次都走市场安装。

## Scene 09｜第三方插件，先过信任三查

最后是最重要的安全边界。插件不是无害的小工具，它可能通过 hook、MCP server 或 bin 里的可执行文件，在你的用户权限下运行代码。安装前至少问三遍：来源可信吗，它带了什么，范围给到哪儿？官方市场优先；不确定的第三方先看代码和权限，必要时用本地范围试，不要一上来就铺到所有项目。

## Scene 10｜插件强在规模，安装前还要判断

所以，插件的价值不在于把所有东西都重新包装一遍，而在于规模化复用。先判断自己是否需要团队共享、跨项目搬运或版本更新，再按两步加入市场和安装插件。安装前看清组件和上下文成本，目录里把 plugin.json 和其他组件放在正确位置，面对第三方还要检查来源、内容和范围。方便可以一键获得，但信任不能一键跳过。
