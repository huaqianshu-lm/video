# VS Code 集成视频化 · 第五步：Visual Script

## 全局视觉原则

### 1. 声音解释，画面证明

旁白负责说明扩展和 CLI 的关系、操作条件、权限选择和使用建议。画面负责展示入口出现、代码被选中、diff 发生、计划被批注和任务如何分流。

### 2. 一个 Scene 只有一个视觉中心

每幕只保留一个主要动作：入口出现、窗口连接、清单点亮、diff 审阅、上下文进入、计划批注、练习推进、快捷键分流或结论预告。不要把整张功能表和多组 UI 同时堆在一幕。

### 3. 界面模拟优先表达状态

使用深色、克制的 VS Code 风格工作区：左侧文件树、中间编辑器、右侧 Claude 面板或底部终端。所有面板都服务于状态变化，不模拟完整产品，不添加文章没有的业务功能。

### 4. 屏幕文字保持可追溯

所有标题、标签、按钮、命令、文件名和状态文字都必须来自 source.md、content-analysis.md、video-narrative.md、scene-script.md 或本文件。预览控制按钮属于 HTML 原型外壳，不属于视频画面。

### 5. 动画表达因果

- Spark 从隐藏到出现：表达打开具体文件是入口条件。
- 两窗口连接同一核心：表达共享引擎、配置和历史。
- 清单逐项点亮：表达排查顺序。
- diff 高亮和手动改字：表达审阅权。
- 标签进入提示框：表达上下文被准确提供。
- 计划批注后停在等待批准：表达执行前的人类判断。
- 练习时间线逐格推进：表达完整工作流。

## Scene 01｜Spark 图标去哪了？

### 视觉目标

让观众立刻看到“扩展安装了，但入口没出现”的真实阻塞，并在同一幕中看到条件满足后的变化。

### 画面结构

16:9 深色 IDE 外壳。左侧显示空工作区；中间提示“打开文件夹”。编辑器顶部右上角工具栏保留空位；当口播说到“右上角没有 Spark”时，用红色虚线定位框圈出入口位置。随后中间打开 demo.py，右上角出现 Spark，定位框切换为围绕 Spark 的蓝绿色高亮，右下角保留 ✱ Claude Code 状态栏入口作为备用。

### 动画顺序

1. 空工作区出现，右上角没有 Spark；口播提到该位置时，红色定位框短暂圈出空位。
2. 一个轻微的搜索光标在工具栏扫过，随后停在“光开文件夹不够”。
3. 文件树打开 demo.py。
4. Spark 以短淡入出现，定位框切换为蓝绿色高亮并围绕 Spark 轻微脉冲，状态栏入口同步亮起。
5. 画面停留，让入口位置清楚可读。

### 主要屏幕文字

Claude Code、Spark、光开文件夹不够、打开具体文件。

### 声音与画面互补

旁白解释入口出现条件，画面只证明前后状态，不重复一整段排查说明。

### Visual Type

IDE Simulation。

## Scene 02｜扩展和 CLI 是什么关系？

### 视觉目标

让观众形成“同一核心、两个窗口、能力不同”的结构直觉。

### 画面结构

左右两列分别为 CLI 和 VS Code 扩展，中间是共享核心卡片。核心卡片只写共享配置、可恢复历史。左侧浮出命令和 skills：全部、MCP 配置：完整、! bash、Tab 补全；右侧浮出并排 diff、选中代码上下文：原生。

### 动画顺序

1. 两个窗口分别出现。
2. 两条线汇入共享核心。
3. 共享配置和可恢复历史亮起。
4. 能力标签从左右窗口向外展开。
5. 底部出现“不是二选一”。

### 主要屏幕文字

CLI、VS Code 扩展、共享配置、可恢复历史、并排 diff、选中代码上下文、命令和 skills：全部／子集。

### 声音与画面互补

旁白使用“同一个后厨的两个点单窗口”解释关系，画面用连接结构证明关系，不制作真实厨房插图。

### Visual Type

Comparison Diagram。

## Scene 03｜安装官方扩展，找不到入口就这样查

### 视觉目标

把三种安装入口和五步排查变成一条可执行路径。

### 画面结构

左侧为扩展市场列表，Claude Code 行显示 Anthropic；顶部显示 VS Code ≥ 1.98.0。右侧为排查清单，底部为活动栏 Spark、✱ Claude Code、命令面板三个备用入口。

### 动画顺序

1. 版本号和 Anthropic 发布者先亮起。
2. 扩展市场搜索框输入 Claude Code，官方行被选中。
3. 直装链接和“其他编辑器分支”作为两张小卡片短暂出现。
4. 排查清单依次点亮：打开文件、确认版本、Developer: Reload Window、禁用冲突扩展、信任工作区。
5. 三个备用入口从 IDE 的对应位置出现。

### 主要屏幕文字

VS Code ≥ 1.98.0、Anthropic、Cmd+Shift+X、vscode:extension/anthropic.claude-code、Developer: Reload Window、信任工作区、活动栏 Spark、✱ Claude Code。

### 声音与画面互补

旁白压缩三种安装方式和首次登录细节，画面优先帮助观众记住官方发布者和排查顺序。

### Visual Type

Step List + IDE Simulation。

## Scene 04｜并排 diff：看清了再点头

### 视觉目标

证明扩展的价值是让用户看清、修改并批准改动。

### 画面结构

中央为双栏 diff 窗口。左列标题为原稿，右列标题为建议改动。代码使用 demo.py 的 greet 函数，右侧新增类型注解和 f-string。右下角放接受、拒绝两个动作，右侧一行先出现一个需要手动修正的字符串，再被改正。

### 动画顺序

1. 原稿和建议改动并排出现。
2. 删除行变红，新增行变绿。
3. 光标落在右侧建议，手动修改一处边界。
4. 接受按钮亮起，改动状态变为已接受。

### 主要屏幕文字

原稿、建议改动、手动修正、接受、拒绝、def greet(name: str) -> str:、return f"Hello {name}"。

### 声音与画面互补

旁白强调“不是闭眼签字”，画面给出实际审阅和修改证据。

### Visual Type

Diff Review。

## Scene 05｜@ 提及和选中代码：把上下文喂准

### 视觉目标

让“提供上下文”成为一个可见的输入动作。

### 画面结构

左侧为文件树和编辑器，右侧为 Claude 提示框。先在提示框输入 @auth，再输入 @src/components/；随后编辑器高亮 greet 函数两行，提示框底部出现“已选中 2 行”。

### 动画顺序

1. @auth 标签从输入框右侧生成。
2. 文件树对应 auth 文件短暂高亮。
3. @src/components/ 进入提示框，文件夹节点亮起。
4. 编辑器选中两行代码，提示框出现已选中 2 行。
5. Option+K／Alt+K 作为角标出现，随后收起。

### 主要屏幕文字

@auth、@src/components/、已选中 2 行、Option+K／Alt+K、上下文更准确。

### 声音与画面互补

旁白解释模糊匹配、选中和行号引用，画面不再重复解释，而是展示上下文如何进入提示框。

### Visual Type

Context Injection。

## Scene 06｜Plan Mode：先交方案，再动手

### 视觉目标

让用户看见计划审阅如何把判断点放在执行之前。

### 画面结构

左侧为 Claude 面板，顶部显示三个模式：正常模式、Plan Mode、自动接受模式；右侧为 Markdown 计划文档。文档内容围绕给 demo.py 增加命令行参数支持，第二步显示引入 argparse，旁边出现一条内联批注。

### 动画顺序

1. 三种模式标签出现，Plan Mode 被选中。
2. 提示框显示增加命令行参数支持。
3. Markdown 计划逐行展开。
4. 第二步出现批注“这里先确认参数入口”。
5. 文档底部停在“等待批准”，不进入实际执行画面。

### 主要屏幕文字

正常模式、Plan Mode、自动接受模式、先看方案、第 2 步：引入 argparse、这里先确认参数入口、等待批准。

### 声音与画面互补

旁白解释三种权限模式和 Plan Mode 的用途，画面把“先审阅”固定为一个停顿状态。

### Visual Type

Plan Review。

## Scene 07｜10 分钟跑通最小练习

### 视觉目标

用一个最小 Python 文件串起前面三个图形界面价值点。

### 画面结构

采用横向时间线，五个节点分别为工作区、面板、选中、diff、计划。每个节点连接到一个简化的 IDE 局部画面。底部显示 demo.py 和当前状态。

### 动画顺序

1. 显示 mkdir vscode-claude-demo 和 demo.py。
2. code . 后，工作区和 Claude 面板打开。
3. greet 两行被选中，状态显示已选中 2 行。
4. 右侧 diff 显示 f-string + 类型注解，动作显示 diff：接受。
5. 最后切换 Plan Mode，显示命令行参数支持任务。

### 主要屏幕文字

mkdir vscode-claude-demo、demo.py、code .、已登录、已选中 2 行、f-string + 类型注解、diff：接受、Plan Mode。

### 声音与画面互补

旁白按自然操作顺序讲解，画面只在状态发生变化时推进，避免把所有命令和说明同时铺满。

### Visual Type

Workflow Timeline。

## 全片视觉类型、组件与动画标准

### 视觉类型分布

| 类型 | Scene |
| --- | --- |
| IDE Simulation | 01、03 |
| Comparison Diagram | 02、08 |
| Diff Review | 04 |
| Context Injection | 05 |
| Plan Review | 06 |
| Workflow Timeline | 07 |
| Summary Scene | 09 |

### 原型组件

- Window：深色窗口外壳、标题栏和轻边框。
- FileTree：只显示 demo.py、auth 和 src/components 等 Source 中出现的文件上下文。
- Editor：显示 greet 函数和少量行号。
- ClaudePanel：提示框、模式标签、登录状态和等待批准状态。
- DiffPane：原稿、建议改动、接受／拒绝动作。
- Checklist：安装排查步骤逐项点亮。
- ShortcutCard：快捷键和对应动作。
- RouteCard：扩展／CLI 任务分流。
- PreviewShell：只属于原型的上一幕、下一幕、自动播放和进度提示。

### 动画层级

1. 信息动画：窗口切换、状态更新、文本进入、路线汇聚。
2. 注意力动画：当前行高亮、按钮短暂发光、清单点亮。
3. 装饰动画：轻微背景渐变和边框呼吸，不使用复杂粒子或花哨转场。

### 画面标准

- 1920 × 1080 横屏构图，原型容器使用 16:9。
- 深色背景，白色主文字，蓝色用于当前焦点，绿色用于完成，红色只用于 diff 删除或找不到入口的提示。
- 主标题控制在 1～2 行；辅助文字不覆盖代码和主要状态。
- 每幕只保留一个主界面动作，字幕位置预留在底部安全区。
- 预览按钮和进度条位于原型外壳，不进入未来 Remotion Composition。
