# 上下文管理：别让它「失忆」也别烧爆 token

## 全局视觉原则

### 1. 让“工作台”成为贯穿全片的视觉隐喻

用深色、克制的工作台界面承载文件、对话、命令和摘要。堆积、压缩、清空和重新摆放都必须改变信息状态，而不是只做装饰动画。

### 2. 声音负责解释，画面负责证明

口播解释 token、上下文衰退和命令选择；画面展示内容进入工作台、占用条增长、文件被压缩、工作台被清空，以及终端输出的前后变化。

### 3. 每幕只有一个视觉中心

避免把全文口播、命令表、五个习惯和工作流同时塞进一幕。命令对比用左右结构，流程用连续状态，抽象结论用一张简洁图。

### 4. 屏幕文字只使用当前文章支持的表达

使用 `source.md` 中的命令、示例文件、症状、习惯和下一集标题。不得引入下一篇权限配置的具体内容，也不得把预览导航或制作说明作为幕内文字。

### 5. 动画优先表达状态变化

优先使用：文件进入、占用增长、症状替换、摘要生成、工作台清空、输出下降、流程推进。发光、漂浮和缩放只作为注意力辅助。

## 逐 Scene 视觉设计

### Scene 01｜读得越多，怎么反而失忆？

- 画面结构：中央是一张有限容量的工作台，左侧文件树不断加入文件，右侧终端连续出现阅读输出。
- 视觉动作：文件卡片和输出行依次进入；容量条接近满载；最后出现 `auth 模块在哪个文件？`。
- 状态变化：`读取更多` 从绿色进度变成红色拥挤，任务状态从 `working` 变为 `stalled`。
- 口播互补：口播讲故事和反转，画面不重复整段叙述，只证明“堆积后停滞”。
- 画面文字：`读了二十几个文件`、`auth 模块在哪个文件？`

### Scene 02｜上下文窗口是一张有限工作台

- 画面结构：工作台分成六个入口，依次放入系统提示、`CLAUDE.md`、自动记忆、用户消息、已读文件和工具输出。
- 视觉动作：前四类以小卡片进入，已读文件和工具输出连续堆叠并占据主要容量。
- 状态变化：容量条从空白逐步增长，已读文件和工具输出区域被高亮。
- 口播互补：口播解释概念，画面建立“所有内容共同占用”的空间直觉。
- 画面文字：`上下文窗口`、`工作台`、`已读文件`、`工具输出`

### Scene 03｜工作台塞满后，会出现上下文衰退

- 画面结构：同一工作台保持满载，中央对话面板连续切换四种症状。
- 视觉动作：先出现前后不一致的方案，再把回答压缩成笼统句子，再重复询问，最后出现两次纠正仍未改变的状态。
- 状态变化：容量条变红，症状标签依次亮起，最后汇聚为 `context rot`。
- 口播互补：口播解释原因和判断标准，画面让症状可见。
- 画面文字：`前后矛盾`、`变得笼统`、`反复询问`、`纠正两遍仍原地打转`、`context rot`

### Scene 04｜两把扫帚：`/compact` 与 `/clear`

- 画面结构：左右两张相同的工作台，左侧为 `/compact`，右侧为 `/clear`。
- 视觉动作：左侧多张对话纸被压缩成一张“摘要”；右侧全部内容移出，留下空台面。
- 状态变化：左侧保留“结论”标签，右侧显示“新会话空间”。
- 口播互补：口播给出使用定义，画面显示“保留”和“清空”的结果差异。
- 画面文字：`/compact`、`留着继续用`、`/clear`、`从头再来`

### Scene 05｜什么时候压缩，什么时候清空？

- 画面结构：从“任务还没完？”和“前文还要用？”两个判断节点分叉，通往三个动作。
- 视觉动作：任务未完成且前文有用时，流线进入 `/compact`；无关任务或污染严重时进入 `/clear`；彻底干净时进入“直接新开会话”。
- 状态变化：每条路径显示对应结果，不出现额外功能卡片。
- 口播互补：口播讲选择时机，画面提供记忆用的决策路径。
- 画面文字：`任务还没完？`、`前文还要用？`、`/compact`、`/clear`、`直接新开会话`

### Scene 06｜用 `/context` 和 `/usage` 盯住用量

- 画面结构：左右两个终端窗口，左侧为 `/context` 的分类占用，右侧为 `/usage` 的会话统计。
- 视觉动作：左侧高亮 `CLAUDE.md`、文件和工具输出；右侧依次显示 `Total cost`、`Total duration (API)` 和 `Total code changes`。
- 状态变化：两个窗口的标题分别落到“看占了什么”和“看烧了多少”。
- 口播互补：口播解释职责区别，画面只保留足以识别的输出字段。
- 画面文字：`/context`、`看占了什么`、`/usage`、`看烧了多少`、`Total cost: $0.55`

### Scene 07｜auto-compact 会保命，但别依赖它

- 画面结构：左侧是正在执行的任务流水线，右侧是自动压缩介入提示；随后切换到带指令的主动压缩。
- 视觉动作：工作台接近上限时弹出 `auto-compact`，流水线短暂停顿；手动输入 `/compact 保留已确认的方案` 后，摘要按指定重点生成。
- 状态变化：被动路径显示“时机不可控”，主动路径显示“保留重点”。
- 口播互补：口播解释机制和风险，画面演示“被动打断”与“主动指定”的区别。
- 画面文字：`auto-compact`、`被动保命`、`主动 /compact`、`保留已确认的方案`

### Scene 08｜五个从源头省 token 的习惯

- 画面结构：一条从输入到输出的五站流程，站点依次为玩具项目、`@` 文件、拆小任务、阶段清理、子代理。
- 视觉动作：每经过一站，工作台上的无关材料减少，主任务区域保持可用空间。
- 状态变化：五个习惯依次点亮，最终形成“少读 → 少塞 → 分阶段 → 隔离输出”的路线。
- 口播互补：口播解释每个习惯的作用，画面表现它们如何减缓堆积。
- 画面文字：`玩具项目`、`@ 精准指文件`、`拆小任务`、`分阶段清理`、`子代理隔离输出`

### Scene 09｜三步亲眼验证压缩效果

- 画面结构：单个终端窗口分成三段状态：初始、读取后、压缩后。
- 视觉动作：第一次 `/context` 显示低占用；读取内容后文件和对话历史上升；执行指定 `/compact` 后历史占用下降，整体结构结论保留。
- 状态变化：用同一条占用条做前后对比，避免凭空增加第三套指标。
- 口播互补：口播带领实验，画面展示预期输出和变化。
- 画面文字：`/context`、`读取内容`、`/compact`、`对比前后占用`、`整体结构结论`

### Scene 10｜把注意力留给真正重要的任务

- 画面结构：混乱工作台收拢为目标、结论、下一步三张卡片，周围保留少量空白。
- 视觉动作：无关文件淡出，三张核心卡片对齐，容量条回到安全区。
- 状态变化：`塞满` 变为 `留出干活的空地`。
- 口播互补：口播总结原则，画面给出克制的视觉收束。
- 画面文字：`有限工作台`、`主动管理`、`留出干活的空地`

### Scene 11｜下一篇：权限配置

- 画面结构：左侧缩小为本篇的“上下文窗口”卡片，右侧出现下一集“权限配置”卡片。
- 视觉动作：镜头从“能记住多少”移动到“能动手做多少”，底部出现问题提示并停留。
- 状态变化：当前篇章完成标记，下一篇预告高亮。
- 口播互补：口播提出下一篇问题，画面只显示源文档已经给出的标题和问题。
- 画面文字：`20 · 权限配置`、`能记住多少`、`能动手做多少`、`git push？`

## 全片视觉类型与动画标准

### 视觉类型

- 工作台与分类占用：Concept Diagram + Process。
- 命令和输出：Terminal Demo。
- 两种清理方式：Comparison。
- 选择时机：Decision Diagram。
- 五个习惯：Step List + Process。
- 最小实验：Terminal Demo + State Change。

### 组件语言

- 深色背景、低饱和蓝紫强调色、绿色表示完成、红色表示拥挤或风险。
- 面板使用细边框和轻微阴影，避免多余图标与装饰。
- 终端、工作台和摘要卡片保持统一圆角、等宽字体和状态标签。
- 主标题控制在一至两行，字幕区与工作台内容分离。

### 动画顺序

1. 先出现任务或工作台。
2. 再进入文件、对话或命令输出。
3. 发生占用、压缩、清空或路由状态变化。
4. 最后高亮本幕结论。
