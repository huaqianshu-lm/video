# 上下文管理：别让它「失忆」也别烧爆 token

## 1. 分析范围

本分析只使用 `source.md` 中的第 19 篇文章内容，不读取或引用下一篇文章。文章末尾的“20 · 权限配置”仅作为系列下一集预告保留。

文章中的命令、示例输出和官方文档名称均视为本篇原始内容中的表达，不在本阶段追加外部验证或执行。

## 2. 核心命题

上下文窗口不是越满越好，而是 Claude 在当前会话中工作的有限“工作台”。真正占用空间的大头通常是它读过的文件、工具输出和对话历史；当工作台被无关内容塞满时，模型可能出现上下文衰退，表现为变慢、变笼统、前后矛盾或重复询问。

因此，上下文管理的核心不是等系统被动救场，而是主动管理信息：任务还要继续且结论要保留时使用 `/compact`，切换到无关任务或上下文污染严重时使用 `/clear` 或直接新开会话，并从源头减少不必要的读取和输出。

如果观众最后只记住一句话，应该是：

> **管理上下文，本质上是在有限工作台上，把 Claude 的注意力留给真正重要的任务。**

## 3. 知识骨架

### 3.1 问题起点：读得越多不等于越懂

- 典型误区：接手陌生中型项目时，要求 Claude 先读完整个仓库。
- 文章中的后果：读了二十几个文件后变慢、变迟钝，随后反问刚读过的 auth 模块在哪里。
- 关键反转：上下文窗口塞满后，更多材料可能反而降低当前任务质量。

### 3.2 上下文窗口装了什么

文章把窗口比作工作台，并列出六类内容：

1. 系统提示词：每次启动加载，用户不可见。
2. 全局与项目 `CLAUDE.md`：启动时加载，大小取决于文件。
3. 自动记忆：启动时加载，有上限。
4. 用户消息：发送一句进入一句，通常较小。
5. 已读取的文件：每读一个就追加，是文章强调的主要占用来源。
6. 命令输出和工具结果：日志或大文件可能快速膨胀。

### 3.3 塞满后的表现：上下文衰退

上下文衰退不是模型“突然学不会了”，而是注意力被摊薄，无关的调试内容开始干扰当前任务。文章给出的可观察症状是：

- 前后矛盾，忘记已经确认的方案。
- 回答越来越模糊、笼统，细节减少。
- 反复询问已经回答过的信息。
- 同一个问题被纠正两遍以上仍在原地打转。

### 3.4 两种清理动作

`/compact`：把当前对话历史压缩为精简摘要，保留结论，在同一任务上继续；可以附加指令指定保留重点。

`/clear`：清空本次对话历史，重新开始；文章强调它不会删除 `CLAUDE.md` 和自动记忆。

直接退出后重新运行 `claude`：同样获得干净会话，适合希望连本次对话痕迹都不保留的场景。

核心判断：任务没完成且前文仍有用，用 `/compact`；切换到无关工作或污染太重，用 `/clear`；需要彻底干净的工作台时，直接新开会话。

### 3.5 两个监控命令

- `/context`：观察工作台被什么占用，查看系统提示、`CLAUDE.md`、MCP、对话历史等分类的实时占用和优化建议。
- `/usage`：查看本次会话的 token 使用、时长和本地估算成本；美元数只是本地估算，文章提醒权威账单以 Claude Console 为准。

### 3.6 自动压缩的边界

auto-compact 是接近窗口上限时自动总结对话历史、腾出空间继续工作的保命机制。但文章不建议把它当作主要策略，原因是：触发时机不可控，可能打断关键步骤；它没有收到用户的保留指令，可能丢掉用户认为重要的内容。

更稳妥的做法是，在占用偏高时主动 `/compact` 并说明要保留什么；也可以把压缩偏好写进 `CLAUDE.md`，让手动和自动压缩都优先保留测试结果、代码变更或已确认的方案。

### 3.7 五个源头节省 token 的习惯

1. 学习和试验使用只有三五个文件的玩具项目。
2. 用 `@` 精准指定文件，避免模糊请求触发大范围扫描。
3. 不要一次塞入多个不相关需求，把任务拆成多次小提问。
4. 长任务分阶段，阶段结束后 `/compact`；切换无关部分时 `/clear`。
5. 把测试、长日志、查文档等冗长操作交给子代理，只把摘要带回主对话。

### 3.8 可操作练习

文章提供一个最小验证流程：启动 Claude 后先运行 `/context` 记录初始占用；让它读取一些文件并再次运行 `/context`，观察对话历史和文件占用增长；随后运行 `/compact 保留这个项目的整体结构结论，丢掉逐个文件的原始内容`，再运行 `/context` 对比压缩前后的占用。

## 4. 认知关系

### 因果关系

读取过多文件与工具输出增加上下文占用；占用过高使注意力分散；注意力分散带来上下文衰退症状；主动压缩、清空或减少输入可以恢复工作台可用空间。

### 对比关系

| 维度 | `/compact` | `/clear` | 直接新开会话 |
|---|---|---|---|
| 历史处理 | 总结后保留 | 清空本次历史 | 从新会话开始 |
| 是否继续同一任务 | 是 | 通常不继续原对话 | 适合重新组织任务 |
| 规范与自动记忆 | 保留 | 保留 | 启动时重新加载 |
| 适用场景 | 任务未完成、结论仍有用 | 切换无关工作、污染严重 | 需要绝对干净的工作台 |

### 流程关系

```text
/context 查看底子
        ↓
读取内容并观察占用增长
        ↓
/compact 保留结论、丢弃原始材料
        ↓
/context 对比结果
```

### 角色关系

```text
人：决定任务目标、保留重点、判断何时清理
Claude：读取、分析、压缩、继续执行
```
