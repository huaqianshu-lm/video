## 1. 内容定位

### 1.1 原文解决的问题

这篇文章解决的不是“如何调用 API”，而是 Claude Code 连接模型时的身份选择、优先级判断和切换验证问题：

> **登录状态、实际生效的身份和实际产生费用的凭证，可能不是同一件事。**

文章通过一个“已经登录 Max 订阅，却因为环境中的 `ANTHROPIC_API_KEY` 持续产生 API 费用”的案例，建立读者对身份优先级的警觉。

### 1.2 内容类型

- 面向初学者的配置认知教程。
- 订阅登录与 API key 的选择指南。
- 环境变量、凭证优先级和模型选择的操作教程。
- 通过 `/status`、`/model` 和环境变量检查完成自查闭环。

### 1.3 目标读者

主要读者是：

- 正在使用或准备使用 Claude Code 的个人开发者。
- 已登录 Claude.ai，但不确定当前到底使用哪种身份的人。
- 曾在 `.zshrc`、系统环境变量或脚本中配置过 API key 的用户。
- 需要在订阅和 API key 之间切换的用户。

次要读者是：

- 需要在脚本、CI 或团队场景中使用 API key 的用户。
- 在 macOS、Linux、Windows、WSL、SSH 或容器中排查登录问题的用户。

本条视频不以企业云厂商接入、第三方模型接入或 `/effort` 深入配置为主体；它们只作为优先级背景或下一篇预告出现。

## 2. 核心命题

### 2.1 主命题

> **Claude Code 最终使用哪个身份，不由“我是否登录过”决定，而由当前存在的凭证及其优先级决定；因此必须用 `/status` 验证实际生效身份。**

### 2.2 观众必须带走的三句话

1. 订阅登录适合个人日常交互式开发，API key 适合脚本、CI 或团队按量结算。
2. 环境中更高优先级的凭证会覆盖更低优先级的凭证，订阅登录位于这套优先级的底层。
3. 不确定当前用了谁，就用 `/status` 看身份和模型；想切回订阅，清掉覆盖它的 API key 后再次确认。

### 2.3 视频成功标准

观众看完后能够：

- 根据使用场景判断订阅登录或 API key 的方向。
- 解释“登录了订阅却产生 API 费用”的原因。
- 说出身份验证优先级栈的基本工作方式。
- 使用 `/status` 查看当前身份和模型。
- 使用 `/model` 查看或切换模型。
- 通过 `unset ANTHROPIC_API_KEY` 后再次检查，验证是否切回订阅。

## 3. 必须保留的知识骨架

### A. 开场案例：登录不等于用对身份

这是全片的叙事钩子，必须保留：

```text
曾经在 .zshrc 中 export ANTHROPIC_API_KEY
        ↓
后来通过 /login 登录 Max 订阅
        ↓
以为自己在用订阅额度
        ↓
Console 账单仍持续产生 API 费用
        ↓
原因：API key 优先级压过订阅
```

### B. 两条主流路径的选择

| 路径 | 核心定位 | 适用场景 | 主要配置方式 |
| --- | --- | --- | --- |
| 订阅登录 | 月卡式的个人使用 | 个人日常交互式开发 | `claude` 后浏览器登录 |
| API key | 按用量结算的凭证 | 脚本、CI、团队按量结算 | Console 创建 key，配置环境变量 |

需要保留计费、额度、是否需要浏览器、凭证来源等差异，但不需要在视频中逐字展示全部表格内容。

### C. 订阅登录的操作闭环

```text
运行 claude
    ↓
浏览器登录 Claude.ai
    ↓
回到终端
    ↓
必要时用 c 复制登录链接或粘贴登录代码
    ↓
需要换账号时使用 /logout
```

WSL2、SSH、容器中的浏览器回调问题需要作为远程环境分支保留，但不应抢占主线。

### D. API key 的操作闭环

```text
Claude Console 创建 key
        ↓
配置 ANTHROPIC_API_KEY
        ↓
启动 claude
        ↓
批准 key
        ↓
开始使用 API 额度
```

必须保留密钥安全边界：不要写进代码、提交 Git 或贴进可分享文件。

### E. 身份验证优先级栈

源文档给出从高到低的 6 层：

1. 云提供商：Bedrock / Vertex / Foundry。
2. `ANTHROPIC_AUTH_TOKEN`。
3. `ANTHROPIC_API_KEY`。
4. `apiKeyHelper`。
5. `CLAUDE_CODE_OAUTH_TOKEN`。
6. `/login` 的订阅凭证。

工作方式是：从栈顶向下检查，跳过空层，使用第一个有值的层。因此订阅位于最低层，任何更高层有值时都可能覆盖订阅。

### F. 身份切换与边界

切回订阅的源文档操作是：

```bash
unset ANTHROPIC_API_KEY
```

随后通过 `/status` 复查。交互模式中也可以通过 `/config` 的“使用自定义 API 密钥”开关关闭。

需要保留的边界：

- `ANTHROPIC_API_KEY` 和 `ANTHROPIC_AUTH_TOKEN` 是不同凭证。
- CLI、Desktop 和 Web 的身份读取范围不同。
- Claude Code on the Web 使用订阅凭证。

### G. 模型选择与配置优先级

模型部分的核心不是记版本号，而是理解“别名 + 选择层级”：

```text
/model
    > claude --model
    > ANTHROPIC_MODEL
    > settings.json
```

主要别名：`default`、`opus`、`sonnet`、`haiku`、`best`、`opusplan` 以及 1m 变体。视频重点放在“按任务选择模型”和“设置方式存在优先级”，具体版本号按源文档保留但不作为永久视觉标题。

### H. 自查验收闭环

源文档最后提供一个可执行闭环：

```text
claude
  ↓
/status：看账户、身份、模型
  ↓
/model：查看或切换模型
  ↓
echo $ANTHROPIC_API_KEY：检查环境变量
  ↓
必要时 unset ANTHROPIC_API_KEY
  ↓
重新 /status：确认身份已改变
```

这是视频结尾的实际行动目标，比单纯总结概念更重要。

## 4. 认知关系

### 4.1 选择关系

```text
个人日常交互式开发
        → 订阅登录

脚本 / CI / 团队按量结算
        → API key
```

### 4.2 覆盖关系

```text
高优先级凭证有值
        → 覆盖低优先级凭证
        → 订阅登录可能不生效
        → 实际账单与主观预期不一致
```

### 4.3 验证关系

```text
主观判断“我已经登录订阅”
        ↓ 不足
/status 查看实际 Auth
        ↓
echo 环境变量找覆盖源
        ↓
unset 清理覆盖源
        ↓
/status 二次确认
```

### 4.4 配置关系

身份配置和模型配置是两条不同的链路，不能混成一条：

```text
身份链路：凭证来源 → 优先级 → 实际 Auth → 计费归属
模型链路：模型别名 → 配置入口优先级 → 实际 Model
```
