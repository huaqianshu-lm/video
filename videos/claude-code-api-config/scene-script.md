# Claude Code API 配置 · Scene Script

> 目标：把 `video-narrative.md` 拆成可制作的视觉事件。本阶段只定义 Scene 的认知任务、口播方向、视觉方向和 Video Value，不编写最终逐句口播、字幕时间轴或 Remotion 配置。

> 本条视频暂拆为 12 个 Scene。Scene 数量按认知变化和状态变化决定，不按原文章节数量机械对应，也不设置固定总时长。

## Scene 01｜登录了，为什么还会产生 API 费用？

### 目的

用源文档中的开场案例制造冲突：用户已经登录 Max 订阅，却发现 Console 账单持续产生 API 费用。

### 认知任务

让观众意识到“我登录过订阅”不能证明“当前正在使用订阅”。

### 叙事作用

开场钩子，提出整条视频要解决的问题。

### 口播方向

你明明已经通过 `/login` 登录了 Max，为什么 API 账单还在持续增加？问题可能不在登录，而在环境里还留着一个优先级更高的 API key。登录进去，不等于用对了身份。

### 视觉方向

深色终端左侧显示：

```text
/login
Claude subscription: connected
```

右侧账单卡片继续增加：

```text
API usage       $...
```

中间出现冲突提示：

```text
登录状态 ≠ 实际生效身份
```

### Scene Type

`OpeningScene`

### 屏幕重点

```text
登进去了，不等于用对了身份
```

### Video Value

把抽象的配置问题转成一个可观察的账单冲突，建立观看动机。

### 信息分工

- **声音**：讲述案例并提出疑问。
- **画面**：同时展示订阅连接和 API 费用。
- **字幕**：强调“登录状态 ≠ 实际生效身份”。

## Scene 02｜先判断：订阅还是 API key？

### 目的

给观众建立两条身份路径的选择框架。

### 认知任务

让观众先根据使用场景选择路径，而不是先复制命令。

### 叙事作用

从开场问题转入解决问题的第一步。

### 口播方向

个人日常交互式开发，优先用订阅登录；要嵌进脚本、CI，或者按团队用量结算，才考虑 API key。它们不是同一套账，也不是同一种使用方式。

### 视觉方向

两张路径卡片：

```text
订阅登录
个人日常交互式开发
月度订阅
浏览器授权
```

```text
API key
脚本 / CI / 团队按量
按 token 计费
环境变量
```

底部用月卡和门票的抽象图形做轻量类比，不使用外部素材。

### Scene Type

`ComparisonScene`

### 屏幕重点

```text
个人日常 → 订阅
自动化按量 → API key
```

### Video Value

把多维对照表转成观众可以立即使用的选择规则。

### 信息分工

- **声音**：解释适用场景和计费差异。
- **画面**：呈现两条路径的选择关系。
- **字幕**：保留“个人日常”和“脚本 / CI”。

## Scene 03｜订阅登录：`claude` 到浏览器授权

### 目的

展示个人订阅用户的最短主路径。

### 认知任务

让观众知道订阅登录主要是启动 CLI、完成浏览器授权，再回到终端。

### 叙事作用

完成第一条身份路径的操作说明。

### 口播方向

如果你是个人订阅用户，装好 Claude Code 后直接运行 `claude`。首次启动会打开浏览器，登录 Claude.ai，完成授权后回到终端。

### 视觉方向

模拟终端和浏览器之间的流程：

```text
终端：claude
        ↓
浏览器：Claude.ai 登录
        ↓
终端：Authenticated
```

右下角显示小型分支提示：浏览器未自动打开时复制登录链接，远程环境粘贴登录代码，换账号使用 `/logout`。

### Scene Type

`TerminalScene`

### 屏幕重点

```text
claude → 浏览器登录 → 回到终端
```

### Video Value

展示跨终端、浏览器和授权状态的过程，比单纯显示一条命令更容易建立操作直觉。

### 信息分工

- **声音**：解释主路径和远程环境例外。
- **画面**：展示授权状态如何从终端转到浏览器再返回。
- **字幕**：强调“完成授权后回到终端”。

## Scene 04｜API key：Console、环境变量、批准

### 目的

展示 API key 的最小配置闭环，同时建立密钥安全意识。

### 认知任务

让观众理解 API key 不是“登录订阅的另一种写法”，而是从 Console 获取、通过环境变量提供、启动时批准的一条独立路径。

### 叙事作用

完成第二条身份路径的操作说明，为后面的优先级冲突做准备。

### 口播方向

需要 API key 时，先在 Claude Console 创建密钥，再配置 `ANTHROPIC_API_KEY`，启动 Claude Code 后批准一次。密钥就是钱，不要写进代码、提交 Git 或贴进可分享文件。

### 视觉方向

三步流程卡片：

```text
01 Console
Create API key

02 Environment
ANTHROPIC_API_KEY=sk-ant-...

03 Claude Code
Approve key
```

API key 使用模糊化占位符，出现“不要提交到 Git”的安全警示。

### Scene Type

`StepListScene`

### 屏幕重点

```text
Console → 环境变量 → 批准
```

### Video Value

展示凭证从创建到生效的完整链路，并把安全边界放进实际流程。

### 信息分工

- **声音**：解释三步和安全风险。
- **画面**：演示配置路径和批准状态。
- **字幕**：保留“不要提交真实 key”。

## Scene 05｜两条身份可以同时存在

### 目的

把开场案例与配置行为连接起来：订阅凭证和 API key 可能同时存在。

### 认知任务

让观众理解问题不是“登录失败”，而是“多个凭证同时存在时谁会生效”。

### 叙事作用

从操作路径转入机制解释。

### 口播方向

真正麻烦的地方在于，这两条路径可以同时留下凭证。你可能已经登录了订阅，但环境变量里仍然有 API key。接下来决定身份的，就不是你的主观选择，而是优先级。

### 视觉方向

展示两条同时亮起的状态：

```text
OAuth subscription   PRESENT
ANTHROPIC_API_KEY    PRESENT
```

画面中央出现“谁先被读取？”的等待状态，随后切向优先级栈。

### Scene Type

`ConceptScene`

### 屏幕重点

```text
凭证可以同时存在
生效顺序由优先级决定
```

### Video Value

把“环境变量覆盖订阅”从一个偶然坑提升为可解释的系统关系。

### 信息分工

- **声音**：说明冲突的来源。
- **画面**：同时显示 OAuth 和 API key。
- **字幕**：突出“优先级决定生效身份”。

## Scene 06｜六层身份验证优先级栈

### 目的

解释源文档中的六层身份验证优先级。

### 认知任务

让观众理解 Claude Code 从栈顶往下找第一个有值的层。

### 叙事作用

整条视频的机制中心，解释开场费用异常。

### 口播方向

源文档给出的优先级从高到低共有六层：云提供商、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`、`apiKeyHelper`、`CLAUDE_CODE_OAUTH_TOKEN`，最后才是 `/login` 的订阅凭证。Claude Code 从上往下扫描，跳过空层，停在第一个有值的层。

### 视觉方向

重新制作一个垂直优先级栈，不直接使用源文档图片：

```text
┌────────────────────────┐  1 云提供商
├────────────────────────┤  2 ANTHROPIC_AUTH_TOKEN
├────────────────────────┤  3 ANTHROPIC_API_KEY
├────────────────────────┤  4 apiKeyHelper
├────────────────────────┤  5 CLAUDE_CODE_OAUTH_TOKEN
└────────────────────────┘  6 /login 订阅
```

一个扫描指针从顶端向下移动，遇到第一个“PRESENT”就停止；空层显示 `EMPTY`。

### Scene Type

`StepListScene`

### 屏幕重点

```text
从上往下找第一个有值的层
```

### Video Value

把源文档中的表格转成有顺序、有动作、有命中结果的机制演示。

### 信息分工

- **声音**：解释六层和扫描规则。
- **画面**：展示栈、空层、指针和命中层。
- **字幕**：强调“高优先级覆盖低优先级”。

## Scene 07｜为什么 API key 会盖过订阅？

### 目的

回到开场案例，具体演示 `ANTHROPIC_API_KEY` 如何覆盖订阅。

### 认知任务

让观众能够完整解释“Max 已登录但 API 在扣费”的原因。

### 叙事作用

完成机制与案例的闭环。

### 口播方向

开场那个案例里，上面的五层大多为空，但第三层 `ANTHROPIC_API_KEY` 有值。于是扫描在这里就停下来了，底部的订阅虽然存在，却不会成为实际使用的身份。

### 视觉方向

优先级栈中：

```text
ANTHROPIC_API_KEY       PRESENT  ← 命中
/login subscription     PRESENT  ← 被跳过
```

扫描指针停在 API key，底部订阅卡片变为“存在但未命中”；右侧账单标签从 `Subscription` 变成 `API usage`。

### Scene Type

`ConceptScene`

### 屏幕重点

```text
API key 有值 → 订阅被覆盖
```

### Video Value

让观众看到“覆盖”是一个实际状态，而不是一句抽象规则。

### 信息分工

- **声音**：解释命中第三层后的结果。
- **画面**：演示指针停在 API key，订阅被跳过。
- **字幕**：保留“订阅存在，但没有命中”。

## Scene 08｜切回订阅：先清理，再复查

### 目的

提供从 API key 切回订阅的可执行修复路径。

### 认知任务

让观众理解 `unset` 的作用不是“重新登录”，而是移除更高优先级覆盖源。

### 叙事作用

从解释问题进入解决问题。

### 口播方向

想切回订阅，就先清掉覆盖订阅的环境变量：`unset ANTHROPIC_API_KEY`。然后重新进入 Claude Code，用 `/status` 查看实际身份。交互模式里，也可以在 `/config` 关闭使用自定义 API 密钥。

### 视觉方向

终端前后对比：

```bash
unset ANTHROPIC_API_KEY
```

命令执行前后，优先级栈中的 API key 从 `PRESENT` 变成 `EMPTY`，扫描指针继续向下，命中 `/login` 订阅。

### Scene Type

`TerminalScene`

### 屏幕重点

```text
清除覆盖源 → /status 复查
```

### Video Value

把“调优先级”落实为可操作的状态变化和验证步骤。

### 信息分工

- **声音**：解释清理与复查的因果关系。
- **画面**：展示 API key 消失、订阅命中的前后变化。
- **字幕**：显示 `unset ANTHROPIC_API_KEY` 和 `/status`。

## Scene 09｜CLI、Desktop、Web：入口边界不同

### 目的

防止观众把 CLI 中的环境变量行为错误地迁移到其他入口。

### 认知任务

让观众知道身份配置不是所有入口共享的一套读取规则。

### 叙事作用

补充高频边界，避免验证结果与预期不一致。

### 口播方向

还要注意入口边界。源文档区分了 CLI、Desktop 和 Web：终端 CLI 会读取相关环境变量；Desktop 和远程会话只认 OAuth；Web 端使用订阅凭证。不要把一个入口的配置方式直接套到另一个入口。

### 视觉方向

三列入口卡片：

```text
CLI       环境变量 + OAuth
Desktop   OAuth
Web       订阅凭证
```

当 API key 被拖向 Desktop 或 Web 时，出现“不是同一读取范围”的边界提示。

### Scene Type

`ComparisonScene`

### 屏幕重点

```text
不同入口，不同凭证读取范围
```

### Video Value

把容易被忽略的产品入口差异做成清晰边界，减少“我明明配置了却没生效”的误判。

### 信息分工

- **声音**：解释入口差异。
- **画面**：对比三种入口的凭证来源。
- **字幕**：只保留“不要混用入口规则”。

## Scene 10｜身份确认后，再选择模型

### 目的

把模型选择与身份配置分开，避免观众把“用谁的额度”和“用哪个模型”混为一谈。

### 认知任务

让观众理解模型别名代表不同任务取向，并知道常用选择。

### 叙事作用

从身份链路切换到模型链路。

### 口播方向

身份确认之后，还有一个独立问题：让它用哪个模型。可以把 Opus 看成处理复杂问题的资深工程师，Sonnet 是日常主力，Haiku 适合简单快速的任务。常用别名包括 `default`、`opus`、`sonnet`、`haiku`、`best` 和 `opusplan`。

### 视觉方向

三张任务卡片：

```text
复杂推理       opus
日常编程       sonnet
简单快速任务   haiku
```

下方出现别名条，`default`、`best` 和 `opusplan` 作为辅助标签，不展示过多版本号。

### Scene Type

`ComparisonScene`

### 屏幕重点

```text
身份决定“用谁的额度”
模型决定“让谁来干活”
```

### Video Value

用任务类比建立模型选择直觉，清楚分开身份和模型两个概念。

### 信息分工

- **声音**：解释模型定位和别名。
- **画面**：展示任务与模型的匹配。
- **字幕**：强调身份链路与模型链路不同。

## Scene 11｜模型配置也有自己的优先级

### 目的

展示模型配置入口的优先级，补齐配置认知。

### 认知任务

让观众知道临时会话选择可以覆盖启动参数、环境变量和 settings 默认值。

### 叙事作用

完成从身份配置到模型配置的第二条优先级链路。

### 口播方向

模型不是只在一个地方设置。源文档给出的优先级是：会话内的 `/model` 最高，其次是 `claude --model`、环境变量 `ANTHROPIC_MODEL`，最后是 settings.json。身份优先级和模型优先级要分别理解。

### 视觉方向

四层横向配置链：

```text
/model
   ↓ 覆盖
claude --model
   ↓ 覆盖
ANTHROPIC_MODEL
   ↓ 覆盖
settings.json
```

模拟输入 `/model sonnet` 后，最终状态卡更新为 `Model: sonnet`。

### Scene Type

`StepListScene`

### 屏幕重点

```text
/model > --model > 环境变量 > settings
```

### Video Value

把配置优先级做成可观察的覆盖关系，避免模型设置与身份设置相互混淆。

### 信息分工

- **声音**：解释四种设置方式的优先级。
- **画面**：演示高层设置覆盖低层默认值。
- **字幕**：展示优先级链。

## Scene 12｜用 `/status` 验收：不要凭感觉判断

### 目的

收束整条视频，给出可执行的身份和模型自查闭环。

### 认知任务

让观众能够明确回答当前 Auth、当前 Model，并知道如何在异常时清理和复查。

### 叙事作用

行动收束、验收和下一篇预告。

### 口播方向

最后实际检查一次：进入 `claude`，用 `/status` 查看当前账户、身份和模型；用 `/model` 查看或切换模型；退出后检查 `ANTHROPIC_API_KEY`，必要时 `unset`，再回到 Claude Code 用 `/status` 复查。你能说清楚当前用的是订阅还是 API key、运行的是哪个模型，这篇的核心目标就完成了。

### 视觉方向

终端完成连续操作：

```text
claude
/status
/model
echo $ANTHROPIC_API_KEY
unset ANTHROPIC_API_KEY
/status
```

最终验收卡片显示：

```text
Auth: Claude subscription (OAuth)
Model: sonnet
Status: verified
```

结尾出现三个总结点：订阅在底层、`/status` 看事实、模型按任务选。最后用一条简短的 `ANTHROPIC_BASE_URL` 线索预告下一篇第三方 / 国产模型内容。

### Scene Type

`SummaryScene`

### 屏幕重点

```text
不确定在用谁：/status
```

### Video Value

把知识转成一次可重复执行的检查流程，形成视频区别于文章的行动价值。

### 信息分工

- **声音**：给出验收标准和总结。
- **画面**：展示完整终端闭环和最终状态。
- **字幕**：保留三个最重要结论。
