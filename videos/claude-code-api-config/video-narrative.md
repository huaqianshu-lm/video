# Claude Code API 配置 · Video Narrative

> 目标：让观众从“我已经登录了，应该没问题”，走到“我知道当前实际使用哪个身份、为什么会被覆盖，以及如何验证和切换”。
>
> 本文基于 `content-analysis.md` 编写，只确定视频叙事和信息取舍，不编写逐句口播、字幕时间轴或 Remotion 配置。

## 1. 视频叙事目标

这条视频不是把配置命令逐条念一遍，而是解决一个高风险误区：

```text
我登录了订阅
        ↓
我以为正在使用订阅
        ↓
环境中的高优先级凭证可能已经覆盖订阅
        ↓
我需要用 /status 查看事实
        ↓
我能清除覆盖源并完成二次验证
```

观众最后应该形成的判断是：

> **不要根据“我登录过什么”判断当前身份，要根据优先级和 `/status` 的结果判断。**

## 2. 叙事主线

建议采用九个叙事段落：

| 段落 | 观众的问题 | 叙事作用 | 核心表达 |
| --- | --- | --- | --- |
| 01 开场案例 | 我明明登录了订阅，为什么还会产生 API 费用？ | 制造冲突 | 登录不等于用对身份 |
| 02 两条路径 | 订阅和 API key 到底怎么选？ | 建立选择框架 | 个人日常选订阅，自动化按量选 key |
| 03 订阅登录 | 订阅应该怎么进入？ | 给出主路径 | `claude` → 浏览器登录 → 回到终端 |
| 04 API key | API key 在什么时候才需要？ | 给出另一条路径 | Console → 环境变量 → 批准 |
| 05 优先级栈 | 为什么两种身份会冲突？ | 解释根因 | 从高到低找第一个有值的凭证 |
| 06 切换身份 | 怎么切回订阅？ | 形成可执行修复 | 清除覆盖源，再用 `/status` 验证 |
| 07 身份边界 | 所有 Claude Code 入口都一样吗？ | 防止错误迁移 | CLI、Desktop、Web 的读取范围不同 |
| 08 模型选择 | 身份确认后，模型怎么选？ | 补齐配置闭环 | 模型别名和四层选择优先级 |
| 09 实际验收 | 我怎样确认自己真的配对了？ | 行动收束 | `/status`、`/model`、环境变量检查和复查 |

## 3. 观众状态变化

```text
状态 1：把“登录过订阅”当成“正在用订阅”
        ↓ 开场案例打破误判
状态 2：知道订阅和 API key 是两条不同路径
        ↓ 对比和操作路径
状态 3：知道凭证存在优先级覆盖
        ↓ 优先级栈建立机制
状态 4：能解释 API 费用从哪里来
        ↓ unset 和 /status
状态 5：能看懂实际身份和模型
        ↓ 终端验收闭环
状态 6：以后遇到配置问题先查事实，不盲目重装
```

## 4. 各段叙事设计

### 01 开场：登录了，为什么账单还在增加？

从源文档中的真实经历切入：`.zshrc` 里曾经配置过 `ANTHROPIC_API_KEY`，之后通过 `/login` 登录 Max，但 Console 账单仍持续产生 API 费用。

开场只提出冲突，不立即解释全部六层优先级：

> **你登录了订阅，不代表 Claude Code 当前真的在用订阅。**

画面先展示“订阅已登录”和“API 费用增加”两个互相冲突的状态，最后给出本条视频的承诺：选对路径、看懂优先级、用命令确认实际身份。

### 02 先选路径：月卡还是按次门票？

用源文档的健身房类比快速建立选择框架：

- 个人日常交互式开发：订阅登录。
- 脚本、CI、团队按量结算：API key。

这里不逐字朗读完整对照表，只展示最影响决策的维度：连接方式、计费方式、适用场景和是否需要浏览器。订阅和 API key 的选择先于具体命令。

### 03 订阅登录：最短的主路径

展示：

```text
claude
  ↓
浏览器登录 Claude.ai
  ↓
回到终端
```

随后用一个小分支说明浏览器不自动打开时的 `c`、登录代码和 `/logout`。WSL2、SSH 和容器只作为“远程环境可能需要粘贴代码”的旁支，不把平台差异扩展成新的主线。

### 04 API key：自动化场景才走的路径

按源文档的三步讲清：Console 创建 key、配置 `ANTHROPIC_API_KEY`、启动后批准。

密钥安全提示必须保留，但不展示真实密钥。画面使用 `sk-ant-你的密钥` 这样的占位符，并明确不能写入代码或提交 Git。

### 05 优先级栈：真正决定身份的是谁在上面

这是整条视频的解释中心。先给出规则：Claude Code 从高到低检查凭证，跳过空层，使用第一个有值的层。

六层按源文档顺序完整出现，但视觉上分为三组：云提供商、环境或辅助凭证、订阅 OAuth。动画重点是 `ANTHROPIC_API_KEY` 从中间一层压住底部订阅，而不是让观众死记六行文字。

回到开场案例：Max 登录仍然存在，但 API key 作为更高层有值，因此实际费用落到了 API。

### 06 切回订阅：清除覆盖源，再验证

把解决方案做成状态变化：

```text
Auth: API key
        ↓ unset ANTHROPIC_API_KEY
Auth: Claude subscription (OAuth)
```

关键不是背住 `unset`，而是理解“先动覆盖源，再复查实际状态”。`/config` 关闭自定义 API 密钥作为补充路径出现。

### 07 身份边界：不要把入口混为一谈

用三列短卡片说明：

- CLI：读取终端环境变量。
- Desktop：源文档所述只认 OAuth 登录。
- Web：源文档所述使用订阅凭证。

这段避免观众把 CLI 的环境变量配置复制到 Desktop 或 Web 后，误以为配置没有生效。

### 08 模型选择：确认身份后再看“用哪个模型”

先用 Opus、Sonnet、Haiku 的任务类比建立选择直觉，再展示常用别名。重点是模型配置存在独立优先级：

```text
/model
  > claude --model
  > ANTHROPIC_MODEL
  > settings.json
```

版本号只作为源文档中的示例信息出现，不让易变化的版本名成为本段的核心结论。

### 09 实际验收：用状态而不是感觉做结论

完整展示源文档的最小检查闭环：

```text
claude
  → /status
  → /model
  → echo $ANTHROPIC_API_KEY
  → 必要时 unset
  → 再次 /status
```

验收结果是观众能够明确回答两件事：当前 Auth 是订阅还是 API key，当前 Model 是什么。如果环境变量为空，也不能直接断言一定是订阅，还要结合 `/status` 判断是否存在其他更高优先级凭证。

## 5. 信息取舍

### 主线必须出现

- 登录不等于实际生效身份。
- 订阅与 API key 的适用场景差异。
- 订阅登录和 API key 的最小操作路径。
- 六层身份验证优先级和“第一个有值”的规则。
- `unset ANTHROPIC_API_KEY` 与 `/status` 的复查关系。
- 模型选择与身份配置是两条不同的链路。
- 最终自查闭环和安全提示。

### 适合压缩为辅助信息

- 不同平台的凭证存储位置。
- `ANTHROPIC_AUTH_TOKEN` 与 `ANTHROPIC_API_KEY` 的请求头区别。
- `apiKeyHelper` 的动态凭证场景。
- `/config` 的补充入口。
- 1m 模型变体和 `/effort` 说明。
- 第三方 / 国产模型预告。

### 不进入主线

- 外部事实核验。
- 真实密钥、账户邮箱或真实账单信息。
- 下一篇文章的完整配置方法。
- 把原图直接作为视频素材。

## 6. 叙事与视觉原则

- 声音解释“为什么”，画面展示“谁覆盖谁、状态如何变化、命令怎样验证”。
- 每个段落只解决一个观众问题。
- 命令只在推动状态变化时出现，不把视频做成命令清单。
- 优先使用终端、配置卡片、优先级栈、状态前后对比和流程箭头。
- 身份验证栈采用项目内重新制作的动画，不依赖源文档图片。
- 具体模型版本和外部时效信息不作为固定视觉锚点。

## 7. 叙事验收标准

完成 Scene Script 后，应该能回答：

1. 开场是否明确提出“登录不等于用对身份”的冲突？
2. 观众是否先知道什么时候选订阅、什么时候选 API key，再进入配置命令？
3. 六层优先级是否解释了开场案例，而不是孤立的表格？
4. `unset` 是否与 `/status` 的前后验证形成闭环？
5. 模型配置是否和身份配置分开？
6. 每个 Scene 是否都能说明自己的 Video Value？
