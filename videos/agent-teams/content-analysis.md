# Agent teams 智能体团队：多会话协作 · Content Analysis

## 1. 核心命题

Agent teams 把多个完整、独立的 Claude Code 会话组织成一个可并行协作的团队：用户作为 leader 负责分派和验收，队友拥有独立上下文，可以直接通信；共享任务列表负责认领、依赖和状态，mailbox 负责消息传递。

视频要让观众建立一个可操作的判断模型：

```text
单会话：上下文有限 + 工作串行
          ↓
Agent teams：leader + 独立队友 + 共享任务 + mailbox
          ↓
并行探索、直接沟通、统一验收
          ↓
只有在任务真正可并行时才值得拆
```

## 2. 观众需要完成的认知变化

1. 从“屏幕上开着几个 Claude”转为理解它们是由 leader 统一协调的多个会话。
2. 从“多几个会话就更快”转为看见 Agent teams 解决的是上下文有限和串行执行两种天花板。
3. 分清 subagent 与 Agent teams：前者是主对话委派的独立助手，后者是可互相通信、用户也能直接管理的对等队友。
4. 理解 leader、teammates、task list、mailbox 四个关键件如何共同运转。
5. 知道 agent view（`claude agents`）如何集中观察多个后台会话，以及状态颜色和 Peek／Attach 的关系。
6. 知道如何用自然语言组队、用 `Shift+Down` 切队友、要求计划批准，以及为什么清理必须由 leader 完成。
7. 能根据并行收益、依赖关系、文件冲突和协调成本判断该不该组队。
8. 能复述从启用实验性功能到三人团队跑通、再由 leader 收摊的最小闭环。

## 3. 必须保留的信息

### A. 单会话的两堵墙

- 一个会话只有一个上下文窗口，同时处理前端、后端、测试可能装不下。
- 单会话本质上串行，互不依赖的工作也只能排队执行。
- Agent teams 的价值是把用户从亲自下场的工人变成分派和验收的工头。

### B. Agent teams 与 subagent 的边界

| 维度 | Subagent | Agent teams |
| --- | --- | --- |
| 上下文 | 独立上下文，结果回传调用者 | 每个队友独立上下文 |
| 协调 | 主代理统管 | leader 协调，也可共享任务自我协调 |
| 队友通信 | 不互相通信 | 队友可直接互发消息 |
| 用户管理 | 不能直接管理子代理 | 可直接与任意队友对话 |
| 成本与适用 | 较低，适合只要结果的专注任务 | 较高，适合需要讨论、质疑和并行的复杂协作 |

### C. 四个关键件和运转规则

- Team lead：创建团队、生成队友、协调分工；leader 创建后不能更换。
- Teammates：独立 Claude Code 实例，生成时不会继承 leader 的对话历史，但会加载常规项目上下文。
- Task list：共享工作清单，有待处理、进行中、已完成状态；支持依赖、自动解锁和文件锁防止同时认领。
- Mailbox：代理之间的消息系统，队友消息会送达 leader，也支持队友直接沟通。

### D. 总控屏和团队内控制

- `claude agents` 是 agent view 的总控屏，一行一个后台会话。
- 工作中、需要输入、已完成、失败分别用动态、黄色、绿色、红色状态提示。
- `Space` Peek 查看最近输出，Peek 中可回复；`Enter` 或 `→` Attach 进入会话，空输入框按 `←` 返回。
- 后台会话由 supervisor 托管，不依赖某个终端持续打开。
- 在 in-process 团队里用 `Shift+Down` 循环队友；`Enter` 查看、`Escape` 打断、`Ctrl+T` 切任务列表。
- 可以要求队友先进入计划模式并由 leader 批准；队友模型不会自动跟随 leader 的 `/model`，需要提示或配置指定。
- 团队完成后先停止活跃队友，再由 leader 执行清理。

### E. 何时值得拆

- 适合：研究与审查、互不依赖的新模块、竞争假设调试、前端／后端／测试等跨层并行改动。
- 不适合：有严格先后依赖、多个队友改同一文件、随手小任务。
- 每个队友都是完整 Claude 实例，会产生额外 token 成本；通信和协调也有开销。
- 新手建议先从不写代码的研究／审查开始，团队规模从 3—5 个起步。

### F. 最小实操闭环

- 前提是 Claude Code v2.1.32 或更高；agent view 另有 v2.1.139 或更高的版本提示，实际使用前应检查版本。
- 在 `~/.claude/settings.json` 的 `env` 中启用 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`。
- 进入 `team-demo` 并启动 `claude`，用自然语言提出三人、三角度的调研团队。
- 确认创建后观察队友，用 `Shift+Down` 直接补充某个队友的任务。
- 调研结束回到 leader，停止队友并清理团队。

## 4. 因果、对比与流程关系

### 核心因果

```text
上下文有限 + 只能串行
        ↓
拆出多个独立会话
        ↓
leader 分工，task list 协调，mailbox 通信
        ↓
并行推进并由用户统一验收
```

### 选择关系

```text
只需要独立结果，不需要互相讨论 → subagent
需要直接通信、互相质疑、自我协调 → Agent teams
```

### 风险关系

```text
任务可并行且边界清晰 → 并行收益覆盖协调成本
任务有依赖／改同一文件／规模过大 → 冲突和 token 成本抵消收益
```

### 实操流程

```text
检查版本 → 启用开关 → 启动 Claude → 自然语言组队
       → 确认创建 → 观察／切队友 → 停止队友 → leader 清理
```
