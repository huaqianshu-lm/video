# Agent teams 智能体团队：多会话协作 · Narration Script

## Scene 01｜三个 Claude 同时跑，为什么还不乱？

一个在改前端，一个在看后端，一个专门写测试。三个 Claude 同时跑，听起来很爽，但你可能马上会问：这真的盯得过来吗？

单会话的天花板有两堵墙。第一堵是上下文有限，同时塞进几大块工作，很快就装不下。第二堵是只能串行，互不相关的活也得一个接一个排队。Agent teams 要做的，就是让你从亲自下场的工人，变成分派和验收的工头。

## Scene 02｜Team 不是放大版 subagent

先别把它和 subagent 混在一起。

Subagent 更像你派出去跑一趟的助手：它有自己的上下文，做完把结果交回主对话，队友之间不互相说话。Agent teams 则是一组对等的 Claude Code 会话。队友可以直接通信，你也能绕过 leader 跟某个队友单独聊。

所以判断很简单：只要结果、不需要讨论，用 subagent 更省；需要分享发现、互相质疑和自我协调，才值得上 team。后者的 token 成本也会更高。

## Scene 03｜四个零件，组成一个团队

一个 team 不是简单多开几个窗口，它有四个关键件。

Leader 负责创建团队、生成队友和协调分工。Teammates 是各自拥有独立上下文的 Claude Code 实例。Task list 是共享任务板，大家在上面认领和完成工作。Mailbox 则是代理之间的信箱，负责传消息。

要注意，创建团队的 leader 不能更换，队友也不会继承 leader 的对话历史。派活时，背景必须交代完整。

## Scene 04｜任务板和信箱，让并行不撞车

任务可以由 leader 指派，也可以由队友自己从任务板上认领。任务有待处理、进行中和已完成三种状态。

如果写测试依赖功能实现，依赖没完成前，这张任务卡就会锁住；前置任务完成后，它会自动解锁。文件锁则负责避免两个队友同时抢同一项工作。

与此同时，队友可以通过 mailbox 直接互发消息。并行不是各干各的，而是让任务板管进度，让信箱管沟通。

## Scene 05｜用 claude agents 看全场

那几个后台会话到底该盯哪一个？可以用 `claude agents` 这块 agent view 总控屏。

每个会话占一行：动态表示工作中，黄色表示需要你输入，绿色表示已完成，红色表示失败。按 Space 可以 Peek，看看最近输出，甚至直接回复；按 Enter 或右箭头则 Attach，进入完整会话。

这些会话由后台 supervisor 托管，不需要你一直守着每个终端。你只在状态需要你的时候介入。

## Scene 06｜leader 怎么分活、切人和收摊

组队和分工可以直接用大白话告诉 leader。进入团队后，按 `Shift+Down` 在队友之间循环，切到谁，就能直接给谁补充指令；`Ctrl+T` 可以切到任务列表。

风险更高的改动，可以先要求队友只做计划，等 leader 批准后再实施。要统一队友模型，也要在提示或配置里明确指定，因为队友默认不会跟随 leader 的模型选择。

活儿结束后，先停掉还在运行的队友，再回到 leader 执行清理。清理这件事不要交给队友。

## Scene 07｜并不是任务越多越该组队

Agent teams 不是越多人越快。每个队友都是完整的 Claude 实例，token 会按人头增加；队友越多，通信、协调和冲突也越多。

研究、审查、竞争假设调试，或者前端、后端、测试这种边界清楚的跨层工作，通常值得拆。相反，有严格先后依赖、几个人要改同一个文件，或者只是一个随手小任务，就别为了拆而拆。

## Scene 08｜从 3—5 个队友起步

更稳的上手方式，是先从不写代码的研究和审查开始。比如三个人分别看安全、性能和测试覆盖，结果可以并行汇总，也不容易发生文件冲突。

团队规模先从三到五个队友起步。只有当新增队友确实能带来额外的并行收益，再考虑扩大规模。

## Scene 09｜启用、组队、切人、清理

现在跑一遍最小闭环。先确认 Claude Code 版本，再在用户设置的环境变量里启用实验性 Agent teams。进入一个玩具目录，启动 Claude。

接着直接用自然语言描述任务和三种角色，让 leader 创建团队。确认后，按 `Shift+Down` 切到某个队友，补充一个角度；最后回到 leader，先让队友停下，再清理团队。

这条链路的重点不是背命令，而是看清：启用、组队、并行、介入、收摊，每一步都有明确的负责人。

## Scene 10｜把自己变成工头

把整篇压缩成五个动作：先识别单会话的天花板，再判断是否真的需要队友；用 leader、任务板和信箱分工协作；用总控屏观察状态，必要时直接介入；最后统一验收并由 leader 清理。

Agent teams 的价值，不是把所有小任务都拆开，而是在复杂工作确实能并行时，让一个人带一支队伍推进。
