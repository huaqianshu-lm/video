# Agent teams 智能体团队：多会话协作 · Visual Script

> 目标：用并行窗口、任务状态、消息流、总控屏和终端时间线展示 Agent teams 如何把多个 Claude Code 会话变成可管理的协作团队。口播负责解释选择、边界和成本，画面负责证明结构、状态和操作顺序。

## 全局视觉原则

### 1. 用并行状态证明“团队在工作”

每幕优先展示工作者、任务、消息或状态的变化，不把文章段落完整铺成静态卡片。Agent teams 的核心视觉不是“很多头像”，而是多个独立工作流同时推进。

### 2. 用颜色区分角色和状态

Leader 使用蓝色，teammates 使用紫色，task list 使用黄色，mailbox 使用绿色；需要输入用黄色，完成用绿色，失败用低饱和红色。颜色只服务于层级和状态，不做高亮装饰。

### 3. 声音解释，画面展示证据

口播解释为什么组队、何时选择 team、成本和责任边界；画面展示窗口、任务卡、锁、消息、状态行、快捷键和清理顺序，不逐句复述口播。

### 4. 每幕只保留一个视觉中心

主标题控制在 1—2 行，软件窗口与流程卡为主体，屏幕文字只保留当前动作所需的命令、角色、状态和结果。底部预留字幕安全区。

### 5. 横屏教程感与预览安全区

使用 1920 × 1080 的 16:9 深色画布、圆角窗口、轻边框和克制发光。最后一幕的预告卡与底部字幕区域分离；上一幕／下一幕、自动播放、进度提示和原型说明只属于 HTML 预览。

## 逐 Scene 视觉设计

### Scene 01｜三个 Claude 同时跑，为什么还不乱？

- **场景容器**：三个并排的 Claude 会话窗口，分别标记前端、后端、测试；下方是一条被阻塞的单会话时间线。
- **视觉动作**：三个窗口的状态点同时闪动；单会话尝试依次接收三项任务，随后“上下文有限”和“只能串行”两块墙挡住队列。
- **信息重点**：需求不是多开窗口，而是突破上下文和串行天花板。
- **口播互补**：口播解释问题和工头类比，画面展示并行与排队的对照。
- **屏幕文字**：`前端`、`后端`、`测试`、`上下文有限`、`只能串行`

### Scene 02｜Team 不是放大版 subagent

- **场景容器**：左右双面板，左侧是主对话与 subagent，右侧是 leader 与三个 team peer。
- **视觉动作**：左侧只有结果箭头回到主对话；右侧出现队友之间的双向消息线，并从用户位置连到任一队友。
- **信息重点**：subagent 单向回传，team 支持队友直聊与用户直接管理。
- **口播互补**：口播给出“跑腿助手／班组”记忆口诀，画面承担通信结构。
- **屏幕文字**：`Subagent`、`只回传结果`、`Agent teams`、`队友直接通信`、`用户可直接管理`

### Scene 03｜四个零件，组成一个团队

- **场景容器**：中心 leader 节点、环绕的三个 teammate 卡片、底部任务板和横向 mailbox 轨道。
- **视觉动作**：leader 先出现，依次生成队友；task list 向所有队友发出任务线；mailbox 在队友间传递消息。leader 节点显示不可替换锁。
- **信息重点**：四个组件各有职责，队友上下文独立且不继承 leader 对话历史。
- **口播互补**：口播解释所有权和背景交代，画面展示关系网络。
- **屏幕文字**：`Team lead`、`Teammates`、`Task list`、`Mailbox`、`leader 不可更换`

### Scene 04｜任务板和信箱，让并行不撞车

- **场景容器**：左侧三张任务卡，右侧两个队友和消息气泡。
- **视觉动作**：任务卡按“待处理 → 进行中 → 已完成”移动；“写测试”先被依赖锁住，功能完成后自动解锁；文件锁挡住第二次重复认领；消息在队友间连线。
- **信息重点**：共享任务管理状态和依赖，mailbox 管理沟通，文件锁防止撞车。
- **口播互补**：口播说明机制和边界，画面展示状态因果。
- **屏幕文字**：`待处理`、`进行中`、`已完成`、`依赖未完成`、`自动解锁`、`文件锁`

### Scene 05｜用 `claude agents` 看全场

- **场景容器**：深色 agent view 总控屏，每行一个会话，右侧浮出操作提示。
- **视觉动作**：四行状态依次变为工作中、需要输入、已完成、失败；对黄色行按 Space 弹出 Peek 面板，再按 Enter 展开完整会话。
- **信息重点**：集中观察和按需介入，不必持续守着每个终端。
- **口播互补**：口播说明状态含义和 supervisor，画面模拟观察动作。
- **屏幕文字**：`claude agents`、`工作中`、`需要输入`、`已完成`、`失败`、`Space：Peek`、`Enter：Attach`

### Scene 06｜leader 怎么分活、切人和收摊

- **场景容器**：横向队友切换轨道、计划批准卡和清理面板三段区域。
- **视觉动作**：`Shift+Down` 高亮不同队友；计划请求到达 leader 后出现批准／退回；模型卡单独标注“需明确指定”；最后队友状态全部停止，leader 执行清理。
- **信息重点**：介入由 leader 完成，清理有明确顺序和责任人。
- **口播互补**：口播解释快捷键、计划、模型和清理规则，画面展示动作链。
- **屏幕文字**：`Shift+Down`、`计划批准`、`模型需指定`、`先停止队友`、`leader 清理`

### Scene 07｜并不是任务越多越该组队

- **场景容器**：中央分流器，左侧“值得拆”、右侧“不要拆”，底部三个成本仪表。
- **视觉动作**：研究／审查、竞争假设、前后端测试进入左侧；依赖链、同一文件、小任务进入右侧；token、协调、冲突仪表在右侧上升。
- **信息重点**：并行收益必须覆盖 token 和协调成本。
- **口播互补**：口播提供决策规则，画面让条件进入不同分支。
- **屏幕文字**：`值得拆`、`不要拆`、`研究／审查`、`有先后依赖`、`改同一文件`、`token 成本`

### Scene 08｜从 3—5 个队友起步

- **场景容器**：三个审查面板和一个规模标尺。
- **视觉动作**：安全、性能、测试覆盖三个结果并行出现并汇入 leader；规模标尺把 `3—5` 区间点亮，超过区间后协调线变密。
- **信息重点**：从不写代码的研究／审查开始，规模先小后大。
- **口播互补**：口播说明稳妥上手策略，画面展示低冲突的并行收益。
- **屏幕文字**：`安全`、`性能`、`测试覆盖`、`协调成本`、`3—5 个队友`

### Scene 09｜启用、组队、切人、清理

- **场景容器**：终端窗口为主，右侧同步显示团队状态卡。
- **视觉动作**：命令状态按时间线出现：版本检查、settings env、`team-demo`、`claude`、三角色创建确认、`Shift+Down` 消息、队友停止和清理完成。
- **信息重点**：启用到收摊的完整顺序；命令是示例，不代表本次执行。
- **口播互补**：口播讲每一步的负责人，画面展示可观察的结果状态。
- **屏幕文字**：`claude --version`、`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`、`team-demo`、`三人团队`、`Shift+Down`、`清理完成`

### Scene 10｜把自己变成工头

- **场景容器**：中央总结路径，右侧不遮挡字幕区的下一篇预告卡。
- **视觉动作**：`分工 → 协作 → 观察 → 验收 → 收摊` 五个节点依次亮起；最后显示 `30「功能怎么选：CLAUDE.md vs Skill vs Hook vs MCP vs Subagent」`。
- **信息重点**：团队是复杂、可并行任务的工具，不是所有任务的默认模式。
- **口播互补**：口播总结和预告，画面保留行动路径与原文明确的下一篇标题。
- **屏幕文字**：`分工`、`协作`、`观察`、`验收`、`收摊`、`30「功能怎么选：CLAUDE.md vs Skill vs Hook vs MCP vs Subagent」`

## 全片视觉类型、组件和动画标准

### 视觉类型

- `ParallelWindow`：Scene 01、02，用于单会话与多会话、subagent 与 team 的关系对照。
- `TeamGraph`：Scene 03、04，用于角色、任务板、依赖和 mailbox。
- `AgentView`：Scene 05，用于多会话状态、Peek 和 Attach。
- `LeaderControl`：Scene 06，用于切队友、计划批准和清理顺序。
- `DecisionMatrix`：Scene 07、08，用于并行收益、成本和团队规模。
- `TerminalDemo`：Scene 09，用于从启用到收摊的操作时间线。
- `SummaryPreview`：Scene 10，用于总结路径和下一集预告。

### 基础组件

- 深色 16:9 画布、圆角软件窗口、轻边框、低强度发光。
- 会话窗口、角色节点、任务卡、状态标签、消息气泡、依赖锁、终端代码块、总控屏列表和预告卡。
- 解释性文字使用清晰无衬线字体；命令、路径、快捷键和状态使用等宽字体。
- Leader 蓝色、队友紫色、任务黄色、消息绿色；警示使用低饱和红色。
- 主标题控制在 1—2 行；底部字幕安全区不放关键卡片；预览控件和原型说明不进入后续 Composition。

### 动画标准

- 窗口生成、任务流转、消息连线和状态变更使用 300—500ms 的淡入、位移或变色传递因果。
- 依赖锁必须先显示“未完成”，再随前置任务完成而解锁，不能同时出现最终状态。
- agent view 先变更状态，再打开 Peek，再进入 Attach，保持观察层级顺序。
- `Shift+Down` 用单一高亮轨迹表示循环切换；计划批准和清理用明确的通过／完成状态。
- Scene 09 的终端状态按时间顺序出现；Scene 10 预告卡至少保留约 2—3 秒可读时间。
