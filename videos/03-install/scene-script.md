# Codex 安装与登录 · Scene Script

> 目标：把「选择入口 → 匹配环境 → 验证命令 → 完成登录 → 按根因排错」拆成可制作的横屏教程场景。每个 Scene 只承担一个认知任务，并明确声音解释、画面证明与观众获得的价值。

---

## Scene 01｜先别急着复制安装命令

### narrativeRole｜认知任务

打破「一条命令适合所有人」的预期，让观众先意识到安装前需要确认自己的使用条件。

### 目的

把安装从孤立的下载动作，改写为一条需要选择、验证和恢复的问题解决路径，为后续入口、环境和登录的判断建立理由。

### narrationIntent｜口播方向

从观众常见的焦虑切入：搜索到命令并不等于已经找到正确路径。使用入口、账号方式和网络连通性都会影响后续步骤，因此第一步不是执行命令，而是确认自己准备怎样使用 Codex。

### visualIntent｜画面证明方向

深色终端中央显示一个待执行的安装命令；命令周围依次浮出三个条件卡片：

```text
使用入口
账号路径
网络连通性
```

单一的「立即安装」箭头收回，三张卡片汇入一条「我的启动路径」。

### keyOnScreenText｜屏幕重点

```text
先确认条件
再选择路径
```

### visualType｜视觉类型

`OpeningScene + ConceptScene`

### 信息分工

- **声音**：解释为什么不能先找唯一命令。
- **画面**：把原本不可见的前置条件变成可检查的选择项。

### videoValue｜观众价值

观众知道安装失败并不只由命令本身造成，开始以自己的环境作为决策起点。

---

## Scene 02｜选择工作入口：桌面 App 还是 CLI

### narrativeRole｜认知任务

让观众按工作方式与操作系统选择入口，而不是把桌面 App 和 CLI 当作优劣之争。

### 目的

建立第一层选择：图形项目工作流可从桌面 App 开始；终端、自动化和跨平台工作流选择 CLI；Linux 直接走 CLI。

### narrationIntent｜口播方向

说明两种入口可以服务同一个工作目标，但适用条件不同。桌面 App 面向 macOS／Windows 的图形项目工作流；CLI 面向终端、自动化和三平台一致的工作流。强调 CLI 的官方独立安装器不要求预先安装 Node.js。

### visualIntent｜画面证明方向

画面左右并列两条路径：左侧是 macOS／Windows 桌面窗口与项目文件，右侧是终端与自动化流程。Linux 标记直接连接到 CLI 路径；底部以小标签标出「官方独立安装器」「不要求 Node.js」。

### keyOnScreenText｜屏幕重点

```text
工作方式决定入口
```

### visualType｜视觉类型

`ComparisonScene`

### 信息分工

- **声音**：说明各入口的适用场景与共同目标。
- **画面**：用两条并行路径展示选择依据和 Linux 的明确去向。

### videoValue｜观众价值

观众能先缩小安装选项，避免为不适合自己工作方式的入口继续查找命令。

---

## Scene 03｜匹配系统与运行环境

### narrativeRole｜认知任务

让观众理解：系统决定安装路径，运行环境决定权限、性能和项目位置。

### 目的

将看似零散的平台差异整理为一条判断链，特别澄清 Windows 原生与 WSL2 各自解决的问题。

### narrationIntent｜口播方向

依次说明 macOS 需要区分芯片架构，macOS／Linux 可使用 shell 路径；Windows 需要在 PowerShell 原生安装、原生沙箱与 WSL2 之间按环境选择。Windows 默认优先考虑原生 `elevated` 沙箱，受策略限制时改用 `unelevated`；只有需要 Linux 原生工具链或项目已在 WSL2 时才选择 WSL2。WSL2 项目应放在 Linux 文件系统，WSL1 不在支持范围内。

### visualIntent｜画面证明方向

以「系统 → 安装路径 → 运行边界」三列决策图展开：

```text
macOS      → 芯片架构 → Shell
Linux      → CLI      → Shell
Windows    → PowerShell / WSL2 → 权限与项目位置
```

Windows 分支继续显示 `elevated`、`unelevated` 与 WSL2；WSL2 卡片标注 Linux 文件系统，并将 `/mnt/c/...` 标为不推荐位置。

### keyOnScreenText｜屏幕重点

```text
系统决定路径
环境决定边界
```

### visualType｜视觉类型

`StepListScene + ComparisonScene`

### 信息分工

- **声音**：解释每个环境选择背后的条件，避免把它们讲成互斥的开关。
- **画面**：把平台、权限和项目位置的关系压缩成可跟随的决策图。

### videoValue｜观众价值

观众能让安装方式适配自己的系统和项目环境，减少照抄他人步骤带来的权限与性能问题。

## Scene 04｜用版本号验证 CLI 已可执行

### narrativeRole｜认知任务

把「安装过程没报错」升级为可观察、可复查的命令可用状态。

### 目的

建立安装后的第一个验证点：只有新终端能找到并执行 `codex`，才算完成 CLI 安装。

### narrationIntent｜口播方向

引导观众在新终端运行 `codex --version` 并查看版本号。明确版本号用于验证可执行性，不承诺某个固定版本；需要了解当前子命令和升级方式时，应查看 `codex --help` 与当前官方说明。出现 `command not found` 或同类提示时，先检查 PATH 或多重安装冲突，而不是立刻重装。

### visualIntent｜画面证明方向

终端依次演示两种结果：

```text
$ codex --version
codex <版本号>
```

绿色状态切换为「CLI 可执行」。另一侧以收起的故障分支展示 `command not found`，只指向「检查 PATH」「检查多重安装」。

### keyOnScreenText｜屏幕重点

```text
能看到版本号
才算命令可用
```

### visualType｜视觉类型

`TerminalScene`

### 信息分工

- **声音**：界定版本检查的意义与排查优先级。
- **画面**：直接展示成功状态、失败现象与对应的首查方向。

### videoValue｜观众价值

观众获得一个最小、确定的安装验证方法，不会把无报错的安装过程误认为可用结果。

---

## Scene 05｜完成登录，连接身份与使用边界

### narrativeRole｜认知任务

说明命令可执行后仍需完成身份验证，并能按当前环境选择安全的登录方式。

### 目的

建立第二个验证点：登录把本地工具连接到实际可工作的账号与用量边界。

### narrationIntent｜口播方向

说明 ChatGPT 账号和 API key 都可用于本地 CLI，但能力与用量边界不同。正常图形环境使用浏览器登录；远程、headless 或 localhost 回调受阻时使用设备码登录。CLI 与 IDE 扩展共享登录缓存，凭据需要按密码保护；认证缓存迁移和 SSH 端口转发只在明确需要时处理，不能暴露凭据。

### visualIntent｜画面证明方向

先显示「CLI 可执行」状态，再进入两条登录分支：浏览器登录与设备码登录。两条分支最终汇入带锁标记的「已认证工作环境」；旁边以小字标注「ChatGPT 账号」「API key」「共享登录缓存」。

### keyOnScreenText｜屏幕重点

```text
可执行 ≠ 可工作
登录完成启动闭环
```

### visualType｜视觉类型

`ConceptScene + StepListScene`

### 信息分工

- **声音**：解释账号方式、替代登录条件与凭据安全边界。
- **画面**：展示从本地可执行到已认证环境的状态变化。

### videoValue｜观众价值

观众知道何时改用设备码登录，并能避免把身份凭据当作普通配置处理。

---

## Scene 06｜遇到问题，回到失败发生的边界

### narrativeRole｜认知任务

把排错从「重装试试」转为按现象定位对应条件的可恢复方法。

### 目的

复用前面建立的闭环，将四类高频问题分别映射到 PATH、网络、登录回调和 Windows 权限策略。

### narrationIntent｜口播方向

依次对应：找不到 `codex` 回到 PATH 与多重安装；下载超时回到网络连通性；浏览器登录失败回到回调环境并改用设备码；Windows 沙箱失败回到系统权限策略和运行环境选择。补充 npm 权限错误不应直接使用 `sudo`，应修正用户目录中的 Node 环境，或改用不依赖 npm 的官方安装器。

### visualIntent｜画面证明方向

中心显示「失败发生在哪一步？」；四张故障卡片依次连接回前面的阶段：

```text
找不到 codex       → PATH / 多重安装
下载超时           → 网络连通性
浏览器登录失败     → 回调环境 / 设备码
Windows 沙箱失败   → 权限策略 / 运行环境
```

`sudo` 图标以警示状态出现，并由箭头指向「修正用户 Node 环境」和「官方独立安装器」。

### keyOnScreenText｜屏幕重点

```text
按现象找根因
不要盲目重装
```

### visualType｜视觉类型

`StepListScene + ConceptScene`

### 信息分工

- **声音**：建立「现象对应边界」的排错规则。
- **画面**：将每类失败显式连回应检查的前置条件。

### videoValue｜观众价值

观众能从失败发生的位置开始恢复，不会用高风险或无效的重装掩盖环境问题。

---

## Scene 07｜建立一条可验证、可恢复的启动路径

### narrativeRole｜认知任务

收束完整路径，并将观众带到下一集的账号用量与计费选择问题。

### 目的

让观众记住安装完成的定义不是一条命令结束，而是已经具备可选择、可验证、可登录和可排错的稳定起点。

### narrationIntent｜口播方向

按顺序回顾：选择入口、匹配环境、验证命令、完成登录、按根因排错。强调不必背下所有平台命令，只要能为自己的条件选择完整路径。最后预告下一集将解释 ChatGPT 套餐登录与 API key 登录的用量边界和计费选择。

### visualIntent｜画面证明方向

前六幕的关键节点汇成一条完整进度路径：

```text
选择入口 → 匹配环境 → 验证命令 → 完成登录 → 按根因排错
```

所有节点点亮后，终点显示「可验证、可登录、可安全工作」。最后一张预告卡片平稳进入：

```text
下一集
ChatGPT 套餐登录 vs API key
用量边界与计费选择
```

### keyOnScreenText｜屏幕重点

```text
安装不是终点
稳定启动才是
```

### visualType｜视觉类型

`SummaryScene`

### 信息分工

- **声音**：完成方法收束，并提出下一集要解决的连续问题。
- **画面**：把分散判断整合为一条已完成的启动路径，为预告留出独立可读空间。

### videoValue｜观众价值

观众带走可复用的启动方法，并清楚知道下一步该如何理解不同账号路径的实际差异。

---

## 场景链路检查

```text
安装焦虑
→ 入口选择
→ 系统与环境匹配
→ 命令验证
→ 登录授权
→ 根因排错
→ 稳定起点与下一集预告
```

- 每幕只推进一个认知问题，先解释选择依据，再进入实际验证与排错。
- 屏幕上的命令、状态、环境名称和预告主题均来自本视频的叙事资料；未引入参考视频的业务文案。
- 本文件只定义 Scene 的认知任务、声音方向和画面证明方向；不进入口播、视觉原型、TTS 或 Remotion 实现阶段。
