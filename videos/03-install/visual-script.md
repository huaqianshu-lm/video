# Codex 安装与登录 · 第五步：Visual Script

> 目标：基于 Scene Script 和 Narration Script，为 7 个 Scene 设计与口播互补的横屏视觉表达。声音负责解释选择依据与排错因果，画面负责展示路径、状态变化、验证证据和可恢复关系。

## 全局视觉原则

### 1．先展示选择过程，再展示安装结果

开场不直接给出一条安装命令，而是让观众看到使用入口、账号路径和网络连通性如何汇成自己的启动路径。后续按入口、系统与环境、命令验证、登录、排错逐步推进，结尾再收束为完整路径。

### 2．画面负责证明，口播负责解释

- **声音**：解释为什么要选择入口、如何理解系统和运行环境差异、验证命令意味着什么，以及不同失败现象对应的根因边界。
- **画面**：展示入口分叉、平台决策、终端输出、登录状态、故障回连和路径完成状态。
- 不把整段口播逐句铺在画面上；屏幕文字只保留关键词、命令、状态、路径标签和下一集预告。

### 3．每个 Scene 只保留一个视觉中心

画布按 1920 × 1080、16:9 横屏设计。顶部保留标题安全区，中部承载主要过程，底部保留字幕安全区。一个 Scene 可以有多个节点，但所有节点必须服务于同一条选择、验证或恢复路径。

### 4．统一使用 Codex 系列视觉语言

- 背景为近黑色，叠加低强度青绿色与蓝色环境光和细网格。
- Codex 主路径使用青绿色；桌面 App、CLI、浏览器登录和设备码登录使用不同的蓝绿或蓝色状态区分，但不引入无关色彩。
- 面板使用半透明深色底、细边框和克制阴影；命令、路径、环境名和状态使用等宽字体。
- 成功使用绿色，停止或风险使用琥珀色或红色，仅表达明确状态。

### 5．屏幕文字必须可追溯

每个 Scene 的“屏幕文字”清单是该 Scene 的可见文字白名单。文字只能来自当前视频的 Source、Scene Script、Narration Script 和本 Visual Script 已有的概念、状态、命令与预告内容。画面结构中的目录、节点和箭头可以作为无文字的视觉证据，不增加参考视频中的业务语义或制作提示。

### 6．动画必须传递信息

优先使用条件卡片汇入、路径分叉、环境边界切换、终端命令执行、状态由未完成变为完成、失败卡回连和节点逐项点亮。避免无意义旋转、粒子和高强度发光。每个关键状态出现后要留出阅读时间，尤其是 Scene 07 的下一集预告卡要独立停留约 2～3 秒。

# Scene 01｜先别急着复制安装命令

## 视觉目标

把“找到命令”与“找到正确起点”区分开，让观众看到安装前需要确认的三个条件。

## 画面结构

主体是一个近黑色终端面板，中央保留一个待执行的安装命令位置，但不展示未经资料确认的具体命令。终端周围依次出现三张条件卡片：使用入口、账号路径、网络连通性。三张卡片最终汇入右侧的一条“我的启动路径”，形成从焦虑到可选择路径的单一动作。

## 动画与状态变化

1. 终端保持待执行状态，单一的安装动作箭头短暂指向命令位置。
2. 箭头收回，使用入口、账号路径、网络连通性依次浮现。
3. 三张卡片分别亮起并沿连接线汇入“我的启动路径”。
4. 启动路径完成高亮，画面停留在选择完成而不是命令执行完成的状态。

## 视觉重点与口播互补

- **画面**把口播中的隐藏前置条件变成可观察的选择卡片。
- **口播**解释入口、账号方式和网络会影响后续步骤，画面不重复这些解释句。
- 不展示具体平台安装命令，避免让观众把本幕误解为正式安装步骤。

## 屏幕文字

```text
使用入口
账号路径
网络连通性
先确认条件
再选择路径
我的启动路径
```

以上文字均来自 Scene Script 01 的 `visualIntent` 或 `keyOnScreenText`；“待执行”只作为无文字状态表现。

## Visual Type

`OpeningScene + ConceptScene / Preflight Path`

## 节奏约束

先让观众看到“立即安装”没有继续执行，再逐项展开条件卡片。三项条件汇入启动路径后再进入下一幕，不提前显示桌面 App 或 CLI 的具体选择结果。

# Scene 02｜选择工作入口：桌面 App 还是 CLI

## 视觉目标

用两条并行路径展示入口差异，让选择依据来自工作方式和系统，而不是来自优劣比较。

## 画面结构

画面左右分栏。左侧是 macOS／Windows 的桌面窗口与项目文件，代表桌面 App；右侧是终端与一条自动化流程，代表 CLI。Linux 标签从下方直接连到 CLI 路径。底部放置两个小能力标签，作为 CLI 路径的辅助证据。

## 动画与状态变化

1. 顶部先出现“工作方式决定入口”。
2. 左侧桌面窗口和右侧终端同时出现，但两条路径保持未选中状态。
3. “图形项目工作流”方向的光标进入桌面 App；“终端操作”和“自动化任务”方向的光标进入 CLI。
4. Linux 标签绕过桌面路径，直接连接 CLI；底部两个能力标签随后点亮。
5. 两条路径保持并列，最后以共同目标收束，不把任一入口显示为唯一答案。

## 视觉重点与口播互补

- **画面**展示入口的路由关系、Linux 的明确去向和 CLI 的安装前提。
- **口播**解释桌面 App 与 CLI 的适用工作流，以及两种入口可以服务同一类工作。
- 不展示完整安装步骤，只展示选择发生在哪里。

## 屏幕文字

```text
工作方式决定入口
桌面 App
CLI
macOS
Windows
Linux
图形项目工作流
终端操作
自动化任务
官方独立安装器
不要求 Node.js
```

以上文字来自 Scene Script 02 的 `narrationIntent`、`visualIntent` 和 `keyOnScreenText`；左右窗口与终端只作为入口的结构性图形。

## Visual Type

`ComparisonScene / Entry Routing`

## 节奏约束

先建立两条并行入口，再显示 Linux 直接进入 CLI 的关系。入口标签出现后要保留足够时间阅读，不把 macOS／Windows 的桌面路径误画成 Linux 路径。

# Scene 03｜匹配系统与运行环境

## 视觉目标

把平台差异压缩成“系统 → 安装路径 → 运行边界”的判断链，并明确 Windows 原生环境与 WSL2 的选择条件。

## 画面结构

主体为三列决策图。第一列是系统，第二列是安装路径，第三列是运行边界。macOS 和 Linux 各自沿 Shell 路径向右连接；Windows 进入 PowerShell／WSL2 分支，再展开 `elevated`、`unelevated` 和项目位置。WSL2 卡片内部显示 Linux 文件系统，并将 `/mnt/c/...` 放在低亮度的“不推荐位置”区域。

## 动画与状态变化

1. “系统决定路径”出现，macOS、Linux、Windows 依次点亮。
2. macOS 先经过“芯片架构”再连接 Shell；Linux 连接 CLI 和 Shell。
3. Windows 路径展开为 PowerShell／WSL2，随后显示权限与项目位置的运行边界。
4. `elevated` 先作为默认原生路径点亮，`unelevated` 作为策略受限时的替代路径出现。
5. WSL2 分支显示 Linux 文件系统；`/mnt/c/...` 停留在不推荐位置，形成清晰的边界对照。
6. “环境决定边界”在三列路径完成后出现，画面保留决策链。

## 视觉重点与口播互补

- **画面**把系统、路径、权限和项目位置串成可跟随的决策图。
- **口播**解释各分支的适用条件，特别说明 WSL2 只在需要 Linux 工具链或项目已在 WSL2 时选择。
- WSL1 支持范围等细节由口播承担，画面不扩展成额外的状态卡片。

## 屏幕文字

```text
系统决定路径
环境决定边界
macOS
Linux
Windows
芯片架构
Shell
CLI
PowerShell
WSL2
elevated
unelevated
Linux 文件系统
/mnt/c/...
不推荐位置
```

以上文字来自 Scene Script 03 的 `visualIntent`、`narrationIntent` 和 `keyOnScreenText`。

## Visual Type

`StepListScene + ComparisonScene / Environment Decision Map`

## 节奏约束

按“系统、安装路径、运行边界”的顺序展开。Windows 分支必须在主路径出现后再展开，避免三个平台同时堆满画面；`/mnt/c/...` 的不推荐状态要在 WSL2 卡片出现后再显示。

# Scene 04｜用版本号验证 CLI 已可执行

## 视觉目标

用一个最小、可复查的终端动作证明 CLI 是否真的可执行，同时保留失败后的首查方向。

## 画面结构

主体是大尺寸终端。命令逐字输入并执行，随后画面分成成功结果和失败结果两个轻量区域。成功区域显示版本号和“CLI 可执行”；失败区域折叠显示 `command not found`，下方仅保留 PATH 与多重安装两个排查标签。

## 动画与状态变化

1. 新终端窗口出现，输入 `$ codex --version` 并回车。
2. 成功结果先出现：`codex <版本号>`，绿色状态切换为“CLI 可执行”。
3. 成功结果缩到左侧，右侧出现另一轮失败结果 `command not found`。
4. 失败分支依次点亮“检查 PATH”和“检查多重安装”，不触发重装动作。
5. 两种结果并列定格，让观众看到“命令可用”与“需要排查”的区别。

## 视觉重点与口播互补

- **画面**直接展示命令、成功输出、失败现象和首查方向。
- **口播**说明版本号只用于验证可执行性，不承诺固定版本，并补充 `codex --help` 的用途。
- 不显示固定版本号，也不把失败分支表现为必须重装。

## 屏幕文字

```text
$ codex --version
codex <版本号>
CLI 可执行
command not found
检查 PATH
检查多重安装
能看到版本号
才算命令可用
```

以上文字来自 Scene Script 04 的 `visualIntent`、`narrationIntent` 和 `keyOnScreenText`。

## Visual Type

`TerminalScene / Verification Branch`

## 节奏约束

先完成成功结果，再引入失败分支；版本号和失败提示都要短暂停留。不要显示版本升级或额外安装命令，以免抢走“验证可执行性”的视觉中心。

# Scene 05｜完成登录，连接身份与使用边界

## 视觉目标

把“CLI 能执行”推进为“环境可工作”，展示账号方式与登录环境如何汇入已认证状态。

## 画面结构

画面先承接 Scene 04 的“CLI 可执行”状态，再展开两层分支。第一层为 ChatGPT 账号与 API key；第二层为浏览器登录与设备码登录。正常图形环境的浏览器路径直接通过，远程、headless 或 localhost 回调受阻的条件转向设备码。两条登录路径最终汇入带锁标记的已认证工作环境，旁侧保留共享登录缓存与凭据安全提示的短标签。

## 动画与状态变化

1. “CLI 可执行”状态卡从上一幕移入，随后出现“可执行 ≠ 可工作”。
2. ChatGPT 账号与 API key 分成两条身份路径，保持并列，不显示比较分数。
3. 浏览器登录先完成并汇入锁定的本地状态；远程、headless 或 localhost 回调受阻时，回路转入设备码登录。
4. 设备码路径完成后，与浏览器路径共同汇入“已认证工作环境”。
5. CLI 与 IDE 扩展的共享登录缓存出现在侧边，凭据状态由普通亮度降为受保护状态。

## 视觉重点与口播互补

- **画面**展示从可执行到已认证的状态变化，以及浏览器登录和设备码登录的分流条件。
- **口播**解释 ChatGPT 账号与 API key 的能力和用量边界，并说明凭据、缓存迁移和 SSH 端口转发的安全边界。
- 不显示真实账号、密钥、回调地址或凭据内容。

## 屏幕文字

```text
CLI 可执行
可执行 ≠ 可工作
ChatGPT 账号
API key
浏览器登录
设备码登录
远程
headless
localhost
已认证工作环境
共享登录缓存
```

以上文字来自 Scene Script 05 的 `visualIntent`、`narrationIntent` 和 `keyOnScreenText`；锁与路径状态不承载额外文字。

## Visual Type

`ConceptScene + StepListScene / Authentication Flow`

## 节奏约束

先承接 CLI 可执行，再展示登录分支。设备码登录要在回调受阻条件出现后进入，两个登录结果都完成后才显示已认证工作环境，并为凭据保护留出短暂停留。

# Scene 06｜遇到问题，回到失败发生的边界

## 视觉目标

把排错从盲目重装改为按失败现象回到对应条件，形成可恢复的根因映射。

## 画面结构

中心放置“失败发生在哪一步？”，四张故障卡片沿环形路径依次出现，并分别连接回入口、网络、登录回调和 Windows 运行环境。卡片右侧显示对应的检查边界。底部单独出现 `sudo` 警示，箭头指向用户 Node 环境和官方独立安装器，作为 npm 权限错误的安全替代路径。

## 动画与状态变化

1. 中心问题先出现，四条空路径从前面 Scene 的节点方向汇入。
2. “找不到 codex”回连 PATH／多重安装；“下载超时”回连网络连通性。
3. “浏览器登录失败”回连回调环境，并转向设备码；“Windows 沙箱失败”回连权限策略和运行环境。
4. 四张卡片完成回连后，中心状态从“重装？”切换为“按现象找根因”。
5. `sudo` 以风险色出现并被划停，随后两条低风险路径亮起：修正用户 Node 环境、官方独立安装器。
6. 所有回连路径降低亮度，只保留“不要盲目重装”的收束状态。

## 视觉重点与口播互补

- **画面**用故障卡片和回连路径证明每种现象都有对应的检查边界。
- **口播**解释各类问题的恢复顺序，并说明 npm 权限错误不应直接使用 `sudo`。
- 不把四类故障做成新的安装教程，只展示从现象回到根因的位置。

## 屏幕文字

```text
失败发生在哪一步？
找不到 codex
PATH / 多重安装
下载超时
网络连通性
浏览器登录失败
回调环境 / 设备码
Windows 沙箱失败
权限策略 / 运行环境
sudo
修正用户 Node 环境
官方独立安装器
按现象找根因
不要盲目重装
```

以上文字来自 Scene Script 06 的 `visualIntent`、`narrationIntent` 和 `keyOnScreenText`；回连线本身表达前置条件，不增加新的屏幕文案。

## Visual Type

`StepListScene + ConceptScene / Root-Cause Recovery Map`

## 节奏约束

中心问题先出现，四类故障按顺序回连，不同时闪现。`sudo` 警示放在四类问题完成之后，修正路径出现后再显示最终结论。

# Scene 07｜建立一条可验证、可恢复的启动路径

## 视觉目标

将前六幕的判断和验证节点汇成一条完整启动路径，并以独立预告卡结束系列视频。

## 画面结构

第一段为横向进度路径，依次连接选择入口、匹配环境、验证命令、完成登录、按根因排错。节点从灰色变为青绿色，终点显示可验证、可登录、可安全工作的完成状态。第二段将路径整体降低亮度，切换到字幕安全区上方的独立预告卡，不与完成状态并列争夺视觉中心。

## 动画与状态变化

1. 五个节点按前六幕的顺序依次进入，路径从左向右连接。
2. 选择入口、匹配环境、验证命令、完成登录、按根因排错依次点亮。
3. 全部节点完成后，终点显示“可验证、可登录、可安全工作”。
4. 完整路径短暂保持，随后整体降低亮度，预告卡平稳进入。
5. 预告卡先显示“下一集”，再显示 ChatGPT 套餐登录与 API key 登录的用量边界和计费选择主题。
6. 预告卡独立停留约 2～3 秒后结束，不能叠加新的导航、调试标记或制作说明。

## 视觉重点与口播互补

- **画面**把分散的判断节点收束为一条可验证、可登录、可排错的启动路径。
- **口播**完成方法论总结，并提出下一集的账号路径与计费问题。
- 预告卡只承担系列连续性，不提前解释下一集的答案。

## 屏幕文字

```text
安装不是终点
稳定启动才是
选择入口
匹配环境
验证命令
完成登录
按根因排错
可验证、可登录、可安全工作
下一集
ChatGPT 套餐登录 vs API key
用量边界与计费选择
```

以上文字来自 Scene Script 07 的 `visualIntent`、`narrationIntent` 和 `keyOnScreenText`；预告卡是最后一个视觉事件，保持独立停留。

## Visual Type

`SummaryScene / Completed Path + Preview Card`

## 节奏约束

完整路径必须先完成并留出读字时间，再切换预告卡。预告卡停留约 2～3 秒，主体位于字幕安全区上方，结束时不回到进度路径。

# 全片视觉类型分布

```text
OpeningScene + ConceptScene / Preflight Path
ComparisonScene / Entry Routing
StepListScene + ComparisonScene / Environment Decision Map
TerminalScene / Verification Branch
ConceptScene + StepListScene / Authentication Flow
StepListScene + ConceptScene / Root-Cause Recovery Map
SummaryScene / Completed Path + Preview Card
```

整体顺序为“安装前置条件 → 入口选择 → 系统与环境匹配 → CLI 验证 → 身份认证 → 根因排错 → 稳定启动与下一集预告”。每一幕只推进一个认知问题，不为每个 Scene 重新设计界面语言。

# 通用组件层建议

后续进入 Visual Prototype 或 Remotion 时，优先复用已有基础表达，不在本阶段新增场景组件：

```text
<SceneFrame />
<SectionTitle />
<TerminalPanel />
<EntryCard />
<DecisionPath />
<EnvironmentMap />
<StatusNode />
<AuthBranch />
<FailureCard />
<RecoveryArrow />
<ProgressPath />
<PreviewCard />
```

组件只负责稳定结构，具体入口、环境、命令、状态和预告文字由每个 Scene 的配置决定。预览导航、自动播放、进度提示和调试标记只属于 Visual Prototype，不进入最终 Composition 或 MP4。

# 动画层级标准

## 一级：信息动画

必须保留，直接表达知识：

```text
条件卡片汇入启动路径
桌面 App 与 CLI 分叉
Linux 路径直接连接 CLI
系统连接安装路径与运行边界
codex --version 产生成功或失败结果
浏览器登录与设备码登录汇入已认证环境
故障卡片回连对应根因边界
五个节点依次点亮并进入下一集预告
```

## 二级：注意力动画

少量使用，用于引导观众：

```text
当前路径高亮
成功状态轻微发光
command not found 的短暂放大
sudo 警示停顿后降亮
已完成路径降低亮度
```

## 三级：装饰动画

尽量不使用：

```text
无意义粒子
无意义旋转
过多弹跳
与选择或验证无关的背景漂浮
```

如果删除一段动画后，观众仍能获得完全相同的信息，就不应把它作为必要动画。

# Visual Script 质量检查

### 1．静音检查

关闭声音后，至少能从每个 Scene 的路径、状态或对照关系看出这一幕发生了什么：条件汇入、入口分叉、环境决策、版本验证、登录分支、故障回连和完整启动路径。

### 2．重复检查

画面不逐句显示 Narration Script。屏幕文字只保留入口、系统、环境、命令、状态、排查方向和系列预告；解释性因果交给口播。

### 3．来源归属检查

每个 Scene 的屏幕文字均已在该 Scene 的 `keyOnScreenText`、`visualIntent` 或 `narrationIntent` 中找到依据。没有引入具体安装命令、固定版本号、真实账号、密钥、回调地址或参考视频业务文案。

### 4．预告检查

Scene 07 的下一集预告同步来自 Scene Script 和 Narration Script，作为最后一个视觉事件独立停留约 2～3 秒，不与完整启动路径或字幕安全区重叠。

### 5．范围检查

本文件只定义 Visual Script，不生成 Visual Prototype、TTS、字幕、Timeline、Remotion 配置或实现代码。
