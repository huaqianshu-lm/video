# Claude Code 订阅套餐与计费视频化 · 第四步：Narration Script

## Scene 01｜账单为什么会失控

官方文档里有一个数字，很多人第一次看到都会愣一下：企业部署中，每个开发者平均每天可能消耗十几美元，一个月甚至达到一两百美元。

这不是说你用 Claude Code 就一定会花这么多钱。真正值得警惕的是，很多人用了一周，打开账单时却完全说不清钱到底花在了哪里。

是模型选贵了？是对话太长了？还是有一次让它读了太多文件？

所以这一篇，我们先不急着讨论哪个套餐便宜。先把账算明白：Claude Code 到底在为什么付费，三种付费路径有什么区别，以及怎样确认钱没有从错误的接口流走。

## Scene 02｜Token 到底怎么计费

先说结论：Claude Code 这个工具本身可以免费下载，你真正付的是背后模型处理请求的算力。

你向它提问，它读取文件，它返回修改方案，甚至它在执行任务前进行的扩展思考，都会产生需要处理的文字量。

这个文字量通常用 token 来计量。可以把 Claude Code 想成一辆出租车，工具本身像是免费上车，但模型处理的内容就是不断跳表的里程。

输入的内容算输入 token，模型返回的内容算输出 token，而输出通常更贵。你让它读一个两千行的文件，整个文件都会进入输入；一轮对话聊到第五十条，前面的上下文也可能继续被带进后面的请求；打开扩展思考，思考过程也会增加处理量。

所以花钱多少，和你问了几个问题并不是简单的正相关。更关键的是，每次请求带了多少上下文，模型需要输出多少内容，以及有没有因为方向错误反复返工。

这也是后面所有省钱方法的基础：先减少无效的上下文，再考虑换什么套餐。

## Scene 03｜三条付费路径怎么选

知道钱花在 token 上以后，接下来就是选择通过什么方式付费。常见的有三条路。

第一种是官方按量计费，也就是 API 或 Console 这条路。用多少 token 就付多少，适合想用官方原生模型、用量比较稳定，也能接受账单浮动的人。

第二种是官方订阅，比如 Pro、Max 或 Team。它的特点是固定月费和计划额度，更适合高频使用、希望支出更可预期，并且愿意使用官方模型的人。

第三种是国产 Coding Plan。它通常是固定月费，把多个模型和工具放在一份额度里，更适合国内用户、对成本敏感，并且能够接受模型差异的人。

这三条路没有一个对所有人都最优。官方按量计费更灵活，官方订阅更容易控制固定支出，国产 Coding Plan 可能在成本和网络连接上更有优势，但厂商规则、模型能力和兼容性都需要单独确认。

尤其是价格、促销和额度都可能变化。画面里的金额只能作为参考，真正购买前要看官方定价页或厂商当前活动页。

## Scene 04｜买了套餐，为什么还会多一笔账单

国产 Coding Plan 有一个特别容易踩的坑：买了套餐，不代表每个请求都会消耗套餐额度。

很多厂商同时提供两类看起来很像的接口地址。一条用于 Coding Plan，另一条是普通 API。以源文档中的火山方舟示例来说，地址里带有 `/api/coding` 的路径用于套餐场景，而 `/api/v3` 则可能进入普通的按量计费路径。

如果你本来以为自己在用固定月费套餐，配置时却把地址填成了普通 API，调用依然可能成功，但钱已经从另一个口子流走了。到了月底，套餐额度没有怎么减少，按量计费那边却多出了一笔账单。

API Key 也一样。套餐专属的 Key 和普通按量计费的 Key 不能随便混用。

所以接入 Coding Plan 以后，至少核对两件事：Base URL 是否是套餐专属路径，API Key 是否是套餐专属版本。具体地址和 Key 的格式属于厂商自己的规则，动手前一定以当前官方文档和控制台为准。

买了套餐，不等于一定走套餐。配置正确，还要用量检查来验收。

## Scene 05｜三个命令分别看什么

Claude Code 里有三个命令，可以帮助你把账和配置看得更清楚。

第一个是 `/usage`。它主要看当前会话用了多少 token，并给出一个本地估算的花销。这个数字适合帮助你建立感觉，但它不一定等于最终账单，权威金额还是要以 Console 的使用页面为准。

第二个是 `/usage-credits`。它可以在官方 Pro 或 Max 计划中设置每月使用上限，达到上限以后，Claude Code 会提醒你是否提高或移除限制。它不是所有国产 Coding Plan 的统一额度开关，国产套餐的额度仍然要看对应厂商的控制台。

第三个是 `/status`。它用来核对版本、模型、账户和连通性。尤其当你配置了代理、网关或第三方 Coding Plan 时，不能只看 Claude Code 能不能启动，还要确认它使用的模型和连接状态是不是你预期的结果。

可以把这三个命令记成一句话：`/usage` 看明细，`/usage-credits` 设上限，`/status` 核配置。

## Scene 06｜省钱不是只换便宜套餐

换一个更便宜的套餐，往往只是下策。真正稳定的省钱方法，是让模型少读没用的内容，少走没必要的弯路。

第一个习惯，不相关的任务之间使用 `/clear`。上午修 Bug，下午写新功能，不要把所有事情都塞进同一个长会话里。旧上下文会在后续请求中重复出现，任务之间清空，能避免这部分浪费。

第二个习惯，日常任务默认使用 Sonnet。普通改代码、写函数和调小问题，通常不需要一直使用更贵的 Opus。复杂架构和多步推理，再考虑切换到更强的模型。

第三个习惯，复杂任务先用 plan mode。先让模型探索代码库、给出计划，再决定是否执行，比方向错了以后修改七八个文件更省 token。

第四个习惯，把提示写具体。与其说“帮我改进这个代码库”，不如指出具体文件、函数和目标。范围越清楚，模型越不需要到处扫描，也越不容易把时间和 token 花在无关内容上。

省钱不是单纯换一个便宜模型，而是清掉陈旧上下文、用合适的模型、减少返工，并缩小搜索范围。

## Scene 07｜现在就建立用量感知

最后，把前面的内容变成一套五分钟就能跑一遍的动作。

第一步，在项目目录里启动 Claude Code，然后输入 `/status`。确认当前使用的模型、账户和连通性都符合预期。如果你使用国产 Coding Plan，还要回到环境变量和厂商控制台，确认 Base URL 走的是套餐路径。

第二步，先让它做一个很小的任务。比如看看当前目录有哪些文件，简单说明项目是做什么的。任务完成后输入 `/usage`，记下这次简单操作的用量和本地估算金额。

这个数字不是固定价格，而是你的个人基准。以后某次对话突然变得特别贵，你就有一个可以对照的参照物。

第三步，如果你使用的是官方 Pro 或 Max 计划，可以输入 `/usage-credits`，给自己设置一个能够接受的月度上限。国产 Coding Plan 用户则要在厂商控制台里管理对应套餐的额度。

这样一来，你就完成了一条最小闭环：先核对配置，再做一个小任务，查看用量，最后设置能够使用的边界。

## Scene 08｜总结与下一集预告

这一篇只记住三件事。

第一，Claude Code 工具本身不是主要的计费来源，模型处理的输入、输出和上下文才是成本核心。

第二，按量计费、官方订阅和国产 Coding Plan 是三种不同的取舍，没有适合所有人的唯一答案。买了 Coding Plan 以后，还要确认 Base URL 和 API Key 真的指向套餐路径。

第三，`/usage` 看明细，`/status` 核配置，`/clear` 勤清上下文，再配合合适的模型和具体提示，才能让同样的任务少烧 token。

账算明白了，配置路径也核对了，下一步就该真正启动 Claude Code。
