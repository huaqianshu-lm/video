# Claude Code 网页版与云端：Video Narrative

> 目标：不机械复述文章章节，让观众从“必须坐在电脑前”走到“按代码运行位置选择 Web、Local 或 Remote Control”。

## 1. 视频叙事目标

观众的认知变化：

```text
手机上只有一个临时修复需求
↓
关键不是入口，而是代码到底在哪台机器上跑
↓
网页版把仓库交给一次性云 VM，适合免安装和并行任务
↓
Remote Control 不把代码搬上云，只把本地会话开一扇远程窗口
↓
相似命令其实代表三个不同方向
↓
按任务和信任边界选择入口
```

## 2. 叙事起点和结论

### 起点

从高铁上的手机修 README 开始：没有电脑、没有本地终端，但任务最后变成 GitHub 上等待提 PR 的分支。这个结果先制造“Claude Code 不一定要在眼前的电脑上跑”的问题。

### 中段问题

如果代码跑在云端，网页版到底拥有和失去什么？如果代码必须留在本机，Remote Control 又如何让手机接管？随后用命令方向和最小操作闭环把抽象差异落地。

### 结论

网页版适合免安装、GitHub 仓库、并行和不依赖本地配置的任务；本地 CLI 适合本机文件和工具；Remote Control 适合本地任务换设备继续。deep-links 只负责准备会话入口，不替用户执行。

## 3. 整体叙事结构

```text
01 手机修 README：电脑可以不在场
↓
02 先认准代码跑在哪台机器上
↓
03 网页版：GitHub → 云 VM → 分支
↓
04 Web 和本地 CLI：不是替代，是分工
↓
05 Remote Control：手机只是本地会话的窗口
↓
06 三个相似命令，三个不同方向
↓
07 deep-links：只填入口，不替你执行
↓
08 五步跑通手机接管本地会话
↓
09 国内访问：分清用户链路和云端链路
↓
10 选择结论，下一集看 /init
```

## 4. 逐段叙事设计

### 第一段：把“必须坐在电脑前”拆掉

手机、车厢 WiFi 和 GitHub 分支形成具体结果，不先给定义。

### 第二段：建立全片判断轴

用本地、网页版、Remote Control 三个入口回答同一个问题：代码在哪里执行。后续所有取舍都从这一条线派生。

### 第三、四段：先展示 Web 的价值，再给出边界

先让观众看到云 VM 如何免安装、并行运行并交付分支，再用本地文件、本地配置和权限模式解释为什么它不是本地 CLI 的替代品。

### 第五、六段：把 Remote Control 与云端执行彻底分开

先展示本地文件仍留在电脑，手机只是遥控器；随后用三条方向箭头解决 `--remote`、`--teleport` 和 `--remote-control` 的命名混淆。

### 第七、八段：用安全闸门和操作流程落地

deep-links 先停在“已填好但未发送”，然后用版本、登录、进程、二维码和手机消息跑通最小闭环。

### 第九、十段：补网络边界并收束选择

把“浏览器／手机访问 claude.ai”和“云 VM 自己访问网络”拆成两条链路，最后给出任务取舍和 source 已提供的 `/init` 下一集预告。

## 5. 叙事节奏

- Scene 01—03：快速建立问题、判断轴和 Web 的核心直觉。
- Scene 04—06：集中处理 Web／本地边界和命令方向，是信息密度最高的解释段。
- Scene 07—08：用安全状态和连续操作降低抽象度。
- Scene 09：短而明确，避免把访问说明变成独立教程。
- Scene 10：保留 2—3 秒阅读空间，取舍卡片和下一集预告分层呈现。

## 6. 声音与视觉分工

| 叙事信息 | 声音负责 | 画面负责 |
|---|---|---|
| 手机修 README | 讲清“电脑不在场”的反差 | 手机、云端任务和 GitHub 分支结果 |
| 执行位置 | 解释本地、云端、远控的边界 | 三入口与机器位置连接 |
| Web 价值 | 解释免安装、并行和仓库前提 | GitHub 克隆、云 VM、分支输出 |
| Web 与本地取舍 | 解释配置和权限差异 | 两列状态对照 |
| Remote Control | 说明代码仍在本机 | 电脑文件、终端和手机窗口连线 |
| 命令方向 | 说明三个命令的方向 | 云与本地之间的箭头 |
| 操作与安全 | 说明只填不发、扫码和进程边界 | URL、二维码、手机消息和状态回传 |
| 结尾 | 给选择建议和下一集主题 | 三张取舍卡与 `/init` 预告 |

## 7. Gate 1 叙事审查结论

- 叙事按照观众认知过程重组，没有把 source 的章节标题直接当作 Scene。
- “代码运行位置”在第 02 幕建立，并贯穿 Web、本地和 Remote Control 的选择。
- Web 和 Remote Control 各有独立视觉机制，未用同一套云端卡片表达所有能力。
- 操作细节服务于理解，不会把命令执行或账号配置变成本任务的实际动作。
- 结尾只使用 source 已给出的下一篇标题和 `/init` 主题，不提前读取或补写下一篇内容。

**Gate 1 结论：通过，可进入 10 个 Scene Script。**
