# Claude Code 网页版与云端：Visual Script

## 全局视觉原则

- 16:9 横屏，按 1920 × 1080 构图；整体使用深色、克制、科技教程风格。
- 主视觉优先使用设备、终端、云 VM、GitHub 分支、连接线和状态变化，不把文章做成文字幻灯片。
- 声音解释运行位置、适用条件和限制；画面负责证明仓库在哪里、代码在哪里、控制权如何移动。
- 每幕只保留 1 个主结论；主标题 1—2 行，屏幕文字只使用本片生产资料中的功能名、命令、状态和判断。
- 字幕预留底部安全区；最后一幕的下一篇预告卡固定在右侧，不与字幕区域重叠。

## 逐 Scene 视觉设计

### Scene 01｜手机修 README，电脑可以不在场

#### 画面结构

左侧是手机窗口，显示 `README 安装命令` 和一条简短任务；右侧依次出现“云端运行”“GitHub 分支 · 等待提 PR”，背景只保留车厢 WiFi 的弱化信号。

#### 视觉动作

1. 手机亮起，任务进入 `claude.ai/code`。
2. 电脑图标保持熄灭，云端任务卡开始运行。
3. GitHub 分支卡片出现并变为绿色完成状态。

#### 声音与画面互补

口播讲故事和结果，画面只展示“手机发起、电脑未开、分支交付”的时间关系。

#### 主要屏幕文字

`手机`、`README 安装命令`、`GitHub 分支 · 等待提 PR`、`电脑：未开启`。

### Scene 02｜先看代码跑在哪台机器上

#### 画面结构

中央放置“代码跑在哪？”判断节点，左边连接本地机器，中间连接 Anthropic 云 VM，右边先经过手机窗口再回到本地机器。

#### 视觉动作

1. 本地 CLI／桌面 app 连接本机文件树。
2. Web 连接云 VM，云 VM 内出现仓库。
3. Remote Control 的手机只连接控制线，代码文件仍留在本机。

#### 声音与画面互补

口播定义三种到岗方式，画面用执行端与控制端的空间关系证明差别。

#### 主要屏幕文字

`本地：你的机器`、`网页版：Anthropic 云 VM`、`Remote Control：手机遥控本地会话`、`代码跑在哪？`。

### Scene 03｜网页版：GitHub 到云端分支

#### 画面结构

左侧 GitHub repo，中间是带“隔离／一次性”的 cloud VM，右侧是三个并行任务卡和输出分支。

#### 视觉动作

1. GitHub 仓库克隆进入 cloud VM。
2. 三个任务卡分别标记 `flaky test`、`API 文档`、`日志模块`。
3. 三个任务完成后各自连到 GitHub 分支。

#### 声音与画面互补

口播解释免安装、并行和本地没 clone 的场景，画面展示任务从仓库到分支的过程。

#### 主要屏幕文字

`claude.ai/code`、`GitHub repo`、`cloud VM · 一次性隔离`、`flaky test`、`API 文档`、`日志模块`、`GitHub branch`。

### Scene 04｜Web 和本地 CLI：不是替代，是分工

#### 画面结构

左右两列：Web 在云 VM 中，本地 CLI 在用户机器中；中间浮现“需要碰本地东西？”判断。

#### 视觉动作

1. Web 列显示 `GitHub：需要`、`本地配置：不可见`、`关闭网页：继续运行`。
2. 本地列显示 `GitHub：不一定`、`本地文件／MCP：可用`、`关闭终端：停止`。
3. 底部出现“自动接受编辑 · 任务描述要具体”。

#### 声音与画面互补

口播解释取舍和权限边界，画面不重复整段口播，只展示决定入口的差异。

#### 主要屏幕文字

`需要本地文件？→ 本地 CLI`、`不需要本地环境？→ 网页版`、`自动接受编辑`、`Plan`。

### Scene 05｜Remote Control：手机只是本地会话的窗口

#### 画面结构

左侧电脑窗口包含本地文件树、终端和会话状态；右侧手机窗口显示同一个会话；两者之间只有“控制／结果”连接线。

#### 视觉动作

1. 电脑上的 `src/` 和本地 MCP 标签保持亮起。
2. 手机连接后显示同一会话名称。
3. 文件树始终停留在电脑一侧，云 VM 节点不出现。

#### 声音与画面互补

口播说明本地执行和换设备控制，画面通过文件留在电脑上避免观众误解为上传到云。

#### 主要屏幕文字

`代码：你的机器`、`手机：遥控窗口`、`本地文件`、`MCP`、`项目配置`。

### Scene 06｜三个相似命令，三个不同方向

#### 画面结构

同一舞台放置“本地机器”和“Anthropic 云 VM”两个节点，手机窗口放在本地节点旁。

#### 视觉动作

1. `claude --remote "任务"` 的箭头从本地指向云 VM。
2. `claude --teleport` 的箭头从云 VM 指回本地。
3. `claude --remote-control` 的箭头从本地会话指向手机窗口，云 VM 变暗。

#### 声音与画面互补

口播读出方向和意义，画面让三个命令的执行位置形成不同几何路径。

#### 主要屏幕文字

三个命令原文，以及 `本地 → 云`、`云 → 本地`、`本地 → 手机窗口`。

### Scene 07｜deep-links：只填入口，不替你执行

#### 画面结构

左侧是 `claude-cli://` 链接，中间是本地仓库选择器，右侧是带预填文本的会话输入框，底部是未按下的回车闸门。

#### 视觉动作

1. 链接解析出 `acme/payments`。
2. `review open PRs` 填入输入框。
3. 输入框停在“等待回车”，绿色执行状态不出现。

#### 声音与画面互补

口播强调安全边界，画面通过“未发送”的静止状态证明只填不发。

#### 主要屏幕文字

`claude-cli://open?repo=acme/payments&q=review%20open%20PRs`、`仓库已选择`、`提示已填入 · 等待回车`。

### Scene 08｜五步跑通手机接管本地会话

#### 画面结构

左侧步骤轨道，中央电脑终端，右侧手机二维码／消息窗口；底部展示进程收束。

#### 视觉动作

1. 依次点亮 `claude --version`、`claude remote-control`、`空格：显示二维码`。
2. 手机扫码后出现“连接状态”，手机发出列目录消息。
3. 电脑终端显示当前目录文件结果，最后出现 `Ctrl+C：结束会话`。

#### 声音与画面互补

口播负责操作顺序，画面负责显示连接、消息回传和结束状态。

#### 主要屏幕文字

`版本 ≥ 2.1.51`、`claude --version`、`claude remote-control`、`空格：显示二维码`、`列出当前目录下有哪些文件`、`Ctrl+C：结束会话`。

### Scene 09｜用户链路和云端链路不是一回事

#### 画面结构

画面分成两条互不相交的路径：上方是浏览器／手机到 `claude.ai`，下方是 cloud VM 到 GitHub／npm。

#### 视觉动作

1. 浏览器和手机连向 `claude.ai`，出现“用户连接”。
2. cloud VM 连接 GitHub／npm，出现“云端基础设施”。
3. 两条路径之间保持明显间距，不出现本地网络桥接。

#### 声音与画面互补

口播说明国内访问的现实门槛和云端网络边界，画面只展示两条链路的分工。

#### 主要屏幕文字

`浏览器／手机 → claude.ai`、`cloud VM → GitHub / npm`、`两条网络链路`。

### Scene 10｜按任务选择，下一集看 `/init`

#### 画面结构

中央四张取舍卡：网页版、本地 CLI、Remote Control、deep-links；右侧独立预告卡，底部留下字幕安全区。

#### 视觉动作

1. 四张卡片按“任务 → 入口”顺序进入。
2. 卡片上方合并成“先看代码跑在哪”。
3. 右侧最后出现“下一篇 12：项目初始化 · `/init`”，保持 2—3 秒。

#### 声音与画面互补

口播完成选择和预告，画面保持四种入口的层级，不增加下一篇的业务细节。

#### 主要屏幕文字

`网页版：云端、免安装、并行`、`本地 CLI：本机文件和工具`、`Remote Control：手机接管本地会话`、`deep-links：选仓库 + 填提示`、`下一篇 12：项目初始化 · /init`。

## 全片视觉类型、组件与动画标准

### 视觉类型分布

| Scene | 类型 |
|---|---|
| 01 | Opening / Process / Device Handoff |
| 02 | Concept Diagram / Comparison |
| 03 | Process / Task Routing / Cloud Sandbox |
| 04 | Comparison / Decision Diagram |
| 05 | Connection Diagram / UI Simulation |
| 06 | Comparison / Direction Diagram |
| 07 | Process / Safety Gate / UI Simulation |
| 08 | StepList / Terminal / Device Handoff |
| 09 | Concept Diagram / Network Boundary |
| 10 | Summary / Decision Cards / Teaser |

### 原型组件

- `DeviceWindow`：电脑、手机和浏览器窗口。
- `CloudVm`：一次性隔离云 VM 与任务状态。
- `RepoBranchGraph`：GitHub 仓库、云任务和分支输出。
- `DirectionGraph`：本地、云 VM、手机窗口之间的方向箭头。
- `TerminalPanel`：命令、版本、二维码和本地目录结果。
- `StepRail`：Remote Control 五步操作。
- `DecisionCard`：入口取舍和结尾总结。
- `SubtitlePill`：幕内预览字幕，固定在底部安全区。
- `PreviewControls`：上一幕／下一幕、自动播放和进度提示，仅属于原型预览。

### 动画层级

1. 信息动画：克隆、分支、连接、箭头方向、扫码、消息回传和结束状态。
2. 注意力动画：当前机器、当前会话、当前命令和“等待回车”安全闸门高亮。
3. 装饰动画：轻微渐变、边框光晕和幕间淡入，不使用无意义粒子或旋转。

### 画面标准

- 原型舞台使用 16:9 比例，主体内容保留安全边距。
- 主标题控制在 1—2 行；每幕同时出现的任务卡不超过 3 张。
- 命令使用等宽字体，辅助文字低对比度，状态颜色只表达运行、完成、等待和边界。
- 字幕固定在底部安全区；下一篇预告卡不覆盖字幕。
- 所有标题、标签、命令、状态和卡片文字都能追溯到本片 Source、Content Analysis、Video Narrative、Scene Script 或本 Visual Script。
