# Video Narrative｜Claude Code 反模式

## 视频叙事目标与定位

- 视频标题：Claude Code 反模式：常见的错误用法
- 视频 slug：`anti-patterns`
- 目标观众：已经会使用 Claude Code，但经常遇到方向跑偏、上下文变脏、结果不可信或权限确认困扰的用户。
- 叙事承诺：看完后，观众能从症状判断自己踩中了哪一个反模式，并立刻知道替换动作。

## 整体叙事结构与核心叙事

这不是一张「七个错误列表」的朗读版，而是一条从误判到自检的认知路径：

> 工具越用越糟，不一定是工具不行；先识别那些看似省事、实际上让系统失控的用法，再用范围、上下文、证据和安全边界把协作拉回可控状态。

## 叙事路径

### 第一段：先改变归因

先用「好工具也能被用废」建立问题张力，再展示七个反模式不是孤立坑，而是一条会自我放大的链。观众先理解为什么要做集中体检，而不是直接背定义。

### 第二段：逐张展示症状卡

按照从「任务输入」到「上下文」再到「信任、验证、安全、调查范围」的顺序讲七个反模式：

1. 任务太宽：一句话塞多个需求。
2. 常驻规则失焦：`CLAUDE.md` 缺失或膨胀。
3. 工作台污染：一个会话从早开到晚。
4. 信任失控：把模型当搜索引擎并全盘相信。
5. 验收缺失：不给产出验证办法。
6. 安全闸门被移除：无脑 `bypassPermissions`。
7. 探索范围失控：让它无范围调查。

每张卡都回答三个问题：症状是什么，为什么会坑，正确替换是什么。画面负责 Before／After 或状态变化，口播负责解释因果和边界。

### 第三段：把识别变成动作

用「某人的一天」做综合体检，把前面七张卡映射到七个具体行为。观众不只是记住定义，还要学会从真实操作中逐条揪出反模式。

### 第四段：压缩成可带走的规则

最后用七条速查收束：拆需求、写精规则、清上下文、查证据、给验证、保安全、限范围。总结之后，最后一个视觉事件承载下一篇第 51 篇 FAQ／Troubleshooting 预告。

## 视觉和声音的总分工

- 声音：解释「看起来为什么合理」「实际哪里失控」「什么条件下可以用」。
- 画面：展示范围变宽、上下文变满、证据缺失、权限闸门消失、调查隔离等状态变化。
- 避免：把完整口播逐字铺满屏幕；屏幕只保留症状、关键术语、动作和结果。

## 目标节奏

- 11 个横屏 Scene，16:9 构图。
- 每幕只承担一个主要认知任务。
- 每个反模式都使用短标题 + 状态对比 + 一个替换动作。
- Scene 11 先完成七条速查，再把第 51 篇预告作为最后视觉事件停留。
