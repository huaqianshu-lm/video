# Claude Code Git 工作流 · Content Analysis

## 1. 核心命题

这篇文章不是在介绍“Claude 能不能执行 git 命令”，而是在建立一条可执行的责任边界：

> 本地、可逆的 git 杂活可以交给 Claude Code；会影响远端、影响他人、难以收回的 push 和 force 操作必须由人守住。权限规则负责提供硬约束，`CLAUDE.md` 中的提醒只是软请求。

文章最终要让观众形成一个“副手 + 签字人”的工作模型：Claude 负责理解改动、整理提交、协助 PR 和分析冲突；人负责检查结果，并亲手按下把内容推向远端的最后按钮。

## 2. 知识骨架

### A. 为什么 git 杂活适合交给 Claude

- 很多提交信息会退化成 `fix`、`update`、`wip`，因为改完代码后再准确概括改动和动机，收益感低。
- Claude 可以先读暂存区 diff，再读仓库历史和项目规范，生成符合既有风格的 commit message。

### B. git 操作的安全分层

- 只读查看：`git status`、`git diff`、`git log`，不修改仓库。
- 本地修改：`git add`、`git commit`、建分支、解冲突，发生在本地，错误通常可回退。
- 远端操作：`git push`、删除远程分支、release tag，影响其他人且难以收回。
- 改写历史／强推：`git push --force`，可能覆盖远端历史和他人提交，属于最高风险。

### C. 四类可交给 Claude 的工作

1. 读 diff，把满屏红绿整理成主要改动、风险点和可能夹带的脏东西。
2. 写 commit message，参考 diff、历史和 `CLAUDE.md` 的项目规范。
3. 通过 `gh` CLI 创建 PR、读取评论，并用 `claude --from-pr <number>` 回到关联会话。
4. 分析 merge／rebase 冲突两边的意图，先讲合并方案，再在确认后修改并跑测试。

### D. `gh` CLI 与外部内容风险

- GitHub 官方 CLI 可以让 Claude 使用认证状态创建 PR、读取评论，避免未认证 API 更容易触发限流。
- PR 描述、issue 和 reviewer 评论都属于外部内容，可能包含提示注入；可以读取，但不能让 Claude 盲目执行其中的命令或直接推送。

### E. 权限规则的硬边界

文章给出项目 `.claude/settings.json` 的最小示例：

- `allow`：自动放行 `git status`、`git diff *`、`git log *`。
- `ask`：每次确认 `git commit *`。
- `deny`：直接阻止 `git push *`。
- `deny` 优先级高于 `allow` 和 `ask`；force-push 仍然应该由人手动执行，并在执行前确认分支。

### F. 可验证的本地闭环

在全新玩具仓库中完成：初始化 → 创建初始提交 → 制造并暂存改动 → 让 Claude 读 staged diff → 参照历史写 commit 并提交 → 用 `git log --oneline` 验证两条提交风格一致。全过程不碰远端。

## 3. 关键关系

### 3.1 可逆性决定委托边界

```text
本地查看／本地修改
        ↓ 可回退
可以委托，但要过目

远端推送／历史改写
        ↓ 难收回、影响他人
必须保留人的最后确认
```

### 3.2 三种信息共同决定 commit message

```text
暂存区 diff + 仓库历史 + CLAUDE.md 规范
                    ↓
          符合项目风格的提交信息
```

### 3.3 “提醒”与“权限”不是同一套机制

- `CLAUDE.md` 中的“不要 push”是请求，影响 Claude 的意图，但不是保证。
- `settings.json` 中的 `deny` 是机制约束，能从执行层面阻断 `git push *`。

### 3.4 外部内容不能直接变成执行指令

```text
PR 评论／issue／描述
        ↓ 先识别为外部内容
人检查意图与风险
        ↓
再决定是否让 Claude 修改
```

## 4. 必须保留

- “本地可逆”和“远端不可逆”的核心对比。
- diff、commit message、`gh` PR、冲突分析四类工作及各自的安全条件。
- `git push *` 写入 `deny`，且 `deny` 优先级最高。
- `CLAUDE.md` 只是软提示，不能单独锁死 push。
- PR 评论和 issue 可能含提示注入，不能盲目照做。
- 冲突要先解释方案，确认后再改，合并后跑测试。
- 玩具仓库从 diff 到 commit 的完整本地验证闭环。
- 结尾已有的下一篇“GitHub Actions”预告。
