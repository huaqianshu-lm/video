# Claude Code Git 工作流 · Video Narrative

## 1. 视频叙事目标

让观众从“git 杂活很烦、随手写 `fix` 很常见”的真实痛点出发，建立一个可以马上使用的判断框架：

> Claude 是 git 副手，不是远端发布按钮的持有人。

视频不按文章的 01～09 逐节朗读，而是按照观众需要形成判断的顺序组织：先看见问题，再划出安全边界；接着用 diff、commit、PR、冲突四个任务证明委托价值；最后用权限配置和玩具仓库闭环把“能交给它”和“必须自己守”落到操作层。

## 2. 观众认知路径

```text
提交历史里满是 fix
        ↓
先判断哪些 git 操作可逆
        ↓
看 diff：让 Claude 消化改动
        ↓
写 commit：让它沿用项目风格
        ↓
开 PR／读评论：效率与外部内容风险同时出现
        ↓
解冲突：先讲方案，再动代码
        ↓
用 allow／ask／deny 把 push 红线焊死
        ↓
在玩具仓库走通 diff → commit
        ↓
形成“副手 + 签字人”的工作流，并预告 GitHub Actions
```

## 3. Scene 结构

### Scene 01｜一串 `fix`，从痛点开始

先用提交历史中重复的 `fix`、`update`、`wip` 建立熟悉而具体的问题：不是不会写，而是改完代码后写好 message 的即时收益太低。

### Scene 02｜先划线：本地和远端不是一回事

用“报销单和最后打款按钮”的类比，把 git 分成只动本地且可回退、会影响远端且难收回两类，确立后续判断标准。

### Scene 03｜看 diff：把满屏红绿讲成人话

展示 Claude 读取 `git diff --staged`，将一坨改动整理成主要变更和风险点。观众先看到低风险、高收益的委托入口。

### Scene 04｜写 commit：diff、历史、规范汇成一句话

展示 commit message 如何参考暂存区、历史提交和 `CLAUDE.md`，并强调本地 commit 可回退，所以可以让 Claude 起草和执行，人负责过目。

### Scene 05｜开 PR：`gh` 让副手接上 GitHub

展示本地分支、`gh` CLI、PR 和会话之间的连接；说明安装并认证 `gh` 能减少未认证 API 限流，并保留 `claude --from-pr <number>` 的会话回溯价值。

### Scene 06｜读评论和解冲突：能看懂，不等于盲目照做

把 reviewer 评论的外部内容风险和 merge／rebase 冲突放在同一个“先理解、再执行”原则下：评论要防提示注入，冲突要先讲两边意图，确认后再改并跑测试。

### Scene 07｜权限规则：把 push 红线焊进机制

展示 `.claude/settings.json` 的 `allow`、`ask`、`deny` 三层配置，重点放大 `git push *` 的 deny，并解释 `deny` 优先级高于其他规则。

### Scene 08｜完整心智模型：Claude 是副手，你是签字人

把前面的任务汇总成一条流水线：本地、可逆的步骤交给 Claude；到远端推送和 force 时切回人的手。避免“什么都自己做”和“什么都甩给 AI”两个极端。

### Scene 09｜玩具仓库：先建立本地历史

进入不碰远端的 `git-demo`，执行 `git init`、创建 `calc.py`、暂存并提交初始 `add` 函数，为后面验证历史风格提供基线。

### Scene 10｜玩具仓库：制造改动，让 Claude 读 staged diff

新增 `sub` 函数并暂存；进入 Claude 会话，让它总结暂存区改动，用准确说出“新增 sub 函数”作为读取成功的可观察证据。

### Scene 11｜玩具仓库：照风格 commit，再用 log 验证

让 Claude 参考上一笔提交写中文 message 并提交，回到终端用 `git log --oneline` 看见两条 `feat:` 风格一致的提交，全程不碰 push。

### Scene 12｜小结与下一集预告

收束五个关键分工：diff、commit、PR、冲突可委托；push、force 由人守；权限规则是保证。最后承接文章已有预告：下一篇讲 GitHub Actions，把协作从本地搬到云端。

## 4. 叙事节奏

- Scene 01～02：快速建立痛点和安全判断标准。
- Scene 03～06：连续展示四个实际工作场景，声音解释原因，画面展示过程。
- Scene 07～08：把经验上升为权限机制和心智模型。
- Scene 09～11：降低抽象度，用玩具仓库给出可复核的本地闭环。
- Scene 12：短总结、停留和下一集预告，不继续引入新操作。

## 5. 叙事约束

- 不把 `git push` 作为 Claude 可自动完成的步骤；所有涉及远端的画面都明确交回人。
- 不让“安装 `gh`”抢走主线；它是 PR 工作流的前置工具，不是本篇的安装教程。
- 冲突和外部评论都遵循“先理解、再执行”的原则，避免把分析能力误写成无条件授权。
- 玩具仓库只展示本地操作，不显示远端、发布或自动推送状态。
- Scene 12 的下一集预告是最后一个视觉事件，并与口播、字幕区域分离。

## 6. Gate 1 结论

12 个 Scene 已按认知变化拆分；核心命题、信息边界、委托／风险关系和后续口播／视觉需求一致。进入 Gate 2 资料制作。
