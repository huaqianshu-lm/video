# Chrome：让它操作浏览器：Video Narrative

> 叙事目标：让观众先看见“代码改完还要切浏览器验证”的断点，再理解 Chrome 集成如何把真实浏览器接入同一对话，并在实际连接前后同时建立能力边界和安全边界。

## 1. 视频的叙事目标

视频不从“安装一个扩展”开始，而从开发者被迫在终端和浏览器之间来回切换开始。观众先看到 Chrome 集成解决的真实断点，再逐层确认它不是 MCP，也不是控制整个桌面，而是一条专门处理浏览器网页的路径。

接着用门槛筛选、六类动作、安全护栏和一个只读实战把“能做什么”和“应该把方向盘留在哪里”放在同一条线上。结尾回到“改代码 → 浏览器验证”的闭环，并留下当前文章已经给出的下一集预告。

## 3. 认知节奏

### 第一段：从断点切入

先让观众看到文件／命令行和浏览器之间的断裂：改登录表单、查 console、比设计稿都要自己切窗口。问题不是浏览器不能用，而是验证结果还没有回到同一条协作路径。

### 第二段：建立核心直觉

把 Chrome 集成表现成一个使用用户真实浏览器的“代驾”：新标签页、已有登录态、实时可见。观众先建立“它替我操作网页”的直觉，再接受后续门槛和风险。

### 第三段：切清工具边界

用一条由精准到笨重的任务路由把 MCP、Chrome 和 computer use 放在同一张图里。重点不是介绍三个产品，而是让观众知道网页任务为什么选 Chrome，以及它为什么不等于控制整个桌面。

### 第四段：先过接入门槛

四个前置条件逐项亮起，Brave、Arc、其他 Chromium 和 WSL 被引到“不支持”区域。这样后续的扩展和启动动作不会被理解成任何环境都能直接复制。

### 第五段：连接与能力展开

扩展、`claude --chrome`、`/chrome` 形成连续接力。连接成功后，六类工作沿同一条浏览器动作轨道展开，声音解释省掉的往返，画面展示点击、输入、读取和记录等状态变化。

### 第六段：把安全放回同一条链路

浏览器窗口里的登录态和网页内容被画成两类风险来源，再用登录／CAPTCHA 停手、实时可见、网站权限和人工方向盘四道闸回应。不可逆和涉钱操作从动作轨道上退回给人。

### 第七段：用最小实战收束

不拿敏感账号做演示，只读官方文档站的 `hooks` 搜索结果。扩展版本、Claude Code 版本、启动、连接和页面操作连续发生；最后补上重启 Chrome、关闭对话框和重新连接扩展的排障路径。

### 第八段：闭环与预告

把“改代码”和“在浏览器里验代码”重新接起来，复盘工具分工、连接方式、六类用例和安全原则，最后显示当前文章明确给出的下一篇“41「并行任务」”。

## 6. 叙事取舍

- 不按原文 01—07 章节逐段朗读，而按断点、直觉、边界、门槛、动作、安全、实战和总结重新组织。
- 保留文章给出的版本号、支持范围、命令和预期结果，不把 beta 功能说成稳定能力。
- 六类用例保留完整类别，但让画面用同一条动作轨道串联，避免六张并列功能卡。
- 安全不放在连接教程之后作为附录，而是在能力展开后立刻解释真实登录态的代价。
- 最小实战只展示当前文章指定的只读 `code.claude.com/docs` 搜索，不引入其他网页内容。
- 结尾预告只使用当前文章已经写出的“41「并行任务」”，不推测下一篇内容。

## 7. Gate 1 结果

- 12 个 Scene 按“痛点 → 定义 → 分工 → 门槛 → 接入 → 用例 → 风险 → 护栏 → 实战 → 闭环”推进，每个 Scene 只有一个主要认知任务。
- 所有关键命令、版本、站点、状态和用例均能回溯到 `content-analysis.md` 与 `source.md`。
- 声音承担解释与边界，画面承担浏览器动作、状态转换和证据展示，没有把口播全文直接贴到画面上。
- Scene 12 是系列预告的最后视觉事件，满足当前项目结尾规则。
