# Chrome：让它操作浏览器：Visual Script

## 全局视觉原则

- 采用 16:9 横屏、1920 × 1080 画面比例的深色科技教程风格，主色使用冷蓝，成功状态使用绿色，风险使用红色，前置提醒使用黄色。
- 声音负责解释“为什么、边界是什么、结果意味着什么”；画面负责展示浏览器动作、任务路由、状态变化和连接证据。
- 浏览器、终端、扩展设置和权限围栏使用统一窗口组件；每个 Scene 只保留一个主视觉事件，不把口播全文铺满画面。
- 动画优先表达断开、接入、分流、过闸、点击、输入、读取、停手、恢复和汇聚；不使用无意义漂浮或快速闪烁。
- 所有幕内标题、命令、版本、站点、状态、用例标签和安全规则都必须能追溯到当前 `source.md` 或本条生产资料；预览控件和进度提示只属于原型交互。

## Scene 01｜改完代码，为什么还要自己切浏览器

- **画面结构**：左侧终端窗口显示 `改代码`，右侧 Chrome 窗口显示 `浏览器验证`，中间有一条断开的连接线。
- **视觉动作**：终端中的 `登录表单`、`console`、`设计比对` 三个任务依次抵达断点，连接线短暂变红，右侧任务停在“手动切换”。
- **视觉重点**：断点，而不是浏览器功能列表。
- **幕内字幕**：`改代码`、`浏览器验证`、`手动切换`。
- **口播互补**：声音解释来回切换和复制结果的成本，画面只展示协作路径在哪里断了。

## Scene 02｜Chrome 集成，就是借用你的真浏览器

- **画面结构**：一个深色 Chrome 窗口占据主体，顶部新标签页从终端对话箭头中展开；页面右上显示 `共享登录态`，窗口边缘显示 `实时可见`。
- **视觉动作**：新标签页打开文档站，鼠标轨迹点击按钮，输入框出现文字；登录态徽章保持在页面上方，不做敏感站点细节。
- **视觉重点**：新标签页、共享登录态、可见操作三个状态同时成立。
- **幕内字幕**：`新标签页`、`共享登录态`、`实时可见`。
- **口播互补**：声音讲“借用你的浏览器”的定义，画面用连续动作证明它不是后台沙箱。

## Scene 03｜MCP、Chrome、computer use，各有主场

- **画面结构**：左侧是任务请求卡，向右经过三个路由节点：`MCP`、`Chrome`、`computer use`。
- **视觉动作**：数据库／Jira／Slack 进入 MCP，网页表单／console 进入 Chrome，原生应用／模拟器进入 computer use；Chrome 节点高亮并停留。
- **视觉重点**：任务类型决定路径，Chrome 的范围是浏览器网页。
- **幕内字幕**：`有接口` → `MCP`、`浏览器网页` → `Chrome`、`原生桌面` → `computer use`。
- **口播互补**：声音解释从精准到笨重的选择顺序，画面负责把主场差异变成分流。

## Scene 04｜连接前，先过四道门

- **画面结构**：四道横向门禁依次标注浏览器、扩展、Claude Code、套餐；右侧另有红色“不支持”出口。
- **视觉动作**：四项条件分别从灰色变绿；`Brave / Arc / 其他 Chromium` 和 `WSL` 落入红色出口，第三方提供商和仅 API key 以小标签停在门外。
- **视觉重点**：门禁先于命令，beta 提醒固定在顶部。
- **幕内字幕**：`beta`、`Chrome / Edge`、`Claude in Chrome ≥ 1.0.36`、`Claude Code ≥ 2.0.73`、`Pro / Max / Team / Enterprise`、`不支持`。
- **口播互补**：声音说明版本和套餐的意义，画面展示“条件不满足就分支失败”。

## Scene 05｜扩展、--chrome、/chrome：三步接上

- **画面结构**：左侧扩展设置，中央终端，右侧 `/chrome` 状态面板；三块由箭头连接。
- **视觉动作**：扩展从未启用切换为已启用；终端出现 `claude --chrome`；状态面板显示连接、管理权限、重新连接和选择浏览器。
- **视觉重点**：连接顺序和网站权限入口；底部以小提示显示“默认启用会增加上下文使用”。
- **幕内字幕**：`Claude in Chrome`、`claude --chrome`、`/chrome`、`扩展设置`。
- **口播互补**：声音解释 CLI 和已有会话的两种入口，以及默认启用的代价；画面展示动作顺序。

## Scene 06｜六类网页活儿，都在同一条动作轨道上

- **画面结构**：一条横向浏览器动作轨道，窗口中央只有一个主浏览器，底部六个节点依次标记任务类别。
- **视觉动作**：窗口状态快速但可读地切换：`localhost:3000` 表单提交、`console` 错误筛选、`contacts.csv` 逐行填入、Google Doc 输入、商品列表抽取 `名称 / 价格 / 库存`、GIF 时间线记录。
- **视觉重点**：浏览器动作不断变化，但“少一次手动切换”主线保持不变。
- **幕内字幕**：`测本地应用`、`读控制台`、`批量填表`、`已登录应用`、`抽取数据`、`录 GIF`。
- **口播互补**：声音概括六类工作和共同收益，画面不重复朗读，而是展示每类动作的可见结果。

## Scene 07｜真登录态，就是便利也是风险

- **画面结构**：中央是带钥匙图标的 `登录态`，左侧连到 `邮箱`、`公司后台`、`银行页面`，右侧连到一个带警示边框的网页文本块。
- **视觉动作**：左侧连接线先变绿表示便利，随后红色风险边框扩散；网页文本块出现 `提示注入` 标签但不展示额外恶意指令。
- **视觉重点**：同一来源同时带来能力和风险。
- **幕内字幕**：`登录态 = 钥匙串`、`提示注入`、`真浏览器 ≠ 沙箱`。
- **口播互补**：声音解释真实后果和外部网页的不可信，画面建立风险来源关系。

## Scene 08｜四道闸：停手、可见、圈站点、留方向盘

- **画面结构**：浏览器动作从左向右通过四道门：`登录 / CAPTCHA：停下`、`实时可见`、`圈小网站范围`、`不可逆操作：自己来`。
- **视觉动作**：遇到登录页时动作暂停；权限围栏缩小可访问站点；下单、转账、删数据三个按钮从自动轨道移到人类方向盘一侧。
- **视觉重点**：安全原则变成动作检查点，而不是警告文字堆叠。
- **幕内字幕**：`停下`、`实时可见`、`圈小权限`、`留方向盘`。
- **口播互补**：声音解释官方护栏和个人底线，画面展示什么情况下要停、什么动作不能交出。

## Scene 09｜最小实战：先确认扩展和版本

- **画面结构**：左侧模拟 `chrome://extensions`，右侧终端依次显示版本检查和启动命令。
- **视觉动作**：扩展状态显示 `已启用`、`≥ 1.0.36`；终端执行 `claude --version` 并显示 `≥ 2.0.73`；随后输入 `claude --chrome`。
- **视觉重点**：自验通过后才进入连接，不直接跳到成功结果。
- **幕内字幕**：`chrome://extensions`、`已启用`、`claude --version`、`claude --chrome`。
- **口播互补**：声音说明本次只读、不碰敏感账号，画面承担版本和状态证据。

## Scene 10｜让 Chrome 真的动起来

- **画面结构**：左侧终端对话，右侧 Chrome 新标签页，底部有一条“动作回传”轨道。
- **视觉动作**：终端显示 `/chrome` 和连接状态；Chrome 导航到 `code.claude.com/docs`，点击搜索框，输入 `hooks`；结果摘要沿轨道回到终端。
- **视觉重点**：命令、页面动作、终端结果三段连续发生。
- **幕内字幕**：`/chrome`、`code.claude.com/docs`、`hooks`、`Chrome 已连接`、`结果回到终端`。
- **口播互补**：声音解释“看到浏览器动起来并收到结果才算跑通”，画面提供可验证证据。

## Scene 11｜连不上时，先查对话框和重新连接

- **画面结构**：成功动作轨道中插入两个故障分支：首次连接的 `重启 Chrome`，页面卡住的 `alert / confirm`，闲置断连的 `重新连接扩展程序`。
- **视觉动作**：对话框遮挡点击，关闭后动作恢复；断线节点回到 `/chrome`，重新连接后再次显示结果。
- **视觉重点**：恢复路径回到同一条实战流程，不新建复杂排障系统。
- **幕内字幕**：`重启 Chrome`、`alert / confirm`、`重新连接扩展程序`。
- **口播互补**：声音讲首次连接和闲置断连的处理顺序，画面展示阻塞和恢复。

## Scene 12｜从改代码到浏览器验证，再到下一集

- **画面结构**：左侧 `改代码`，右侧 `Chrome 验证`，中央闭环箭头；下方压缩成 `MCP`、`Chrome`、`computer use` 和三条安全标签；右下为预告卡。
- **视觉动作**：闭环箭头亮起，六类用例缩成动作节点，`圈小权限`、`警惕提示注入`、`不可逆操作自己来` 依次出现；最后其他元素降暗，只保留预告卡。
- **视觉重点**：预告卡是最后一个视觉事件，停留约 2～3 秒，不与底部字幕区重叠。
- **幕内字幕**：`改代码 → Chrome 验证`、`圈小权限`、`警惕提示注入`、`不可逆操作自己来`。
- **预告卡**：`下一篇：41「并行任务」`。
- **口播互补**：声音完成复盘和预告，画面用闭环和预告卡收束，不重复全文。

## 全片视觉类型／组件／动画标准

### 视觉类型

- `Concept Diagram`：代码与浏览器断点、登录态风险。
- `Browser UI Simulation`：新标签页、表单、console、文档站搜索。
- `Task Routing`：MCP、Chrome、computer use 的主场分流。
- `Prerequisite Gate`：四项前置和不支持分支。
- `Connection Flow`：扩展、`--chrome`、`/chrome`。
- `Workflow Montage`：六类浏览器任务的连续动作。
- `Safety Flow`：登录、CAPTCHA、权限和人工方向盘。
- `Troubleshooting Flow`：重启、对话框和重新连接。

### 组件标准

- `Window`：统一深色标题栏、细边框和圆角面板。
- `Terminal`：等宽字体，命令、状态和结果分层。
- `Browser`：地址栏、新标签页、搜索框和简化页面内容。
- `RouteNode`：任务类型、工具名称和主场标签。
- `Gate`：通过使用绿色，不支持使用红色，beta 和提醒使用黄色。
- `PermissionFence`：显示站点范围可缩小，不展示真实账号信息。
- `Caption`：底部单行幕内字幕，不遮挡浏览器主体。
- `Progress`：仅服务于原型浏览，不属于正式视频画面。

### 动画标准

- 动画只表达断开、接入、分流、过闸、点击、输入、读取、停手、恢复和汇聚。
- Scene 06 的六类用例沿同一动作轨道切换，单次切换保留足够时间读取类别和结果。
- Scene 10 的“终端 → 浏览器 → 终端”必须按顺序出现，Scene 12 的预告卡最后单独停留约 2～3 秒。
- 不使用大段口播文字滚屏，不使用与知识无关的粒子、旋转或快速闪烁。

## Gate 2 内部审查结论

- Narration Script 每个 Scene 下只有实际口播，没有视觉说明、制作备注或 Gate 清单。
- Visual Script 的 12 个 Scene 与 Scene Script 的 ID、标题、认知任务和主视觉事件一一对应。
- 声音解释能力、因果、边界、排障和结论；画面展示状态变化、浏览器动作和连接证据。
- 原型所需的标题、版本、命令、站点、状态、用例、风险规则和下一篇预告均可追溯到当前生产资料。
- 本阶段停在 Visual Prototype，不生成 `tts-script.json`、音频、字幕、Timeline 或 Remotion 资料。
