# Chrome：让它操作浏览器：Content Analysis

## 1. 核心命题

Chrome 集成把 Claude Code 从“只在文件和命令行里工作”带到用户已经登录的真实浏览器中：它可以在可见的新标签页里打开网页、点击、输入、读取页面和控制台，并把“改代码”和“在浏览器里验证”接到同一个对话里。

但这不是一个无边界的自动化入口。它是实验性功能，依赖指定浏览器、扩展、Claude Code 版本和直接 Anthropic 订阅；它共享真实登录态，所以必须同时讲清工具分工、连接门槛、权限边界、提示注入风险和不可逆操作的人工把关。

## 2. 必须保留的信息

### 2.1 它是什么

- 借用用户已经登录好的 Chrome 或 Edge。
- 为浏览器任务打开新标签页，操作过程在实时可见的窗口中运行。
- 能开网页、点按钮、填表单、读页面和浏览器控制台，并继续回到代码任务中。

### 2.2 它与其他外部工具的分工

文章给出的优先级和主场是：有接口的服务优先走 MCP；shell 命令走 Bash；浏览器网页操作走 Chrome 集成；只有前面都到不了时才使用 computer use。

- MCP：数据库、Jira、Slack 等有接口的服务。
- Chrome 集成：浏览器里的网页操作。
- computer use：原生应用、模拟器和没有 API 的桌面工具。

Chrome 集成只处理浏览器，不等于控制整个桌面。

### 2.3 接入门槛和不支持范围

四个硬条件：

1. 浏览器是 Google Chrome 或 Microsoft Edge。
2. “Claude in Chrome”扩展版本为 1.0.36 或更高。
3. Claude Code 版本为 2.0.73 或更高。
4. 使用直接的 Anthropic Pro、Max、Team 或 Enterprise 计划。

通过 Amazon Bedrock、Google Cloud Vertex AI、Microsoft Foundry 或仅 API key 的访问方式不能直接使用本功能；文章说明需要单独的 claude.ai 账户。Brave、Arc 和其他基于 Chromium 的浏览器不支持，WSL 也不支持。

### 2.4 接入方式

- 安装并启用扩展。
- 用 `claude --chrome` 启动，或在已有会话中用 `/chrome` 启用。
- `/chrome` 可检查连接状态、管理权限、重新连接扩展和选择已连接浏览器。
- 可以设为默认启用，但浏览器工具常驻会增加上下文使用；更稳妥的默认习惯是只在需要浏览器的会话临时启用。
- 网站级权限从 Chrome 扩展设置继承。
- VS Code 扩展在已安装 Chrome 扩展后可直接使用浏览器自动化，不需要 CLI 标志。

### 2.5 六类高频用例

- 测本地网页应用：打开 `localhost:3000`，提交错误数据，检查校验提示。
- 读控制台调试：读取页面加载时的错误，并按目标模式过滤，不要求输出全部日志。
- 批量填表单：读取 `contacts.csv`，逐行填写 CRM 联系人。
- 操作已登录应用：在 Gmail、Notion 或 Google Docs 中写入内容，不必额外配置 API。
- 抽取结构化数据：从商品列表提取名称、价格和库存状态，保存为 CSV。
- 录制操作 GIF：把从购物车到确认页的完整流程录下来用于文档或 issue。

这些用例的共同价值不是“多了六个按钮”，而是减少手动切换浏览器、复制结果再粘回终端的往返。

### 2.6 安全边界

风险来自两个事实：浏览器共享真实登录态，网页内容又可能包含提示注入。登录的邮箱、公司后台和银行页面都可能被访问；网页中的恶意文字可能试图改变任务。

文章给出的官方护栏：

- 遇到登录页或 CAPTCHA 时暂停，要求用户手动处理。
- 操作发生在实时可见的 Chrome 窗口中。
- 网站范围由扩展设置控制。

用户自己的规则：先检查浏览器里登录了哪些敏感账号；涉钱或不可逆操作（如下单、转账、删数据）自己完成或全程盯住；把网站范围圈小；对陌生或不可信网页中的指令保持警惕。越不可逆、越涉及钱，越不能交出方向盘。

### 2.7 最小实战和排障

最小实战只读 `code.claude.com/docs` 的搜索结果，不碰敏感账号：

1. 安装扩展，并在 `chrome://extensions` 确认启用且版本不低于 1.0.36。
2. 运行 `claude --version`，确认 Claude Code 不低于 2.0.73。
3. 运行 `claude --chrome`，在会话中执行 `/chrome` 查看连接状态。
4. 发送“打开 code.claude.com/docs，点一下搜索框，输入 hooks，把出现的结果告诉我”。

预期是 Chrome 弹出新标签页、导航、点击、输入，随后终端收到结果。首次连接可能需要重启 Chrome；没有反应时检查 alert／confirm 对话框；长时间闲置断连时通过 `/chrome` 重新连接扩展。

## 3. 认知关系

### 因果关系

共享登录态 → 不需要重复认证 → 能直接操作已登录网页 → 便利增加；共享登录态 → 可接触更多敏感站点 → 风险增加，因此要收窄网站权限并人工把关不可逆动作。

浏览器在同一对话中可见 → 代码修改结果可以直接在页面中验证 → 少一次切换、复制和描述的往返。

网页内容来自外部 → 可能携带提示注入 → 读取网页时不能把页面文字自动当成任务指令。

### 对比关系

| 维度 | Chrome 集成 | MCP | computer use |
| --- | --- | --- | --- |
| 主场 | 浏览器网页 | 有接口的外部服务 | 原生桌面、模拟器、无 API 工具 |
| 范围 | Chrome／Edge 标签页 | 服务 API | 整个 macOS 桌面等更广的屏幕控制 |
| 本文角色 | 重点 | 对照 | 对照 |

同时存在“沙箱 vs 真浏览器”的安全对比：沙箱里出错相对容易重来，真浏览器中的付款、删除等动作会产生真实后果。

### 流程关系

前置条件 → 安装扩展 → `claude --chrome` → `/chrome` 验连接 → 只读页面任务 → 观察浏览器动作和终端结果 → 按需排障。

## 4. 可视觉化内容

- 文件／命令行区域向浏览器窗口扩展，表现能力边界的变化。
- 新标签页、登录态徽章和实时可见窗口，表现 Chrome 集成的核心定义。
- MCP、Chrome、computer use 三段任务路由，表现工具主场和优先级。
- 四个前置条件门槛与“不支持”分支，表现接入前的筛选。
- 扩展 → `--chrome` → `/chrome` → 页面动作的连接流程。
- 六类用例沿同一条浏览器动作轨道依次切换，避免做成六张静态卡片。
- 登录钥匙串、提示注入、权限围栏和人工方向盘组成风险／护栏关系。
- 最小实战中浏览器新标签页的导航、点击、输入和终端回报，表现真实状态变化。

## 5. 可弱化的信息

- 作者个人第一次看到鼠标操作的经历压缩为开场感受，不单独做 Scene。
- 各节重复出现的“一句话总结”不逐条复述，保留为叙事节点之间的转折。
- computer use 的套餐、平台和权限细节只保留用于边界比较的必要信息，不展开成教程。
- 六类用例的长指令不全部上屏；选择代表性的本地调试、控制台读取、批量表单和最小只读实战，其余以动作节点呈现。
- 国内网络说明保留为连接前提醒，不把网络配置扩展为本视频主题。

- “beta／可能随版本变化”必须在开场或前置条件处保留，避免把实验性功能说成稳定承诺。
