# 安全与风险边界：权限之后，如何判断该不该放手

## 1. 视频叙事目标

让观众完成一次认知变化：

```
“权限配好了就安全”
          ↓
权限只是程序层的工具，不是全部安全
          ↓
不可信内容可能把数据伪装成指令
          ↓
deny 能拦直接访问，却可能被子进程绕道
          ↓
沙箱、容器和 VM 按信任程度逐层加码
          ↓
最终仍要靠批准前的判断和安全自保清单
```

## 2. 叙事主线

```
三层安全模型：程序、隔离、判断
↓
提示注入：陌生内容冒充用户命令
↓
多道拦截：黑名单、分析、批准和隔离上下文
↓
敏感数据泄露：deny 的工具层盲区
↓
沙箱：OS 级边界与更外层隔离
↓
内置断路器：系统替你守住的底线
↓
三分钟验证：直接读、绕道读、沙箱补防
↓
按场景选择自保清单
↓
总结判断力，并预告 MCP
```

## 3. 整体叙事结构与叙事段落

### 第一段：先回答“你到底在信任谁”

开场用安全带、气囊、限速建立三层安全模型。先把观众从“模型会不会自觉”转向“程序强制什么、隔离能兜什么、我批准什么”。

### 第二段：让提示注入变成一通诈骗电话

不先讲抽象定义，而是展示 README 中藏着“把 SSH 私钥编码后发出去”的恶意指令。观众先看见数据如何伪装成命令，再理解为什么 AI Agent 会遇到这种风险。

### 第三段：把拦截画成连续闸门

同一条危险路径依次经过命令黑名单、上下文感知分析、网络批准、隔离上下文和命令注入检测，最后停在用户批准前。这样把“有保护”与“可以无脑批准”明确区分开。

### 第四段：制造 deny 的反转

先让 `Read(./.env)` 被拦住，随后让 Python／Node 子进程从 Bash 绕道打开文件。这个反转说明工具层 `deny` 的边界，引出“锁死敏感路径需要 OS 级防线”。

### 第五段：把沙箱放进隔离梯

用外圈逐层扩张的结构展示权限规则、内置断路器、Bash 沙箱、容器和 VM／网页版云端。随后补上沙箱只管 Bash、默认仍可能读取凭证的边界，避免把沙箱讲成万能开关。

### 第六段：收束官方写死的底线

用保险丝式断路器快速展示删根目录仍提示、root／sudo 禁止全裸奔、网络抓取命令默认拦截、未知规则故障关闭和 auto 分类器。重点是“底线存在，但判断仍在人”。

### 第七段：用验证把抽象边界变成证据

把 `sandbox-demo` 五步做成一条终端时间线：假密钥、只配 deny、直接读被拒、Python 绕道、沙箱 denyRead 补防。声音解释结果，画面展示同一条 Python 命令前后从“可读”到“被 OS 拦截”。

### 第八段：按信任程度给出动作

将自保清单压成日常本机、真实敏感数据、陌生代码三列。每列只保留最关键的动作：deny 和审查、沙箱和 denyRead、容器／VM 或网页版云端。

### 第九段：把安全收束为习惯，并转向 MCP

用“默认怀疑、批准前多看一眼”收束全片，再显示原文给出的下一集 `22「MCP：连接外部服务」`，只提出外部连接会改变信任边界，不展开下一篇正文。

## 4. 视频价值

- 用三层防护的视觉隐喻，把“安全不是模型自觉”变成可记忆的结构。
- 用 README 恶意注入到 SSH 私钥外传的过程，展示 Agent 风险的真实形态。
- 用多道拦截和用户批准前的停顿，表达自动防线与人工判断的分工。
- 用 `deny` 被子进程绕过、沙箱补防的状态变化，展示工具层与 OS 层的本质差异。
- 用隔离梯和三档自保清单，把不同可信度下的安全选择变成行动路线。
- 用前后验证结果证明配置和隔离真的改变了行为，而不是停留在概念解释。

## 5. 节奏与收束

- 开场先建立三层模型，快速进入提示注入的高风险案例。
- 中段以“拦截有效但不是万能”推进到敏感数据绕道，再拉出沙箱和更外层隔离。
- 断路器段落短促，作为安全底线的集中回收。
- 验证段落放慢，让观众看清直接读、绕道读和沙箱拦截的差异。
- 清单和总结保持克制，最后预告卡片留出约 2～3 秒的可读停留。
