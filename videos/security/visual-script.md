# 安全与风险边界：到底该不该信任 AI 碰你的代码

## 全局视觉原则

- 采用 16:9 横屏、深色、克制的科技教程风格；视觉中心从“审批闸门”逐步扩展为“隔离层与信任梯”。
- 声音负责解释风险、因果、边界和判断；画面负责展示恶意路径、拦截状态、绕道过程、隔离范围和前后结果，不逐字复述口播。
- 每幕只保留一个主要视觉动作；长命令、长 JSON 和完整清单只展示可识别的关键片段。
- 绿色表示被阻断后的安全或可恢复状态，红色表示高风险、外传或拒绝，蓝紫表示机制、路径和过渡；不使用刺眼发光。
- 主标题、主体面板和底部字幕保持空间分离；预览按钮、进度提示和说明文字只属于 HTML 外壳，不进入视频内容。

## 逐 Scene 视觉设计

### Scene 01｜你在信任谁？

- 画面结构：中央为“Claude Code”节点，向外连接三层环形防护：程序强制、内置保护与隔离、你的判断。
- 视觉动作：先锁定权限闸门，再展开断路器和隔离墙，最后出现用户眼睛／批准节点。
- 状态变化：模型自觉的软期待淡出，程序强制的硬边界变亮。
- 口播互补：口播解释三层模型，画面用同心层展示防护不是单点开关。
- 画面文字：`程序强制`、`内置保护与隔离`、`你的判断`、`权限规则`
- Visual Type：`Concept Diagram + Security Model`

### Scene 02｜README 里藏着一封写给 AI 的诈骗邮件

- 画面结构：左侧是 `README.md` 内容面板，右侧是 Claude 读取内容后的动作链，底部是 SSH 私钥和外部地址。
- 视觉动作：普通“总结项目”任务出现后，README 注释高亮；箭头从 `~/.ssh/id_rsa` 指向 `evil.example.com`。
- 状态变化：`数据` 标签被恶意文字伪装成 `指令`，风险路径变红。
- 口播互补：口播解释提示注入的含义，画面展示凭证从本地路径到外部地址的具体路径。
- 画面文字：`README.md`、`数据`、`指令`、`~/.ssh/id_rsa`、`evil.example.com`
- Visual Type：`Prompt Injection Demo + Data Exfiltration`

### Scene 03｜危险命令会经过几道拦截？

- 画面结构：一条红色 `curl` 外传路径横穿五个拦截节点，终点是用户批准面板。
- 视觉动作：命令黑名单先亮红；上下文分析、网络请求批准、隔离上下文和命令注入检测依次显示“检查”；最后批准按钮停留不点击。
- 状态变化：自动拦截逐步收紧，但最终的 `批准前审查` 保持可操作状态。
- 口播互补：口播说明各道机制的职责，画面只表现路径如何被截停和等待决定。
- 画面文字：`命令黑名单`、`上下文分析`、`网络请求批准`、`隔离上下文`、`命令注入检测`、`批准前审查`
- Visual Type：`Security Pipeline + Process`

### Scene 04｜deny 挡住明枪，挡不住暗箭

- 画面结构：中间放置敏感文件 `.env`，左侧是内置 `Read`，右侧是 `Bash → Python / Node`。
- 视觉动作：`Read(./.env)` 进入工具闸门后变为“拒绝”；脚本箭头绕过工具闸门后仍触达 `.env`。
- 状态变化：同一个敏感文件同时出现“直接读取被挡”和“子进程绕道可达”。
- 口播互补：口播解释工具层边界，画面用两条不同路径证明覆盖范围不同。
- 画面文字：`Read(./.env)`、`Bash`、`Python / Node`、`绕道读取`、`deny 有盲区`
- Visual Type：`Security Boundary + Process`

### Scene 05｜沙箱不是 deny 的同义词

- 画面结构：内圈为工具层 `deny`，外圈为 OS 级沙箱；圈外标注内置文件工具、MCP server、Hook 的未覆盖区域。
- 视觉动作：Python 子进程从内圈绕出后撞上沙箱外墙；`.env`、`~/.ssh/` 和 `~/.aws/credentials` 作为需显式 `denyRead` 的路径亮起。
- 状态变化：工具层“软约束”升级为进程访问的“硬隔离”，但未覆盖对象保留警示色。
- 口播互补：口播解释沙箱的功能和限制，画面用空间边界呈现“管什么、不管什么”。
- 画面文字：`工具层`、`OS 级`、`Bash 子进程`、`denyRead`、`MCP server`、`Hook`
- Visual Type：`Comparison + OS Isolation Diagram`

### Scene 06｜信任越低，隔离越要往外加

- 画面结构：五级横向隔离梯：权限规则、内置断路器、Bash 沙箱、容器、VM／网页版云端；右侧是信任度从高到低的三种代码来源。
- 视觉动作：陌生仓库从本机入口被推向容器和 VM；`--dangerously-skip-permissions` 只在隔离层内显示可进入。
- 状态变化：代码可信度降低，隔离边界向外扩张，本机入口变为红色禁止。
- 口播互补：口播说明不同项目的推荐隔离，画面表现“越不信任越往外”的方向。
- 画面文字：`权限规则`、`内置断路器`、`Bash 沙箱`、`容器`、`VM / 网页版云端`、`完全陌生`
- Visual Type：`Trust Gradient + Layered Isolation`

### Scene 07｜官方写死的几条底线

- 画面结构：四张保险丝卡片和一条 `fail-closed` 闸门，底部保留用户批准入口。
- 视觉动作：`rm -rf /`、`rm -rf ~`、`root / sudo`、`curl / wget` 依次触发断路器；未知命令进入手动批准；`auto` 分类器在旁边扫描。
- 状态变化：危险动作被拦或转为询问，画面最后强调“底线不是判断”。
- 口播互补：口播解释保护的范围，画面用状态标签区别“拒绝”“仍提示”和“分类检查”。
- 画面文字：`rm -rf /`、`rm -rf ~`、`root / sudo`、`curl / wget`、`fail-closed`、`auto`
- Visual Type：`Circuit Breaker + Rule Status`

### Scene 08｜三分钟验证：绕道读密钥，沙箱能不能挡住？

- 画面结构：终端时间线从 `sandbox-demo`、假 `.env`、只配 deny、直接 Read，到 Python 绕道和沙箱 `denyRead` 前后对比。
- 视觉动作：直接 Read 显示“拒绝”；未开沙箱的 Python 路径显示“可能读到”；开启沙箱后，同一条路径变为“被 OS 拦截”。
- 状态变化：一个命令在两种隔离状态下得到相反结果，最后合并成 `deny + 沙箱 = 深度防御`。
- 口播互补：口播带领验证逻辑，画面突出同一命令前后状态变化。
- 画面文字：`sandbox-demo`、`Read(./.env)`、`python3`、`denyRead`、`被 OS 拦截`、`深度防御`
- Visual Type：`Terminal Demo + Before / After`

### Scene 09｜安全自保清单：按信任程度对号入座

- 画面结构：三列风险卡：日常本机、真实敏感数据、陌生代码；每列只出现三项关键动作。
- 视觉动作：风险从左向右升高，`deny`、沙箱、凭证 `denyRead`、容器／VM 依次点亮；批准前审查贯穿三列上方。
- 状态变化：从“本机可控”切换为“外层隔离优先”，第三列的本机裸跑入口被封锁。
- 口播互补：口播解释三档策略，画面把清单压缩为风险匹配关系。
- 画面文字：`日常本机`、`真实敏感数据`、`陌生代码`、`批准前看一眼`、`沙箱`、`容器 / VM`
- Visual Type：`Checklist + Risk Matrix`

### Scene 10｜安全不是开关，而是判断力

- 画面结构：三层安全模型、隔离梯和批准节点收成一条路线，右侧出现下一集卡片。
- 视觉动作：`程序强制 → 隔离加码 → 默认怀疑 → 批准前多看一眼` 依次落位，随后转场到 `22「MCP：连接外部服务」`。
- 状态变化：本篇的“安全判断”完成，下一集只出现标题和外部连接的信任边界提示。
- 口播互补：口播总结习惯并提出下一篇问题，画面不展开 MCP 正文。
- 画面文字：`默认怀疑`、`批准前多看一眼`、`安全不是开关`、`22「MCP：连接外部服务」`
- Visual Type：`Summary Diagram + Next Episode Card`

## 全片视觉类型、组件与动画标准

### 视觉类型

- 三层安全模型：Concept Diagram + Security Model。
- 提示注入与外传：Prompt Injection Demo + Data Exfiltration。
- 多道拦截与断路器：Security Pipeline + Circuit Breaker。
- deny 绕道与沙箱：Security Boundary + OS Isolation。
- 信任梯与自保清单：Trust Gradient + Risk Matrix。
- 终端验证与前后结果：Terminal Demo + Before／After。
- 结尾收束与下一集卡片：Summary Diagram + Next Episode Card。

### 组件语言

- 深色背景、蓝紫机制强调、绿色表示安全或被阻断后的可恢复状态、红色表示外传、高风险或本机裸跑。
- 面板使用细边框、统一圆角和轻微阴影；危险路径使用低饱和红色，不使用刺眼发光。
- 代码、路径、命令和配置使用等宽字体；普通解释文字保持清晰层级。
- 主标题控制在一至两行；终端只展示关键命令和结果，不塞入完整文章段落。
- 底部字幕区域与主体面板分离；上一幕、下一幕、自动播放、进度提示和原型说明只属于 HTML 外壳。

### 动画顺序

1. 先出现环境、内容或敏感路径。
2. 再进入恶意路径、工具调用或规则匹配。
3. 发生拦截、绕道、隔离、信任升级或状态反转。
4. 最后高亮本幕唯一结论，并为下一幕留下清晰入口。

## Gate 2 内部审查结论

- `narration-script.md` 每个 Scene 下只有实际口播，没有视觉说明、制作备注、Gate 清单或 TTS 指令。
- 视觉与口播分工清晰：口播解释安全模型、攻击机制、隔离边界和判断方法；画面展示路径、闸门、空间边界、状态变化和验证结果。
- 所有画面文字均可追溯到指定原文或本篇前置生产资料；未引入下一篇 `MCP` 正文，只使用当前原文末尾的标题预告。
- 10 个 Scene 的横屏构图、信息密度和动画事件可由无依赖 HTML + CSS + 少量 JS 表达。
- 本阶段到 Visual Prototype 为止，不生成 `tts-script.json`、音频、字幕、Timeline，不修改 `src/videos/`。
