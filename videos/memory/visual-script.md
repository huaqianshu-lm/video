# Claude Code「记忆系统」视频化 · Visual Script

> 目标：用横屏过程化画面证明记忆的分工、写入、加载、审计和筛选。口播负责解释，画面负责展示状态和关系。

## 全局视觉原则

### 1. 画面演示记忆如何变化

不把“记忆系统”做成静态功能列表，而是让 8081 变旧、`Writing memory` 出现、`MEMORY.md` 落盘、下一会话 `Recalled memory` 发生。

### 2. 两套系统保持视觉分色

CLAUDE.md 使用冷蓝色，表示正式规则；自动记忆使用暖紫色，表示私人经验。两条路径最终汇入同一个“新会话上下文”，但不合并成同一种纸张。

### 3. 口播解释，画面证明

口播解释“谁写、为什么记、如何判断”；画面展示文件、状态、命令、分流和时间线，避免逐句把口播做成大字卡。

### 4. 每幕一个视觉中心

每个 Scene 只保留一个主要过程：风险、双通路、加载边界、审计、筛选或验证。屏幕文字控制在 1—2 行或少量标签。

### 5. 横屏构图克制

使用 1920 × 1080 的深色背景、居中的内容容器和左右留白。字幕预留底部安全区，核心卡片不压到底部字幕区域；预告卡片与字幕区域分离。

## 逐 Scene 视觉设计

### Scene 01｜记错的 8081

- **场景容器**：左侧显示“这次先用 8081”的记忆条目，右侧显示两周后的项目状态。
- **视觉动作**：8081 先亮起绿色“当前使用”，随后变灰并标注“已废弃”；右侧 Claude 提示气泡仍引用 8081，出现轻微红色警示。
- **信息重点**：旧记忆不是无害的历史，而可能成为未来的错误依据。
- **口播互补**：口播讲“记错比不记还坑”，画面只负责证明信息状态已经过期。
- **屏幕文字**：`8081`、`已废弃`、`未来误导`

### Scene 02｜两套记忆并行

- **场景容器**：左右两栏分别放一张“正式守则”和一张“私人笔记”，底部放新会话上下文。
- **视觉动作**：两张纸沿不同路径向下流动，最后汇入同一上下文容器；路径颜色保持不同。
- **信息重点**：两套系统并行存在，不是同一个记忆池。
- **口播互补**：口播解释两套系统由谁写、分别管什么；画面展示并行关系。
- **屏幕文字**：`CLAUDE.md`、`自动记忆`、`新会话上下文`

### Scene 03｜CLAUDE.md

- **场景容器**：一张带项目目录图钉的文档卡，旁边是三条规则标签。
- **视觉动作**：依次出现“用户手动写”“规则和指令”“项目级共享”“全量加载”。
- **信息重点**：CLAUDE.md 是正式规则，不是 Claude 自己的心得。
- **口播互补**：口播解释规则的共享属性和职责边界；画面展示文档属性。
- **屏幕文字**：`用户手动写`、`规则和指令`、`项目级共享`

### Scene 04｜自动记忆

- **场景容器**：终端对话窗口与旁侧 MEMORY.md 卡片。
- **视觉动作**：用户输入“记住：构建命令是 make build”，终端出现 `Writing memory`，文件卡新增一条记录；切换为新会话后显示 `Recalled memory`。
- **信息重点**：自动记忆既可以被明确要求写入，也可能从纠正中学习。
- **口播互补**：口播解释触发方式，画面展示写入和召回两个状态。
- **屏幕文字**：`记住：构建命令是 make build`、`Writing memory`、`Recalled memory`

### Scene 05｜存储与加载边界

- **场景容器**：左侧文件树，右侧 MEMORY.md 的纵向内容条和加载窗口。
- **视觉动作**：文件树展开到 `memory/`；加载窗口从顶部覆盖到“200 行／25KB”边界，边界以下内容变为“按需读取”。
- **信息重点**：`MEMORY.md` 是入口，自动加载有明确上限。
- **口播互补**：口播给出路径和上限，画面把“只加载一部分”变成遮罩效果。
- **屏幕文字**：`~/.claude/projects/<project>/memory/`、`MEMORY.md`、`前 200 行或 25KB`

### Scene 06｜/memory

- **场景容器**：命令输入条上方浮出记忆管理面板。
- **视觉动作**：`/memory` 输入后，依次点亮“查看加载文件”“打开目录”“编辑／删除”“自动记忆开关”。
- **信息重点**：自动记忆可审计、可修改、可删除、可关闭。
- **口播互补**：口播解释控制权，画面用四个真实状态反馈替代抽象承诺。
- **屏幕文字**：`/memory`、`读`、`改`、`删`、`ON / OFF`

### Scene 07｜三道筛选

- **场景容器**：中间三道门，左侧为候选记忆条目，右侧分成“值得记”和“不要记”。
- **视觉动作**：候选条目依次通过“会不会变”“能不能复用”“敏不敏感”三道门；8081、临时变量、token 在拒绝区，构建命令、架构事实在保留区。
- **信息重点**：记忆质量由筛选决定，不由数量决定。
- **口播互补**：口播讲三条原则，画面展示具体条目的分流。
- **屏幕文字**：`会不会变？`、`能不能复用？`、`敏不敏感？`

### Scene 08｜# 的新旧入口

- **场景容器**：旧入口 `#` 位于左侧灰色区域，右侧是三个当前入口。
- **视觉动作**：`#` 逐渐淡出；三条线分别指向“自动记忆”“Git 守则”“审计和删改”。
- **信息重点**：记住、共享规则、审计是三个不同动作。
- **口播互补**：口播说明旧做法和当前做法的差异，画面展示目标分流。
- **屏幕文字**：`#`、`记住 xxx`、`加进 CLAUDE.md`、`/memory`

### Scene 09｜记一条并落盘

- **场景容器**：横向终端时间线，底部同步显示文件卡。
- **视觉动作**：`mkdir memory-demo` → `cd memory-demo` → `claude` → 记忆请求 → `Writing memory`；最后 MEMORY.md 新行闪亮。
- **信息重点**：记忆从对话请求变成机器上的 Markdown 文件。
- **口播互补**：口播带过操作顺序，画面突出“写入提示”和文件落盘。
- **屏幕文字**：`mkdir memory-demo`、`claude`、`make build`、`Writing memory`

### Scene 10｜换会话验证召回

- **场景容器**：会话 A、MEMORY.md、会话 B 三段横向时间线。
- **视觉动作**：会话 A 写入后关闭，记忆文件保留；会话 B 提问“这个项目怎么构建？”，答案出现 `make build` 和 `Recalled memory`；右下角保留删除图标。
- **信息重点**：跨会话召回是记忆真正生效的证据，错误记忆可以清理。
- **口播互补**：口播说明退出重进和可选删除，画面展示内容跨越会话边界。
- **屏幕文字**：`/exit`、`这个项目怎么构建？`、`make build`、`Recalled memory`

### Scene 11｜记住该记的

- **场景容器**：三列归位图：CLAUDE.md、自动记忆、不要记。
- **视觉动作**：规则卡进入 CLAUDE.md，稳定经验进入自动记忆，临时和敏感条目进入“不要记”；`/memory` 作为顶部审计入口。
- **信息重点**：形成可执行的最终心智模型。
- **口播互补**：口播说结论，画面把分散判断收束为三栏。
- **屏幕文字**：`规则 → CLAUDE.md`、`经验 → 自动记忆`、`不要记`

### Scene 12｜下一集预告

- **场景容器**：中央预告卡，顶部保留系列标签，底部字幕安全区留空。
- **视觉动作**：左侧“记忆”卡写入“被动记住事实”，右侧“Skills”卡淡入“主动封装能力”；右卡作为最后停留元素。
- **信息重点**：当前视频结束，下一集主题被明确预告。
- **口播互补**：口播承接文章最后的对照，画面只保留预告主题和一句关系说明。
- **屏幕文字**：`26「Agent Skills」`、`记忆：被动记住事实`、`Skills：主动封装能力`

## 全片视觉类型、组件与动画标准

### 视觉类型

- `StateChangeDemo`：Scene 01、04、10，用于表现过期、写入和召回。
- `DualPathDiagram`：Scene 02、03，用于表现两套系统和规则属性。
- `FileTreeBoundary`：Scene 05，用于表现目录和加载上限。
- `CommandPanel`：Scene 06、08、09，用于表现入口、审计和实操。
- `FilterFlow`：Scene 07、11，用于表现判断和归位。
- `PreviewCard`：Scene 12，用于系列预告。

### 组件标准

- 深色背景、圆角窗口、轻边框和克制发光。
- 规则使用冷蓝色，自动记忆使用暖紫色，警告使用低饱和红色，成功使用绿色。
- 终端和文件树使用等宽字体；解释性文字使用清晰无衬线字体。
- 主标题控制在 1—2 行，标签只保留当前视觉动作所需的内容。
- 预览按钮、进度提示和自动播放控件只属于 HTML 原型，不属于后续 Composition 或 MP4。

### 动画标准

- 状态变化用 300—500ms 淡入、变色或位移表达因果，不使用无意义弹跳。
- 流程节点按口播顺序逐个出现，前一节点完成后再连接下一节点。
- 文件树展开和加载遮罩从上到下发生，直观表达“读取范围”。
- 三道筛选门保持同一节奏，拒绝区与保留区状态明确。
- Scene 12 至少保留约 2—3 秒的可读停留，且预告卡不覆盖字幕安全区。
