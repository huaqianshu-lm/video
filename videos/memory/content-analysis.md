# Claude Code「记忆系统」视频化 · Content Analysis

> 目标：从指定原始文章中提取这条视频必须讲清的认知、事实边界和可视觉化过程。本文只使用 `25-memory.md` 的内容，不延展下一篇文章。

## 1. 核心命题

这篇文章真正要解决的不是“Claude 会不会记东西”，而是：

> **Claude Code 的记忆分成两套：人写的 CLAUDE.md 负责规则，Claude 自己写的自动记忆负责经验；记忆的价值不在数量，而在稳定、可复用和准确。**

观众最后应该形成一个可执行的判断：

```text
规则 → 写进 CLAUDE.md
经验 → 交给自动记忆
会变、一次性、敏感 → 不要记
需要审计 → 用 /memory
```

## 2. 必须保留的信息

### A. 两套记忆的分工

| 维度 | CLAUDE.md | 自动记忆（auto-memory） |
|---|---|---|
| 谁写 | 用户手动写 | Claude 自己写，也可由用户要求它记 |
| 内容 | 指令、规则、项目守则 | 构建命令、调试心得、架构笔记、代码风格和工作流习惯 |
| 范围 | 用户、项目或本地级；项目级可进版本控制共享 | 每个 Git 仓库一份，机器本地，worktree 共享 |
| 加载 | 每次会话全量加载 | 每次会话加载 `MEMORY.md` 前 200 行或 25KB，以先到者为准 |

必须说清：两者都是上下文，不是硬性的权限拦截；要真正阻止操作，仍需要权限规则或 hook。

### B. 自动记忆如何产生

- 用户直接说“记住……”时，Claude 可以保存这条信息。
- Claude 也可能从用户的纠正中判断出可复用的规律并记下。
- 界面上的 `Writing memory` 和 `Recalled memory` 分别表示写入和读回。

### C. 自动记忆存在哪里、怎么加载

自动记忆目录位于：

```text
~/.claude/projects/<project>/memory/
├── MEMORY.md
├── debugging.md
├── api-conventions.md
└── ...
```

`MEMORY.md` 是入口和索引。详细主题可以拆到其他 Markdown 文件；新会话自动加载的只有 `MEMORY.md` 前 200 行或前 25KB，主题文件需要时再读取。

### D. `/memory` 的审计作用

在会话中输入 `/memory` 可以：

- 查看当前会话加载的记忆文件。
- 打开自动记忆目录，阅读、修改和删除 Markdown 记忆。
- 切换自动记忆开关。

文章还给出两种关闭方式：项目级 `settings.json` 中的 `autoMemoryEnabled: false`，以及临时环境变量 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`。

### E. 该记什么、不该记什么

三条判断原则：

1. 会不会变：临时端口、临时变量和当前状态不要记。
2. 能不能复用：构建命令、架构事实和稳定调试心得值得记。
3. 敏不敏感：密码、API key、token 绝对不能写进记忆文件。

开头的 8081 端口例子必须保留，因为它把“记错比不记更危险”具体化了。

### F. `#` 快捷键的当前处理

文章明确把 `#` 定义为早期做法，不应继续作为当前入口。现在的分工是：

```text
记住 xxx       → 自动记忆
加进 CLAUDE.md → Git 守则、团队共享
/memory        → 查改删和开关
```

## 3. 因果关系

```text
啥都往记忆里塞
↓
过时信息和临时状态积累
↓
真正重要的经验被淹没
↓
Claude 可能用旧信息误导后续会话
↓
需要按“稳定、复用、非敏感”筛选，并定期用 /memory 审计
```

## 4. 流程关系：把一条记忆跑通

文章给出的最小验证流程是：

```text
mkdir memory-demo
↓
cd memory-demo
↓
claude
↓
说“记住：这个项目的构建命令是 make build，不是 npm build”
↓
看到 Writing memory
↓
/memory 或 cat 确认写入 MEMORY.md
↓
/exit 后重新进入
↓
询问项目怎么构建
↓
看到 Recalled memory，并得到 make build
```

可选的最后一步是删除该记忆，验证清理也会生效。
