# Claude Code「记忆系统」视频化 · Narration Script

## Scene 01｜记错的 8081

刚开始接触记忆功能时，很多人会下意识地觉得，记得越多就越聪明。

比如这次先用 8081 端口，就顺手让它记下来。

问题是，两周以后这个端口早就废弃了，它却还拿着这条旧信息一本正经地提醒你。

这时候你会发现，记错了比不记还坑。

## Scene 02｜两套记忆并行

所以，Claude Code 的记忆不是一套，而是两套并行的系统。

一套是你手写的 CLAUDE.md，里面放项目规则和工作守则。

另一套是 Claude 自己写的自动记忆，里面放它在工作中积累的经验和模式。

两种内容都会影响新会话的上下文，但它们的来源、范围和用途完全不同。

## Scene 03｜CLAUDE.md

CLAUDE.md 更像是你钉在显示器旁边的正式守则。

它由你手动维护，适合放编程标准、项目架构和提交流程，也可以进入版本控制，让团队共享。

每次会话都会把它完整加载进来。

简单说，CLAUDE.md 解决的是：你希望 Claude 按什么规则工作。

## Scene 04｜自动记忆

自动记忆更像是 Claude 自己攒下来的私人笔记。

你可以直接说“记住，这个项目的构建命令是 make build，不是 npm build”。

它也可能从你的纠正里学到一条以后还用得上的规律。

当界面出现 Writing memory，说明它正在写入；下次会话出现 Recalled memory，说明它正在把记忆读回来。

## Scene 05｜存储与加载边界

这些笔记放在 `~/.claude/projects/<project>/memory/` 目录里。

其中的 MEMORY.md 是入口和索引，调试心得、接口约定之类的详细内容，可以拆到其他 Markdown 文件中。

新会话并不会把所有内容无限加载，而是只自动读取 MEMORY.md 的前 200 行，或者前 25KB，以先到的为准。

## Scene 06｜/memory

那它自己记的东西，会不会变成一个你看不见的黑箱？

不会。

在会话里输入 `/memory`，你可以查看当前加载了哪些记忆文件，打开自动记忆目录，直接读、改、删里面的 Markdown，也可以切换自动记忆的开关。

如果不想让它自动记，还可以在设置里关闭，或者用环境变量临时关闭。

## Scene 07｜三道筛选

真正难的不是让它记，而是判断什么值得记。

可以先问自己三个问题：这条信息会不会很快变化？以后还能不能复用？里面有没有密码、API key 或 token 这样的敏感内容？

临时端口、临时变量和当前正在调试的页面，不要记。

稳定的构建命令、项目架构事实和反复会用到的调试心得，才值得记。

## Scene 08｜# 的新旧入口

还有一个容易被旧教程带偏的地方：井号这个老快捷键。

文章给出的判断是，`#` 属于早期做法，现在不要再把它当成当前入口。

想让 Claude 记一条，就说“记住”；想让团队共享一条规则，就明确说“加进 CLAUDE.md”；需要检查、修改或删除记忆，就用 `/memory`。

## Scene 09｜记一条并落盘

下面把整条流程跑一遍。

先建立一个 memory-demo 目录，进入以后启动 Claude。

然后告诉它：记住，这个项目的构建命令是 make build，不是 npm build。

看到 Writing memory 之后，用 `/memory` 查看，或者在终端里检查 MEMORY.md，确认这条内容已经从对话落到了文件。

## Scene 10｜换会话验证召回

接下来退出当前会话，再重新启动 Claude。

在全新的会话里问它：这个项目怎么构建？

如果它直接回答 make build，并且出现 Recalled memory，就说明这条记忆真的跨会话生效了。

如果哪天发现它记错了，也可以回到 `/memory` 把那条笔记删掉。

## Scene 11｜记住该记的

把整篇文章压缩成一句话：记忆不是越多越好，而是该记的记准，不该记的别碰。

规则写进 CLAUDE.md，经验交给自动记忆；会变的、只用一次的、敏感的内容，不要让它留下来。

这样，Claude 才是在跨会话变得更懂你的工作，而不是背着一堆过期信息继续误导你。

## Scene 12｜下一集预告

这一篇讲的是让 Claude 被动记住事实。

下一篇 26「Agent Skills」，会继续往前一步，聊怎么把反复要它做的工作，主动封装成一项它可以按需调用的能力。

记忆让它更懂你，Skills 让它会得更多。
