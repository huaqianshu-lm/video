# Claude Code「记忆系统」视频化 · Video Narrative

> 目标：把文章重新组织成一条让观众能判断“什么该记、记在哪里、如何审计”的视频叙事。

## 1. 视频叙事目标

观众的认知变化应当是：

```text
记得越多越聪明
↓
过时记忆可能反过来误导
↓
记忆其实分 CLAUDE.md 和自动记忆两套
↓
两套系统的写入者、内容、范围和加载方式不同
↓
自动记忆可以被写入、召回和审计
↓
记忆前要过“会变、复用、敏感”三道筛选
↓
一条记忆要经过落盘和新会话召回才算真正生效
```

核心结论：

> **记忆不是越多越好，而是该记的记准，不该记的别碰。**

## 3. 叙事推进

### 第一段：先让观众看见风险

用“曾经有用的 8081 端口”开场。它不是为了讲端口，而是证明：如果记忆不筛选，Claude 会拿过时信息一本正经地误导未来会话。

### 第二段：给出系统地图

立刻把记忆拆成 CLAUDE.md 和自动记忆两条通路。通过“正式工作守则”和“显示器旁便利贴”的对比，让观众先建立分工，而不是把所有记忆混成一类。

### 第三段：解释自动记忆的机制

从“谁写、记什么、何时触发”推进到“存在哪里、加载多少”。200 行／25KB 是画面中的边界，不用大段口播背表格。

### 第四段：把控制权交还给用户

用 `/memory` 展示记忆不是黑箱；再用三道筛选门解释用户在主动要求记忆时如何判断。这里形成全片的实用方法。

### 第五段：用最小实验完成验证

把文章的 `memory-demo` 流程做成连续过程：让它记、看到 `Writing memory`、检查 `MEMORY.md`、退出重进、看到 `Recalled memory`。观众看到的是“记忆如何跨会话生效”，不是命令清单。

### 第六段：收束与预告

总结两套系统和三道筛选，明确 `#` 不再是当前入口，并保留源文档中的下一集 `26「Agent Skills」` 主题预告。

## 4. 叙事边界

- 不把 CLAUDE.md 讲成自动记忆，也不把自动记忆讲成 Git 团队规则。
- 不把“上下文”误说成“硬权限”；记忆只是影响行为的软提示。
- 不把 `#` 旧做法包装成推荐技巧。
- 不延展 Agent Skills 的具体内容；预告只承担系列承接作用。
