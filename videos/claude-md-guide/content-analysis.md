# Claude.md 使用指南视频化 · 第一步：Content Analysis

> 来源：`source.md`（对应外部文章 `18-claude-md-guide.md`）。本分析只处理 CLAUDE.md 的写法、加载、引用、维护和验证，不扩展到下一篇文章的上下文管理正文。

## 1. 核心命题

CLAUDE.md 是 Claude Code 每次会话都会读取的项目记忆文件，适合保存每个会话都应保持的项目事实和可验证规则；它能稳定塑造行为，但不是能够百分之百强制执行的铁律。

真正有效的 CLAUDE.md 不是越长越好，而是把项目中 Claude 无法仅靠读代码推断、又需要每次遵守的关键约定，写得具体、短小、可验证。长篇背景、过时信息和可由代码自证的内容会消耗上下文，并稀释真正重要的规则。

## 2. 必须保留的信息

### A. 它解决的实际问题

- 每个会话从白纸开始，上次对话里的包管理器、禁改目录和测试命令不会自动保留。
- CLAUDE.md 像每天重读的入职手册，让项目约定在新会话中重新出现。
- 典型失败不是 Claude 完全不听，而是重要规则被大量背景和废话埋没。

### B. 它的边界

- 文件内容作为用户消息传递，在系统提示之后加载。
- Claude 会尝试遵循，但没有严格遵守的保证。
- 需要真正阻止危险操作时，应该使用 Hook 等硬性机制；CLAUDE.md 负责提供清晰的项目指导。

### C. 三个主要层级和一个本地变体

| 层级 | 范围 | 版本控制含义 |
| --- | --- | --- |
| 用户级 `~/.claude/CLAUDE.md` | 当前机器上的所有项目 | 个人偏好，不进项目 Git |
| 项目级 `./CLAUDE.md` 或 `./.claude/CLAUDE.md` | 当前项目 | 团队共享，通常进入 Git |
| 子目录级 `任意子目录/CLAUDE.md` | Claude 读到该目录文件时 | 大仓库的模块细则，进入 Git |
| 本地级 `./CLAUDE.local.md` | 当前项目，仅当前用户 | 不进 Git，需加入 `.gitignore` |

加载方向是从范围最广到最具体，越靠近当前工作目录的内容越晚读取。多个文件是拼接，不是覆盖；子目录级文件按需加载。项目根文件在 `/compact` 后会重新从磁盘读取，嵌套文件则要等再次读到对应目录。

### D. 应该写入的五类长期事实

1. 项目概述：一句话说清项目是什么。
2. 技术栈：语言、框架、数据库和关键工具。
3. 常用命令：测试、构建和检查的准确命令。
4. 代码约定：命名、写法和必须遵守的工程规则。
5. 明确的不要做：禁改目录、必须先问的操作和敏感边界。

常用命令和禁止清单尤其有价值，因为 Claude 不应靠猜来决定包管理器、验证方式或可修改范围。

### E. 应该删除的内容和大小边界

- 公司介绍、产品愿景和技术选型历史等长篇背景。
- 已经过时的包管理器、构建命令或依赖说明。
- Claude 读代码就能推断的目录结构和已有配置规则。
- “尽量整洁”“注意安全”这类无法一眼验证的模糊散文。

官方建议每个 CLAUDE.md 目标控制在 200 行以内。文章用“写了三百行却没人听”说明：额外文本同时消耗上下文、稀释注意力，并不等于更强的约束。

### F. `@` 引用的真实作用

- 可以在 CLAUDE.md 中写 `@README` 或 `@docs/git-instructions.md`，把现有文档纳入结构。
- 相对路径相对于包含引用的那个文件解析，绝对路径也可用。
- 引用可以继续引用其他文件，最多递归四跳。
- 第一次引用项目外文件时会出现批准提示。
- 引用文件启动时会展开并加载进上下文，所以它改善组织方式，不减少上下文占用。

### G. 维护和验证闭环

- 临时形成的长期规则，可以直接让 Claude “加进 CLAUDE.md”；也可以用 `/memory` 查看并手动编辑已加载的记忆文件。
- 换包管理器、调整依赖、改变约定或文件超过 200 行时，应主动精简。
- 发现未遵守规则时，先用 `/memory` 确认文件已加载，再检查规则是否模糊，最后检查规则之间是否冲突。
- 文章提供一个玩具项目演示：建立最小项目，写一份不到 15 行的 CLAUDE.md，用 `/memory` 确认加载，再让 Claude 执行会触碰约定的任务。

## 3. 因果、对比和流程关系

### 因果关系

```text
长篇背景／过时信息／模糊规则
        ↓
上下文被占用，重要规则被稀释
        ↓
Claude 更容易用错命令或忽略约定
```

### 层级关系

```text
用户级 → 项目级 → 子目录级
范围广                 范围窄
先加载                 后加载
```

三层是拼接关系，不是后者把前者完全覆盖；项目规则通常因加载更晚而在冲突时更占优势。

### 维护流程

```text
发现长期规则
    ↓
写入 CLAUDE.md 或用 /memory 编辑
    ↓
让 Claude 执行任务验证
    ↓
定期删除过时、冲突和可推断内容
```

## 4. 可视觉化内容

- CLAUDE.md 长文件中，一条 `pnpm` 规则被背景文字淹没，Claude 却执行 `npm install`。
- 从白纸会话到读取项目手册，再到执行任务的启动流程。
- 用户级、项目级、子目录级文件堆叠，并用箭头表达从广到窄的加载顺序。
- 五类长期事实逐条写入一份短小的 CLAUDE.md。
- 300 行文件被裁剪成少于 200 行，留下可验证规则。
- `@` 引用从主文件展开到上下文窗口，展示“文件组织变清楚，但上下文没有变少”。
- 对话中的规则进入文件，`/memory` 检查加载，再执行任务验证。
- 模糊规则与具体规则的对照，以及玩具项目的验证链路。

## 5. 可以弱化或删除的信息

- 文章中的完整终端命令细节只保留为视觉示例，不作为视频教学中逐条执行的目标。
- 早期以 `#` 开头追加记忆的版本差异可压缩为“以当前官方做法为准”，避免分散主线。
- 企业托管策略层只作为“还有更高层策略”的背景，不展开操作。
- 玩具项目的 `main.py` 代码本身不是主知识点，画面只保留最小项目和约束验证。
- 文章里的系列导航和下一篇主题保留为结尾预告，不提前展开上下文管理的知识。

## 6. 事实边界与画面文字边界

- 视频只陈述文章明确给出的 CLAUDE.md 行为和维护建议，不把 CLAUDE.md 描述成强制安全机制。
- 三层主结构使用用户级、项目级、子目录级；`CLAUDE.local.md` 明确标为本地变体，不混成第四个共享层级。
- 所有 `pnpm`、`npm install`、`@README`、`/memory`、`/compact`、200 行、15 行等屏幕文字均来自 source 或由其直接概括。
- 不使用 `19-context-management.md` 的正文内容；只在结尾提到文章已经给出的下一篇主题“上下文管理”。
