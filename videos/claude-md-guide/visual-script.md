# Claude.md 使用指南视频化 · 第五步：Visual Script

> 目标：让画面演示规则如何被加载、稀释、裁剪、引用、维护和验证。口播负责解释原因与结论，画面负责展示过程和状态变化。

## 全局视觉原则

### 1. 画面不能只是重复口播

口播说“规则被稀释”，画面要让一条 `pnpm` 规则被长文档滚动带走，再显示 `npm install` 的错误结果；不把“规则被稀释”做成单独标题卡片。

### 2. 视觉承担证明和演示

口播解释 CLAUDE.md 的定位、层级、取舍和维护顺序；画面展示文件堆叠、加载箭头、内容裁剪、引用展开、规则替换和验证 diff。

### 3. 一个 Scene 只表达一个视觉中心

每个 Scene 只保留一个主要事件：失效、启动、加载、裁剪、展开、维护、替换、验收或收束。辅助标签只服务于该事件。

### 4. 少做页面，多做过程

优先使用滚动、堆叠、连接、展开、裁剪、替换、状态改变和点亮路径；避免把五类规则、三层结构和维护建议同时铺成静态卡片墙。

### 5. 动画必须有意义

- 一级信息动画：文件滚动、规则高亮、层级连接、内容展开、文本裁剪、验证状态切换。
- 二级注意力动画：对错误命令短暂放大、对当前层级加亮、对具体规则加边框。
- 三级装饰动画：仅使用轻微网格、光晕和光标闪烁，不让装饰抢走规则和状态变化。

## Scene 01｜三百行，零条被听见

### 视觉目标

让观众看到“长文档 → 规则被埋没 → 错误命令”的因果，而不是只听到结论。

### 画面结构

16:9 深色工作台。左侧是一份带滚动条的 `CLAUDE.md`，顶部与中段是淡化的项目背景、产品愿景和历史说明；右侧是任务执行面板。

### 动画

1. 文档快速滚动，长篇背景连续掠过。
2. 深处出现 `依赖管理只用 pnpm`，短暂高亮后被滚走。
3. 右侧执行区出现 `npm install`，状态变为“规则未生效”。
4. 文档和执行区淡出，只保留“重要规则被埋没”。

### 屏幕文字

`CLAUDE.md`、`依赖管理只用 pnpm`、`npm install`、`重要规则被埋没`

### 视觉与口播互补

口播解释上下文稀释的原因，画面证明规则确实从可见到不可见，并呈现了错误动作。

### Visual Type

`UI Simulation + Process`

## Scene 02｜CLAUDE.md 是入职手册，不是铁律

### 视觉目标

用一个启动过程建立“每次会话重新读取”的直觉，同时标明能力边界。

### 画面结构

中央是一条横向流程：`Blank session`、`Read CLAUDE.md`、`Start task`。中间的 CLAUDE.md 卡片像入职手册，右下角有两枚互斥状态标签：`强烈建议` 与 `非铁律`。

### 动画

1. `Blank session` 以空白光标开始。
2. 手册卡片从下方进入，项目命令和禁区两行文字出现。
3. 连接线点亮到 `Start task`。
4. `强烈建议` 保留亮色，`非铁律` 保持醒目但不使用错误警报色，表达边界而非失败。

### 屏幕文字

`Blank session`、`Read CLAUDE.md`、`Start task`、`强烈建议`、`非铁律`

### 视觉与口播互补

口播解释文件像入职手册、但不是硬性机制；画面只展示加载前后变化，不重复整段定义。

### Visual Type

`Concept Diagram + Process`

## Scene 03｜三层范围，从广到窄加载

### 视觉目标

让“范围”和“顺序”同时可见，并明确拼接关系。

### 画面结构

四张纵向文件卡片从上到下排列：`~/.claude/CLAUDE.md`、`./CLAUDE.md`、`subdir/CLAUDE.md`、`CLAUDE.local.md`。前三张按用户级、项目级、子目录级呈主路径，最后一张作为本地变体放在侧边。

### 动画

1. 用户级卡片先亮起，范围环覆盖多个项目。
2. 项目级卡片后亮起，范围收窄到当前项目。
3. 子目录级卡片最后亮起，范围收窄到模块。
4. 三张主路径卡片沿同一条线叠入“拼接上下文”，不是覆盖。
5. 本地变体以个人标识亮起，不进入共享路径。

### 屏幕文字

`~/.claude/CLAUDE.md`、`./CLAUDE.md`、`subdir/CLAUDE.md`、`CLAUDE.local.md`、`拼接，不是覆盖`

### 视觉与口播互补

口播负责解释每层管理什么，画面通过范围环和时间顺序建立空间直觉。

### Visual Type

`Connection Diagram + Process`

## Scene 04｜该写什么，也该删什么

### 视觉目标

把内容筛选呈现为“只留下每次会话都需要的事实”。

### 画面结构

中央是一份短 CLAUDE.md 编辑区，五条规则从左侧进入：`项目概述`、`技术栈`、`常用命令`、`代码约定`、`不要做`。下方有一个内容量指示器，从 `300 lines` 下降到 `< 200 lines`。

### 动画

1. 五类规则逐条进入文件并获得确认标记。
2. “公司背景”“过时命令”“代码可推断信息”从文件中滑出并淡化。
3. 内容量指示器向下收敛，`< 200 lines` 成为稳定状态。

### 屏幕文字

`项目概述`、`技术栈`、`常用命令`、`代码约定`、`不要做`、`< 200 lines`

### 视觉与口播互补

口播解释保留和删除的判断依据，画面展示添加与裁剪动作，避免把五类内容扩展成大段说明。

### Visual Type

`Task Routing + Process`

## Scene 05｜`@` 引用：整理，不省上下文

### 视觉目标

用一条引用展开动画表现“组织更好，但上下文占用不降”的反差。

### 画面结构

左侧是 `CLAUDE.md`，其中一行高亮 `@README`，下方还有 `@docs/git-instructions.md`。右侧是 Context usage 轨道，初始和展开后的高度保持一致。

### 动画

1. `@README` 从 CLAUDE.md 发出连接线。
2. README 内容在右侧展开，连接线标注“最多递归四跳”。
3. 文件结构栏变得更清楚，Context usage 轨道保持相同高度。
4. 右下角出现 `Context usage 不下降`，并短暂高亮。

### 屏幕文字

`@README`、`@docs/git-instructions.md`、`最多递归四跳`、`Context usage 不下降`

### 视觉与口播互补

口播说明路径解析和批准边界，画面集中证明“展开后仍占用上下文”这一核心反直觉。

### Visual Type

`Connection Diagram + UI Simulation`

## Scene 06｜让记忆跟着项目一起收敛

### 视觉目标

展示规则从会话纠正进入文件，再经过检查和精简的维护循环。

### 画面结构

左侧是对话气泡，显示一条待固化的约定；中央是 CLAUDE.md 文件；右侧是 `/memory` 检查面板。底部是一条“项目变化”时间线，挂着旧规则删除节点。

### 动画

1. 对话中的约定沿箭头进入 CLAUDE.md。
2. `/memory` 面板点亮，显示文件已加载。
3. 时间线出现“换包管理器”的变化，旧命令被划掉。
4. 三个排查节点依次亮起：`文件是否加载` → `规则是否模糊` → `是否冲突`。

### 屏幕文字

`加进 CLAUDE.md`、`/memory`、`文件是否加载`、`规则是否模糊`、`是否冲突`

### 视觉与口播互补

口播给出维护时机和排查顺序，画面展示规则在时间轴上从新增到清理的生命周期。

### Visual Type

`Process + Task Execution`

## Scene 07｜好规则要一眼能验收

### 视觉目标

把“具体到可验证”变成一次清晰的文字替换。

### 画面结构

左右分栏。左栏是淡红色模糊规则，右栏是亮色具体规则。每一行通过一条替换箭头完成转化：

```text
代码应该比较整洁 → 函数不超过 50 行
尽量写测试 → 每个新增函数必须有单元测试
```

### 动画

1. 左栏模糊句子出现，旁边显示不可验收标记。
2. 替换箭头横向划过，具体规则落到右栏。
3. 右栏规则获得可检查标记，左栏逐渐退到背景。

### 屏幕文字

`代码应该比较整洁`、`函数不超过 50 行`、`尽量写测试`、`每个新增函数必须有单元测试`

### 视觉与口播互补

口播解释“能不能一眼看出违反”，画面用替换前后状态展示可验证性提升。

### Visual Type

`Comparison + Code Exploration`

## Scene 08｜用最小项目验证它真的生效

### 视觉目标

展示从最小项目到规则影响 diff 的完整验收过程。

### 画面结构

中央是 `claude-md-demo` 项目，文件树只包含 `main.py` 和 `CLAUDE.md`。右侧依次出现 `< 15 lines`、`/memory`、一个带类型注解的 diff。底部状态从待验证变为“验证通过”。

### 动画

1. 项目文件树从空白中出现，突出最小范围。
2. CLAUDE.md 高度标注 `< 15 lines`。
3. `/memory` 检查面板显示文件已加载。
4. `add` 函数 diff 出现类型注解，禁止修改函数签名的约束保持不变。
5. 状态条切换为“验证通过”。

### 屏幕文字

`claude-md-demo`、`< 15 lines`、`/memory`、`函数必须有类型注解`、`验证通过`

### 视觉与口播互补

口播串起验证步骤，画面证明一个短文件确实被加载并影响了最终 diff。

### Visual Type

`Demo + Task Execution`

## Scene 09｜把 CLAUDE.md 变成项目护栏

### 视觉目标

将全片原则收束成可复用检查路径，并把下一篇预告作为最后一个视觉事件。

### 画面结构

前景是一条横向护栏路径，五个节点依次标记：`范围`、`具体规则`、`引用`、`维护`、`验证`。路径完成后，中央出现 `CLAUDE.md 不是百科全书`。最后切换为独立预告卡片：`下一篇：上下文管理`。

### 动画

1. 五个节点按前文顺序依次点亮并连成护栏。
2. “不是百科全书”在护栏后方稳定出现，背景内容降低透明度。
3. 全片总结淡出，预告卡片单独进入并保持约 2–3 秒。

### 屏幕文字

`范围`、`具体规则`、`引用`、`维护`、`验证`、`CLAUDE.md 不是百科全书`、`下一篇：上下文管理`

### 视觉与口播互补

口播总结职责和动作，画面把它们变成一条能复查的路径；预告只提出上下文管理问题，不带入下一篇正文。

### Visual Type

`Summary + Process`

## 全片视觉类型／组件／动画标准

### 视觉类型分布

| Visual Type | Scene |
| --- | --- |
| UI Simulation + Process | S01 |
| Concept Diagram + Process | S02 |
| Connection Diagram + Process | S03 |
| Task Routing + Process | S04 |
| Connection Diagram + UI Simulation | S05 |
| Process + Task Execution | S06 |
| Comparison + Code Exploration | S07 |
| Demo + Task Execution | S08 |
| Summary + Process | S09 |

### 组件建议

- `DocumentWindow`：展示 CLAUDE.md 的滚动、编辑和规则高亮。
- `ScopeStack`：展示用户级、项目级、子目录级和本地变体。
- `ContextRail`：展示 `@` 展开前后的上下文占用。
- `RuleComparison`：展示模糊规则到可验证规则的替换。
- `MemoryCheck`：展示 `/memory` 加载检查和验证状态。
- `SummaryRail`：展示五步护栏路径与下一篇预告卡片。

### 动画标准

- 信息动画使用滚动、连接、展开、裁剪、替换和点亮。
- 注意力动画只高亮当前规则、当前层级或当前状态。
- 不使用无意义粒子、旋转或复杂转场。
- 所有屏幕文字保持 1–2 行，字幕区域与最后预告卡片分离。

## Gate 2 内部结论

- 9 个 Scene 均有画面结构、视觉动作、状态变化、屏幕文字、Visual Type 和口播互补关系。
- 画面没有直接复述口播全文；主要承担展示过程、层级、内容取舍和验证结果。
- 所有原型文字都能追溯到 `source.md`、Content Analysis、Video Narrative 或 Scene Script，未使用下一篇文章的正文内容。
- S09 预告卡片是最后一个视觉事件，单独保留约 2–3 秒阅读时间，且不与字幕区域叠放。
- 当前任务在 Visual Prototype 阶段结束，不生成 TTS Script、音频、字幕、Timeline，不进入 Remotion。
