# Project Init 视频化 · 第五步：Visual Script

> 目标：为 10 个 Scene 明确画面结构、状态变化、动画顺序和声音与画面的互补关系。Visual Prototype 沿用基线的横屏 Scene 容器、幕内字幕、上一幕／下一幕、自动播放和进度提示结构。

## 全局视觉原则

### 1. 画面演示“重复如何消失”

旁白解释跨会话失忆和项目说明书的价值，画面用问题卡片重复出现，再让同一信息汇聚到 CLAUDE.md。

### 2. 画面展示扫描和落盘过程

不要只显示“自动生成”。应让依赖、README、配置和代码结构逐项被扫描，最后形成 CLAUDE.md 草稿。

### 3. 一个 Scene 一个视觉中心

每幕最多保留一个主动作：重复、归因、输入、扫描、保留、展开、验证、分流或收束。命令和字幕只作为辅助信息。

### 4. 文字服务于操作和状态

屏幕文字优先使用 /init、CLAUDE.md、文件名、命令、扫描状态、unchanged、建议改进和简短结论，不把文章段落整块搬进画面。

### 5. 风格统一

1920 × 1080 横屏构图，深色背景、蓝紫色主强调、绿色成功状态、红色问题状态。卡片和窗口保持克制，发光只用于当前动作。

## Scene 01｜同一个问题被问了三遍

### 画面结构

左侧为简化项目文件树，右侧垂直排列三个会话卡片。每个卡片先显示“新会话”，随后依次弹出“测试怎么跑？”和“npm 还是 pnpm？”。

### 动画顺序

1. 第一张会话卡出现并显示正在扫描 package.json。
2. 卡片淡出，第二张会话卡重复相同问题。
3. 第三张卡出现，问题计数从 1、2、3 递增。

### 视觉目标

重复不是 Claude 速度慢，而是每个会话都从空白起点开始。

### 与口播互补

旁白给出真实场景和问题内容，画面负责让相同动作重复发生。

### 屏幕文字

测试怎么跑？；npm 还是 pnpm？

### Visual Type

IDE Simulation + Workflow

## Scene 02｜根因不是 Claude 笨

### 画面结构

左边是空白上下文窗口，右边是一份尚未生成的 CLAUDE.md 轮廓。中间用“没有固定载体”的断开连接表示缺口。

### 动画顺序

1. 空白上下文中出现“重新摸索”。
2. CLAUDE.md 外框从虚线变为可写入状态。
3. 连接线接通，重复问题卡片收缩为一个项目说明书节点。

### 视觉目标

把“失忆”落到“缺少项目说明书”这个可修复的原因。

### 与口播互补

旁白负责类比和归因，画面负责展示从空白到固定载体的变化。

### 屏幕文字

从零摸索；项目说明书

### Visual Type

Concept Visualization

## Scene 03｜认识 /init

### 画面结构

中央为终端窗口，输入行突出 /init。右侧为项目文件树，底部为 CLAUDE.md 文件卡。

### 动画顺序

1. 光标在终端输入 /init。
2. 命令提交后，文件树节点依次亮起。
3. CLAUDE.md 卡片从空白变为“草稿已生成”。

### 视觉目标

/init 是一个起草动作，不显示“最终完成”之类超出原文边界的状态。

### 与口播互补

旁白给出定义，画面把“扫描 → 生成”直接演示出来。

### 屏幕文字

/init；生成 CLAUDE.md 草稿

### Visual Type

Terminal Simulation + Process

## Scene 04｜三步跑起来

### 画面结构

横向三段终端步骤：项目根目录、claude、/init。当前步骤使用蓝色边框，其余步骤保持暗色。

### 动画顺序

1. 路径提示出现：/path/to/your-project。
2. 输入 claude，出现 Claude Code 输入界面。
3. 输入 /init 并显示等待分析的状态。

### 视觉目标

顺序比命令数量重要：必须先在正确目录启动。

### 与口播互补

旁白解释为什么不能在桌面或主目录启动，画面仅展示正确路径。

### 屏幕文字

cd /path/to/your-project；claude；/init

### Visual Type

Terminal Demo

## Scene 05｜它扫描哪些项目事实

### 画面结构

左侧文件来源四格：package.json、README.md、config/、src/；右侧为项目地图节点。

### 动画顺序

1. 扫描光标依次经过依赖、README、配置和代码结构。
2. 每个节点亮起对应标签：技术栈、项目用途、目录和入口。
3. 信息线汇聚到“CLAUDE.md 草稿”。

### 视觉目标

只展示原文列出的来源类别，避免宣称固定扫描顺序或完整覆盖所有文件。

### 与口播互补

旁白解释每类信息的作用，画面展示来源与结果的映射。

### 屏幕文字

Dependencies；README；Config + Code Structure

### Visual Type

Codebase Scan

## Scene 06｜已有文件不会被粗暴覆盖

### 画面结构

左侧为已有 CLAUDE.md 文件，右侧为两张建议卡片。中间禁止覆盖图标仅用于表示“保留原文件”，不使用删除或替换动画。

### 动画顺序

1. 已有文件显示 unchanged。
2. 建议卡片逐张出现：补充命令、补充约定。
3. 文件和建议同时保留，形成“检查与改进”状态。

### 视觉目标

原文件不动，建议另行出现。

### 与口播互补

旁白解释官方行为边界，画面直接证明没有覆盖。

### 屏幕文字

CLAUDE.md · unchanged；建议改进

### Visual Type

File State Comparison

## Scene 07｜草稿里面有什么

### 画面结构

中央为一张 CLAUDE.md 文档，五个区块从上到下展开：项目概述、技术栈、目录结构、常用命令、开发规范。左侧保留一个“重复问题”小标签区。

### 动画顺序

1. 文档标题先出现。
2. 五个区块逐项展开，每项只显示一行示例。
3. “测试怎么跑？”连到常用命令，“项目是做什么的？”连到项目概述。

### 视觉目标

区块的用途，而不是完整 Markdown 内容。

### 与口播互补

旁白解释每一块回答什么，画面展示结构和问题之间的对应关系。

### 屏幕文字

概述 · 技术栈 · 目录结构 · 常用命令 · 开发规范

### Visual Type

Document Reveal

## Scene 08｜最小项目跑通闭环

### 画面结构

左侧为 init-demo/ 文件树，底部终端显示创建和检查命令，右侧为生成的 CLAUDE.md 摘要。

### 动画顺序

1. package.json 和 index.js 出现。
2. 终端提交 /init，CLAUDE.md 生成。
3. 文档中依次高亮 init-demo、Node.js / JavaScript 和 echo test ok。
4. 最后出现提问“这个项目的测试命令是什么？”，回答来自文档。

### 视觉目标

输入文件、生成文件和再次提问构成一个闭环。

### 与口播互补

旁白讲验证逻辑，画面展示文件和命令被识别的证据。

### 屏幕文字

init-demo/；package.json；index.js；CLAUDE.md

### Visual Type

Terminal Demo + File Tree

## Scene 09｜草稿必须人工补一刀

### 画面结构

左右两列：左列为扫描能得到的“客观事实”，右列为等待补充的“团队约定”。底部合并成“可用 CLAUDE.md”。

### 动画顺序

1. 左列自动填入技术栈、目录和命令。
2. 右列以空白占位显示分支、部署、Review、业务背景。
3. 人工光标将右列内容补入文档。
4. 文档标记从 draft 变为“持续迭代”。

### 视觉目标

自动扫描和人工判断各有边界，不能把“草稿”渲染成“终稿”。

### 与口播互补

旁白负责解释隐性知识，画面负责展示两种来源如何合并。

### 屏幕文字

客观事实：自动打底；团队约定：人工补充

### Visual Type

Comparison + Checklist

## Scene 10｜把失忆变成起点

### 画面结构

中央是一条完整路径：进入根目录 → claude → /init → 扫描 → CLAUDE.md 草稿 → 审阅 → 迭代。底部为半透明字幕胶囊，右下角为下一篇预告卡。

### 动画顺序

1. 路径节点从左到右依次亮起。
2. “审阅”和“迭代”停留时间最长，强调人的责任。
3. 预告卡出现：下一篇：项目结构。

### 视觉目标

用“起点”而不是“自动完成”收束；预告卡与字幕区域分离。

### 与口播互补

旁白完成总结和下一篇过渡，画面负责留下可复用的操作链路。

### 屏幕文字

扫描 → 草稿 → 审阅 → 迭代；下一篇：项目结构

### Visual Type

Summary + Next Episode Preview

## 全片视觉类型／组件／动画标准

### 视觉类型

- Scene 01：IDE Simulation + Workflow
- Scene 02：Concept Visualization
- Scene 03、04、08：Terminal Demo
- Scene 05：Codebase Scan
- Scene 06：File State Comparison
- Scene 07：Document Reveal
- Scene 09：Comparison + Checklist
- Scene 10：Summary + Next Episode Preview

### 复用组件方向

- OpeningScene：Scene 01、02 的问题与概念开场。
- ConceptScene：Scene 03、05、07、09 的概念、扫描和文档表达。
- TerminalScene：Scene 04、08 的命令和最小项目操作。
- ComparisonScene：Scene 06、09 的状态与责任边界对比。
- SummaryScene：Scene 10 的链路总结和下一篇预告。

本阶段只完成资料和静态原型，不实现或修改这些 Remotion 组件。

### 动画标准

- 每个 Scene 先出现主状态，再出现次要信息。
- 扫描、输入、文件生成和建议出现使用 300～600ms 的渐入或位移表达顺序。
- 终端命令和文件名使用等宽字体，状态颜色统一：问题红色、扫描蓝紫色、成功绿色、人工补充黄色。
- 不使用复杂 3D、粒子或快速转场。
- 原型中的导航、自动播放、进度提示和幕内字幕只服务于静态预览，不进入未来 Composition 或 MP4。
