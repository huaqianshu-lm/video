这篇文章表面上是在介绍一个斜杠命令，真正要建立的认知是：

> **进入新项目后运行 /init，可以让 Claude 扫描项目并生成一份 CLAUDE.md 草稿，把每次会话都要重新摸索的客观信息沉淀下来；但这份草稿仍需要人工审阅和补充。**

## 3. 必须保留的信息

### A. /init 解决的痛点

- 新会话不会自动记得上一会话的项目上下文。
- 没有 CLAUDE.md 时，Claude 可能反复查找测试命令、包管理器、目录位置等信息。
- CLAUDE.md 是写给 Claude 看的项目说明书，承载架构、构建命令和约定。

### B. /init 是什么

- 它是 Claude Code 内置的斜杠命令。
- 它会扫描代码库，生成起始版 CLAUDE.md。
- 文章将其描述为可识别项目技术栈、目录结构、命令和项目约定的自动起草过程。

### C. 怎么使用

1. 进入项目根目录。
2. 启动 claude。
3. 输入 /init 并回车。
4. 等待 Claude 分析并写入文件。
5. 打开 CLAUDE.md，人工通读和补充。

### D. 它大致会看什么

- 依赖清单：例如 package.json、requirements.txt、pom.xml。
- 现有文档：例如 README。
- 配置文件和代码结构：用于理解目录、入口和项目组织方式。

### E. 已有 CLAUDE.md 时的行为

原文明确写到：已有 CLAUDE.md 时，/init 不会粗暴覆盖，而是建议改进。

### F. 生成文件包含什么

原文用示例说明可能出现：

- 项目概述。
- 技术栈。
- 目录结构。
- 常用命令。
- 开发规范。

这些字段分别对应“项目做什么”“用了什么”“文件在哪里”“怎么运行”和“如何协作”。

### G. 最小项目验证

文章提供了一个 init-demo 示例：创建 package.json 和 index.js，在项目目录启动 Claude Code，运行 /init，退出后检查 CLAUDE.md，再询问测试命令验证上下文是否被记住。

### H. 最关键的边界

- /init 生成的是草稿，不是终稿。
- 分支命名、部署流程、Code Review 约定和业务背景等隐性知识，可能不在代码库中，不能指望扫描自动推断。
- 使用方式应是通读、补充、持续迭代，而不是一次生成后永久不修改。

## 4. 因果、对比和流程关系

### 因果关系

    没有项目说明书
    → 每次会话重新摸索
    → 重复解释和查找
    → 工作启动慢

    运行 /init
    → 扫描项目客观事实
    → 生成 CLAUDE.md 草稿
    → 后续会话有初始上下文
    → 减少重复摸索

### 对比关系

    没有 CLAUDE.md：每天换一个失忆的新人
    有 CLAUDE.md：开局先读过项目说明书

    自动扫描能得到：技术栈、目录、命令等客观事实
    人工补充才能得到：团队约定、业务背景、为什么这样设计
