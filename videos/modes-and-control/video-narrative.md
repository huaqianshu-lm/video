# Claude Code 视频化 · 第二步：Video Narrative

## 视频叙事目标与定位

- 视频标题：Claude Code 控制与模式：会话里的调音台
- 视频 slug：`modes-and-control`
- 叙事命题：会话启动后，用户仍然可以控制 Claude 的自主权、运行过程和响应方式；掌握这些控制手段，才能从“打字、回车、等”变成“随时调整方向”。
- 观众起点：已经会启动 Claude Code，但只把交互界面当成输入框，不知道会话中途如何暂停、回退、切模式或控制成本。
- 观众终点：能按任务选择控制类别，用 `Esc` 处理跑偏，用 `Shift+Tab` 和 Plan Mode 管理自主权，并理解 `/fast` 与 Vim 模式的取舍。
- 时长策略：不预设固定时长；由 11 个视觉事件、正常口播、必要停顿和状态变化自然决定。

## 整体叙事结构与叙事路径

本片不按原文 01–08 章节逐节复述，而按观众的认知过程重新组织：

```text
误区：只会打字、回车、等
    ↓
建模：会话控制分成三类
    ↓
救场：先掌握暂停、回退、中断和后台
    ↓
控权：看懂 Shift+Tab 的默认与可选循环
    ↓
转折：Plan Mode 先出方案，再决定如何执行
    ↓
取舍：快速模式用成本换延迟，Vim 用习惯换输入效率
    ↓
实践：把切模式、计划、批准和喊停串成一次练习
    ↓
收束：掌握操纵杆，才真正拥有会话控制权
```

## 声音与视觉分工

- 声音负责解释每个控制手段何时使用、行为差异和成本取舍。
- 视觉负责展示键位触发后的状态变化、模式循环、计划分支和练习结果。
- 画面不把口播逐字打出来；例如口播解释 `Esc` 不是撤销时，画面用“已完成保留／方向交还”两个状态证明差异。
- 危险的 `bypassPermissions` 只作为可选模式的边界提醒出现，不包装成默认推荐。
- 原型中的控制按钮、进度条和说明只服务于预览，不进入未来正式 Composition。
