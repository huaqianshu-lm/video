# Claude Code 视频化 · 第四步：Narration Script

## Scene 01｜会话不是输入框加回车

很多人把 Claude Code 会话用成了一个很简单的循环：打字、回车，然后等它输出。

但它一旦跑偏了，或者一上来就准备改文件，你不能只等它自己结束。

会话真正有用的地方，还包括你能不能在过程中把方向拉回来。

## Scene 02｜三类开关，各管一摊

先别把这些快捷键当成一张零散的速记表。

会话里的控制手段，其实分成三类。

第一类管自主权，也就是它动手前要不要问你，代表是 Shift 加 Tab。

第二类管过程，负责暂停、回退、中断、退出，或者把长命令放到后台，代表是 Esc、Ctrl 加 C 和 Ctrl 加 B。

第三类管响应，负责换模型、开关扩展思考，或者用快速模式换响应速度，代表是 Option 加 P、Option 加 T 和斜杠 fast。

以后想做什么，先判断它属于哪一类，再去找对应的控制手段。

## Scene 03｜过程控制：刹车、倒车和后台

最该先练熟的，是管过程的这一类。

Claude 跑偏了，按一下 Esc，它会停下当前响应或工具调用，把控制权交还给你，已经完成的部分会保留。

所以 Esc 不是撤销，而是暂停加重定向。

输入框里有字时，双击 Esc 会清空草稿，并把它存进历史；输入框为空时，双击 Esc 会打开回退菜单，让你退回对话之前的某个状态。

Ctrl 加 C 也要分清场景：有操作在跑时，它会中断；没有操作时，第一次可以清空输入框，再按一次就会退出会话。

Ctrl 加 D 是直接退出。

如果是一条很长的命令，比如安装依赖、跑构建或者启动开发服务器，可以按 Ctrl 加 B 把它放到后台，自己继续发新的指令。在 tmux 里，这个组合键需要按两下。

## Scene 04｜Shift+Tab：默认三档怎么转

接下来管自主权。

会话里按 Shift 加 Tab，默认会在 default、acceptEdits 和 plan 三档之间循环。

当前是哪一档，可以看状态栏。

auto 只有在账户满足条件并且确认加入后，才会出现在循环里。

bypassPermissions 需要用启动参数显式启用，dontAsk 则永远不进入这个循环，只能在启动时指定。

如果同时启用了可选模式，bypassPermissions 会排在 plan 后面，auto 再排在它后面。

绝大多数时候，先在默认三档里切换就够了。危险的权限模式，不应该变成日常操作里的默认路径。

## Scene 05｜先出方案，再决定怎么动手

Plan Mode 的价值，不只是一个叫 plan 的权限标签。

它更像正式施工前的一次彩排：Claude 可以读文件、运行探索命令、整理结构、写出计划，但不会编辑源代码。

你可以用 Shift 加 Tab 切到 plan，也可以只在这一条提示前加上斜杠 plan。

比如，先让它研究一个陌生项目，告诉你准备怎么改。

这时你拿到的是一份方案，而不是已经发生的修改。

## Scene 06｜批准计划，也是在选择怎么执行

计划写完以后，Claude 不会只有一个继续按钮。

你可以批准并让它自动执行，也可以批准并接受编辑，让它在危险命令处继续询问；还可以选择手动审查每个编辑，或者继续规划并给反馈。

也就是说，批准计划的同时，你也选定了接下来要用哪种自主权。

如果计划里有一步你想亲手改，可以按 Ctrl 加 G 在编辑器里修改。

所以 Plan Mode 串起的是一整条流程：先研究，再出方案，然后审查，最后才决定怎么执行。

## Scene 07｜快速模式：用成本买响应速度

快速模式解决的是等待时间，不是模型质量。

文章把它描述成同一个 Opus 的另一种 API 配置，最多可以快两点五倍，但每个 token 更贵。

实时调 Bug、快速迭代或者赶截止时间时，速度可能更重要，可以考虑打开。

长时间自主任务、批处理、持续集成，或者成本敏感的工作，通常应该把成本放在前面。

还要把它和努力级别分开：快速模式是同样的质量、更多的钱换更低延迟；降低努力级别是让它少想一点，复杂任务上质量可能下降。

如果要开快速模式，最好从会话一开始就开，不要等上下文已经很长了才切换。

## Scene 08｜Vim 模式：输入框里的两种状态

Vim 模式是给输入效率准备的可选项。

在斜杠 config 的编辑器模式里切成 vim，之后按 Esc 进入 NORMAL 模式，按 i、a 或 o 回到 INSERT 模式。

NORMAL 模式下，按 dd 可以删掉整行，cw 可以改当前单词，0 和美元符号可以跳到行首和行尾，u 可以撤销。

如果你本来就是 Vim 用户，这些手势会很顺手。

如果你完全没用过 Vim，也不用为了这项功能改变习惯，普通输入框已经够用。

## Scene 09｜练习前三步：观察、计划、批准

把前面的控制手段连起来跑一遍。

启动会话以后，先连续按 Shift 加 Tab，盯着状态栏，看 default、acceptEdits 和 plan 依次循环。

然后切到 plan，输入一个请求：在当前目录创建一个 hello 点 txt，里面写一行 hi from claude。

预期结果是，它只给你一段计划，不会真的创建文件。

接着批准并接受编辑。

这时，状态栏会切到 accept edits on，hello 点 txt 才真正出现。

亲眼看到“批准前不存在，批准后才创建”，就理解了 Plan Mode 的边界。

## Scene 10｜练习后两步：Esc 喊停，fast 看取舍

再给它一个需要较长时间的任务，等它开始运行时按一下 Esc。

它应该停下来，把控制权交还给你，已经完成的部分保留着。

然后补一句新的指令，让它沿着新方向继续。

最后可以选做快速模式练习：输入斜杠 fast 并按 Tab。

账户支持时，你会看到 Fast mode ON；如果当前账户或计划不支持，也会看到不可用提示，这同样是正常结果。

## Scene 11｜会话跑起来以后，你仍然握着方向盘

所以，会话里的控制手段可以记成三类。

自主权，用 Shift 加 Tab 和 Plan Mode 管；过程，用 Esc、Ctrl 加 C、Ctrl 加 D 和 Ctrl 加 B 控；响应，用模型切换、扩展思考和斜杠 fast 调整。

你不再只是打字、回车、等结果，而是能在它跑偏时喊停，在陌生项目里先看方案，再决定放多少自主权给它。
