# Claude Code 视频化 · 第五步：Visual Script

## 全局视觉原则

- 画布按 1920 × 1080 的 16:9 横屏构图设计，深色背景，使用蓝紫色表示控制和模式，绿色表示完成，黄色表示成本或提醒，红色只表示中断、危险或未完成。
- 每个 Scene 只有一个视觉中心：控制分类、按键状态、模式循环、计划分支、速度取舍、输入状态或练习结果。
- 声音解释“什么时候用、为什么用、有什么边界”，画面展示“按下之后发生什么、状态如何变化、下一步走哪条路”。
- 终端和快捷键使用等宽字体；标题和解释使用清晰的无衬线字体。
- 控制台、模式环路、流程和分支用连续状态变化表现，不把每幕都做成标题加卡片。
- 画面文字只保留当前文章及本条生产资料可追溯的词语；不执行文章中的命令和练习。
- 原型底部的提示、上一幕／下一幕、自动播放和进度条属于预览交互，不属于未来正式视频画面。

## Scene 01｜会话不是输入框加回车

### 视觉目标

从被动等待的单一输入框，转成可被操纵的会话控制台。

### 画面结构

中央是一块深色终端，会话提示符停在“输入 → 回车 → 等待”三步。终端外沿展开三枚控制旋钮，分别标记“自主权”“过程”“响应”。

### 动画

先显示输入、回车和等待；当等待状态停留时，外沿控制台亮起，三类控制从终端边缘依次展开。

### 屏幕文字

`输入`、`回车`、`等待`、`自主权`、`过程`、`响应`。

### Visual Type

OpeningScene／Concept Diagram。

### 口播与画面互补

口播说明只会等待的局限，画面证明会话仍有三组可以拨动的控制。

## Scene 02｜三类开关，各管一摊

### 视觉目标

让观众记住“想控制什么，就去对应的一类”。

### 画面结构

中央节点为“Claude 会话”，左侧自主权连接 `Shift+Tab`，下侧过程连接 `Esc`、`Ctrl+C`、`Ctrl+B`，右侧响应连接 `Option+P`、`/fast`。

### 动画

三条连接线依次亮起；每个代表按键以短促高亮接入对应类别，最后三类一起稳定显示。

### 屏幕文字

`自主权` → `Shift+Tab`；`过程` → `Esc`／`Ctrl+C`／`Ctrl+B`；`响应` → `Option+P`／`/fast`。

### Visual Type

ConceptScene／Connection Diagram。

### 口播与画面互补

口播解释三类控制的职责，画面用连线建立归位关系，不逐字复述解释。

## Scene 03｜过程控制：刹车、倒车和后台

### 视觉目标

把相似的过程快捷键区分成不同的结果状态。

### 画面结构

左侧终端显示任务日志和输入框，右侧为五行控制台：

- `Esc`：暂停，已完成保留。
- `Esc Esc`：有字清草稿／空框开回退。
- `Ctrl+C`：中断／清空／再按退出。
- `Ctrl+D`：直接退出。
- `Ctrl+B`：后台继续。

### 动画

任务日志先运行；按键提示依次出现，终端状态在“运行、暂停、回退、退出、后台”之间切换。每次只高亮一行，避免变成静态快捷键墙。

### 屏幕文字

`Esc`、`Esc Esc`、`Ctrl+C`、`Ctrl+D`、`Ctrl+B`、`已完成保留`、`后台运行`。

### Visual Type

TerminalScene／StepListScene。

### 口播与画面互补

口播解释边界和易错点，画面用终端状态变化证明每个键不是同一种“退出”。

## Scene 04｜Shift+Tab：默认三档怎么转

### 视觉目标

展示权限模式的默认循环、可选模式的插入规则和循环外模式。

### 画面结构

中央环路依次为 `default`、`acceptEdits`、`plan`。环路右侧有可选插槽：先是 `bypassPermissions`，再是 `auto`；环路外单独放置 `dontAsk`。

### 动画

高亮点沿默认三档循环；随后“已启用可选模式”的插槽从 `plan` 后插入。底部显示“dontAsk：启动时指定”。

### 屏幕文字

`default → acceptEdits → plan → default`、`bypassPermissions`、`auto`、`dontAsk`。

### Visual Type

ConceptScene／Decision Diagram。

### 口播与画面互补

口播讲条件和安全边界，画面负责把顺序和“永不入循环”变成空间关系。

## Scene 05｜Plan Mode：先谋后动

### 视觉目标

让观众看到 Plan Mode 在批准前不会编辑源代码。

### 画面结构

左侧是项目文件树和探索命令，中间是计划文档，右侧是源码文件保持“未修改”的状态。底部状态条显示“等待批准”。

### 动画

文件树被扫描，探索日志逐行出现；计划文档生成；源码区域保持锁定，最后“等待批准”亮起。

### 屏幕文字

`/plan`、`Research`、`Write plan`、`No source edits`、`等待批准`。

### Visual Type

Process／TerminalScene。

### 口播与画面互补

口播解释 Plan Mode 能读和探索但不改源码，画面用锁定的源码和已生成的计划证明边界。

## Scene 06｜批准计划，也是在选择怎么执行

### 视觉目标

展示计划批准菜单如何决定下一阶段的自主权。

### 画面结构

中央为“等待批准”，向四个方向分支：

- 批准并自动执行。
- 批准并接受编辑。
- 手动审查每个编辑。
- 继续规划并给反馈。

旁边保留 `Ctrl+G`：编辑计划。

### 动画

中央等待状态停留后，四条分支依次出现；前三条落到不同的执行状态，第四条回环到计划文档。先出现的分支保持主色，其余降低亮度。

### 屏幕文字

`批准并自动执行`、`批准并接受编辑`、`手动审查`、`继续规划`、`Ctrl+G`。

### Visual Type

Decision Diagram／ComparisonScene。

### 口播与画面互补

口播解释批准时同时选择后续模式，画面展示四条路径和回环关系。

## Scene 07｜快速模式：用成本买响应速度

### 视觉目标

避免把快速模式误解成更强模型或更高质量。

### 画面结构

左侧固定一个“同一个 Opus”节点，向右分两路：`/fast` 路线标注“最多 2.5 倍／更贵”，努力级别路线标注“少想一点／复杂任务质量可能下降”。底部三类任务分别放在速度优先、成本优先两侧。

### 动画

先固定模型节点，再点亮 `/fast` 的速度和成本标签；随后出现努力级别的不同结果。最后“实时调 Bug”靠近速度侧，“长任务／批处理／成本敏感”靠近成本侧。

### 屏幕文字

`/fast`、`同一个 Opus`、`最多 2.5 倍`、`更贵`、`努力级别`、`速度优先`、`成本优先`。

### Visual Type

ComparisonScene／Decision Diagram。

### 口播与画面互补

口播解释成本和质量差异，画面用两条不同的取舍轴展示“快”和“少想”不是一回事。

## Scene 08｜Vim：给输入框加两种状态

### 视觉目标

让观众理解 Vim 模式的输入状态和适用边界。

### 画面结构

中央为提示输入框，顶部有 `INSERT`／`NORMAL` 状态切换；右侧显示 `dd`、`cw`、`0`、`$`、`u` 五个代表手势，底部显示“Vim 党适合／新手可跳过”。

### 动画

输入框从 INSERT 切到 NORMAL；`dd` 删除一行，`cw` 改变一个词，`0` 移到行首，`u` 恢复文本；再切回 INSERT。

### 屏幕文字

`/config`、`INSERT`、`NORMAL`、`dd`、`cw`、`0`、`$`、`u`、`Vim 党适合`、`新手可跳过`。

### Visual Type

UI Simulation／StepListScene。

### 口播与画面互补

口播判断是否值得开启，画面只演示手势如何改变输入内容，不重复整张表格。

## Scene 09｜练习前三步：观察、计划、批准

### 视觉目标

用一次连续练习验证 Plan Mode 的“批准前不动、批准后执行”。

### 画面结构

三段横向时间线：

1. 状态栏在 `default`、`acceptEdits`、`plan` 间循环。
2. `plan` 中输入创建 `hello.txt`，显示“文件未创建”。
3. 批准并接受编辑后，显示 `accept edits on` 和“文件已创建”。

### 动画

第 1 步状态栏高亮；第 2 步计划出现但文件区域为空；第 3 步批准按钮落下后，文件从空列表进入项目树。

### 屏幕文字

`Shift+Tab`、`plan`、`hello.txt`、`文件未创建`、`accept edits on`、`文件已创建`。

### Visual Type

TerminalScene／StepListScene。

### 口播与画面互补

口播带练习操作，画面用文件出现的时点证明 Plan Mode 的边界。

### 口播与画面互补

## 全片视觉类型／组件／动画标准

### 视觉类型分布

- Opening／Concept Diagram：Scene 01。
- Concept／Connection Diagram：Scene 02。
- Terminal／StepList：Scene 03、09、10。
- Concept／Decision Diagram：Scene 04。
- Process／Terminal：Scene 05。
- Decision／Comparison：Scene 06。
- Comparison／Decision：Scene 07。
- UI／StepList：Scene 08。
- Summary／Connection Diagram：Scene 11。

### 组件层建议

- `SessionConsole`：承载会话终端和状态条。
- `ControlCategory`：展示三类控制入口。
- `KeyStateRow`：展示快捷键和触发后的状态。
- `ModeLoop`：展示默认模式与可选模式插槽。
- `PlanFlow`：展示研究、计划、批准和执行。
- `DecisionBranch`：展示批准后的执行路径。
- `TerminalLog`：展示练习中的日志状态。
- `SummaryCard`／`PreviewCard`：展示总结和下一篇预告。

### 动画标准

- 一级信息动画：状态变化、模式插入、计划生成、批准分支、文件出现和日志暂停必须有明确先后关系。
- 二级注意力动画：当前按键、当前模式和当前分支使用短暂高亮。
- 三级装饰动画：只使用轻微的边框光晕和进度流，不让装饰抢走控制关系。
- Scene 03、09、10 的日志和文件状态按顺序出现，不能一帧全部出现。
- Scene 05 和 Scene 06 的“等待批准”至少停留到观众能读完状态。
- Scene 11 的总结和下一篇预告使用淡入与停留，避免和底部原型提示重叠。
- 不使用炫技式转场；删除动画后若不影响理解，该动画不应保留。
