## 2. 核心命题

这篇文章真正要建立的认知不是“记住一张快捷键表”，而是：

> Claude Code 会话不是“输入、回车、等待”的单向过程，而是一块可以实时控制自主权、运行过程和响应方式的调音台。

```text
只会打字、回车、等
        ↓

        ↓
能切换自主权、暂停或回退过程
        ↓

        ↓
按任务取舍速度、成本和输入效率
        ↓
从被动等待变成主动操纵会话
```

## 3. 知识骨架与关系

### A. 三类控制

- **自主权**：`Shift+Tab` 循环权限模式，控制 Claude 动手前的确认程度。
- **过程**：`Esc`、双击 `Esc`、`Ctrl+C`、`Ctrl+D` 和 `Ctrl+B`，分别处理中断、重定向、回退、退出、清空输入和后台运行。
- **响应**：`Option+P`、`Option+T`、`/fast`，控制模型、扩展思考和响应速度。

### B. 过程控制的差异

- `Esc` 是暂停当前响应或工具调用，保留已经完成的工作，并把控制权交还给用户。
- 输入框有字时双击 `Esc` 会清空草稿并保存到历史；输入框为空时会打开回退菜单。
- `Ctrl+C` 在有操作时中断；空输入框第一次清空，第二次退出。
- `Ctrl+D` 直接退出会话。
- `Ctrl+B` 把长命令放到后台；在 tmux 中需要按两下。

### C. Shift+Tab 的模式循环

默认循环是：

```text
default → acceptEdits → plan → default
```

可选模式并非默认都在循环内：

- `auto` 需要满足账户条件并确认加入。
- `bypassPermissions` 需要启动参数显式启用。
- `dontAsk` 永远不进入循环，只能启动时指定。
- 同时启用可选模式时，`bypassPermissions` 插在 `plan` 后、`auto` 之前。

### D. Plan Mode 是完整工作流

Plan Mode 的核心不是“只读”这个标签，而是：

```text
研究文件和项目
        ↓
写出计划
        ↓
用户审查或修改计划
        ↓
批准时选择后续权限模式
        ↓
开始执行
```

它允许 Claude 读取文件、运行探索命令和写计划，但不编辑源代码。进入方式是 `Shift+Tab` 切换到 `plan`，或在单条提示前使用 `/plan`。批准时可以选择自动执行、接受编辑、手动审查，或继续规划；`Ctrl+G` 可编辑计划。

### E. 快速模式与 Vim 模式

- `/fast` 使用同一个 Opus 的更快响应配置，文章说明最多可快 2.5 倍，但每个 token 更贵。
- 快速模式适合实时调试和赶时间，不适合长时间自主任务、批处理和成本敏感任务；它与降低努力级别不同。
- Vim 模式在 `/config` 的编辑器模式中开启，提供 INSERT／NORMAL 两种状态和 `dd`、`cw`、`0`、`$`、`u`、`i`、`a` 等手势；不熟 Vim 的用户可以跳过。

### F. 串联练习

文章的五步练习把核心控制手段串起来：

1. 用 `Shift+Tab` 观察状态栏循环。
2. 切到 Plan Mode，提出创建文件的请求，确认它只出方案不创建。
3. 批准方案，观察权限模式切换并确认文件真正创建。
4. 让 Claude 做长任务，再用 `Esc` 喊停并重定向。
5. 选做：用 `/fast` 检查账户是否支持快速模式。
