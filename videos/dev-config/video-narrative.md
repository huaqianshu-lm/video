# Video Narrative｜开发配置：把 Claude 干活的工作环境调顺

## 1. 叙事目标与命题

从“接到不熟仓库后只能盯住每条命令”的焦虑开始，让观众发现：问题不是要不要一直批准，而是有没有给 Claude 安排合适的工作环境。随后建立五类配置地图，先解决安全边界，再处理连通性和使用手感，最后用模型选择控制成本，并通过一条可验证的操作链收束。

## 2. 观众认知路径

```text
私有仓库的不安
→ 人工监控不是长期方案
→ 开发配置其实在安排五件环境问题
→ 沙箱减少 Bash 权限摩擦，但边界有限
→ devcontainer 扩大到一致的开发环境
→ 按信任程度选择隔离强度
→ 网络配置解决“连不上”
→ 终端配置解决“用着别扭”
→ 模型配置解决“太贵或不够强”
→ 改配置后必须用状态和结果验证
→ 工作环境调顺，进入下一篇语音模式
```

## 3. 整体叙事结构与叙事节奏

- **Opening**：用私有仓库和“手放在 `Ctrl+C` 上”建立真实痛点。
- **Framework**：把五类配置压缩成“隔到哪、门窗到哪、桌椅是否顺、派谁来干、如何验收”的工作台图。
- **Isolation**：先给出 `/sandbox` 的快速收益，再立刻补上“只管 Bash”的限制，避免形成过度安全的错觉。
- **Choice**：用 devcontainer 和隔离梯度回答“什么时候需要更强的边界”。
- **Connectivity**：把代理、证书、防火墙解释成同一栋楼的总机、安检章和门禁。
- **Ergonomics**：用三个高频终端问题快速给出可执行选择。
- **Cost and capability**：通过模型排班和 effort 旋钮解释能力／成本的平衡。
- **Proof**：把 `/sandbox`、测试文件、`/status`、`/model haiku` 串成“改配置 → 验生效”的最小实验。
- **Summary**：回收五类配置，并以“47 Voice 语音模式”作为最后视觉事件和口播承接。

## 5. 叙事中的声音与视觉分工

- 声音解释“为什么这类问题属于某个配置维度”，说明边界、取舍和适用条件。
- 画面展示状态变化：从主机风险到隔离、从网络阻断到代理链路、从模型默认到模型切换。
- 画面文字只保留命令、配置名、状态和选择标签，不复述整段口播。
- 关键结论用对比和流程展示，让观众看到“只管 Bash”“命令在容器、改动落本地”“改完回头验”的差异。
