# 功能怎么选：CLAUDE.md vs Skill vs Hook vs MCP vs Subagent · Visual Script

## 全局视觉原则

### 1. 用“选择过程”代替功能罗列

每幕只保留一个选择动作：出现需求、提出问题、走一条分支或落到一个方案。六个扩展点的内容不做成密集 PPT，而用高亮、连线和窗口边界表达。

### 2. 声音解释，画面证明

口播负责主治范围、选择理由和边界解释。画面负责呈现触发者、上下文位置、路径分叉、内容流向、硬护栏和组合关系。

### 3. 颜色承担稳定语义

- 蓝色：需求、主路径、CLAUDE.md。
- 紫色：Skill、Subagent 和按需能力。
- 绿色：MCP、完成、已连接。
- 黄色：Hook、权限护栏和需要注意的判断。
- 红色：错误选择、上下文负担或被拦截动作。

### 4. 横屏教程感和安全区

按 1920 × 1080 横屏构图设计，标题控制在 1—2 行，主要结构放在中央，底部预留字幕安全区。预览控件和进度提示只在原型外层，不属于画面内容。

### 5. 画面文字语义归属

所有卡片、标签、按钮、命令和预告文字都能追溯到当前 `source.md`、Content Analysis、Video Narrative 或 Scene Script。原型不执行源文中的命令，不使用其他文章的业务文案。

## 逐 Scene 视觉设计

### Scene 01｜名词都懂，需求一来就卡

- **画面结构**：中央是需求输入框，周围散落六个扩展点卡片。
- **视觉动作**：卡片短暂互相推挤，输入“我这个需求该用哪个？”后全部卡片退到两侧，中央出现“需求 → 方案”。
- **信息重点**：从名词记忆切换到需求映射。
- **口播互补**：口播说明困惑来源，画面让“选项过多”可见。

### Scene 02｜六个挂钩，插在代理循环不同位置

- **画面结构**：一条“想 → 做 → 看”的循环轨道，六个挂钩落在不同区段。
- **视觉动作**：背景、外部连接、独立窗口、事件触发和主动流程依次亮起。
- **信息重点**：扩展点的位置和触发关系。
- **口播互补**：口播解释代理循环，画面证明它们不是平行菜单。

### Scene 03｜六个科室，各治什么

- **画面结构**：六张等宽定位卡，固定显示主治、谁触发、上下文占用三行。
- **视觉动作**：每张卡依次翻开，当前卡放大，其余卡降低对比度。
- **信息重点**：六项一句话定位。
- **口播互补**：口播完整解释，画面提供可回看的扫读锚点。

### Scene 04｜需求表：先找最像你的一句话

- **画面结构**：左侧是需求列，中间是推荐方案，右侧是判断理由。
- **视觉动作**：“查公司数据库”、“读几十个文件只要结论”、“自动跑 ESLint”三行依次高亮并连到 MCP、Subagent、Hook。
- **信息重点**：表格是检索工具，不是背诵清单。
- **口播互补**：口播讲使用方法，画面展示检索结果。

### Scene 05｜四个问题，走完一棵决策树

- **画面结构**：中央四层分叉树，左侧保留问题，右侧逐步生成落点。
- **视觉动作**：每次只出现一个问题，错误分支淡出，正确路径延伸到 MCP、Hook／权限规则、Subagent、CLAUDE.md／Skill。
- **信息重点**：四问顺序。
- **口播互补**：口播解释为什么这样排序，画面保留路径记忆。

### Scene 06｜Skill 和 Subagent：手册还是外派

- **画面结构**：左右两个工作窗口；左侧主窗口接收 Skill 手册，右侧隔离窗口运行 Subagent。
- **视觉动作**：左侧手册内容流入主窗口；右侧文件列表被扫描，最后只飞回“结论”卡。
- **信息重点**：上下文是否进入主窗口。
- **口播互补**：口播用“手册／外派”解释，画面展示内容流向。

### Scene 07｜CLAUDE.md 和 Skill：每次看还是按需看

- **画面结构**：横向会话时间线，起点是“新会话”，上方是 CLAUDE.md，下方是 Skill。
- **视觉动作**：会话启动时 CLAUDE.md 固定进入背景；需求出现后 Skill 才展开。长文档卡片被推离常驻区。
- **信息重点**：自动加载与按需加载的区别，以及上下文成本。
- **口播互补**：口播讲适用范围，画面把加载时机固定下来。

### Scene 08｜Hook 和权限规则：硬护栏怎么分工

- **画面结构**：一个危险操作入口，前方有“权限规则”门，侧边有“Hook”事件轨道。
- **视觉动作**：权限门直接显示允许／拒绝；Hook 拦截后分出日志、通知或改写三条附带动作。
- **信息重点**：准入判断与拦截后动作。
- **口播互补**：口播强调文字提醒不是保证，画面显示硬护栏发生了什么。

### Scene 09｜组合才是常态，Plugin 负责装箱

- **画面结构**：四组组合卡从四个方向连到中央 Plugin 行李箱。
- **视觉动作**：Skill 与 MCP 先接上，Skill 与 Subagent 形成并行，CLAUDE.md 与 Skill 分层，Hook 与 MCP 触发通知，最后一起锁进箱子。
- **信息重点**：组件各司其职，Plugin 是打包层。
- **口播互补**：口播解释组合理由，画面提供空间关系和迁移隐喻。

### Scene 10｜A—G 需求清单，现场分诊

- **画面结构**：左侧 A—G 需求卡，中间四问入口，右侧方案列。
- **视觉动作**：每张卡经过入口后落到方案列，混淆项用黄色边框提醒，落位后显示一个简短判断理由。
- **信息重点**：方法能应用到真实需求。
- **口播互补**：口播给出答案和理由，画面让七次选择连续发生。

### Scene 11｜四问锁定方案，下一篇见

- **画面结构**：四问路径汇聚成“需求 → 方案”，下方留出独立预告卡区域。
- **视觉动作**：路径完成后，预告卡作为最后一个视觉事件淡入并停留。
- **信息重点**：四问口诀、六个落点和第 31 篇标题。
- **口播互补**：口播完成总结和预告，画面为预告留出 2—3 秒阅读空间。

## 全片视觉类型、组件和动画标准

### 视觉类型

- 需求映射钩子
- 代理循环／系统关系图
- 定位卡片
- 决策表
- 决策树
- 双窗口上下文对比
- 加载时间线
- 硬护栏事件图
- 组合连线与 Plugin 装箱
- 练习清单映射
- 总结与预告卡

### 基础组件

- `RequestInput`：需求输入和映射结果。
- `LoopRail`：想、做、看的循环轨道。
- `RoleCard`：扩展点定位卡。
- `DecisionTable`：需求行和方案列。
- `DecisionTree`：四问分支。
- `ContextWindow`：主窗口与隔离窗口。
- `Timeline`：自动加载和按需加载。
- `GuardRail`：权限规则与 Hook。
- `BundleBox`：组合关系和 Plugin。
- `PracticeBoard`：A—G 练习清单。

### 动画标准

- 卡片进入：短距离上移 + 淡入，避免弹跳过快。
- 路径连接：先亮起起点，再延伸连线，最后点亮落点。
- 状态变化：使用边框和文字颜色，不依赖闪烁。
- 表格高亮：一次只突出一行，上一行回到低对比度。
- 决策树：不同时显示全部答案，按问题逐层展开。
- 预告卡：最后停留约 2—3 秒，和底部字幕区域分离。
