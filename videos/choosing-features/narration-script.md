# 功能怎么选：CLAUDE.md vs Skill vs Hook vs MCP vs Subagent · Narration Script

## Scene 01｜名词都懂，需求一来就卡

CLAUDE.md、Skill、Hook、MCP、Subagent，再加上 slash command，这些名词你可能都见过，单看也都懂。可一旦换成“我这个需求该用哪个”，很多人还是会卡住。问题不是知识不够，而是还没有建立从需求到方案的映射。这一篇就把方向反过来：不先问它是什么，而是先问你想干什么。

## Scene 02｜六个挂钩，插在代理循环不同位置

这六个扩展点不是平行摆着的六个按钮。Claude 工作时会在想、做、看之间循环，它们分别插在这个循环的不同位置：有的负责提供背景，有的负责连接外部世界，有的负责派出独立工作者，还有的会在固定时机自动触发。选哪个，关键不是哪个更强，而是你的需求应该挂在哪个位置。

## Scene 03｜六个科室，各治什么

CLAUDE.md 解决的是每次都要遵守的项目规矩。Skill 解决的是需要时才调出的知识和流程。slash command 是你主动一键触发的固定流程。MCP 负责连接外部服务和数据。Subagent 是在独立上下文里干活、最后只回传结果的分身。Hook 则是在固定事件发生时自动扣扳机。记住它们的主治范围，后面的选择就有了入口。

## Scene 04｜需求表：先找最像你的一句话

如果你已经知道自己想做什么，可以直接查需求表。每次都按团队约定来，落到 CLAUDE.md。要查公司数据库，落到 MCP。想读一大批文件，只要最后结论，落到 Subagent。每次改完文件自动格式化，落到 Hook。表格的用法不是背答案，而是先把自己的需求说成一句话，再找最像的那一行。

## Scene 05｜四个问题，走完一棵决策树

需求不够清楚时，就按四个问题往下走。第一，这件事要不要连接外部服务或数据？要，就选 MCP。第二，它是不是每次都必须成立，不能靠 Claude 自觉？要硬保证，就看 Hook 或权限规则。第三，它是不是一次性的脏活，想隔离过程，或者几件事想并行？是，就派 Subagent。走到最后，再问它是每次都要看到的规矩，还是需要时才查的知识和流程。前者是 CLAUDE.md，后者是 Skill；主动一键触发的固定流程，就用 slash command。

## Scene 06｜Skill 和 Subagent：手册还是外派

Skill 和 Subagent 都可以装下一套流程，但它们解决的不是同一个问题。Skill 像一本共享手册，需要时翻开，内容会进入你当前的工作窗口。Subagent 像外派出去的人，它在自己的窗口里读文件、做搜索，回来只汇报结论。要把内容拿进来用，选 Skill；要让过程不要占满主对话，只要结果，选 Subagent。

## Scene 07｜CLAUDE.md 和 Skill：每次看还是按需看

CLAUDE.md 和 Skill 都能存规则或知识，但加载方式不同。CLAUDE.md 在每个会话开始时自动加载，适合项目约定、构建命令和永远不能做的事情。Skill 平时只保留描述，用到时才把完整内容调进来，适合 API 风格指南、部署清单和调试套路。不要把一份很长的参考资料全塞进 CLAUDE.md，否则每次开工都会先付出上下文成本。

## Scene 08｜Hook 和权限规则：硬护栏怎么分工

还有一组容易混的，是 Hook 和权限规则。写在 CLAUDE.md 或 Skill 里的“永远不要做某事”，本质上只是请求，不是保证。权限规则适合声明式地判断某个工具或命令准不准。Hook 也能做强制拦截，而且如果拦截之后还要记日志、发通知或改写参数，就更适合用 Hook。简单的准入判断优先用权限规则，需要附带动作再用 Hook。

## Scene 09｜组合才是常态，Plugin 负责装箱

真实项目里很少只有一个扩展点。MCP 负责接上数据库，Skill 可以教它怎么查；Skill 可以派出 Subagent 做并行审查；CLAUDE.md 放常驻规矩，Skill 放按需细则；Hook 也可以在事件发生时通过 MCP 通知外部服务。要把整套能力搬到另一个项目，就用 Plugin 把这些组件装进一个可安装的单元。

## Scene 10｜A—G 需求清单，现场分诊

把方法练一遍。团队一律用 pnpm，是 CLAUDE.md。查内部 PostgreSQL，是 MCP。一键完成发版流程，是 slash command。编辑后自动格式化，是 Hook。扫描整个目录只要死代码结论，是 Subagent。偶尔查一份错误码表，是 Skill。生产迁移脚本绝对不许执行，是权限规则或 Hook。真正重要的不是背这七个答案，而是看见每个答案都能由那四个问题推出来。

## Scene 11｜四问锁定方案，下一篇见

以后再遇到“我想让 Claude……”的需求，先问：连外部吗？要硬保证吗？要隔离吗？每次看还是按需看？六个扩展点各有主治，Plugin 负责把它们打包带走。把需求翻译成问题，再沿着树走到叶子，你就不必再对着一串名词发懵了。下一篇是第 31 篇：settings.json：用户级 / 项目级配置。
