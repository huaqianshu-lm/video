# 功能怎么选：CLAUDE.md vs Skill vs Hook vs MCP vs Subagent · Content Analysis

## 1. 核心命题

当用户已经知道 CLAUDE.md、Skill、slash command、MCP、Subagent 和 Hook 各自是什么，却不知道“我的需求该用哪个”时，问题不在名词记忆，而在缺少“需求 → 方案”的映射。

本片要建立一套可执行的分诊模型：

```text
先说清需求
    ↓
连外部？要硬保证？要隔离？
    ↓
每次都要看到，还是需要时才调出？
    ↓
选 CLAUDE.md / Skill / slash command / MCP / Subagent / Hook
```

## 2. 观众需要完成的认知变化

1. 从“六个扩展点是六个平行选项”转为理解它们分别插在代理循环的不同位置。
2. 能用一句话说出六个扩展点各自的主治范围和触发方式。
3. 能把真实需求先翻译成判断问题，再用决策表或决策树选方案。
4. 分清 Skill 与 Subagent 的关键差异是上下文是否进入主窗口。
5. 分清 CLAUDE.md 与 Skill 的关键差异是加载时机和常驻程度。
6. 分清 Hook 与权限规则都能做强制护栏，但权限规则偏声明式准入判断，Hook 适合拦截之外还要执行动作。
7. 认识到真实配置常常是组合，Plugin 是把多种能力打包分发的层。
8. 知道选择错误会带来上下文负担、漏执行、协调成本或权限边界失配。

## 3. 必须保留的信息

### A. 选择问题的来源

- CLAUDE.md、Skill、Hook、MCP、Subagent 和 slash command 单看都能理解，但需求出现时容易卡住。
- 官方说明通常按“这是什么”组织，本片反过来按“你想干嘛”组织。

### B. 六个扩展点的定位

| 扩展点 | 主治 | 触发方式 | 上下文关系 |
| --- | --- | --- | --- |
| CLAUDE.md | 每次都遵守的项目规矩 | 自动加载 | 全文常驻 |
| Skill | 按需调出的知识或流程 | Claude 判断或主动调用 | 平时只占描述 |
| slash command | 主动一键触发的固定流程 | 用户输入 `/<name>` | 同 Skill |
| MCP | 连接外部服务或数据 | 用到工具时 | 先占工具名 |
| Subagent | 隔离上下文的专项工作者 | 用户或 Claude 派发 | 独立窗口 |
| Hook | 固定时机自动执行的动作 | 生命周期事件 | 不依赖主上下文 |

### C. 决策表与决策树

- 需求是常驻规矩，选 CLAUDE.md。
- 需求是偶尔查的知识或流程，选 Skill；想主动一键触发固定流程，用 slash command。
- 需要连接数据库、Slack 或浏览器等外部服务，选 MCP。
- 需要读很多文件、并行处理或只要结论，选 Subagent。
- 需要在固定事件上自动运行并保证发生，选 Hook；纯准入判断也可用权限规则。
- 决策树顺序是：连外部？→ 要硬保证？→ 要隔离？→ 每次看还是按需看？

### D. 三组易混边界

- Skill 是共享手册，内容会进入当前工作上下文；Subagent 是外派工作者，过程留在独立窗口，主窗口只接收结果。
- CLAUDE.md 每个会话自动加载，适合常驻规矩；Skill 按需加载，适合参考内容和可调用流程。
- 权限规则适合声明式“准不准”，Hook 适合“拦截 + 记录、通知或改写”等附带动作；两者都比文字提醒更接近硬保证。

### E. 组合和 Plugin

- Skill + MCP：MCP 负责接通，Skill 负责教会如何使用。
- Skill + Subagent：专项流程派出隔离的并行工作者。
- CLAUDE.md + Skill：常驻规矩和按需细则分层。
- Hook + MCP：事件触发后连接外部服务。
- Plugin 把 Skill、Hook、Subagent 和 MCP server 装进一个可安装单元，便于迁移和分享。

### F. 实战清单

- A 一律用 pnpm → CLAUDE.md。
- B 查 PostgreSQL → MCP。
- C 一键发版 → slash command。
- D 编辑后自动 prettier → Hook。
- E 扫描 utils 找死代码 → Subagent。
- F 偶尔查错误码表 → Skill。
- G 禁止执行生产迁移 → 权限规则或 Hook。

## 4. 因果、对比与流程关系

### 核心因果

```text
名词按功能介绍
    ↓
知道“是什么”，却不会“怎么选”
    ↓
从需求倒推方案
    ↓
选择更准确，少用错相邻工具
```

### 选择关系

```text
外部连接 → MCP
硬保证 → Hook / 权限规则
上下文隔离 → Subagent
常驻规矩 → CLAUDE.md
按需知识或流程 → Skill
主动一键流程 → slash command
```

### 成本关系

- 把长参考资料塞进 CLAUDE.md 会增加每个会话的上下文负担。
- 把应该隔离的工作做成 Skill，会把过程灌进主窗口。
- 把需要硬保证的规则写成提醒，可能漏执行。
- 把简单准入判断写成复杂 Hook，会增加不必要的维护成本。
