# Claude Code 环境变量 · Content Analysis

## 1. 核心命题

本篇把环境变量定位为 Claude Code 启动时读取的一组键值对「总开关」，用于控制连接、认证、超时、隐私和配置目录等底层行为。它不是「高阶玩家才碰」的危险配置，而是把「每次都想这么来」的选择固化下来。

观众看完应能：

1. 说清环境变量控制什么，以及为什么发生在启动阶段。
2. 按范围选择 shell 临时设置、shell 配置文件或 `settings.json` 的 `env`。
3. 分辨四类 `settings.json` 文件的影响对象和 git 边界。
4. 认识连接、超时、隐私、配置目录四组常用变量。
5. 解释环境变量高于设置字段，以及模型配置中 `/model`／`--model` 高于 `ANTHROPIC_MODEL` 的例外。
6. 用 `BASH_DEFAULT_TIMEOUT_MS` 完成设置、验证、关闭终端、持久化闭环。

## 3. 关键关系

### 3.1 设置范围

`当前 shell → shell 配置文件 → settings.json 的 env` 代表从一次试验到机器级持续，再到跟配置文件作用范围绑定。选择重点不是谁绝对更好，而是变量应该影响一次试验、个人机器、项目成员还是组织。

### 3.2 文件归属

`~/.claude/settings.json` 管你所有项目；`.claude/settings.json` 管项目所有人并进入源代码控制；`.claude/settings.local.json` 只管你在当前项目且不进入源代码控制；托管设置由管理员部署。带个人凭据或私有地址的变量不能放进会提交的项目设置。

### 3.3 优先级

通则是：

`环境变量 > settings.json 设置字段`

模型配置的文章示例是：

`/model 或 --model → ANTHROPIC_MODEL → settings.json 的 model`

不同功能的交互方式可能不同，不能把模型例外套到所有变量。

### 3.4 验证链

`默认值 → shell 临时设值 → 新会话读到新值 → 关闭终端后恢复 → 写入 settings.json 后持久`。这条链把「变量有效」和「变量放哪儿」分开验证。

## 4. 必须保留

- 三种设置方式的生效范围和典型场景。
- 四类设置文件的影响对象、git 边界和个人凭据风险。
- `API_TIMEOUT_MS` 默认 `600000`，`BASH_DEFAULT_TIMEOUT_MS` 默认 `120000`。
- `ANTHROPIC_API_KEY` 可能让已登录订阅改走 API key，清除需要 `unset`。
- `API_TIMEOUT_MS` 的文章提示上限为 `2147483647`。
- 变量修改后需要退出并重新启动 Claude Code。
- 通用优先级、模型配置例外和 `BASH_DEFAULT_TIMEOUT_MS=300000` 实验。
