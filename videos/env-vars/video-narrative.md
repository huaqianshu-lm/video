# Claude Code 环境变量 · Video Narrative

## 1. 视频叙事目标

本片不按原文章节逐段朗读，而是让观众从「为什么每次都要手动改」进入「环境变量是启动时读入的总开关」，再经过范围、归属、常用变量和优先级，最后用一个可观察实验完成验证。

`每次手动调设置
        ↓
环境变量是启动时读入的总开关
        ↓
三种设置方式决定生效范围
        ↓
settings.json 决定谁受影响、什么进 git
        ↓
常用变量覆盖连接、超时、隐私和配置目录
        ↓
优先级有通则，也有模型例外
        ↓
用实验验证，再决定是否持久化
        ↓
总结并预告 Git 工作流`

## 2. 观众认知路径

1. 先看到「每次手动切换」的重复成本。
2. 建立环境变量是启动时读入的键值对。
3. 用影响范围解释三种设置方式。
4. 用四类 `settings.json` 解释「谁会被影响」。
5. 按真实场景认识四组变量，而不是背长清单。
6. 用重启前后的值差异解释读取时机。
7. 先讲环境变量优先，再展示模型配置例外。
8. 用 `BASH_DEFAULT_TIMEOUT_MS` 完成验证闭环。
9. 总结先试、再按范围固化，并预告下一篇。

## 3. 整体叙事结构与 Scene 结构

### Scene 01｜每次都要重新拨

问题钩子：同一套偏好却在每个新会话里重设模型、超时和隐私。

### Scene 02｜启动时读入的总开关

建立环境变量的核心定义，并将变量连接到启动行为。

### Scene 03｜三种设置范围

比较 shell 临时设置、shell 配置文件和 `settings.json` 的 `env`。

### Scene 04｜四类 settings.json

说明主目录、项目共享、项目本地和托管设置分别管谁，以及 git 边界。

### Scene 05｜四组常用开关

按连接认证、超时、隐私遥测、多账号与上下文分组展示代表变量。

### Scene 06｜改了，为什么没变化

展示只有重启后新值才会进入 Claude Code。

### Scene 07｜谁说了算

先给环境变量高于设置字段的通则，再展示模型配置例外。

### Scene 08｜最小验证闭环

从默认值开始，临时设值、验证、关闭终端、再持久化。

### Scene 09｜把开关拨在正确的位置

收束选择原则，最后出现「下一篇：Git 工作流」。

## 5. 叙事约束

- 不把全部变量做成静态清单，画面必须展示关系或状态。
- 不把口播全文复制到画面。
- 不把模型优先级例外扩展成所有变量的统一规则。
- 不执行文章中的任何命令，命令只出现在视觉模拟中。
- Scene 09 的 Git 工作流预告是最后视觉事件，不提前讲解 Git。
