# Claude Code 环境变量 · Narration Script

## Scene 01｜每次都要重新拨

你是不是也遇到过这种情况：每次打开 Claude Code，都要重新切一次模型，网络慢了再调一次超时，隐私设置也要重新确认。明明这些选择你一直都想保持不变，却只能在每个新会话里再拨一遍。

## Scene 02｜启动时读入的总开关

环境变量解决的，就是这类「每次都想这么来」的问题。它是 Claude Code 启动时读取的一组键值对，用来控制模型怎么连接和认证、请求等多久、要不要上报数据，以及配置放在哪里。你可以把它理解成藏在启动入口后面的那排总开关。

## Scene 03｜三种设置范围

设置环境变量，先别急着记语法，先看它要影响多久。shell 里用 export，适合当前终端临时试一次；写进 zshrc 或 bashrc，适合这台机器的每个终端；写进 settings.json 的 env，适合让变量跟着配置范围走。临时验证用第一种，确认长期需要，再选择后两种。

## Scene 04｜四类 settings.json

settings.json 也不是只有一个地方。主目录下的文件管你所有项目，项目里的 settings.json 管项目中的所有人，settings.local.json 只管你在当前项目里的使用，还有由管理员下发的托管设置。尤其要记住，带个人凭据或私有地址的变量，不要放进会提交到 git 的项目设置。

## Scene 05｜四组常用开关

真正常碰到的变量，可以先按四组认识。连接和认证看 API key、base URL 和 model；超时里，API_TIMEOUT_MS 的默认值是 600000，BASH_DEFAULT_TIMEOUT_MS 的默认值是 120000；隐私可以看 DISABLE_TELEMETRY 和 DO_NOT_TRACK；多账号和上下文则可以看 CLAUDE_CONFIG_DIR 以及 DISABLE_AUTO_COMPACT。先按场景找变量，不必背完整清单。

## Scene 06｜改了，为什么没变化

这里还有一个很容易误判的点：Claude Code 只在启动时读取环境变量。你在已经打开的会话外面改了值，旧会话不会突然改变；退出并重新启动之后，新值才会被读进去。所以设置后没有反应，先确认自己有没有真正重开 Claude Code。

## Scene 07｜谁说了算

如果同一件事同时写在环境变量和设置字段里，通常是环境变量优先。模型配置却还有一层更明确的选择：会话里的 model 命令，或者启动时的 --model，会覆盖 ANTHROPIC_MODEL，后者又覆盖 settings.json 里的 model。不要把一个变量的优先级想当然套到所有功能上。

## Scene 08｜最小验证闭环

最稳的办法，是先做一次小实验。先不设置 BASH_DEFAULT_TIMEOUT_MS，记住默认的 120000；然后临时 export 成 300000，重新打开 claude，问它当前读到的值。接着关掉这个终端，开一个新的，不再 export，值应该回到默认。确认临时设置确实有效后，再把它写进不进 git 的 settings.local.json。

## Scene 09｜把开关拨在正确的位置

所以，环境变量不是玄学：先用临时设置验证，再按照影响范围决定放在机器、项目还是个人配置里；带凭据的内容，始终避开会进入 git 的文件。把总开关拨在正确的位置，下一次启动就不用重复劳动。下一篇，我们继续讲 Git 工作流：让 Claude Code 参与 diff、提交和协作时，哪些动作可以交给它，哪些仍然要由你把关。
