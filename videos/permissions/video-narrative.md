# 权限配置：放多松、收多紧，你说了算

## 1. 视频叙事目标

让观众完成一次认知变化：

`
“权限越松效率越高”
          ↓
权限的风险取决于 Claude 所处的环境
          ↓
先分清哪些动作默认放行、哪些动作要批准
          ↓
再用六种模式调节自主度
          ↓
用规则精确到单个工具、命令和路径
          ↓
发现单层 deny 仍有绕道边界
          ↓
用玩具／生产模板和隔离环境做选择
          ↓
亲手验证规则是否真的生效
          ↓
权限不是一次性开关，而是环境匹配的行为边界
`

视频不从六种模式的定义表直接开始，而是先用“隔离容器敢放、生产机器不敢放”的反差制造问题：同一个危险模式为什么在两个地方结论相反？观众先建立“环境决定松紧”的判断，再学习模式和规则。

`

## 3. 整体叙事结构与叙事段落

### 第一段：先把“危险模式”放进两个环境

开场左右对比隔离容器与装着公司生产代码的本机。同一个 `--dangerously-skip-permissions`，左边代表删了可重建，右边代表真实代码不可轻率承担。悬念不是“哪个模式最好”，而是“你到底在哪用”。

### 第二段：先看权限系统的默认闸门

把权限系统抽象成实习生的行为守则，展示只读、Bash 命令、文件修改三类操作对应的默认审批。随后点明 `CLAUDE.md` 是软提示，权限规则才是程序强制执行的硬边界。

### 第三段：建立六种模式的自主度光谱

用一条由绿到红的光谱承载六种模式。先让观众记住自主度和风险同时变化，再在卡片上区分 `default`、`acceptEdits`、`plan`、`auto`、`dontAsk`、`bypassPermissions` 的核心差异，不逐字堆表格。

### 第四段：把模式变成可操作的切换

展示 `Shift+Tab` 在 `default`、`acceptEdits`、`plan` 三档间循环，再把 `--permission-mode plan` 和 `settings.json` 的 `defaultMode` 放到另外两条入口。`auto`、`bypassPermissions`、`dontAsk` 的特殊进入方式作为边界提示出现。

### 第五段：从粗调进入精调

把模式比作总闸，把 `allow`、`ask`、`deny` 比作单条线路的开关。通过 `deny → ask → allow` 的优先级和 `Bash(ls *)` 的空格示意，说明规则如何精确到命令和路径。

### 第六段：展示单层规则的盲区

先让 `Read(./.env)` 拦住内置读取，再让 Python / Node 子进程从 Bash 绕过去；最后用沙箱把“所有进程访问路径”的防线补齐。视觉上必须明确：deny 不是无条件的铁壁。

### 第七段：把选择落到项目类型

同屏呈现玩具项目与生产／公司项目的模板。玩具项目可以 `acceptEdits` 提速，但仍拦危险动作；生产项目默认 `default`，放行低风险查看命令，敏感文件和危险命令直接拒绝。最右侧用红线收束 `--dangerously-skip-permissions` 的隔离环境边界。

### 第八段：用五分钟练习验证，而不是只背规则

用一个最小流程展示 `.claude/settings.json` 被加载，`git push` 被直接拒绝，`git status` 不弹批准提示。练习的价值是把“配置语法”变成可观察的行为结果。

### 第九段：总结控权能力并预告下一集

最后用“自主度滑杆”回收模式、切换、规则、沙箱和环境选择。下一集只显示源文章给出的标题“21「安全与风险边界」”，提出更上层的信任问题，不展开下一篇内容。

## 4. 视频价值

- 用同一危险模式在两个环境中的相反结论，把抽象的“风险取决于环境”变成视觉冲突。
- 用操作闸门和自主度光谱展示权限是行为边界，不是提示词礼貌。
- 用循环、分流和优先级动画解释命令与规则之间的关系。
- 用绕道读写和沙箱补防演示单层 deny 的真实边界。
- 用 deny／allow 的实际反馈证明配置生效，避免视频停留在 JSON 朗读。

## 5. 节奏与收束

- 开场快速建立“隔离环境／生产机器”的反差。
- 中段按“默认闸门 → 模式光谱 → 切换 → 精细规则”逐步增加控制精度。
- 第六幕用绕道案例制造一次反转，再进入模板和红线。
- 实操段保持终端步骤紧凑，以规则反馈为重点。
- 结尾保留约 2～3 秒的下一集预告停留，不引入下一篇正文。
