# 权限配置：放多松、收多紧，你说了算

## 全局视觉原则

- 采用 16:9 横屏、深色、克制的科技教程风格；所有画面文字只使用当前 permissions 主题和指定原文可追溯的命令、配置、状态。
- 视觉主隐喻是“审批闸门 + 自主度滑杆 + 环境边界”：权限不是一句提示，而是会改变工具行为的边界。
- 声音负责解释环境差异、模式含义和安全边界；画面负责展示闸门、光谱、规则匹配、绕道与实际反馈，不逐字复述口播。
- 主标题控制在一至两行；终端和配置面板使用等宽字体；高风险用低饱和红色，已放行或完成用绿色，提示和过渡用蓝紫色。
- 每幕只保留一个主要视觉事件，字幕预留独立底部安全区；原型控制、进度提示和说明文字只属于预览外壳。

## 逐 Scene 视觉设计

### Scene 01｜同一个危险模式，为什么结论相反？

- 画面结构：左右两个环境面板，共享同一个 `--dangerously-skip-permissions` 标签。
- 视觉动作：左侧隔离容器显示可重建和“提速”，右侧生产代码机器显示真实影响和红色风险；中间的模式标签保持不变。
- 状态变化：同一开关从绿色可承受切换为红色不可轻率承担。
- 口播互补：口播解释权限没有绝对对错，画面证明差异来自使用环境。
- 画面文字：`隔离容器`、`生产代码机器`、`可重建`、`真实代码`、`--dangerously-skip-permissions`

### Scene 02｜权限系统在管哪些动作？

- 画面结构：三列操作卡片接入一条审批闸门，下方是“提示层”和“强制层”的分层。
- 视觉动作：只读卡片绿灯直通，Bash 和文件修改卡片先停在批准闸门；`CLAUDE.md` 退到软提示层，权限规则锁定强制层。
- 状态变化：三类操作从“动作类型”转为不同的审批结果。
- 口播互补：口播解释默认待遇与软硬边界，画面只展示动作流向。
- 画面文字：`只读`、`Bash 命令`、`文件修改`、`直接放行`、`需要批准`、`权限规则强制执行`

### Scene 03｜六种模式是一条自主度光谱

- 画面结构：横向光谱从绿色低自主度到红色高自主度，六张卡按顺序排布。
- 视觉动作：卡片依次点亮，底部的“会不会先问”指标从高频询问移动到完全不问；`plan` 保留“只读”标记，`auto` 保留“分类器检查”标记。
- 状态变化：光谱从安全侧推向高自主度侧，最后停在隔离环境警告。
- 口播互补：口播负责解释六种模式，画面用短标签帮助记忆，不堆完整表格。
- 画面文字：`default`、`acceptEdits`、`plan`、`auto`、`dontAsk`、`bypassPermissions`、`只读`、`跳过检查`

### Scene 04｜Shift+Tab 怎么切，其他模式怎么进？

- 画面结构：左侧状态栏循环，右侧为启动参数和配置文件两个入口。
- 视觉动作：`default → acceptEdits → plan → default` 依次高亮；随后命令行显示 `claude --permission-mode plan`，配置卡显示 `defaultMode: acceptEdits`。
- 状态变化：会话内切换与启动时固定被分成两条路径。
- 口播互补：口播说明默认循环和特殊模式入口，画面只展示路径与结果。
- 画面文字：`Shift+Tab`、`default → acceptEdits → plan`、`--permission-mode plan`、`defaultMode`

### Scene 05｜allow、ask、deny：权限的精细开关

- 画面结构：左侧三种规则卡，右侧一条从规则到结果的匹配管线。
- 视觉动作：同一个 `git push` 先命中 `deny` 并停止；另一条 `npm run build` 命中 `allow`；底部放大 `Bash(ls *)` 与 `Bash(ls*)` 的空格差异。
- 状态变化：规则按 `deny → ask → allow` 顺序决出唯一结果。
- 口播互补：口播解释语法和优先级，画面展示命令如何被截断或放行。
- 画面文字：`allow`、`ask`、`deny`、`deny → ask → allow`、`git push`、`Bash(ls *)`

### Scene 06｜deny 不是铁壁，沙箱补上绕道

- 画面结构：敏感文件 `.env` 位于中间，左侧是内置 `Read`，右侧是 Bash → Python / Node 绕行，最外层是沙箱。
- 视觉动作：内置读取被 deny 拦截；脚本路径绕过工具层；沙箱闭合外圈，所有进程访问被挡住。
- 状态变化：单层工具限制显示“有盲区”，叠加沙箱后变为“路径级边界”。
- 口播互补：口播解释绕道机制，画面通过路径和封锁范围让边界可见。
- 画面文字：`Read(./.env)`、`Bash`、`Python / Node`、`绕道读写`、`沙箱`

### Scene 07｜玩具放松，生产收紧

- 画面结构：左右两张 `settings.json` 配置卡，底部横跨一条危险模式红线。
- 视觉动作：玩具卡高亮 `defaultMode: acceptEdits` 和两个 deny；生产卡高亮 `defaultMode: default`、低风险 allow、敏感文件 deny；红线只允许隔离环境通过。
- 状态变化：项目类型标签从“可重建”切换为“真实影响”，推荐模式随之收紧。
- 口播互补：口播解释模板选择，画面展示字段差异和危险模式边界。
- 画面文字：`玩具 / 个人项目`、`生产 / 公司项目`、`acceptEdits`、`default`、`仅隔离环境`

### Scene 08｜五分钟验证：deny 拦住，allow 放行

- 画面结构：单个终端按时间线分成五步，右侧同步出现规则状态。
- 视觉动作：`mkdir perm-demo`、创建 `.claude`、写入 `settings.json`、`/permissions` 检查；随后 `git push` 显示拒绝，`git status` 显示直接执行。
- 状态变化：从“配置文件存在”推进到“deny／allow 的行为反馈”。
- 口播互补：口播带领操作，画面突出不执行、不提示与不弹批准提示的区别。
- 画面文字：`perm-demo/.claude/settings.json`、`/permissions`、`git push`、`不执行，不提示`、`git status`

### Scene 09｜权限是环境匹配的行为边界

- 画面结构：三段路线“匹配环境 → 设定边界 → 验证反馈”，旁边收束模式、规则和沙箱三张卡。
- 视觉动作：环境卡先点亮，模式滑杆和规则闸门随后落位，最后盾牌和验证终端亮起。
- 状态变化：零散配置项变成一条可重复使用的控制流程。
- 口播互补：口播总结判断框架，画面只保留三个动作节点。
- 画面文字：`匹配环境`、`设定边界`、`验证反馈`、`模式`、`规则`、`沙箱`

### Scene 10｜下一篇：安全与风险边界

- 画面结构：左侧收起本篇“权限配置”卡，右侧出现下一篇预告卡。
- 视觉动作：镜头从“怎么配置”移向“是否应该信任”，标题停留约 2～3 秒。
- 状态变化：本篇完成标记，下一篇问题高亮。
- 口播互补：口播提出更上层的信任问题，画面不引入下一篇正文。
- 画面文字：`21「安全与风险边界」`、`什么时候该收，什么时候能放？`

## 全片视觉类型、组件与动画标准

### 视觉类型

- 环境风险对比：Comparison + Risk Boundary。
- 默认审批和模式光谱：Concept Diagram + Spectrum。
- 模式进入和规则匹配：Process + Terminal Demo。
- deny 绕道与沙箱补防：Security Boundary + Process。
- 两套模板与五分钟练习：Configuration + Terminal Demo。
- 结尾路线与下一集卡片：Summary Diagram + Next Episode Card。

### 组件语言

- 深色背景、蓝紫主强调、绿色表示放行或可恢复、红色表示高风险或被拒绝。
- 面板使用细边框、统一圆角和轻微阴影；危险模式使用红色边框但不做刺眼发光。
- 代码、命令和配置使用等宽字体；普通解释文字保持清晰层级。
- 主标题、主体面板和底部字幕保持空间分离；不把长 JSON 或整张文章表格塞进画面。
- 预览导航、进度提示和原型说明只存在于 HTML 外壳，不属于视频内容。

### 动画顺序

1. 先出现环境、操作或配置面板。
2. 再进入权限模式、规则或命令流。
3. 发生批准、拒绝、绕道、隔离或模板切换。
4. 最后高亮本幕唯一结论。

## Gate 2 内部审查结论

- `narration-script.md` 每个 Scene 下只有实际口播，没有视觉说明、制作备注或 Gate 清单。
- 视觉表达与口播分工清晰：口播解释选择和边界，画面展示闸门、光谱、规则反馈与状态变化。
- 所有画面文字均可追溯到指定原文或前置生产资料；未引入下一篇正文或参考视频业务语义。
- 10 个 Scene 的横屏构图、信息密度和动画事件可由无依赖 HTML + CSS + 少量 JS 表达。
- 本阶段到 Visual Prototype 为止，不生成 `tts-script.json`、音频、字幕、Timeline，不修改 `src/videos/`。
