# Claude Code 图片与多模态 · Video Narrative

## 1．叙事命题

这条视频不从“图片功能介绍”开始，而是先让观众看到一个描述成本很高的问题：设计稿截图交给 Claude 后，页面骨架和 CSS 很快出现。

叙事核心是：

> **图片不是多一个输入格式，而是把任务现场直接交给 Claude；当文字说不清时，给它看通常比给它讲更快。**

## 2．观众认知路径

```text
先看到效率差距
↓
建立“描述成本”判断标准
↓
掌握三种给图入口
↓
记住 Mac 粘贴图片的关键快捷键
↓
理解截图、设计稿、结构图的三类用途
↓
学会多图引用和核对
↓
用三步练习完成第一次输入
↓
收束为可执行选择
```

## 3．叙事结构

### 第一段：先让观众看到“给它看”

开场用设计稿截图、生成 CSS 和浏览器结果构成一次快速前后变化。口播不先解释 API，而是指出：很多描述要花一上午，图片可以把现场直接交出去。

### 第二段：先判断要不要上图

把“文字描述不清楚或繁琐”变成分流规则，并通过页面错位、报错弹窗、设计稿三种对象让标准立刻落地。

### 第三段：三条入口，记住一个坑

先总览拖拽、`ctrl+v`、图片路径三种入口，再拆出拖拽和粘贴的具体状态。Mac 的 `ctrl+v` 是这一段唯一需要强记的反直觉细节，使用错误路径对比强化记忆。

### 第四段：三类用途从“现场”到“结构”

依次展示报错／UI 截图、设计稿、图表／schema／架构图。声音解释每类输入适合解决什么问题，画面展示输入如何变成分析、代码或结构建议。

### 第五段：多图核对与第一次练习

说明多图可以放在同一条提示中，`[Image #N]` 是引用编号，并用 Cmd／Ctrl+Click 打开核对。最后把准备图片、启动 `claude`、请求描述压缩为三步。

### 第六段：总结与系列承接

用“怎么喂、能干嘛、什么时候上图”三栏速查卡收束，并以“把图片作为任务上下文”作为系列承接视觉事件，不引入下一篇未提供的具体主题。

## 4．视频价值

- 用前后变化展示“给图比描述快”，而不是把文章变成文字卡片。
- 用判断仪表盘把“该不该用图片”变成一个可重复使用的决策。
- 用键盘和终端状态变化展示 `ctrl+v` 的具体操作差异。
- 用三类真实图片场景证明多模态输入的价值边界。
- 用编号、点击和三步流程把文档细节转成可以立刻尝试的动作。

## 5．节奏与信息密度

- 共 11 个 Scene，按认知变化拆分，不设置固定总时长。
- Scene 01、04、05、10 使用动作或状态变化作为主要节奏；Scene 02、03、11 用简洁结构收束信息。
- 每幕只保留一个主画面机制：前后对照、判断分流、入口流程、快捷键对比、图片引用、现场诊断、设计还原、关系图、终端练习或总结卡。
- 主标题控制在 1～2 行，辅助文字只保留必要标签；画面底部预留字幕安全区。

## 6．系列关系

- 本篇承接上一篇“常见工作流”中以文字给指令的方式，新增图片作为输入上下文。
- 本篇最后保留“把图片能力接进更多真实任务”的系列承接卡，不读取或猜测下一篇文章内容。

## 7．叙事边界

- 不把图片输入讲成独立的自动截图或视觉设计工具。
- 不承诺像素级复刻、绝对准确识图或完全无需人工判断。
- 不为了凑功能而扩展到 source 没有提到的文件格式、模型原理或 API。
- 终止边界是 Visual Prototype；本资料不进入 TTS、音频、字幕、Timeline 或 Remotion。
