# Claude Code 图片与多模态 · Content Analysis

> 目标：从原文提取“什么时候给 Claude 看图、如何给、给图能解决什么问题”的知识骨架，再决定视频的认知路径。

## 1．核心命题

这篇文章真正要建立的不是“Claude Code 支持图片”这一条功能事实，而是一个可执行的判断标准：

> **当文字描述比截图更费劲、更不清楚时，就该把图片作为上下文交给 Claude Code。**

图片的价值不在于替用户截图，而在于让 Claude 直接读取界面、错误、设计和结构关系，减少人的描述成本，也减少模型根据模糊描述进行猜测的成本。

## 2．观众需要完成的认知变化

观众开始时可能把图片输入理解成“多一个上传按钮”；看完后应完成三次变化：

1. 从“图片是附件”变成“图片是任务现场和上下文”。
2. 从“我应该把图里的内容描述给 Claude”变成“我可以直接把图交给 Claude，让它看着做事”。
3. 从“只要有图就上传”变成“先判断描述成本，再决定是否上图”。

## 3．必须保留的信息

### A．判断标准

- 文本描述不清楚或繁琐时使用图像。
- 典型判断：描述起来比截图还累，就上图。
- Claude Code 负责看懂图片内容，不负责替用户完成截图。

### B．三种输入图片的方法

- 把图片文件拖进正在运行 Claude Code 的终端窗口。
- 复制图片后使用 `ctrl+v` 粘贴；Mac 也使用 `ctrl+v`，不要默认按 `cmd+v`。
- 在提示中直接给出图片路径，适合脚本或已存好的图片。

### C．粘贴方式的关键细节

- 粘贴成功后，输入框会显示 `[Image #1]` 这样的图片占位标记。
- Windows／Linux 通常使用 `ctrl+v`；如果 WSL 终端拦截，可改用 `alt+v`。
- 个别终端对 `cmd+v` 的行为不同，但 `ctrl+v` 是更稳定的通用记法。

### D．图片的三大用途

1. 报错截图或 UI 截图：把错误现场、颜色、布局和错位直接交给 Claude 分析。
2. 设计稿还原：让 Claude 生成 CSS 或推断 HTML 结构，得到一个高完成度起点，再人工微调。
3. 图表、数据库 schema、架构图：让 Claude 读取模块、连接、数据流和分层关系，再协助修改或审查。

### E．多图与引用

- 同一条提示中可以放多张图片，用于旧设计稿与新设计稿的对比等任务。
- Claude 使用 `[Image #1]`、`[Image #2]` 等编号引用图片。
- Mac 用 `Cmd+Click`，Windows／Linux 用 `Ctrl+Click`，可以打开它引用的图片。

### F．三步跑通

- 准备一张 PNG／JPG 并记住路径。
- 在任意目录启动 `claude`。
- 通过拖拽、粘贴或路径给图，再问“这张图里是什么？用中文描述一下”。
- 看到 Claude 准确描述图片内容，就说明输入链路已经跑通。

## 4．认知关系

### 描述成本关系

```text
文字描述清楚、成本低 → 直接打字
文字描述不清楚或繁琐 → 直接给图
```

### 输入方式关系

```text
拖拽文件 ／ ctrl+v 粘贴 ／ 图片路径
                 ↓
          Claude 读取图片内容
```

三种方式的入口不同，但都服务于同一个结果：让图片成为提示中的上下文。

### 图片用途关系

```text
看见现场 → 报错与 UI 截图
还原界面 → 设计稿截图
读懂关系 → 图表、schema、架构图
```

### 交互细节关系

```text
多图输入 → [Image #N] 引用 → Cmd/Ctrl+Click 打开核对
```

## 5．适合视频表达的内容

- 开场用“设计稿截图 → CSS → 浏览器还原”的前后变化建立一图胜千言的直觉。
- 用一个“描述成本”判断仪表盘把文字输入和图片输入分流。
- 用三条真实入口路径组成并行流程，突出它们结果相同。
- 用键盘按键动画强调 Mac 的 `ctrl+v` 坑，并把 `cmd+v` 标成错误路径。
- 用截图现场、设计稿和架构图三种画面切换，展示三大用途的差异。
- 用多图编号和点击动作说明引用与核对，不把交互细节写成大段说明。
- 用终端三步流程收束成可执行的第一次尝试。

## 6．可以弱化的信息

- “像素级复刻”与“高完成度起点”的细微措辞可合并成合理预期：先得到八成稿，再人工微调。
- 医院 CT、裁缝样衣等类比保留其认知作用，不在画面中完整复述。
- 各终端对快捷键的个别差异可以压缩为 `ctrl+v` 是通用优先路径，WSL 例外放入口播说明。
- `claude` 启动后的欢迎屏幕无需做成真实品牌界面，只保留命令和“出现输入框”的状态。

## 7．事实边界与画面文字审查

- 不把 Claude Code 描述成会自动替用户截图；它读取的是用户提供的图片。
- 不把设计稿还原描述成必然像素级一致；画面使用“高完成度起点／再微调”。
- 不把 `cmd+v` 说成所有终端都绝对失败；重点是 Mac 默认记 `ctrl+v`，个别终端可能另有行为。
- 不把图片理解扩大为自动识别一切内容；仅展示原文给出的报错、UI、设计稿、图表、schema、架构图场景。
- 画面中的命令、快捷键、占位符、图片编号、错误名和提示语均能追溯到本篇 source 或本层生产资料。
- 不读取或复用下一篇文章，不引入下一篇的主题或固定文案。

## 8．Gate 1 内部审查结论

- 核心命题、判断标准、三种输入方式、三大用途、多图引用和三步练习均已从 source 提取。
- Video Narrative 不机械复述文章章节，而是按“先判断，再操作，后证明价值，最后上手”的观众认知顺序组织。
- 11 个 Scene 各自只有一个主要认知任务，覆盖文章的主要事实和可视觉化关系。
