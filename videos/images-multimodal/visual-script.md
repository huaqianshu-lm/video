# Claude Code 图片与多模态 · Visual Script

> 目标：让声音解释图片输入的判断逻辑和操作细节，让画面演示输入路径、现场信息、结构关系和成功状态。

## 全局视觉原则

### 1．声音负责解释，画面负责证明

口播负责说明什么时候该上图、快捷键为什么容易错以及三类用途的边界；画面负责展示图片进入终端、占位符出现、错误现场被分析、设计稿变成代码和结构连线被读懂。

### 2．每幕只保留一个视觉中心

11 个 Scene 依次处理开场前后变化、判断分流、三种入口、拖拽、快捷键、路径引用、错误现场、设计还原、结构图、三步练习和总结卡。每幕不同时塞入多种主机制。

### 3．保持 16:9 深色教程感

- 使用 1920 × 1080 横屏构图，深色终端和蓝紫色结构强调保持系列一致。
- 绿色只表示输入成功、分析完成或高完成度结果；红色只表示错误路径和未输入成功。
- 标题控制在 1～2 行，路径、命令、快捷键、图片编号和错误信息使用等宽字体。
- 终端、截图和结构图不贴边，底部预留字幕安全区。

### 4．画面文字必须有当前资料依据

所有命令、快捷键、路径示例、图片引用、提示语、错误名和场景标签均来自本篇 source 或本篇前置生产资料。不得把其他视频的业务语义、固定状态文字或未提供的下一篇主题带入原型。

## 逐 Scene 视觉设计

### Scene 01｜给它看，比跟它讲快

- **画面结构**：左侧设计稿缩略图，中部 Claude 工作台，右侧浏览器组件；三者以箭头连接。
- **视觉动作**：设计稿进入工作台，CSS 行逐步出现，右侧页面从空白变为近似设计稿的组件。
- **信息重点**：`设计稿 PNG`、`生成 CSS`、`高完成度起点`。
- **与口播互补**：口播解释过去的测量成本，画面只展示从图片到代码和页面结果的变化。
- **场景类型**：`Before/After Comparison + UI Simulation`。

### Scene 02｜先看描述成本，再决定上不上图

- **画面结构**：中央是“描述成本”分流仪表盘，左边为“文字清楚”，右边为“文字不清楚／繁琐”；下方放三个现场缩略卡。
- **视觉动作**：三个缩略卡依次落入“直接给图”一侧，左侧保持简洁文字输入。
- **信息重点**：`描述起来比截图还累？`、`直接给图`、`页面错位`、`报错弹窗`、`设计稿`。
- **与口播互补**：口播给判断规则，画面把抽象标准变成可识别的分流动作。
- **场景类型**：`Decision Diagram + Scenario Cards`。

### Scene 03｜拖、贴、给路径

- **画面结构**：三条输入轨道从文件、键盘和路径提示框汇入同一个图片上下文节点。
- **视觉动作**：三条轨道依次点亮，中心节点显示 `[Image #1]`，终端输入区出现“已挂上”状态。
- **信息重点**：`拖进窗口`、`ctrl+v`、`图片路径`、`[Image #1]`。
- **与口播互补**：口播说清三种方式，画面展示它们最终汇合为同一张图片上下文。
- **场景类型**：`Process + Connection Diagram`。

### Scene 04｜把图片直接拖进窗口

- **画面结构**：左侧文件管理器显示 `error-screenshot.png`，右侧终端窗口有输入区。
- **视觉动作**：图片文件沿拖拽轨迹进入终端，终端输入区从空白变成 `[Image #1]`，成功边框变绿。
- **信息重点**：`error-screenshot.png`、`拖入 Claude Code`、`[Image #1]`。
- **与口播互补**：声音用生活化比喻降低门槛，画面证明文件实际落点和成功反馈。
- **场景类型**：`UI Simulation + Task Execution`。

### Scene 05｜Mac 的关键坑：ctrl+v，不是 cmd+v

- **画面结构**：左右两个键盘操作卡，左侧 `ctrl+v`，右侧 `cmd+v`；下方分别连接成功和失败终端状态。
- **视觉动作**：`ctrl+v` 让 `[Image #1]` 出现；`cmd+v` 输出一长串路径文本并标红，最后把 `Mac：ctrl+v` 固定为主标签。
- **信息重点**：`Mac：ctrl+v`、`不要默认 cmd+v`、`图片已挂上`、`路径文本`。
- **与口播互补**：口播补充 WSL 的 `alt+v` 例外，画面集中记住主规则和错误后果。
- **场景类型**：`Keyboard Comparison + Error State`。

### Scene 06｜图片已存好，就直接给路径

- **画面结构**：左侧提示框显示图片路径和两张图片标签，右侧回复面板显示 `[Image #1]`、`[Image #2]`。
- **视觉动作**：两条路径进入提示后，回复逐条引用编号；点击 `[Image #2]` 后弹出对应图片预览。
- **信息重点**：`Analyze this image: /path/to/your/image.png`、`[Image #1]`、`[Image #2]`、`Cmd+Click`。
- **与口播互补**：声音说明脚本和多图场景，画面演示引用编号与核对动作。
- **场景类型**：`Prompt + Multi-image Reference`。

### Scene 07｜贴报错截图，直接给它现场

- **画面结构**：左侧为带红色错误弹窗和错位按钮的 UI 截图，右侧为 Claude 提示框和分析标注。
- **视觉动作**：截图中的红叉、错位边界和按钮位置被依次圈出，提示框出现两个问题示例。
- **信息重点**：`Here's a screenshot of the error.`、`What's causing it?`、`Describe the UI elements`。
- **与口播互补**：声音解释图像保留的上下文，画面直接展示文字转述难以保留的颜色、位置和排版。
- **场景类型**：`Screenshot Diagnosis + UI Simulation`。

### Scene 08｜从设计稿到能跑的代码

- **画面结构**：左侧设计稿，中部 CSS／HTML 代码，右侧浏览器组件；下方是一条“八成稿 → 人工微调”的进度线。
- **视觉动作**：设计稿颜色和间距标记映射到代码行，浏览器组件出现，最后只保留两处微调标记。
- **信息重点**：`照着这张设计稿生成对应的 CSS`、`What HTML structure would recreate this component?`、`八成稿`。
- **与口播互补**：口播说明合理预期，画面展示高完成度起点而不承诺像素级复刻。
- **场景类型**：`Design-to-Code Demo + Before/After`。

### Scene 09｜结构关系，用图更容易讲清

- **画面结构**：中央架构图由用户、订单、库存和支付等抽象节点组成，旁边叠放 schema 询问卡；仅使用文章中的关系性表达，不添加业务结论。
- **视觉动作**：节点和箭头逐层扫描，连接关系高亮，随后出现 schema 修改和问题审查提示。
- **信息重点**：`database schema`、`How should we modify it?`、`Are there any problematic elements?`。
- **与口播互补**：声音解释“谁连谁、数据怎么流”，画面用扫描和连线证明图片适合表达结构。
- **场景类型**：`Code Exploration + Connection Diagram`。

### Scene 10｜三步跑通：喂图、提问、看懂

- **画面结构**：终端横向三步进度：准备图片、启动 `claude`、给图并提问；右侧回复框显示中文描述。
- **视觉动作**：每完成一步出现绿色勾，最后图片内容被准确描述并显示 `Image understood`。
- **信息重点**：`1．准备图片`、`2．claude`、`3．描述这张图`、`Image understood`。
- **与口播互补**：口播给出完整试法，画面提供可照抄的顺序和成功判据。
- **场景类型**：`Terminal Demo + Checklist`。

### Scene 11｜什么时候该上图？描述比截图还累的时候

- **画面结构**：三栏总结卡分别回答“怎么喂”“能干嘛”“什么时候上图”，下方单独升起系列承接卡。
- **视觉动作**：三栏卡按顺序出现，最后收缩为一条判断句，承接卡停留约 2～3 秒。
- **信息重点**：`拖／ctrl+v／路径`、`现场／还原／读结构`、`描述比截图还累 → 上图`、`让图片成为任务上下文`。
- **与口播互补**：声音完成总结，画面提供可记忆的速查结构和系列延伸方向。
- **场景类型**：`Summary Card + Preview`。

## 全片视觉类型、组件与动画标准

### 视觉类型

- `Before/After Comparison`：Scene 01、08。
- `Decision Diagram`：Scene 02。
- `Process / Connection Diagram`：Scene 03、06、09。
- `UI Simulation / Terminal Demo`：Scene 04、07、10。
- `Keyboard Comparison`：Scene 05。
- `Summary Card + Preview`：Scene 11。

### 组件标准

- 深色终端窗口、文件管理器、提示框、代码框和浏览器面板使用统一圆角、细边框和低强度阴影。
- 图片缩略图使用统一的画框和 `PNG`／`JPG` 标签；图片编号统一使用等宽字体。
- 绿色只用于成功输入、完成分析和测试式通过状态；红色只用于错误或失败路径。
- 原型导航、进度条和幕内字幕区域只服务于预览，不属于最终视频画面。

### 动画标准

- 一级信息动画：文件拖入、按键触发、占位符出现、图片扫描、连线高亮、结果生成。
- 二级注意力动画：错误边框、路径高亮、引用编号和“描述成本”分流聚焦。
- 三级装饰动画仅使用轻微淡入和位移，不加入粒子、复杂转场或无意义旋转。
- 每个 Scene 的主要元素先完成入场，再留出阅读时间；Scene 11 的承接卡停留约 2～3 秒。
