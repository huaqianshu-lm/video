# Claude Code 图片与多模态 · Narration Script

## Scene 01｜给它看，比跟它讲快

你想让 Claude Code 还原一张设计稿，过去得先对着图片量间距、字号、颜色和圆角，光描述这些细节就能磨掉一上午。现在更直接：把 PNG 拖进窗口，告诉它照着设计稿生成 CSS。几分钟后，布局、配色、圆角和阴影就先有了一版。给它看，比跟它讲快。

## Scene 02｜先看描述成本，再决定上不上图

判断要不要用图，其实就一句话：当文字描述比截图还费劲，就直接上图。页面错位、报错弹窗、设计稿，这些东西用嘴说很容易漏掉位置、颜色和上下文；截张图，现场就完整交过去了。但要注意，Claude Code 看的是你提供的图片，它不会替你完成截图。

## Scene 03｜拖、贴、给路径

把图片交给 Claude Code，有三种方法：从文件管理器直接拖进终端，复制图片后按 `ctrl+v` 粘贴，或者在提示里直接写图片路径。三种入口不一样，结果一样，都是让 Claude 把图片作为当前任务的上下文。粘贴成功后，输入框里会出现 `[Image #1]` 这样的占位标记。

## Scene 04｜把图片直接拖进窗口

第一种，直接拖。把图片从访达或者文件管理器拖进正在运行 Claude Code 的终端窗口，松手，它就挂进当前提示了。这个操作跟把文件拖进聊天框差不多，最直觉，也最适合第一次试。

## Scene 05｜Mac 的关键坑：ctrl+v，不是 cmd+v

第二种是复制粘贴，但 Mac 这里有个特别反直觉的坑：粘贴图片也用 `ctrl+v`，不是习惯里的 `cmd+v`。很多终端里按错了，出来的是一长串路径文本，图片根本没进去。记住，看到 `[Image #1]`，才说明图片真的挂上了。Windows 和 Linux 通常也用 `ctrl+v`；如果 WSL 拦截，再考虑 `alt+v`。

## Scene 06｜图片已存好，就直接给路径

第三种，直接给路径。图片已经存好，或者你要写进脚本时，这种最省事，比如提示里写 `Analyze this image: /path/to/your/image.png`。一条提示也可以放多张图。Claude 会用 `[Image #1]`、`[Image #2]` 来引用它们；Mac 用 `Cmd+Click`，Windows 和 Linux 用 `Ctrl+Click`，可以点开对应图片核对。

## Scene 07｜贴报错截图，直接给它现场

第一个最实用的用途，是报错和 UI 截图。错误弹窗里的图标、颜色、排版，页面里差几个像素的错位，光靠文字很难讲完整。把截图丢进去，再问一句“这个错误是什么原因”，或者“描述一下这张图里的 UI 元素”，Claude 就能对着现场分析，而不是靠你转述一个模糊版本。

## Scene 08｜从设计稿到能跑的代码

第二个用途，是还原设计稿。你可以直接说“照着这张设计稿生成对应的 CSS”，也可以问它需要怎样的 HTML 结构来复刻这个组件。合理的预期不是像素级复刻，而是先拿到一版高完成度的起点。你再微调最后一两成，工作量就从从零搭建，变成修改一版能跑的代码。

## Scene 09｜结构关系，用图更容易讲清

第三个用途，是图表、数据库 schema 和架构图。这些图里最重要的不是某个颜色，而是谁连着谁、数据怎么流、模块怎么分层。你可以让 Claude 先读懂当前 schema，再问新功能应该怎么改；也可以让它检查架构图里有没有不合理的地方。先看懂关系，再做修改或审查。

## Scene 10｜三步跑通：喂图、提问、看懂

想马上试一次，不需要准备项目。第一步，找一张 PNG 或 JPG，记住它的位置。第二步，在任意目录启动 `claude`。第三步，用拖拽、粘贴或路径把图交进去，再问：“这张图里是什么？用中文描述一下你看到的内容。”如果它准确说出了图片里的东西，就说明整条喂图链路跑通了。

## Scene 11｜什么时候该上图？描述比截图还累的时候

最后把要点记成三句话：怎么喂，拖进窗口、`ctrl+v` 粘贴，或者给图片路径；能干嘛，看报错和 UI 现场、还原设计稿、读图表和架构关系；什么时候上图，文字描述比截图还累的时候。以后遇到说不清的现场，就别急着组织一大段话，先把图片交给 Claude，让它看着干活。
