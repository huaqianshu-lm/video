## 1. 核心命题

子代理不是“任务越多越该拆”的高级装饰，而是一个拥有独立上下文、独立人设和独立工具／权限的专项助手。它适合承接脏、重、可自包含、需要隔离或锁定权限的工作；简单、快速、需要频繁来回沟通的工作，留在主对话里往往更快、更省。

这条视频真正要教会观众的，不是如何把任务拆得更多，而是建立“该外包还是自己干”的判断线。

---

## 2. 必须保留的核心信息

### A. 子代理是什么

- 子代理在自己的 context window 中运行。
- 它可以拥有自定义系统提示，也就是独立人设。
- 它可以拥有特定工具访问权限和独立权限。
- 它从一张白纸开始，看不到主对话的历史、已调用技能和主对话已经读取的文件。
- 它在自己的上下文里完成工作，通常只把相关结论交回主对话。

### B. 子代理解决的三个问题

1. **隔离上下文**：测试输出、文档、日志或 API 返回等大量中间信息留在子代理上下文，主对话只接收摘要。
2. **专精任务**：把反复出现的代码审查等工作固化为专属人设，并通过工具清单限制能力边界。
3. **可并行**：认证、数据库、API 等互不依赖的调研任务可以分别交给不同子代理同时处理。

### C. 什么时候不该拆

- 子代理从头收集上下文，有启动开销。
- 它看不到此前对话，交代不清时容易返工。
- 每多开一个上下文都会增加 token 花费。
- 多个子代理回灌大量细节，可能再次挤满主对话。
- 频繁来回、共享上下文、快速小改、在意速度的工作留在主对话。
- 产出大量中间过程、可自包含、需要锁定工具权限且只需回结论的工作，才适合外包。

### D. 怎么创建

- 交互式入口是 `/agents`。
- 交互式流程包含位置、让 Claude 生成、工具、模型和保存等选择。
- 项目级子代理可以放在 `.claude/agents/`，个人级子代理可以放在 `~/.claude/agents/`。
- 手写文件是 Markdown：YAML frontmatter 管配置，正文是系统提示。
- `name` 和 `description` 是必填字段；`tools`、`model`、`permissionMode` 等字段用于进一步限定配置。
- 手写或直接修改磁盘文件后，需要重启会话才能加载。

### E. 怎么触发和验证

- `description` 清晰时，Claude 可以根据任务自动委派。
- 自然语言点名可以请求某个子代理；`@` 点名用于确保指定子代理运行。
- 子代理完成后把结论交回主对话，过程留在自己的上下文中。
- 实战用只读的 `code-reviewer` 检查 `calc.py`：它可以读文件并给建议，但不能修改文件。
- 通过 `cat calc.py` 验证文件仍保持原样，证明工具权限确实限制了写入。

## 3. 认知关系

### 因果关系

```text
大量中间输出 / 反复重复同类任务 / 互不依赖的任务
        ↓
需要隔离上下文 / 固化专长 / 并行处理
        ↓
考虑使用子代理
```

```text
从白纸收集上下文 + 额外 token + 回灌结果
        ↓
简单任务反而更慢、更贵、更容易把主线堆满
        ↓
建立“不该拆”的判断线
```

### 对比关系

| 判断维度 | 主对话 | 子代理 |
|---|---|---|
| 上下文 | 共享当前对话和已知背景 | 独立上下文，从任务交代开始 |
| 任务形态 | 快速小改、频繁来回 | 自包含、脏重、只回结论 |
| 权限 | 依主对话可用能力 | 可以通过工具清单主动收窄 |
| 结果 | 直接继续对话 | 独立工作后返回摘要 |

### 流程关系

```text
创建配置
  → 加载子代理
  → 自动委派或 @ 点名
  → 子代理独立读取与分析
  → 只回结论
  → 检查结果和权限边界
```

## 4. 可视觉化内容

- 主对话桌面与子代理房间的上下文隔离：大量日志留在子代理房间，主线只收到结论。
- 三个用途从中心节点展开：隔离上下文、专精任务、可并行。
- “主对话 vs 子代理”的决策分流，而不是静态特性列表。
- `/agents` 交互式创建流程的步骤推进。
- Markdown 配置文件的 frontmatter 与正文分层。
- `description` 自动委派与 `@` 直接点名的双路径。
- `calc.py` 只读审查流程：建立目录、写配置、启动 Claude、点名运行、`cat` 验证不变。
- `tools: Read, Grep, Glob` 与“只回结论、不越权”的结果状态。
- 结尾从“会建”回到“会判断”，再进入下一集插件预告。
