# 子代理（Subagents）视频化 · 第四步：Narration Script

---

## Scene 01｜拆得多，不等于更专业

很多人刚知道子代理，就忍不住把一个任务拆成五六份，觉得这样更专业，也更高效。

但说句实话，多数人一上来就拆，是错的。

子代理不是任务越多越该用的高级玩法。用对了，它能帮你省心；用错了，就会又慢又贵。

所以这篇真正要解决的问题不是“怎么拆得更多”，而是：什么时候该外包，什么时候自己干更快。

---

## Scene 02｜子代理在自己的房间干活

先给子代理下一个最简单的定义。

它就像 Claude 临时雇来的一个专项助手，在自己的房间里干活，干完以后只把结论交给你。

它从一张白纸开始，看不到你们之前的对话，也不知道主对话已经读过哪些文件。但它有自己的上下文、自己的系统提示，也就是自己的人设，还可以有单独的工具和权限。

你不需要把它翻过的所有资料重新搬回主对话，只接收真正有用的结果。

---

## Scene 03｜它真正解决三个问题

子代理真正解决的，主要是三个问题。

第一，隔离上下文。跑测试、翻日志、获取文档，这些工作可能产生几百上千行中间输出。交给子代理以后，细节留在它的房间里，主对话只收到摘要。

第二，专精任务。如果你总是重复要求 Claude 做代码审查，就可以把这套人设和工作方式固化成一个专门的代码审查员。

第三，可并行。认证、数据库和 API 这类互不依赖的任务，可以分别交给不同的子代理同时探索。

---

## Scene 04｜简单活儿别硬拆

但这不代表所有任务都应该交给子代理。

子代理从头开始收集上下文，有启动开销；如果任务交代不清，还可能因为看不到前面的对话而返工。多开几个上下文，也会多花 token，最后把大量结果回灌回来，主对话还是会被堆满。

所以，频繁来回、共享上下文、快速小改、在意速度的活，留在主对话。

产出大量中间过程、能够自己完成、需要锁定工具权限，而且只需要回一句结论的活，才适合外包。

---

## Scene 05｜用 /agents 交互式创建

确定值得外包以后，最省事的创建方式是使用 `/agents`。

在交互式界面里，你可以选择把它放在个人位置还是项目位置，让 Claude 根据描述生成配置，选择它能使用的工具和模型，最后保存。

这里有一个关键动作：主动砍掉不需要的工具。比如代码审查员只应该读文件，就不要给它写入工具。否则它可能继承主对话的全部能力。

---

## Scene 06｜一个 Markdown 文件就是岗位说明

交互式创建以后，子代理落到磁盘上，其实就是一个 Markdown 文件。

上面的 YAML 头管理硬信息：叫什么名字，什么任务该派给它，能使用哪些工具，用哪个模型。下面的正文则是它的岗位说明书，规定它是谁、被调用时要做什么。

其中 `name` 和 `description` 是必填字段。文件放在 `~/.claude/agents/`，可以供你的所有项目使用；放在 `.claude/agents/`，就是当前项目的专属助手。

还有一个容易踩的坑：手写或直接修改文件以后，需要重启会话，它才会加载新的配置。

---

## Scene 07｜description 自动派单，@ 直接点名

建好以后，子代理有两种常见的触发方式。

第一种是让 `description` 驱动自动委派。你的任务描述如果和某个子代理的岗位匹配，Claude 就可能自动把任务派给它，所以 description 写得越清楚，自动委派越准。

第二种是直接点名。你可以在自然语言里叫出它的名字，也可以用 `@` 选择指定的子代理。想确保一个刚建好的子代理真的运行，直接用 `@` 更稳。

无论哪种方式，子代理都在自己的上下文里工作，最后只把结论交回主对话。

---

## Scene 08｜五分钟跑通一个只读点评员

现在手写一个最小的只读代码点评员。

先创建一个玩具项目和 `.claude/agents` 目录，再写入一个叫 `code-reviewer` 的配置。它只拿到 Read、Grep 和 Glob，用来读取文件和给出建议，但不给 Write 或 Edit。

接着准备一个简单的 `calc.py`。里面的函数名和参数名都不够清楚，而且没有处理除数为零。

启动 Claude 以后，用 `@agent-code-reviewer` 点名，让它点评 `calc.py`。它会读文件、分析问题，然后把一份点评结论交回主对话。

---

## Scene 09｜只读权限真的能挡住修改

这次实战的重点，不只是它能指出问题，而是它没有权限直接改文件。

因为配置里只给了 Read、Grep 和 Glob，没有 Write 或 Edit，所以它只能提出命名和边界判断方面的建议。

退出 Claude，回到终端执行 `cat calc.py`。如果输出仍然是原来的两行，就说明“只读”不是一句说明，而是真正生效的权限边界。

你亲手跑通了这样一条链路：写配置、加载、点名触发、独立工作、只回结论，而且不越权。

---

## Scene 10｜真正的门槛是判断线

所以，子代理真正的门槛不是会不会创建，而是有没有分寸。

脏活、可自包含、需要锁定权限的任务，可以外包给子代理。简单、快速、需要共享当前上下文并频繁沟通的任务，自己在主对话里完成。

子代理强，但强在用对场景，不在拆得多。
