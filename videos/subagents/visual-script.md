# 子代理（Subagents）视频化 · 第五步：Visual Script

> 目标：基于 Scene Script 和纯口播稿，确认横屏构图、视觉动作、状态变化和信息密度。声音负责解释，画面负责演示、证明和建立直觉。

---

## 全局视觉原则

### 1. 让“判断”成为视觉主线

本片不是字段百科。所有画面都围绕一个问题组织：这个任务应该留在主对话，还是外包给子代理？

### 2. 声音解释，画面证明

旁白解释上下文、成本和选择逻辑；画面展示房间隔离、分流、配置加载、委派状态和文件是否被修改。

### 3. 少做静态卡片，多做过程

优先使用堆积、扫描、连线、分流、配置高亮、终端执行和前后状态对照。避免把口播全文直接铺在屏幕上。

### 4. 一个 Scene 一个视觉中心

每幕只让一个核心动作成为焦点。解释多个字段时，用代码高亮顺序而不是同时展示所有说明；总结时只保留判断线。

### 5. 横屏构图和信息密度

- 1920 × 1080，深色背景，左右留出安全边距。
- 主标题控制在 1～2 行，卡片文字尽量短。
- 终端和代码区域使用等宽字体，中文说明作为辅助层。
- 每个 Scene 保留一个幕内短标签，不把口播稿整段上屏。
- 动画为信息服务：堆积表达拥挤，扫描表达理解，连线表达委派，状态切换表达权限验证。

# Scene 01｜拆得多，不等于更专业

## 视觉目标

让观众先看到过度拆分造成的拥挤，制造“这是不是反而更慢”的问题。

## 主要画面

中心是一张主对话工作台。左侧是用户任务，右侧连续弹出五个子代理卡片：`收集上下文`、`等待回灌`、`额外上下文`、`返工`、`更多 token`。

卡片叠加到工作台边界，底部出现一个被遮住的输入框。最后所有卡片淡出，只留下一个清晰的判断问题。

## 动画

1. 主对话显示“拆成五六个任务”的任务条。
2. 子代理卡片从不同方向进入，依次显示启动和回灌状态。
3. 工作台可用区域变窄，回灌线变多。
4. 卡片停止堆叠，画面中心切换为“该外包，还是自己干？”。

## 屏幕文字

- `子代理：用对省心，用错又慢又贵`
- `该外包，还是自己干？`

## Voice / Visual 分工

旁白说明“拆得多不等于专业”；画面只负责让启动、回灌和拥挤变得可见。

## Visual Type

`Decision Diagram` + `Process`

# Scene 02｜子代理在自己的房间干活

## 视觉目标

建立“主工作台／子代理房间”的空间直觉。

## 画面结构

左侧是 `主对话`，保留少量当前任务信息；右侧是 `子代理` 房间，内部有日志、文件和工具清单。两侧之间只有一条细的“任务交代”输入线和一张“结论摘要”回传卡。

## 动画

1. 任务交代从主对话进入子代理房间。
2. 子代理房间快速展开日志与文件细节，主工作台不变化。
3. 右侧细节收缩成一张“结论摘要”。
4. 摘要沿回传线进入主对话，右侧细节继续留在房间中。

## 屏幕文字

- `独立上下文`
- `独立人设`
- `独立工具`
- `只交结论`

## Voice / Visual 分工

旁白定义子代理和“从白纸开始”；画面展示它与主对话之间的边界，以及详细过程没有被搬回主线。

## Visual Type

`Concept Diagram`

# Scene 03｜它真正解决三个问题

## 视觉目标

将子代理的价值压缩成三个可记忆的节点。

## 画面结构

中心节点为 `子代理`。三条连线按顺序指向：

1. `隔离上下文`：日志细节留在房间，主线收到 `只回结论`。
2. `专精任务`：代码审查员卡片带有 `只读` 标签。
3. `可并行`：`认证`、`数据库`、`API` 三条独立分支同时亮起。

## 动画

1. 中心节点出现，第一条日志连线展开。
2. 第二条连线替换为代码审查人设和工具边界。
3. 第三条连线复制成三个并行分支。
4. 三个节点回收成一行短总结。

## 屏幕文字

- `隔离上下文`
- `专精任务`
- `可并行`
- `只回结论`

## Voice / Visual 分工

旁白解释三个用途的意义；画面用日志、审查和并行分支演示每个用途的工作形态。

## Visual Type

`Concept Diagram` + `Connection Diagram`

# Scene 04｜简单活儿别硬拆

## 视觉目标

展示“该用主对话还是子代理”的条件分流。

## 画面结构

中心入口为 `一个任务`，向左右分流：

- 左侧 `主对话`：`频繁来回`、`共享上下文`、`快速小改`、`在意速度`。
- 右侧 `子代理`：`脏活`、`可自包含`、`锁定权限`、`只回结论`。

分流底部出现一个被划掉的“改变量名”小任务，快速落到主对话；“翻日志”任务经过独立房间后只回摘要。

## 动画

1. 任务入口出现，四个判断标签逐一进入。
2. 标签根据形态移动到左右两侧。
3. “改变量名”不经过子代理，直接在主对话完成。
4. “翻日志”进入右侧房间，只留下摘要卡。

## 屏幕文字

- `频繁来回 / 共享上下文 / 快速小改 → 主对话`
- `脏活 / 可自包含 / 锁定权限 / 只回结论 → 子代理`
- `拆得多 ≠ 专业`

## Voice / Visual 分工

旁白说明启动、沟通、花费和回灌成本；画面通过两条任务路径证明不同任务应该走不同入口。

## Visual Type

`Decision Diagram` + `Comparison`

3. 工具面板展开，Write／Edit 变灰，Read-only tools 被强调。
4. Sonnet 和 Save 出现，顶部状态变为“已保存”。

## 屏幕文字

- `/agents`
- `Library → Create new agent → Personal`
- `Generate with Claude`
- `Read-only tools`
- `Sonnet`
- `Save`

## Voice / Visual 分工

旁白解释步骤和“主动砍工具”的理由；画面展示真正发生的选择和取消状态。

## Visual Type

`UI Simulation` + `Process`

## 全片视觉类型／组件／动画标准

### 视觉类型

- `Decision Diagram`：Scene 01、04、10 的判断和分流。
- `Concept Diagram`：Scene 02、03 的抽象关系。
- `Connection Diagram`：Scene 03、11 的节点连接与汇入。
- `UI Simulation`：Scene 05、06、07、09、11 的管理界面、代码文件和状态。
- `Terminal`／`Demo`／`Task Execution`：Scene 08、09 的实战链路。
- `Code Exploration`：Scene 06 的配置文件和目录范围。

### 组件形态

- 深色窗口：承载主对话、子代理房间、终端和管理界面。
- 节点与连线：表达上下文、任务路由和插件汇入。
- 文件标签与状态胶囊：表达 `calc.py`、配置文件和“原封不动”。
- 代码高亮：按字段顺序聚焦，不同时铺满说明。
- 幕内短标签：只显示当前视觉事件的核心词，不放内部制作说明。

### 动画标准

- 一级信息动画：任务分流、日志扫描、配置高亮、委派、文件前后对照、卡片汇入。
- 二级注意力动画：当前节点边框亮起、Write／Edit 变灰、差异扫描结果高亮。
- 三级装饰动画：只保留轻微呼吸光和窗口状态变化，不使用无意义粒子、旋转或跳动。
- 所有延迟均以非负时间实现；Prototype 只验证节奏，不代表最终 Remotion 动画。

## Gate 2 内部审查

### 口播与视觉互补

- 旁白解释“为什么”和“什么时候”，画面展示房间隔离、任务分流、配置加载、委派和权限结果。
- 没有把整段口播直接复制到画面卡片；屏幕文字均为短标签、命令、字段或状态。
- Scene 08 与 Scene 09 形成“执行 → 验证”关系，确保实战不是只展示一个配置文件。

### 画面文字语义归属

- `独立上下文`、`独立人设`、`独立工具`、`只交结论`均来自 Source 的子代理定义。
- `隔离上下文`、`专精任务`、`可并行`和“不该拆”的判断来自 Source 的三个用途与成本对比。
- `/agents`、字段名、目录路径、`@agent-code-reviewer`、`calc.py` 和只读工具均来自 Source 的创建与实战步骤。
- `插件（Plugins）`、配件列表和“一键安装／一键分享”只使用 Source 末尾的下一篇预告，不展开下一篇内容。
- 未使用其他视频的固定文案、状态文字、参考业务语义或预览调试文字。

### 原型交付检查

- 16:9 横屏，按 1920 × 1080 构图设计。
- 11 个 Scene 与 Scene Script、Narration Script、Visual Script 一一对应。
- 包含幕内短标签、上一幕／下一幕、自动播放和进度提示，仅服务于静态预览。
- 不生成 TTS、`tts-script.json`、音频、字幕、Timeline 或 Remotion 配置。

**Gate 2 结论：通过，Visual Prototype 可交付检查；本任务在原型检查后停止。**
