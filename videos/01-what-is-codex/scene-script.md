# 认识 Codex 与四种入口 · 第三步：Scene Script

> 目标：把 Video Narrative 拆成 10 个可制作的视觉事件。每幕只承担一个主要认知任务；安装、联网和外部命令不在本阶段执行。

## Scene 01｜到底哪个才是 Codex

### 目的
用四个同时出现的入口制造困惑，再把它们收拢成同一个 Codex 核心。

### narrativeRole
开场钩子：把“我该装哪个”转成“先认清它们的共同本体”。

### narrationIntent
提出桌面 App、CLI、IDE 扩展和云端 Web 为什么都叫 Codex，并给出“一个代理、四种入口”的初步答案。

### visualIntent
四块不同形态的界面从四角进入，中央问号翻转为 Codex 核心，四条连线保持可见。

### visualType
`Opening + Interface Montage`

### keyOnScreenText
```text
桌面 App
CLI
IDE 扩展
云端 Web
一个 Codex · 四种入口
```

### videoValue
四块界面动态汇入一个核心节点，能在数秒内消除“四个产品”的误解。

### 信息分工
- **声音**：提出新手真正的入口困惑。
- **画面**：先展示四种形态，再证明它们共享一个核心。

## Scene 02｜回答代码，和执行任务

### 目的
建立普通代码问答与 AI 编程代理之间的动作差异。

### narrativeRole
对比建立：从产品名称进入 Agent 的工作方式。

### narrationIntent
解释只给建议仍需人复制、粘贴和排错，而 Codex 能进入项目执行一串动作。

### visualIntent
左右两条工作流同步开始：左边停在代码回答，右边继续进入文件树、终端、测试和 diff。

### visualType
`Comparison + Workflow`

### keyOnScreenText
```text
回答：给你建议
代理：进入项目执行
```

### videoValue
两条路径的长度和状态差异，能直观看见“更会聊天”与“能动手”的区别。

### 信息分工
- **声音**：解释任务责任从人手工搬运转向代理执行。
- **画面**：展示两条路径分别在哪里结束。

## Scene 03｜一个目标如何变成结果

### 目的
把“代理”拆成可观察的五步动作链。

### narrativeRole
概念落地：证明 Codex 围绕目标工作，而不只生成孤立代码。

### narrationIntent
说明它可以读取项目、定位问题、修改文件、运行测试，最后交付 diff 给人验收。

### visualIntent
一个任务卡进入队列，文件树扫描、错误定位、文件状态、测试结果和 diff 依次点亮。

### visualType
`Step List + Project State Change`

### keyOnScreenText
```text
读取项目
定位问题
修改文件
运行测试
交付 diff
```

### videoValue
连续状态变化能解释 Agent 的过程性，也为后面的人工验收埋下边界。

### 信息分工
- **声音**：解释每个动作为什么围绕同一个目标。
- **画面**：显示项目状态如何一步步改变。

## Scene 04｜三扇门在本机，一扇门去云端

### 目的
解释四种入口最关键的执行位置差异。

### narrativeRole
地图建立：从“同一个代理”进入“入口如何连接环境”。

### narrationIntent
说明桌面 App、CLI 和 IDE 扩展读取本机文件、运行本机命令；云端 Web 在远程隔离环境中处理任务。

### visualIntent
前三个入口的连线汇入本机项目，云端 Web 的连线跨过边界进入云端沙箱与远程仓库。

### visualType
`Routing Diagram`

### keyOnScreenText
```text
本机：App · CLI · IDE
云端：Web · 隔离环境
```

### videoValue
本机与云端的空间分区能比四行说明更快建立执行环境的差异。

### 信息分工
- **声音**：说明各入口在哪里执行。
- **画面**：让四条路由与两个环境边界可见。

## Scene 05｜按工作场景选入口

### 目的
给出可复用的入口选择方法，避免寻找唯一“本体”。

### narrativeRole
决策应用：把入口地图转成实际选择。

### narrationIntent
说明看可视化 diff、多任务可选桌面 App；终端和 SSH 可选 CLI；编辑器内工作可选 IDE；后台长任务可选云端 Web。

### visualIntent
四张任务卡依次落入对应入口；最后四个入口并列保持，没有冠军标记。

### visualType
`Task Routing + Comparison`

### keyOnScreenText
```text
可视化 diff / 多任务 → App
终端 / SSH → CLI
编辑器内开发 → IDE
后台长任务 → Web
```

### videoValue
任务卡自动匹配入口，能把“按场景选”从建议变成一套可见规则。

### 信息分工
- **声音**：给出选择标准。
- **画面**：完成任务与入口的映射。

## Scene 06｜可以委托的五类工作

### 目的
把 Codex 的主要能力压缩成一条任务队列。

### narrativeRole
能力展开：在入口选择之后回答“进去以后能做什么”。

### narrationIntent
概括写代码、理解项目、代码审查、调试修复和自动化重复工作。

### visualIntent
五张任务卡逐一进入执行队列，右侧分别出现 Created、Indexed、Reviewed、Fixed、Migrated 状态。

### visualType
`Task Queue + Status Board`

### keyOnScreenText
```text
写代码
理解项目
代码审查
调试修复
自动化杂活
```

### videoValue
同一队列推动多个项目状态变化，能避免把能力清单做成静态 PPT。

### 信息分工
- **声音**：解释五类工作共同点是需要理解上下文并执行。
- **画面**：用状态变化证明任务已经进入项目层面。

## Scene 07｜执行可以交给 AI，判断不能

### 目的
明确 Codex 的能力边界和人的责任。

### narrativeRole
风险转折：在能力展示后阻止“全自动托管”的错误结论。

### narrationIntent
说明技术方向、需求取舍和最终正确性不能外包；人要查看 diff、运行验证并拍板。

### visualIntent
左右责任区同时出现；AI 把 diff 推向验收 Gate，Gate 在“未审查”时拦截，人工检查后才变为 Accepted。

### visualType
`Responsibility Split + Gate State`

### keyOnScreenText
```text
人：目标 · 边界 · 审查 · 验收
AI：分析 · 执行 · 重复劳动
完成执行 ≠ 自动正确
```

### videoValue
Gate 的拦截与放行动作把抽象责任变成可观察的协作机制。

### 信息分工
- **声音**：解释不能替代的判断工作。
- **画面**：演示未经审查的改动不会自动进入完成态。

## Scene 08｜问答工具与编程代理

### 目的
帮助观众区分 ChatGPT、Codex 与 Claude Code 的类别关系。

### narrativeRole
概念归位：把常被混用的名称放回工作流坐标。

### narrationIntent
说明 ChatGPT 式交互更偏问答与建议；Codex 和 Claude Code 都是能进入项目执行的编程代理，差异在产品体系和入口侧重，不做绝对强弱判断。

### visualIntent
横轴从“给建议”移动到“执行项目任务”；Codex 和 Claude Code 放在代理区，旁边展示 OpenAI／Anthropic、`AGENTS.md`／`CLAUDE.md` 和入口侧重标签。

### visualType
`Concept Map + Comparison`

### keyOnScreenText
```text
问答与建议
执行项目任务
同类代理 · 不同产品体系
按任务分工
```

### videoValue
先分类再比较，能降低品牌名称带来的混淆，又不落入易过时的强弱排行。

### 信息分工
- **声音**：解释交互类别与稳定差异。
- **画面**：展示工具在工作流坐标中的位置。

## Scene 09｜电脑认不认识 Codex

### 目的
让观众用一个安全、零成本动作确认本机 CLI 状态。

### narrativeRole
行动闭环：把认知地图落到一次明确检查。

### narrationIntent
引导运行 `codex --version`，解释显示版本号代表已安装，`command not found` 代表尚未安装，两者都完成了状态确认。

### visualIntent
终端输入命令后分成两张结果卡，两张卡都出现“状态已确认”的勾选标记。

### visualType
`Terminal Simulation + Result Branch`

### keyOnScreenText
```text
codex --version
版本号 → 已安装
command not found → 尚未安装
状态已确认
```

### videoValue
真实命令和结果分叉让观众获得可立即执行的最小反馈，而不是只听完定义。

### 信息分工
- **声音**：解释两个结果的含义。
- **画面**：展示命令、结果和共同的确认状态。

## Scene 10｜一张地图，三个判断

### 目的
收束本集知识，并把〈02 核心概念速览〉作为最后一个视觉事件。

### narrativeRole
总结与系列承接：从“认识入口”进入“理解代理运行规则”。

### narrationIntent
总结一个代理、四种入口、AI 执行但人验收；预告下一集将解释代理循环、上下文、项目说明、审批、沙箱、Skills 和 MCP。

### visualIntent
三张总结卡依次锁定；随后下一集预告卡从右侧进入并独立停留，字幕区与预告卡不重叠。

### visualType
`Summary + Next Episode Teaser`

### keyOnScreenText
```text
一个 Codex · 四种入口
按场景选择
AI 执行 · 人来验收
下一集：02 核心概念速览
代理循环 · 上下文 · AGENTS.md · 审批 · 沙箱 · Skills · MCP
```

### videoValue
总结卡完成记忆压缩，独立预告卡为系列下一步留下清晰且可读的视觉停留。

### 信息分工
- **声音**：完成三点总结并自然引出下一集。
- **画面**：固定当前地图，再把下一集术语作为新的最后事件。

# Gate 1 内部审查要点

- 10 个 Scene 与 Video Narrative 的 10 个视觉事件一一对应，顺序未改变。
- 每幕只有一个主要认知任务，且均包含完整的 Scene 契约字段。
- 核心命题、四入口、能力、限制、工具关系和命令结果均可追溯到 Source 与 Content Analysis。
- 没有引入价格、额度、跑分或版本号等易变化信息。
- Scene 10 明确承载下一集预告，并为独立停留和字幕避让预留结构。
