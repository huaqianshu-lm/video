# 认识 Codex 与四种入口 · 第一步：Content Analysis

> 本分析只提取视频需要表达的知识与边界；安装命令、版本检查和外部链接只作为内容素材，不在本阶段执行。

## 1. 核心命题

这篇内容真正要解决的，不是教观众安装某个客户端，而是先消除一个入口层面的误解：

> **Codex 不是四个彼此竞争的软件，而是同一个 AI 编程代理通过桌面 App、CLI、IDE 扩展和云端 Web 四种入口参与开发工作。**

建立这张地图后，观众还需要形成第二层判断：

> **Codex 的价值不只是回答代码问题，而是能进入项目、读取上下文、修改文件、运行命令与测试，再把结果交给人验收；但方向、需求和最终判断仍由人负责。**

如果视频结束后观众只记住一句话，应该是：

> **先按工作场景选择入口，再把执行交给 Codex，把判断留在人手里。**

## 2. 必须保留的核心信息

### A. Codex 是什么

- Codex 是 OpenAI 面向编程工作的 AI 代理。
- 它接收的是任务目标，不只是一轮问答。
- 它能读取项目、修改文件、运行命令、运行测试，并把改动交给人验收。
- “代理”最关键的含义是能围绕目标执行一串动作，而不只是给出建议。

### B. 四种入口是一套能力的不同落点

| 入口 | 执行位置 | 主要特点 | 更适合的场景 |
| --- | --- | --- | --- |
| 桌面 App | 本机 | 图形界面、可视化 diff、多任务 | 不想依赖命令行、需要同时观察多个任务 |
| CLI | 本机 | 终端原生、便于脚本和远程环境 | 熟悉终端、自动化、SSH 场景 |
| IDE 扩展 | 本机 | 靠近编辑器和当前代码 | 长时间在 IDE 内开发 |
| 云端 Web | 云端隔离环境 | 后台与并行，不占用本机 | 长任务、并行任务、基于远程仓库工作 |

需要明确：前三种读取本机项目并在本机执行；云端 Web 在远程隔离环境中处理任务。入口不同，不等于核心能力彼此割裂。

### C. Codex 能做什么

- 依据现有项目结构写代码。
- 理解陌生代码库。
- 审查代码与发现潜在问题。
- 沿错误信息定位并修复问题。
- 完成重构、补测试、迁移和环境调整等重复工作。

### D. Codex 不能替代什么

- 不能替人决定业务目标和技术方向。
- 不能保证生成或修改的代码百分之百正确。
- 不能补齐没有被说明的业务需求。
- 不能在人完全无法审查结果时承担无监督托管。
- 人必须查看 diff、运行必要验证并对最终结果负责。

### E. 与 ChatGPT、Claude Code 的关系

- 原文用“参谋与执行者”区分 ChatGPT 式问答和 Codex 式代理执行，重点是交互方式，而不是比较模型跑分。
- Codex 与 Claude Code 都属于能读取项目、修改文件和运行命令的编程代理。
- 原文把二者差异归纳为产品来源、模型体系、项目说明文件和工作流入口侧重不同。
- 功能、价格和模型能力变化快，视频不写死额度、跑分或“谁更强”的结论。

### F. 零成本动作与系列衔接

- `codex --version` 用于确认本机是否已安装 CLI；出现版本号或 `command not found` 都能提供下一步信息。
- 安装不是本集任务，安装命令只作为后续内容预告，不在本视频展开。
- 下一集主题有明确依据：〈02 核心概念速览〉，将解释代理循环、上下文、`AGENTS.md`、审批模式、沙箱、Skills 和 MCP。

## 3. 关键关系

### 目标与动作

普通问答的核心是“问题 → 回答”；代理工作的核心是“目标 → 读取上下文 → 执行动作 → 验证 → 交付”。视频必须把这个动作链展示出来，不能只放一张定义卡。

### 入口与执行位置

四种入口的核心差异不是能力清单，而是用户在哪里发起任务、任务在哪里执行、适合怎样的工作节奏。画面应突出“三个本机入口汇入本机项目，一个云端入口进入隔离环境”。

### 自动执行与人工把关

Codex 越能自动执行，人的目标描述、边界设置、diff 审查和结果验收就越重要。视频不能把代理表达为无需监督的全自动替代者。

### 工具比较与任务分工

ChatGPT、Codex、Claude Code 的比较用于帮助观众建立类别与使用情境，不用于制造绝对强弱排名。变化快的价格、额度和模型数据不进入核心画面。

## 4. 可视觉化内容

- 聊天框只输出代码片段，对比代理在项目中连续读取、修改、测试和交付。
- 一个 Codex 核心向四扇入口门分流，再分别连接本机项目或云端沙箱。
- 桌面 App、CLI、IDE、Web 四种工作空间的状态切换。
- “写代码、理解、审查、调试、自动化”五项任务进入同一个执行队列。
- 任务委托后，文件树、终端测试和 diff 依次发生变化。
- “AI 执行”与“人定方向／审查／拍板”的责任分界线。
- `codex --version` 的两种结果分叉。
- 下一集术语卡片从模糊变清晰，形成系列预告。

## 5. 可弱化或删除的信息

- 旧 Codex 模型的历史只保留为开场困惑，不展开产品沿革。
- Python 爬虫个人案例可压缩成一个“依赖过期 → 自动定位 → 测试通过”的执行演示，不保留叙述细节。
- 厨师、参谋、特种兵等多个类比不同时铺开，只保留最能支撑视觉表达的“建议与执行”对比。
- 订阅档位、免费额度、Linux 桌面 App 状态和登录条件变化快，不作为稳定知识结论。
- 两段安装脚本不进入主体，避免本集从认知地图偏成安装教程。
