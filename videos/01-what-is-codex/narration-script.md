# 认识 Codex 与四种入口 · 第四步：Narration Script

---

## Scene 01｜到底哪个才是 Codex

第一次打开 Codex，你可能会看到桌面 App、命令行、编辑器扩展，还有云端网页。

它们看起来像四个不同产品，到底哪个才是 Codex 本体？

答案是：它们都是。

Codex 不是一个固定窗口，而是 OpenAI 面向编程工作的 AI 代理。桌面 App、CLI、IDE 扩展和云端 Web，只是进入同一套能力的四扇门。

先把这张地图记住：一个 Codex，四种入口。

## Scene 02｜回答代码，和执行任务

那 AI 编程代理和普通的代码问答，有什么不同？

如果你把报错放进聊天框，得到的通常是一段解释和几行代码。接下来，复制、粘贴、寻找文件、重新运行，还是要你自己完成。

Codex 接收的则是一个任务目标。

它可以进入项目，读取文件，运行命令，再把改动和结果交回来。

真正的区别，不只是回答得更聪明，而是从给建议变成了参与执行。

## Scene 03｜一个目标如何变成结果

比如一个旧项目突然跑不起来，你可以让 Codex 查清原因，并修到测试通过。

它会先读取项目结构和依赖，再结合报错定位问题。

找到原因后，它修改对应文件，重新运行命令和测试，最后把 diff 交给你检查。

读取项目、定位问题、修改文件、运行测试、交付结果，这一串动作都围绕同一个目标展开。

这就是代理的分量：不只告诉你可以怎么做，而是进入工作现场，把步骤真正走一遍。

## Scene 04｜三扇门在本机，一扇门去云端

四种入口背后，最重要的区别是任务在哪里执行。

桌面 App、CLI 和 IDE 扩展都在你的电脑上工作。它们读取本机文件，也运行本机命令。

云端 Web 走的是另一条路。你从浏览器发起任务，任务进入远程隔离环境，从远程仓库取得代码，完成后再交回 diff，甚至可以准备拉取请求。

所以这张地图可以再简化一点：三扇门通向本机项目，一扇门通向云端环境。

## Scene 05｜按工作场景选入口

既然能力相通，就不用纠结哪个入口才最正宗。

想用图形界面查看 diff，还要并排观察多个任务，可以从桌面 App 开始。

习惯终端，或者需要在 SSH 和脚本环境里工作，CLI 更顺手。

一天大部分时间都在编辑器里，就用 IDE 扩展，把任务放在代码旁边。

需要运行不占本机的后台长任务，或者同时推进多个任务，再考虑云端 Web。

选择标准不是谁更强，而是你在哪里工作，这个任务适合在哪里执行。

## Scene 06｜可以委托的五类工作

进入任意一扇门以后，Codex 能接手的工作大致有五类。

它可以按项目现有结构写代码，也可以快速理解一套陌生代码库。

它能审查改动，寻找潜在错误和遗漏的边界条件。

遇到报错，它可以沿着日志定位根因，再修改并验证。

重构、补测试、迁移和环境调整这些重复工作，也可以作为完整任务交给它。

这些能力的共同点是：Codex 不只生成一段代码，而是结合项目上下文完成工作。

## Scene 07｜执行可以交给 AI，判断不能

但能执行，不等于可以把一切都交出去。

技术方向怎么选，需求应该怎么取舍，哪些行为绝对不能改变，这些判断仍然属于人。

Codex 给出的也是高质量候选，不是百分之百正确的答案。

所以每次改动都要看 diff，需要的测试也要真的运行，最终结果由你验收。

更清楚的人机分工是：人负责目标、边界、审查和拍板；AI 负责分析、执行和重复劳动。

它是能动手的搭档，但不是无需检查的自动驾驶。

## Scene 08｜问答工具与编程代理

再把几个经常放在一起的名字归个位。

ChatGPT 更常见的交互是你提问，它给出解释、建议和方案。

Codex 和 Claude Code 则都属于能进入项目、修改文件、运行命令的编程代理。

它们来自不同公司，使用不同模型体系，也有各自的项目说明文件和入口侧重。

但这些差异不需要变成一场永远不变的强弱排名。

更实用的做法，是先判断任务需要问答还是执行，再按自己的工作流选择工具。

## Scene 09｜电脑认不认识 Codex

现在可以做一个三十秒的小检查。

打开终端，输入 `codex --version`。

如果出现版本号，说明 Codex CLI 已经安装，可以继续使用。

如果出现 `command not found`，也不代表操作失败，它只是告诉你 CLI 还没有安装。

两种结果都完成了同一件事：确认这台电脑目前认不认识 Codex。

安装和登录留到后面的步骤，现在只需要记住这个状态。

## Scene 10｜一张地图，三个判断

最后把这张地图收起来。

Codex 是一个能进入项目执行任务的 AI 编程代理，它有桌面 App、CLI、IDE 扩展和云端 Web 四种入口。

选择入口时，看自己的工作位置和任务节奏，不用寻找唯一正确答案。

把分析和执行交给 AI，同时把目标、边界和验收留在人手里。

下一集，我们继续认识 Codex 的核心概念：代理循环、上下文、`AGENTS.md`、审批模式、沙箱、Skills 和 MCP。

把这些词捋顺之后，你就能看懂 Codex 为什么这样工作，也更知道应该怎样和它协作。
