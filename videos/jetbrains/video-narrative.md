# JetBrains 集成视频化 · 第二步：Video Narrative

> 目标：把 Source 中的 JetBrains 集成信息重新组织成一条“从怀疑到跑通”的视频叙事。

## 1. 视频叙事目标

观众看完后不只是记住一张功能表，而是能回答三个问题：

1. JetBrains 插件与 VS Code 扩展最根本的差异是什么？
2. 从哪里启动 Claude，才能让它与 IDE 正确连接？
3. 遇到 ESC、WSL2、远程开发问题时，应该先改哪里？

最终让观众形成一条可复述的工作闭环：

```text
CLI + 插件
→ 完全重启
→ 内置终端自动连 / 外部终端 /ide 手动连
→ 选区与诊断共享
→ diff = auto
→ 在 IDE 中审阅改动
```

## 2. 叙事起点和结论

### 起点

从 JetBrains 用户的真实担心开始：VS Code 有独立扩展面板，JetBrains 会不会只是少一个体验的“二等公民”？

### 中段问题

- 装插件后为什么没有新聊天面板？
- CLI 和插件如何连起来？
- 内置终端和外部终端什么时候用？
- 选区、诊断、diff、快捷键到底保留了多少？
- 三个 JetBrains 专属坑如何处理？

### 结论

JetBrains 不是少了核心能力，而是采用“终端对话 + IDE 原生反馈”的轻量桥接方式。掌握安装、连接、`auto` diff 和三项排障后，核心闭环仍然完整。

## 4. 逐段叙事设计

### 第一段：先制造“是不是二等公民”的疑问

Scene 01 不从支持名单开始，而是把 JetBrains 与 VS Code 的入口放在同一画面：一个有独立面板，一个只有终端入口。观众先看到差异，再等待解释。

### 第二段：把插件解释成桥

Scene 02 用一座桥连接 IDE 与 CLI，展示选区、诊断和改动三种信息流。旁白说明对话仍在终端里，插件的职责是让终端里的 Claude“看见”IDE 上下文并把结果送回 IDE。

### 第三段：把安装变成最小前提链

Scene 03 只展示 CLI 检查、Marketplace 安装和完全重启三个动作。支持名单作为 IDE 家族标签短暂出现；名单外只标“未明确支持”，不把它们包装成保证。

### 第四段：用启动来源解释连接方式

Scene 04 把内置终端和外部终端并列。内置终端直接运行 `claude` 后自动激活；外部终端需要输入 `/ide` 并选择 IDE。两边最后都回到“项目根目录一致”。

### 第五段：连续展示接通后的核心价值

Scene 05 不做五项静态卡片，而是让一次选区提问带出上下文共享，再让 IDE 的 lint 诊断进入终端，最后用 `Cmd+Option+K` 与 `@src/auth.ts#L1-99` 表达精确引用，并落到 JetBrains 内置终端与 VS Code 独立面板的体感差异。

### 第六段：把 diff 配置做成状态变化

Scene 06 先让改动停留在终端文本形式，再运行 `/config`，把 diff tool 改成 `auto`，同一份修改移动到 IDE 原生 diff 查看器。这样画面证明配置的实际价值，而不是朗读菜单。

### 第七段：把三个坑做成排障路线

Scene 07 以三条互不混淆的路线展示：ESC 是终端快捷键焦点问题；WSL2 是 Windows IDE 与 WSL 中 Claude 的网络连通问题；远程开发是插件安装位置问题。每条只给 Source 支持的解决方向。

### 第八段：用一个最小项目验证闭环

Scene 08 回到 PyCharm 的 `demo.py`，依次显示 `greet`、选中提问、要求 f-string 与类型注解、diff 出现。前面讲过的连接、上下文、配置在同一个小任务里汇合。

### 第九段：总结“少的是面板，不是能力”并预告下一篇

Scene 09 用一条对照回收结论：JetBrains 是终端对话、IDE 反馈；VS Code 是图形面板，但核心 CLI 能力保持。最后只出现“10 桌面 app（Desktop）”预告卡，说明下一篇转向独立客户端，不展开下一篇文章内容。

## 5. 叙事节奏

- Scene 01—02：快，先解决“有没有独立面板”这个疑问。
- Scene 03—04：中速，给安装和连接的因果关系足够时间。
- Scene 05—06：每幕一个可见状态变化，不把核心能力压成列表。
- Scene 07：三条排障路线清晰分隔，避免同时出现大量命令。
- Scene 08：稍快但保留提问、修改、diff 三个因果节点。
- Scene 09：减速收束，结论停留约 2～3 秒，再进入下一篇预告。
