# Visual Script｜Output Styles

## 全局视觉原则

- 画幅为 16:9 横屏，按 1920 × 1080 构图；深色背景、克制发光、清晰层级，沿用已有视频生产基线。
- 声音负责解释“为什么、何时、怎么选”；画面负责展示错位、路径、文件结构、状态变化、分支和功能边界。
- 屏幕文字只保留当前 Scene 的关键字段、命令、样式名、状态和总结关键词；不把口播全文塞进画面。
- 终端命令、版本号和路径只作为模拟教程画面展示，不执行任何源文命令。
- 所有画面文字必须能追溯到 `source.md`、Content Analysis、Video Narrative、Scene Script 或本 Visual Script；不带入其他文章的业务语义。
- Scene 12 的下一篇预告必须最后出现，并留出字幕和预览控件安全区。

## 逐 Scene 视觉设计

### Scene 01｜默认工程师，不等于所有角色

- **画面结构**：左侧简历编辑卡，右侧 Claude Code 对话卡；右侧连续弹出 `拆函数`、`加测试` 两个工程标签。
- **视觉动作**：左侧任务“改简历”亮起，右侧标签先后出现，中央出现“角色错位”提示。
- **动画顺序**：需求卡进入 → 工程标签弹出 → `这不是项目知识问题` 锁定为结论。
- **口播互补**：口播解释为什么 CLAUDE.md 里的风格要求不稳定，画面只展示错位结果。
- **视觉类型**：双窗口错位对比。

### Scene 02｜改的是方式，不是知识

- **画面结构**：中央固定 `Claude` 节点，左侧为 `知道什么`，右侧为 `怎么回应`；下方显示 `系统提示`。
- **视觉动作**：左侧保持低亮，右侧由 `角色`、`语气`、`格式` 三个标签接入 `Output styles`。
- **动画顺序**：Claude 节点出现 → 两个分支展开 → 右侧标签和系统提示高亮。
- **口播互补**：口播给出定义和适用信号，画面把“修改对象”明确定位。
- **视觉类型**：概念分层图。

### Scene 03｜四档内置样式怎么选

- **画面结构**：四列卡片分别为 `Default`、`Proactive`、`Explanatory`、`Learning`；每张卡保留一句行为摘要和一个使用场景。
- **视觉动作**：四卡依次亮起，`Explanatory` 与 `Learning` 底部出现 `更长响应`。
- **动画顺序**：Default → Proactive → Explanatory → Learning → 两张长响应提示汇聚。
- **口播互补**：口播解释差异和使用时机，画面只呈现选择线索。
- **视觉类型**：四卡片对照。

### Scene 04｜切换入口已经变了

- **画面结构**：左侧旧入口 `/output-style`，中间版本节点 `v2.1.73`、`v2.1.91`，右侧两条当前路径 `/config` 与 `outputStyle`。
- **视觉动作**：旧入口变灰并划线，两个版本节点依次亮起，当前路径变绿。
- **动画顺序**：旧命令出现 → `v2.1.73 弃用` → `v2.1.91 移除` → 两条正路亮起。
- **口播互补**：口播给出版本变更和操作建议，画面形成迁移证据。
- **视觉类型**：命令迁移图。

### Scene 05｜切完为什么没变化

- **画面结构**：横向时间线：`选择样式` → `当前会话`（停顿）→ 分支 `/clear`／`新会话` → `新系统提示` → `新样式生效`。
- **视觉动作**：当前会话节点显示旧样式仍在，经过清理或新会话后变绿。
- **动画顺序**：选择保存 → 旧会话停住 → `/clear` 和 `新会话` 二选一亮起 → 新提示组装。
- **口播互补**：口播解释“保存”和“生效”的差别，画面演示时间关系。
- **视觉类型**：生效时间线。

### Scene 06｜自定义样式就是一个 Markdown 文件

- **画面结构**：中央编辑器展示 `diagrams-first.md`；顶部 frontmatter 卡片，底部正文卡片；右侧三个作用域抽屉。
- **视觉动作**：`name`、`description`、`keep-coding-instructions` 逐一高亮，文件名同步变成样式名。
- **动画顺序**：文件出现 → frontmatter 展开 → 正文展开 → 用户级、项目级、托管策略级分流。
- **口播互补**：口播解释字段职责和存放级别，画面展示一个文件如何成为可选样式。
- **视觉类型**：文件结构与作用域分层。

### Scene 07｜`keep-coding-instructions` 的二分题

- **画面结构**：中央问题卡 `这样式 Claude 还编程吗？`，左分支 `是`，右分支 `不是`；末端分别为 `true` 与 `省略字段`。
- **视觉动作**：左分支保留 `内置工程指令`，右分支移除；错误方向以红色提示“角色跑偏”。
- **动画顺序**：问题出现 → 两分支展开 → 工程指令保留／移除 → 错误示例短暂闪现。
- **口播互补**：口播解释判断标准，画面承担字段选择和后果证明。
- **视觉类型**：二分决策图。

### Scene 08｜样式如何进入系统提示

- **画面结构**：一个纵向 `系统提示` 容器，依次放入 `内置工程指令`、`样式说明`、`会话提醒`；旁侧为 `prompt caching` 和 `token` 小卡。
- **视觉动作**：`keep=true` 时工程指令保留，`keep=false` 时该层抽掉；样式说明固定在末尾。
- **动画顺序**：容器打开 → 依次装入 → 工程指令分支 → 会话提醒循环 → 成本提示出现。
- **口播互补**：口播解释底层机制和成本，画面展示“拼入、保留、提醒”。
- **视觉类型**：系统提示组装图。

### Scene 09｜五种工具，各管一个抽屉

- **画面结构**：五列矩阵：`output style`、`CLAUDE.md`、`--append-system-prompt`、`Subagent`、`Skill`；每列显示“作用对象”和“加载方式”。
- **视觉动作**：顶部五个标签依次亮起，中央箭头将“方式／内容／一次性／独立任务／按需工作流”归类。
- **动画顺序**：矩阵框架出现 → 五列依次填充 → output style 与 CLAUDE.md 两列加粗对照。
- **口播互补**：口播讲差异，画面提供并行检索表。
- **视觉类型**：功能边界矩阵。

### Scene 10｜实操：建文件并选择样式

- **画面结构**：左侧终端显示 `mkdir -p ~/.claude/output-styles`，中间编辑器显示 `diagrams-first.md`，右侧 `/config` 选择器显示 `Diagrams first`。
- **视觉动作**：命令行完成后不显示执行结果，只让文件卡出现；选择器随后显示描述“每次解释都先画图，再用文字说明”。
- **动画顺序**：路径出现 → 文件头部出现 → 正文约定出现 → `/config` 选项亮起。
- **口播互补**：口播按五步实操推进，画面只展示当前步骤的可见结果。
- **视觉类型**：文件编辑与菜单模拟。

### Scene 11｜实操：`/clear` 后验证差异

- **画面结构**：左侧命令卡 `/clear`，中央请求路径图 `前端 → 后端 → 数据库`，右侧上下两块回应顺序卡：`Mermaid`、`文字解释`；底部有 `Default` 对照。
- **视觉动作**：图形先出现，文字卡后出现；切到 Default 后只保留文字卡并显示对照标记。
- **动画顺序**：`/clear` → Mermaid 图 → 文字解释 → Default 对照 → `图在前，文字在后`。
- **口播互补**：口播描述验证问题和预期，画面直接证明顺序变化。
- **视觉类型**：验证前后对比。

### Scene 12｜换方式，不换知识；下一篇 Hooks

- **画面结构**：六个总结节点汇入中央 `output style` 卡：`怎么回应`、四档样式、`/config`、`/clear`、自定义 Markdown、`keep-coding-instructions`；预告卡位于上中部。
- **视觉动作**：六个节点依次汇入，中央结论变亮；所有总结完成后，最后淡入 `33「钩子（Hooks）」` 与“事件触发自动发生”。
- **动画顺序**：六点汇聚 → `方式归 output style` 与 `内容归 CLAUDE.md` 出现 → 预告卡最后出现。
- **口播互补**：口播完成总结和预告，画面保留可回忆的关键词，不重复整段口播。
- **视觉类型**：总结汇聚与系列预告。

## 全片视觉类型／组件／动画标准

### 视觉类型

- 双窗口错位对比：Scene 01。
- 概念分层图：Scene 02。
- 四卡片对照：Scene 03。
- 命令迁移图：Scene 04。
- 生效时间线：Scene 05。
- 文件结构与作用域分层：Scene 06。
- 二分决策图：Scene 07。
- 系统提示组装图：Scene 08。
- 功能边界矩阵：Scene 09。
- 文件编辑与菜单模拟：Scene 10。
- 验证前后对比：Scene 11。
- 总结汇聚与系列预告：Scene 12。

### 基础组件

- `MismatchPanel`：需求与默认工程师回应的错位。
- `StyleBoundary`：知识与响应方式的分层。
- `StyleCard`：四档内置样式选择卡。
- `MigrationTrack`：旧命令到当前入口的迁移。
- `ActivationTimeline`：保存、清理、新会话和生效节点。
- `StyleFile`：Markdown、frontmatter 和正文结构。
- `DecisionBranch`：`keep-coding-instructions` 二分判断。
- `PromptAssembly`：系统提示组装和会话提醒。
- `CapabilityMatrix`：五种工具职责矩阵。
- `TerminalPanel`、`EditorPanel`、`ConfigMenu`：实操模拟。
- `SummaryHub`、`PreviewTeaser`：总结与下一篇预告。

### 动画标准

- 一级信息动画：需求错位、分支选择、路径迁移、时间线推进、文件展开、系统提示装配、矩阵填充和总结汇聚。
- 二级注意力动画：当前卡片高亮、旧命令划线、工程指令保留／移除、图文顺序和预告延迟出现。
- 三级装饰动画：仅保留轻微背景光、面板淡入和柔和扫描线，不使用无意义粒子、旋转或快速弹跳。
- 所有动画都服务于“改什么、何时生效、放哪个抽屉、如何验证”；删除后不影响理解的装饰不保留。
