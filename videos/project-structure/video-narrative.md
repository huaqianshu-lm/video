# Project Structure 视频化 · 第二步：Video Narrative

> 目标：按照观众从“这是什么”到“怎么安全判断”的认知过程组织视频，不把文章的 7 个章节直接变成画面目录。

## 1. 视频叙事目标

让观众完成一次认知变化：

    .claude/ 不是“会自己处理”的黑箱
            ↓
    它是一张配置与扩展的落盘地图
            ↓
    项目级和用户级是两套不同的家
            ↓
    文件职责和 Git 边界决定谁能看到、谁应该提交
            ↓
    优先级和只读命令帮助定位实际行为

整条视频的主线是：

> **先看清 .claude/ 的两棵树，再按归属、共享边界和优先级做配置判断。**

## 3. 叙事推进

### 01：先制造一个具体风险

从“为什么权限没生效、队友为什么没有命令”的困惑切入，再带出把数据库密码写入共享配置并推送的真实风险，让观众知道这不是目录认知题，而是项目协作和安全题。

### 02—04：建立两层空间

先用项目档案柜与个人工位抽屉建立作用域直觉，再分别展开项目级 .claude/ 和用户级 ~/.claude/，让观众先知道“归谁管”，再记文件名。

### 05—07：从文件职责进入决策

将文件按“指导、强制配置、扩展能力”分组，随后进入共享与个人的 Git 分流，最后处理配置冲突中的优先级、标量覆盖和数组合并。

### 08：把地图变成可执行检查

用 ls、git check-ignore 和查看 CLAUDE.md 的只读命令验证两层目录和忽略状态；同时提示没有 Git 仓库时的边界。

### 09：形成可复用判断法

回放“路径 → 归属 → 共享 → Git → 优先级”的判断链，最后预告下一篇“交互界面与快捷键”，不提前讲下一篇内容。

## 4. 信息分工原则

- 旁白负责解释两个作用域的差异、文件职责、泄密风险和优先级逻辑。
- 画面负责演示两棵目录树、文件分组、Git 分流、配置覆盖／合并和只读验证。
- 屏幕文字只保留路径、文件名、状态、命令和短结论，不把文章段落搬到画面。
- 画面中的示例密码保持为抽象占位，不展示真实秘密。

## 5. Gate 1 叙事检查

- 每个段落都服务于“理解并安全判断 .claude/ 结构”这一主命题。
- 文章内容已被重组为“风险 → 空间 → 文件 → 边界 → 冲突 → 验证 → 结论”，不是平铺文件清单。
- 所有命令、路径、优先级和示例状态均有原文依据。
- 最后一幕包含第 14 篇“交互界面与快捷键”预告，且只作为预告存在。
