# Claude Code 如何工作视频化 · 第二步：Video Narrative

## 1. 视频的叙事目标

让观众从“它怎么一句话就自己跑命令、读文件、改代码、做验证”的疑问出发，亲眼看到 Claude Code 不是聊天框，而是一个由模型和工具驱动、可被用户随时控制的代理循环。

## 2. 叙事原则

- 先展示结果和困惑，再揭开机制。
- 用一个闭环解释“为什么能自主工作”，不用堆定义。
- 让工具按真实修 bug 顺序出现，而不是平铺五类名词。
- 将用户的急停、补充、批准和权限边界放进事件流。
- 以空目录实验收束，让观众从概念回到可观察的操作。

## 3. 整体叙事结构

```text
困惑：它怎么自己干活？
↓
机制：想 → 做 → 看
↓
控制：你也在循环里
↓
能力：工具让它真正动手
↓
边界：它看得到什么、哪些动作受保护
↓
实验：计划 → 建文件 → 测试 → 再循环
↓
结论：模型 + 工具 + 用户控制
```

## 4. 逐段叙事设计

### 第一段：先展示“它会自己干活”

#### Scene 01｜一句问题，连续几步

用测试失败、读取函数、修改 return、再次测试的连续状态制造疑问。

#### Scene 02｜聊天框与 Claude Code 的差别

把“只返回文字”和“在项目里实际行动”并置，给出本视频要回答的问题。

### 第二段：建立核心机制

#### Scene 03｜想 → 做 → 看

把代理循环展示为闭环，并说明循环轮数由任务复杂度决定。

#### Scene 04｜一轮修复如何展开

将开头的测试案例映射到收集上下文、采取行动、验证结果，补上模型与工具的分工。

### 第三段：把控制权还给用户

#### Scene 05｜Esc：立刻叫停

展示错误方向上的大范围改动被 `Esc` 取消。

#### Scene 06｜补充指令：不打断当前动作

展示用户在工具执行期间补充约束，Claude 完成当前动作后读取新指令；形成“迭代比憋大招快”的结论。

### 第四段：工具让循环落地

#### Scene 07｜五类工具箱

把文件、搜索、执行、网络、代码智能放入同一个工具箱，强调工具是 Claude 的“手”。

#### Scene 08｜模型自己选择工具

用“修复失败测试”的 6 步路径表现每次工具返回如何决定下一步；扩展层只作为外围提示。

### 第五段：能力必须有视野和安全边界

#### Scene 09｜当前目录是工作范围

从工作目录向外展开项目文件、终端、git、`CLAUDE.md` 和扩展，明确不是无条件读取整个硬盘。

#### Scene 10｜两道安全闸

用检查点和权限模式分层：一个负责部分本地文件恢复，一个负责动作前的自主权；Plan Mode 是复杂任务的安全起点。

### 第六段：从概念到可观察实验

#### Scene 11｜空目录实验：先想再做

展示 Plan Mode 下要求创建 `add.py` 和测试，先出计划，批准后才建文件并运行测试。

#### Scene 12｜验证失败，再来一轮

让加法改成减法导致测试失败，回到循环并收束到下一篇 `04 · API 配置`。

## 5. 认知节奏

- Scene 01—02：快，先建立“为什么它不是聊天框”的悬念。
- Scene 03—04：放慢，让闭环和工具顺序看清。
- Scene 05—06：用明确的停／补状态制造交互感。
- Scene 07—08：以工具过程为主，减少静态定义堆叠。
- Scene 09—10：降低速度，给视野和安全边界留阅读时间。
- Scene 11—12：按真实实验时间线推进，失败后再循环并停留在结论。

## 6. Video Value 审查

- 循环必须通过节点顺序和回路动画表达，静态三列表不足以建立直觉。
- 工具选择必须通过 6 步状态变化表达，单纯口播五类工具没有视频价值。
- `Esc` 的即时取消与补充指令的延迟读取必须通过时间差表现。
- 项目视野要用空间范围表达，检查点和权限模式要用连续闸门表达。
- 最小实验的“先计划、再批准、再执行、失败再循环”天然适合视频时间线。

## 7. Gate 1 内部审查结论

- 叙事没有机械复刻原文的 6 个章节，而是按观众认知过程重组为 12 个视觉事件。
- 每一段都有明确的知识推进，且最终回到原文的主命题：Claude Code 凭模型、工具和验证循环完成工作。
- 下一篇预告只指向原文明确的 `04 · API 配置`，不提前讲其内容。

## 8. 下一步
