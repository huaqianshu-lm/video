# Claude Code 如何工作视频化 · 第四步：Narration Script

> 每个 Scene 下只保留实际需要朗读的内容。命令、画面说明和审查信息不属于口播正文。

## Scene 01｜一句问题，连续几步

第一次用 Claude Code，最容易被一个场景弄懵：你只问了一句“这个测试为什么挂了”，它却自己跑测试、读报错、找到函数、改掉代码，最后又跑了一遍测试。

它不是只回你一段建议，而是真的在项目里连续做了几件事。

## Scene 02｜聊天框与 Claude Code

这就是 Claude Code 和普通聊天框最大的区别。聊天框主要负责回你文字；Claude Code 会在项目里读文件、改代码、跑命令，再看结果。

那它凭什么知道下一步该干什么？答案是一套固定的工作机制。

## Scene 03｜代理循环：想、做、看

Claude Code 干活时，会反复走三个动作：先收集上下文，再采取行动，最后验证结果。

换个更好记的说法，就是想、做、看。结果不对，就从“看”回到“想”，再来一圈；任务有多复杂，循环就可能转多少轮。

这套机制叫代理循环，也就是 agentic loop。

## Scene 04｜一轮修复如何展开

拿刚才的失败测试来说，它先执行测试，读到报错；再搜索相关文件，读函数逻辑；找到少掉的 return 后改文件，最后重新跑测试。

模型负责判断和选择下一步，工具负责实际读取、修改、执行和返回结果。模型和工具一起，才让这个循环真正转起来。

## Scene 05｜Esc：立刻叫停

不过，自主工作不等于你只能在旁边干等。

如果它跑偏了，或者正准备大范围修改不该动的文件，按下 Esc，当前工具调用会立刻取消。你可以等它停下来，再给一条新的方向。

## Scene 06｜补充指令：不打断当前动作

如果你只是想补充上下文，不急着叫停，就直接打字并按 Enter。当前操作会继续，Claude 做完手头这一步后再读取你的补充。

所以你不需要憋出一条完美提示。先给大方向，看它怎么做，不对就纠正；这是对话，不是一次性命令。

## Scene 07｜五类工具箱

模型要真正动手，靠的是工具。Claude Code 的内置工具可以分成五类：文件操作、搜索、执行、网络和代码智能。

文件操作对应读写代码，搜索对应找文件和内容，执行对应终端、测试和 git，网络对应查网页和文档，代码智能则对应类型、定义和引用。

## Scene 08｜模型自己选择工具

你说“修复失败的测试”，并不需要先告诉它每一步该用什么工具。

它可能先跑测试，再读输出；接着搜索源文件，读懂逻辑，修改文件，最后再次测试。每次工具返回的信息，都会成为模型选择下一步的依据。

这六步，就是想、做、看循环在工具层面的展开。

## Scene 09｜当前目录是工作范围

那它能看到你电脑上的什么？可以先记一句：它的视野，大致等于你在当前目录下的终端能摸到的东西。

它能访问项目文件、终端命令、git 状态、CLAUDE.md 和你配置的扩展，所以能跨文件协调；但这不等于它无条件翻遍整个硬盘，其他位置需要相应权限。

## Scene 10｜两道安全闸

安全边界主要有两道闸。检查点像本地存档，能把 Claude 用编辑工具改过的文件恢复到之前的状态，但 bash 命令和数据库、API、部署这类外部副作用不在它的回滚范围里。

另一道是权限模式。复杂任务可以先进入 Plan Mode，只读、只搜、先出计划，批准之后再动手。一个管恢复，一个管动手前的自主权。

## Scene 11｜空目录实验：先想再做

想亲眼看一遍，可以在空目录里启动 Claude Code，进入 Plan Mode，然后让它创建一个 add.py 和几条测试，但先不要动手。

你会先看到一份计划：创建文件、创建测试、运行测试。此时文件还没有被改动，它停在等你批准的状态。

## Scene 12｜验证失败，再来一轮

批准之后，它才会建文件、写代码、运行测试。你甚至可以故意把加法改成减法，再让它重新测试；测试失败，就会把循环重新推回“想”。

所以，Claude Code 不是许愿池，而是一个会自己想、动手、检查的搭档。你的工作，是给方向、定验收标准，跑偏时拉它一把。
