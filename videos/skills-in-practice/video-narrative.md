# Skills 使用实例：装一个、喊一声、看它干活 · Video Narrative

## 1. 叙事目标

让观众从一个具体的“半天做图压缩到几分钟”的结果出发，亲眼看到 Skill 的调用闭环：查清可用能力，读懂它的入口，选择自动或手动触发，遇到问题会排查，最后把能力共享或自己搭出来。

## 2. 观众认知路径

1. 先看到结果差异：Skill 把重复流程压缩成一句目标和一套稳定产出。
2. 再建立使用前动作：先确认当前会话到底有哪些 Skill。
3. 接着拆开 Skill 的内部结构，理解 description 为什么是触发命门。
4. 用 `baoyu-diagram` 演示自然语言触发，再用 `/` 点名形成对照。
5. 当触发失败时，把问题拆成说法、在册和入口三个检查点。
6. 把“个人能用”推进到“团队能复用”，明确目录范围、Git 和信任边界。
7. 从空目录创建 `explain-casual`，把抽象方法变成一个可验证的最小实践。
8. 通过自动和手动两次调用收束：入口可以不同，背后是同一份 `SKILL.md`。

## 3. 叙事结构

### 第一段：结果先行

- Scene 01 用“半天 → 不到五分钟”的前后对照制造问题：究竟是什么把繁琐流程压缩了？

### 第二段：使用前先看清楚

- Scene 02 展示可用列表、`/skills` 和 `/doctor`，把“先查家底”变成第一个动作。
- Scene 03 拆开 `SKILL.md` 目录和 description，解释匹配到产出的因果链。

### 第三段：两种入口跑一遍

- Scene 04 用自然语言调用 `baoyu-diagram`，画面展示从需求到文件产出的过程。
- Scene 05 用 `/baoyu-diagram` 点名，和自然语言入口对照，明确什么时候该让 Claude 选、什么时候自己点名。

### 第四段：失败也有路径

- Scene 06 把“喊不动”拆成三步排查，并补充“触发太勤”时收窄 description 或关闭自动调用。

### 第五段：从个人使用到团队复用

- Scene 07 对比个人目录和项目目录，加入 Git 提交与信任检查，说明 Skill 的共享边界。

### 第六段：从零搭一个并完成验证

- Scene 08 依次展示创建 `explain-casual`、写 `SKILL.md`、重启会话和列表出现。
- Scene 09 用自然语言和 `/explain-casual` 两条路径验证同一套三步规则。

### 第七段：结论与系列承接

- Scene 10 将全片压缩为“查 → 看 → 触发 → 排查 → 共享／创建 → 验证”，最后承接 28「skill-creator：造你自己的 skill」。

## 4. 叙事取舍

- 不按原文 01—07 逐节朗读，而是把同一内容重排成“结果—机制—实践—验证”。
- `baoyu-diagram` 负责证明使用现成 Skill 的价值，`explain-casual` 负责证明用户可以从零复现。
