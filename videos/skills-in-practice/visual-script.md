# Skills 使用实例：装一个、喊一声、看它干活 · Visual Script

> 目标：用结果对照、文件结构、匹配路径、终端状态和双入口验证，把“会用 Skill”表达成一条可观察的实践流程。口播负责解释选择、因果和边界，画面负责展示加载、分流、产出与验证。

## 全局视觉原则

### 1. 先展示产出，再解释机制

开场用“半天 → 不到五分钟”的结果对照制造问题，后续每一幕都尽量展示一个实际状态变化，不把文章段落直接排成 PPT。

### 2. 用文件和路径建立可信度

`SKILL.md`、`description`、`references/`、`scripts/`、个人目录和项目目录都用文件树或等宽面板呈现。命令只作为示例文本，不执行、不模拟真实外部结果以外的项目状态。

### 3. 声音解释，画面证明

口播解释什么时候让 Claude 选择、什么时候手动点名、为什么要信任检查；画面展示列表、扫描线、路径分流、Git 状态和共同结果，避免逐句重复旁白。

### 4. 每幕只有一个视觉中心

每幕只突出一个过程：查列表、拆目录、命中、排查、共享、创建或验证。主标题控制在 1—2 行，辅助标签只保留当前动作需要的信息。

### 5. 横屏构图与安全区

使用 1920 × 1080 的 16:9 深色画布、圆角窗口、轻边框和克制发光。底部预留字幕安全区；结尾预告卡放在中下部但不压住安全区。上一幕／下一幕、自动播放和进度提示只属于 HTML 预览。

## 逐 Scene 视觉设计

### Scene 01｜半天的活，为什么不到五分钟就出图？

- **场景容器**：左右 Before／After 双面板。
- **视觉动作**：左侧依次堆叠“理节点、画草图、调配色、导出”，右侧从一句需求开始，经过 `baoyu-diagram`，亮起 SVG 和 @2x PNG。
- **信息重点**：Skill 把重复流程压缩为稳定产出。
- **口播互补**：口播讲时间和价值差异，画面只展示动作与结果。
- **屏幕文字**：`半天`、`不到五分钟`、`baoyu-diagram`、`SVG`、`@2x PNG`

### Scene 02｜用之前，先查手里有哪些 Skill

- **场景容器**：模拟 Claude 会话与右侧工具入口面板。
- **视觉动作**：输入“有哪些可用的 skill？”，列表逐行出现；`/skills` 和 `/doctor` 从侧边亮起。
- **信息重点**：先确认能力是否存在，再开始调用。
- **口播互补**：口播解释查询与诊断的用途，画面展示可见状态。
- **屏幕文字**：`有哪些可用的 skill？`、`/skills`、`/doctor`、`baoyu-diagram`

### Scene 03｜拆开一个真实 Skill：description 是触发命门

- **场景容器**：`baoyu-diagram/` 文件树连接右侧流程。
- **视觉动作**：展开 `SKILL.md`、`references/` 和 `scripts/`；从用户说法发出扫描线，命中蓝色 `description`，再展开紫色正文。
- **信息重点**：description 负责匹配，正文负责执行，配套资源按需读取。
- **口播互补**：口播讲因果链，画面把因果顺序变成连线和展开动作。
- **屏幕文字**：`SKILL.md`、`description`、`references/`、`scripts/`、`匹配 → 加载 → 产出`

### Scene 04｜不记名字，也能用：让 Claude 自己匹配

- **场景容器**：自然语言输入、Skill 列表和产出文件三列。
- **视觉动作**：输入句子后，关键词扫描多个 description，锁定 `baoyu-diagram`；随后依次出现参考说明、设计系统、SVG 和 @2x PNG。
- **信息重点**：自动匹配从用户说法开始，最终落到文件产出。
- **口播互补**：口播说明“只说要什么”，画面展示“怎么做”和“产出什么”。
- **屏幕文字**：`帮我画一张图，说明 Claude 的「想→做→看」代理循环`、`match`、`27-agent-loop.svg`、`27-agent-loop@2x.png`

### Scene 05｜不想等它猜？用 `/` 直接点名

- **场景容器**：左右双路径对比面板。
- **视觉动作**：左路标注“自然语言／Claude 选择”，右路显示 `/baoyu-diagram` 和图表参数；两路在同一 Skill 卡片汇合。
- **信息重点**：入口不同，执行的 Skill 流程可以相同。
- **口播互补**：口播给出选择条件，画面承担“自动匹配被跳过”的差异。
- **屏幕文字**：`让 Claude 选`、`/baoyu-diagram`、`直接点名`、`同一份 Skill 流程`

### Scene 06｜喊了没反应？三步排查

- **场景容器**：横向故障排查轨道与右侧权限开关。
- **视觉动作**：三个检查节点按顺序点亮：改说法、查列表、`/` 点名；末端另起一条“触发太勤”支路，切换 `disable-model-invocation: true`。
- **信息重点**：先解决匹配，再确认加载，最后用手动入口定位。
- **口播互补**：口播解释判断逻辑，画面展示分支顺序和终点。
- **屏幕文字**：`帮我画一张架构图`、`有哪些可用的 skill？`、`/baoyu-diagram`、`disable-model-invocation: true`

### Scene 07｜想让全队都能用：把 Skill 放进项目

- **场景容器**：个人目录与项目目录的双树对比。
- **视觉动作**：`~/.claude/skills/` 标注“个人／本机”，`.claude/skills/` 接入 `git add .claude/skills/` 和团队成员；最后弹出“先查看项目 skills”的信任提示。
- **信息重点**：路径决定共享范围，Git 决定团队复用，信任检查是安全边界。
- **口播互补**：口播解释谁能用和为什么检查，画面展示路径与协作流转。
- **屏幕文字**：`~/.claude/skills/`、`.claude/skills/`、`git add .claude/skills/`、`先查看项目 skills`

### Scene 08｜从零造一个：`explain-casual`

- **场景容器**：终端与 `SKILL.md` 内容卡并排。
- **视觉动作**：命令行依次出现目录创建、文件写入和重启会话；右侧卡片展开 description 与三步规则。
- **信息重点**：真实用户说法应进入 description，正文只保留可执行规则。
- **口播互补**：口播讲三步任务，画面展示文件和状态如何生成。
- **屏幕文字**：`mkdir -p ~/.claude/skills/explain-casual`、`SKILL.md`、`用大白话讲讲这段代码`、`整体作用 → 关键代码 → 潜在坑`

### Scene 09｜两条入口，同一份说明

- **场景容器**：左右自动／手动两路，底部共同结果面板。
- **视觉动作**：列表中亮起 `explain-casual`；左路自然语言经过 description match，右路 `/explain-casual` 经过 manual invoke，两路汇入同一份 `SKILL.md` 和三步结果。
- **信息重点**：列表确认、自动入口、手动入口和共同规则形成最小验证闭环。
- **口播互补**：口播得出验证结论，画面提供两条路径汇合的证据。
- **屏幕文字**：`explain-casual`、`description match`、`/explain-casual`、`同一份 SKILL.md`

### Scene 10｜把重复流程封装起来，下一步自己造 Skill

- **场景容器**：中央总结路径与右侧下一篇预告卡。
- **视觉动作**：`查`、`看`、`触发`、`排查`、`共享／创建`、`验证` 六个节点依次亮起，最后显示 28 预告卡并留出停留。
- **信息重点**：从使用别人写好的 Skill 走向自己封装流程。
- **口播互补**：口播收束方法，画面保留最短可记忆路径和下一篇标题。
- **屏幕文字**：`查 → 看 → 触发 → 排查 → 共享／创建 → 验证`、`28「skill-creator：造你自己的 skill」`

## 全片视觉类型、组件和动画标准

### 视觉类型

- `BeforeAfterProcess`：Scene 01，用于时间和产出差异。
- `CommandPanel`：Scene 02、04、05、06、08、09，用于会话输入、命令和状态。
- `FolderExploration`：Scene 03、07、08，用于 Skill 目录与范围。
- `TriggerFlow`：Scene 03、04、05、09，用于匹配、加载和双入口汇合。
- `TroubleshootingFlow`：Scene 06，用于排查顺序与权限支路。
- `SummaryPreview`：Scene 10，用于结论路径与预告卡。

### 基础组件

- 深色 16:9 画布、圆角软件窗口、轻边框、低强度发光。
- 文件树、等宽命令块、状态标签、匹配连线、流程节点、Git 状态卡和预告卡。
- 路径、命令、文件名和状态使用等宽字体；解释性文字使用清晰无衬线字体。
- 蓝色表示 description／自动匹配，紫色表示完整 Skill 正文，绿色表示已加载／已验证，黄色表示排查或警示。
- 主标题控制在 1—2 行；辅助文字不复述完整口播；底部保留字幕安全区。
- 上一幕／下一幕、自动播放、进度提示和原型说明只属于 HTML 预览，不进入后续 Composition 或 MP4。

### 动画标准

- 文件树展开、节点连线和状态变更使用 300—500ms 的淡入、位移或变色。
- 匹配动画严格保持“用户说法 → description → `SKILL.md` → 产出”的顺序。
- 排查节点按顺序出现；手动点名和权限开关使用清晰的分支，不使用无意义旋转。
- Scene 08—09 的创建、重启、列表发现和共同结果留出停顿，确保观众能读到状态。
- Scene 10 的预告卡与字幕安全区分离，并保留约 2—3 秒可读停留。
