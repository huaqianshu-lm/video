# Skills 使用实例：装一个、喊一声、看它干活 · Content Analysis

## 1. 核心命题

Skill 的价值不在于让 Claude “更聪明”，而在于把一套专项流程、资源和判断标准封装起来，让用户用自然语言或 `/` 入口调用，并稳定得到可复用的结果。真正上手时，关键闭环是：先确认可用 Skill，再读懂 `SKILL.md` 和 `description`，选择触发方式，遇到不触发时按顺序排查，最后把验证过的能力放进项目或自己创建。

## 2. 观众需要完成的认知变化

- 从“Skill 是一个神秘的自动功能”变成“它是一套写好的、可复用的工作流程”。
- 从凭印象乱喊，变成先问“有哪些可用的 skill？”并通过 `/skills`、`/doctor` 观察环境。
- 从只会看名字，变成能读懂 `SKILL.md`、`description`、参考文件和脚本之间的关系。
- 从只会一种调用方式，变成会在自然语言自动触发与 `/名字` 手动触发之间选择。
- 从把不触发归因于 Skill 损坏，变成按“说法是否匹配 → 是否在册 → 是否手动点名”定位问题。
- 从只在个人电脑使用，变成知道个人 Skill、项目级 Skill、Git 提交和工作区信任之间的边界。
- 从只会使用别人写好的 Skill，变成能照最小闭环创建 `explain-casual`，并验证它已经可用。

## 3. 必须保留的信息

### A. 价值入口

- 文章用 `baoyu-diagram` 的架构图案例说明：原本半天的整理、排版、导出流程，可以被一句话压缩为几分钟。
- Skill 固化的是流程、设计系统、模板、脚本和产出标准，而不是单纯增加一句提示。

### B. 使用前的可见性检查

- 在会话里询问“有哪些可用的 skill？”。
- `/skills` 用于查看和管理列表，`/doctor` 用于排查描述预算或截断问题。
- 不在可用列表里的 Skill，不能靠反复改说法解决。

### C. 读懂一个真实 Skill

- 一个 Skill 以目录为边界，`SKILL.md` 是必需入口，参考文件和脚本是可选配套资源。
- frontmatter 中的 `description` 负责描述何时使用；正文负责被调用后如何执行。
- 触发链条是“用户说法 → 匹配 description → 加载 `SKILL.md` → 按规则产出”。

### D. 两种调用方式

- 自然语言调用：用户不必知道 Skill 名字，让 Claude 根据 description 自己匹配。
- `/baoyu-diagram ...` 直接点名：跳过自动匹配，适合明确知道目标或希望立即执行时使用。
- 两者都要讲清适用场景，不把自动触发和手动触发混成同一件事。

### E. 不触发时的排查和项目共享

- 三步排查：换更贴近 description 的直白说法；确认 Skill 在可用列表；仍不行就 `/名字` 点名。
- 触发太勤时，可收窄 description 或设置 `disable-model-invocation: true`。
- 个人 Skill 放在 `~/.claude/skills/`，项目级 Skill 放在 `.claude/skills/` 并提交 Git。
- 信任外部项目之前先查看其中的 Skill，因为 Skill 可能申请工具权限。

### F. 从零创建和验证

- 创建 `~/.claude/skills/explain-casual`。
- 写入包含真实用户说法的 description，以及“整体作用 → 关键代码 → 潜在坑”的三步规则。
- 新建顶级 Skill 目录后重启会话，重新查看列表。
- 用自然语言解释代码，再用 `/explain-casual` 点名，验证两条入口都能调用同一份规则。

## 4. 因果、对比与流程关系

### 核心因果

1. 重复交代流程 → Skill 将流程写进 `SKILL.md`。
2. description 写得贴近用户说法 → 自动匹配更准确。
3. 匹配成功 → 加载正文和所需资源 → 按固定规则产出。
4. 项目级目录 + Git 提交 → 团队成员拉取代码后共享同一套流程。

### 关键对比

- 没有 Skill：用户需要重复解释配色、布局、步骤和导出方式；有 Skill：一句目标描述即可复用既定流程。
- 自然语言触发：由 Claude 判断匹配；`/名字`：由用户明确点名。
- 个人级：跨项目但只在本机；项目级：随仓库共享给团队。
- 触发不成功：匹配问题、加载问题和调用入口问题分别排查。

### 实操流程

1. 查可用列表。
2. 读 `SKILL.md` 结构和 description。
3. 用自然语言调用或用 `/` 点名。
4. 观察产出或状态。
5. 不成功时按三步排查。
6. 创建 `explain-casual`，重启会话，列表确认，再用两种入口验证。

- 三步排查路径和“触发太勤”的收窄开关。
- 个人目录、项目目录、Git 提交和工作区信任警示。
