# Skills 使用实例：装一个、喊一声、看它干活 · Narration Script

## Scene 01｜半天的活，为什么不到五分钟就出图？

平时做一张项目架构图，要自己理节点、画草图、调配色，再导出图片，一套下来可能要半天。现在只要对 Claude Code 说一句“帮我画一张这个项目的架构图”，它就能加载 `baoyu-diagram`，按固定的暗色设计系统生成 SVG，再转成 @2x PNG，前后不到五分钟。

这就是 Skill 的价值：不是让 Claude 凭空变聪明，而是把一套靠谱流程提前写好，需要时直接调用。

## Scene 02｜用之前，先查手里有哪些 Skill

但动手前先别急着喊。第一步，问一句“有哪些可用的 skill？”，确认当前会话里到底有谁在册。

你也可以打开 `/skills` 菜单查看和管理列表。如果 Skill 很多、描述像是被截断了，再用 `/doctor` 看看描述预算有没有溢出。先查清家底，能避免对着一个根本没加载的 Skill 反复尝试。

## Scene 03｜拆开一个真实 Skill：description 是触发命门

接着看一个真实的 `baoyu-diagram`。一个 Skill 通常就是一个目录，里面必须有 `SKILL.md`，还可以带参考文档和脚本。

`SKILL.md` 顶部的 `description` 负责说明什么时候该用，下面的 Markdown 正文负责说明调用之后怎么做。整个链条很简单：你说的话先去匹配 description，匹配上之后才加载正文和需要的资源，最后照着规则产出结果。

## Scene 04｜不记名字，也能用：让 Claude 自己匹配

现在不提 Skill 的名字，直接说：“帮我画一张图，说明 Claude 的想、做、看代理循环。”

Claude 会拿这句话去和各个 Skill 的 description 比对，命中 `baoyu-diagram`，再读取流程图的参考说明，套用暗色设计系统，最后告诉你 SVG 和 @2x PNG 放在哪里。你只说要什么，怎么稳定做出来，交给 Skill 的流程。

## Scene 05｜不想等它猜？用 `/` 直接点名

如果你已经确定就要用 `baoyu-diagram`，也可以直接输入 `/baoyu-diagram 画一张用户登录的时序图`。

这次跳过了自动匹配，斜杠后面的文字直接作为任务参数传给 Skill。探索时，让 Claude 自己挑；明确知道要哪个，或者操作有副作用时，用 `/` 点名会更直接。

## Scene 06｜喊了没反应？三步排查

如果喊了一句，Claude 没有触发 Skill，先别急着判断它坏了。第一步，怀疑自己的说法太含糊，把它改成更贴近 description 的直白表达，比如“帮我画一张架构图”。

第二步，再问“有哪些可用的 skill？”，确认它到底在不在列表里。第三步，如果它在册却还是没有自动触发，就用 `/baoyu-diagram` 直接点名。

反过来，如果某个 Skill 触发得太勤，可以把 description 写得更具体，或者设置 `disable-model-invocation: true`，只允许用户手动调用。

## Scene 07｜想让全队都能用：把 Skill 放进项目

放在 `~/.claude/skills/` 的个人 Skill，所有项目都能用，但只有你这台机器有。想让团队成员一起用，就把它放进项目的 `.claude/skills/`，再像普通代码一样提交 Git。

这样别人 clone 或拉取仓库后，就能拿到同一套流程。不过，信任外部项目之前，先看一眼它的 Skill 写了什么、申请了哪些工具权限。

## Scene 08｜从零造一个：`explain-casual`

最后自己造一个最小 Skill。先创建 `~/.claude/skills/explain-casual`，再写入 `SKILL.md`。

它的 description 要写进用户真实会说的话，比如“用大白话讲讲这段代码”。正文只规定三步：先说整体作用，再讲关键代码，最后指出可能的坑。

新建了顶级 Skill 目录后，重启一次 Claude 会话，再回到可用列表里确认它出现。

## Scene 09｜两条入口，同一份说明

现在先用自然语言说“用大白话讲讲这段代码”，让 Claude 自动匹配 `explain-casual`。

再输入 `/explain-casual`，处理一段代码或报错。两次入口不同，但背后读取的都是同一份 `SKILL.md`，所以结果都会遵循“整体作用、关键代码、潜在坑”这三步。

这就完成了验证：Skill 不只是被写出来了，它已经进入列表，也确实能被自动和手动两种方式调用。

## Scene 10｜把重复流程封装起来，下一步自己造 Skill

把这篇内容压缩成一条路径：先查有哪些 Skill，再看懂它的结构，然后选择自动触发或 `/` 点名；遇到问题按三步排查；需要共享就放进项目，想复用自己的流程就从零创建并验证。

Skill 的本质，是把反复说明的做法封装起来，让 Claude 在需要时调出一套专项能力。
