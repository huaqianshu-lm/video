# Claude Code 视频化 · 第二步：Video Narrative

## 视频叙事目标与定位

- 视频标题：Claude Code 斜杠命令：从 / 菜单到自己的工作流
- 视频 slug：slash-commands
- 叙事命题：当你把 / 当成 Claude Code 的控制面板，内置命令可以按场景查找，重复提示可以被刻成带参数、带边界、能注入现场数据的自定义流程。
- 观众起点：会在 Claude Code 中输入普通任务，但把 / 当成普通文字，或只把它当作一张没翻过的命令菜单。
- 观众终点：能理解斜杠命令的控制边界，并照着文章的 /explain 流程创建、传参和验证一个自定义命令。
- 时长策略：不预设固定时长；由 11 个视觉事件、正常口播、命令状态变化和实操停留自然决定。

## 整体叙事结构与叙事路径

本片不按原文 01–09 章节机械复述，而按观众的认知过程重新组织：

~~~text
误区：为清空上下文退出重启
    ↓
定义：/ 是 Claude Code 的控制面板
    ↓
边界：只有消息开头的 / 才会触发命令
    ↓
查找：按使用场景看内置命令
    ↓
创造：markdown 文件直接变成自定义命令
    ↓
增强：参数、frontmatter 和动态上下文
    ↓
消歧：Skill、插件命名空间和 MCP 来源各有规则
    ↓
实践：五步完成带参数的 /explain
    ↓
收束：把重复提示变成自己的工作流入口
~~~

## 声音与视觉分工

- 声音负责解释“斜杠命令控制谁”“什么时候能触发”“项目级和个人级如何选”“参数和 frontmatter 如何改变行为”。
- 视觉负责展示重启与 /clear 的状态差异、消息识别分流、文件映射、参数替换、配置护栏、现场数据注入和实操进度。
- 画面不逐字重复口播；例如口播解释 $ARGUMENTS 时，画面让同一个占位符被两个不同输入替换。
- 危险命令、动态 shell 执行和带副作用的自定义命令只作为边界提醒，不包装成默认推荐。

## 视觉统一原则

- 16:9 横屏、1920 × 1080 构图，深色 Claude Code 工具面板与蓝／紫／绿色状态层级。
- 每幕只有一个视觉中心：替代、分流、识别、查表、映射、替换、注入、命名空间或实操进度。
- 终端、命令卡、流程线和对比板交替出现，避免整片都是标题加列表。
- 命令、路径和参数使用等宽字体；解释性文字使用短句。
- 底部仅保留原型阶段的幕内提示，不生成真实字幕或 Timeline。
