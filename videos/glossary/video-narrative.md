# Claude Code 术语表视频化 · 第二步：Video Narrative

> 目标：把“静态术语速查卡”转成一条按认知关系观看的视频。

## 1. 视频的叙事目标

观众不需要在视频结束时背完所有术语，而要获得三种能力：

1. 知道这张术语表应该怎么用：遇到词时按主题族回查，而不是从头背诵。
2. 能把术语放回六张关系地图：代理循环、上下文、扩展点、MCP、安全权限、入口与运行。
3. 面对容易混的术语，知道应该比较哪个维度；需要权威定义时，知道如何用官方文档 server 查证。

## 2. 叙事原则

- 先改变观众对术语表的期待，再交付术语地图。
- 每一族用一个统一隐喻表达关系，不用逐条词典式切换。
- 先讲“系统如何工作”，再讲“如何加能力”“如何接外部”“如何控制风险”和“从哪里运行”。
- 对照场景只展示决定差异的关键维度，不把九组关系变成一张不可读的大表。
- 活字典是结尾的行动方法：静态卡片负责定位，官方文档 server 负责现查。
- 结尾承接文章明确给出的第 53 篇 Remotion 选读预告。

## 3. 整体叙事结构

| 段落 | Scene | 认知任务 | 叙事推进 |
| --- | --- | --- | --- |
| 开场 | 01 | 把术语表从课文重新定义为速查卡 | 先回答“为什么不要背” |
| 机制地基 | 02–03 | 建立代理循环与上下文工作台 | 解释 Claude 如何工作、记住什么 |
| 能力扩展 | 04–05 | 解释扩展点和 MCP | 说明能力如何增加、外部世界如何接入 |
| 安全与入口 | 06–07 | 解释动手边界与运行方式 | 让观众知道“能做什么”不等于“无边界” |
| 横向辨析 | 08–09 | 用区分维度解决术语撞车 | 把相邻概念切开 |
| 行动闭环 | 10–12 | 演示活字典、收束六族、预告下一篇 | 把“会看”变成“会查” |

## 4. 逐段叙事设计

### 第一段：术语表不是课文

#### Scene 01｜从“背诵”切换到“查找”

开场用“墙上的物料清单”类比术语表。画面先出现密集黑话，再把它们归入六张卡，形成一个明确转折：术语要在真正撞上时回来查。

#### 观众得到的结论

这不是一条逐字典朗读视频，而是一张帮助观众建立索引和查找路径的动态速查卡。

### 第二段：先搭地基，再铺装备

#### Scene 02｜代理循环

把 `agentic loop` 作为整套术语的运行地基，用闭环串起上下文、工具、行动和验证。agentic coding、harness、turn、verification loop、extended thinking 和 effort level 作为这个闭环周围的零件出现。

#### Scene 03｜上下文工作台

让观众看到“记性”不是无限的：对话、文件、工具输出、CLAUDE.md、skill 都会占用工作台；compaction 和 auto-compact 负责整理，session 与 turn 说明时间粒度。

### 第三段：给代理加装备、接到外部世界

#### Scene 04｜扩展点装备包

用不同装备位置解释 skill、subagent、hook、command、plugin 和 marketplace 的差异。重点不是功能数量，而是它们插入代理循环的方式不同。

#### Scene 05｜MCP 扩展坞

把 MCP 解释为统一标准，把 server、transport、scope 和 MCP Tool Search 拆成四个插口／设置，让观众知道“标准、具体服务、连接方式、共享范围和按需加载”各自负责什么。

### 第四段：能力必须有边界，入口可以变化

#### Scene 06｜安全与权限分层

从 permission mode 的会话级基线，到 permission rule 的细粒度规则，再到 sandboxing 的物理隔离；plan mode、auto mode、checkpoint 和 prompt injection 形成风险路径。画面不把安全术语做成单一“安全开关”，而是做成多层门禁。

#### Scene 07｜入口与运行模式

同一个 Claude Code 引擎放在不同入口和运行姿势中：surface、non-interactive、Agent SDK、网页、bare mode、worktree isolation、Remote Control 和 Teleport。重点是“在哪里、怎么跑”，不是制造产品比较。

### 第五段：把容易撞车的边界切开

#### Scene 08｜上下文与扩展的边界

用“内容进谁的上下文”“什么时候加载”“粒度”和“是否保留”四个维度，展示 Skill／Subagent、CLAUDE.md／Skill、Session／Turn、Compaction／`/clear`、CLAUDE.md／auto memory。

#### Scene 09｜控制、连接与协作的边界

用“管事件还是管权限”“粗基线还是细规则”“本地还是远程”“能否直接对话”四个维度，展示 Hook／权限规则、Permission mode／权限规则、stdio／http、Subagent／Agent team。观众学会的是切分方法，而不是死记表格。

### 第六段：把静态卡片变成活字典

#### Scene 10｜官方文档 server 查询流程

严格按原文中的四步展示：`claude mcp add --transport http ...`、`claude mcp list`、进入 `claude` 会话点名查询、可选 `claude mcp remove ...`。状态文字使用原文中的 `Added`、`✓ Connected`、`✗ Failed to connect` 和工具标记。画面只模拟流程，不执行命令。

#### Scene 11｜六族总地图

把六族压缩为一张可回查的索引卡：每族一句定位和镇族术语。通过高亮路径让观众看到术语之间的关系，而不是把所有条目重新铺满画面。

#### Scene 12｜查卡收束与下一篇预告

收束为“遇到术语 → 先按族定位 → 看区分维度 → 必要时用官方 server 现查”。最后明确出现第 53 篇「制作视频（Remotion）〔选读〕」预告，作为系列最后一个视觉事件，并保留停留时间。

## 5. 认知节奏

```text
不要背
  ↓
先看代理如何工作
  ↓
再看记性、装备、外部连接和安全边界
  ↓
用区分维度解决撞车
  ↓
用官方文档 server 现查
  ↓
把术语表当作长期速查卡
```

前半段以概念图和关系图为主，避免连续出现密集词条；中段以对照卡减轻信息负担；后半段用可执行的查词流程和六族索引收束。

## 6. Video Value 审查

- Scene 01：视频能把“密集黑话”动态归类，建立从背诵到查找的转折。
- Scene 02：闭环动画能同时呈现行动顺序和验证回路，文字无法直接表达循环节奏。
- Scene 03：工作台动画能把上下文容量、整理和粒度变成可见状态变化。
- Scene 04–05：装备包和扩展坞能把术语之间的层级与连接关系空间化。
- Scene 06–07：分层门禁和多入口路由能同时展示“边界”和“形态变化”。
- Scene 08–09：对照卡能让观众看到“区别看哪个维度”，而非只听定义。
- Scene 10：逐步命令状态能把活字典的使用路径演示出来。
- Scene 11–12：地图和收束动画能帮助观众形成可回忆、可行动的索引。

## 7. Gate 1 内部审查结论

- 叙事已从文章的六个章节和操作段落重组为“使用心智 → 运行地基 → 能力扩展 → 边界与入口 → 横向辨析 → 查证闭环”。
- 六族、九组易混关系、活字典四步和第 53 篇预告均有明确承载场景。
- 未把文章中的命令当作执行指令；命令只会作为 Scene 10 的视觉内容。
- 叙事没有引入其他文章的业务语义或参考视频固定文案，可以进入 Scene Script。
