# Claude Code 术语表视频化 · 第四步：Narration Script

> 每个 Scene 下只保留实际需要朗读的内容。命令、画面说明和审查信息不属于口播正文。

## Scene 01｜术语表不是课文

术语表最没用的读法，就是从头到尾把每个词背一遍。

因为这些词当时还没有在你手里发生过，背完转头就忘。

更好的用法，是把它当成一张速查卡。你以后遇到 transport、auto-compact，或者某个突然想不起的术语，回来找到那一条，一句话加一个类比，看完继续干活。

这篇文章把术语按主题归成六族，先帮你找到它属于哪张卡，再去理解它和相邻概念的关系。

## Scene 02｜代理循环：想、做、看

第一张卡，是代理循环。Claude 接到任务以后，会收集上下文，采取行动，再看工具返回的结果；如果还没完成，就继续下一圈。

这就是 agentic loop。tool 是它实际读文件、改代码、跑命令、搜索网页或派出 subagent 的手。agentic coding 说的是这种可以自主读、写、执行的工作方式，而 harness 是把模型、工具、权限、记忆和循环装在一起的那层外壳。

一次完整的来回叫一个 turn。verification loop 则负责检查“看起来完成”和“真的完成”是不是一回事。extended thinking 像草稿纸，effort level 决定这道题分配多少思考预算。

把这些词放回循环里看，它们就不再是一堆孤立的黑话，而是同一条流水线上的不同零件。

## Scene 03｜上下文：一张有限的工作台

第二张卡讲上下文。context window 就是一次会话的工作台，里面摆着对话历史、文件内容、命令输出、CLAUDE.md 和加载的 skill。

这张台面不是无限大的。token 是模型处理文字和计算占用的单位，东西越多，台面越容易被铺满。

快满的时候，compaction 会把旧的工具输出清掉，把对话整理成精简版；auto-compact 是系统自动按下这个按钮。session 是一整段独立会话，turn 是其中一次你发消息、Claude 完成响应的来回。

CLAUDE.md 是你写给它的常驻说明书，auto memory 是它自己写的笔记，rules 是按需要加载的模块化规矩，output style 则是改变它说话方式的设置。

## Scene 04｜扩展点：给 Claude 加装备

第三张卡是扩展点。它们都能让 Claude 更贴合你的工作，但插入的位置并不一样。

skill 像一条按需加载的快捷流程；subagent 有自己的上下文，干完专项任务只把结论递回来；hook 在生命周期的固定事件发生时自动执行动作。

command 或 slash command 是你按下的可复用入口。plugin 把 skill、hook、subagent 和 MCP server 打成一整箱装备，plugin marketplace 则是获取这些装备的来源。

所以看到“扩展”这个词时，先问它是在主桌面里加载、在旁边单独工作、在事件发生时触发，还是把一整套东西打包分发。

## Scene 05｜MCP：把 Claude 接到外部世界

第四张卡是 MCP。它是一套让 AI 工具连接外部数据和服务的开放标准，可以把 Slack、Jira、数据库或浏览器这类能力接到 Claude 面前。

MCP server 是一个具体接头，transport 说的是怎么连：stdio 是本机进程，http 是远程托管服务，sse 已经被弃用。

scope 决定这个接头在哪些地方共享：local 只在当前项目私有，project 写进配置跟团队共享，user 则可以用于你的所有项目。

如果外部工具很多，MCP Tool Search 会先只加载名字，真正要用时再拉取完整说明，避免闲着的工具白占上下文。

## Scene 06｜安全与权限：动手前的多层把关

第五张卡讲安全和权限。Claude 能动手，不代表所有动作都可以直接通过。

permission mode 是一整个会话的自主权基线；plan mode 只读、只搜、只研究，先把方案列出来；auto mode 则让独立分类器逐个审查操作，目前还是研究预览。

permission rule 更细，它按照工具和参数模式决定 allow、ask 还是 deny。sandboxing 是文件和网络的操作系统级隔离，像一堵物理的墙。

prompt injection 是藏在文件、网页或工具结果里的恶意话术。checkpoint 则像会话本地的存档点，走错时可以回到早先的提示点，但它和 git 不是一回事。

## Scene 07｜入口与运行：同一个引擎，不同的到岗方式

第六张卡回答的是：你从哪里用 Claude，又用什么姿势让它跑起来。

surface 可以是 CLI、VS Code、JetBrains、桌面端或 claude.ai。non-interactive mode 用 `-p` 或 `--print` 执行一次提示，做完就退出，适合 CI、脚本和流水线；Agent SDK 则把能力搬进 Python 或 TypeScript 程序。

网页版在云端沙箱执行。bare mode 跳过本地扩展的自动发现，worktree isolation 用单独的 worktree 和分支隔开并行任务。

Remote Control 是远程接管本机正在运行的会话，Teleport 则把云端会话拉回本地终端。入口不同，底下仍然是同一个引擎。

## Scene 08｜易混关系一：上下文与加载边界

术语最容易混的地方，不是定义不够长，而是两个词刚好在相邻维度上。

Skill 和 Subagent，要看内容进谁的上下文：skill 加载进主桌面，subagent 用自己的桌面，只回传结论。

CLAUDE.md 和 Skill，要看什么时候加载；Session 和 Turn，要看粒度；Compaction 和 `/clear`，要看旧内容是被总结保留，还是直接清台面；CLAUDE.md 和 auto memory，则要看是谁写下这份长期笔记。

记住比较的维度，比背两列定义更有用。

## Scene 09｜易混关系二：控制、连接与协作边界

剩下几组，也可以用同样的方法切开。

Hook 和权限规则，比较的是事件触发，还是工具准不准。Permission mode 和权限规则，比较的是整场的大基线，还是叠加在上面的细规则。

stdio 和 http，比较的是 server 在本机进程里，还是远程网址上。Subagent 和 Agent team，比较的是单个会话只向主对话汇报，还是多个完整会话之间可以直接交流。

遇到撞车的术语，先找区分它们的那一个维度，通常就能把边界切开。

## Scene 10｜官方文档 server：把静态卡变成活字典

术语会更新，静态速查卡不能替代官方文档。所以文章还给了一条把 Claude 当活字典用的路径。

第一步，在终端添加官方文档 server。第二步运行 `claude mcp list`，看到 `claude-code-docs` 和绿色的 `Connected`，才说明连接状态正常。

第三步进入 `claude` 会话，点名让它查询某个术语的官方定义。第一次调用可能会先问你是否批准；工具标记显示 `claude-code-docs`，说明这次回答走的是这个 server。

最后可以按需移除它。这里的关键不是背四条命令，而是建立一条查证闭环：添加、确认、点名查询，再清理。

## Scene 11｜六族总地图：回来查哪一张

现在把六张卡再串起来。

代理循环，讲 Claude 会自己动手的运转机制；上下文，讲它的记性边界和说话方式；扩展点，讲怎么给它加装备。

MCP，讲怎么接外部世界；安全权限，讲动手前的把关；入口运行，讲你从哪儿用、它怎么跑。

以后看到一个陌生词，先把它放回这六族中的一张，再看它和哪一个相邻词容易撞车。这样术语表就从一长串黑话，变成了一张可以导航的地图。

## Scene 12｜查卡收束与下一集预告

所以，这篇术语表不是让你背，而是让你在真正撞上一个词时查得到、分得清、必要时还能让官方文档现查一遍。

遇到术语，先按主题族定位；遇到相似词，再看它们的区分维度；拿不准，就用官方文档 server 查权威定义。
