# Claude Code 最佳实践视频化 · Video Narrative

> 目标：让观众从“为什么 Claude 总是越改越乱”走到“怎样建立可自验、可纠偏、可扩展的协作闭环”。

## 1. 视频的叙事目标

观众不是来背六条清单的，而是先看见一个熟悉的失败：一句模糊指令让 Claude 猜错、用户不断补充，双方共同把上下文白板写满。随后视频把这些零散经验统一解释成一个总约束：上下文窗口是最金贵的资源。

有了这个解释，六条法则不再是孤立技巧，而是同一套工作系统的不同动作：给验收、先探索、说具体、写精常驻规则、及时止损。最后再说明并行、审查和脚本属于扩展层，并用密码函数实验让观众亲眼看到“具体 + 验收”的收益。

## 2. 整体叙事结构

| 段落 | 认知推进 | 主要 Scene |
|---|---|---|
| 问题 | 模糊任务为什么容易失败 | 01 |
| 总约束 | 失败背后是上下文白板被填满 | 02 |
| 建立闭环 | 先让 Claude 能自己验收，再按 Plan Mode 工作 | 03–04 |
| 减少歧义 | 具体指令、足够上下文、精简常驻规则 | 05–06 |
| 及时止损 | 跑偏就停、回退或重开 | 07 |
| 稳定后扩展 | 并行、Writer／Reviewer、脚本和独立审查 | 08 |
| 形成习惯 | 问资深同事的问题、先采访、索要证据 | 09 |
| 亲眼验证 | 模糊 prompt 与具体 prompt 的对比实验 | 10 |
| 收束 | 六条法则速查与下一集预告 | 11 |

## 3. 第一段：先让观众看见“省略的代价”

开场不定义最佳实践，先展示“修一下登录 bug”这句指令。Claude 需要自己猜登录模块、bug 位置、验收标准，输出虽然像完成了任务，却未必符合目标。把它改写成带用户症状、目录、测试要求的具体任务，结果立刻变得可验收。

这段只负责制造问题和承诺：好用的关键在协作方式，不在多背几个命令。

## 4. 第二段：所有法则都在保护同一块白板

把对话、文件、命令输出画成不断写入的固定白板。白板填满后，早先的约束被挤掉，Claude 更容易忘记上下文和犯低级错误。随后把六条法则以六个“节省白板”的动作短暂亮出：验收、探索、具体、精简、纠偏、扩展。

这一步建立全片总坐标，后面每条法则都回扣到白板，而不变成孤立的技巧卡片。

## 5. 第三段：先闭合“执行—验证”循环

先展示没有测试时的断点：Claude 改完说“看起来完成”，用户只能自己检查。再展示有测试、构建或截图基准时的闭环：执行、检查、读取结果、继续修正，直到出现明确通过证据。

紧接着进入 Plan Mode：陌生项目先探索，输出计划，确认后实施，最后验证；一句话能说清的微小 diff 才跳过计划。声音解释判断标准，画面用流程状态表达先后关系。

## 6. 第四段：减少“猜”而不是增加“话”

把具体 prompt 拆成四个可见支点：文件／范围、症状／边界、现有模式、完成标准。随后用 `@` 文件、截图、URL 和管道把上下文喂足，提醒观众：探索时可以故意开放，实施时要具体。

再把镜头切到 `CLAUDE.md` 便签：短而关键的规则留在开局，能从代码看懂的背景和偶尔才用的细则移走。这里的重点不是“文档越少越好”，而是让真正会导致错误的规则被看见。

## 7. 第五段：错误方向要及时止损

用一条逐渐变长的错误路径表达“硬熬”：Claude 改错，用户纠正，新的修改又建立在脏上下文上。按 `Esc` 停止、`/rewind` 回退；三次纠正仍未解决就 `/clear`，把教训带到新白板。

subagent 调查和会话续接作为两个辅助出口出现：脏活放到独立白板，重要会话用描述性名字保存和继续。

## 8. 第六段：稳定一个，再横向扩展

先显示警告“一个还没用顺，开五个只会乱五倍”。然后把单会话成果向外展开：隔离 worktree 的并行会话、全新上下文的 Writer／Reviewer、非交互脚本、收尾审查。

扩展画面必须保留审查边界：审查者报出的每个问题都不等于真实缺陷，只追踪影响正确性的发现，避免过度工程。

## 9. 第七段：把沟通变成可复用习惯

用三个短场景做生活化收束：接手陌生项目时像问资深同事一样问；大功能先让 Claude 采访并产出 `SPEC.md`；听到“应该可以了”就要求亮出命令输出。三者分别对应探索、明确需求和证据闭环。

## 10. 第八段：用实验把抽象规则落地

展示同一个密码强度需求的两次会话。第一版只有“写个判断密码强不强的函数”，规则由模型猜，无法直接验收。第二版明确 `password.js`、长度、大写、数字、三个示例和测试要求，结果面板直接显示通过与失败样例。

这一段不再增加新规则，只把“具体 + 验收”变成观众可以复现的动作。

## 11. 结尾：从六条法则回到一个总原则

最后用速查表把场景和动作对应起来：没验收就补检查，方向不明就先探索，理解不一致就说具体，规则太多就精简，反复纠正就重开，一个会话稳定后再并行。

结尾强调这些是通常有效的起点，不是僵硬咒语；并保留本篇原文给出的下一集预告：下一篇讨论“反模式：常见的错误用法”。预告作为最后一个视觉事件，停留时间足够，且不展开下一篇内容。

## 12. 声音与视觉分工

- 声音：解释上下文为什么会成为约束，讲清每条法则的判断标准、使用边界和因果关系。
- 画面：展示白板填充、验证循环、流程状态、prompt 结构、回退路径、并行分工和实验输出。
- 屏幕文字：只保留法则名称、命令、示例输入／输出和结论短语，不把整段口播贴上去。

## 13. Gate 1 叙事审查

- 顺序由失败体验 → 总约束 → 单会话闭环 → 纠偏 → 扩展 → 实验 → 速查收束，符合观众认知过程。
- 六条法则均有明确的因果位置，不会被“横向扩展”提前抢走主线。
- 对比实验回收前面“具体 + 验收”的两条核心法则。
- 最后一幕包含本篇原文依据的下一集预告，并不调用下一篇文章内容。
