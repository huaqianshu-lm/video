# Claude Code 视频化 · 第四步：Narration Script

> 目标：基于 Scene Script 生成完整口播。  
> 口播要服务视频叙事，而不是把原文重新念一遍。

---

## Scene 01｜一个 Bug，把问题带出来

假设你正在写一个项目，突然遇到一个报错。

这种场景应该很多人都很熟。

以前如果我们想让 ChatGPT 帮忙，大概率会先把报错复制出来，打开聊天窗口，再把错误信息发给它。

这其实已经成了很多人现在写代码时的常规操作。

---

## Scene 02｜传统 AI 工作流为什么麻烦

ChatGPT 看完报错之后，可能会告诉你，问题大概出在哪。

但这里有一个很现实的问题：

它并不真正处在你的项目里面。

它看不到完整代码，也不知道这个报错和哪些文件有关。

所以你还得回到编辑器，找到对应代码，把相关内容复制出来，再发给它。

它给你修改建议以后，你再回去自己改。

改完以后重新运行。

如果又出现新的错误，就继续复制、粘贴、切窗口。

AI当然可以帮你分析。

但整个过程中，真正负责查代码、改代码、运行项目的人，还是你自己。

---

## Scene 03｜同一个 Bug，Claude Code 怎么处理

如果换成 Claude Code，同一个问题，工作方式会完全不一样。

你可能只需要告诉它一句：

“帮我找到这个报错的原因，然后修掉。”

接下来，它可以自己去查看相关文件，搜索代码之间的调用关系，定位问题，然后直接修改代码。

修改完成以后，它还可以继续运行测试，检查问题到底有没有解决。

这里真正发生变化的地方，不只是少复制了几次代码。

而是以前需要你自己完成的一整串中间步骤，现在 AI 可以自己继续往下做。

---

## Scene 04｜真正的区别不是“更聪明”

所以 Claude Code 真正重要的地方，并不是简单地说：

它比 ChatGPT 更会写代码。

更准确地说，是它和你的项目之间那层距离消失了。

普通聊天 AI 更多是在项目外面给你建议。

而 Claude Code 可以直接读取项目文件，理解代码之间的关系，修改文件，还可以执行命令。

也就是说，AI开始从“告诉你应该怎么做”，慢慢变成“直接参与把事情做完”。

---

## Scene 05｜Claude Code 到底是什么

如果现在再来给 Claude Code 下一个定义，就会容易理解很多。

Claude Code 是 Anthropic 推出的 AI 编程工具。

它可以进入你的代码项目，读取项目上下文，并直接执行真实的开发任务。

所以它不是一个单纯“会写代码的聊天框”。

更像是一个真正参与项目工作的 AI 编程搭档。

而且 Claude Code 也并不等于只能在终端里使用。

终端只是最完整、最典型的一种方式。

你也可以在编辑器、桌面端，甚至网页环境里使用它。

但不管界面怎么变，真正重要的仍然是后面这件事：

它可以直接参与项目。

---

## Scene 06｜从 Copilot 到 Agent

这里其实还涉及一个现在非常重要的概念：

Agent，也就是 AI 代理。

过去我们用 AI 写代码时，人的角色其实非常重。

你要先发现问题。

然后自己判断下一步该查哪里。

再把某个局部问题交给 AI。

AI回答以后，你再决定下一步怎么做。

也就是说，整个任务仍然是由人一步一步拆开的。

AI只是参与其中某一个环节。

Agent 的变化就在这里。

你开始不再告诉 AI：

“下一步具体应该做什么。”

而是直接告诉它：

“我最终想完成什么。”

至于中间需要看哪些文件、分析哪些代码、修改什么地方、执行什么命令，它可以自己继续完成。

所以从 Copilot 到 Agent，真正变化的不是 AI 会不会写代码。

而是：

**人开始从管理每一步操作，转向管理最终目标。**

---

## Scene 07｜第一层能力：看懂项目

理解这一点之后，再来看 Claude Code 能做什么，就不会只是看到一堆功能列表了。

它的第一层能力，其实是理解。

比如你刚刚接手一个完全陌生的项目。

目录很多，文件很多，也不知道核心模块在哪里。

以前你可能要自己先翻文档、找入口、读代码。

现在可以先让 Claude Code 阅读整个代码库，然后告诉你：

这个项目是怎么组织的？

核心模块在哪里？

数据是怎么流动的？

某一个功能中间经过了哪些文件？

甚至当项目出现 Bug 时，它也可以顺着代码关系去帮你追根因。

所以第一层不是“写”。

而是先真正看懂。

---

## Scene 08｜第二层能力：真正动手

第二层，是执行。

看懂以后，它不只是告诉你：

“这里应该改一下。”

而是真的可以直接去改。

比如修改一个函数。

把一个大模块拆开。

跨多个文件做重构。

给现有代码补测试。

修 Bug。

清理 lint。

升级依赖。

或者处理 Git 相关操作。

这些任务有一个共同特点：

它们往往不是回答一个问题就结束，而是需要连续完成几个步骤。

这正是 Agent 最擅长的地方。

它不是只给你一个建议。

而是可以沿着这个任务一直执行下去。

---

## Scene 09｜第三层能力：从代码库向外延伸

再往前一步，Claude Code 的工作范围甚至不一定只停留在代码库里面。

通过 MCP 这一类能力，它还可以连接外部工具和数据。

比如读取项目文档。

获取项目管理系统里的任务。

查询其他服务中的信息。

这意味着它开始不只是处理“代码”。

而是可以围绕一个真实项目，获取更多完成任务需要的上下文。

所以你也可以把 Claude Code 看成：

一个正在从代码工具，慢慢向项目级 AI 工作入口发展的东西。

---

## Scene 10｜是不是以后项目都可以交给 AI？

看到这里，可能会有一个很自然的想法。

既然它已经可以看代码、改文件、跑测试，甚至连接其他工具。

那以后是不是整个项目都可以直接交给 AI？

答案是：

还远远没到这个程度。

---

## Scene 11｜AI 能执行，但不能替你判断

因为开发里面有很多问题，本身就不是单纯的“对”和“错”。

比如现在有两个技术方案。

到底选方案 A，还是方案 B？

要不要为了未来扩展性，增加现在的开发成本？

这个功能应该优先追求速度，还是长期可维护性？

这些问题背后都涉及业务、时间、成本、团队能力和风险。

AI当然可以帮你分析。

但最后做取舍的人，仍然应该是你。

另外还有一个非常重要的问题：

Claude Code 改完代码，并不意味着它一定是对的。

测试通过，也不等于所有业务逻辑都正确。

它依然可能误解需求，也可能在某些边界条件上做错判断。

所以一个非常重要的习惯是：

不要把 AI 的结果当成最终答案。

把它看成一个高质量候选方案。

然后由人来 Review，再决定是否提交。

---

## Scene 12｜真正的人机分工

所以真正适合 Claude Code 的使用方式，不是：

“这个项目以后全部交给 AI，我不管了。”

而是重新划分人和 AI 的工作。

人更适合负责：

目标。

判断。

决策。

以及最终验收。

AI 更适合承担：

理解代码。

分析问题。

执行任务。

以及大量重复、机械、耗时间的工作。

这不是把人从开发流程里拿掉。

而是把人的注意力，从大量执行细节里释放出来。

所以真正的关键词不是替代。

而是协作。

---

## Scene 13｜ChatGPT、Cursor、Claude Code 怎么选

理解这一点以后，再看 ChatGPT、Copilot、Cursor 和 Claude Code，就会清楚很多。

ChatGPT 最典型的工作方式是：

你问，它答。

所以它很适合问知识、分析问题、讨论方案，或者处理一些相对独立的内容。

Copilot 最经典的方式是：

你写，它补。

它更像是在编码过程中实时帮你提高输入效率。

Cursor 现在已经进一步加入了越来越多 Agent 能力。

所以编辑器和 Agent 之间的边界正在快速变模糊。

而 Claude Code 最典型的工作方式是：

你把一个任务交给它。

它进入项目执行。

最后再由你验收。

所以这些工具其实不一定非要互相替代。

真正实用的方式反而是：

按照任务来派工。

需要讨论和分析，可以找 ChatGPT。

写代码时需要实时辅助，可以用 Cursor 或 Copilot。

而遇到需要理解整个项目、跨文件修改、修 Bug、重构、跑测试这一类项目级任务时，就可以交给 Claude Code。

---

## Scene 14｜最后真正发生了什么变化

如果把视角再拉远一点，你会发现：

真正变化的，其实不只是 Claude Code 这一个工具。

而是我们和 AI 一起写代码的方式。

最开始，我们问 AI：

“这段代码怎么写？”

后来开始变成：

“这个问题应该怎么解决？”

而现在，我们正在越来越多地告诉 AI：

“这个任务最终要达到什么结果，你去完成，完成以后把结果交给我。”

这背后，其实代表着一种新的开发分工。

人负责目标、判断和验收。

AI开始承担越来越多理解、分析和执行工作。

所以 Claude Code 真正值得关注的地方，不只是它让写代码变快了。

而是它让 AI 从聊天框里走出来，真正进入了开发流程。

而这，也可能是未来 AI 编程最重要的一次变化。
