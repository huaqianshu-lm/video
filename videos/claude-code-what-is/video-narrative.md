# Claude Code 视频化 · 第二步：Video Narrative

> 目标：不按原文章节机械改编，而是重新设计“这条视频从第一秒到最后一秒，应该按什么顺序让观众理解 Claude Code”。

---

## 1. 视频的叙事目标

这条视频不是为了“介绍 Claude Code 的功能”。

真正的目标是让观众完成一次认知变化：

```text
Claude Code 是一个写代码的 AI
                ↓
它其实可以直接进入项目工作
                ↓
它和普通聊天 AI 的工作方式完全不同
                ↓
这种变化本质上是 Copilot → Agent
                ↓
AI 开始从“回答问题”变成“执行任务”
                ↓
但人的判断仍然不能被替代
```

所以整条视频应该围绕：

> **AI 编程方式发生了什么变化**

来展开。

---

## 2. 整体叙事结构

建议整条视频分成 8 个叙事段落：

```text
01 一个真实问题
↓
02 两种完全不同的解决方式
↓
03 Claude Code 到底改变了什么
↓
04 Agent 是什么
↓
05 Claude Code 到底能做到什么程度
↓
06 为什么不能把项目完全交给它
↓
07 ChatGPT / Cursor / Claude Code 怎么分工
↓
08 AI 编程真正发生的变化
```

这是整条视频的主线。

---

## 3. 第一段：不要先介绍 Claude Code，先制造问题

### 叙事目的

先让观众产生共鸣。

不要一上来：

> Claude Code 是 Anthropic 推出的 AI 编程工具……

这种开场非常像教程文章。

更适合视频的开场是一个真实开发场景。

### 内容设计

假设：

> 项目突然报错了。

开发者打开 ChatGPT。

然后开始：

```text
复制报错
↓
粘贴给 ChatGPT
↓
ChatGPT 分析
↓
回编辑器
↓
找文件
↓
复制代码
↓
再发给 ChatGPT
↓
获得修改建议
↓
自己改代码
↓
运行
↓
又出现新问题
```

### 这一段真正表达的信息

这里先不需要解释 Claude Code。

只让观众感受到：

> **传统聊天 AI 最大的问题，不一定是不够聪明，而是它不在你的项目里面。**

这是后面所有内容的起点。

---

## 4. 第二段：同一个问题，Claude Code 怎么做

上一段让观众先看到问题。

现在立刻展示另外一种方式。

### 内容

面对同一个 Bug：

只告诉 Claude Code：

> 帮我找到这个错误的原因，然后修掉。

然后它开始：

```text
读取相关文件
↓
搜索调用关系
↓
定位问题
↓
修改代码
↓
运行测试
↓
检查结果
```

### 这里不要急着讲功能

重点不是：

> Claude Code 可以读取文件。

而是让观众看到：

> **以前需要开发者自己完成的一串中间步骤，现在 AI 可以自己完成。**

于是自然得到第一个核心结论：

> Claude Code 最大的变化，不是它更会回答问题，而是它开始能够直接执行任务。

---

## 5. 第三段：解释 Claude Code 到底是什么

到这里，观众已经先“看见”区别了。

现在才给定义。

### 核心表达

Claude Code 可以被解释成：

> 一个能够进入你的代码项目、理解项目上下文，并直接执行开发任务的 AI 编程搭档。

这里需要强调三个关键词：

```text
理解项目
+
直接修改
+
执行命令
```

### 这里顺便纠正一个误解

Claude Code 名字里有 Code，而且经常在终端里运行。

很容易让人觉得：

> 它就是一个命令行聊天工具。

这里简单说明：

它可以在：

- Terminal
- VS Code / Cursor
- JetBrains
- Desktop
- Web

等环境中使用。

但这一部分只做补充。

不要展开。

因为视频主线不是“它在哪里运行”。

---

## 6. 第四段：真正解释 Agent

这一段是整条视频最重要的知识升级。

前面已经通过 Bug 场景，让观众感受到差异。

现在告诉观众：

> 这种变化，其实就是从 Copilot 向 Agent 的变化。

### 过去的工作方式

以前我们和 AI 的关系通常是：

```text
人发现问题
↓
人拆解问题
↓
问 AI
↓
AI 回答
↓
人操作
↓
再遇到问题
↓
继续问 AI
```

也就是说：

> 人负责每一步，AI 负责局部回答。

### Agent 的工作方式

现在变成：

```text
人
↓
给出目标

Agent
├─ 找资料
├─ 看代码
├─ 分析
├─ 修改
├─ 执行
└─ 验证
```

也就是说：

> **人开始从“告诉 AI 下一步怎么做”，变成“告诉 AI 最终要完成什么”。**

这是 Claude Code 最值得理解的地方。

---

## 7. 第五段：Claude Code 到底能做到什么程度

现在观众已经理解 Agent。

这时候再讲 Claude Code 的能力，就不会变成功能堆砌。

建议按三个层级展开。

### 第一层：理解项目

例如：

> 你接手一个陌生项目。

Claude Code 可以：

- 阅读目录
- 找核心模块
- 理解代码关系
- 解释调用链
- 帮你找 Bug 根因

这里表达：

> **它先能够“看懂”。**

### 第二层：执行任务

再进一步：

- 修改代码
- 跨文件重构
- 写测试
- 修 Bug
- 清理 lint
- 升级依赖
- 操作 Git

这里表达：

> **看懂之后，它可以直接“动手”。**

### 第三层：连接外部世界

通过 MCP 等能力：

Claude Code 可以进一步连接：

- 文档
- 项目管理工具
- 外部数据
- 其他服务

于是它不再只是一个：

> Code Agent

而开始成为：

> **以项目为中心的 AI 工作入口。**

这一部分不用展开 MCP 的原理。

只需要让观众知道：

> 它的工作范围并不一定只局限在代码文件里。

---

## 8. 第六段：制造一次反转

前面讲完这些能力以后，观众很容易形成一个感觉：

> 那以后是不是项目全部交给 Claude Code 就行了？

这里需要主动提出这个问题。

这是视频中非常重要的一次转折。

### 回答

不是。

因为 AI 可以做大量执行工作，但有几件事情仍然属于人。

比如：

```text
方案 A 还是方案 B？
要不要重构？
这个需求到底应该怎么设计？
现在应该追求速度还是可维护性？
这个修改是否真的符合业务？
```

这些问题没有单纯的“正确答案”。

它们涉及：

- 业务
- 成本
- 团队
- 时间
- 风险
- 长期规划

### 第二个风险

Claude Code 修改了代码：

不代表一定正确。

即使：

```text
测试通过
```

也不意味着：

```text
业务逻辑一定正确
```

所以这里应该建立一个重要规则：

> **Claude Code 提供的是高质量候选结果，而不是绝对正确答案。**

因此：

```text
AI 修改
↓
人 Review
↓
再提交
```

仍然非常重要。

---

## 9. 第七段：重新解释几个 AI 编程工具

前面已经建立完整认知以后，再做工具对比。

这时候不用复杂表格。

只需要解释它们和人的工作关系。

### ChatGPT

```text
你问
↓
它答
```

适合：

- 问知识
- 分析问题
- 讨论方案
- 写零散代码

更像：

> 顾问

### Copilot

```text
你写
↓
它补
```

更偏：

> 编码过程中的实时辅助。

### Cursor

Cursor 现在已经包含越来越多 Agent 能力。

所以不能简单归类成：

> 智能输入法。

更准确应该说：

> Cursor 正在把编辑器和 Agent 能力融合在一起。

### Claude Code

最典型的方式是：

```text
你给任务
↓
它执行
↓
你验收
```

### 这一段最终不是为了比较谁更强

而是告诉观众：

> **不要把这些工具理解成只能二选一。**

真正合理的是：

```text
问问题
→ ChatGPT

实时写代码
→ Copilot / Cursor

项目级任务
→ Claude Code
```

也就是：

> **按任务派工。**

---

## 10. 第八段：最后不要总结功能，要总结“变化”

视频最后不能再回到：

> Claude Code 可以读项目、修改代码、运行命令……

这样收尾太弱。

最终应该提升一个层级。

### 最终结论

过去我们使用 AI 编程，最常问的是：

> 这段代码怎么写？

后来变成：

> 这个问题怎么解决？

而现在开始变成：

> **这个任务我要完成成这样，你去处理，完成之后告诉我结果。**

这是最值得关注的变化。

### 最终的人机分工

最后画面可以收束成：

```text
人
│
├─ 目标
├─ 判断
├─ 决策
└─ 验收

AI
│
├─ 理解
├─ 分析
├─ 执行
└─ 重复劳动
```

最后一句可以落在：

> **Claude Code 真正改变的，不只是写代码的速度，而是人和 AI 在开发流程里的分工方式。**

---

## 11. 整条视频的认知节奏

最终叙事节奏应该是：

```text
问题
↓
对比
↓
发现差异
↓
解释差异
↓
认识 Agent
↓
看到能力
↓
产生期待
↓
打破过度期待
↓
建立正确分工
↓
形成新的 AI 编程认知
```

这比：

```text
定义
↓
功能
↓
场景
↓
对比
↓
总结
```

更适合视频。

## 12. Video Narrative 最终版

可以压缩成下面这一条主线：

```text
开发者遇到 Bug
       ↓
ChatGPT 需要不断复制粘贴
       ↓
Claude Code 直接进入项目处理
       ↓
为什么会有这种区别？
       ↓
因为 Claude Code 是 Agent
       ↓
从“回答问题”变成“执行任务”
       ↓
它可以理解 → 执行 → 连接
       ↓

不能，AI 仍然需要人的判断和 Review

转向

```

## 13. 下一步

完成 Video Narrative 之后，下一步应该进入：

> **Scene Script**

也就是第一次真正把整条视频拆成一个个 Scene。

到了那一步，每个 Scene 都需要定义：

- Scene 的目的
- 这一幕解决什么认知问题
- 口播内容
- 画面表达
- 屏幕文字
- Scene Type
- 转场关系
- 哪些信息由声音承担
- 哪些信息由视觉承担

从 Scene Script 开始，才正式进入“视频制作设计”阶段。
