# Claude Code 视频化 · 第一步：Content Analysis

> 目标：先确定“这条视频必须讲清楚什么”，暂时不写口播、不设计具体镜头。

---

## 1. 核心命题

这篇文章表面上是在介绍 Claude Code，但它真正想建立的认知并不是：

> Claude Code 有哪些功能。

而是：

> **Claude Code 代表了一种新的 AI 编程方式：AI 不再只是给建议，而是可以进入真实项目，理解上下文并直接执行任务。**

这是整条视频最核心的主线。

如果观众最后只记住一句话，应该是：

> **Claude Code 的关键，不是“更会写代码”，而是“能进入项目直接干活”。**

---

## 2. 必须保留的核心信息

### A. Claude Code 到底是什么

必须讲清：

- Anthropic 官方 AI 编程工具
- 能读取项目
- 能修改文件
- 能运行命令
- 能执行真实开发任务

核心区别：

> 不是“会写代码的聊天框”，而是“能进入项目执行任务的 AI 搭档”。

---

### B. 为什么它和 ChatGPT 的体验完全不同

这是整篇最适合视频化的一部分。

传统 ChatGPT：

```text
发现报错
↓
复制报错
↓
打开 ChatGPT
↓
粘贴
↓
获得建议
↓
回 IDE
↓
找代码
↓
手动修改
↓
再测试
```

Claude Code：

```text
发现报错
↓
“帮我找到原因并修复”
↓
读取项目
↓
定位问题
↓
修改代码
↓
运行测试
```

这里传达的不是“哪个 AI 更聪明”，而是：

> **AI 和项目之间的距离变了。**

---

## 3. Agent 是这篇真正需要解释的概念

原文里“代理 / Agent”实际上是第二个核心。

需要让观众理解：

以前：

> 人负责拆步骤，AI 负责回答每一步。

现在：

> 人负责描述目标，AI 自己完成中间步骤。

可以抽象成：

```text
过去：

人
↓
步骤 1
↓
AI
↓
步骤 2
↓
AI
↓
步骤 3
```

变成：

```text
现在：

人
↓
任务目标
↓
Agent
├─ 找文件
├─ 分析代码
├─ 修改
├─ 执行命令
└─ 验证结果
```

这其实比“Claude Code 有什么功能”更重要。

---

## 4. Claude Code 的能力应该分成 3 层

原文列了很多功能，如果视频里平铺，很容易变成功能列表。

建议重新组织成三个层级。

### 第一层：理解

它可以：

- 阅读整个项目
- 理解架构
- 解释代码
- 找调用关系
- 找 Bug 根因

也就是：

> **先看懂。**

### 第二层：执行

它可以：

- 修改文件
- 跨文件重构
- 写测试
- 修 Bug
- 清 lint
- 升级依赖
- 处理 Git

也就是：

> **再动手。**

### 第三层：连接

通过 MCP 等能力：

- 读取外部文档
- 获取任务
- 连接项目管理工具
- 获取其他系统数据

也就是：

> **从代码库继续向外扩展。**

这样比简单说 8 个功能更容易理解。

---

## 5. “不能做什么”必须保留

这一部分不能删，因为它决定视频不是一条吹捧 Claude Code 的广告。

需要保留四个边界：

- 不能替你做最终技术决策
- 不能保证代码绝对正确
- 不能自动理解你没说清楚的业务
- 不能在你完全看不懂项目时无脑托管

最后收束成一句：

> **AI 可以承担执行责任，但不能替代人的判断责任。**

或者更适合整条视频的表达：

```text
人：方向 / 判断 / 验收

AI：理解 / 执行 / 重复劳动
```

这个结论应该成为后半段的重要转折。

---

## 6. ChatGPT / Copilot / Cursor / Claude Code 怎么讲

这里原文的信息需要保留，但不能完全照表格念。

真正需要观众理解的是工具的“工作关系”。

可以抽象为：

```text
ChatGPT
你问 → 它回答

Copilot
你写 → 它补

Claude Code
你交任务 → 它执行
```

Cursor 要稍微特殊处理。

因为现在 Cursor 也已经越来越 Agent 化，所以视频不能简单说：

> Cursor 就是智能输入法。

更准确的说法应该是：

> Copilot 和 Cursor 最初更偏编辑器内辅助，而现在 Cursor 也在快速 Agent 化，所以工具边界正在模糊。

最终重点不是谁替代谁，而是：

> **按任务选择工具。**

## 8. 这篇文章隐藏的“认知升级路径”

这是后面设计视频叙事最重要的一部分。

观众应该经历下面这几个认知变化：

```text
① Claude Code 是不是另一个聊天 AI？

↓

② 不，它可以直接进入项目。

↓

③ 进入项目意味着什么？

↓

④ 它不只是回答，而是执行任务。

↓

⑤ 这就是 Agent。

↓

⑥ 那是不是以后项目全交给 AI？

↓

⑦ 不，人仍然负责判断和验收。

↓

⑧ 所以真正变化的是人与 AI 的分工方式。
```

这才是这条视频真正的“剧情”。

## 9. 最终知识骨架

后续设计视频时，建议以这个结构作为唯一知识基线：

```text
核心命题
│
└─ Claude Code 让 AI 从“回答问题”进入“执行任务”

   ├─ 1. 它是什么
   │    └─ 能读项目 / 改文件 / 跑命令
   │
   ├─ 2. 为什么不一样
   │    └─ 顾问 vs 项目里的搭档
   │
   ├─ 3. Agent 是什么
   │    └─ 从“告诉 AI 每一步”到“给 AI 一个目标”
   │
   ├─ 4. 它能做什么
   │    ├─ 理解
   │    ├─ 执行
   │    └─ 连接
   │
   ├─ 5. 它不能做什么
   │    └─ 判断 / 决策 / 最终验收
   │
   ├─ 6. 和其他工具什么关系
   │    └─ 问答 / 补全 / Agent
   │
   └─ 7. 最终结论
        └─ 人负责判断，AI 负责执行
```
