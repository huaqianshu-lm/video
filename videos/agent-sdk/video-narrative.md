# Agent SDK 视频化 · 第三步：Video Narrative

## 1. 叙事主线

这条视频不按文章的 01—08 章节逐节讲，而按观众的疑问推进：

```text
我已经会用 Claude Code，为什么还要 SDK？
↓
SDK 到底把什么能力搬进程序？
↓
它和 CLI 是什么关系？和原始 API 又差在哪？
↓
我该怎么选语言、从哪里调用、权限怎么给？
↓
最小代理如何从输入走到真实文件结果？
↓
我是否真的需要它？本地原型之后怎么走向生产？
```

## 2. 观众认知变化

### 开始前

观众把 Claude Code 理解成一个在终端里使用的工具，知道 API 可以调用模型，但容易把 Client SDK 和 Agent SDK 混为一谈，也不清楚工具执行循环由谁负责。

### 结束后

观众能说清：Agent SDK 是 Claude Code 内核的程序化入口；CLI 和 SDK 共用能力但服务对象不同；原始 API 需要自己写工具循环，而 `query()` 让 SDK 代为编排；是否上手取决于是否要把重复流程或代理能力嵌进程序。

## 3. 叙事结构

### 第一段：从使用者转成构建者

用「终端里手敲」和「自动审 PR／定时任务」的落差开场，提出 SDK 的价值不是多一个命令，而是把 Claude Code 的背面搬进自己的程序。

### 第二段：先建立内核，再处理入口关系

先把工具、代理循环、上下文管理聚成一个可编程内核，再用同一内核的 CLI／SDK 双入口解释「人操作」与「程序触发」的差异。

### 第三段：钉死最大误区

将 Client SDK 的手写 `while` 与 Agent SDK 的 `query()` 并排展示，让观众看到两者的差异是工具循环和执行责任，而不只是包名不同。

### 第四段：从入口落到可运行闭环

用语言选择、安装前提、API key、`query()`、`allowed_tools` 和消息流建立最小心智模型，再用 `utils.py` 的两个 bug 让抽象能力变成可观察结果。

### 第五段：给出边界和下一步

用「只在终端工作」与「需要自动化／嵌产品」的判断收束，再说明本地 Agent SDK 原型与 Managed Agents 之间的生产化边界，最后预告下一篇开发配置。

## 4. 视觉节奏

- 结尾用选择路径和收束关系图，下一篇预告作为最后一个视觉事件并停留 2～3 秒。
