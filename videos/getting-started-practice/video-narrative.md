# 实战入门：Video Narrative

> 叙事目标：让观众经历一次“从一句需求到可交付结果”的完整任务闭环，并理解每个交接棒为什么不能省。

## 1. 视频的叙事目标

视频不从“Claude Code 有哪些功能”开始，而从一个真实痛点开始：一句话交给 AI，为什么经常得到跑偏、越界、未验证的结果？

随后把观众带进一个足够小、却包含全部环节的 `wordcount-demo` 任务。观众先看到全景，再跟着六步依次执行，最后用“改岔了怎么办”和“老手 vs 新手”把一次练习提升为通用方法。

## 2. 叙事主线

```text
一句话等结果会失控
        ↓
完整实战其实是六个交接棒
        ↓
先造一个有缺功能和 Bug 的小项目
        ↓
定规则 → 探索 → 规划
        ↓
批准后改动，并逐处审 diff
        ↓
新功能、旧功能、边界行为三连验
        ↓
概览 → commit → log，形成交付闭环
        ↓
偏了就干净退回，不在烂摊子上硬补
        ↓
老手不是更快跳步，而是把交接棒交完整
```

## 3. 认知节奏

### 第一段：制造问题

先呈现“说清需求 → 等结果”的错觉，再用方向跑偏、多改文件、Bug 仍崩溃的后果制造必要性。核心问题是流程缺少交接，而不是 AI 不够聪明。

### 第二段：给出全景

用六步接力棒建立记忆框架。观众先知道即将走哪条路，再进入具体操作，避免把后续命令看成孤立技巧。

### 第三段：把任务缩小到可跑的练习

用两个文件和纯 Python 标准库快速造出 `wordcount-demo`，先跑原始输出，再指出 `--top N` 和缺参崩溃两个目标。开工前的 git commit 作为干净原点出现。

### 第四段：先定规矩、先看懂、先出方案

连续展示 `CLAUDE.md`、探索提示和计划卡。这里故意延迟“改文件”，让观众感受到稳定协作的关键不是更复杂的提示词，而是正确的顺序。

### 第五段：执行不是放任

方案获批后进入 diff。画面展示预期修改范围、`argparse`、`--top` 与不引入第三方依赖；声音解释批准是事中拦截点。

### 第六段：用证据替代声明

三条命令形成验证节奏：新功能、旧功能、Bug 边界。视觉上分别显示排序结果、完整回归输出和 `usage` 错误提示。

### 第七段：交付与止损

先看改动概览，再 commit，再 `git log`；之后补充失败路径：轻档 `/rewind`，重档 git 原点。观众得到“交付包含止损能力”的完整闭环。

### 第八段：抽象为可复用习惯

最后用老手／新手对照重述六步，强调流程是骨架不是镣铐，熟练后可以压缩表达但不能删除认知环节。总结画面预告下一篇 Chrome。

## 4. 叙事中的声音与视觉分工

| 声音负责 | 画面负责 |
| --- | --- |
| 解释为什么“一句话等结果”会失控 | 显示错误、越界修改和未验证的结果 |
| 讲六步之间的交接关系 | 接力棒逐步点亮并移动 |
| 解释命令和动作的目的 | 展示终端、文件树、规则卡和状态变化 |
| 说明 plan mode 与 diff 审查的意义 | 显示方案等待批准、红删绿加和范围边界 |
| 解释验证是事实标准 | 分别亮出三条命令和不同结果 |
| 说明交付与回退边界 | 把概览、commit、log 和两档回退连成闭环 |

## 5. Scene 规划

| Scene | 认知任务 | 视觉事件 |
| --- | --- | --- |
| 01 | 让观众意识到“说一句就等结果”不可靠 | 任务卡分裂成跑偏、越界、未验证 |
| 02 | 记住六步骨架 | 六根交接棒依次点亮 |
| 03 | 建立练手任务与干净原点 | 目录生成、原始输出、git commit |
| 04 | 开工时先定最小规则 | `claude` 进入目录，`CLAUDE.md` 两条规则落位 |
| 05 | 先探索，不修改 | 文件树扫描，`sys.argv[1]` 被标出，代码保持稳定 |
| 06 | 先出方案，再批准 | 需求进入 plan 卡，显示等待确认 |
| 07 | 执行并审查 diff | `argparse`、`--top` 进入，范围边界被框出 |
| 08 | 用三条命令证明结果 | 新功能、回归、缺参提示依次通过 |
| 09 | 把成果存进 git | status 概览 → commit → `git log -1` |
| 10 | 学会干净止损 | `/rewind` 与 git 原点两条路径分流 |
| 11 | 把一次练习抽象成习惯 | 老手／新手对照收束，出现 Chrome 预告 |

## 6. 叙事取舍

- 不逐段复述文章的前篇引用，而把它们压缩成“已经学过的零件”。
- 保留所有对任务闭环有决定作用的命令、文件名和验证结果。
- 不把可选测试扩成独立 Scene，作为验证后的加固提示。
- 不把远程 push、subagent 或全部接受模式扩展为新主题，只保留边界提醒。
- 结尾预告只使用当前文章已经给出的下一篇标题，不读取下一篇正文。

## 7. Gate 1 结果

- 叙事顺序按观众认知从问题、全景、练习、顺序控制、证据、交付到抽象结论推进。
- 11 个 Scene 各承担一个主要认知任务，且都能用过程、状态或对比表达。
- 所有关键屏幕文字可回溯到 `source.md` 或本叙事直接压缩内容。
- 结尾包含当前系列要求的下一集预告，并将其作为最后一个视觉事件。
