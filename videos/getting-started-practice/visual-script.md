# 实战入门：Visual Script

## 全局视觉原则

### 1. 画面负责证明交接和状态

旁白解释为什么流程会失控、每一步为什么重要；画面展示任务卡如何失败、文件如何被读取、方案如何等待批准、diff 如何变化、命令如何通过。不要把口播全文直接铺在画面上。

### 2. 统一视觉语言

- 16:9 横屏，按 1920 × 1080 构图设计。
- 深色科技感界面，低饱和蓝紫为主色；绿色表示通过，黄色表示待确认，红色表示错误或越界。
- 统一使用 `window`、`terminal`、`file-tree`、`diff`、`chip`、`status` 和 `caption` 模拟组件。
- 每个 Scene 只有一个主要视觉动作；幕内字幕保持单行，不抢主体空间。

### 3. 动画优先级

- 一级信息动画：任务分裂、交接棒点亮、目录生成、文件扫描、方案停住、diff 替换、命令执行、状态回退。
- 二级注意力动画：高亮 `sys.argv[1]`、红绿 diff、验证结果、干净原点。
- 三级装饰动画：轻微背景光和窗口切换；不使用无意义粒子、旋转或快速闪烁。

### 4. 画面文字语义归属

命令、文件、函数、参数、输出、模式名、状态和结论都来自 `source.md` 或前置生产资料的直接压缩。`Chrome：让它操作浏览器` 只作为当前文章已经给出的下一篇预告，不使用下一篇正文。上一幕、下一幕、自动播放和进度提示只属于原型交互。

## Scene 01｜一句话交给 AI，为什么会失控

- **画面结构**：中央一张 `需求` 卡，左侧是 `说需求 → 等结果`，右侧分出三个结果卡。
- **视觉动作**：结果卡依次变红：`方向跑偏`、`多改文件`、`Bug 仍崩溃`；中间出现断开的交接线。
- **视觉重点**：问题是流程断点，不是单纯工具能力不足。
- **幕内字幕**：`一句话然后等结果？`
- **口播互补**：声音解释返工成本，画面只展示失控状态。

## Scene 02｜一趟实战，就这六步

- **画面结构**：横向六节点接力带。
- **视觉动作**：`开工`、`探索`、`规划`、`动手`、`验证`、`交付`依次点亮并交出一根棒；探索和验证短暂出现黄色提醒。
- **视觉重点**：顺序和交接不可跳过。
- **幕内字幕**：`六步，不能跳`
- **口播互补**：声音解释熟手如何压缩，画面保留完整骨架。

## Scene 03｜先造一个有原点的练手项目

- **画面结构**：左侧终端，右侧文件树和原点标记。
- **视觉动作**：输入 `mkdir wordcount-demo && cd wordcount-demo`；`wordcount.py`、`sample.txt` 出现；终端显示 `the: 3`、`fox: 2`；`--top N` 和 `IndexError` 变成两个待办；最后 `git commit` 连接到 `clean origin`。
- **视觉重点**：小项目同时具备新功能、Bug 和回退基础。
- **幕内字幕**：`先有干净原点`
- **口播互补**：声音说明任务背景，画面证明练手场已可运行。

## Scene 04｜开工先定最小规则

- **画面结构**：终端路径和项目根目录卡片。
- **视觉动作**：`claude` 在 `wordcount-demo` 中启动；两条规则写入 `CLAUDE.md`：`纯标准库`、`改完运行验证`。
- **视觉重点**：约束从一次提示沉淀为项目文件。
- **幕内字幕**：`把核心规矩说一次`
- **口播互补**：声音解释小项目不必堆规则，画面展示规则落位。

## Scene 05｜探索：先看懂，别急着改

- **画面结构**：文件树、代码编辑器和扫描状态。
- **视觉动作**：`@wordcount.py` 进入探索窗口；`main()`、`sys.argv[1]` 依次高亮；右侧显示 `入口已定位`、`缺参风险`；编辑器顶部保持 `未修改`。
- **视觉重点**：只读探索与修改状态明确分开。
- **幕内字幕**：`先别改任何代码`
- **口播互补**：声音讲探索问题，画面用扫描和风险标记证明“看懂”。

## Scene 06｜规划：先出方案，再砸代码

- **画面结构**：左侧任务卡，右侧计划卡和批准闸门。
- **视觉动作**：任务 `--top N + 缺参修复` 进入计划卡；`argparse`、`most_common(N)`、`usage` 三项出现；按钮状态停在 `等待批准`，代码区保持锁定。
- **视觉重点**：批准前没有源代码变化。
- **幕内字幕**：`方案先过，代码后动`
- **口播互补**：声音区分普通提示约束和 plan mode，画面表达共同的“先审后改”。

## Scene 07｜动手，但每处 diff 都过一眼

- **画面结构**：左右 diff 编辑器和审查栏。
- **视觉动作**：红色 `sys.argv[1]` 被替换为绿色 `argparse`；`--top` 加入 `main()`；审查栏勾选 `范围符合方案`、`纯标准库`；`count_words` 被绿色框保护。
- **视觉重点**：改了什么与没改什么同时可见。
- **幕内字幕**：`每处 diff 扫一眼`
- **口播互补**：声音解释事中拦截，画面展示审查证据。

## Scene 08｜验证：新、旧、边界三连验

- **画面结构**：三列终端验证卡。
- **视觉动作**：第一列运行 `--top 3`，显示 `the: 3 / fox: 2 / quick: 1`；第二列显示完整统计；第三列显示 `usage:` 和缺少 `path`，三列依次变绿。
- **视觉重点**：新功能、回归、边界分别验收。
- **幕内字幕**：`跑出来的通过，才是事实`
- **口播互补**：声音解释三种验证的意义，画面展示结果差异。

## Scene 09｜交付：概览、commit、log

- **画面结构**：状态栏、提交卡、日志卡三段式。
- **视觉动作**：`git status` 只显示 `wordcount.py`；commit message 进入确认卡；`git log -1` 亮出提交；旁边用细线标出 `push` 不在本次闭环内。
- **视觉重点**：交付不是“改完就算”，而是范围确认后入库。
- **幕内字幕**：`概览 → commit → log`
- **口播互补**：声音讲本地 commit 与远程 push 的边界，画面完成本地状态转换。

## Scene 10｜改岔了：干净退回再重开

- **画面结构**：一团红色错误 diff，分叉为轻档和重档。
- **视觉动作**：轻档连接 `/rewind`，重档连接 `git restore .` / `git reset --hard`；两条线都回到 `clean origin`，最后出现 `补清指令`。
- **视觉重点**：退回是止损，不是失败。
- **幕内字幕**：`别在烂摊子上硬补`
- **口播互补**：声音解释何时使用哪档回退，画面展示从混乱回到已知正确点。

## Scene 11｜老手不是跳步，而是交接完整

- **画面结构**：左右新手／老手对照，下方是完整六步闭环。
- **视觉动作**：新手路径缺少探索、规划和验证节点；老手六步全部点亮并汇聚为 `流程是骨架，不是镣铐`；最后出现预告卡 `下一篇：Chrome：让它操作浏览器`。
- **视觉重点**：最该形成肌肉记忆的是先探索、后验证；预告卡在最后单独停留约 2～3 秒。
- **幕内字幕**：`先探索，后验证`
- **口播互补**：声音抽象经验并预告下一篇，画面收束路径和下一集入口。

## 全片视觉类型／组件／动画标准

### 视觉类型

- `Concept Diagram`：失控原因和老手／新手对照。
- `Process Diagram`：六步接力棒。
- `Terminal Simulation`：命令、输出、验证和 git。
- `File Tree`：练手项目和探索范围。
- `Code Exploration`：入口、风险和未修改状态。
- `Plan Mode Simulation`：方案与批准闸门。
- `Code Diff`：红删绿加和范围审查。
- `Recovery Flow`：检查点和 git 原点回退。

### 组件标准

- `Window`：顶部栏、暗色面板、细边框。
- `Terminal`：等宽字体，命令与输出分层。
- `FileTree`：目录缩进清晰，扫描和错误位置短暂高亮。
- `Diff`：删除使用红色，新增使用绿色，保护范围使用蓝色框。
- `Chip`：命令、参数、模式名和状态。
- `Caption`：底部单行幕内字幕，不遮挡主体。
- `Progress`：仅服务于原型浏览，不属于正式视频画面。

### 动画标准

- 动画只表达出现、交接、扫描、等待、替换、验证、回退和汇聚。
- Scene 02、08、11 保留足够停留时间，确保六步、验证结果和下一篇预告可读。
- 不使用大段口播文字滚屏，不使用无意义漂浮和快速闪烁。

## Gate 2 内部审查结论

- Narration Script 每个 Scene 下只有实际口播，没有视觉说明、制作备注或 Gate 清单。
- Visual Script 的每个 Scene 与 Scene Script 的 11 个 ID、标题和视觉任务一一对应。
- 声音负责解释顺序、原因、边界和结论；画面负责显示过程、状态变化和证据。
- 原型所需的标题、命令、参数、输出、状态和预告均可在当前生产资料中追溯。
- 本阶段停止在 Visual Prototype，不生成 `tts-script.json`、音频、字幕、Timeline 或 Remotion 资料。
