# Claude Code「第一次使用」视频化 · 第二步：Video Narrative

> 叙事目标：把“我不知道终端里该敲什么”的紧张，转化为一次可控、可检查、可恢复的五分钟第一次成功。

## 1. 视频的叙事目标

观众不是来背命令的，而是要亲眼看到第一次使用 Claude Code 的安全路径：先给它一个小项目，再让它先读后改，最后看懂 diff 并保留回溯能力。

全片的情绪曲线是：

```text
不敢开始 → 有一个安全练习场 → 知道从哪里启动
→ 先确认它读懂了 → 看见它提出改动
→ 我批准后才落盘 → 改错也能回去 → 我能自己再跑一遍
```

## 2. 整体叙事结构

| 段落 | Scene | 观众认知 | 视觉事件 |
|------|------|----------|----------|
| 开场 | 01 | 第一次卡住很正常 | 终端光标与“然后呢？” |
| 降低风险 | 02 | 不要拿正式项目练手 | 创建 `hello-claude` 和 `main.py` |
| 确定边界 | 03 | Claude 要在项目目录里启动 | 路径切入工作区 |
| 认识入口 | 04 | 欢迎屏幕只需先看三处 | 输入框、`/help`、`/resume` |
| 先读后改 | 05 | 解释型任务是低风险试水 | 读取 `main.py` 并返回解释 |
| 人的批准 | 06 | 修改不是黑盒，先看 diff | 旧行／新行 → 批准 → 文件更新 |
| 恢复能力 | 07 | 改错不等于失控 | “改回去”、`/rewind`、Checkpoint 与 Git 边界 |
| 完整闭环 | 08 | 五步可以照着复现 | 命令、预期输出、结果确认 |
| 收束与预告 | 09 | 最小内核是提需求、看 diff、批准／反悔 | 五步路线图与 VS Code 预告 |

## 3. 叙事推进原则

### 先解决心理门槛，再给命令

开场不直接上 `mkdir`，先呈现“终端打开后不知道下一步”的真实停顿。这样后续每条命令都有明确目的，而不是命令清单。

### 让目录成为第一条安全线

玩具项目和项目目录不是两个孤立技巧：前者控制修改范围，后者确定 Claude 读取什么。Scene 02 和 Scene 03 连续出现，构成“安全场地 → 正确入口”的关系。

### 把第一次交互设计成只读验证

Scene 04 认识输入框后，Scene 05 先让 Claude 解释 `main.py`。观众先看到“它读到了真实文件”，再进入可能修改文件的任务，降低不确定性。

### 用 diff 作为全片高潮

Scene 06 是全片的主要视觉和认知转折：Claude 不是直接替人改文件，而是把修改摆出来等待批准。画面重点必须是 diff 的变化和人的选择，不是复杂的代码内容。

### 用回溯把安全感闭环

Scene 07 不重复 Scene 06 的批准逻辑，而是回答观众的潜台词：“如果我批准后发现不对呢？”通过“改回去”与 `/rewind` 给出即时恢复路径，再把 Checkpoint 与 Git 的边界说清。

### 最后再给完整操作路线

Scene 08 才把前面拆开的动作压缩成五步，配合预期输出，让观众有可执行的复现脚本。Scene 09 只收束本片最小内核，并预告下一篇 VS Code 集成。

## 4. 不采用的叙事方式

- 不按原文 01～07 逐节做成七张标题页，避免视频变成文章目录朗读。
- 不把欢迎屏幕做成产品功能介绍，避免新手被 `/resume` 等非关键命令分散注意力。
- 不把完整 Python 错误处理代码做成编程教学；它只是用于让观众看到“有明确 diff、有结果”。
- 不在本片展开 Git、权限报错、安装和登录；这些内容属于系列其他篇章。

## 5. 结尾定义

最后不要说“Claude 会自动帮你完成一切”。准确的收束是：第一次使用的最小内核，是在正确项目里用自然语言提需求，先看 diff，再批准或反悔；人仍然负责看懂和做判断。

下一集预告固定为：**08「VS Code 集成」——命令行跑通后，把 Claude Code 放到编辑器旁边，看 diff 会更直观。**
