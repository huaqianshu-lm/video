# Claude Code「第一次使用」视频化 · 第五步：Visual Script

## 全局视觉原则

### 1. 用一个可控项目讲清全过程

全片只使用 `hello-claude`、`main.py` 和 `add` 函数，不扩展到正式项目、复杂依赖或其他工具。观众要能持续认出同一个文件在不同状态下发生了什么。

### 2. 视觉承担“过程证明”

口播解释为什么要小项目、为什么先读后改、为什么要看 diff；画面负责证明目录切换、文件读取、待批准状态、改动落盘和回溯路径确实发生。

### 3. 一个 Scene 只表达一个状态变化

每幕只有一个视觉中心：焦虑、创建、进入工作区、认识入口、只读解释、diff 审批、回溯、五步复现、最小闭环。避免一幕同时堆叠多个功能表格。

### 4. 少做页面，多做操作过程

终端、文件卡片、diff、状态徽标和流程线都使用轻量模拟 UI。它们服务于动作顺序，不做真实产品界面的完整复刻。

### 5. 画面文字必须有当前资料依据

标题、命令、文件名、状态和预告全部可追溯到当前 Source、Content Analysis、Video Narrative、Scene Script 或本 Visual Script。不得带入其他视频的 Bug、ChatGPT、Copilot、Cursor 等业务语义。

## Scene 01｜终端打开了，然后呢？

### 视觉目标

把第一次使用的停顿和担心变成可见的开场问题。

### 画面结构

深色终端占据画面主体，光标在空输入行闪烁；上方只出现两个低对比度短语：“然后呢？”、“怕改坏”。随后中央浮出 `今天：跑通第一个任务`。

### 动画

先保持光标闪烁约 1 秒，再让问题文字轻微浮现，最后让任务卡片从模糊变清晰。所有元素入场缓慢，给口播留下停顿。

### 屏幕文字

`终端打开了，然后呢？`、`跑通第一个任务`、`不超过五分钟`

### Visual Type

`Opening / Terminal`

## Scene 02｜先建一个可以重来的玩具项目

### 视觉目标

用对比建立“正式项目太复杂，玩具项目可控”的理由。

### 画面结构

左侧是模糊、低透明度的复杂目录，右侧是清晰的 `hello-claude` 文件夹和 `main.py`。下方终端按顺序显示：

```text
$ mkdir hello-claude
$ cd hello-claude
$ create main.py
```

右侧编辑器只显示：

```python
def add(a, b):
    return a + b
```

### 动画

先压低复杂目录，再让 `hello-claude` 卡片高亮；命令逐行出现，`main.py` 从“创建中”变为“可读”。

### 屏幕文字

`练车场：hello-claude`、`main.py`、`改砸了也能重建`

### Visual Type

`Terminal / File Workspace`

## Scene 03｜一定要在项目目录里启动

### 视觉目标

让工作区边界成为一个明确的空间关系。

### 画面结构

终端路径从 `~/` 移动到 `~/hello-claude`。错误路径区域用灰色虚线框，正确目录用蓝色实线框包住 `main.py`。命令行最后显示：

```text
~/hello-claude $ claude
```

### 动画

路径片段逐段高亮，输入 `claude` 后，工作区边框锁定，文件树从目录内部展开。

### 屏幕文字

`当前目录 = 工作区`、`~/hello-claude $ claude`、`Claude 从这里读文件`

### Visual Type

`Terminal / Boundary Diagram`

## Scene 04｜欢迎屏幕先认住三样东西

### 视觉目标

把欢迎屏幕的复杂感压缩成三个入口。

### 画面结构

模拟欢迎屏幕作为软件窗口，背景保留会话信息和更新提示但降低对比度。底部输入框高亮，右侧标签依次指向 `/help` 与 `/resume`。

### 动画

先聚焦输入框，再依次点亮 `/help` 和 `/resume`。`/resume` 标签出现“第一次先不管”，避免观众误以为必须先学习它。

### 屏幕文字

`输入框`、`/help：查看命令`、`/resume：继续会话`、`用大白话提需求`

### Visual Type

`Terminal UI / Callouts`

## Scene 05｜先让 Claude 读懂，再让它动手

### 视觉目标

展示只读解释任务：文件被读取，但没有发生修改。

### 画面结构

左侧是输入请求：`解释 main.py 这个文件在做什么`。中间是 `main.py` 文件卡片，状态为 `Reading`；右侧是返回解释：`add(a, b) → 返回 a + b`。底部三个标签中只有 `解释型：只读` 为绿色。

### 动画

扫描线从文件名穿过两行代码，右侧解释卡片随后出现；文件状态保持 `Unchanged`，强调“读了但没改”。

### 屏幕文字

`解释 main.py 这个文件在做什么`、`add(a, b)`、`解释型：只读`、`Unchanged`

### Visual Type

`Concept / Read-only Verification`

## Scene 06｜看懂 diff，再批准改动

### 视觉目标

把“先问后动”做成全片最清楚的状态转换。

### 画面结构

顶部是请求：`增加类型注解，并补充基本的错误处理`。中间左右两列为 `Before` 与 `Proposed Change`：左列两行旧代码，右列新增类型注解和 `TypeError`。删除行用红色 `-`，新增行用绿色 `+`。底部是批准选项。

### 动画

先出现请求，再逐行显示 diff，最后弹出批准条。只高亮 `同意 / Yes` 一次，文件状态从 `Waiting for approval` 变为 `Updated`。

### 屏幕文字

`等待批准`、`- 旧行`、`+ 新行`、`同意 / Yes`、`本次会话不再问`、`拒绝 / No`

### Visual Type

`Comparison / Diff Review`

## Scene 07｜改错了，还有两条后悔药

### 视觉目标

区分自然语言回退、Checkpoint 回溯与 Git 历史。

### 画面结构

中央为 `当前修改` 卡片，向下分出两条路径：`改回去` 和 `/rewind`。右侧是 Checkpoint 卡片，底部为两条对照胶囊：`Checkpoint = 本地撤销`、`Git = 永久历史`。

### 动画

先让当前修改出现，再让两条回退路径从同一点展开；`/rewind` 出现时补充小字“输入框为空时双击 Esc”。最后点亮 Git 胶囊，作为边界提醒。

### 屏幕文字

`改回去`、`/rewind`、`输入框为空时双击 Esc`、`Checkpoint = 本地撤销`、`Git = 永久历史`

### Visual Type

`Recovery / Comparison`

## Scene 08｜五步跑通第一个任务

### 视觉目标

把完整动作变成可执行路线图，并在末尾显示预期结果。

### 画面结构

横向五节点：

```text
建项目 → 启动 → 解释 → 批准 → 确认结果
```

节点下方分别显示 `mkdir + cd`、`claude`、`解释 main.py`、`看 diff / 同意`、`cat main.py`。末端文件卡片显示 `a: float` 与 `raise TypeError(...)`。

### 动画

节点按照口播逐个点亮，连接线在当前节点前方推进；最后文件卡片从 `Before` 切换为 `After`，绿色状态标记 `流程完成`。

### 屏幕文字

`1 建项目`、`2 启动`、`3 解释`、`4 批准`、`5 确认结果`、`流程完成`

### Visual Type

`Step List / Workflow`

## Scene 09｜第一次使用的最小内核

### 视觉目标

将五步压缩成可迁移的协作循环，并完成下一集预告。

### 画面结构

中央循环线连接三个节点：`提需求`、`看 diff`、`批准 / 反悔`。左下角短句说明 `人：确认与判断`，右下角说明 `Claude：读取、分析、执行`。右上角为下一集卡片：`08 · VS Code 集成`，副文案为 `让代码和 diff 并排出现`。

### 动画

三个节点依次点亮并形成循环，人的判断与 Claude 的执行两张卡片从两侧进入；最后预告卡片轻微上移并停留，预留 2～3 秒可读时间。

### 屏幕文字

`提需求 → 看 diff → 批准 / 反悔`、`人：确认与判断`、`Claude：读取、分析、执行`、`下一篇：08 · VS Code 集成`

### Visual Type

`Summary / Preview Card`

## 全片视觉类型／组件／动画标准

### 视觉类型分布

- `OpeningScene`：Scene 01。
- `TerminalScene`：Scene 02、03。
- `ConceptScene`：Scene 04、05。
- `ComparisonScene`：Scene 06、07。
- `StepListScene`：Scene 08。
- `SummaryScene`：Scene 09。

### 组件复用

优先复用 `OpeningScene`、`ConceptScene`、`ComparisonScene`、`StepListScene`、`TerminalScene`、`SummaryScene` 六个通用场景，不新增场景组件。终端窗口、文件树、Diff 列、状态徽标和预告卡片作为场景内部的基础视觉元素表达。

### 动画标准

- 目录和文件状态变化使用短距离淡入／上移，不做大幅飞入。
- 扫描、连接线和光标动画只用于表示读取、路径和流程状态。
- diff 逐行出现，先展示内容，再展示批准选择。
- 回溯路径从当前修改点展开，不能把 `/rewind` 画成删除或 Git 提交。
- 总结循环和下一集预告在最后停留 2～3 秒。
- 不使用复杂 3D、粒子、快速闪烁或无法在静态原型中验证的效果。

### 信息密度与安全区

- 1920 × 1080 横屏构图；主标题控制在 1～2 行。
- 终端和 diff 区域保持主体面积，字幕预留底部安全区。
- 单幕屏幕主文案不超过 3 个层级；代码只显示与当前口播直接相关的行。
- 最后一幕的预告卡片放在右上或右侧，不与底部字幕区重叠。

## 下一步

制作无依赖 HTML + CSS Visual Prototype，沿用基线的 Scene 容器、幕内字幕、上一幕／下一幕／自动播放和进度提示结构；原型只用于确认画面语言、构图、信息密度和状态变化，不作为最终 Remotion 实现。
