# 插件参考手册：Video Narrative

## 1. 视频叙事目标

这条视频不重复“如何安装别人插件”，而是让观众完成一次角色变化：

```text
插件只是装好的能力
        ↓
插件其实由清晰的目录、清单和组件组成
        ↓
我可以按规则造一个能跑的插件
        ↓
我可以在本地迭代、验证，再选择合适的分发方式
        ↓
我知道版本和依赖怎样影响发布
```

核心承诺是：先把一个插件看懂，再把从骨架到发布的链路走通；字段表和边角限制作为随查随用的参考，而不是一次塞给观众的百科全书。

## 2. 叙事结构

```text

↓
02 先摆正目录骨架

↓

↓
06 从零造插件并在本地跑通
↓

↓

↓

↓

```

## 3. 观众认知推进

### 第一段：从 token 数字切入结构问题

用 `claude plugin details` 中的常驻 token 与 skill 触发 token 作为钩子，让观众意识到插件即使不主动操作也由明确组件组成。随后明确本片从“会用”转向“会造、会发”。

### 第二段：从空间关系建立插件骨架

先展示完整目录，再强调 `.claude-plugin/` 只放 `plugin.json` 的铁律。观众先记住“说明书”和“零件盒”的空间关系，后面再理解字段和组件。

### 第三段：从身份到能力边界

先用 `plugin.json` 解释 name、命名空间和路径字段的替换／追加差异，再把七类组件放进同一个盒子里，最后用 agent 限制和 monitor 实验性状态制造边界感。

### 第四段：从写死路径转向可迁移插件

用坏掉的绝对路径和三个变量对比，让 `${CLAUDE_PLUGIN_ROOT}`、`${CLAUDE_PLUGIN_DATA}`、`${CLAUDE_PROJECT_DIR}` 各自承担可理解的职责。

### 第五段：从本地闭环走向分发

用 `my-greeter` 的命令链把“初始化、加载、调用、重载”串成一个连续过程；接着拆开 marketplace 的市场源和插件源，最后比较三种分发路线。

### 第六段：以发布坑收束

把 version 和 dependencies 处理成两个会改变发布结果的决策点，最后回到“插件是可拆、可测、可发布的配置包”，并预告下一集将把前面零件串成一条实战路径。

## 4. 叙事原则

- 不从字段表开场，先用 token 和“黑盒拆解”制造问题。
- 不把七类组件做成静态百科页，使用“装入插件盒”和状态标签完成认知。
- 命令只展示开发链路中的必要节点，不把文章全部命令照单朗读。
- 旁白解释为什么规则重要，画面展示目录、状态、连接和选择。
- 结尾保留约 2～3 秒给总结和下一集预告阅读。
