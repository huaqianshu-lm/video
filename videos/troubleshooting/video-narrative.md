# Video Narrative：Claude Code 出问题，别先重装

## 视频叙事目标与命题

Claude Code 的故障排查不是“多试几个命令”，而是一个逐步缩小变量的诊断过程：先判断类别，再查看真实状态，按根因处理，最后用日志或干净配置对照确认。

## 观众认知路径

```text
我看到一个吓人的错误
  ↓
错误可能只是表象，先复盘典型案例
  ↓
我需要先判断问题属于哪一类
  ↓
我可以用 /doctor 和 /status 获取证据
  ↓
不同类别有不同的排查动作
  ↓
复杂问题可以用 --debug 和 clean config 二分
  ↓
我能照着一条体检链执行
```

## 叙事结构

### 第一段：先打破“重装就能好”的直觉

用 `This organization has been disabled` 和旧 `ANTHROPIC_API_KEY` 的案例制造反转：问题不在账号订阅，而在实际使用的凭证。观众先理解“表面错误不等于根因”。

### 第二段：建立总路由和自助入口

把错误按安装、认证、配置、性能、API／请求等方向分流，再给出 `/doctor`、`claude doctor` 和 `/feedback` 的使用时机，建立排查的起手式。

### 第三段：按类别展示排查动作

认证以 `/status` 和环境变量为例；配置以实际加载状态、hooks、MCP 和权限为例；性能以上下文和搜索为例；API 报错以责任方三分法为例。声音解释判断逻辑，画面展示状态变化和命令映射。

### 第四段：把复杂问题变成可控实验

用 `--debug` 查看实时过程，用干净配置对照排除用户／项目配置，再一次只加回一个变量，把“玄学问题”变成二分定位。

### 第五段：形成肌肉记忆并打开下一集

让观众走完 `claude --version` → `/doctor` → `/status` → clean session 的体检链，最后收束为“先分诊、查状态、按根因处理、留证据”，并预告第 52 篇术语表。

## 视频节奏

- Scene 01 先给反转案例，快速建立问题。
- Scene 02—03 给总方法和工具入口，避免进入细节前失去方向。
- Scene 04—08 每幕只解释一类排查动作，用明显的状态／分支变化区分。
- Scene 09—10 将进阶方法和可执行流程收束为实验链。
- Scene 11 复盘，Scene 12 单独承担下一篇预告并留出停留空间。

## 口播与画面分工

- 口播负责解释“为什么先查这里”“这个错误意味着什么”“什么时候等、改或回退”。
- 画面负责展示错误到根因的反转、分类流向、状态命令、配置面板、三分法和二分对照。
- 不把整段口播逐字铺到屏幕；屏幕只显示命令、错误短语、类别、状态和结果。

## 结尾设计

Scene 11 先把排查主干收束成可执行动作。Scene 12 作为最后视觉事件显示“下一篇：52 · 术语表（小白友好）”，对应 Source 结尾的系列导航，预告卡与字幕区域分离，并保留约 2～3 秒可读停留。

## Gate 1 叙事审查

- 没有机械按文章 01—09 章节逐章朗读，而是按“反转案例—认知框架—类别动作—进阶实验—体检闭环”重组。
- 12 个 Scene 的顺序支持从困惑到可执行，不依赖未解释的术语。
- 文章中的命令和案例是叙事证据，不被扩写为真实执行结果。
