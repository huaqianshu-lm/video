# Content Analysis：Claude Code 常见问题排查

## 1. 内容定位

这篇文章不是错误码百科，而是一套从症状到根因的排查方法。它要把读者从“看到红字就乱试”带到“先分类、查实际状态、缩小变量、用证据确认”的工作方式。

文章围绕一个典型案例展开：旧的 `ANTHROPIC_API_KEY` 残留在 `~/.zshrc`，优先于订阅登录，导致 `This organization has been disabled`。这个案例证明，表面错误不等于根因，诊断工具和状态检查比重装软件更重要。

## 2. 核心命题

> Claude Code 出问题时，先按症状分诊，再用内置诊断命令和实际配置确认问题边界；根据根因分别处理凭证、配置、上下文、网络、额度或服务端故障，最后用调试日志和干净配置对照锁定剩余变量。

## 3. 观众必须带走的信息

1. **先分诊**：安装、认证、配置、性能、API 报错不是同一类问题，类别错了，后续动作就会错。
2. **先用自助入口**：能启动时运行 `/doctor`，不能启动时运行 `claude doctor`；解决不了再用 `/feedback` 上报。
3. **认证先看凭证**：用 `/status` 判断当前走 OAuth 订阅还是 API key；残留 `ANTHROPIC_API_KEY` 可能压过订阅。
4. **配置先查实际加载**：用 `/context`、`/memory`、`/skills`、`/agents`、`/hooks`、`/mcp`、`/permissions` 和 `/status` 看系统真正读入了什么。
5. **权限有软硬边界**：`CLAUDE.md` 是请求，不是强制保证；硬约束应使用 `deny` 规则或 `PreToolUse` hook，并注意字面命令匹配及大小写。
6. **性能先清工作台**：`/compact`、重启、`claude --resume`、分块读取大文件；搜索或 `@file` 失灵时检查系统 `ripgrep`。
7. **API 错误先判断责任方**：5xx／529 是服务端，limit 是额度，too long／too large 是请求，Unable to connect 多半是网络或代理。
8. **怪问题用二分法**：`claude --debug`、`--debug mcp`、`--debug hooks` 看实时过程；用 `CLAUDE_CONFIG_DIR` 指向干净目录做对照。
9. **形成固定体检链**：`claude --version` → `/doctor` → `/status` → 干净会话对照。

## 4. 知识骨架与关系

### 4.1 排查主链

```text
症状
  ↓
问题分类
  ↓
/doctor 或 claude doctor
  ↓
读取实际状态／配置
  ↓
按根因处理
  ↓
运行结果或调试日志验证
```

### 4.2 六类问题路由

| 症状 | 分类 | 首要方向 |
|---|---|---|
| `command not found`、PATH、`EACCES` | 安装 | 检查安装与 PATH |
| 反复登录、`403`、`organization disabled` | 登录认证 | `/status` 看凭证 |
| settings、hooks、MCP、权限不生效 | 配置 | 查实际加载状态 |
| 卡顿、高内存、搜索失灵 | 性能 | 清上下文、检查环境 |
| `5xx`、`529`、`429`、额度、请求过大 | API／请求 | 判断服务端、额度或输入 |
| 模型不可用、政策拒绝 | 模型／会话 | 重选模型或回退会话 |

### 4.3 关键因果关系

- 错误表面 → 类别判断 → 不同处理动作；分类错误会把修复方向带偏。
- `/status` → 当前认证来源 → 发现 `ANTHROPIC_API_KEY` 优先级问题 → `unset` 并清理 shell 配置。
- `/hooks` 已注册但不触发 → 检查 matcher 大小写和配置位置；规则“存在”不代表规则“匹配”。
- 上下文过满 → `/compact`、重启、分块读取；自动压缩抖动则减少单次输入或 `/clear`。
- `5xx`／`529` → 自动重试已耗尽 → 等待、查状态页或换模型，而不是盲目修改本机配置。
- 干净配置中问题消失 → 根因在用户／项目配置；一次只加回一个变量即可二分定位。

## 5. 可视觉化内容

- 开场案例：错误提示、旧 API key、订阅身份、`unset` 修复前后。
- 症状路由板：症状标签流向安装、认证、配置、性能、API 五类入口。
- `/doctor` 与 `/feedback`：体检面板和上报入口的先后关系。
- 认证状态：OAuth 与 API key 的分流，以及 `/status` 的确认作用。
- 配置检查台：多个状态命令对应实际加载内容。
- 权限边界：自然语言请求与 `deny`／hook 硬约束的对比。
- 性能修复：上下文容量条、`/compact`、重启、`claude --resume`、ripgrep。
- API 错误三分法：服务器、额度、请求大小，并补充网络连接分支。
- 调试二分法：普通配置与 clean config 的对照，以及逐项加回。
- 体检流水线：版本、doctor、status、clean session。
- 结尾速查：问题类型与对应动作；最后预告第 52 篇术语表。

## 6. 信息取舍

### 必须保留

- `ANTHROPIC_API_KEY` 覆盖订阅的开场根因。
- `/doctor`、`claude doctor`、`/feedback`、`/status`。
- 配置实际加载检查与权限软硬边界。
- 性能、API 报错三分法和网络分支。
- `--debug` 与干净配置对照法。
- 可执行的完整体检链和预期结果。

### 适合弱化

- 所有具体错误表不逐条复述，合并成路由和代表性例子。
- `heapdump`、`/terminal-setup`、`/usage-credits` 等低频补充只作为卡片标签或旁注。
- 各平台安装差异不展开，保留症状和方向即可。

### 不进入本视频

- 不新增文章外的 Claude Code 功能、版本承诺或外部事实。
- 不执行文章中的任何命令，不验证真实账号、网络或 API 状态。
- 不生成 TTS、音频、字幕、Timeline 或 Remotion 配置。

## 7. 事实边界与画面文字约束

- 所有命令、错误文本、路径、环境变量、状态页和配置文件名均来自 Source；画面只保留理解所需的短标签。
- “四十分钟”“旧 key 压过订阅”是文章开场案例中的叙事事实，不扩展为普遍概率。
- `/feedback` 会发送什么、第三方提供商如何保存等细节只在口播中谨慎概括，不在原型中伪造真实提交结果。
- 原型中的“服务端”“额度”“请求过大”“干净配置”等标签是对文章现有分类的视觉压缩，不添加新的技术结论。
