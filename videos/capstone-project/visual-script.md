# Claude Code 综合实战视频化 · 第五步：Visual Script

## 全局视觉原则

### 1. 让流程承担解释

口播负责解释为什么要规划、验证、恢复和交付，画面负责展示文件、会话、连接、输出和状态变化。不要把六个能力名词直接排成静态海报。

### 2. 一个 Scene 一个视觉中心

每幕只保留一个主要动作：聚合、回路、搭地基、交接、连接、分工、退回、执行、验证、交付、对照或收束。

### 3. 视觉文字必须可追溯

所有标题、标签、命令、状态和卡片文案都来自当前文章或本视频的 Content Analysis、Video Narrative、Scene Script、Narration Script 或本文件。示例项目文字只作为文章中的示例状态，不表示本次视频项目实际执行过 todo-cli。

### 4. 视觉类型

优先使用 Concept Visualization、Process Diagram、Project Setup Simulation、Cross-Session Workflow、Connection Diagram、Delegation + Review、Recovery Comparison、Terminal + Plan Simulation、Verification Demo、Delivery Boundary、Comparison Diagram、Summary + Preview。

### 5. 运动规则

- 能表达因果的运动优先：节点亮起、文件生成、卡片接力、连接接通、任务派出、状态恢复。
- 动画保持克制，给终端输出、流程节点和结尾预告足够停留时间。
- Scene 12 的预告卡片与字幕区域分离，预留约 2～3 秒阅读时间。
- 原型只验证 1920 × 1080 横屏构图、密度和状态变化，不代表最终 Remotion 动画。

## Scene 01｜毕业设计不是新功能

- **视觉目标**：散落的 CLAUDE.md、权限、MCP、subagent、检查点、git 标签被吸入一条项目时间线，最后形成乐队指挥台。

- 画面结构：深色工作台，六个能力标签散落在不同位置，中央留出空白项目轨道。
- 视觉动作：标签依次靠拢，形成「项目」节点和一条从开工到交付的线。
- 屏幕文字：学会零件 ≠ 完成项目。
- 口播互补：声音说明「学会」与「合奏」的差异，画面展示从分散到聚合。
- Visual Type：Concept Visualization。

## Scene 02｜中等项目是一条带回路的工程流

- **视觉目标**：六个节点依次亮起，最后从交付回到规划形成回路；跨会话标签沿回路移动。

- 画面结构：六节点横向流程，交付节点下方有回到规划的弧线。
- 视觉动作：节点按顺序亮起，跨会话标签沿回路移动。
- 屏幕文字：立项 → 规划 → 接外部 → 分活 → 容错 → 交付。
- 口播互补：声音解释为什么会话结束后还要回到规划，画面证明它不是单向直线。
- Visual Type：Process Diagram。

## Scene 03｜立项：先把规矩和退路立起来

- **视觉目标**：空项目依次出现 CLAUDE.md、todos.json、test_todo.py、README，下方生成 git init 原点；权限允许列表亮起。

- 画面结构：左侧项目文件树，右侧 CLAUDE.md 规则卡和权限卡，底部是 git 原点。
- 视觉动作：文件从空白项目中逐个生成，git init 变成稳定原点。
- 屏幕文字：CLAUDE.md、todos.json、test_todo.py、README、先定规矩、先留退路。
- 口播互补：声音说明各个基础设施的作用，画面展示它们如何同时到位。
- Visual Type：Project Setup Simulation。

## Scene 04｜规划：SPEC 让大活儿可以跨会话

- **视觉目标**：模糊需求卡片经过采访问题，收敛为 SPEC.md；四个会话卡片依次接力，SPEC.md 始终位于中间。

- 画面结构：左侧模糊需求，中间 SPEC.md，右侧四张会话卡。
- 视觉动作：采访问题扫过需求，SPEC.md 成形并被四个会话依次读取。
- 屏幕文字：SPEC.md、会话 1 → 会话 2 → 会话 3 → 会话 4。
- 口播互补：声音解释文件化交接，画面展示同一份文件跨会话传递。
- Visual Type：Cross-Session Workflow。

## Scene 05｜接外部：MCP 把够不着的资料接进来

- **视觉目标**：项目窗口左侧反复出现复制粘贴断点，随后一条 MCP 连接接通文档、数据库和 GitHub，连接旁出现信任检查与只读标记。

- 画面结构：项目节点在左，文档、数据库、GitHub 在右，中间是 MCP 连接。
- 视觉动作：复制粘贴箭头先断裂，再由 MCP 连接成稳定通道；信任检查和只读标记随后出现。
- 屏幕文字：先验信任、数据库只读。
- 口播互补：声音说明何时接入与为什么谨慎，画面同时表现连接价值和安全条件。
- Visual Type：Connection Diagram。

## Scene 06｜分活：隔离探索，保留主上下文

- **视觉目标**：主会话把「探索 todos.json 读写」任务派出，subagent 在独立档案室扫描，回传一张摘要卡；另一条审查通道接收 diff 并标记问题。

- 画面结构：主会话、独立 subagent 档案室、新鲜审查上下文三列。
- 视觉动作：探索任务从主会话派出，档案室扫描后只返回摘要卡，diff 进入审查列。
- 屏幕文字：只回传摘要、新鲜上下文挑刺。
- 口播互补：声音解释上下文保护和审查独立性，画面展示信息如何被压缩和转交。
- Visual Type：Delegation + Review。

## Scene 07｜容错：改崩时先干净退回

- **视觉目标**：左侧代码越补越乱，右侧从稳定提交分出两档恢复：检查点轻档和 git 重档；最终回到干净状态。

- 画面结构：左侧混乱代码，右侧两条恢复路径：检查点轻档、git 重档。
- 视觉动作：补丁线在左侧堆叠后变红；右侧选择恢复路径，画面回到稳定 commit。
- 屏幕文字：干净退回、不是硬补。
- 口播互补：声音解释适用边界，画面展示止损动作。
- Visual Type：Recovery Comparison。

## Scene 08｜真实项目：先规划，再开始动手

- **视觉目标**：Terminal 中出现项目任务，plan mode 输出文件结构和命令；批准按钮亮起后，todo.py、test_todo.py 和 todos.json 依次出现。

- 画面结构：终端窗口显示 plan mode，旁边是 todo.py、test_todo.py、todos.json。
- 视觉动作：计划出现，批准后文件依次生成，diff 面板显示范围。
- 屏幕文字：先出方案、再开始、add、list、unittest。
- 口播互补：声音讲顺序和约束，画面证明批准门槛和文件变化。
- Visual Type：Terminal + Plan Simulation。

## Scene 09｜真实项目：验证和挑刺

- **视觉目标**：Terminal 先显示测试 OK，再显示两条任务和未完成标记；/code-review 生成审查卡，指出待检查项。

- 画面结构：终端分成测试、真实运行、code review 三个连续状态。
- 视觉动作：OK 亮起，随后出现两条任务，再由 review 卡标记待检查项。
- 屏幕文字：OK、[1] [ ] 写第48篇教程、跑出来才是事实。
- 口播互补：声音解释证据链，画面展示从命令到事实输出。
- Visual Type：Verification Demo。

## Scene 10｜交付：看范围、写 commit、守住 push

- **视觉目标**：工作区文件进入 diff，diff 被压缩成一条明确 commit；远程 push 按钮停在人工检查线之前。

- 画面结构：工作区、git diff、本地 commit、远程 push 四个节点，人工检查线放在 push 前。
- 视觉动作：文件差异收敛成 commit，push 箭头在人工检查线前暂停。
- 屏幕文字：git status、git diff、commit、人把关 push。
- 口播互补：声音解释本地与远程的责任边界，画面把「停住」作为最后状态。
- Visual Type：Delivery Boundary。

## Scene 11｜玩具打法与真实打法

- **视觉目标**：左侧玩具流程短而断裂，右侧真实流程完整并带回路；七个差异标签逐个从左侧迁移到右侧。

- 画面结构：左侧短而断裂的玩具流程，右侧带回路的真实流程。
- 视觉动作：七个标签从断点处飘出，逐个嵌入真实流程；左侧的省略符号变成返工箭头。
- 屏幕文字：流程不是镣铐、是把项目做大的骨架。
- 口播互补：声音说明省步骤会把成本推迟，画面展示断裂与补全的差异。
- Visual Type：Comparison Diagram。

## Scene 12｜合奏完成，下一集预告

- **视觉目标**：六个能力节点回到同一条项目曲线，合奏指挥台变成清晰的交付路线；最后只留下下一集预告卡片。

- 画面结构：六个能力节点围绕交付路线汇聚，最后切换为居中的预告卡。
- 视觉动作：节点汇聚后静止，预告卡单独淡入并保持 2～3 秒。
- 屏幕文字：下一集、49「最佳实践」。
- 口播互补：声音总结「零件变方法」，画面负责系列收束和下一集导航。
- Visual Type：Summary + Preview。

## 全片视觉类型／组件／动画标准

### 视觉类型

- 流程图和回路用于表达顺序、回到规划和跨会话。
- 文件树、终端和 diff 用于表达真实项目的过程证据。
- 连接图用于表达 MCP 的范围扩展和信任边界。
- 双栏对照用于表达玩具打法与真实打法的差异。

### 组件

- 深色 16:9 Scene 容器。
- 顶部 eyebrow、主标题、状态卡、文件卡、终端窗口、连接线、进度指示器。
- 幕内字幕胶囊置于底部安全区；内容区和字幕区不重叠。
- 上一幕、下一幕、自动播放和进度提示只属于原型控制层，不属于最终视频内容。

### 动画标准

- Scene 切换：短淡入和轻微缩放。
- 状态变化：节点亮起、文件生成、连接线流动、输出逐条出现。
- 恢复场景：错误状态停留后再回到稳定节点。
- 交付场景：push 前保持明显停顿，避免暗示自动发布。
- 结尾预告：卡片保持约 2～3 秒，避免与字幕胶囊重叠。
