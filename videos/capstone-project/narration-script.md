# Claude Code 综合实战视频化 · 第四步：Narration Script

## Scene 01｜毕业设计不是新功能

前面四十多篇，我们已经把 Claude Code 的很多零件分别练过了。

但会用每一个零件，和能把它们组织成一个真实项目，是两回事。

这一篇不再教你一个新功能。

我们要做的是一次毕业设计：把这些零件按正确的时机串起来，从开工一直走到交付。

## Scene 02｜中等项目是一条带回路的工程流

一个中等项目的骨架，可以拆成六棒：立项、规划、接外部、分活、容错，最后交付。

它和单文件小练习最大的不同，是一个会话通常干不完。

你需要把工作分块，跨会话接力。

验证完一轮之后，还可能回到规划阶段，继续下一块。

所以真实项目不是一条做完就结束的直线，而是一条可以反复转几圈的工程回路。

## Scene 03｜立项：先把规矩和退路立起来

这次的示例项目，是一个命令行任务清单工具 todo-cli。

它有多个文件，要把数据保存到本地 JSON，还要配测试和 README。

所以开工时，先不要急着写功能。

先用 CLAUDE.md 把项目规矩写清楚，用权限基线减少重复批准，再用 git 留下一个干净的原点。

这样后面的每个会话，都知道应该遵守什么，也知道出了问题可以退回哪里。

## Scene 04｜规划：SPEC 让大活儿可以跨会话

规矩立好以后，下一步不是直接开写，而是先规划。

让 Claude 采访你，把命令、字段、边界情况和验收标准问清楚，再把结果写进 SPEC.md。

然后按功能切成几个会话：第一个会话搭骨架，后面继续做 list、done、边界处理和文档。

每次换会话，先读 SPEC.md 和 git log。

对话会结束，文件不会。

SPEC 就是跨会话交接时最可靠的备忘录。

## Scene 05｜接外部：MCP 把够不着的资料接进来

项目继续做，很快会遇到代码库之外的资料。

如果你总是在另一个工具里查文档、看数据库或找项目任务，再复制回来贴给 Claude，这就是该考虑 MCP 的信号。

MCP 可以把这些外部上下文接进来。

但连接能力变大，边界也要一起变清楚：先验证 server 是否值得信任，生产数据库优先使用只读账号。

## Scene 06｜分活：隔离探索，保留主上下文

项目变大以后，不要让主对话把每个文件全文都读一遍。

可以派一个 subagent 去摸清 todos.json 的读写位置，只把文件、函数和作用整理成摘要带回来。

功能完成以后，再用一个新鲜上下文审查 diff。

这样既能保护主对话的上下文，也能减少刚写完代码就自我肯定的偏差。

## Scene 07｜容错：改崩时先干净退回

复杂改动总有改偏的时候。

最容易犯的错，是对着已经混乱的代码继续补丁，结果越补越乱。

更稳的做法是先干净退回：小范围用检查点或 /rewind 撤掉当前会话的编辑，大范围回到一个稳定的 git 提交。

退回不是失败，而是止损。

退回之后，再把这次漏掉的约束说清楚，重新开始。

## Scene 08｜真实项目：先规划，再开始动手

现在把这套方法放进 todo-cli。

在 plan mode 里，先明确 add 和 list 怎么工作，数据放在 todos.json，测试怎么写。

方案确认以后，再让 Claude 开始建 todo.py 和 test_todo.py。

每改一处，都看一眼 diff，确认它实现的是刚才的方案，没有引入第三方依赖，也没有乱动范围外的文件。

## Scene 09｜真实项目：验证和挑刺

代码写完不能只听 Claude 说「我改好了」。

先亲手跑 unittest，再跑一次真实的 add 和 list，确认终端真的列出了任务和完成状态。

然后用 /code-review 找一个新鲜上下文来挑刺。

测试、真实功能输出和审查结果放在一起，才构成一条可相信的证据链。

## Scene 10｜交付：看范围、写 commit、守住 push

交付前，先看 git status 和 git diff，确认这次到底改了哪些文件。

然后用一句清楚的中文描述拟好 commit，再提交到本地 git。

但 push 到远程是另一条边界。

本地 commit 可以纳入流程，真正推到远程之前，最后的钥匙必须握在自己手里。

## Scene 11｜玩具打法与真实打法

玩具练习可以一口气做完，也可以少写几条规矩。

但真实项目不能把这些步骤都省掉。

规矩、规划、会话接力、外部信任、新鲜挑刺、容错退路和交付把关，每一步都在替后面的复杂度买保险。

流程不是拖慢你的镣铐，而是让你敢把项目摊子铺得更大。

## Scene 12｜合奏完成，下一集预告

所以，这一篇真正完成的，不是一个新功能，而是一次合奏。

CLAUDE.md、权限、MCP、subagent、检查点和 git，只有在真实项目里按顺序接力，才真正从零件变成方法。

当流程能够规划、验证、恢复并交付，你才更有把握把更大的任务交给 Claude Code。
